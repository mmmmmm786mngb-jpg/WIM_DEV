Обработка - ПИФ2\ДопОбработки\Заполнение списка владельцев номинального держателя (выбор формата)

Документ -   Список владельцев номинального держателя и доверительного управляющего

Регистр - Список владельцев номинального держателя и доверительного управляющего

1. В   регистре и в документе -    в расширениии добавляем новый доп.столбик   НРД_id,  судя по примерам от НРД -  тип Строка -

2. В Обработке в ТЧ добавляем столбик НРД_id.  Из загружаемого файла формата Гарант -

 EntitledReceiveIncomeRersons+MainData.xls  -  начитываем туда данные из последнего столбца -

3. Записываем начитанные данные в Документ.  И при проведении Документа - в Регистр.

4. пишем id  в доп.свойство на Контрагенте  (это потом позволит лучше бороться с дублями)

порядок примерно такой:

4.1. По кнопке Прочитать -  у нас по разным параметрам ищутся Контрагенты  со стороны АванПИФа (ключи не помню точно -  ФИО/ДУЛ/дата рождения....).  Здесь в самом начале перебора поставить  приоритетом№1  поиск по Контрагент.ДопСвойство.НРД id клиента. Например  со стороны файла у нас нрдшный идшник =   01_21612345678.  Поиском со стороны Аванкор ПИФ,  где  ключом№1 поиска стоит нрд_id  найдётся Контрагент  Пажуков М.А. 2211 825662:

4.2.  По кнопке Прочитать,  если  по НРД_id контрагент со стороны АванПИФа не найден - далее действует текущая реализация.       Контрагент ищется  по остальным ключам.

4.2.1. Если Контрагент найден и    НРД id клиента  у такого клиента не заполнен -  прописываем ему  нрд id из файла

4.2.2.  Если ни по одному из ключей Контрагент не найден -   в текущей реализации -  создаётся Новый контрагент . Новому Контрагенту  доп-но прописываем  нрд id  в  Контрагент.ДопСвойство.НРД id клиента

5. При начитке списка - в блоке где создаётся новый контрагент и ищется существующий в базе (по ФИО / дул/ др? Какие там ключи?) - добавляем поиск по НРД_id  из доп.свойства Контрагента. Это позволит нам   по кейсам  из IMAPPS-27939 & IMAPPS-35613 - не создавать дубль клиента (особенно в сложных случаях,  когда клиент сменил ФИО или Паспорт на новый - к примеру клиентка вышла замуж, сменила фамилию и паспорт.  В текущей реализации точно создастся дубль. А если уцепимся за НРД_id - то подцепим старого клиента).
