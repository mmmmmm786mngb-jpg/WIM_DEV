3. Калькуляторы: тяжёлый старый, трёхмесячный Стеганцевой, паспорта, шаблон загрузки в 1С

Калькулятор маркетинг с Катман переделали в корне. У Катман несколько итераций файлов, единого формата нет.

Исторический большой калькулятор маркетинга
Считал объём через дистрибьюцию, АКБ, фейсинги, плановый выход на 100% мощности. Его забросили примерно два года назад. По словам Анны, его создавала [неуверенно: Владасова / Владсова]; Стеганцева сказала «слишком тяжёлый, не хочу» и родила следующий.

Калькулятор «на три месяца» (Стеганцева)
Простой формат: новинка; минимальная партия упаковки СиМ; эту партию нужно реализовать за три месяца; объём раскидывают по месяцам и через калькулятор — по клиентам.

Сейчас им тоже не пользуются. Около двух лет работали так. Задача Анны была: получить калькулятор маркетинга и интегрировать в 1С.

Как загружается в 1С (это важно)
Формат всегда один: клиент, артикул, месяц, штуки, рубли.

Как Борисова технически превращала паспорта в этот вид, Анну не интересовало. Задача была: из паспорта загрузить в 1С.

Дальше продажи могут:
- скорректировать / обнулить, если клиенту точно не заведут;

За эти три месяца по калькулятору продажи уже ставят горизонт по мере договорённостей. Дальше подтягиваются отгрузка и факт, формируется статистический прогноз — всё плавно распределяется.

4. Файл Катман по уже вышедшим новинкам. Что требовать на верхний уровень

По гейт 0 верхний уровень цифр Анна с ними проговорила: ей эти цифры нужны в 1С. Для СиМ объём всё равно нужен, объект должен быть в 1С. Поэтому на гейт 0 всё равно нужна какая-то дезагрегация.

Анна не видела шаблона, в каком виде Катман будет давать верхний уровень (отдел? помесячно? одной годовой цифрой?). Процесс ещё не договорен. Владимиру нужно довести его с Катман до конца: требовать чёткий шаблон верхнего уровня.

В шаблоне должно быть:
- уровень (отдел / иное — зафиксировать);
- помесячно или нет — тоже зафиксировать;
- обязательно средняя цена.

Исходя из этого можно автоматизировать дезагрегацию: правила, каким клиентам ставим целевые планы; как по историческим данным ежемесячно выходить на плановые объёмы.

Катман позиционирует себя как большой босс и не хочет нырять в детали: «это всё делал Demand». При этом в своей табличке по новинкам она сама пишет, что Demand — формирование планов в системе и фазировка по месяцам. То есть по её же схеме Demand должен раскладывать по месяцам.

Как клиент берёт новинку — экспертно, документа с жёсткими правилами нет:
- федеральная сеть: большая первая прогрузка, примерно на 20% больше последующих;
- дистрибьютор: пробная партия, скорее коробка-две;
- экспорт: скорее три коробки.

Можно опереться на Немыкину и Куберину [неуверенно] — они выпускают новинки, они эксперты; Катман тоже поможет прописать.

Владимир: годовая цифра — и кто бьёт по месяцам, она или Demand?

Анна. Тоже не поняла. Ни одного её шаблона «как будет наверх» не видела. То, что сейчас прислали по текущим, — Анна настояла, чтобы разбили по клиентам. Это ассортимент, который УЖЕ выпустился (в т.ч. [неуверенно: Лунчик, Бомбок] — уже в январе / феврале). По новинкам, которые только запускаются, паспорта и калькулятора у Анны ещё не было.

Целевые цифры должна давать Катман. Пока нет артикулов — можно вешать на «эффективного» / ДМ. ДМ — чисто для стратплана; на 2027 ДМ тоже будут.

Логика по аналогам / регионам:
- КАМ в Planicum: планирую завести, например, рулон на клиента, у которого рулоны уже продаются;
