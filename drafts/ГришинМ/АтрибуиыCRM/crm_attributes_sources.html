Атрибуты CRM: откуда брать данные

Разбор полей из перечня для CRM. Для каждого поля указана база 1С, объект и почему это поле закрывает запрос бизнеса. ДУ и ФИН - две редакции доверительного управления: один договор читается только из той базы, где он ведется.

ПИФ - учет фондов и паев ДУ - доверительное управление, редакция 1.5 ФИН - доверительное управление, редакция 2 ДО - документооборот, файлы и юридические карточки
Как выбирать базу Карточка фонда, расчетная цена пая, параметры формирования и лицевой счет пайщика живут в ПИФ. Договор доверительного управления, стратегия, портфель, стоимость активов и доходность в процентах живут в ДУ либо в ФИН. Скан договора, приложения и юридические даты действия живут в ДО. Одинаковые по смыслу реквизиты есть в нескольких базах: ниже у каждого поля отмечен основной источник и запасной.

Продукты информация по ПИФ, общий список

В исходном перечне источник этой группы уже назван: Аванкор ПИФ. В конфигурации это справочник фондов и периодические параметры фонда. ДУ, ФИН и ДО карточку фонда не ведут.

1

Наименование

ПИФ

Пример. ОПИФРФИ «ВИМ - Умный капитал»

Есть поле Справочник ПИФ («Фонды»), стандартный реквизит «Наименование».

Это короткое имя фонда на карточке. Длина наименования 90 символов, его и видит пользователь в списке фондов. Рядом есть параметр фонда «Краткое наименование фонда»: его имеет смысл сверять, если в CRM нужно имя без организационно-правовой формы.

2

Полное наименование

ПИФ

Пример. Открытый паевой инвестиционный фонд рыночных финансовых инструментов «ВИМ - Умный капитал»

Есть поле Регистр сведений ПараметрыПИФ, параметр ПолноеНаименованиеФонда («Полное наименование фонда»).

Полное имя не лежит в реквизите справочника. Оно хранится как значение параметра фонда на дату. Для CRM берется запись на текущую дату. На карточке фонда отдельно есть «Наименование на английском» и «Наименование для выгрузки» - это другие имена, в полное русское наименование их подставлять не нужно.

3

Тип фонда

ПИФ

Пример. Открытый паевой инвестиционный фонд

Есть поле Регистр ПараметрыПИФ, параметр ТипФонда. Значение - перечисление «Типы фонда»: открытый, интервальный, закрытый, биржевой, ипотечное покрытие, личный фонд.

Подпись значения «Открытый» в интерфейсе - «Открытый паевой инвестиционный фонд». Она совпадает с примером в перечне. Категория фонда (акции, облигации, рыночные инструменты) - отдельный параметр, ее в тип подставлять не нужно.

4

Специализированный депозитарий

ПИФ

Пример. ООО «ЦДФ»

Есть поле Регистр ПараметрыПИФ, параметр СпецДепозитарий («Специализированный депозитарий»). Тип значения - ссылка на контрагента.

В перечень нужно наименование этого контрагента. Лицензия спецдепозитария лежит отдельным параметром «Лицензия специализированного депозитария» и в это поле не входит. В ФИН спецдепозитарий есть на документе «Настройки вознаграждения», но это настройка портфеля, а не карточка фонда.

5

Дата формирования

ПИФ

Пример. 20.06.2026. В перечне источник назван «Дата начала формирования».

Есть поле Регистр ПараметрыПИФ, параметр ДатаНачалаФормирования.

В перечне поле называется «Дата формирования», а колонка источника прямо указывает на дату начала формирования. Берется она. У контрагента в ДУ есть реквизит «Дата формирования», но это не дата фонда из ПИФ.

6

Дата окончания формирования

ПИФ

Пример. 30.06.2026

Есть поле Регистр ПараметрыПИФ, параметр ДатаОкончанияФормирования.

Это отдельный параметр от даты начала. В ДУ и ФИН такой даты на договоре нет: там дата окончания - это окончание договора, а не окончания формирования фонда.

7

Расчетная цена пая

ПИФФИН

Пример. 1026.27. В перечне источник не заполнен.

Есть поле Основной источник - ПИФ, регистр сведений СтоимостьЧистыхАктивов, ресурс «Стоимость пая». Период регистра - день, измерение - фонд.

Расчетная цена пая считается при закрытии дня фонда и пишется в этот регистр вместе со СЧА. Для CRM берется последняя запись на нужную дату. Если тот же фонд ведется как портфель в ФИН, та же величина есть в регистре РегистрРСА_СЧА, ресурс «Стоимость пая». ДУ расчетную цену пая фонда не хранит.

8

Активность

ПИФ

Пример. Активен. В перечне источник не заполнен.

Ближайшее поле Справочник ПИФ, реквизит Используется (да/нет).

Отдельного статуса «Активен / Не активен» нет. Признак «Используется» - рабочий переключатель карточки фонда. Для CRM: Истина - «Активен», Ложь - не показывать как действующий продукт. Пометка удаления справочника сюда не подходит: это техническое удаление, а не бизнес-статус.

9

Минимальная сумма входа

ПИФ

Пример. 1000. Источник в перечне: «Мин. сумма покупки паев после формирования фонда».

Есть поле Регистр ПараметрыПИФ, параметр МинСуммаПокупкиПаевПослеФормирования.

Подпись параметра совпадает с колонкой источника в перечне. Рядом лежат две другие суммы, их не смешивать: «при формировании фонда» и «после формирования - вторично». Та же сумма продублирована на договоре контрагента в ПИФ, но мастер - параметр фонда.

10

Описание

Нет готового поля

Пример. В перечне стоит прочерк, источник не указан.

Маркетингового описания нет Ближе всего комментарий и «Доп. информация» на справочнике ПИФ.

Это служебные заметки учетной карточки, а не текст для клиента. Среди параметров фонда отдельного «Описания» нет. Текст для CRM нужно заводить в самой CRM либо договориться, что в это поле пишется комментарий фонда.

Клиент юридическое лицо

Мастер клиентских реквизитов - справочник «Контрагенты». Он есть в ДУ, в ФИН и в ДО. Для институционального клиента основной источник - та база, где ведется его договор: ДУ или ФИН. ДО хранит свою карточку контрагента для документов, она может расходиться с учетом.

0

ID

ДУФИН

Пример. В перечне пусто. Нужен устойчивый идентификатор компании.

Несколько ключей Справочник Контрагенты: уникальный идентификатор ссылки, код элемента, реквизит «Внешний код». В ФИН дополнительно SUN ID.

Отдельного «CRM ID» в 1С нет. Для связи систем надежнее всего уникальный идентификатор ссылки контрагента в той базе, которая выбрана мастером. Для человека и для сверки дублей ключ - ИНН. Код и внешний код менять могут, ссылку - нет. Карточка ДО - другой справочник, ее идентификатор с ДУ и ФИН не совпадает.

1

Название компании

ДУФИНДО

Пример. В перечне пусто.

Есть поле Контрагенты.Наименование и НаименованиеПолное в ДУ и ФИН. В ДО полное имя - «Полное наименование».

В список CRM логично класть полное наименование, а если оно пустое - краткое. ДУ и ФИН заполняют его по учетной карточке клиента. ДО может содержать то же юридическое лицо, но карточка заводится для документов и не обязана совпадать с учетом.

2

Реквизиты: ИНН

ДУФИНДО

Пример. ИНН компании.

Есть поле Контрагенты.ИНН во всех трех базах. Рядом в ДУ и ФИН есть КПП и ОГРН, в ДО - КПП и «ОГРН, ОГРНИП, рег. номер».

Перечень в этом пункте называет именно ИНН. Его и передавать. КПП и ОГРН имеет смысл отдать отдельными реквизитами, если CRM сможет их принять: в карточке они уже есть, но в перечень одним полем «Реквизиты» не разложены.

3

Статус клиента

Нет готового поля

Пример. Действующий или Потенциальный.

Статуса нет Признак КлиентДУ на контрагенте и даты договора только подсказывают, что отношения уже есть.

Учетные базы заводят контрагента, когда с ним работают, и не хранят воронку «потенциальный». «Действующий» можно вычислить: признак «Клиент ДУ» включен и есть договор или портфель без даты окончания в прошлом. «Потенциальный» из 1С не берется - такого клиента в ДУ, ФИН и ДО нет, пока не появилась карточка. Это поле CRM.

4

Тип клиента

ДУФИНПИФ

Пример. Корпоративный или Структурные фонды.

Другой классификатор На договоре ДУ и на портфеле ФИН есть ТипКлиентаДУ: юрлица, НПФ, страховые, собственные средства, ИИС и другие. В ПИФ тип фонда - открытый, закрытый и так далее.

Пары «Корпоративный / Структурные фонды» в 1С нет. «Структурные фонды» - это продуктовая линейка закрытых фондов, а не тип контрагента. Для CRM тип можно собрать правилом: есть действующий договор ДУ юрлица - корпоративный; есть лицевой счет или владение закрытым фондом нужной категории - структурные фонды. Один клиент может попасть в оба типа.

5

Глобальный бренд

Нет готового поля

Пример. В перечне прочерк.

Поля нет Ближайшее в ДУ и ФИН - ГоловнаяОрганизация контрагента.

Головная организация - это другое юрлицо группы, а не маркетинговый бренд. Ни в ДУ, ни в ФИН, ни в ДО справочника брендов нет. Поле остается в CRM.

6

Адрес

ДУФИНДО

Пример. Адрес регистрации юридического лица.

Есть поле Не на договоре. Табличная часть Контрагенты.КонтактнаяИнформация, вид «Юридический адрес» (ЮрАдресКонтрагента в ДУ и ФИН). Текст - в «Представлении». Договор только указывает клиента: ДоговорДУ.Клиент или Портфели.Клиент.

У справочников «Договоры ДУ», «Портфели» и «Договоры контрагентов» нет реквизита адреса и нет своей контактной информации. На внутреннем документе в ДО есть строка «Адрес УК» - это адрес управляющей компании, не адрес регистрации клиента. Юридический адрес один на контрагента, даже если договоров несколько. Фактический и почтовый адреса - другие виды, в это поле их не подставлять.

7

Телефон

ДУФИНДО

Пример. Контактный телефон компании.

Есть поле Та же табличная часть, колонка НомерТелефона у строки с типом «Телефон».

Телефонов может быть несколько (общий, бухгалтерия, факс). В CRM как телефон компании берется строка с видом «телефон» / «телефон организации». Телефон контактного лица - это уже поле «Связанные контакты», его сюда не подмешивать.

8

Email

ДУФИНДО

Пример. Официальный email компании.

Есть поле Табличная часть контактной информации, колонка АдресЭП.

Официальный адрес - строка с видом электронной почты организации. Адреса сотрудников лежат на контактных лицах. Если вид не заполнен, отличить официальный ящик от личного по одному реквизиту нельзя.

9

Сайт

ДУФИНДО

Пример. Сайт компании.

Та же контактная информация Строка контактной информации с видом для сайта. Текст - в «Представлении».

Отдельного реквизита «Сайт» на контрагенте нет. Сайт хранится, только если в базе заведен соответствующий вид контактной информации и его заполнили. Пустая строка означает, что сайт в 1С не вели, а не то, что его нет у компании.

10

Связанные контакты

ДУФИНДО

Пример. ФИО, телефон, почта.

Есть поле Справочник КонтактныеЛица, подчинен контрагенту. ФИО - фамилия, имя, отчество. Телефон и почта - табличная часть «Контактная информация» самого контактного лица.

Это люди компании, а не сама компания. В ДО контактные лица тоже есть и привязаны к внутренним документам как «контактное лицо» и «подписал от контрагента». Табличная часть «Представители» на контрагенте ДУ - про полномочия и долю владения, для телефона и почты она не подходит.

Продукты клиента институциональные

В одном списке CRM смешаны два продукта. Договор ДУ со стратегией и портфелем читается из ДУ или из ФИН. Пай, лицевой счет и цена пая читаются из ПИФ. Ниже у поля написано, к какому продукту оно относится.

1

Название

ДУФИНПИФ

Есть поле Для договора: наименование справочника ДоговорДУ либо Портфели. Для фонда: наименование справочника ПИФ.

В ДУ на договоре есть еще строка «Наименование портфеля», в ФИН - такой же реквизит портфеля и «Полное наименование». В название продукта CRM кладется то имя, под которым договор или фонд узнают в учете. Смешивать имя стратегии и имя договора не стоит: стратегия - отдельное поле.

2

Категория продукта

ПИФДУФИН

Собирается из типа Фонд: параметры ТипФонда и КатегорияФонда (акции, облигации, рыночные инструменты, недвижимость и другие). Договор ДУ: ТипКлиентаДУ и «Вид услуг по договору».

Готовой подписи «институциональный продукт» нет. Для паевого продукта категория берется из категории фонда. Для договора ДУ категория - это тип клиента и вид услуг. Правило, какая пара дает именно «институциональный», нужно зафиксировать с бизнесом: сам классификатор 1С шире.

3

Краткое наименование

ПИФДУФИН

Есть поле ПИФ: параметр КраткоеНаименованиеФонда. ДУ и ФИН: наименование договора или портфеля, если полное имя лежит в «Полном наименовании».

У фонда краткое имя заведено отдельным параметром, его и брать. У договора отдельного «краткого» реквизита нет: короткое имя - это наименование карточки, длинное - реквизит «Полное наименование».

4

Номер договора ДУ

ДУФИН

Есть поле Код справочника ДоговорДУ (ДУ) или код справочника Портфели (ФИН). На лицевом счете в ПИФ номер продублирован строкой НомерДоговораДУ.

Отдельного реквизита «Номер» на карточке договора ДУ нет: номер элемента - это его код. В ФИН учетный аналог договора - портфель, номер - его код. Строка на лицевом счете в ПИФ удобна, чтобы связать пай с договором, но мастер номера - карточка в ДУ или ФИН. Регистрационный номер в ДО может отличаться: это номер учета документов, а не номер договора ДУ.

5

Название стратегии

ДУФИН

Есть поле Регистр ИнвестиционныеПрофили, ресурс «Стратегия». Пишет его документ «Инвестиционный профиль».

Пул стратегией не является. В коде наименование пула «Розничное ДУ» отличает розничный договор. Название стратегии берется из среза регистра инвестиционных профилей по портфелю (ФИН) или по договору ДУ. Реквизит стратегии на самом пуле для CRM не используется.

6

Дата приобретения

ДУФИН

Ближайшее поле ДатаВводаСредствВДУ («Дата ввода средств в ДУ») на договоре ДУ и на портфеле ФИН.

Это дата, когда средства клиента впервые попали в управление, а не дата подписания договора. Если реквизит пуст, дату можно взять из первого документа ввода денег или ценных бумаг по этому договору. Дату заключения в это поле ставить не стоит: она вынесена в карточку договора отдельно.

7

Номер лицевого счета

ПИФ

Есть поле Справочник ЛицевыеСчетаПайщиков, подчинен фонду. Номер - код счета. Пайщик - контрагент. Рядом дата открытия и дата закрытия.

Реестр лицевых счетов ведется в ПИФ. В ФИН на портфеле есть «Код для лицевого счета» - это числовой код учетной карточки, а не номер счета у регистратора. Для поля CRM нужен код лицевого счета из ПИФ. Закрытый счет (заполнена дата закрытия) в действующие не отдавать.

8

Дата начала действия

ДОДУФИН

Две разные даты В ДО у внутреннего документа есть ДатаНачалаДействия. В ДУ и ФИН отдельного поля нет: ДатаНачала подписана как «Дата заключения».

Если бизнес хочет юридическое начало действия, источник - ДО. Если готов принять дату заключения договора как старт, источник - ДУ или ФИН. Это разные события, их лучше не склеивать молча.

9

Срок действия

ДУФИН

Есть поле СрокДействия - число лет. Рядом дата ДействуетДо в ДУ и ДатаОкончания / «Плановая дата окончания» в ФИН.

В перечень срок попал отдельной строкой от даты окончания. Готовое число лет лежит в «Сроке действия». Если в CRM ждут дату, а не число лет, ее дает «Действует до» или дата окончания. Пролонгация в ДУ - отдельный флажок, срок из-за нее сам не пересчитывается.

10

Дата расчета цены пая

ПИФФИН

Есть поле Период последней записи регистра СтоимостьЧистыхАктивов (ПИФ) или РегистрРСА_СЧА (ФИН).

Отдельного реквизита «дата расчета» нет: дата - это день, на который записаны стоимость пая и СЧА. В CRM отдается период той же записи, из которой взята цена. В ПИФ у записи есть еще «Дата время согласования» - это момент согласования, а не расчетная дата.

11

Комиссия MF, %

ДУФИНПИФ

Есть поле Документ НастройкиВознаграждения по договору (ДУ) или по портфелю (ФИН). В табличной части «Вознаграждения» строка по виду вознаграждения УК, колонка «Величина вознаграждения». Для фонда в ПИФ - параметр ВеличинаВознагражденияУК.

Management fee в учете называется вознаграждением управляющей компании, отдельной подписи MF нет. Брать нужно ставку из действующей настройки, а не начисленную сумму. Способ начисления в той же строке показывает, это процент или другая величина: перед выводом в CRM это стоит проверить.

12

Комиссия SF, %

ДУФИНПИФ

Есть поле Тот же документ «Настройки вознаграждения», реквизит шапки ВеличинаВознагражденияЗаУспех. Для фонда в ПИФ - параметр «Величина вознаграждения за успех».

Success fee в учете - вознаграждение за успех. Ставка лежит в шапке настройки, а не в строке обычного вознаграждения УК. Рядом есть ставка порогового уровня доходности: это hurdle, в процент SF ее не подставлять. Начисленная сумма за успех считается отдельно и в это поле не идет.

13

Доходность, сумма

Нет готового поля

Суммы доходности нет Регистр ДоходностьПортфеля хранит только проценты.

Доходность в деньгах пришлось бы считать: изменение стоимости активов минус вводы и плюс выводы. Готовой суммы «заработал столько-то» ни ДУ, ни ФИН, ни ПИФ не хранят. В CRM это либо расчет, либо поле остается пустым, пока формулу не согласуют.

14

Доходность, %

ДУФИН

Есть поле Регистр сведений ДоходностьПортфеля. В ДУ измерение - договор ДУ, в ФИН - портфель. Ресурсы: «Доходность с начала текущего года» и «Доходность за предшествующие 12 месяцев». Период - квартал.

Это готовые проценты по портфелю, а не доходность пая фонда. Какой из двух показателей класть в CRM, нужно выбрать: с начала года или за 12 месяцев. Доходности «с даты приобретения» в регистре нет.

15

Список операций

ДУФИН

Список документов Документы, в которых заполнен договор ДУ или портфель. Опорные виды: ввод и вывод ценных бумаг, поступление и списание с расчетного счета, сделки.

Одной таблицей «операции клиента» учет не обходится: операции - это документы по договору. Для CRM собирается лента документов этого договора или портфеля: дата, вид, сумма. В ПИФ по паям свои документы (заявки, выдача, погашение), они про фонд, а не про договор ДУ.

16

Структура портфеля

ДУФИН

Есть регистр Регистр накопления СтоимостьАктивовУправленческий. Измерения: договор ДУ (в ФИН - портфель), актив, валюта. Ресурсы: количество и сумма.

Состав на дату - остатки этого регистра, сгруппированные по активу. Доля считается от суммы остатка. Это управленческая стоимость, не бухгалтерская оценка каждой бумаги по отдельной методике. Для паевого фонда структура активов фонда - другой контур, ПИФ, и к портфелю одного клиента ее прикладывать не нужно.

17

Связанный договор

ПИФДУФИН

Несколько связей Лицевой счет ПИФ хранит НомерДоговораДУ и «Дату договора ДУ». В ФИН у портфеля есть «Мастер портфель». Договор контрагента ссылается на договор ДУ. На договоре ДУ есть цессия.

Поле в перечне не уточняет, какой договор связан. Самая прямая связь продукта-пая с договором ДУ - номер и дата на лицевом счете. Мастер-портфель связывает портфели между собой внутри ФИН. Пока бизнес не выберет один смысл, в CRM лучше отдавать номер договора ДУ с лицевого счета, а остальные связи не подмешивать.

18

Дата формирования

ПИФ

Есть поле Параметр фонда ДатаНачалаФормирования, тот же, что в общем списке продуктов.

Для паевого продукта это дата формирования фонда. Для чистого договора ДУ такой даты нет: у договора есть дата заключения и дата ввода средств. Если продукт - договор без фонда, поле оставлять пустым, а не копировать дату договора.

19

Состояние портфеля

ДУФИНПИФ

Смысл по соседней группе. Для структурных фондов в перечне написано «AUM на последнюю дату». Здесь та же величина.

Есть поле Договор ДУ: сумма остатка СтоимостьАктивовУправленческий на последнюю дату. ФИН: ресурс «СЧА» или «СЧА (УУ)» регистра РегистрРСА_СЧА. Фонд целиком: ресурс «СЧА» регистра СтоимостьЧистыхАктивов.

Состояние портфеля клиента - это его активы под договором, а не СЧА всего фонда. СЧА фонда показывает размер фонда и подходит, только если продукт CRM - сам фонд. Для институционального договора основной источник - ДУ или ФИН. Дату состояния брать из периода той же записи.

20

Ответственный

ДОДУФИН

На договоре пользователя нет В ДО у внутреннего документа есть Ответственный - пользователь. В ДУ и ФИН на контрагенте есть «Менеджер», но это ссылка на контрагента, не на пользователя. На договоре ДУ и на портфеле ответственного нет.

Если в CRM нужен сотрудник, который ведет договор как документ, источник - ДО. Менеджер с карточки клиента - другой смысл и другой тип данных. Подменять одно другим нельзя.

Договоры клиента

Юридический документ, файлы и срок действия - ДО, справочник «Внутренние документы» и подчиненные ему «Файлы». Учетная карточка того же договора - ДУ («Договоры ДУ») или ФИН («Портфели»). Номер и даты в этих базах могут не совпасть.

1

Название

ДОДУФИН

Есть поле ДО: ВнутренниеДокументы.Заголовок («Наименование»). ДУ: наименование договора ДУ. ФИН: наименование портфеля.

Для карточки договора в CRM основной заголовок - наименование внутреннего документа: так документ назван в юридическом архиве. Учетное имя договора может быть короче и служебнее. Если документа в ДО еще нет, временно берется наименование из ДУ или ФИН.

2

Номер договора

ДУФИНДО

Два номера Учетный номер - код ДоговорДУ или код портфеля, плюс «Номер договора» на справочнике «Договоры контрагентов». Юридический номер регистрации - РегистрационныйНомер внутреннего документа.

На бумаге договора номер часто совпадает с кодом учетной карточки, а в ДО документ получает свой регистрационный номер. В поле CRM нужен номер, который написан на договоре: сначала код договора ДУ или портфеля и номер из «Договоров контрагентов». Регистрационный номер ДО отдавать отдельно, если CRM хранит ссылку на архив.

3

Тип

ДОДУФИН

Вид, а не один список ДО: ВидДокумента (справочник «Виды внутренних документов»). ДУ: «Вид услуг по договору» и тип клиента. Договоры контрагентов: «Вид договора» и «Роль договора».

Тип в CRM, скорее всего, ждут как вид юридического документа (договор ДУ, допсоглашение, правила фонда). Это вид внутреннего документа в ДО. Учетный вид услуг отвечает на другой вопрос - что именно оказывает управляющий. Их стоит развести, а не писать в одно поле подряд.

4

Статус

ДОДУФИН

Набор признаков ДО: «Не действует», «Подписан утвержден», «Бессрочный». ДУ: блокировка, дата приостановки, дата расторжения. ФИН: «Не продлевается», дата окончания, для ИИС - статус счета.

Одного списка статусов «действует / закрыт / на согласовании» нет. Для CRM статус можно собрать правилом. Документ ДО с «Не действует» или договор с заполненной датой окончания в прошлом - не действующий. Пустая дата окончания и отсутствие блокировки - действующий. Промежуточные статусы согласования есть в ДО (подпись, утверждение), в учетной карточке их нет.

5

Заказчик (УК)

ДУФИН

Есть поле УправляющаяКомпания на договоре ДУ и на портфеле ФИН. Тип - контрагент. В ДО ближайшее - реквизит «Организация».

УК в учете указана явно на каждом договоре и портфеле, потому что в базе может быть больше одной компании. Организация в ДО - наша сторона документа, обычно та же УК, но справочник другой. Для подписи «заказчик (УК)» основной источник - управляющая компания договора.

6

Контрагент

ДУФИНДО

Есть поле ДУ: ДоговорДУ.Клиент. ФИН: Портфели.Клиент. ДО: ВнутренниеДокументы.Контрагент.

Клиент договора в учете и контрагент документа в ДО должны быть одним лицом, но карточки разные. Связывать их по ИНН. В CRM контрагента договора лучше брать из ДУ или ФИН, а карточку ДО использовать, чтобы найти файлы.

7

Дата заключения

ДУФИНДО

Есть поле ДУ и ФИН: ДатаНачала, подпись «Дата заключения». ДО: ДатаПодписания.

Учетная дата заключения уже подписана так, как называется поле CRM. Дата подписания в ДО - когда документ подписали в архиве, она может отличаться на дни. Основной источник для этого поля - ДУ или ФИН. Дату регистрации документа в ДО сюда не ставить.

8

Дата начала действия

ДО

Есть поле ВнутренниеДокументы.ДатаНачалаДействия.

Именно это поле так и называется. В учетной карточке договора отдельной даты начала действия нет, там «Дата начала» уже занята датой заключения. Для договора источник один - ДО. Если внутреннего документа нет, поле нечем заполнить из ДУ и ФИН без подмены смысла.

9

Дата окончания действия

ДОДУФИН

Есть поле ДО: ДатаОкончанияДействия. ДУ: ДатаОкончания и «Действует до». ФИН: ДатаОкончания и «Плановая дата окончания».

Юридический конец срока - дата окончания действия в ДО. Учетная дата окончания может быть заполнена раньше, если договор закрыли в учете. Для карточки договора в CRM основная - ДО, а если документа нет - дата окончания из ДУ или ФИН. Флажок «Бессрочный» в ДО означает, что даты окончания может не быть осознанно.

10

Файл договора

ДО

Есть поле Справочник Файлы. Владелец файла - внутренний документ. Имя файла - наименование, содержимое - текущая версия.

Архив скан-копий и подлинников ведется в ДО, не в учетных карточках. У портфеля в ФИН есть присоединенные файлы, но это вложения учетного объекта, а не юридический архив. Файл договора - файл внутреннего документа с видом «договор». Если к документу прикреплено несколько файлов, договор отличают по виду документа и по имени файла.

11

Файл приложений

ДО

Те же файлы, отдельного слота нет Остальные файлы того же внутреннего документа либо связанные документы. На карточке есть число КоличествоПриложений и «Листов в приложениях» - это количество листов, не файлы.

ДО не делит вложения на два жестких реквизита «договор» и «приложения». Все файлы висят на документе. Приложения для CRM - все файлы документа, кроме основного файла договора, плюс дочерние внутренние документы (допсоглашения), если их заводят отдельно. Счетчик листов в файл не превращается.

12

Комментарий

ДОДУФИН

Есть поле Комментарий на внутреннем документе, на договоре ДУ, на портфеле и на договоре контрагента. В ДО есть еще «Содержание».

Комментарии в трех базах пишут разные люди и про разное. Для карточки договора в CRM логичен комментарий внутреннего документа. Содержание в ДО - текст предмета документа, его можно отдать отдельно, в комментарий его лучше не склеивать.

13

Ответственный

ДО

Есть поле ВнутренниеДокументы.Ответственный, справочник «Пользователи». Рядом «Подготовил» и «Подписал».

Ответственный за документ в архиве - это пользователь ДО. На договоре ДУ и на портфеле такого реквизита нет. Если документ в ДО не заведен, ответственного из учета взять неоткуда. «Подготовил» - автор проекта, его в ответственные подставлять только если ответственный пуст и бизнес на это согласится.

Продукты клиента структурные фонды

По комментариям в перечне это закрытый фонд: название фонда, дата создания, AUM, комиссия в фонде. Основной источник - ПИФ. ФИН дополняет, если тот же фонд ведется портфелем. ДУ эту карточку не закрывает.

1

Название

ПИФ

Комментарий в перечне. Прочерк. По смыслу группы - имя фонда.

Есть поле Справочник ПИФ, наименование. Отбор: тип фонда «Закрытый».

Структурный фонд в учете - карточка фонда с типом «Закрытый паевой инвестиционный фонд». Отдельного признака «структурный» нет, закрытый тип - необходимый фильтр, категорию фонда бизнес должен сузить списком.

2

Категория продукта

ПИФ

Пример. ЗПИФ Структурные фонды.

Подписи один в один нет Параметры ТипФонда = закрытый и КатегорияФонда.

«ЗПИФ» собирается из типа «Закрытый паевой инвестиционный фонд». Слов «Структурные фонды» в перечислении категорий нет: там недвижимость, комбинированный, рыночные инструменты, кредитный и другие. Категорию CRM либо фиксируют константой для отобранного списка фондов, либо показывают категорию фонда из ПИФ как есть.

3

Краткое наименование

ПИФ

Комментарий. Наименование фонда.

Есть поле Параметр КраткоеНаименованиеФонда. Если он пуст - наименование справочника фонда.

Комментарий перечня прямо говорит «наименование фонда». Короткое имя для витрины - параметр «Краткое наименование фонда», оно для этого и заведено. Полное имя в это поле не класть.

4

Дата приобретения

ПИФ

Комментарий. Дата создания ЗПИФ.

Есть поле Параметр ДатаНачалаФормирования.

В этой группе бизнес сам расшифровал поле как дату создания фонда, а не как дату покупки клиентом. Поэтому источник - дата начала формирования, а не дата открытия лицевого счета и не дата ввода средств в ДУ. Дата открытия лицевого счета пригодится, только если позже решат показывать вход конкретного клиента.

5

Доходность, сумма

Нет готового поля

Комментарий. Доходность в деньгах.

Суммы нет Есть история СЧА и цены пая в СтоимостьЧистыхАктивов, но не сумма дохода.

Прирост в деньгах можно посчитать из изменения СЧА только с оговорками: вводы и выводы имущества меняют СЧА и доходом не являются. Готового ресурса «доходность в деньгах» нет ни в ПИФ, ни в ФИН. Пока формулу не согласуют, поле из 1С не заполняется.

6

Доходность, %

ПИФФИН

Комментарий. Доходность в процентах.

Считается или берется с портфеля История «Стоимость пая» в ПИФ. Если фонд ведется портфелем в ФИН - регистр ДоходностьПортфеля.

У фонда нет регистра «доходность фонда» с готовым процентом. Процент по паю считается из цены пая на две даты. Если в ФИН на этот фонд заведен портфель, там уже лежат процент с начала года и процент за 12 месяцев - их можно отдать без своего расчета. Какой горизонт нужен CRM, в перечне не сказано.

7

Связанные документы

ДОПИФ

Есть связь ДО: внутренние документы с реквизитами ВТБ_ИК_Фонд, «Номер ПДУ», «Дата ПДУ». Файлы этих документов - справочник «Файлы». ПИФ: правила фонда как значение параметров фонда.

Правила доверительного управления и протоколы по фонду лежат в документообороте: на внутреннем документе есть ссылка на фонд и номер ПДУ. Это и есть связанные документы для CRM. Учетные «Правила фонда» в ПИФ - настройки расчета, их клиенту как комплект документов не отдавать. Файлы брать из ДО.

8

Состояние портфеля

ПИФФИН

Комментарий. AUM на последнюю дату.

Есть поле ПИФ: ресурс «СЧА» регистра СтоимостьЧистыхАктивов на последнюю дату по фонду. ФИН: «СЧА» регистра РегистрРСА_СЧА, если фонд отражен портфелем.

Для фонда AUM - это СЧА, а не сумма активов одного клиента. Берется последняя дневная запись. Стоимость пая в это поле не кладется: она в общем списке продуктов отдельно. СЧА всего фонда и доля конкретного пайщика - разные числа.

9

Комиссия MF

ПИФФИН

Комментарий. Комиссия в фонде.

Есть поле Параметр фонда ВеличинаВознагражденияУК. Если фонд ведется в ФИН - строка вознаграждения УК в документе НастройкиВознаграждения.

Комментарий говорит «комиссия в фонде», значит ставка фонда, а не ставка договора конкретного клиента. Мастер для фонда - параметр ПИФ. Вознаграждение спецдепозитария и вознаграждение за успех - другие параметры, в MF их не включать.

Чего в этих базах нет готовым полем

Эти пункты перечня нельзя просто прочитать из реквизита. Их либо заводят в CRM, либо считают по отдельной формуле.

Описание продукта. Маркетингового текста нет, есть только комментарий карточки фонда.

Статус «потенциальный». Учет не хранит клиентов до появления договора. «Действующий» можно вывести из признака «Клиент ДУ» и незакрытого договора.

Тип «Корпоративный / Структурные фонды». Такого значения нет. Есть тип клиента ДУ и тип фонда. Тип для CRM собирается правилом.

Глобальный бренд. Нет справочника брендов. Головная организация - другое юрлицо, не бренд.

Доходность суммой. И по договору, и по фонду хранится процент или цена пая и СЧА. Сумма дохода отдельным ресурсом не пишется.

Подпись «ЗПИФ Структурные фонды». Есть тип «Закрытый» и категория фонда. Слово «структурные» в классификаторе не найдено.

Составлено по перечню атрибутов CRM и по составу конфигураций ПИФ, ДУ (редакция 1.5), ФИН (ДУ, редакция 2) и ДО. Где поле есть в двух редакциях ДУ, договор читается только из той базы, в которой он ведется.
