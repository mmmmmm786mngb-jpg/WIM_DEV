Тема: ВАР1 — временное отключение проверки ДУЛ по справке участника СВО
Обращение WIMI-2448 / задача IMCCT-338 | оценка ~1.5 недели

Что делаем (ВАР1)
Цель Клиент со справкой СВО и просроченным паспортом может работать с паями в КК без блокировки по ДУЛ — на ограниченный срок.
КК Клиент грузит справку через текущий «иной документ» (отдельный блок СВО в КК не делаем).
КА «Отдельный блок» = UI в профиле клиента: флаг «отключить проверку ДУЛ» + дата «действует по». Ставит сотрудник УК после проверки справки.
Срок T+30 от даты выдачи справки (позиция ЦДФ). Пример: выдана 30.06.2026 → по 30.07.2026 включительно; с 31.07.2026 проверка снова включена автоматически.
Снятие Автоматически системой по истечении срока + обязательный лог (кто, когда, до какой даты).
КК логика Достаёт признак и сверяет с текущей датой; если активен — проверку ДУЛ не применяет.
Риски
1 ЕСИА (главный): ВАР1 снимает только нашу проверку ДУЛ. Регистрация / апгрейд / ИАД через ЕСИА могут по-прежнему блокировать клиента с просроченным паспортом. На тесте кейс плохо воспроизводится. Нужно до старта понять: какие операции клиента идут в ЕСИА и поможет ли флаг.
2 Не все точки проверки: ДУЛ может проверяться в нескольких местах (заявки, лс, обмен, погашение и т.д.). Риск обойти одну точку и оставить другую.
3 Ручной шаг УК: без проставления флага в КА клиент остаётся заблокирован; отдельного уведомления «СВО» в ВАР1 нет — документ может затеряться среди «иных».
4 Частичный эффект: формально ТЗ закрыто, а нужные клиенту операции (паи) всё ещё недоступны из-за ЕСИА/другого контура.
5 Прочее: кэш сессии КК; авто-снятие только джобом (лучше проверять дату «на лету»); права на установку флага; зависимость от вендора.

Уточнение по вопросу «что за отдельный блок?»: это блок в КА (флаг + срок), не новый раздел загрузки в КК. Отдельный блок в КК = ВАР2 (~3 нед.), вне текущего скоупа.

Просьба подтвердить ВАР1 и отдельно закрыть вопрос по ЕСИА для сценариев регистрации/ИАД текущего обращения.
