Тип контрагента ЦБ РФ в сделках РЕПО

Ответ пользователю
Добрый день! В сделках РЕПО реквизит «Тип контрагента ЦБ РФ» заполняется не всегда из карточки контрагента сделки. Важно: это поле из ДУ готовым значением не передаётся. В конфигурации ДУ у сделки РЕПО такого реквизита нет. Значение проставляется уже в ФИН при загрузке обмена ДУ → ФИН (алгоритм «СчетаЕПСПроставитьВСделкеРЕПО»). Если для портфеля включён параметр «Определять тип контрагента по РЕПО от клиента ДУ», значение берётся из реквизита «Тип контрагента ЦБ РФ» у клиента портфеля (в вашем примере — АО «НПФ Альфа»), а не у Банка ВТБ (ПАО). Поэтому в сделке стоит «Негосударственные финансовые организации», хотя у ВТБ в карточке — «Кредитные организации». Это штатное поведение для портфелей ДУ при включённом параметре. Проверить можно так: 1) параметры портфеля ДУ 8298 / учётная политика — флаг «Определять тип контрагента по РЕПО от клиента ДУ»; 2) карточку клиента портфеля (НПФ Альфа) — реквизит «Тип контрагента ЦБ РФ». С уважением.

1. Суть вопроса

Пользователь просит пояснить, откуда заполняется поле «Тип контрагента ЦБ РФ» в сделках РЕПО.

Наблюдение:

  • В сделке контрагент = Банк ВТБ (ПАО).
  • В карточке ВТБ тип = Кредитные организации.
  • В самой сделке РЕПО тип = Негосударственные финансовые организации.
  • Это важно, потому что тип влияет на учёт и проводки.
Кажется, что система «подставила не то». На самом деле подстановка идёт по другому источнику — по клиенту портфеля ДУ, а не по брокеру/контрагенту сделки.

3. Ход рассуждений (для бизнес-пользователя)

Шаг 1. Сравниваем два значения

Если бы система всегда копировала тип из карточки контрагента сделки, в РЕПО должно было бы стоять Кредитные организации. Но стоит Негосударственные финансовые организации. Значит, источник заполнения — не карточка ВТБ.

Шаг 2. Смотрим на портфель

Портфель сделки — ДУ 8298 (АО «НПФ Альфа»). НПФ — это типичная негосударственная финансовая организация. Тип в сделке совпадает именно с ожидаемым типом клиента ДУ, а не брокера.

Вывод: в сделку подтянулся тип клиента портфеля (НПФ Альфа), а не тип контрагента/брокера (ВТБ).

Шаг 3. Почему так сделано в системе

Для портфелей доверительного управления в учётной политике / параметрах портфеля есть специальный флаг:

Определять тип контрагента по РЕПО от клиента ДУ

Когда флаг включён:

1. Берём портфель ДУ 8298
(АО «НПФ Альфа»)
->
2. Берём клиента портфеля АО «НПФ Альфа»
(не Банк ВТБ)
->
3. Копируем его тип ЦБ РФ Негосударственные
финансовые организации

Если флаг выключен, тип берётся как обычно — из контрагента сделки (ВТБ → «Кредитные организации»).

Шаг 4. Зачем это бизнесу

В РЕПО по портфелю ДУ контрагент на форме часто = брокер/банк (ВТБ), но для регуляторного и бухгалтерского учёта важен тип клиента ДУ (кто фактически владелец средств — НПФ, УК и т.п.). От типа зависят счета ЕПС / символы ОФР и, как следствие, проводки.

Поэтому система умеет «переключить» источник типа именно для РЕПО по ДУ.

Шаг 5. Это не ошибка обмена

  • В ДУ у сделки РЕПО поля «Тип контрагента ЦБ РФ» нет — из ДУ оно не «приехало».
  • Значение посчитала сторона ФИН при загрузке обмена (алгоритм СчетаЕПСПроставитьВСделкеРЕПО).
  • Та же логика есть на форме БП в ФИН (ОбновитьТипКонтрагента) и при подборе символов ОФР.
В примере на скриншоте сделка биржевая (режим EQRP_BND, «Внебиржевая сделка» не отмечена). Правило заполнения типа ЦБ РФ одинаково для таких сделок РЕПО: решает параметр портфеля, а не «биржа / ОТС».

4. Алгоритм в коде: откуда подтягивается поле

Как именно заполнилось поле в вашем примере (последовательность)

Поле не пришло готовым из ДУ. Оно было перезаполнено в ФИН в момент загрузки обмена ДУ → ФИН.
1 В ДУ создаётся / проводится сделка РЕПО (портфель ДУ 8298, контрагент Банк ВТБ и т.д.). Реквизита «Тип контрагента ЦБ РФ» у БП «Сделки РЕПО» в ДУ нет — передать его нечему.
2 Обмен ДУ → ФИН загружает сделку в ФИН: подтягиваются портфель, контрагент, суммы, даты и прочие реквизиты обмена.
3 При загрузке в ФИН вызывается алгоритм правил обмена СчетаЕПСПроставитьВСделкеРЕПО (флаг ИспользуетсяПриЗагрузке = true). Именно здесь заполняется ТипКонтрагентаЦБРФ.

Кратко: ДУ отдал сделку без этого поля → ФИН при загрузке сам посчитал тип процедурой/алгоритмом СчетаЕПСПроставитьВСделкеРЕПО → из-за параметра портфеля взял тип у клиента ДУ (НПФ Альфа), а не у ВТБ.

Идея в коде

Реквизит сделки ТипКонтрагентаЦБРФ — это снимок типа на момент заполнения, а не «живая» ссылка на карточку контрагента формы. Система сначала выбирает, у какого элемента справочника «Контрагенты» читать тип (контрагент сделки или клиент портфеля), и только потом копирует его ТипКонтрагентаЦБРФ в сделку.

Зачем: на форме РЕПО в поле «Контрагент» часто стоит брокер (ВТБ), но для учёта ЕПС/ОФР по портфелям ДУ нужен тип клиента ДУ. Параметр портфеля включает этот особый режим.

Когда вызывается на форме (если правят сделку уже в ФИН)

1 Изменение портфеля или даты сделки (ПортфельПриИзменении / ДатаПриИзменении → ИзмененПортфель()). После смены портфеля тип пересчитывается, потому что параметр и клиент портфеля могли измениться.
2 Изменение контрагента сделки (КонтрпартнерПриИзменении → ОбновитьТипКонтрагента()). Если параметр выключен — тип обновится с нового контрагента; если включён — останется тип клиента портфеля (смена ВТБ на другого брокера тип не сменит).

Условия и ветвление (пошагово)

A Берём «кандидата» по умолчанию: КонтрагентДляТипКонтрагентаЦБРФ = Объект.Контрагент (в примере — Банк ВТБ).
B Читаем параметр портфеля на дату сделки: ОпределятьТипКонтрагентаПоРепоОтКлиентаДУ.
C Если параметр = Истина → подменяем кандидата на Портфель.Клиент (в примере — АО «НПФ Альфа»). Если параметр = Ложь / не задан → оставляем контрагента сделки (ВТБ).
D В сделку пишем: Объект.ТипКонтрагентаЦБРФ = кандидат.ТипКонтрагентаЦБРФ.

Имя параметра в системе: «Определять тип контрагента по РЕПО от клиента ДУ» (параметр портфеля / реквизит учётной политики).

6. Как самостоятельно проверить в базе

  • Открыть портфель ДУ 8298 и посмотреть параметры портфеля / связанную учётную политику: флаг «Определять тип контрагента по РЕПО от клиента ДУ» должен быть включён.
  • В карточке портфеля открыть реквизит Клиент (ожидается АО «НПФ Альфа») и проверить у него «Тип контрагента ЦБ РФ» = «Негосударственные финансовые организации».
  • Сверить: значение в сделке РЕПО должно совпасть с типом клиента, а не с типом ВТБ.
  • Для сравнения: у портфеля без этого флага тип в новой сделке РЕПО подтянется уже из контрагента сделки.

7. Итог

В примере всё согласовано с настройкой ДУ: тип в сделке перезаполнен в ФИН при обмене (не передан из ДУ) — взят у клиента портфеля (НПФ Альфа) = «Негосударственные финансовые организации», поэтому он не равен типу ВТБ («Кредитные организации»). Это ожидаемое поведение 1С ФИН.
