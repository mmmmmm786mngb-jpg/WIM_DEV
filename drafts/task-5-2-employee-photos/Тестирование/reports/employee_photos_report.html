Введение. Постановка

Задача 5.2 из сборника для подготовки к экзамену «1С:Специалист» по платформе. В справочнике «Сотрудники» нужно хранить фотографию двумя способами:

  • в базе данных, реквизитом типа «ХранилищеЗначения»;
  • файлом на диске сервера: путь к папке хранится в отдельной константе, имя файла - в реквизите справочника.

На форме элемента должны быть: показ фотографии, переключение места сохранения и загрузка снимка. Загрузить можно кнопкой и щелчком по самому изображению.

Имена в демо-карточках вымышленные. Портреты взяты из открытого набора фотографий людей для примеров, это не документы этих сотрудников.

План реализации

  1. Перечисление «Способы хранения фотографий»: в информационной базе и в каталоге на диске.
  2. Константа «Каталог фотографий сотрудников», строка 255.
  3. Справочник «Сотрудники»: способ хранения, фотография (хранилище значения), имя файла.
  4. Форма элемента. Поле картинки смотрит не в хранилище, а в адрес временного хранилища с двоичными данными.
  5. Кнопка «Выбрать снимок» и щелчок по портрету открывают диалог файла. Очистка убирает снимок при следующей записи.
  6. Перед записью: если снимок и способ не менялись, ничего не перекладывать. Иначе записать байты в выбранное место и освободить другое. Старый файл удаляется только после успешной записи.
  7. Если у снимка из базы нет имени, расширение читается по первым байтам: PNG, JPEG, GIF, BMP.
  8. Карточка для HR: крупный портрет слева, имя, переключатель «В карточке / В папке», папка видна только для файлового режима.
  9. Список «Люди в команде» с колонками сотрудника, табельного номера, места снимка и имени файла.
  10. Проверка чтением базы и проходом по формам в тонком клиенте.

Как снимок доходит до записи

Технология

Проверка данных идет через COM: Component Object Model и библиотеку pywin32. Коннектор платформы создается как V83.COMConnector. Соединение получает строку подключения и возвращает внешнее соединение с базой. Перед работой вызывается pythoncom.CoInitialize(), в конце pythoncom.CoUninitialize().

Параметры строки: Srvr - сервер, Ref - имя базы на сервере, File - каталог файловой базы, Usr и Pwd - пользователь и пароль, App - имя приложения, Locale - язык сеанса.

Три способа подключения

Серверная база:

pythoncom.CoInitialize()
com = win32com.client.Dispatch("V83.COMConnector")
conn = com.Connect("Srvr='localhost';Ref='WIM_DU';Usr='admin';Pwd='1';App='PyCOM';Locale=ru_RU;")

Файловая база этой задачи, без пароля:

conn = com.Connect("File='C:\\Users\\Acer\\Documents\\1C\\EmployeePhotos';App='PyCOM';Locale=ru_RU;")

Файловая база с пользователем:

conn = com.Connect("File='C:\\base\\demo';Usr='Администратор';Pwd='';App='PyCOM';Locale=ru_RU;")

Вызовы методов

Справочник. Менеджер создается через NewObject, затем элемент. Свойство СправочникОбъект напрямую не устанавливается.

manager = conn.NewObject("СправочникМенеджер.Сотрудники")
item = manager.СоздатьЭлемент()
item.Наименование = "Соколова Мария"
item.Записать()

Снимок в базе. Двоичные данные заворачиваются в хранилище со сжатием.

binary = conn.NewObject("ДвоичныеДанные", path)
storage = conn.NewObject("ХранилищеЗначения", binary, conn.NewObject("СжатиеДанных", 9))
item.СпособХраненияФотографии = conn.Перечисления.СпособыХраненияФотографий.ВИнформационнойБазе
item.Фотография = storage

Константа папки. Чтение и установка идут через менеджер константы, не через поле объекта.

folder = conn.Константы.КаталогФотографийСотрудников.Получить()
conn.Константы.КаталогФотографийСотрудников.Установить(folder)

Замечания про обработки

Внешняя обработка через COM требует в строке подключения App='PyCOM' и Locale=ru_RU. Иначе создание обработки часто заканчивается отказом. Дальше нужен менеджер conn.Обработки.Имя, метод Создать() и вызов экспортной функции уже у созданного объекта. Общий модуль вызывается только если у него включено внешнее соединение. В этой задаче обработка не использовалась: проверка шла запросом, менеджером справочника и константой.

ОБНАРУЖЕН БАГ

Перенос снимка из хранилища значения в файл записал PNG под расширением .jpg, потому что исходного имени файла не было. Это не исключение платформы, расхождение поймали сравнением байтов:

Имя файла: b33aaf72-142c-47a6-b1a8-67e20f0e2c10.jpg
Сигнатура: 89 50 4E 47 0D 0A 1A 0A
Ожидалось для JPEG: FF D8
Факт: содержимое PNG при расширении jpg

Теперь пустое расширение определяется по первым байтам. Повторная запись нового сотрудника дала файл .png, байты совпали с исходным снимком.

Возможности

  • Показ портрета на карточке и пустая подсказка, если снимка еще нет.
  • Загрузка кнопкой и щелчком по изображению. Фильтр: jpg, jpeg, png, gif, bmp.
  • Переключение «В карточке» и «В папке» без немедленной порчи второго места: перенос происходит при записи.
  • Очистка снимка. Пустые данные стирают и хранилище, и файл.
  • Папка создается, если ее нет. Имя файла очищается от разделителей пути.
  • Старый файл удаляется после успешной записи, а не до нее.
  • Список команды показывает, где лежит снимок, не открывая карточку.

Выводы

Условие задачи 5.2 закрыто. Снимок живет либо в хранилище значения, либо файлом в папке константы, и форма показывает одно место за раз. Проверка 26.10.2026: 11 сотрудников, 11 непустых снимков, 5 в базе и 6 в файлах, обе формы открываются, переключатель и блок папки ведут себя по способу хранения.

Два дефекта, найденные на первых прогонах, исправлены до этой проверки: невидимый переключатель без списка выбора и расширение .jpg у содержимого PNG. В текущем прогоне исключений платформы не было.
