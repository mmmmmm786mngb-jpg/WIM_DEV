Техническое задание: временное отключение проверки ДУЛ по справке участника СВО

Обращение: WIMI-2448-30062026_Нгуен
Задача: IMCCT-338
Вариант реализации: ВАР1 (быстрый)
Оценка: ~1.5 недели
Дата ТЗ: 21.07.2026
Статус: черновик по согласованной позиции ЦДФ / юр. отдела / продукта

Зачем это нужно Клиент находится на СВО, паспорт просрочен, поменять его нельзя. В клиентском кабинете (КК) из-за проверки ДУЛ он не может работать с паями. При наличии справки участника СВО с QR-кодом УК должна дать возможность обслуживаться без действующего паспорта — на ограниченный срок, согласованный с позицией ЦДФ.

1. Цель и результат для клиента

При наличии в профиле клиента признака «проверка ДУЛ отключена» и пока текущая дата не позже даты окончания действия признака, клиентский кабинет не блокирует операции из-за истекшего ДУЛ.

Операции, которые должны стать доступны (в рамках обычных бизнес-правил продукта, кроме проверки ДУЛ):

  • регистрация / апгрейд;
  • открытие лицевого счета;
  • заявки на приобретение, обмен, погашение;
  • ИАД (в части, где сейчас мешает именно проверка ДУЛ).
Важно Признак не «открывает всё подряд». Он только снимает ограничение по просроченному ДУЛ. Остальные проверки (идентификация, лимиты, статус клиента и т.д.) работают как раньше.

4. Участники и системы

КтоЧто делает
Клиент Загружает справку в КК через «иной документ». Пользуется сервисами, пока признак активен.
Сотрудник УК Получает информацию о загруженном документе, знакомится со справкой, в КА ставит признак и срок.
Система КА Хранит признак, срок, журнал изменений; автоматически снимает признак после истечения срока.
Система КК При проверке ДУЛ запрашивает признак, сверяет с текущей датой; если признак активен — проверку ДУЛ не применяет.

5. Бизнес-процесс (пошагово)

  1. КК Клиент в профиле загружает справку участника СВО через существующий механизм «загрузить иной документ».
  2. УК Сотрудник УК получает информацию о загруженном документе (текущий канал уведомлений / очереди документов).
  3. КА Сотрудник открывает профиль клиента, открывает отдельный блок «Отключение проверки ДУЛ», указывает дату окончания и включает признак.
  4. Система Фиксирует в логе: кто, когда, до какой даты (включительно) установлен признак.
  5. КК При любой операции, где раньше срабатывала проверка ДУЛ, КК читает признак и дату. Если сегодня <= дата окончания — проверка ДУЛ пропускается.
  6. Система Начиная со дня после даты окончания признак считается неактивным (снимается автоматически). Проверка ДУЛ снова применяется без действий сотрудника УК.
  7. При необходимости клиент загружает новую справку; сотрудник УК заново ставит признак на новый срок.

6. Правило срока T+30

Позиция ЦДФ (согласовано с юр. отделом ЦДФ) Справка действительна 30 дней (как QR на справке). После истечения срока для операций нужна новая справка.
Пример из обращения
  • Дата выдачи справки T = 30.06.2026
  • Проверка ДУЛ отключена по 30.07.2026 включительно (T+30)
  • С 31.07.2026 проверка ДУЛ снова применяется автоматически
ПравилоОписание
Дата окончания Календарная дата «действует по» = дата выдачи справки + 30 дней (включительно)
Сравнение в КК Признак активен, если: флаг установлен И текущая дата (по календарю сеанса/системы) <= дата окончания
Авто-снятие С даты = дата окончания + 1 день признак неактивен; ручное действие УК не требуется
Продление Только через новую справку и повторную установку признака сотрудником УК
Уточнение для разработки Рекомендуется в КА при установке флага показывать подсказку: «Рекомендуемый срок: дата выдачи справки + 30 дней». Сотрудник указывает дату окончания явно (не «год»). Значение по умолчанию можно предложить как T+30, если дата выдачи известна из карточки документа; иначе сотрудник вводит вручную по справке.

7. Функциональные требования

7.1. Клиентский кабинет (КК)

IDТребование
KK-01 Сохранить текущий сценарий загрузки «иного документа» без нового блока СВО в КК.
KK-02 Перед применением проверки ДУЛ система должна получать признак отключения и дату окончания по клиенту.
KK-03 Если признак активен (дата текущая <= даты окончания) — проверку ДУЛ не применять для операций из цели ТЗ.
KK-04 Если признак отсутствует, снят или срок истёк — поведение проверки ДУЛ как сейчас (без изменений для остальных клиентов).
KK-05 Признак не должен обходиться кэшем устаревших данных дольше согласованного TTL (см. NFR); после снятия признака блокировка по ДУЛ должна восстановиться без ручного сброса сессии клиента (если технически возможно — иначе зафиксировать ограничение).

7.2. Кабинет администратора (КА) — «отдельный блок»

IDТребование
KA-01 В профиле клиента добавить отдельный блок UI: отключение проверки паспорта (ДУЛ) с указанием срока.
KA-02 Блок содержит как минимум: переключатель/флаг «Отключить проверку ДУЛ»; поле «Действует по (включительно)» (дата); отображение кто и когда установил (из лога / последних значений).
KA-03 Устанавливать и изменять признак может только сотрудник УК с соответствующими правами (роль уточняется продуктом / ИБ).
KA-04 Нельзя сохранить признак «включён» без заполненной даты окончания.
KA-05 Дата окончания не должна быть в прошлом на момент установки (валидация).
KA-06 Сотрудник может досрочно снять признак вручную (если нужно отозвать допуск). Снятие логируется.
KA-07 Система автоматически снимает (деактивирует) признак после истечения срока без действий сотрудника.

8.1. Атрибуты профиля клиента (минимум)

8.2. Обязательный журнал (лог)

Каждое событие установки, изменения, ручного снятия и автоматического снятия должно писаться в лог:

  • дата и время события;
  • тип события (установка / изменение / ручное снятие / авто-снятие);
  • кто выполнил (для авто-снятия — система);
  • дата «по какую включительно» (для установки/изменения);
  • идентификатор клиента.
Формулировка из согласования «Признак руками после ознакомления со справкой проставляет сотрудник УК, признак снимается по истечении срока системой автоматически (с обязательным логированием — дата, время, кто из сотрудников установил и датой по какую включительно признак установлен)».

9. Нефункциональные требования

  • Обратная совместимость: клиенты без признака не меняют поведение.
  • Безопасность: установка признака только уполномоченными ролями УК.
  • Аудит: лог неизменяемый для обычных пользователей (или с ограничением прав на правку).
  • Надёжность авто-снятия: регламент / job не реже 1 раза в сутки; предпочтительно — проверка «на лету» по дате при каждом запросе из КК (даже если job ещё не отработал, КК считает признак неактивным после даты окончания).
  • Срок поставки: ориентир ~1.5 недели на ВАР1 после фиксации ТЗ.

10. Критерии приемки

  1. Клиент без признака с просроченным ДУЛ по-прежнему блокируется проверкой ДУЛ.
  2. После установки в КА флага и даты T+30 тот же клиент проходит операции без блокировки по ДУЛ.
  3. На дату окончания включительно операции ещё доступны (без блокировки по ДУЛ).
  4. На следующий день после даты окончания проверка ДУЛ снова блокирует (без действий сотрудника).
  5. В логе есть запись об установке (кто, когда, до какой даты) и об авто-снятии / факте истечения.
  6. Загрузка справки идёт через существующий «иной документ»; отдельного блока СВО в КК нет.
  7. В КА виден отдельный блок управления признаком и сроком.

11. FAQ — ответы на частые вопросы

Q1. Что такое «отдельный блок»? Это новый раздел в КК?

Нет. В ВАР1 «отдельный блок» — это UI в КА (профиль клиента): флаг отключения проверки ДУЛ + дата «действует по».

В КК отдельный раздел под СВО не делается. Клиент грузит справку как «иной документ».

Отдельный блок в КК — это уже ВАР2 (~3 недели), он вне текущего ТЗ.

Q2. Чем ВАР1 отличается от ВАР2?

ВАР1: текущая загрузка документа в КК + ручной флаг/срок в КА + чтение признака в КК. ~1.5 недели.

ВАР2: плюс отдельный блок в КК под меры поддержки СВО и отдельное уведомление УК. ~3 недели.

По удобству для клиента ВАР2 лучше (понятный сценарий без «иного документа»), по скорости вывода — ВАР1.

Q3. Кто в КА ставит флаг и кто указывает срок?

Флаг и срок ставит сотрудник УК вручную после ознакомления со справкой.

Срок указывает тот же сотрудник в блоке КА (рекомендуемое значение — T+30 от даты выдачи справки).

Клиент сам себе признак поставить не может.

Q4. До какого времени отключаем проверку паспорта: T+30 или иначе?

T+30 от даты выдачи справки — по позиции ЦДФ (QR/справка действует 30 дней), согласовано с юр. отделом ЦДФ.

Пример: выдана 30.06.2026 → отключение по 30.07.2026 включительно; с 31.07.2026 проверка снова включена.

Вариант «на год», который был в первом черновике описания задачи, не используем.

Q5. Нужно ли сотруднику вручную снимать флаг после 30 дней?

Нет. Система снимает признак автоматически по истечении срока.

Ручное снятие — только если нужно отозвать допуск раньше срока.

Q6. Что делает КК с этим признаком?

КК при проверке ДУЛ достаёт признак и сверяет с текущей датой.

Если признак активен — проверка ДУЛ не применяется. Если нет — поведение как сейчас.

Q7. Постановление Правительства не задаёт срок справки. Почему тогда 30 дней?

Юридически срок в постановлении может быть не зафиксирован, а действие справки связано с периодом участия.

Для операционной модели УК принята позиция ЦДФ: ориентир на срок QR = 30 дней, после этого для операций нужна новая справка.

Продукт и разработка руководствуются согласованной позицией ЦДФ / СД для реализации.

Q8. Решаем только для одного клиента или сразу для всех?

Функционал ВАР1 — общий механизм (флаг/срок в профиле), им можно пользоваться для любого клиента при наличии справки.

Операционно можно сначала закрыть текущее обращение, затем применять тот же процесс для остальных.

Отдельный «хардкод только на одного клиента» в ТЗ не закладываем.

Q9. Закрывает ли ВАР1 проблемы регистрации и ИАД через ЕСИА?

Не полностью гарантировано. ВАР1 снимает внутреннюю проверку ДУЛ в контуре КК/КА.

Если на пути регистрации/ИАД есть внешний ответ ЕСИА, поведение ЕСИА по таким клиентам может остаться ограничением. Это отдельный риск (отмечен разработкой ранее).

В скоупе ВАР1 — отключение своей проверки ДУЛ по признаку; доработки ЕСИА не входят.

Q10. Нужно ли клиенту писать в УК, чтобы загрузить справку?

В ВАР1 клиент может загрузить справку сам через «иной документ».

Но включение признака всё равно делает сотрудник УК после проверки документа. Без этого шага операции по просроченному ДУЛ не откроются.

Q11. Что отвечать, если снова спросят: «Сможем?»

Да, ВАР1 реализуем: загрузка через текущий механизм + блок в КА (флаг и срок T+30) + чтение признака в КК + авто-снятие и логирование. Ориентир ~1.5 недели после фиксации ТЗ и приоритизации в спринте.

Q12. Какие операции клиент хочет прямо сейчас?

По обращению: взаимодействовать с паями — в т.ч. открытие лс, обмен, погашение (и связанные сценарии, где мешает просроченный ДУЛ).
