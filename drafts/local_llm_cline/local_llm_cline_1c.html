Локальная LLM для разработки 1С

Открытые модели (Qwen, GLM, DeepSeek, gpt-oss, Devstral, Gemma) на тестовом сервере компании + VS Code с расширением Cline на ноутбуках разработчиков + те же MCP-серверы и навыки (skills) по 1С, которые сегодня используют Cursor и Claude Code. Код и данные не покидают контур.

Только автономные модели: без обращений в интернет Open weights: Китай, США, Европа Ollama / vLLM VS Code + Cline MCP: платформа, индекс кода, тест-клиент 1С Agent Skills: ~100 навыков по 1С 0 руб. за токены

1Зачем это нужно

Сейчас ИИ-помощь в разработке 1С работает через облачные модели. Локальная модель на своем сервере снимает три ограничения сразу.

Безопасность контура

Исходники конфигураций, расширения, тексты запросов и данные тестовых баз не отправляются во внешние сервисы. Модель отвечает по локальной сети, доступ в интернет сервер не требует.

Предсказуемая стоимость

Открытые модели бесплатны (Apache 2.0, MIT). Затраты — один раз на GPU-сервер и электричество. Нет лимитов на запросы, нет счетов за токены, нет зависимости от курса, платежных и санкционных ограничений.

Переиспользование наработок

Навыки по 1С (сборка обработок, формы, СКД, роли, расширения) и MCP-серверы уже написаны и работают в Cursor и Claude Code. Cline поддерживает тот же стандарт — переносится копированием папок.

2Архитектура решения

Четыре слоя: модель (думает), Cline (действует в редакторе), MCP-серверы (дают доступ к 1С), навыки (объясняют, как правильно работать с 1С).

Схема 1. Модель живет на сервере, все инструменты (MCP, навыки, платформа 1С) остаются на рабочем месте разработчика. По сети ходит только текст запросов и ответов.

Роли компонентов

Модель

Читает контекст, пишет код на BSL, решает, какой инструмент вызвать. Главный критерий выбора: умение надежно вызывать инструменты (tool calling) и большой контекст (от 64К токенов).

Cline

Открытое расширение VS Code (Apache 2.0). Превращает ответы модели в действия: правит файлы, выполняет команды, вызывает MCP. Каждое действие подтверждает разработчик.

MCP-серверы

Стандартный протокол подключения инструментов. Один и тот же JSON-конфиг работает в Cursor, Claude Code и Cline. Для 1С уже есть три сервера: платформа, индекс кода, тест-клиент.

Skills (навыки)

Папки с файлом SKILL.md: пошаговые инструкции и скрипты для конкретной задачи (собрать EPF, добавить форму, проверить роль). Подгружаются по требованию, не расходуют контекст впустую.

3Открытые модели: что есть и что выбрать

В презентацию включены только модели с открытыми весами, которые скачиваются один раз и далее работают на сервере компании без обращений в интернет. Облачные модели и API (Claude, GPT, Gemini, облачные версии DeepSeek и Qwen) не рассматриваются. Все ниже — бесплатны для коммерческого использования (кроме отмеченных), запускаются в Ollama или vLLM. Память указана для весов при квантовании 4-bit (если не указано иное); к ней добавляется KV-кэш контекста (для 32К токенов: 1-3 ГБ на запрос).

Критерий отбора. Модель — это файл весов на диске сервера. Весь расчет ответа идет на GPU компании. У модели нет сетевого доступа: она не может ничего отправить наружу, даже если «захочет». Единственный выход в интернет — разовое скачивание весов администратором (или перенос на носителе).

Три уровня внедрения

Уровень A. Пилот

Сервер: 1 GPU 24-32 ГБ, 64 ГБ RAM.

Сервер инференса: Ollama.
Пользователи: 1-3 одновременно.

Уровень B. Команда

Сервер: 1-2 GPU 48-96 ГБ (L40S, A6000, H100, RTX PRO 6000).
Модели: qwen3-coder-next; американская — gpt-oss-120b; европейская — Mistral Medium 3.5 (проверить лицензию).
Сервер инференса: vLLM.
Пользователи: 5-15.

Уровень C. Замена облака

Сервер: 4-8x H100/H200 (256-640 ГБ).
Модели: DeepSeek-V4-Flash, GLM-5.3-Flash, GLM-4.7, Qwen3-Coder-480B, DeepSeek-V3.2.
Сервер инференса: vLLM с тензорным/экспертным параллелизмом.
Пользователи: вся разработка.

Почему не ноутбук. На типовом рабочем ноутбуке (16 ГБ RAM, без дискретной GPU) помещается только 7B-модель, и считает она на процессоре: один шаг агента занимает минуты, а инструменты она вызывает нестабильно. Сервер с GPU решает обе проблемы: модель в 4-10 раз крупнее и скорость в 10-30 раз выше.

4Порядок подключения и настройки

Семь шагов. Шаги 1-2 делает администратор сервера один раз, шаги 3-7 — каждый разработчик на своем рабочем месте (или централизованно через скрипт).

Схема 2. Последовательность развертывания

Сервер инференса и модель

Где: тестовый сервер с GPU. Кто: администратор. Время: 1-2 часа (основное — скачивание весов).

Вариант 1 — Ollama (рекомендуется для пилота: одна команда, автоматическая загрузка моделей, OpenAI-совместимый API).

# Linux
curl -fsSL https://ollama.com/install.sh | sh

# Открыть доступ из локальной сети и держать модель в памяти постоянно
sudo systemctl edit ollama
#   [Service]
#   Environment="OLLAMA_HOST=0.0.0.0:11434"
#   Environment="OLLAMA_KEEP_ALIVE=-1"
#   Environment="OLLAMA_CONTEXT_LENGTH=65536"
#   Environment="OLLAMA_NUM_PARALLEL=4"
sudo systemctl restart ollama

# Скачать модель: китайская / американская / европейская
ollama pull glm-4.7-flash          # 19 ГБ
ollama pull qwen3-coder:30b        # 18 ГБ
ollama pull gpt-oss:20b            # 14 ГБ
ollama pull devstral-small-2       # 13 ГБ

На Windows Server те же переменные задаются как системные переменные окружения, после чего перезапускается служба Ollama.

Вариант 2 — vLLM (для уровней B и C: параллельные запросы, высокая пропускная способность, точные парсеры вызова инструментов).

docker run --gpus all -p 8000:8000 --ipc=host \
  -v /opt/models:/root/.cache/huggingface \
  vllm/vllm-openai:latest \
  --model Qwen/Qwen3-Coder-30B-A3B-Instruct-FP8 \
  --max-model-len 131072 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --served-model-name qwen3-coder

# gpt-oss-120b на одной H100:
#   --model openai/gpt-oss-120b --tool-call-parser openai
# GLM-4.7 на 8 GPU:
#   --model zai-org/GLM-4.7-FP8 --tensor-parallel-size 8 --tool-call-parser glm47 --reasoning-parser glm47
Параметр --tool-call-parser критичен: он переводит ответ модели в структурированный вызов инструмента. Без него Cline не сможет вызывать MCP и редактировать файлы.

VS Code и расширение Cline

Где: ноутбук разработчика. Время: 10 минут.
  1. Установить VS Code и расширение Cline из Marketplace (издатель saoudrizwan, открытый код, Apache 2.0).

Cline и Cursor могут использоваться параллельно на одном репозитории: конфигурации у них в разных папках (.cline/ и .cursor/), конфликтов нет.

Навыки (skills) по 1С и правила проекта

Где: папка репозитория. Это ключевой шаг: без него модель знает BSL «в общем», но не знает, как собрать обработку нашими скриптами или где лежат исходники баз.

Как это устроено. Навык — папка с файлом SKILL.md. В начале файла YAML-шапка с полями name и description, дальше инструкции и ссылки на скрипты внутри папки. Cline при старте читает только шапки (около 100 токенов на навык), а полный текст подгружает, когда запрос разработчика совпал с описанием. Это стандарт Agent Skills, его поддерживают Cursor, Claude Code, Cline, Codex, OpenCode — одна и та же папка работает везде.

epf-build/
  SKILL.md              # шапка: name: epf-build, description: Собрать внешнюю обработку 1С (EPF/ERF) из XML...
  scripts/
    build-epf.ps1       # вызывает конфигуратор в пакетном режиме
  docs/
    troubleshooting.md

Откуда берем. Сегодня в работе три набора, все в одном формате:

НаборСейчас лежитСоставПримеры
cc-1c-skills.cursor/skills/ (обновляется из git)~85 навыков: сборка и разбор EPF/ERF, формы, макеты, СКД, роли, расширения, подсистемы, XDTO, базы, хранилище, веб-публикацияepf-build, form-add, skd-compile, cfe-borrow, db-load-xml
cursor-1c-extras.agents/skills/4 навыка: язык запросов, оптимизация запросов, RLS, распаковка CFcomposing-1c-queries, 1c-query-optimization

Куда кладем для Cline. Cline ищет навыки в трех папках проекта: .cline/skills/ (рекомендуется), .clinerules/skills/, .claude/skills/, и в глобальной %USERPROFILE%\.cline\skills\. Структура строго плоская: skills/<имя>/SKILL.md, вложенные категории не распознаются.

# PowerShell: собрать все три набора в .cline/skills проекта
$dst = ".cline\skills"
New-Item -ItemType Directory -Force $dst | Out-Null

$sources = @(".cursor\skills", ".agents\skills", "$env:USERPROFILE\.claude\skills")
foreach ($src in $sources) {
    Get-ChildItem $src -Directory | Where-Object { Test-Path (Join-Path $_.FullName "SKILL.md") } |
        ForEach-Object { Copy-Item $_.FullName (Join-Path $dst $_.Name) -Recurse -Force }
}

# Контроль: имя папки обязано совпадать с полем name в шапке SKILL.md
Get-ChildItem $dst -Directory | ForEach-Object {
    $head = Get-Content (Join-Path $_.FullName "SKILL.md") -TotalCount 5 -Encoding UTF8
    $name = ($head | Select-String '^name:\s*(.+)$').Matches.Groups[1].Value.Trim()
    if ($name -ne $_.Name) { Write-Warning "Несовпадение: папка $($_.Name), name: $name" }
}
Три правила, из-за которых навык «молча» не подхватывается: (1) в шапке есть и name, и description; (2) name точно равен имени папки, с учетом регистра; (3) папка лежит непосредственно в skills/, без промежуточных каталогов. Остальные поля шапки (allowed-tools, argument-hint) Cline не мешают.

Чем отличается вызов. В Claude Code навык вызывается как команда /epf-build ИмяОбработки. В Cline навык активируется по смыслу запроса: «собери обработку ЗагрузкаВыписок из src» — Cline сам сопоставит с описанием epf-build и загрузит инструкцию. Можно назвать навык явно: «используй навык epf-build». Список и переключатели навыков — в панели по иконке весов под строкой ввода.

Правила проекта. Правила Cursor (.cursor/rules/*.mdc) в Cline переносятся в папку .clinerules/ как обычные markdown-файлы; они всегда в контексте. Для локальной модели правила держим короткими: 30-60 строк каждое, без длинных примеров.

.clinerules/
  01-project-structure.md     # bases/, projects/, source-path.txt
  02-ut-reference.md          # где эталон УТ, как им пользоваться
  03-code-index-mcp.md        # алиасы repo, какой инструмент для какой задачи
  04-platform-mcp.md          # сверять сигнатуры через 1c-platform
  05-bsl-style.md             # отступы, регистр ключевых слов, комментарии, запрет HTML-сущностей

Итог

Локальная модель на тестовом сервере с GPU дает команде 1С-разработки ИИ-помощника, который работает внутри контура, не требует оплаты за токены и использует уже созданные навыки и MCP-серверы без переделки. Выбор моделей широкий: китайские Qwen, GLM, DeepSeek лидируют по качеству на всех уровнях; американские gpt-oss, Gemma 4 и европейская Devstral закрывают уровни A и B, если нужна модель не из Китая. Cline, Cursor и Claude Code читают один и тот же формат навыков и MCP-конфигов, поэтому переход не ломает текущий процесс.

Минимальный старт: одна видеокарта 24 ГБ, Ollama, две-три модели на выбор, один день на развертывание, две недели пилота с измеримыми метриками. Целевой уровень для команды — сервер с 1-2 GPU по 48-96 ГБ и vLLM. После загрузки весов сервер и рабочие места могут работать без доступа в интернет.

Предложение по развертыванию локальной LLM для разработки 1С. Все упомянутые модели — с открытыми весами, работают автономно на сервере компании, лицензии Apache 2.0 или MIT, кроме отмеченных отдельно. Cline — открытое расширение VS Code (Apache 2.0).
