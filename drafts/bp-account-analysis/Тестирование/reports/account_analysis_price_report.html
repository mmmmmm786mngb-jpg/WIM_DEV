Анализ счета: строка цены для товарных счетов

Отчет о принципе доработки и результате проверки. База: Бухгалтерия предприятия, файловая информационная база БП_ДЕМО. Организация Конфетпром ООО, счет 41.01, период 01.01.2020 - 04.10.2026.

Введение

В типовом отчете Анализ счета по товарному счету 41.01 выводились сумма бухгалтерского учета и количество по номенклатуре. Строки с ценой не было.

Доработка сделана расширением конфигурации ЦенаВАнализеСчета. Типовая конфигурация не изменялась. Для счетов, код которых начинается с 41, и только если в отчете включен показатель количества, под строкой количества появляется строка Цена. Фон строки янтарный, RGB 255, 224, 130, текст коричневый, RGB 102, 60, 0. Числовая цена выводится с двумя знаками после запятой.

Цена равна сумме бухгалтерского учета, деленной на количество. На группировке и в итоге это средневзвешенная цена: сумма сумм, деленная на сумму количеств. Если количество равно нулю, цена равна нулю и в ячейке не показывается.

Счет 51 к товарным не относится. Строка цены на нем не появляется, даже если количество в параметрах отчета включено.

Как устроена доработка

Показатели отчета идут вертикальными строками: БУ, количество и другие включенные показатели. Количество таких строк считает общий модуль бухгалтерских отчетов по массиву НаборПоказателей. Расширение добавляет в этот массив имя Цена до сборки макета, поэтому типовой цикл сам выводит подпись "Цена" в трех секциях: остаток на начало, оборот и остаток на конец.

Числовые поля цены добавляются в схему компоновки как вычисляемые поля и ресурсы. В выбранные поля они вставляются сразу после полей количества. Подписи с путем Показатели.* повторно не вставляются: их уже добавляет типовой цикл.

После добавления полей компоновщик настроек инициализируется заново и загружает те же настройки. Иначе процедура восстановления настроек отбросила бы новые поля, которых не было в доступных полях при первой инициализации.

Выражение детальной записи:

ВЫБОР
    КОГДА ЕстьNull(СальдоНаКонецПериода.КоличествоКонечныйОстатокДт, 0) = 0
        ТОГДА 0
    ИНАЧЕ ЕстьNull(СальдоНаКонецПериода.БУКонечныйОстатокДт, 0)
        / СальдоНаКонецПериода.КоличествоКонечныйОстатокДт
КОНЕЦ

Выражение ресурса (итог и группировка) то же, но сумма и количество обернуты в Сумма(). Для конечного остатка по дебету это Сумма(БУКонечныйОстатокДт) / Сумма(КоличествоКонечныйОстатокДт). Поэтому общий итог 49 500 / 140 = 353,57, а не среднее арифметическое четырех цен.

Цвет задается условным оформлением компоновки: элемент "Строка цены товарного счета" красит все поля цены, элемент "Формат цены товарного счета" ставит формат ЧДЦ=2 только на числовые поля.

Технология

COM-подключение

Проверка данных и пробное формирование отчета выполнялись из Python через COM. Используется библиотека pywin32 и соединитель платформы 1С:Предприятие 8.3. ProgID соединителя: V83.COMConnector. Перед работой поток инициализируется вызовом pythoncom.CoInitialize(), в конце вызывается pythoncom.CoUninitialize().

Метод Connect принимает строку соединения. Внешнее соединение видит объекты базы, выполняет запросы и вызывает экспортные методы общих модулей с флажком "Внешнее соединение". Оно не открывает управляемую форму и не исполняет перехватчики расширения &Перед и &После. Поэтому итоговая проверка строки цены выполнена в сеансе предприятия запуском внешней обработки.

Примеры вызова методов

Замечания о внешних обработках и расширении

В строке COM-соединения для работы с обработками обязательны App='PyCOM' и Locale=ru_RU. Объект обработки создается через менеджер: conn.Обработки.Имя.Создать(), затем вызывается экспортный метод. Общий модуль доступен внешнему соединению только если у него включено свойство "Внешнее соединение".

Перехватчики расширения &Перед и &После в сеансе внешнего соединения не выполняются. Отчет при этом строится штатно, без строки цены. Это ограничение способа проверки, а не ошибка расширения. Проверка перехватчиков сделана внешней обработкой check_price.epf, запущенной в сеансе предприятия: 1cv8.exe ENTERPRISE /F ... /N Admin /Execute check_price.epf. Обработка на сервере вызывает ПодготовитьОтчет, обходит табличный документ и записывает результат в файл, затем на клиенте завершает работу.

Для такого запуска у пользователя Admin есть право на открытие внешних обработок, а у расширения ЦенаВАнализеСчета выключен безопасный режим. После повторной загрузки расширения безопасный режим остался выключенным: SafeMode=False, расширение активно.

2. Отчет в сеансе предприятия, счет 41.01

Успех Повторный запуск после загрузки очищенного расширения. Параметры: Организация="Конфетпром ООО", НачалоПериода="01.01.2020", КонецПериода="04.10.2026", Счет="41.01", ПоказательБУ=Истина, ПоказательКоличество=Истина, группировка Поле="Субконто1".

Формирование выполнено, контрольное соотношение итогов выполняется. Размер табличного документа 50 x 5. Найдено 15 строк с текстом "Цена", у всех фон RGB 255, 224, 130.

3. Отчет в сеансе предприятия, счет 51

Успех Параметры те же, Счет="51". Формирование выполнено, контрольное соотношение выполняется, размер 17 x 5. В обходе ячеек нет текста "Цена" и нет фона RGB 255, 224, 130. Строки количества на счете 51 пустые, что ожидаемо для денежного счета.

4. Тот же сценарий через внешнее соединение

Ограничение проверки COM построил отчет по счету 41.01: выполнено, контроль итогов пройден, размер 35 x 5. Строк "Цена" 0, цветных ячеек 0. Расширение при этом было активно.

Это не ошибка кода расширения. Внешнее соединение не вызывает аннотации &Перед и &После. В сеансе предприятия те же параметры дают 15 цветных строк. Ошибки платформы при формировании не было, желтый блок с текстом исключения 1С не требуется.

Возможности

  • Строка цены появляется для счетов с кодом 41, 41.01, 41.02 и других счетов этой группы, если в отчете включено количество.
  • Цена считается отдельно по дебету и кредиту начального остатка, оборота и конечного остатка.
  • На группе и в итоге цена средневзвешенная, а не сумма цен строк.
  • Строка выделена янтарным фоном и не смешивается со строками БУ и количества.
  • Для счета 51 и других нетоварных счетов макет отчета не меняется.
  • Повторное формирование не дублирует поля: перед добавлением проверяется, что путь поля уже есть в схеме.

Выводы

Доработка работает. По счету 41.01 организации Конфетпром ООО за период с 01.01.2020 по 04.10.2026 отчет показывает строку цены под количеством. Цены номенклатуры совпали с независимым запросом к регистру бухгалтерии: 450,00, 300,00, 250,00 и 400,00. Общий итог 353,57 равен 49 500 / 140. Все 15 строк цены окрашены.

По счету 51 строка цены не выводится, контрольные итоги отчета не нарушены. Ошибок в коде расширения проверка не обнаружила. Ограничение касается только внешнего COM-соединения: им нельзя подтвердить перехватчик, это подтверждает сеанс предприятия.
