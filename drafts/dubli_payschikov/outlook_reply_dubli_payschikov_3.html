1. Что видно по двум карточкам

Это с высокой вероятностью один человек, две карточки в справочнике Контрагенты:

  • совпадают имя, отчество, дата рождения, адрес и номер счета в спецрегистраторе;
  • не совпадают фамилия и паспорт: на новой карточке паспорт выдан незадолго до даты списка (31.08);
  • старая карточка относится к январю, новая - к дате начитки 31.08 (и счет на новой открыт той же датой);
  • на обеих уже заполнено свойство "НРД id клиента", но это два разных кода, не один и тот же.

То есть это не "склеили - и снова создалось", а скорее первый заход после смены фамилии и паспорта. Цифры в наименовании карточек - серия и номер паспорта, не ID пайщика (он на обеих пустой).

2. Как система сейчас решает: это новый клиент или нет

На каждую строку файла НРД обработка задает один вопрос: этого человека мы уже знаем? Дерево ниже - как сейчас, шаги не переписываем. Голубым - одна доп. ветка, которой сейчас нет. Желтым - путь этой пары.

Старт. Из файла пришла одна строка: фамилия, имя, отчество, дата рождения, паспорт, код НРД, номер спецдепозитария.
|
+-- Вопрос 1. Есть ли уже карточка с таким же кодом НРД, как в файле?
|-- Да -> это старый клиент. Подставляем карточку. Конец.
Так августовский релиз и должен спасать смену фамилии - если код НРД тот же.
+-- Нет -> идем дальше.
В этой паре: на старой карточке код НРД есть, но другой, не тот, что пришел из файла. Для системы это "не нашли".
+-- Вопрос 2. Есть ли карточка с точно таким же ФИО и той же датой рождения?
Фамилия должна совпасть буква в букву. Паспорт здесь почти не смотрят.
|-- Да -> это старый клиент. Подставляем карточку. Конец.
+-- Нет -> идем дальше.
В этой паре: имя, отчество и дата рождения те же, фамилия уже другая. Для системы полное ФИО не совпало.
+-- Вопрос 2а. Доп. ветка (сейчас ее нет). Совпали сразу все четыре:
имя + отчество + дата рождения + номер спецдепозитария?
Фамилию здесь не требуем. В этой паре все четыре как раз совпали.
|-- Да -> это старый клиент. Новую карточку не создаем.
Сюда эта пара и попала бы. Новый код НРД из файла дописываем на ту же карточку, старый не затираем.
+-- Нет -> как сейчас, идем в вопрос 3.
+-- Вопрос 3. Включено "Создавать контрагентов при начитке"?
|-- Да -> это новый клиент. Создаем карточку.
Сейчас эта пара дошла сюда, потому что ветки 2а еще нет.
+-- Нет -> карточку не создаем, строка остается без контрагента (или ручной выбор).
Коротко: старое дерево не ломаем. Вопрос 1 (код НРД) и вопрос 2 (полное ФИО + дата рождения) остаются как есть. Между "ФИО не совпало" и "создать нового" добавляем только ветку 2а.

В этой паре вопросы 1 и 2 честно ответили "нет": из файла пришли новая фамилия и другой код НРД. Паспорт тоже новый, им эту пару не спасти. Четыре поля ветки 2а совпали - с ней вторая карточка бы не создалась.

Для Натальи

Пара карточек Контрагенты, один фонд, начитка на 31.08. Совпали: имя, отчество, ДР, адрес, номер счета спецрегистратора. Разъехались: фамилия, ДУЛ, свойство "НРД id клиента" (два разных значения, оба заполнены), внешний ID для ПК. IDПайщика пуст. Новая карточка по дате исторических реквизитов и дате открытия счета садится на 31.08; старая - на 30.01. Паспорт на новой выдан за несколько дней до списка.

ПолучитьКонтрагент: шаг 1 по новому НРД id старую не находит; шаг 2 - точное ФИО+ДР, фамилия другая. Поиск по ДУЛ закомментирован и в этом кейсе все равно был бы мимо. Автосоздание включено. Отсюда новая карточка с новым НРД id.

Для ТЗ дерево ПолучитьКонтрагент не переписывать. После пустого ФИО+ДР добавить ветку: имя + отчество + ДР + номер счета спецдепозитария. Если нашли - старый клиент, новый НРД id дописать, старый не затирать. Паспорт в ключ не ставить.

Файл начитки все еще полезен как подтверждение, что в строке НРД был именно новый id. На диагноз по этой паре это уже не похоже на блокер.
