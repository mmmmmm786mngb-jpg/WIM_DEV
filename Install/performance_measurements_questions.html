2. Контрольные вопросы к внедрению

2.1 Перенос подсистемы БСП

  • Какая версия подсистемы "Оценка производительности" выбрана как базовая (ДУ 20 / ПИФ / МО)?
  • Есть ли план унификации версий для последующей выгрузки в ЦУП КИП?
  • Подготовлен ли перечень зависимостей при переносе (общие модули, роли, регламентные задания)?

2.2 Список ключевых операций

  • Согласован ли полный список операций с бизнесом и сопровождением?
  • Включены ли внешние отчеты и редкие ночные регламенты?
  • Есть ли ответственный по каждой операции (владелец SLA)?

2.3 Качество метрик

  • Во всех замерах передается ВесЗамера (число обработанных сущностей)?
  • Заполняется ли комментарий JSON с техническими параметрами (например, число потоков)?
  • Разделяются ли измерения по контурам: интерактив, регламент, интеграции?

3. Риски и точки отказа

  • Риск: неполный список операций приведет к ложной картине производительности.
  • Риск: отсутствие веса замера не даст сравнивать результаты между днями.
  • Риск: разные версии подсистемы между базами нарушат экспорт и сопоставимость данных.
  • Контрмера: утвердить матрицу "операция - ответственный - SLA - метрика веса".

4. Практический план запуска

  1. Перенести и включить подсистему в ДУ 15.
  2. Инструментировать ключевые процедуры: "НачатьЗамер" и "ЗавершитьЗамер".
  3. Зафиксировать JSON-формат комментария замера.
  4. Согласовать каталог ключевых операций с бизнесом.
  5. Подготовить регулярный HTML-отчет по замерам.
