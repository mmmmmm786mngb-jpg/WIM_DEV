1. Цели поля и бизнес-назначение

Поле МастерПортфель реализует связь "подчиненный портфель -> главный портфель". На практике оно используется как источник "базового договора" в отчетных формах, когда нужно агрегировать данные по группе портфелей и выводить единые реквизиты договора.
  • Технический тип: ссылка на тот же справочник (CatalogRef.Портфели).
  • Определено в: Catalogs/Портфели.xml.
  • Выведено в UI формы портфеля: Catalogs/Портфели/Forms/ФормаЭлемента/Ext/Form.xml.

2. Фактический паттерн использования в коде

Основной алгоритм: если Портфель.МастерПортфель пустой, используем сам портфель; если заполнен - используем мастер-портфель как договор/шаблонный источник реквизитов.

4. Что это дает уже сейчас

  • Унификация "договорных" реквизитов в отчетах без дублирования на каждом портфеле.
  • Возможность сворачивать и анализировать данные по группе портфелей.
  • Сохранение обратной совместимости: если мастер не заполнен, используется обычный портфель.

5. Ограничения текущей реализации

Использование МастерПортфель сейчас сосредоточено в отчетном контуре. Массового сквозного применения в расчетных модулях учетной политики, параметров и регламентных операций пока не видно.
  • Нет единого общего метода "получить шаблонный портфель для расчета".
  • Часть алгоритмов все еще ориентирована на прямой Портфель.
  • Для полноценной модели "шаблон" нужно стандартизировать правило чтения настроек через мастер-портфель.

7. Рекомендуемые шаги внедрения

  1. Закрепить единый сервисный метод: "ЭффективныйПортфельДляНастроек(Портфель)".
  2. Перевести чтение параметров/учетной политики на правило: сначала мастер-портфель, затем портфель.
  3. Применить правило в пуловых регламентных операциях и документах-основаниях.
  4. Добавить тесты на оба сценария: с заполненным и пустым МастерПортфель.
  5. Подготовить матрицу модулей, где прямой Портфель должен быть заменен на эффективный.
