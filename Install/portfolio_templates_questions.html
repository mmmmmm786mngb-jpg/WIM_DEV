Шаблоны портфелей: единая учетная политика по пулу

Вопросы и контрольные точки по реализации модели, где розничные договоры объединяются в пул и используют единые настройки через шаблон договора ДУ.

Инфо #17a2b8 Успех #28a745 Риск #dc3545

1. Бизнес-идея

Для объединенных договоров ДУ (по признаку "Пул"/"Стратегия"/"Продукт") учетная политика, котировки, вознаграждение и отчетность должны задаваться один раз на шаблонном договоре и применяться ко всем участникам пула.

Ключевые сущности

  • Справочник "Пулы": добавить реквизит ШаблонДоговораДУ (тип: ДоговорДУ).
  • Шаблонный договор хранит единую учетную политику и настройки расчета.
  • Для внепуловых договоров остается текущий алгоритм (настройки в разрезе договора).

Что уже есть в базовой WIM_FIn

  • Catalogs/Пул.xml - отдельный справочник "Пул".
  • Catalogs/Портфели.xml - в портфеле есть реквизиты Пул и МастерПортфель.
  • Documents/ПуловаяСделка.xml - документ с реквизитом Пул и пуловым сценарием.
  • CommonModules/ПуловыеОперации/Ext/Module.bsl - сервисный модуль пуловых операций.
  • DataProcessors/Тест_Сценарный_ПуловыеОперации/Ext/ObjectModule.bsl - набор сценарных тестов по пуловой логике.

2. Вопросы по архитектуре и данным

Тема Вопрос Критерий готовности
Модель пула Где хранится признак принадлежности договора к пулу и как обеспечивается его актуальность? Есть единое место чтения и обновления признака.
Шаблон договора Какие настройки строго читаются из шаблона, а какие остаются индивидуальными? Утвержден перечень полей "из шаблона" и "индивидуально".
Обратная совместимость Как ведут себя алгоритмы для договоров вне пула? Полностью сохраняется текущий сценарий без регрессии.
Миграция Как переносить существующих клиентов в новую схему? Есть сценарий миграции и отката.

3. Что проверить в текущей реализации

  • Проверить и задокументировать текущий механизм "шаблона" через МастерПортфель, который уже используется в отчетных алгоритмах.
  • Определить точки, где чтение параметров идет по портфелю: InformationRegisters/УчетныеПолитики/Ext/ManagerModule.bsl, InformationRegisters/ЗначенияПараметровПортфеля/Ext/ManagerModule.bsl.
  • Проверить пуловое распределение сделок: Documents/ПуловаяСделка/Ext/ObjectModule.bsl (отбор портфелей по Портфели.Пул = &Пул).
  • Проверить, что в целевых местах вместо прямого портфеля используется мастер-шаблон (паттерн Портфели.МастерПортфель).
  • Сформировать карту доработки: где остается логика "по портфелю", а где переводим на "по шаблону пула".

4. Риски и управление ими

  1. Риск данных: смешение пуловых и индивидуальных настроек. Мера: жесткие правила приоритета источника.
  2. Риск производительности: массовые перерасчеты при смене шаблона. Мера: пакетные фоновые задания.
  3. Риск сопровождения: пропуск отдельных мест чтения настроек. Мера: реестр точек обращения и обязательный code review.
  4. Риск миграции: некорректный перевод в пул. Мера: пошаговый пилот на ограниченном наборе договоров.

5. Критерии успеха

  • Единая учетная политика действительно поддерживается в одном месте на пул.
  • Число записей в ключевых регистрах снижается кратно числу розничных договоров.
  • Все внепуловые процессы работают без изменений.
  • Есть тестовый контур с подтверждением корректности расчетов и отчетности.
