Розничное ДУ: бизнес-карта процесса

Формат: для руководителя, владельца процесса и аналитика.

Цель процесса

Обеспечить стабильный ежедневный запуск операций Розничного ДУ с автоматическим выбором режима (Основной или Пользовательский), корректной датой расчета и корректным набором циклов.
Бизнес-риск при неформализованной логике: неверный выбор режима и запуск неправильного набора операций.
Решение: формально зафиксировать правила разницы дат, правила заполнения дополнительной даты и правила назначения циклов.

Постановка пользователя в одном экране

1

Старт

Открывается лист Основной. Т-0 = сегодня, Т-1 = прошлый рабочий день.
2

Ключевая развилка

Если разница Т-0 и Т-1 больше 3 дней, переход в Пользовательский режим.
3

Расчет доп. даты

На границе месяцев рассчитывается дата "Последний день квартала/месяца".
4

Назначение циклов

Для Т-0, Т-1 и дополнительной даты выбираются рабочие циклы.
5

Исполнение

Запуск регламентных операций и обработок по выбранному сценарию.

Бизнес-диаграмма пути решения

START -> Автозаполнение Т-0/Т-1 -> Проверка разницы дат -> (>3) Пользовательский режим -> (<=3) Основной режим + расчет дополнительной даты -> Назначение циклов по правилам квартала/месяца -> Запуск операций и обработок -> END

Критерии качества для бизнеса

Понятно У каждого шага есть цель и ожидаемый результат.

Управляемо Есть явные правила выбора режима и правила исключений.

Риск Любая неоднозначность по датам приводит к операционным ошибкам.

Предложенные исправления

  • Явно определить: разница считается по рабочим дням календаря.
  • Если дополнительная дата пустая, цикл для нее не назначать.
  • Описать полный сценарий Пользовательского режима: ввод, проверки, выход.
  • Добавить таблицу решений для согласования бизнеса и разработки.
