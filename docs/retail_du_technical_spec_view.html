Розничное ДУ: техническая спецификация логики процесса

Формат для разработчика, тестировщика, аналитика. Акцент на формальные правила, состояния и проверяемость.

1. Цель и границы

Цель: однозначно определить выбор режима, расчет дат и назначение циклов для запуска операций.

Триггер: запуск обработки пользователем.

Результат: выполнены регламентные и специализированные операции с корректными параметрами дат.

2. Decision table (ядро логики)

Rule Условие Ожидаемое поведение Тест
R1 РабочиеДниМежду(Т-1, Т-0) > 3 Переход на Пользовательский лист Проверить переключение и блокировку автосценария
R2 РабочиеДниМежду(Т-1, Т-0) <= 3 Остаться на Основном листе Проверить запуск стандартного сценария
R3 месяц(Т-0) = месяц(Т-1) Доп. дата = Пусто Проверить отсутствие значения и цикла доп. даты
R4 месяц(Т-0) != месяц(Т-1) и Т-1 последний день месяца Доп. дата = Пусто Проверить отсутствие значения и цикла доп. даты
R5 месяц(Т-0) != месяц(Т-1) и Т-1 не последний день месяца Доп. дата = ПоследнийДеньМесяца(Т-1) Проверить корректную дату и назначение цикла

5. Замечания и исправления

Проблема: не определена единица измерения разницы дат.
Исправление: считать строго по рабочим дням регламентного календаря.
Проблема: цикл доп. даты назначается даже при пустом значении.
Исправление: назначать цикл доп. даты только при заполненной дате.
Проблема: Пользовательский режим не формализован.
Исправление: добавить обязательные поля, проверки, критерий завершения и возврат.
