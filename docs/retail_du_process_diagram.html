Розничное ДУ: постановка, замечания и исправленная диаграмма процесса

Источник: документ docs/Розничное ДУ.docx. Ниже единый файл в требуемой структуре: постановка задачи -> замечания к логике -> диаграммы -> предложенные исправления.

1) Постановка задачи от пользователя (как в документе)

Непрерывный процесс запуска обработок Розничного ДУ.
Обработка состоит из двух листов: Основной и Пользовательский.
По умолчанию открывается лист Основной.

Автозаполнение дат:
- Т-0 = дата запуска обработки (сегодня)
- Т-1 = предыдущий рабочий день по регламентному календарю

Если разница Т-0 и Т-1 больше 3 дней:
- показать сообщение "Переход в Пользовательский режим"
- открыть лист Пользовательский

Если разница Т-0 и Т-1 меньше или равна 3:
- продолжить работу на листе Основной
- заполнить поле "Дата Последний день квартала/месяца" по правилам:
  1) если месяц Т-0 равен месяцу Т-1 -> поле не заполняется
  2) если месяц Т-0 не равен месяцу Т-1 и Т-1 последний день месяца -> поле не заполняется
  3) если месяц Т-0 не равен месяцу Т-1 и Т-1 не последний день месяца -> поле заполняется последним днем месяца Т-1

Далее назначаются циклы:
- Т-0: если первый рабочий день квартала -> "Ежедневный Цикл Т рабочего дня начало квартала", иначе "Ежедневный Цикл Т рабочего дня"
- Т-1: если последний день квартала -> "Цикл Т-1 последнего дня квартала", иначе "Ежедневный Цикл Т-1 рабочего дня"
- Последний день квартала/месяца: если последний день квартала -> "Цикл Т-1 последнего дня квартала", иначе "Ежедневный Цикл Т-1"

После этого выполняются действия регламентных операций и запусков обработок.

2) Замечания к логике

Критично: не определено, разница дат считается в календарных или рабочих днях.
Критично: не задано правило назначения цикла для поля "Последний день квартала/месяца", когда поле не заполнено.
Высокий риск: сценарий пользовательского листа описан неполно: нет четкого набора шагов и условий возврата.
Высокий риск: объединены две сущности в одном поле: "последний день квартала" и "последний день месяца".
Средний риск: список действий по циклам помечен как неокончательный, значит постановка не полностью тестопригодна.
Средний риск: не формализовано, как считать "первый рабочий день квартала" при переносах/праздниках.

  v

  |

Автозаполнение дат:
  - Т-0 = дата запуска (сегодня)
  - Т-1 = предыдущий рабочий день по регламентному календарю

  |

         - Остаемся на листе "Основной"

  v
Назначение циклов датам:
  - Для Т-0:

  - Для Т-1:
      если Т-1 = последний день квартала ->

  - Для "Последний день квартала/месяца":
      если дата = последний день квартала ->
          "Цикл Т-1 последнего дня квартала"
      иначе (последний день месяца) ->
          "Ежедневный Цикл Т-1"
  |
  v
Выполнение набора действий по выбранным циклам
  |
  +--> Блок регламентных операций (Т-1)
  |      - Запуск, установка/снятие флагов, фильтры, заполнение, создание, ожидание завершения

  +--> Блок обработок

         - Установка даты расчетов = Т
         - Запуск "Начитать"
  |
  v

5) Предложенные исправления (выделены цветами)

Исправление 1 (зеленый): Зафиксировать тип разницы дат: считать по рабочим дням регламентного календаря.
Исправление 2 (зеленый): Если поле "Последний день квартала/месяца" не заполнено, цикл для него не назначается.
Исправление 3 (фиолетовый): Разделить поле на два явных расчетных признака: "ДатаПоследнегоДняМесяца" и "ДатаПоследнегоДняКвартала" (или оставить одно поле, но добавить атрибут типа даты).
Исправление 4 (фиолетовый): Формализовать ветку Пользовательского режима: обязательные поля, валидации, порядок шагов, условия возврата в Основной сценарий.
Исправление 5 (зеленый): Добавить матрицу решений (таблица if/else) для автотестов. 
Рекомендуемая нормализация правил:
1) Разница = РабочиеДниМежду(Т-1, Т-0)
2) Если Разница > 3 -> Пользовательский режим
3) Иначе:
   - если месяц(Т-0) = месяц(Т-1) -> ДатаПоследнегоДня = Пусто
   - если месяц(Т-0) != месяц(Т-1) и Т-1 = ПоследнийДеньМесяца -> ДатаПоследнегоДня = Пусто
   - иначе -> ДатаПоследнегоДня = ПоследнийДеньМесяца(Т-1)
4) Цикл для ДатаПоследнегоДня назначать только если дата заполнена

6) Контрольные примеры

Пример 1:
Т-0 = 10.03.2026, Т-1 = 06.03.2026 -> разница > 3 -> переход на Пользовательский лист

Пример 2:
Т-0 = 12.03.2026, Т-1 = 11.03.2026 -> разница <= 3, месяцы одинаковые -> поле "Последний день..." не заполняется

Пример 3:
Т-0 = 02.03.2026, Т-1 = 27.02.2026 -> разница = 3, месяцы разные, Т-1 не последний день месяца ->
поле "Последний день..." = 28.02.2026
