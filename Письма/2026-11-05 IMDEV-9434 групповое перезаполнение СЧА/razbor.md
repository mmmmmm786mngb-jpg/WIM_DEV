# Разбор: поле Ссылка.РасчетСЧА.Показатель при групповом перезаполнении

Письмо: Вадим Кукушкин, 05.11.2026 18:54, тема "Групповое перезаполение документов".
Задача: IMDEV-9434. Ответ бизнесу: `otvet_kukushkin.html` (HTML для вставки в тело письма).

## Что произошло

После деплоя сохраненные отборы обработки "Групповое перезаполнение документов" сбросились. Кукушкин заново
собрал отбор для перезаполнения СЧА по договорам, где в табличной части "Расчет СЧА" есть конкретная бумага:
строка `Ссылка.Расчет СЧА.Показатель Равно "Закрытый паевой инвестиционный фонд недвижимости "РД"..."`
(вид сравнения "Равно", не "Содержит"). Остальные включенные строки: Дата с 30.10.2026 0:00:00 по
30.10.2026 23:59:59, Договор ДУ.Тип клиента ДУ = Физические лица.

Список документов отбирается как раньше. Кнопка "Перезаполнить" с включенным флагом "Перезаполнять контроль
допустимого уровня риска" дает диалог:

```
Поле не найдено "Ссылка.РасчетСЧА.Показатель"
```

Флаг снят - перезаполнение идет (на скриншоте прогресс 0 из 31).

## Это не сломанный синоним

Строка `Ссылка.РасчетСЧА.Показатель` в ошибке - путь поля компоновки, а не синоним. Синонимы документа
`РасчетСЧА_РСА` доработка IM9434 не меняла.

| Что видит платформа | Имя в метаданных | Синоним |
|---|---|---|
| Узел табличной части | `РасчетСЧА` | Расчет СЧА |
| Реквизит строки | `Показатель` | Показатель |
| Поле ссылки списка | `Ссылка` | Ссылка |

Путь собирается из имен, поэтому в тексте ошибки `РасчетСЧА` без пробела. В дереве доступных полей тот же узел
подписан синонимом "Расчет СЧА". У табличной части `РасчетСЧА` реквизиты `ИсточникПоказателя`, `Показатель`,
`Сумма`.

Список это поле принимает: основная таблица списка при виде "Расчет СЧА/РСА" - `Документ.РасчетСЧА_РСА`.

## Причина

При включенном флаге обработка собирает два набора документов:

1. Расчеты СЧА/РСА - макет `РасчетСЧА_РСА`, поле `Ссылка` типа `ДокументСсылка.РасчетСЧА_РСА`. Путь
   `Ссылка.РасчетСЧА.Показатель` существует, отбор по бумаге работает (31 документ).
2. Документы контроля риска - макет `КонтрольДопустимогоУровняРиска`, поле `Ссылка` типа
   `ДокументСсылка.КонтрольДопустимогоУровняРиска`. Табличной части `РасчетСЧА` у этого документа нет.

Оба набора собирает одна функция формы `ПолучитьМассивДокументовДляПерепроведения(Макет)`. Она копирует все
включенные строки пользовательского отбора списка в настройки макета (`ДобавитьЭлементОтбора`, группы целиком) и
выполняет компоновку. Для макета риска компоновщик не находит путь и выбрасывает "Поле не найдено".

Поля, общие для обоих макетов (с флагом в отборе можно использовать только их): `Дата`, `Номер`, `ДоговорДУ`
и его реквизиты через точку, `ДокументОснование`, `Проведен`, `ПометкаУдаления`, `ВерсияДанных`. Поля только
расчета СЧА (`РасчетСЧА.*`, `РасчетРСА.*`, `СуммаСЧА`, `СуммаРСА`, `СЧА`, `РСА`) с флагом дают ту же ошибку.
Поле `Комментарий` есть в списке, но нет ни в одном макете - отбор по нему падает даже без флага.

## И до IM9434 эта строка давала ошибку

Второй проход по макету риска - типовой код Аванкора (комментарий ASP-139357), он был до IM9434 и сохранен в
теле `&ИзменениеИКонтроль("Перезаполнить")` расширения вне блоков `#Вставка`. Функция
`ПолучитьМассивДокументовДляПерепроведения` IM9434 не менялась.

Прежний порядок (клиент): отбор СЧА -> цикл перезаполнения СЧА -> отбор документов риска по макету риска с тем
же отбором списка -> цикл по риску. С отбором по бумаге и включенным флагом СЧА перезаполнялись, затем на
отборе документов риска возникала та же ошибка "Поле не найдено". Документы контроля риска при этом не
пересчитывались. Если раньше запускали с этим отбором и флагом, документы риска за те даты остались
рассчитанными по старым СЧА.

## Что изменилось после IM9434

Изменилось только место вызова. `Перезаполнить` для всех видов, кроме котировок по пулам, уходит в
`ЗапуститьПерезаполнениеНаСервере`: там до запуска фонового задания читаются оба набора (СЧА и риск, строка
`ПолучитьМассивДокументовДляПерепроведения("КонтрольДопустимогоУровняРиска")`). Ошибка возникает сразу, до
прогресса. Неудачная попытка данные не меняет: ни один документ не перезаписан.

Флаг снят - макет риска не вызывается, перезаполняются 31 СЧА. Документы риска по этим договорам не
пересчитываются.

Логика IM9434 перенесена в CF ДУ начиная с 1.5.30.3 (сверка `vendor_cf_im9434_comparison.html` в проекте задачи).
В выгрузке WORK версия 1.5.30.9, код совпадает с описанным.

## Почему прогон этого не показал

Массовые прогоны СЧА с включенным флагом прошли: день и пул "Розничное ДУ" (21 993 документа, документов риска
нет), день и пул не "Розничное ДУ" (6 161 документ, из них 3 075 контроля риска, ошибок 0). Отбор там был по дате
и по пулу договора - эти поля есть у обоих документов.

Отбора по строке табличной части `РасчетСЧА.Показатель` в прогоне не было.

## Обход без доработок

1. Рекомендуемый, один запуск. С отбором по бумаге посмотреть 31 договор ("Еще -> Вывести список"). Включить
   строку "Договор ДУ В списке" и подбором внести эти договоры. Снять галку со строки по бумаге, убедиться, что
   в списке те же 31 документ, включить флаг, "Перезаполнить". Перезаполнятся те же СЧА и документы риска по
   этим договорам за день; по каждому договору сначала СЧА, затем риск (`ОбработатьПачкуДокументов`).
2. Флаг снят, отбор по бумаге - СЧА перезаполняются. Документы "Контроль допустимого уровня риска" этих
   договоров за дату пересчитать вручную: в документе кнопка "Рассчитать", затем "Провести".
3. Флаг включен, строку по бумаге снять (дата + тип клиента). Работает, но пересчитает СЧА и риск по всем
   договорам физлиц за день.

Обработка "Перепроведение документов" с флагом "С перезаполнением" умеет пересчитывать контроль риска, но
перепроводит все документы выбранных договоров за период - не рекомендуется.

## Исправление в коде (предложение, не сделано)

Перед вызовом макета риска проверять, все ли поля отбора списка есть среди доступных полей отбора макета
`КонтрольДопустимогоУровняРиска` (`КомпоновщикНастроекКомпоновкиДанных.Инициализировать` по схеме макета,
`Настройки.ДоступныеПоляОтбора.НайтиПоле`; обход как в `ДобавитьЭлементОтбора`: включенные строки верхнего
уровня, группы целиком).

- Все поля есть - вызов как сейчас, поведение не меняется.
- Есть поле только расчета СЧА - макет риска не вызывать, вернуть пустой массив и сообщить пользователю, какое
  поле не применено. Документы риска фоновый обработчик берет по договорам и дням отобранных СЧА
  (`ТаблицаРискаПоДокументамСЧА`) - для отбора по бумаге это ровно нужные документы.

Отвергнуто: выбросить из отбора только неподходящие строки (макет риска вернет документы по всем физлицам дня);
убрать вызов макета риска совсем (меняет поведение обычных отборов по дате и договорам); `Попытка` вокруг вызова
(скрывает остальные ошибки компоновки).

Реализация: расширение с заимствованием формы обработки, перехватчик `&Вместо` на
`ПолучитьМассивДокументовДляПерепроведения` и две новые функции проверки; либо передать изменение Аванкору в CF.
На тесте отдельно проверить, что сохраненные отборы списка не сбрасываются после подключения расширения.

Синонимы `Показатель` и "Расчет СЧА" не трогать: путь поля и текст ошибки строятся по именам.

## Где лежат отборы списка

Кнопка "Настройка списка" и вкладка "Отбор" пишут пользовательские настройки динамического списка. В
конфигурации `DynamicListsUserSettingsStorage` пустой, своего хранилища нет: платформа кладет их в стандартное
хранилище системных настроек, в системные таблицы информационной базы, с привязкой к пользователю 1С. На
компьютере Кукушкина эти отборы не хранятся. Тот же вход с другого компьютера видит те же отборы.

Деплой был обычной поставкой конфигурации, не установкой расширения. Поставка системные таблицы настроек не
очищает и на компьютер пользователя их не переносит.

Вывод "форма стала новой, поэтому отборы не подставились" не подтверждается составом поставки IM9434. В
переносе в CF явно сказано форму не менять: элементы, реквизиты и настройки динамических списков не
переносились. Менялся модуль формы (`Перезаполнить` и новые процедуры) и добавлялся модуль менеджера.
Идентификаторы пользовательских настроек списка (`userSettingID`) этой правкой не обновлялись. Почему
сохраненные отборы Кукушкина не открылись после поставки, по этой форме не объясняется.

сеансов; если форма была открыта в этот момент или сеанс завершился иначе чем штатным закрытием, несохраненные
