5. Критичные замечания

C1 Фон НДФЛ: три режима подряд вместо выбора ветки

По ФТ и сценарию Вадима (дни 1–8) регламент раз в день смотрит регистры и запускает «Оплату КЗ» в одном режиме: блокировка или сравнение с б/с или с р/с.

В коде ВыполнитьОбработкуВФонеНДФЛ всегда подряд: (1) НеУчитывать + блокировка + письмо, (2) БрокерскимСчетом + поручения + письмо, (3) РасчетнымСчетом + шаблон/статусы. Проверок 68.01 / начального остатка блокировок / требований как гейтов ветки нет.

Риск: в дни, когда по схеме должна отрабатывать «пустая» ветка р/с или только б/с, обработка всё равно создаёт блокировки/поручения/меняет статусы — расходится с замечаниями заказчика («идёт по другой ветке», 23.07).

C2 Сумма блокировки при учёте остатков на б/с

ТЗ: при флаге «Учитывать остатки» сумма блокировки = Сумма обязательств − Брокерский счет, отбор где б/с меньше обязательства.

Код: всегда СуммаБлокировки = СуммаОбязательства; условие СуммаБрокерскийСчет <= СуммаОбязательства.

C3 Дата блокировки: календарный T−1 вместо рабочего дня

ДатаДок = НачалоДня(НачалоДня(Период) - 1) + 60*60*9;

ТЗ: «ВСЕГДА … Т−1 рабочий день … 09:00». После выходных/праздников дата будет неверной.

C4 Смена статусов: Возврат в цикле

В ИзменитьСтатус… при пустом/чужом основании — Возврат вместо Продолжить. Остальные строки пакета не обновляются. Типовой шаблон CF рассчитан на один документ.

C5 СтрШаблон без аргумента в теме/теле блокировки ВУК

Текст из ТЗ содержит дату; в коде для ветки ВУК %1 без подстановки — падение или битая тема. Для НДФЛ аргумент передан.

6. Высокий риск

H1 Статус начисления меняется не в той точке процесса

Заказчик (24.07): статус менять после создания п/п с р/с, не после поручения перевода б/с→р/с. Вендор в 2.19 оставил смену в обработке и пометил «к обсуждению». Сейчас вызов из СформироватьШаблон (ветка р/с) — может быть рано относительно разборщика выписки.

H2 Шаги 2–3 фона без повторного ЗаполнитьНачислениями

После шага блокировки таблица не перечитывается под новый режим сравнения (вызовы закомментированы). Даже если оставить «все шаги в одном запуске», отбор/суммы будут от режима шага 1.

H3 Приоритет И/ИЛИ в ДанныеДляРассылки

Если ВидРассылки = "Перевод" И СуммаПоручений = 0 ИЛИ СуммаОбязательства = 0

При нулевой сумме обязательства отсекается любая рассылка. В 2.19 чинили кейс некорректной рассылки — этот оператор всё ещё опасен.

H4 Запись документов при непроведённом основании

Отказ = Истина, но создание/проведение продолжается (поручение, блокировка).

7. Средние / низкие

  • M1 Входящий номер поступлений/списаний не инкрементируется (ручной контур; в фоне по ТЗ не нужен).
  • M2 Word COM + busy-wait Задержка на сервере — риск для фонового шага шаблона.
  • M3 Ошибки почты → Info, без ОшибкиВыполнения.
  • M4 Hardcode субсчёта 13W6XW в письмах (совпадает с текстом в тикете — осознанно, но хрупко).
  • L1 Имя файла EPF ≠ Name объекта — путаница при передаче на установку.
  • L2 Нет ФТ ВУК (8836) в комплекте — фон ВУК ревьюить неполно.

8. Что совпало с ТЗ / CF

  • Развитие одной обработки «Оплата КЗ…», не отдельный продукт.
  • Команды фона НДФЛ/ВУК в СведенияОВнешнейОбработке.
  • Пул Розничное ДУ, ФЛ, без уведомления о расторжении.
  • Налоговый период год−1; окно поиска начислений 3 месяца.
  • Объекты блокировки НДФЛ/Вознаграждение — как в ТЗ и предопределённых CF.
  • В фоне НДФЛ нет автосоздания поступлений/списаний с р/с — как согласовал заказчик.
