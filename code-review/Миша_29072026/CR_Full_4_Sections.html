Суть блок-схемы ФТ (один запуск = одна ветка)

68.01 кредит (день запуска, НП = год-1)
  нет  → КОНЕЦ
  да   → ДС заблокированные НДФЛ, начальный остаток на Т-1
           нет  → режим «Не учитывать остатки» + блокировка + Middle
           да   → Требования по ДС (начальный остаток)
                    нет  → режим «Расчетным счетом» + рассылка Settlements
                    да   → режим «Брокерским счетом» + поручения перевода

1.1 Фон НДФЛ не соответствует блок-схеме
Где плохо
Постановка: каждый день — одна ветка (блокировка или б/с или р/с) после проверок 68.01 / блокировок / требований. Заказчик прямо писал: в дни без Требований обработка «не должна создавать документы». 
ВыполнитьОбработкуВФонеНДФЛ:
  режим НеУчитывать + блокировка + письмо
  режим БрокерскимСчетом + поручения + письмо
  режим РасчетнымСчетом + шаблон/статусы
Как исправить
В начале фона выполнить гейты ФТ (или получить уже выбранный режим от менеджера РДУ) и вызвать только одну ветку: 
Если НетСальдо6801 Тогда Возврат; КонецЕсли;
Если НетБлокировокНДФЛ Тогда
  // только блокировка + Middle
ИначеЕсли ЕстьТребованияПоДС Тогда
  // только БрокерскимСчетом + поручения
Иначе
  // только РасчетнымСчетом + Settlements
КонецЕсли;
1.2 Сумма и условие блокировки при учёте остатков б/с
Где плохо
ТЗ: б/с меньше обязательства; сумма = обязательство − б/с. 
СуммаБрокерскийСчет <= СуммаОбязательства
НоваяСтрока.СуммаБлокировки = Выборка.СуммаОбязательства;
Как исправить
// ПроверкаУсловийДобавления
СуммаБрокерскийСчет < СуммаОбязательства

// ЗаполнитьНачислениями
НоваяСтрока.СуммаБлокировки =
  Выборка.СуммаОбязательства - Выборка.СуммаБрокерскийСчет;
1.3 Дата блокировки — не рабочий день
Где плохо
ДатаДок = НачалоДня(НачалоДня(Период) - 1) + 60*60*9;
После выходных получится воскресенье/суббота, а не T−1 рабочий.
Как исправить
Использовать производственный календарь конфигурации / БСП: 
РабочийДень = ПредыдущийРабочийДень(Период);
ДатаДок = НачалоДня(РабочийДень) + 9 * 3600;
1.4 Смена статуса начисления — точка процесса не согласована
Где плохо
Заказчик: статус после п/п с р/с. В 2.19 смена вызывается из СформироватьШаблон; вендор отметил «к обсуждению».
Как исправить
Убрать вызов из этой обработки до фиксации контракта с разборщиком/обработкой п/п; либо менять статус только при появлении документа списания/п/п с р/с.
1.5 Имя файла поставки vs ИмяОбъекта
Где плохо
Файл СозданиеПорученийПоДоговорамДУ_2_19.epf, объект ОплатаКзПоКлиентамРДУ. При установке БСП идентифицирует по Name → перетирает существующую запись.
Как исправить
Переименовать файл в ОплатаКзПоКлиентамРДУ_2_19.epf. Name не менять (это апдейт по 8815/8837).

Раздел 2. Корректность алгоритмов и логики

2.1 После смены режима таблица не перечитывается
Где плохо
СравниватьСБрокерскимиСуммами = "БрокерскимСчетом";
//ЗаполнитьНачислениями(...);  // закомментировано
ПересчитатьСуммуОбязательства();
СформироватьПлатежноеПоручение();
Строки остались от режима «Не учитывать». Фильтры/суммы и создание поручений расходятся с режимом.
Как исправить
Перед каждым режимом (после внедрения ветвления 1.1 — перед единственной веткой): 
ЗаполнитьНачислениями(НачислениеНДФЛ, Истина);
ПересчитатьСуммуОбязательства();
2.2 Цикл смены статусов обрывается на первой «плохой» строке
Где плохо
Если Не ЗначениеЗаполнено(ДокументОснование) Тогда
    Возврат; // выход из всей процедуры
КонецЕсли;
Типовой шаблон CF — на один документ; здесь цикл по ТЧ.
Как исправить
Заменить Возврат на Продолжить в обеих проверках (пустое основание / неподходящий тип).
2.3 Приоритет И/ИЛИ в ДанныеДляРассылки
Где плохо
Если ВидРассылки = "Перевод" И СуммаПоручений = 0
    ИЛИ СуммаОбязательства = 0 Тогда
При СуммаОбязательства = 0 отсекается любая рассылка (в т.ч. не «Перевод»).
Как исправить
Если ВидРассылки = "Перевод" Тогда
  Если СуммаПоручений = 0 Или СуммаОбязательства = 0 Тогда
    Возврат ...;
  КонецЕсли;
ИначеЕсли ВидРассылки = "Блокировка" Тогда
  Если СуммаБлокировки = 0 Тогда Возврат ...; КонецЕсли;
КонецЕсли;
2.4 СтрШаблон без параметра (блокировка ВУК)
Где плохо
СтрШаблон("Коллеги, %1 произведена ... вознаграждения УК");
// нет второго аргумента
Как исправить
СтрШаблон("Коллеги, %1 произведена ... УК", ПериодФормат);
// лучше: дата документа блокировки (T-1 рабочий)
2.5 Фон ВУК: два режима подряд + нет ФТ 8836
Где плохо
РасчетнымСчетом → Заполнить + Поручения + Шаблон
БрокерскимСчетом → Пересчитать + письмо (без Fill)
Отбор «РасчетнымСчетом» требует ДокументБлокировки; шаг создания блокировок в ВУК-фоне отсутствует. ФТ IMDEV-8836 в комплекте CR нет.
Как исправить
Получить ФТ 8836; выровнять ветвление аналогично НДФЛ; при необходимости добавить шаг блокировки или явно требовать уже существующие блокировки Вознаграждение.
2.6 Отказ при непроведённом основании не останавливает запись
Где плохо
Если Основание.Проведен = Ложь Тогда
  Отказ = Истина; ...
КонецЕсли;
// дальше СоздатьДокумент / Записать(Проведение)
Как исправить
Если Отказ Тогда
  Возврат Документы.Поручение.ПустаяСсылка();
КонецЕсли;
То же в БлокировкаДенежныхСредствСоздатьЗаполнить.

Раздел 3. Корректность кода по стандартам

Стандарты 1С / БСП / читаемость / безопасность побочных эффектов.

3.1 Возврат вместо Продолжить в цикле
Где плохо
Нарушение семантики цикла: досрочный выход из процедуры вместо пропуска элемента. Метод: ИзменитьСтатусВознагражденияПриИзмененииСтатусаПлатежногоПоручения.
Как исправить
Продолжить; не копировать «однодокументный» типовой шаблон в пакетный цикл без адаптации.
3.2 СтрШаблон / конкатенация без проверки числа параметров
Где плохо
Платформа падает или даёт непредсказуемый текст при несовпадении плейсхолдеров.
Как исправить
Всегда передавать аргументы; покрыть ветку ВУК тестом/ручным прогоном рассылки.
3.3 Глотание ошибок почты
Где плохо
Попытка
  РаботаСПочтовымиСообщениями.ОтправитьСообщение(...);
Исключение
  ЗаписьЖурналаРегистрации(..., Уровень.Информация, ...); // не Ошибка
КонецПопытки;
Флаг ОшибкиВыполнения не ставится → фон «успешен» без письма.
Как исправить
Уровень Ошибка; ОшибкиВыполнения = Истина; по согласованию с 26.05 детальный отчёт на почту не обязателен, но сбой отправки должен быть виден.
3.4 Ключевые слова / стиль / мёртвый код
Где плохо
Опечатки в UX-текстах («регламетного», «согластно»); закомментированные блоки шагов фона; ПередЗакрытием сразу делает Возврат (контроль рассылки мёртв); no-op НомерВходящегоДокумента = НомерВходящегоДокумента на форме.
Как исправить
Почистить мёртвый код; инкремент номера; восстановить или удалить проверку закрытия формы осознанно.
3.5 Что по стандартам приемлемо
Регистрация БСП (СведенияОВнешнейОбработке), параметры запросов без конкатенации, использование предопределённых ОбъектыБлокировки, ОбщегоНазначения с ServerCall — соответствуют практике конфигурации. БезопасныйРежим = Ложь оправдан Word/COM, но требует контроля среды сервера.

Раздел 4. Оптимизация по скорости

4.1 Busy-wait Задержка — жжёт CPU сервера
Где плохо
Пока ТекущаяДатаСеанса() < КонДата Цикл
КонецЦикла;
Вызывается из рассылки/Word (по 10 сек). В фоне блокирует рабочий процесс вхолостую.
Как исправить
Убрать искусственные паузы; если нужна синхронизация с файлом — явная проверка готовности / retry с паузой ОС, не цикл.
4.2 Word.Application на сервере регламента
Где плохо
COM Word в СформироватьШаблон — тяжёлый, нестабильный на сервере 1С, сериализует задания.
Как исправить
Генерация docx без Word (OpenXML / макет табличного документа / HTML→PDF), либо вынос на выделенный хост с Word вне критического пути регламента.
4.3 Лишняя работа из-за «трёх шагов подряд»
Где плохо
Даже в дни «пустой» ветки код гоняет заполнение/проведение/почту/Word по нескольким режимам. Это и логическая ошибка (раздел 1), и лишняя нагрузка на СУБД/проведение.
Как исправить
Одна ветка на запуск — сразу снижает число запросов и документов в разы.
4.4 Запрос и журналирование
Где плохо
  • Сначала выборка всех договоров РДУ в массив, потом тяжёлый пакет с ВТ и ОстаткиИОбороты.
  • НайтиПоНаименованию("Розничное ДУ") на каждый вызов.
  • Журнал регистрации на каждую строку цикла блокировки (шаги 1.2 / 1.3) — I/O.
  • МАКСИМУМ по ссылкам аналитических счетов — недетерминированно и тяжело при дублях.
Как исправить
  • Кэшировать ссылку пула; соединять договоры во временной таблице запроса без лишнего round-trip.
  • Журнал: старт/итог/ошибки, не каждая строка.
  • Явный выбор аналитического счёта (приоритет / единственный открытый), не MAX(Ссылка).
  • Окно 3 месяца уже есть — сохранить; для НДФЛ при желании сузить до 2 мес. по договорённости.
Позитив по скорости
Введение временного окна поиска начислений (2.14) — правильный шаг; без него полный срез статусов «Новый» был бы ещё тяжелее.
