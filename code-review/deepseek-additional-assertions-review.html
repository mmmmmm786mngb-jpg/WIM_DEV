1. Заключение

Тип заключения Ограниченное

Карту модуля можно принимать. Диагноз дефектов и оценку числа запросов принимать нельзя.

Сторонний разбор верно описал линейный оркестратор: один writer, один менеджер временных таблиц, два вложенных цикла, подготовка фактов до цикла и очистка внутри цикла. На этом надежность разбора заканчивается. Сравнение в ЕстьУтвержденияСОтборомФактов объявлено багом из-за неверного чтения итогов запроса. Обход уже выполненной выборки объявлен N+1. Нижняя граница "2N запросов" из текста модуля не следует.

Практический вывод: схемой якорей пользоваться можно. Пункты про баг отбора фактов и про курсор СУБД нужно вычеркнуть до любого решения об оптимизации.

4. Разбор по пунктам

Линейный оркестратор описан верно

F-01, F-02
Утверждение Весь функционал идет в одном потоке. Параллельного пула нет. Якоря: группировка, подготовка фактов, ВыполнитьУтверждение, пакет УНИЧТОЖИТЬ.
Основание ПайплайнДопУтверждений создает один writer и один контекст временных таблиц. Дальше два цикла Пока Следующий(). В тексте нет запуска фоновых заданий и нет второго менеджера. Подготовка фактов стоит до цикла. Очистка стоит внутри цикла по утверждениям. АгрегироватьСтатистикуV1 обходит уже собранные разделы.
Следствие Эту часть можно цитировать как карту модуля. Узкое место оркестратора действительно последовательный вызов ядра V1 на общем менеджере временных таблиц.

Факт про прогресс верный, причинная связь нет

F-03
Утверждение ДлительныеОперации.СообщитьПрогресс вызывается только в начале, и это следствие линейной архитектуры.
Основание Вызов в начале пайплайна в тексте есть, внутри циклов его нет. Тот же линейный цикл может сообщать прогресс на каждом утверждении. Отсутствие промежуточного прогресса - пропуск вызова, а не свойство однопоточности.
Следствие Факт оставить. Фразу "следствие линейной архитектуры" убрать.

Баг сравнения отбора фактов не подтверждается

F-04
Утверждение Ссылка - ссылка на утверждение, УтверждениеБезОтбора - флаг 0 или 1, поэтому сравнение почти всегда истинно и общие временные таблицы готовятся всегда.
Основание Функция обходит выборку ПоГруппировкам и не вызывает вложенный Выбрать(). На записи группировки поля из ИТОГИ содержат агрегаты, а не исходные значения детальной строки.
ИТОГИ
    СУММА(УтверждениеБезОтбора),
    КОЛИЧЕСТВО(Ссылка)
ПО
    Ракурс

Ссылка на группировке - количество утверждений ракурса. УтверждениеБезОтбора - сумма флага "без отбора": 0, если отбор фактов есть, и 1, если его нет. Равенство означает, что в ракурсе нет ни одного утверждения с отбором. Неравенство означает, что такое утверждение есть. Функция на первом таком ракурсе возвращает Истина.

Следствие Это сжатая запись условия "есть хотя бы один отбор фактов", а не сравнение ссылки с числом. Пункт как дефект отклоняется. Отдельно верно другое: если отбор стоит хотя бы у одного утверждения, тяжелый набор строится один раз на весь запуск.

N+1 на выборке группировок нет

F-05
Утверждение Каждый Следующий() внешнего цикла - неявный курсор по СУБД. Вложенный Выбрать() на больших объемах дает N+1, особенно пока занят менеджер временных таблиц.
Основание Запрос выполняется один раз, в ДополнительныеУтвержденияПоРакурсамV2. Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам) читает уже полученный результат платформы. Повторных обращений к СУБД этот обход не создает. Занятость менеджера временных таблиц на чтение этой выборки не влияет: выборка и менеджер - разные объекты.
Следствие Пункт отклоняется целиком. Единственный запрос списка остается дешевым и вне горячего цикла.

Нижняя граница 2N не следует из модуля

F-06
Утверждение На каждое утверждение минимум один round-trip вычисления и один round-trip очистки. При N утверждениях минимум 2N запросов.
Основание Очистка сразу выходит, если текст УНИЧТОЖИТЬ пуст. Это утверждения, которые не создали таблиц поверх базового набора. Число запросов внутри ВыполнитьУтверждение в модуле V2 не видно: ядро может выполнить один пакет или несколько. Поэтому пол "2N" не доказан. Потолок тоже не "2N": ядро может быть тяжелее одного запроса.
Следствие Формулировку заменить. Для этого модуля видно N синхронных вызовов ядра и до N очисток. Плюс один запрос списка и ноль или один запрос подготовки фактов.

Мелкие стоимости очистки раздуты

F-07, F-08
Утверждение Вызов ОбщегоНазначения.РазделительПакетаЗапросов() в сборке строки и новый Запрос на каждой итерации - заметная компиляция. Удержание всех подготовленных фактов в памяти СУБД на время обхода - минус.
Основание Разделитель пакета возвращает границу пакета запросов. Это не обращение к СУБД. Короткий УНИЧТОЖИТЬ имеет свою стоимость, но без замера она не сопоставима с запросом самого утверждения. Общий набор фактов как раз для того и держится, чтобы не строить его заново на каждой итерации. Это уже сделанная оптимизация V2, а не дефект.
Следствие Очистку оставить в карте как условный round-trip. Не ставить ее в один ряд с ядром, пока нет пошагового времени. Удержание базовых таблиц описать как расчетное свойство пайплайна.

В карту V2 попало содержимое другого файла

F-09
Утверждение В ядре нужно искать построчные формулы {expr}, обход РезультатыВалидации и ЗаменитьВыраженияПлейсхолдерами с регекспами на каждой строке.
Основание В модуле V2 этих имен нет. Есть один вызов ДополнительныеУтвержденияXBRL.ВыполнитьУтверждение. Все, что внутри него, для этого разбора остается гипотезой. Верно только место вызова и то, что ядро получает общий менеджер, а после возврата рабочие таблицы уничтожаются.
Следствие Поиск этих конструкций допустим как план чтения V1. В доказанную карту V2 его не включать.

Имена механизмов параллелизма указаны неверно

F-10
Утверждение Параллелизма нет ни через ФоновыеЗадания, ни через Асинх.Выполнить, ни через пул. Для нарезки предложен ФоновыеЗадания.ВыполнитьВФоне.
Основание Отсутствие пула в этом модуле подтверждается. Имена методов нет. У платформы запуск фонового задания - ФоновыеЗадания.Выполнить. Длительная операция БСП запускается через ДлительныеОперации.ВыполнитьВФоне. Серверный Асинх не создает второй поток исполнения запросов. Сам пайплайн уже может идти внутри одного длительного задания: на это указывает СообщитьПрогресс, но задание стартует снаружи модуля.
Следствие Вывод "этот модуль сам работу не распараллеливает" оставить. Рекомендацию по запуску переписать на существующие методы. Ограничение про несериализуемый менеджер временных таблиц верное: воркеру нужна своя копия либо заранее записанная таблица фактов.

Что в разборе не разобрано

F-11
Пропуски Ниже факты того же модуля, без которых вывод об оптимизации неполный.
Основание
  • После проверки отбора фактов выборка уже пройдена. Перед основным циклом стоит Сбросить(). Без него повторный обход пуст. Это штатная связка.
  • В запросе группировки нет УПОРЯДОЧИТЬ ПО. Порядок разделов и профиль времени зависят от плана. Итог проверки от порядка не зависит.
  • В вызов ядра передаются пустая строка, повторно версия отчета и Ложь. По месту вызова Ложь означает, что общий набор фактов уже подготовлен и заново его строить не нужно.
  • НеВычислено прибавляется к числу успешных утверждений и не прибавляется к числу успешных результатов. На скорость не влияет, колонку "ОК" раздувает.
  • В журнал пишется только длительность всего пайплайна. Долю подготовки, ядра и очистки из этого модуля не вывести.
  • Исключение закрывает раздел и прерывает весь этап: оставшиеся утверждения не считаются.
  • Java-валидатор считает формулы по уже загруженному набору фактов. Здесь каждое утверждение заново строит рабочие таблицы поверх одной общей заготовки. Разница не сводится к наличию цикла.
Предел проверки: ядро ДополнительныеУтвержденияXBRL.ВыполнитьУтверждение и текст СхемаЗапросаПодготовленныхФактов в основание не входили. Любая оценка формул, регекспов и числа запросов внутри одного утверждения остается вне заключения.

6. Исправленная формулировка

Дополнительный этап в ДополнительныеУтвержденияV2 выполняется последовательно в одном вызове. Общие факты, если они нужны, строятся одним запросом. Затем по каждому утверждению синхронно вызывается ядро V1, и при появлении своих временных таблиц выполняется отдельный пакет УНИЧТОЖИТЬ.

  1. Запрос списка по ракурсам один. Его обход не порождает новых запросов.
  2. Проверка отбора фактов читает агрегаты группировки. Общие таблицы готовятся, когда хотя бы у одного утверждения включен отбор актуальных фактов.
  3. Число запросов ядра по этому модулю неизвестно. Очистка есть не на каждом утверждении, а только там, где появились лишние временные таблицы.
  4. Параллелить этот цикл на том же менеджере временных таблиц нельзя. Сначала нужен текст ВыполнитьУтверждение и замер трех шагов: подготовка фактов, ядро, очистка.
CR-XBRL-DA-001. Заключение ограничено текстом оркестратора V2. Замеры СУБД и модуль V1 в объем проверки не входили.
