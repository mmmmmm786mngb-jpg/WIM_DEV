1. Введение

Учебная конфигурация реализует оперативный учет оптовой торговли: приход и расход товаров по складам, партионное списание себестоимости по методу учетной политики (FIFO / LIFO / по средней), отдельный учет услуг, контроль недостачи, ручную корректировку регистров и два отчета на СКД.

Платформа: 1С:Предприятие 8.3.27 (формат выгрузки 2.20). Комплект включает XML-исходники, бинарный файл конфигурации ОперативныйУчетУчебная.cf, алгоритм для разработчика (developer-algorithm.html) и COM-автотесты.

2. Постановка задачи и источник

Откуда взята постановка. Задача относится к типовому блоку «Оперативный учет» экзамена «1С:Специалист по платформе». В открытых источниках публикуются близкие варианты условий (нумерация у разных авторов: 1.1, 1.7 и др.):
  • Обзоры и разборы на Infostart — например, «Сквозной пример задачи оперативного учета (ОУ)…» и статьи по подготовке к «1С:Специалист».
  • Сборники условий задач ОУ (например, navigator1c8.ru, раздел «Специалист 8 / Оперативный учет») — сюжет про оптовую торговлю, приходную/расходную накладные, услуги в одной ТЧ, FIFO/LIFO, учетную политику и отчеты.
  • Учебные разборы (itsale.ru и аналоги) с той же канвой: метод списания из учетной политики, партии, контроль остатков, отчеты.
Официальный билет на экзамене может отличаться деталями, но предметная канва устойчива: оптовая торговля + партии + FIFO/LIFO + услуги + отчеты.

2.1. Классическая постановка (обобщение открытых формулировок)

Компания занимается оптовой торговлей.

  • Поступление — документ «Приходная накладная».
  • Продажа — документ «Расходная накладная».
  • Помимо товаров компания оказывает услуги (например, доставка); товары и услуги указываются в одной табличной части.
  • Учет товаров ведется в разрезе складов (склад в шапке документа).
  • При недостатке товара расходный документ не проводится.
  • Списание себестоимости — по партиям, по методу из учетной политики (в классике обычно FIFO / LIFO; политика действует период — часто год).
  • Нужны отчеты: продажи за период (количество, себестоимость, сумма продажи, прибыль) и остатки товаров на дату.

2.2. Адаптация в комплекте «ОУ_ПартионныйУчет»

В учебной конфигурации постановка сохранена по смыслу и расширена для удобства приёмки и обучения:

3. План разработки

  1. Проектирование регистров и метаданных. Спроектировать РС учетной политики, РН остатков ТоварыНаСкладах (склад + номенклатура + партия), РН оборотов Продажи, справочники (номенклатура, склады, контрагенты, партии), перечисления методов и типов номенклатуры.
  2. Каркас конфигурации. Создать пустую конфигурацию, подсистемы (Главное / Оперативный учет / Сервис), роль ПолныеПрава, командный интерфейс.
  3. Документы прихода и расхода. Реквизиты шапки и ТЧ; проведение через общий модуль УчетТоваров (создание партий на приходе, подбор партий на расходе).
  4. Учетная политика. Модуль УчетнаяПолитикаСервер: метод на дату документа, значение по умолчанию FIFO при отсутствии записей.
  5. Алгоритмы FIFO / LIFO / средняя. Сортировка остатков партий, пропорциональное списание стоимости, для средней — единая цена с сохранением партионного разреза движений.
  6. Товары vs услуги и контроль остатков. Услуги не двигают склад; при недостаче — отказ проведения и сообщение пользователю.
  7. Корректировка регистров и отчеты. Ручные движения; СКД-отчеты продаж и остатков по партиям.
  8. Сборка и приёмка. Выгрузка XML / CF, создание ИБ, пользователь Admin, COM-автотесты с эталонными цифрами, HTML-отчет о прогоне.
Ключевые точки входа в код: УчетТоваров.ВыполнитьПроведениеПрихода, УчетТоваров.ВыполнитьПроведениеРасхода, УчетТоваров.ПодобратьПартииКСписанию, УчетнаяПолитикаСервер.МетодОценкиНаДату. Подробности алгоритмов — в файле developer-algorithm.html.
