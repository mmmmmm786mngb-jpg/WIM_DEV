1. Обзор конфигурации

Конфигурация учебная, без БСП: оперативный учёт оптовой торговли со складом, партиями и тремя методами оценки запасов. Платформа 8.3.27, формат выгрузки 2.20.

3. Учётная политика на дату

Регистр сведений УчетнаяПолитикаУУ: периодичность Day, измерений нет, ресурс МетодОценкиЗапасов.

Чтение метода
  1. При проведении расхода вызывается УчетнаяПолитикаСервер.МетодОценкиНаДату(ДокументОбъект.Дата).
  2. Запрос: срез последних РС на дату документа.
  3. Если записей нет — возвращается FIFO по умолчанию.

Смена метода «с даты» делается новой записью РС (пример: до 15.01 — FIFO, с 15.01 — По средней). Документ расхода 16.01 берёт уже среднюю. 

Функция МетодОценкиНаДату(ДатаДокумента) Экспорт
  // СрезПоследних(&ДатаДокумента) по УчетнаяПолитикаУУ
  // Пустой результат → МетодыОценкиЗапасов.FIFO
КонецФункции

Важно: метод берётся по дате документа расхода, а не по дате прихода партии. Остатки партий при этом всегда читаются на момент времени документа.

4. Алгоритм прихода и партий

Точка входа: ОбработкаПроведения документа ПриходнаяНакладная → УчетТоваров.ВыполнитьПроведениеПрихода.

По каждой строке ТЧ Товары
  1. Пропуск пустой номенклатуры и количества ≤ 0.
  2. Если тип = Услуга — строка пропускается (склад не трогаем).
  3. Если в строке уже есть Партия — обновляем реквизиты элемента; иначе создаём новый элемент ПартииТоваров и пишем ссылку в строку ТЧ.
  4. Добавляем движение Приход в ТоварыНаСкладах: склад из шапки, номенклатура и партия из строки, количество и стоимость (= сумма строки).

Наименование партии

Шаблон: «Номенклатура / dd.MM.yyyy / НомерДокумента».

Перед записью документа

Если сумма = 0, а количество и цена заполнены — сумма пересчитывается как Количество * Цена (и на приходе, и на расходе).

5. Алгоритм расхода

Точка входа: РасходнаяНакладная.ОбработкаПроведения → УчетТоваров.ВыполнитьПроведениеРасхода.

  1. Очистить наборы движений ТоварыНаСкладах и Продажи.
  2. Получить метод оценки на дату документа.
  3. Для каждой строки ТЧ:
    • Услуга — только оборот Продажи, себестоимость 0; складской регистр не трогать.
    • Товар — вызвать ПодобратьПартииКСписанию.
  4. При недостаче — накопить текст сообщения и продолжить обход строк (все сообщения потом).
  5. При успехе — движения расхода по партиям + одна строка Продажи с суммой продажи и суммарной себестоимостью списания.
  6. Если были недостачи — Отказ = Истина, очистить оба набора движений, вывести сообщения пользователю.

Опционально в строке расхода можно указать явную Партию — тогда остатки читаются только по этой партии (удобно для ручного указания).

6. FIFO / LIFO / по средней

Общая функция: УчетТоваров.ПодобратьПартииКСписанию. Сначала запрос остатков партий, затем сортировка и разбор количества.

Получение остатков

Запрос к РегистрНакопления.ТоварыНаСкладах.Остатки на МоментВремени документа, отбор по складу и номенклатуре (и опционально по партии). Соединение со справочником партий даёт ДатаПоступления. Берутся только строки с количеством > 0.

Сравнение методов

Метод Порядок партий Стоимость списания
FIFO По возрастанию ДатаПоступления, затем партия Доля стоимости остатка партии: Стоимость * КолСписать / КолОстаток (если списывается весь остаток партии — вся стоимость)
LIFO По убыванию ДатаПоступления, затем партия Та же пропорция стоимости партии
По средней Хронологический разбор количества (как FIFO по порядку), но цена единая КолСписать * (СуммаСтоимостей / СуммаКоличеств) по всем остаткам номенклатуры на складе; округление до 2 знаков

Числовой пример (из экзаменационных сценариев)

СобытиеКоличество / ценаЭффект
Приход 05.01 10 × 100 = 1000 Партия 1
Приход 10.01 10 × 200 = 2000 Партия 2
Расход 12.01, FIFO, 5 шт продажа 300 Себестоимость 500 (с партии 1)
Остаток после 5×100 + 10×200 = 15 / 2500 Средняя ≈ 166.67
Расход 16.01, По средней, 6 шт продажа 350 Себестоимость ≈ 1000 (6 × 2500/15)
При методе «по средней» движения расхода всё равно пишутся по партиям (количество разбирается по остаткам партий), а стоимость каждой порции считается по единой средней цене. Это сохраняет партионный разрез остатков.

7. Контроль остатков

  • После обхода партий, если ещё осталось списать (ОсталосьСписать > 0), в результат пишется Недостача, массив строк списания очищается.
  • Проведение не делает частичных движений по проблемной строке.
  • На уровне документа: при любой недостаче отменяются все движения документа (и по успешным строкам тоже) — атомарный отказ.
  • Текст: Недостаточно товара "…" на складе "…". Недостача: N.

Сценарий проверки: расход 999 шт при остатке 9 — документ не проводится.

8. Товары и услуги

ОперацияТоварУслуга

Расход Списание партий + Продажи с себестоимостью Только Продажи, себестоимость = 0

Тип читается запросом к справочнику (ОбщегоНазначенияТипНоменклатуры). При пустой ссылке считается Товар.

9. Корректировка регистров

Документ КорректировкаРегистров → УчетТоваров.ВыполнитьПроведениеКорректировки.

  • ТЧ ТоварыНаСкладах: вид движения из перечисления Приход/Расход → ВидДвиженияНакопления; измерения и ресурсы копируются из строки.
  • ТЧ Продажи: прямая запись оборотов (количество, сумма продажи, себестоимость).
  • Автоподбора партий и контроля остатков нет — ответственность пользователя/экзаменатора.

12. Чеклист разработчика

  • Не дублировать логику списания в модулях документов — только вызов УчетТоваров.
  • Любое изменение метода оценки — через РС на дату, не хардкод в документе.
  • При доработке средней помнить: количество по партиям, стоимость по средней.
  • Контроль остатков должен обнулять движения всего документа при отказе.
  • Услуги никогда не создавать партии и не писать в ТоварыНаСкладах.
  • После правок алгоритма прогнать сценарии из README экзамена / task-дока.
