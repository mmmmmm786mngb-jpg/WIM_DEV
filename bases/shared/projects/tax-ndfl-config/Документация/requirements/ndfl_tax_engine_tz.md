# ТЗ: движок расчета НДФЛ и отчетность

## 1. Основание

Документ подготовлен на основании файла `bases/shared/projects/Требования от налогов.xlsx`.

Цель: перевести требования налогового блока в формальную спецификацию для реализации в новой конфигурации 1С.

## 2. Область автоматизации

Система должна автоматизировать:

- расчет налоговой базы по операциям клиентов;
- сальдирование убытков по матрице допустимых связок кодов;
- распределение налоговой базы по ставкам и КБК;
- расчет исчисленного, удержанного, возвращенного, излишне удержанного и неудержанного налога;
- заполнение `6-НДФЛ`, `Приложения 1` и справки для клиента.

## 3. Входные нормативные таблицы

### 3.1 Лист "Коды доходов и расходов"

Содержит:

- соответствие кодов доходов и кодов вычетов;
- правила учета лимитов по совокупной налоговой базе;
- базовые требования к определению налоговой базы.

Базовое правило:

- НалоговаяБаза = Доходы - Вычеты (после сальдирования и применения лимитов);
- если результат < 0, тогда НалоговаяБаза = 0.

### 3.2 Листы "КБК и Ставки"

Содержат матрицы:

- для резидентов;
- для нерезидентов;
- для резидентов по ИИС.

Матрица определяет:

- ставку;
- КБК;
- код дохода;
- код соответствующего вычета (если применимо);
- диапазон лимита налоговой базы.

### 3.3 Листы "Сальдирование убытков"

Содержат:

- допустимые направления сальдирования;
- приоритет сальдирования (где есть очередность);
- формулы распределения убытка РЕПО;
- коды убытков для форм отчетности.

Отдельно ведется для:

- обычного контура;
- контура ИИС.

### 3.4 Листы "Заполнение 6-НДФЛ..." и "Заполнение Справки..."

Содержат:

- состав показателей;
- формулы заполнения;
- особенности распределения по ставкам/КБК;
- контрольные примеры и ожидаемые значения.

## 4. Функциональные требования

### FR-01. Ведение нормативных справочников

Система должна хранить версионируемые нормативные таблицы:

- `КодДохода -> КодВычета`;
- `КодДохода -> Ставка -> КБК -> ДиапазонБазы`;
- матрица сальдирования убытков;
- формулы особых распределений (РЕПО, спецусловия по 1010 и др.).

### FR-02. Расчет налоговой базы

Для налогового периода и физлица система должна:

1) собрать доходы и вычеты в требуемых аналитиках;
2) выполнить сальдирование убытков по матрице;
3) применить ограничения и лимиты;
4) обнулить отрицательную базу;
5) разложить итог по ставкам и КБК.

### FR-03. Сальдирование убытков

Должны поддерживаться:

- прямые пары сальдирования;
- пары с приоритетом (сначала код A, затем код B);
- запрет сальдирования для отдельных кодов;
- распределение убытка РЕПО пропорционально стоимости второй части сделки.

### FR-04. Расчет налоговых сумм

Должны рассчитываться:

- `СуммаНалогаИсчисленная = НалоговаяБаза * Ставка`;
- `СуммаНалогаУдержанная = СуммаПеречисленного - СуммаВозвращенного`;
- `СуммаИзлишнеУдержанного` и `СуммаНеудержанного` по правилам из требований.

### FR-05. Формирование 6-НДФЛ и Приложения 1

Должны формироваться:

- Раздел 1;
- Раздел 2;
- Приложения 1.

Требования:

- формирование по ставкам и КБК (где требуется);
- формирование нарастающим итогом;
- корректная обработка периодов без перечислений/возвратов;
- заполнение строк по формулам и контрольным сценариям.

### FR-06. Формирование справки для клиента

Должна формироваться справка с показателями:

- доходы и вычеты (по кодам и совокупно);
- налоговая база;
- исчисленный/удержанный налог;
- зачет по налогу на прибыль;
- налог в иностранном государстве;
- излишне удержанный/неудержанный налог.

## 5. Алгоритмические требования

### ALG-01. Общий контур расчета

1) Загрузка операций периода.
2) Привязка к кодам доходов/вычетов.
3) Применение матрицы сальдирования.
4) Нормализация вычетов:
- если после сальдирования Вычеты > Доходы по коду, ограничить Вычеты значением Доходов.
5) Расчет совокупной базы по группе.
6) Распределение по лимитам и ставкам.
7) Присвоение КБК.
8) Расчет налога.
9) Формирование выходных таблиц отчетности.

### ALG-02. Лимиты и прогрессивная шкала

Для кодов, где предусмотрены лимиты:

- база разбивается на диапазоны;
- каждая часть диапазона умножается на соответствующую ставку;
- результат отражается по соответствующему КБК.

### ALG-03. Сальдирование по очередности

Если код убытка имеет несколько направлений сальдирования:

- сначала выполняется сальдирование направления с приоритетом 1;
- остаток убытка переносится на приоритет 2;
- далее - по порядку.

### ALG-04. Сальдирование РЕПО

Убыток по РЕПО распределяется:

- пропорционально стоимости ЦБ по второй части РЕПО;
- отдельно на группы ОРЦБ и не ОРЦБ;
- с учетом суммы сделки и НКД (как указано в требованиях).

### ALG-05. Особый случай кода 1010

При превышении лимита 2.4 млн и наличии зачета налога на прибыль:

- для ветки 13% значения дохода, базы и исчисленного налога увеличиваются на сумму зачета;
- для ветки 15% соответствующая часть дохода/базы уменьшается.

## 7. Проверки качества данных

### 7.1 Контрольные проверки

- отсутствие кодов дохода без нормативной привязки;
- отсутствие КБК/ставки для кода и диапазона;
- запрет отрицательной налоговой базы после финального этапа;
- непрерывность диапазонов лимитов;
- проверка сумм отчета: контроль формул по строкам.

### 7.2 Диагностика

Система должна логировать:

- шаги сальдирования (до/после);
- применение лимитов;
- распределение по КБК;
- причины незаполнения строк в формах.

## 8. Требования к отчетности

### 8.1 6-НДФЛ

Обязательно:

- заполнение разделов по правилам периода;
- раздельный и совокупный режимы представления там, где это предусмотрено;
- корректная обработка периодов без перечислений/возвратов.

### 8.2 Приложение 1

Обязательно:

- заполнение по ставкам и КБК согласно нормативам;
- перенос исчисленных/удержанных сумм по формулам;
- отражение специальных случаев (излишне удержанный/неудержанный).

### 8.3 Справка для клиента

Обязательно:

- единые расчетные правила с регламентированной отчетностью;
- показатели должны совпадать с базовым налоговым контуром.

## 9. Нефункциональные требования

- воспроизводимость расчетов за любой закрытый период;
- возможность пересчета при изменении нормативов с хранением версии правил;
- трассируемость: от строки отчета до исходных операций и формул.

## 10. Набор приоритетных тест-кейсов

Минимальный перечень автотестов:

1) Расчет резидента с прогрессивной шкалой и несколькими КБК.
2) Расчет нерезидента (30% + отдельные ветки 15%).
3) Сальдирование с простой парой кодов.
4) Сальдирование с очередностью (первый/второй приоритет).
5) Сценарий, где убыток не сальдируется.
6) Сценарий РЕПО с пропорциональным распределением.
7) Спецсценарий кода 1010 и лимита 2.4 млн.
8) Кейс с положительной разницей для излишне удержанного налога.
9) Кейс с отрицательной разницей для неудержанного налога.
10) Формирование 6-НДФЛ и Приложения 1 по контрольному примеру из требований.

## 11. Этапы реализации

### Этап 1. Нормативный слой

- загрузка и хранение таблиц кодов, ставок, КБК, матриц сальдирования.

### Этап 2. Расчетный движок

- реализация алгоритмов сальдирования, лимитов и разложения по КБК.

### Этап 3. Отчетный слой

- генерация 6-НДФЛ, Приложения 1, справки клиента.

### Этап 4. Контроль и тесты

- автотесты по контрольным кейсам;
- сверка результатов с примерами из исходного Excel.
