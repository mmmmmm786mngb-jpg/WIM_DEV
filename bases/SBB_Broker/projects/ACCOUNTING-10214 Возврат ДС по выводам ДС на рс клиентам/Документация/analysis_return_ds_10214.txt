ACCOUNTING-10214. Возврат ДС ушел на невыясненные
Разбор инцидента 21.09.2026 для коллег
================================================================================

Письмо: Кузьмина Арина, 21.09.2026
Тема: возврат ДС по выводам ДС на р/с клиентам не работает
Кейс: возврат ДС по действующему ДОФР, причина банка - счет получателя закрыт


1. ЧТО СЛУЧИЛОСЬ
--------------------------------------------------------------------------------

Регламент загрузки реестров НРД создает документ "Операции с денежными средствами"
(тип Ввод). Если это банковский возврат вывода на р/с клиента, должен сработать
сценарий ACCOUNTING-10214:

  - флажок "Возврат ДС";
  - основание = исходный вывод;
  - дальше этапы сами делают Перевод ДС и платежное поручение.

Сегодня входящее зачисление от ВТБ легло на невыясненные.
Робот прислал письмо "Невыясненный платеж!" по операции 260921-00076.

Сломалось:
  документ       260921-00076
  сумма          1 000 000 SUR
  п/п            43867
  договор        НЕВЫЯСНЕННЫЕ/ОШИБОЧНЫЕ ПЛАТЕЖИ БПИ
  портфель       Основной портфель

Эталон 30.06.2026 (сработал):
  документ       260630-00001
  сумма          23 000 000 SUR
  п/п            27623
  договор        1006427
  основание      260629-00055
  флажок         Возврат ДС установлен

Сегодняшний кейс - договор действующий, закрыт только банковский счет получателя.
Ожидался вариант как 30.06.2026, а не уход на невыясненные.


2. НАЗНАЧЕНИЯ ПЛАТЕЖА
--------------------------------------------------------------------------------

Сегодня, ВТБ, п/п 43867 (не сработало):
  Возврат средств по ПД № 43867 от 21/09/2026 на сумму 1000000RUB.
  Счет получателя закрыт. Без НДС

Эталон, Альфа-Банк, п/п 27623 (сработало):
  Возврат средств на сумму 23,000,000.00 по п/п № 27623 от 29.06.26
  в связи с закрытием счета получателя

Тестовые XML задачи 10214 (тот же шаблон ВТБ, суммы с точкой):
  Возврат средств по РД Плат.пор. №143726 от 20.06.2024 на сумму 81.60RUB. ...
  Возврат средств по РД Плат.пор. №143700 от 20.06.2024 на сумму 73.85RUB. ...

Номер п/п в банк-клиенте сегодня совпадает (43867 на списании и на возврате).
Формулировка "ПД" вместо "п/п" сама по себе ни при чем.


3. ПРИЧИНА
--------------------------------------------------------------------------------

Автовозврат включается ТОЛЬКО ЕСЛИ:
  1) из назначения не извлекли номер договора (ровно семь цифр подряд);
  2) текст начинается со слова "Возврат".

Сегодня из "на сумму 1000000RUB" функция берет 1000000 как номер договора
(ровно 7 цифр, дальше буквы RUB). Клиента с кодом 1000000 нет.
Ветка возврата даже не вызывается: нет флажка "Возврат ДС" и нет основания
на исходный вывод. Документ уходит на невыясненные.

Почему тесты и июнь прошли:
  81.60RUB / 73.85RUB     - точка рвет цифры, семи подряд нет
  23,000,000.00           - запятые рвут цифры, семи подряд нет
  1000000RUB              - семь цифр подряд, ложный договор

Кейса "целая сумма без разделителей" в тестах 10214 не было.

Цепочка сегодня:
  1. НомерДоговораИзНазначенияПлатежа находит 1000000
  2. ЭтоВозвратДС = Ложь (номер договора не пустой)
  3. ДополнитьДанныеДляЗаполненияПоВозврату не вызывается
  4. НовыйВводДС заполняет невыясненные и шлет письмо робота

Задача ACCOUNTING-15493 закрывала ДРУГОЙ случай: номер п/п в файле НРД
не совпадал с номером вывода (в назначении 163276, в файле 14475).
Тогда добавили запасной поиск вывода по цифрам из назначения.
Сегодня этот код не запускается: он внутри процедуры возврата,
а туда выполнение не заходит.

Если бы ветка возврата включилась, первая группа цифр из назначения
(43867) как раз совпадает с п/п в банк-клиенте.

5. КАК ИСПРАВИТЬ
--------------------------------------------------------------------------------

Рекомендуемый вариант: сначала слово "Возврат", потом номер договора.
Так и было задумано в постановке 10214. Сейчас проверка договора стоит
раньше и перекрывает возврат.

В процедуре СформироватьВводДС поменять порядок:

  ЭтоВозвратДС = СтрНайти(СтрокаДанных.НазначениеПлатежа, "Возврат") = 1;
  Если ЭтоВозвратДС Тогда
      НомерДоговора = "";
      ЗаполнитьДаннымиПоУмолчанию = Истина;
      Уведомить("Получен возврат от банка получателя!");
  Иначе
      НомерДоговора = РаботаСПоручениямиПовтИсп.НомерДоговораИзНазначенияПлатежа(
          СтрокаДанных.НазначениеПлатежа);
      ЗаполнитьДаннымиПоУмолчанию = ПустаяСтрока(НомерДоговора);
      Если ЗаполнитьДаннымиПоУмолчанию Тогда
          Уведомить("Не удалось определить номер договора по назначению платежа!");
      КонецЕсли;
  КонецЕсли;

Дальше существующие ДополнитьДанныеДляЗаполненияПоВозврату и запасной поиск
15493 отработают сами: вывод ищут по сумме и номеру п/п, договор берут
из найденного вывода, а не из семи цифр суммы.

Запасной вариант, если развилку менять нельзя:
  в НомерДоговораИзНазначенияПлатежа не возвращать семь цифр, если сразу
  после них идет валюта (RUB, SUR, USD). Это уже и не закрывает другие
  ложные семерки в тексте банка.

Что не надо чинить:
  разбор "ПД" / "п/п" / "РД Плат.пор." - для текущего текста первая группа
  цифр уже 43867;
  поиск вывода по сумме и номеру - если включить ветку возврата, он сработает.


6. ЧТО ПРОВЕРИТЬ В БАЗЕ
--------------------------------------------------------------------------------

1. Документ 260921-00076: флажок "Возврат ДС" снят, основание пустое,
   договор невыясненных - это следствие, не отдельный сбой.
2. Исходный вывод по п/п 43867 на 1 000 000 (ДОФР 1003084, действующий):
   он должен был стать основанием.
3. РС "Операции по выплате дохода" по этому выводу: тип Вывод, сумма, НомерПП.
4. Сравнить с эталоном 260630-00001 / основанием 260629-00055.


7. МИНИМАЛЬНЫЙ РЕГРЕСС ПОСЛЕ ПРАВКИ
--------------------------------------------------------------------------------

1. Назначение как сегодня (1000000RUB) - ввод с флажком "Возврат ДС",
   основание на вывод 43867, договор 1003084.
2. Тестовые XML 10214 (81.60RUB / 73.85RUB) - действующий и закрытый договор
   как раньше.
3. Эталон июня (23,000,000.00) - без регресса.
4. Кейс 15493: в файле НРД один номер п/п, в назначении другой - запасной
   поиск по цифрам из текста все еще работает.
5. Обычный ввод с настоящим номером ДОФР из семи цифр в назначении -
   по-прежнему находится договор, это не возврат.
