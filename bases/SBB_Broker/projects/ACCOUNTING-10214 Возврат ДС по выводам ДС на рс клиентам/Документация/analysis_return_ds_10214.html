1. Ситуация

Регламент загрузки реестров НРД (API РКО) создает документ «Операции с денежными средствами» с типом Ввод. Если это банковский возврат вывода на р/с клиента, должен сработать сценарий ACCOUNTING-10214: флажок Возврат ДС, основание = исходный вывод, дальше этапы сами делают Перевод ДС и платежное поручение.

Сегодня входящее зачисление от ВТБ на счет НРД 30411810000001001190 легло на невыясненные. Робот прислал письмо «Невыясненный платеж!» по операции 260921-00076.

21.09.2026 - не сработало

Банк-клиент, п/п 43867, сумма 1 000 000. Номер списания и возврата совпадает.

Возврат средств по ПД № 43867 от 21/09/2026 на сумму 1000000RUB. Счет получателя закрыт. Без НДС

В 1С: договор и клиент «НЕВЫЯСНЕННЫЕ/ОШИБОЧНЫЕ ПЛАТЕЖИ БПИ», портфель «Основной портфель».

30.06.2026 - эталон

Банк-клиент, п/п 27623, сумма 23 000 000. Документ 260630-00001.

Возврат средств на сумму 23,000,000.00 по п/п № 27623 от 29.06.26 в связи с закрытием счета получателя

В 1С: флажок «Возврат», основание 260629-00055, договор и портфель 1006427, клиент МТС-Инвест.

Как задумано в 10214 Для действующего ДОФР ввод заполняется как исходный вывод (клиент, договор, портфель, р/счет клиента). Для закрытого ДОФР - невыясненные БПИ, портфель с кодом «номер_», технический р/счет. Сегодняшний кейс - договор действующий, закрыт только банковский счет получателя. Ожидался эталонный вариант, как 30.06.2026.

2. Сравнение назначений

Тестовые XML задачи 10214 - тот же шаблон ВТБ, что и сегодня. Разница только в записи суммы.

Источник Фрагмент суммы в назначении Семь цифр подряд Ветка возврата
Тест 10214, XML НРД на сумму 81.60RUB / 73.85RUB Нет: точка рвет цифры Включается
Эталон 30.06.2026, Альфа-Банк на сумму 23,000,000.00 Нет: запятые рвут цифры Включается
Инцидент 21.09.2026, ВТБ на сумму 1000000RUB Да: 1000000, затем буквы RUB Не включается
«ПД» вместо «п/п» ни при чем Номер п/п из назначения берется как первая группа цифр. Для сегодняшнего текста это 43867 - верно. До этого разбора выполнение не доходит.

3. Причина

Автовозврат включается только если из назначения не извлекли номер договора (ровно семь цифр подряд) и текст начинается со слова «Возврат». Порядок сейчас такой:

1
Ищем 7 цифр

НомерДоговораИзНазначенияПлатежа. Сегодня находит 1000000.

2
Это не возврат

Номер договора не пустой. ЭтоВозвратДС = Ложь. Ветка 10214 пропускается.

3
Клиента нет

Контрагент с кодом 1000000 не находится. Данные вывода не подставляются.

4
Невыясненные

НовыйВводДС заполняет договор по умолчанию и шлет «Невыясненный платеж!».

Корень ошибки Сумма 1000000RUB без пробелов и запятых совпадает по длине с номером ДОФР (7 цифр). Функция поиска договора не отличает сумму платежа от номера договора. В тестах 10214 такого формата суммы не было, поэтому дефект не поймали.

Связанная задача ACCOUNTING-15493 закрывала другой случай: номер п/п в файле НРД не совпадал с номером вывода (в назначении 163276, в файле 14475). Тогда добавили запасной поиск вывода по цифрам из назначения. Сегодня этот код не запускается: он живет внутри ДополнитьДанныеДляЗаполненияПоВозврату, а туда мы не заходим.

5. Как исправить

Рекомендуемый вариант: сначала слово «Возврат», потом номер договора Так и было задумано в постановке 10214: если первое слово назначения «Возврат», это возврат вывода, а не ввод по договору. Сейчас проверка договора стоит раньше и перекрывает возврат.

В СформироватьВводДС поменять порядок:

// Было: сначала 7 цифр, и только если пусто - смотрим "Возврат"
// Надо: сначала "Возврат", договор из назначения для возврата не используем

ЭтоВозвратДС = СтрНайти(СтрокаДанных.НазначениеПлатежа, "Возврат") = 1;
Если ЭтоВозвратДС Тогда
    НомерДоговора = "";
    ЗаполнитьДаннымиПоУмолчанию = Истина;
    Уведомить("Получен возврат от банка получателя!");
Иначе
    НомерДоговора = РаботаСПоручениямиПовтИсп.НомерДоговораИзНазначенияПлатежа(СтрокаДанных.НазначениеПлатежа);
    ЗаполнитьДаннымиПоУмолчанию = ПустаяСтрока(НомерДоговора);
    Если ЗаполнитьДаннымиПоУмолчанию Тогда
        Уведомить("Не удалось определить номер договора по назначению платежа!");
    КонецЕсли;
КонецЕсли;

Дальше существующие ДополнитьДанныеДляЗаполненияПоВозврату и запасной поиск 15493 отработают сами: вывода ищут по сумме и номеру п/п, договор берут из найденного вывода, а не из семи цифр суммы.

Запасной вариант, если менять развилку нельзя

В НомерДоговораИзНазначенияПлатежа не возвращать семь цифр, если сразу после них идет валюта (RUB, SUR, USD) или фрагмент на сумму. Это уже, хуже читается, не закрывает другие ложные семерки в тексте банка.

Что не надо чинить Разбор «ПД» / «п/п» / «РД Плат.пор.» трогать не нужно: для текущего текста первая группа цифр уже 43867. Поиск вывода по сумме и номеру тоже менять не нужно, если включить ветку возврата.

Минимальный набор регресса

  1. Назначение как сегодня: на сумму 1000000RUB - должен создаться ввод с флажком «Возврат ДС» и основанием на вывод 43867, договор 1003084.
  2. Тестовые XML 10214: 81.60RUB / 73.85RUB - действующий и закрытый договор как раньше.
  3. Эталон июня: 23,000,000.00 - без регресса.
  4. Кейс 15493: в файле НРД один номер п/п, в назначении другой - запасной поиск по цифрам из текста все еще работает.
  5. Обычный ввод с настоящим номером ДОФР из семи цифр в назначении - по-прежнему находится договор, это не возврат.

6. Что проверить в базе

  1. Документ 260921-00076: флажок «Возврат ДС» снят, основание пустое, договор невыясненных - это следствие, не отдельный сбой.
  2. Исходный вывод по п/п 43867 на 1 000 000 (ДОФР 1003084, действующий): он должен был стать основанием.
  3. РС «Операции по выплате дохода» по этому выводу: тип Вывод, сумма, НомерПП.
  4. Сравнить с эталоном 260630-00001 / основанием 260629-00055.
