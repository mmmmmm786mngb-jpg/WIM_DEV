1. Зачем этот документ

Jira просит изменить порядок расчета НКЛ по строкам 28 и 29. В коде эти строки уже есть, но считают не то, что написано в названии показателя. Задача аналитика SBB — не «найти кнопку», а зафиксировать правило: какие сделки РЕПО в какую строку, как классифицировать обеспечение ВЛА-1 / ВЛА-2, вычитается ли стоимость ЦБ и одинаково ли это для собственной и клиентской книги.

Важно Это шпаргалка по текущей реализации в SBB. Формулы из вложения Jira нужно наложить сверху. Если вложение расходится с кодом — приоритет у ТЗ бизнеса / риск-офиса, код описывает только факт «как есть».

3. Что такое строки 27 / 28 / 29 по форме

Это блок ожидаемых оттоков по возврату денег, которые брокеру предоставили по РЕПО, в горизонте 30 дней. Строка выбирается по качеству обеспечения (ЦБ), а не по тому, чья это книга — собственная или клиентская.

Код Смысл по названию показателя в отчете Вычет стоимости ЦБ
П27 Оттоки по РЕПО, обеспечение — ЦБ ВЛА-1 Да: отток = ДС к возврату минус величина этих ЦБ (не ниже нуля)
П28 Оттоки по РЕПО, обеспечение — ЦБ ВЛА-2 Да: та же схема, обычно с большим дисконтом, чем у ВЛА-1
П29 Оттоки по РЕПО, обеспечение — ЦБ, которые не ВЛА-1 и не ВЛА-2 По названию формы вычета нет (весь остаток ДС — отток)

Зеркало на притоках (когда брокер сам предоставил деньги под РЕПО): П41 / П42 / П43. В коде П42 сейчас тоже всегда 0 — та же дыра, что и П28, только с другой стороны баланса НКЛ.

Итог НКЛ: П48 = П1 / П47 * 100, где П47 — чистый ожидаемый отток (ЧООДС), а в П19 (итого оттоки) входят и П27, и П28, и П29.

4. Как считает система сейчас (AS-IS)

Фактическое разбиение — по регистру ДС в пути и типу деятельности, не по классу ВЛА обеспечения.

Строка Что реально попадает Источник в SBB Формула суммы
П27 Все незакрытые РЕПО по дилерской книге (остатки ДС в пути Д), срок оплаты в ближайшие 30 дней Документ БиржеваяСделка, режим торгов РЕПО + регистр ДенежныеСредстваВПутиД MAX(0, остаток ДС − рыночная стоимость ЦБ с дисконтом НКЦ)
П28 Ничего. Константа 0 — Нет расчета, нет расшифровки, нет цк/итог
П29 Все незакрытые РЕПО по брокерской книге (остатки ДС в пути Б) по клиентам с правом использования ДС Регистр ДенежныеСредстваВПутиБ + регистр ПравоИспользованияДСКлиентов Весь остаток ДС, без вычета стоимости ЦБ. Нет фильтра 30 дней

Дилерская книга (сейчас = П27)

  • Режим торгов = РЕПО, плановая дата оплаты >= даты отчета и менее 30 дней.
  • Дисконт берется из регистра СтавкиРискаЦентральногоКонтрагента по ЦБ и количеству (диапазон). Если ставки нет — подставляется 100%, стоимость ЦБ обнуляется, в отток уходит весь остаток ДС.
  • Сделки с ЦК и без ЦК разносятся: без ЦК идет в П27, нетто по ЦК участвует в П34 (нетто-оттоки с ЦК).
Сумма П27 по сделке = MAX(0,
    ОстатокДС
    − Количество × (РыночнаяЦена + НКД) × (1 − СтавкаРискаНКЦ / 100)
)

Брокерская книга (сейчас = П29)

  • Остаток ДС в пути Б по сделке РЕПО.
  • Клиент договора есть в срезе ПравоИспользованияДСКлиентов со значением Истина.
  • Нет отбора по 30 дням, нет рыночной цены, нет дисконта НКЦ, нет вычета обеспечения.
  • Покупка дает отток (П29), продажа — приток (П43).
Прямой вывод по коду Название П27 говорит «ВЛА-1», а в выборку попадают все дилерские РЕПО, в том числе с обеспечением не ВЛА-1. Название П29 говорит «не ВЛА-1 и не ВЛА-2», а в выборку попадают все брокерские РЕПО клиентов с правом использования ДС. П28 (ВЛА-2) не реализован.

5. Разрыв: дилер / брокер вместо ВЛА-1 / ВЛА-2

Для постановки удобно держать две оси отдельно. Сейчас система режет только по оси «чья книга».

ВЛА-1 ВЛА-2 Не ВЛА
Дилерская книга (ПутиД, своя позиция) сейчас все в П27 должно быть П28, сейчас тоже в П27 должно быть П29, сейчас тоже в П27
Брокерская книга (ПутиБ, клиент с правом использования ДС) должно быть П27, сейчас все в П29 должно быть П28, сейчас все в П29 сейчас все в П29

Пока аналитик не скажет, режем ли мы обе книги по ВЛА или только дилерскую, разработчик не сможет отличить «досчитать П28 внутри текущей дилерской выборки» от «переклассифицировать каждую сделку РЕПО по ЦБ».

6. Какие строки поедут вместе с 28 и 29

Нельзя менять только две ячейки свода. Связанные показатели:

КодПочему заденет
П19Итого оттоки = сумма, в том числе П27+П28+П29+П34
П34 / П46Нетто с ЦК сейчас берет П27цк и П29цк. Если появится П28цк — его тоже надо включить, иначе нетто с ЦК разъедется
П41 / П42 / П43Зеркальные притоки. П42 = 0 по той же причине, что П28. Если меняем оттоки — симметрия притоков обязательна, иначе ЧООДС поедет в одну сторону
П35, П47, П48Итого притоки, ЧООДС, сам норматив НКЛ (%)
Раздел 2Контрагенты по брокерскому РЕПО сейчас подписаны именем П29 / П43. После сплита часть строк должна сменить показатель
Раздел 3Реестр ЦБ по дилерскому РЕПО сейчас подписан П27 / П41. ЦБ класса ВЛА-2 должны уйти в П28 / П42
Excel / XBRL / почтовая рассылкаТе же вкладки, тема письма «ТАКСОНОМИЯ 7.1»

7. Вопросы, которые аналитик закрывает до разработки

Без ответов на эти пункты код трогать рано. Источник ответов: вложение Jira + риск / отчетность SBB.

1 Классификатор ВЛА. Откуда в SBB берем признак ВЛА-1 / ВЛА-2 / прочее?

  • По ставке риска НКЦ (сейчас для дилерского РЕПО дисконт уже оттуда)? Какой порог ставки = ВЛА-1, какой = ВЛА-2?
  • Отдельный справочник / регистр / список ISIN от риска?
  • ОФЗ и бумаги Минфина всегда ВЛА-1, остальное по списку?

2 Охват книг. Строки 27-29 считаем:

  • только по дилерской книге (ПутиД), а брокерскую оставляем целиком в П29; или
  • по обеим книгам, класс ВЛА важнее, чем «своя / клиентская»?

3 Формула П28. Та же, что у П27 (вычет рыночной стоимости с дисконтом), но другой дисконт? Или фиксированный коэффициент из указания ЦБ (часто для ВЛА-2 это 15%)?

4 Формула П29 после доработки. Оставляем «весь остаток ДС» или тоже вычитаем обеспечение с дисконтом 100% (то есть вычет ноль — тот же эффект)?

5 Горизонт 30 дней. На дилерской книге фильтр есть, на брокерской нет. После доработки брокерские РЕПО дальше 30 дней исключаем?

6 Симметрия притоков. П42 и П43 меняем теми же правилами, что П28 и П29?

7 ЦК. Появляется ли П28цк и входит ли он в нетто П34 / П46 рядом с П27цк и П29цк?

8 Клиенты без права использования ДС. Сейчас брокерские РЕПО таких клиентов в НКЛ не попадают. Это правильно и после доработки?

9 Эталон. На какую отчетную дату сверка с Excel/XBRL прошлого расчета? Что считаем «было» для регресса?

Минимальный пакет в постановку разработчику Таблица: условие отбора сделки → строка (27/28/29 и 41/42/43) → формула суммы → фильтр 30 дней да/нет → участие в нетто ЦК. Плюс правило классификации ЦБ (ВЛА-1 / ВЛА-2 / прочее) с указанием регистра или списка. Без этой таблицы разработка будет угадыванием.

8. Как проверить текущие цифры в базе

Практический прогон аналитика до постановки (на дате последнего расчета НКЛ).

  1. Сформировать отчет 0420454 (7.1) с признаком «Развернутый».
  2. С листа Сводно выписать П27, П28, П29, П41, П42, П43, П19, П34, П47, П48.
  3. Ожидание по текущему коду: П28 = 0, П42 = 0.
  4. Расшифровка П27: список дилерских РЕПО. По каждому ISIN посмотреть ставку риска НКЦ. Если ставка высокая / нет ставки — бумага по смыслу формы скорее не ВЛА-1, но сейчас она сидит в П27.
  5. Расшифровка П29: список брокерских РЕПО. По ISIN оценить, нет ли там ОФЗ / ВЛА-1 / ВЛА-2 — по форме они не должны быть в 29.
  6. Оценить порядок эффекта: сколько из текущего П27 уехало бы в 28 и 29, сколько из текущего П29 уехало бы в 27 и 28. Это и есть материал для ТЗ и для регресса.
Где смотреть сделкуПоля
Документ «Биржевая сделка»Режим торгов РЕПО, вид сделки (покупка/продажа), тип деятельности (Д / Б), ЦБ, количество, контрагент, дата оплаты плановая, биржа
Регистр «Денежные средства в пути Д»Остаток по сделке на конец дня отчета — база дилерского РЕПО
Регистр «Денежные средства в пути Б»Остаток по сделке — база брокерского РЕПО
Регистр «Право использования ДС клиентов»Без Истины на дату клиент в П29 не попадет
Регистр «Ставки риска центрального контрагента»Дисконт обеспечения для дилерской формулы П27
Регистр «Признаваемые котировки»Рыночная цена и НКД ЦБ
