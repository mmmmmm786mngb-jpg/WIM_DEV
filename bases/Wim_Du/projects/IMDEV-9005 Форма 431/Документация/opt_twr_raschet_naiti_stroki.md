# IMDEV-9005: узкое место РасчетTWR (строка 2275 VTBAM_MWR_TWR)

## Замер

`Отчет.VTBAM_MWR_TWR.МодульОбъекта`, строка 2275:

```bsl
СтрокиРазделителя = MV.НайтиСтроки(ПараметрыПоискаСтрок);
```

~77% времени TWR при `MANDATE_STRATEGY`.

## Причина

Для каждого уникального `Разделитель` — полный перебор таблицы MV. При тысячах мандатов и сотнях дней это миллионы операций.

Дополнительно: строка 2230 — `ВводыВыводы.НайтиСтроки` в цикле по всем строкам MV.

## Ограничение проекта

**Базовую конфигурацию МО не меняем.** Внешний отчет `внVTBAM_TWR_MANDATE_STRATEGY` вызывает штатный API:

```bsl
ВТБ_РасчетДоходностиСервер.TWR(...) -> Отчеты.VTBAM_MWR_TWR.TWR() -> РасчетTWR()
```

`РасчетTWR` не экспортная — подменить ее из внешнего отчета без копирования всего контура TWR (~2000 строк) нельзя.

## Предлагаемое исправление (для отдельной задачи в МО / расширении)

В `РасчетTWR` конфигурационного отчета `VTBAM_MWR_TWR`:

1. Индекс `Соответствие` для вводов/выводов по ключу `Разделитель|Период`.
2. `MV.Сортировать("Разделитель, Период")` + один проход с накоплением TWR вместо цикла по разделителям с `НайтиСтроки`.

Полный патч с пометками УДАЛЕНО/ДОБАВЛЕНО — `Отчеты/IMDEV-9005_RaschetTWR_patch_VTBAM_MWR_TWR.bsl`.

## Роль внешнего отчета

Только замеры и воспроизведение вызова TWR с параметрами 0420431. Ускорение — отдельная доработка конфигурации МО.
