Хранение объемных табличных частей документа 0420431

Задача: IMAPPS-37477  |  Документ: РО_XBRL7_1_0420431_СведенияОДеятельностиПоУправлениюЦБ_7119У
Доработка: только базовая конфигурация Аванкор. Внешние обработки (EPF) не меняются.

Суть. Лимит платформы — 99 999 строк в табличной части объекта. При превышении CF перед записью документа сохраняет ТЧ в регистр сведений (ХранилищеЗначений) и очищает ТЧ в документе. При чтении — восстанавливает ТЧ из регистра в объект документа. Реквизит-флаг на документе не добавляется.

2.1. Алгоритм СохранитьПереполненныеТабличныеЧасти

Для каждой ТЧ метаданных документа: Количество = ДокументОбъект[ИмяТЧ].Количество() Если Количество > 99999: ЗаписатьТабличнуюЧасть(Ссылка, ИмяТЧ, ДокументОбъект[ИмяТЧ].Выгрузить()) ДокументОбъект[ИмяТЧ].Очистить() ИначеЕсли ТабличнаяЧастьХранитсяВРегистре(Ссылка, ИмяТЧ): УдалитьТабличнуюЧасть(Ссылка, ИмяТЧ) // объем снова в допустимых пределах

2.2. Алгоритм ВосстановитьТабличныеЧастиВОбъект

Выбрать все записи регистра WHERE ДокументXBRL = Ссылка Для каждой записи: Таблица = ДанныеТабличнойЧасти.Получить() ДокументОбъект[ИмяТабличнойЧасти].Загрузить(Таблица)

Содержимое хранилища — результат ТабличнаяЧасть.Выгрузить() (все колонки + НомерСтроки).

Обязательно. Перед физической записью документа в ИБ:

4. Выгрузка в Ортикон / XBRL — только формы недостаточно

Важно. Восстановление ТЧ только при открытии формы не покрывает серверные сценарии без UI.

4.1. Где в текущей CF используются ТЧ (анализ Wim_Du)

МестоКак читает ТЧДостаточно формы?
ВыгрузитьОтчет(), модуль объекта Циклы Для каждого ... Из Раздел4 (и все разделы 1–7, РеестрЦенныхБумаг) Нет
ОбработкаПроведения Вызывает ВыгрузитьОтчет(), сохраняет .xtdd в присоединенные файлы Нет
Форма, команда «Выгрузить» ДокументОбъект.ВыгрузитьОтчет() через реквизит формы Да, если перед этим было восстановление на форме
EPF заполнения (VTB) Пишет в Раздел4 объекта в памяти, затем Записать() Да — EPF не меняем; ПередЗаписью CF перенесет в регистр
Запросы SQL к Документ....Раздел4 Читают только ТЧ в БД (пустая после переноса) Нет — запросы не увидят данные в регистре

4.2. Восстановление при выгрузке (два варианта реализации)

Почему недостаточно восстановления только на форме. После ПередЗаписью в базе ТЧ пустая; данные лежат в регистре. При проведении документ читается на сервере без UI: в ОбработкаПроведения вызывается ВыгрузитьОтчет(), формируется .xtdd для Ортикон. Если перед этим не восстановить ТЧ в объект, цикл Для каждого ... Из Раздел4 отработает по пустой табличной части. Это не отдельный «вариант C» — это ограничение, которое закрывают варианты A или B ниже (плюс восстановление на форме из п. 3.2 — для просмотра и редактирования).
Вариант A (рекомендуется, минимальные правки): в начале ВыгрузитьОтчет() одна строка: 
ХранилищеТабличныхЧастейXBRL.ВосстановитьТабличныеЧастиВОбъект(ЭтотОбъект);
Существующие циклы XDTO по Раздел4, Раздел2 и т.д. не меняются. Покрывает проведение, ручную выгрузку с формы и любые другие вызовы ВыгрузитьОтчет().

Вариант B (больше правок): переписать циклы выгрузки — читать данные через ПрочитатьТабличнуюЧасть() вместо обращения к ТЧ объекта. Тот же смысл, больший объем diff.

4.3. Схема потоков данных

[Заполнение EPF / ручной ввод] | v ТЧ в памяти объекта (может быть > 99999 строк) | v ПередЗаписью CF: если > 99999 -> регистр + Очистить ТЧ | v Запись документа (ТЧ в БД пустая или <= 99999) | +---> [Открытие формы] -> ВосстановитьТабличныеЧастиВОбъект | +---> [Проведение / ВыгрузитьОтчет] -> ВосстановитьТабличныеЧастиВОбъект | v Циклы XDTO / Ортикон работают с полной ТЧ в памяти

5. EPF VTB Capital — без изменений

Внешняя обработка внЗаполнениеРеглОтчетаПоДоговорамДУ_0420431_71 продолжает: заполнять ОтчетОбъект.Раздел4.Добавить() и вызывать ОбъектНазначения.Записать(). Перенос в регистр выполняет ПередЗаписью документа в CF.
