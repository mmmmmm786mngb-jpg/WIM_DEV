h3. Оптимизация 1: batch TWR через MANDATE_STRATEGY (база МО)



{panel:title=Теория|borderStyle=solid|borderColor=#6554C0|titleBGColor=#EAE6FF|bgColor=#F8F6FF}

В прод-версии для *каждой стратегии* и *каждого COM-соединения* с МО вызывался:

{{ВТБ_РасчетДоходностиСервер.TWR(..., МассивМандатов, ТекущаяСтрока.Стратегия, "MANDATE", ...)}}



Это десятки полных пересчетов TWR через COM.



*Почему нельзя просто один TWR с {{"MANDATE"}} и {{Стратегия = Неопределено}}:*

при {{MANDATE}} и без отбора по стратегии доходность считается *сводно по всему мандату* — значения другие.



*Решение:* режим МО {{"MANDATE_STRATEGY"}} — TWR отдельно для каждой пары *(мандат, нормализованная стратегия)*.

Ключ результата: {{Разделитель = КодМандата + "_" + КодСтратегии}}.

Нормализация стратегии совпадает с логикой запроса ДУ к МО; batch-вызов эквивалентен N отдельным per-strategy вызовам для «общих» стратегий.



*Исключение IS-001:* для индивидуальных стратегий ({{Стратегия = ""}} в запросе МО) сохранен оригинальный вызов {{"MANDATE"}} — один раз на всю группу IS-001.

h3. Оптимизация 2: индекс вместо НайтиСтроки (раздел 1.2)



{panel:title=Теория|borderStyle=solid|borderColor=#6554C0|titleBGColor=#EAE6FF|bgColor=#F8F6FF}

При заполнении {{Раздел1_Подраздел1_2}} для *каждой* строки агрегата выполнялись *два* линейных поиска:

* {{СведенияПоДоговорам.НайтиСтроки(Отбор)}} — 10 полей отбора;

* {{СведенияПоДоговорамЗагруженные.НайтиСтроки(Отбор)}} — проверка «группа уже обработана».



Сложность: *O(N x M)* — строки отчета x договоры во ВТ.



*Решение:* индекс + кэш — построить индекс один раз, читать много раз:

* {{ИндексСтрокПоГруппе}} — {{Соответствие}} «составной ключ -> Массив строк ТЗ»;

* {{ОбработанныеГруппы}} — {{Соответствие}} для O(1) проверки «уже считали»;

* ключ формирует {{КлючГруппыРаздел1_2()}} из 10 полей (нормализация через {{XMLСтрока}}).



Итоговая сложность: *O(N + M)*. Логика подсчета договоров (заключен / прекращен / на конец периода) не изменена.
