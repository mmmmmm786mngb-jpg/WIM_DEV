h3. Оптимизация 3: параллельное вычисление разделов 2–7

{panel:title=Зачем|borderStyle=solid|borderColor=#DE350B|titleBGColor=#FFEBE6|bgColor=#FFFAFA}
*Профилирование* ({{Тесты_замеры_9005.docx}}):

После оптимизаций 1–2 (МO + раздел 1.2) основное время уходит на *получение и расчет данных* по договорам в разделах 2–7 и реестре ЦБ. Эти разделы независимы по пачкам договоров — их можно считать параллельно.

||Сценарий (локальный стенд)||Длительность||
|После опт. 1–2, февраль 2026|~10 мин|
|После опт. 1–2 + *5 потоков*, февраль 2026|*~8 мин* (21:25 – 21:34)|

*Причина:* последовательный расчет разделов 2–7 не использует ресурсы сервера и лицензии при большом числе договоров.
{panel}

{panel:title=Как реализовано|borderStyle=solid|borderColor=#0052CC|titleBGColor=#DEEBFF|bgColor=#F4F5F7}
*Архитектура*

# *Основной сеанс:* полный {{МВТ}}, {{СформироватьВТ_ДанныеПоСтратегиям}}, *раздел 1* (агрегаты по *всем* договорам).
# Список договоров из {{ВТ_Договоры}} делится на N пачек ({{РазбитьМассивНаПачки9005}}).
# Для каждой пачки — *фоновое задание* БСП: команда {{РассчитатьПачкуРазделов9005}} -> {{ВыполнитьРасчетПачкиРазделов9005}}.
# *Воркер:* свой {{МВТ}} с фильтром пачки ({{ОтборПачкиВыкл9005}} / {{ПачкаДоговоров9005}}), временный документ-контейнер *без записи в ИБ*, вызов {{ЗаполнитьРаздел_2_3}} ... {{ЗаполнитьРаздел_7}} + {{ЗаполнитьРазделРеестрЦБ}} *без изменений*.
# Результат ({{ТаблицаЗначений}} табличных частей) -> {{ВременноеХранилище}}.
# Основной сеанс: {{ОжидатьЗавершенияАктивныхЗаданий9005}} + {{СклеитьРезультатыПачек9005}} (конкатенация; для раздела 7 — повторная {{Свернуть}}).

*Управление:* {{ПолучитьКоличествоПотоковЗаполнения9005()}} — по умолчанию *1* (старое поведение); для теста на РЕГР — например, 5.

*Маркировка:* блок {{// IMDEV-9005 ++ ============================================================}} в конце модуля объекта (~стр. 5230+).
{panel}

{panel:title=Ограничения и включение|borderStyle=solid|borderColor=#FF991F|titleBGColor=#FFF0B3|bgColor=#FFFAE6}
* Раздел 1 *не* параллелится — нужны агрегаты по полному набору договоров.
* Требуются: регистрация обработки в БСП, рабочие фоновые задания, достаточно лицензий и соединений с МO в каждом воркере.
* На DR-контуре замеры не проводились (нет баз МO) — проверка на РЕГР/локальном стенде с МO.
* Подробная схема: {{IMDEV-9005_parallel_zapolnenie.html}} в репозитории проекта.
{panel}

{panel:title=Эффект|borderStyle=solid|borderColor=#00875A|titleBGColor=#E3FCEF|bgColor=#F4FFF9}
Дополнительное ускорение *поверх* опт. 1–2 за счет параллелизма; выигрыш растет с числом потоков и объемом данных (разделы 2–7).
{panel}
