Позиция по сути замечания

Замечание по хронологии нарастающего итога подтверждается анализом алгоритма. TWR по определению — цепочка перемножения периодных коэффициентов Rn; накопленная доходность и бенчмарк должны строиться строго в хронологическом порядке периодов внутри каждого разделителя. Любое нарушение порядка обработки строк дает математически неверный нарастающий итог — в том числе «выбросы» и негладкую кривую доходности.

Почему текущий код MO уязвим

  • После расчета Rn накопление TWR выполняется циклом по СтрокиРазделителя = MV.НайтиСтроки(...).
  • Согласно документации платформы 1С, метод НайтиСтроки не гарантирует порядок возвращаемых строк — он зависит от внутренней реализации и может меняться.
  • Попытка «закрыть» порядок через MV.Индексы.Добавить(...) — недокументированная и хрупкая: в конфигурации уже меняли состав индекса (Разделитель, Период → только Разделитель), без явной гарантии хронологии по периоду.
  • Отсюда поведение «на одних кейсах ок, на других — выбросы»: порядок строк может совпадать с хронологией случайно, а не по контракту алгоритма.

Вывод: полагаться на индекс + НайтиСтроки для математики нарастающего итога рискованно. Надежнее явно задать порядок в самом алгоритме.

Предлагаемое решение

Перед накоплением TWR явно отсортировать таблицу по разделителю и периоду и пройти по ней один раз — накапливая доходность и бенчмарк в хронологическом порядке.

Порядок периодов задается в коде сортировкой, а не индексом и НайтиСтроки. Расчет вводов/выводов и периодных коэффициентов Rn на каждую дату остается прежним; меняется только способ накопления нарастающего итога.

Накопление TWR — БЫЛО (текущая MO)

БЫЛО
//MV.Сортировать("Разделитель, Период");  // закомментировано
//MV.Индексы.Добавить("Разделитель, Период");
MV.Индексы.Добавить("Разделитель");

//Расчет TWR
Для Каждого ТекРазделитель Из Разделители Цикл

    ПараметрыПоискаСтрок = Новый Структура("Разделитель", ТекРазделитель.Ключ);
    СтрокиРазделителя = MV.НайтиСтроки(ПараметрыПоискаСтрок);
    // ^ порядок строк НЕ гарантирован платформой

    Rn_Накопленный = 1;
    Rn_НакопленныйБенчмарк = 1;

    Для Каждого ТекСтрока Из СтрокиРазделителя Цикл
        Rn_Накопленный = Rn_Накопленный * ТекСтрока.Rn;
        Rn_НакопленныйБенчмарк = Rn_НакопленныйБенчмарк * ТекСтрока.Rn;
        ТекСтрока.Доходность = Rn_Накопленный - 1;
        ТекСтрока.TWR_Бенчмарк = Rn_НакопленныйБенчмарк - 1;
    КонецЦикла;

КонецЦикла;

Накопление TWR — СТАЛО (предлагаемый вариант)

СТАЛО
MV.Сортировать("Разделитель, Период");  // явный хронологический порядок

ТекущийРазделитель = "#IMDEV9005_NO_DIVIDER#";  // sentinel, не совпадает с реальным разделителем
Rn_Накопленный = 1;
Rn_НакопленныйБенчмарк = 1;

Для Каждого ТекСтрока Из MV Цикл
    // при смене разделителя сбрасываем накопление — новая цепочка TWR

    Если ТекСтрока.Разделитель <> ТекущийРазделитель Тогда
        ТекущийРазделитель = ТекСтрока.Разделитель;
        Rn_Накопленный = 1;
        Rn_НакопленныйБенчмарк = 1;
    КонецЕсли;

    Rn_Накопленный = Rn_Накопленный * ТекСтрока.Rn;
    Rn_НакопленныйБенчмарк = Rn_НакопленныйБенчмарк * ТекСтрока.Rn;

    ТекСтрока.Доходность = Rn_Накопленный - 1;
    ТекСтрока.TWR_Бенчмарк = Rn_НакопленныйБенчмарк - 1;
КонецЦикла;

Что это дает математически: порядок обработки строк = порядок после Сортировать("Разделитель, Период"), то есть хронология по периоду внутри каждого разделителя зафиксирована в коде, а не «надеемся на индекс».

Что это дает технически: убирается вложенный цикл Разделители + НайтиСтроки (~77% времени узкого места TWR по профилю).

Регрессионное тестирование математики

Для проверки эквивалентности (и выявления расхождений из-за порядка) создан внешний отчет:

внСверкиМатематикиРасчетаTWR.erf

Путь: bases/Wim_Du/projects/IMDEV-9005 Форма 431/Отчеты/

Как работает

  1. Пользователь задает период, группировку и список мандатов (как в отчете TWR для формы 431).
  2. Отчет получает исходные данные MV через штатный пайплайн MO (VTBAM_MWR_TWR.TWR()).
  3. На одних и тех же данных независимо выполняются два алгоритма РасчетTWR:
    • БЫЛО — текущий MO: индекс Разделитель + НайтиСтроки;
    • СТАЛО — сортировка по периоду и один проход (код перенесен в отчет);
  4. Сравниваются все строки и все колонки таблицы TWR (10 колонок: Период, Разделитель, MVn, MVn_1, IO, SUM_IO, Rn, Rn_Бенчмарк, Доходность, TWR_Бенчмарк).
  5. Формируется компактный табличный документ: сводка + только расхождения (если есть).

Итог для обсуждения

  • Риск нарушения хронологии при накоплении TWR подтверждается текущей реализацией MO.
  • Индекс + НайтиСтроки не является надежным способом обеспечить этот порядок.
  • Предлагаемый вариант явно сортирует MV и считает TWR в одном проходе — порядок зафиксирован в алгоритме, индекс не нужен.
  • Отчет внСверкиМатематикиРасчетаTWR позволяет на реальных данных MO прогнать регрессию и увидеть, есть ли расхождения между «как сейчас» и «как должно быть по хронологии».
