Отчет доходности МО: пример расчета TWR_Бенчмарк

Объект: Отчет.VTBAM_MWR_TWR  |  Функция: РасчетTWR  |  База: Wim_Mo  |  Режим: TWR (Time-Weighted Return)

Введение

Документ объясняет на числовом примере, почему в режиме TWR колонка TWR_Бенчмарк в отчете МО не является отдельным показателем бенчмарка, а фактически повторяет портфельную доходность (Доходность).

Пример рассчитан для одного мандата за 2 дня, на второй день есть пополнение счета (+500). Такой сценарий типичен для выявления расхождения формул.

Как устроен расчет в МО

Шаг 1. Дневные коэффициенты (для каждого дня периода)

Показатель Формула в коде МО Смысл
Rn (портфель) (MVn - IO) / MVn_1 Доходность дня без влияния ввода/вывода
Rn_Бенчмарк MVn / MVn_1 Относительное изменение стоимости без вычитания IO

Шаг 2. Накопление за период

Колонка отчета Как должно быть логически Как сделано в коде МО
Доходность Произведение всех Rn - 1 Произведение всех Rn - 1
TWR_Бенчмарк Произведение всех Rn_Бенчмарк - 1 Произведение всех Rn - 1

ШАГ 1 Дневные коэффициенты — две разные формулы (строки 2242-2261)

Здесь код намеренно считает портфель и бенчмарк по-разному: для портфеля вычитается IO, для бенчмарка — нет. Это не выглядит как опечатка. 

// Отчет.VTBAM_MWR_TWR / Модуль объекта / Функция РасчетTWR
// Файл: Wim_Mo/SRC/CF/Reports/VTBAM_MWR_TWR/Ext/ObjectModule.bsl

2242|  Если (ТекMV.MVn_1<>0 )  тогда
2243|      Rn = (ТекMV.MVn - ТекMV.IO)/ТекMV.MVn_1;      // портфель: без IO
2244|      Rn_Бенчмарк = (ТекMV.MVn)/ТекMV.MVn_1;        // бенчмарк: MVn/MVn_1
2245|  КонецЕсли;
...
2260|  ТекMV.Rn           = Rn;
2261|  ТекMV.Rn_Бенчмарк  = Rn_Бенчмарк;                 // сохраняется в колонку, но далее...

ШАГ 2 Накопление TWR — подозрительная строка 2283

Вероятная опечатка или недоделка: для Rn_НакопленныйБенчмарк умножается ТекСтрока.Rn вместо ТекСтрока.Rn_Бенчмарк. Из-за этого TWR_Бенчмарк совпадает с Доходность. 

// Отчет.VTBAM_MWR_TWR / Модуль объекта / Функция РасчетTWR
// Файл: Wim_Mo/SRC/CF/Reports/VTBAM_MWR_TWR/Ext/ObjectModule.bsl

2280|  Для каждого ТекСтрока из СтрокиРазделителя Цикл
2281|
2282|       Rn_Накопленный         = Rn_Накопленный * ТекСтрока.Rn;           // OK: портфель
2283|       Rn_НакопленныйБенчмарк = Rn_НакопленныйБенчмарк * ТекСтрока.Rn;  // ??? должно быть Rn_Бенчмарк?
2284|
2285|       ТекСтрока.Доходность    = Rn_Накопленный - 1;
2286|       ТекСтрока.TWR_Бенчмарк  = Rn_НакопленныйБенчмарк - 1;
2287|
2288|  КонецЦикла;

Как могло бы быть (если бизнес подтвердит использование дневного Rn_Бенчмарк):

2283|  Rn_НакопленныйБенчмарк = Rn_НакопленныйБенчмарк * ТекСтрока.Rn_Бенчмарк;

Без комментария в коде и без истории задачи нельзя на 100% утверждать «опечатка» — возможно, так оставили намеренно. Но тогда колонка Rn_Бенчмарк (стр. 2244, 2261) в итоговый расчет не используется, что выглядит нелогично.

ДОПОЛНИТЕЛЬНО Ограничение скачка только для портфеля (строки 2255-2257)

При аномальном дневном Rn > 2 портфельная ставка обнуляется до 1 (без доходности). Для Rn_Бенчмарк такого ограничения нет — но в накоплении бенчмарка все равно используется Rn, поэтому на практике это вторично. 

2255|  Если Rn > 2 тогда     // A.Sakhartsev 2015-08-27
2256|      Rn = 1;
2257|  КонецЕсли;

АНАЛОГ Тот же паттерн в отчете MWR_TWR (строки 1135-1139)

Дублирование логики в старом/параллельном отчете — признак давнего копирования, а не разовой ошибки.

// Отчет.MWR_TWR / Модуль объекта / Функция РасчетTWR
// Файл: Wim_Mo/SRC/CF/Reports/MWR_TWR/Ext/ObjectModule.bsl

1135|   Rn_Накопленный         = Rn_Накопленный * ТекСтрока.Rn;
1136|   Rn_НакопленныйБенчмарк = Rn_НакопленныйБенчмарк * ТекСтрока.Rn;
1137|
1138|   ТекСтрока.TWR          = Rn_Накопленный - 1;
1139|   ТекСтрока.TWR_Бенчмарк = Rn_НакопленныйБенчмарк - 1;

ДЛЯ СРАВНЕНИЯ Режим MWR — бенчмарк считается отдельно (строки 1888-1897)

В том же модуле VTBAM_MWR_TWR, функция РасчетMWR, колонки Доходность и MWR_Бенчмарк в запросе разведены — там формулы действительно разные. 

// Отчет.VTBAM_MWR_TWR / Модуль объекта / Функция РасчетMWR (запрос, фрагмент)

1888|  ... (MVE.Сумма - MVS - SUM_IO) / ACI  ...  КАК Доходность,    // с учетом IO
1896|  ... (MVE.Сумма - MVS) / ACI           ...  КАК MWR_Бенчмарк  // без SUM_IO

Исходные данные примера

Один мандат, 2 торговых дня. На 2-й день клиент вносит 500 (пополнение).

День MV на начало (MVn_1) Ввод/вывод (IO) MV на конец (MVn) Комментарий
1 1 000 0 1 050 Рост стоимости на 5% без движений денег
2 1 050 +500 1 650 Пополнение 500; инвестиционный результат отдельно от ввода

Подневной расчет

День 1 (без вводов и выводов)

Rn = (1050 - 0) / 1000 = 1,0500   (+5,00%)
Rn_Бенчмарк = 1050 / 1000 = 1,0500   (+5,00%)

На день без IO обе формулы совпадают.

День 2 (пополнение +500)

Rn = (1650 - 500) / 1050 = 1150 / 1050 = 1,0952   (+9,52%)
Rn_Бенчмарк = 1650 / 1050 = 1,5714   (+57,14%)

Портфельная формула «отрезает» пополнение: из 1650 вычитается IO=500, остается прирост 1150 от базы 1050. Формула бенчмарка видит полный рост MV с 1050 до 1650.

День Rn (портфель) Доходность дня, % Rn_Бенчмарк «Бенчмарк» дня, % Разница формул
1 1,0500 +5,00 1,0500 +5,00 Нет
2 1,0952 +9,52 1,5714 +57,14 Да

Итог за период: что показывает отчет МО

15,0%
Доходность
1,05 x 1,0952 - 1
15,0%
TWR_Бенчмарк (как в МО)
1,05 x 1,0952 - 1
65,0%
Через Rn_Бенчмарк
1,05 x 1,5714 - 1

ВЫВОД

Отчет МО выводит Доходность = TWR_Бенчмарк = 15,0%. Колонки совпадают, хотя на 2-й день дневные коэффициенты портфеля и «бенчмарка» различались (9,52% vs 57,14%).

Если бы в накопление бенчмарка попадал рассчитанный Rn_Бенчмарк, итог был бы 65,0% — это не «правильный индексный бенчмарк» в финансовом смысле, но показывает, что две заложенные формулы различаются, а в отчет уходит только одна.

Когда проблема не заметна

Период без вводов и выводов (IO = 0 каждый день)

Пример: 1000 → 1050 → 1102,50 без пополнений.

День MVn_1 IO MVn Rn Rn_Бенчмарк
1 1 000 0 1 050 1,05 1,05
2 1 050 0 1 102,50 1,05 1,05
Итог = 1,05 x 1,05 - 1 = 10,25% (обе колонки одинаковы)

При нулевых IO формулы Rn и Rn_Бенчмарк совпадают каждый день, поэтому отчет выглядит корректно, хотя колонка бенчмарка по-прежнему не независима.

Сводка для бизнеса

Часть отчета МО Оценка Комментарий
TWR — портфель (Доходность) OK Классическая логика TWR с учетом IO
TWR — бенчмарк (TWR_Бенчмарк) Вопрос Дублирует портфель; Rn_Бенчмарк не используется в итоге
MWR — портфель и MWR_Бенчмарк OK Отдельные формулы в запросе (другой режим отчета)
Скорость TWR на больших объемах Медленно Вопрос производительности, не искажения цифр

Обнаруженная логическая особенность

TWR_Бенчмарк В режиме TWR показатель «доходность бенчмарка» не является отдельным расчетом: он повторяет портфельную цепочку Rn. На периодах с вводами и выводами сравнение «портфель vs бенчмарк» внутри отчета бессмысленно — цифры будут одинаковыми.

Для принятия решения о доработке нужно согласовать с бизнесом целевую методику бенчмарка в TWR. Технический факт: сейчас в итог не попадает рассчитанный Rn_Бенчмарк.

Основной источник: Отчет.VTBAM_MWR_TWR → Модуль объекта → РасчетTWR → строки 2242-2244 (дневные ставки), 2282-2286 (накопление, ключевая строка 2283). Аналог: Отчет.MWR_TWR, строки 1135-1139. Документ подготовлен для пояснения бизнес-пользователям и аналитикам.
