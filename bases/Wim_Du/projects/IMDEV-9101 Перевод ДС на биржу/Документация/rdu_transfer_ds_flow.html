IMDEV-9101: перевод ДС на биржу (формирование п/п)

Схема контуров создания поручения и платежного поручения для розничного ДУ. EPF: внСинхронизацияНСИ, команда ФоновоеВыполнение (РЗ 07:02 / 120 с).

AvancoreDU РДУ ДУ.СинхронизацияНСИ.ФоновоеВыполнение

ГЛАВНОЕ: отладка без записи в ДО (только чтение)

Обработка внСинхронизацияНСИ при полном запуске ФоновоеВыполнение не только читает из 1С:ДО. Часть процедур пишет обратно в ДО и вызывает веб-сервис ДО. На тестовой базе ДУ при подключении к боевому ДО можно закрыть задачи, изменить договоры и отправить отметки в прод.

СоздатьПоручение, СоздатьПлатежноеПоручение, ПлатежныеПорученияРозничногоДУ, ДобавитьСвязь (регистр интеграции в ДУ) - работают в тестовой базе ДУ, в ДО не пишут.

Что сделать перед отладкой IMDEV-9101

  1. Настройки доп. обработки (Справочник доп. отчетов и обработок -> Синхронизация НСИ с ДО): поле БазаДО укажите на тестовую копию ДО, не на прод. Аналогично АдресВебДО / ПользовательДО / ПарольДО - только тестовый контур.
  2. Отключите РЗ «Синхронизация НСИ с ДО (фоновое выполнение)» на тестовой базе или убедитесь, что в настройках РЗ стоит тестовая БазаДО. Иначе фон каждые 120 с снова дернет ДО.
  3. Для доработки кода (рекомендуется): добавить в EPF флаг РежимТолькоЧтениеДО (реквизит обработки или константа отладки) и в ВыполнитьСинхронизациюНСИ / ВыполнитьКоманду оборачивать вызовы:
    • не вызывать ИсполнитьЗадачиДО()
    • не вызывать СинхронизацияДатыРасторженияДоговоров_в_ДО()
    • в СоздатьНСИ пропускать блок ВнешОбъект.Записать() для контрагентов ДО
    • не вызывать УстановкаПризнакаОтправкиНаБрокерскийСчет()
    Чтение через ПрочитатьДанныеДО, СписокОбъектовИзОткрытыхЗадач, ПолучитьУведомления при этом сохраняется.
  4. Узкий сценарий теста п/п без полной синхронизации: на тестовой ДУ с уже созданными Поручение (Перевод) без ПлатежноеПоручение вызывать только ПлатежныеПорученияРозничногоДУ (интерактивно из формы или через отладчик) - ДО не затрагивается, если не запускать остальной контур.
  5. Проверка после запуска: в журнале регистрации ДО не должно быть новых закрытых задач, измененных внутренних документов и вызовов SetRetailSentToBroker по вашим тестовым договорам.
Минимум для безопасности без правки кода: тестовая ДУ + тестовая БазаДО + выключенный РЗ на прод-ДО. Надежный вариант для разработки: флаг РежимТолькоЧтениеДО в EPF (версия 0.69 IMDEV-9101).

Вывод для IMDEV-9101

Узкое место при росте объема - не пересоздание поручений для старых договоров (его нет), а массовое создание и проведение п/п в ПлатежныеПорученияРозничногоДУ и СоздатьПлатежноеПоручение по договорам с недавней ДатаВводаСредствВДУ.
Поручение создается один раз при появлении нового РДУ-договора из ДО. Для уже существующих договоров при синхронизации выполняется только догон п/п (контур B), если поручение есть, а п/п еще нет.
Вне scope: команда ФоновоеВыполнениеПоручения («Загрузка поручений из ДО», РЗ 09:30) создает Поручение с ВыводИзДУ и не формирует п/п на биржу.
