Тестовый отчет внТестППРозничногоДУ

Инструкция по запуску, заполнению параметров и отладке замеров процедуры ПлатежныеПорученияРозничногоДУ (IMDEV-9101). Отчет автономный: не требует внСинхронизацияНСИ.epf и не подключается к ДО.

База: WIM_DU (тестовая) Файл: Тестирование/внТестППРозничногоДУ.erf Задача: IMDEV-9101

1. Как открыть отчет

  1. Откройте тестовую базу WIM_DU в режиме Предприятие (желательно толстый клиент для отладки).
  2. Меню Файл -> Открыть.
  3. Укажите файл: 
    bases/Wim_Du/projects/IMDEV-9101 Перевод ДС на биржу/Тестирование/внТестППРозничногоДУ.erf
  4. На форме отчета задайте параметры (см. раздел 2) и нажмите Выполнить тест.
Источники отчета (для правки кода и отладки в конфигураторе): 
Тестирование/erf_test_pp_rdu_erf/внТестППРозничногоДУ/Ext/ObjectModule.bsl

2. Параметры формы отчета

Параметр По умолчанию Назначение Рекомендация для отладки
Дата расчета Сегодня Дата, передаваемая в СоздатьПлатежноеПоручение (расчет рабочего дня и времени документа). Оставьте текущую дату или укажите дату, на которую есть поручения в тестовой базе.
Дата начала периода Пусто Нижняя граница отбора договоров по ДатаВводаСредствВДУ. В режиме отладки не используется (см. флаг ниже). Заполняйте только при снятом флаге «Режим теста производительности».
Дата окончания периода Пусто Верхняя граница отбора договоров по ДатаВводаСредствВДУ. Аналогично дате начала — только для режима «как в бою».
Пул розничное ДУ Пул РДУ (GUID IMAPPS-34301) Отбор договоров и поручений по пулу. Проверьте, что в тестовой базе в этом пуле есть документы Поручение с видом операции Перевод.
Ограничение количества 0 (без лимита) Максимум поручений для обработки в одном прогоне. Для первой отладки поставьте 5-10, чтобы быстрее дойти до точки останова в цикле.
Режим теста производительности Включен Вкл: все поручения пула (в т.ч. с уже существующими ПП); перед созданием старые ПП удаляются.
Выкл: отбор как в бою — только поручения без ПП, с фильтром по периоду договоров. 		Для поиска узкого места в СоздатьПлатежноеПоручение держите включенным.
Создавать платежные поручения Включен Если выкл. — только запрос и замер без записи документов. Для полного замера цикла создания — включено. Для проверки только запроса — выключите.

3. Что делает отчет (блоки замеров)

После выполнения в окне сообщений и в табличном документе выводятся замеры:

БлокСодержание
1. Расчет рабочих датПодготовка дат (в режиме отладки период договоров не применяется).
2. Запрос отбора порученийSQL-запрос к Документ.Поручение и Справочник.ДоговорДУ.
3. Удаление существующих ППТолько при включенном режиме теста + создании ПП. Отмена проведения и удаление старых ПП.
4. Создание платежных порученийЦикл вызовов СоздатьПлатежноеПоручение — главный блок для оптимизации.
ИТОГОСводка: найдено / удалено / создано / ошибок / время.

В детализации по строкам — отдельно Удал., мс и Созд., мс на каждое поручение.

4. Где ставить точки останова (отладка)

Отчет автономный. Точки останова ставятся в модуле объекта внешнего отчета внТестППРозничногоДУ, а не в внСинхронизацияНСИ.

4.1. Подготовка отладчика

  1. Откройте исходники отчета в конфигураторе (файл .erf или каталог erf_test_pp_rdu_erf).
  2. Модуль объекта: внТестППРозничногоДУ -> Модуль объекта.
  3. Запустите предприятие в режиме отладки (F5) и откройте отчет.
  4. Установите Ограничение количества = 5 для быстрого входа в цикл.

4.2. Основные точки останова (по приоритету)

Приоритет Процедура / функция Строка (ориентир) Зачем
1 - главная СоздатьПлатежноеПоручение ~271 Узкое место: Заполнить, Записать(Проведение). Сравнивайте время внутри построчно.
2 ВыполнитьТестПлатежныеПорученияРозничногоДУ — цикл Пока Выборка.Следующий() ~150-220 Проверить данные выборки, счетчик итераций, переход к следующему поручению.
3 УдалитьПлатежныеПорученияПоОснованию ~326 Если блок «Удаление» занимает заметное время.
4 ВыполнитьТестПлатежныеПорученияРозничногоДУ — после Запрос.Выполнить() ~130 Проверить количество найденных поручений до цикла.
5 БлижайшийРабочийДень ~290 Редко, но можно проверить запрос к регистру КалендарныеГрафики.

4.3. Пошаговая отладка внутри СоздатьПлатежноеПоручение

Функция СоздатьПлатежноеПоручение(ПоручениеПоДС, ДатаВводаСредствВДУ)

    // [ТО1] вход: проверить ПоручениеПоДС, ДатаВводаСредствВДУ

    ПлатежноеПоручениеОбъект = Документы.ПлатежноеПоручение.СоздатьДокумент();
    ПлатежноеПоручениеОбъект.Дата = БлижайшийРабочийДень(...) + ВремяТекущее();

    // [ТО2] перед Заполнить - замерить отдельно

    ПлатежноеПоручениеОбъект.Заполнить(ПоручениеПоДС);

    // [ТО3] перед Записать - часто самое медленное место

    ПлатежноеПоручениеОбъект.Записать(РежимЗаписиДокумента.Проведение);

    // [ТО4] выход: ссылка на созданный документ

КонецФункции

Рекомендуется поставить точки останова на метках [ТО1]-[ТО4] и сравнить длительность шагов с колонкой Созд., мс в отчете.

4.4. Сверка с боевым кодом (опционально)

Логика в отчете скопирована из обработки. Для сравнения после оптимизации смотрите оригинал:

Обработка/внСинхронизацияНСИ_epf/внСинхронизацияНСИ/Ext/ObjectModule.bsl
  - Процедура ПлатежныеПорученияРозничногоДУ
  - Функция СоздатьПлатежноеПоручение

Изменения сначала отлаживайте в отчете, затем переносите в EPF.

5. Интерпретация результатов

  • Найдено = 0 — в пуле нет подходящих поручений. Проверьте пул, вид операции «Перевод», пометку удаления.
  • Найдено > 0, создано = 0 — смотрите колонку «Ошибка» в детализации; типично ошибка проведения ПП.
  • Блок 4. Создание занимает > 80% ИТОГО — оптимизировать СоздатьПлатежноеПоручение и обработчики документа ПлатежноеПоручение.
  • Блок 2. Запрос медленный — смотреть план запроса, индексы по ДоговорДУ / Поручение.
  • Блок 3. Удаление заметен — возможно много старых ПП на одно поручение; проверить лишние связи.

6. Безопасность и ограничения

ВНИМАНИЕ: отчет изменяет данные в ДУ (удаляет и создает платежные поручения). Запускайте только на тестовой базе WIM_DU.
  • К ДО отчет не подключается — синхронизация с ДО не выполняется.
  • Внешняя обработка внСинхронизацияНСИ.epf не нужна.
  • Режим «как в бою» не пересоздает ПП, если они уже есть (отбор только без ПП).
  • Режим отладки пересоздает ПП — повторные прогоны на одних и тех же поручениях допустимы.
