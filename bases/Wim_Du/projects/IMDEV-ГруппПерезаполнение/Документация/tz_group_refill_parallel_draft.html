Ускорение группового перезаполнения документов

Ответ на письмо «Оптимизация отчетов Аванкора для РДУ». Черновик для согласования. 10.09.2026.

Вы прислали форму обработки «Групповое перезаполнение документов» с видом «Расчет СЧА/РСА» и попросили рассмотреть оптимизацию / запуск потоками. Ниже — как предлагаем сделать это для пользователя и что изменится на экране.

Что сейчас неудобно

Обработка перезаполняет документы по одному, подряд. Пока идёт большой список (много договоров ДУ на одну дату), сеанс занят, нормального окна с процентом нет — только индикатор состояния. На вашем скрине как раз типичный массовый случай: много документов СЧА/РСА по разным портфелям.

Рис. 1. Ваша форма из письма: вид «Расчет СЧА/РСА», флаг контроля риска, список по договорам ДУ.

Что предлагаем

  • Запускать работу «потоками» — несколько портфелей (договоров ДУ) обрабатываются параллельно, а не строго по одному.
  • После нажатия «Перезаполнить» открывается привычное окно ожидания с кружком и процентом (как при формировании регламентных операций).
  • Если включён флаг «Перезаполнять контроль допустимого уровня риска», для каждого портфеля сначала делается СЧА/РСА, и только потом — контроль риска по этому же портфелю.
  • В конце — понятная сводка в окне сообщений (сколько сделано, сколько с ошибкой, сколько времени заняло).
  • Система будет фиксировать длительность прогона в типовом журнале замеров времени (для контроля производительности).
Исключение: вид «Установка котировок ц/б (по пулам)» оставляем как сейчас (там другая логика, без договора ДУ в шапке). Остальные виды из списка обработки — на новом параллельном пути.

Как это будет выглядеть для пользователя

1. Открыли обработку, выбрали вид, нажали «Перезаполнить»

Как сейчас: выбрали «Расчет СЧА/РСА» (или другой вид, кроме «по пулам»), поставили отбор, при необходимости флаг риска — и кнопка Перезаполнить.

2. Появилось окно с кружком и процентом

Форма не «зависает» в молчании: видно, что идёт работа, какой процент пройден, можно нажать Отмена. Пример того, как это будет выглядеть:

Групповое перезаполнение документов
Групповое перезаполнение документов…
Пожалуйста, подождите… 0%
(Обработано 0/2100. Сейчас: расчет СЧА/РСА. Договоров 0/800, потоков 4)
Рис. 2. Макет окна ожидания сразу после запуска.

3. Процент растёт по ходу работы

Тот же экран, но уже с прогрессом:

Групповое перезаполнение документов
Групповое перезаполнение документов…
Пожалуйста, подождите… 35%
(Обработано 735/2100. Сейчас: расчет СЧА/РСА. Договоров 280/800, потоков 4)

Когда доходит очередь до контроля риска (если флаг включён):

Групповое перезаполнение документов
Групповое перезаполнение документов…
Пожалуйста, подождите… 82%
(Обработано 1722/2100. Сейчас: контроль риска. Договоров 650/800, потоков 4)
Процент считается по всем документам прогона (и СЧА, и контроль риска). Для одного портфеля контроль риска всегда только после успешного перезаполнения СЧА/РСА этого же портфеля.

4. Окно закрылось — итог в сообщениях

После окончания видно сводку. Если были сбои по отдельным документам — они перечислены отдельно:

Перезаполнение завершено. Вид: Расчет СЧА/РСА. Документов: 2100, из них риск: 800. Договоров: 800. Успешно: 2090, с ошибкой: 10. Потоков: 4. Затрачено: 12 мин 30 сек. Не удалось перезаполнить документ Расчет СЧА/РСА 000003019076 от 09.09.2026 23:55:12 по причине: … Не удалось перезаполнить документ Контроль допустимого уровня риска … по причине: …

При полном успехе будет только одна итоговая строка. Уже успешно обработанные портфели при частичных ошибках не откатываются.

Итог для согласования: та же привычная обработка и кнопка «Перезаполнить», но массовые прогоны (как на вашем скрине) идут быстрее за счёт параллели по портфелям, с понятным процентом и итогом в сообщениях. Вид «котировки по пулам» — без изменений поведения.

Блок для разработки (техническая постановка)

Ниже — детали реализации. Для бизнес-согласования основной текст выше.

Объект

Обработка ГрупповоеПерезаполнениеДокументов (Сервисные операции → Групповые операции).

Ветвление

ВидРежим
Установка котировок ц/б (по пулам)как сейчас последовательный клиентский цикл (+ замер)
Остальные 10 видов (есть ДоговорДУ)новый диспетчер БСП, пачки по портфелям, окно процента

Виды на новом пути: начисление %%, купон, погашение облигаций, погашение НКД, переоценки (активы/ВР/ДС), расчет СЧА/РСА (+ опц. контроль риска), реформация баланса, установка котировок ц/б.

Константы (без новых)

  • Число одновременных воркеров: МаксимальноеКоличествоПараллельныхПотоков
  • Размер порции (договоров в чанке), по умолчанию 50: МаксимальныйРазмерПорцииДоговоровВПотокеРегл через ОбщегоНазначенияДУ.ПолучитьЧисловуюКонстанту(..., 50)
  • Константу предподготовки регл (3000) не использовать
  • Если потоков 0 / фоновые запрещены — последовательно внутри одного задания диспетчера, окно процента остаётся

Диспетчер и UX

  • Кнопка → ДлительныеОперации.ВыполнитьВФоне (одно родительское задание)
  • Клиент: ДлительныеОперацииКлиент.ОжидатьЗавершение, ВыводитьОкноОжидания, ВыводитьПрогрессВыполнения, ВыводитьСообщения
  • Прогресс пишет только диспетчер: ДлительныеОперации.СообщитьПрогресс
  • Знаменатель процента = число всех документов прогона (СЧА + риск при флаге)
  • Нарезка: группировка по ДоговорДУ, пачка = целые портфели до размера порции; один договор не рвать по потокам
  • Скользящее окно воркеров (как у регл-операций), запуск через обёртку общего модуля
  • Маппинг вид → процедура заполнения на сервере; не использовать клиентский Выполнить("ДокументОбъект." + ...) в воркерах

СЧА + контроль риска

В воркере по каждому портфелю пачки: сначала СЧА/РСА, затем контроль риска того же договора (если есть в выборке). Не гонять риск параллельно со своим СЧА. Ошибка на СЧА → риск этого договора не запускать.

Сообщения

Сводка в окно сообщений + отдельные сообщения по упавшим документам (как в текущем ПереполнитьДокументы).

Замеры

  • Регистр ЗамерыВремени, ключ ДУ.ГрупповоеПерезаполнениеДокументов
  • Сервер: ОценкаПроизводительности.НачатьЗамерДлительнойОперации / ЗакончитьЗамерДлительнойОперации (опц. ЗафиксироватьЗамерДлительнойОперации по пачкам)
  • Вес = число обработанных документов; комментарий: Вид, Договоров, Документов, Риск, Потоков, Успешно, Ошибок, Порция
  • «По пулам» тоже писать замер того же ключа, Потоков=1

Критерии приёмки

  1. «По пулам» — поведение как сейчас (+ замер)
  2. Другие виды — окно БСП с растущим процентом, без клиентского цикла по документам
  3. Лимит потоков из константы; один ДоговорДУ не в двух заданиях сразу
  4. СЧА+риск: риск только после СЧА того же договора
  5. Сводка и ошибки в сообщениях; запись в ЗамерыВремени
  6. Потоки 0 / без фоновых — доходит до конца в одном задании с прогрессом и замером
  7. Результат заполнения/проведения совпадает с текущими процедурами объектов
