h2. Зачем

Обработка *Групповое перезаполнение документов* сейчас идёт строго по одному документу в клиентском сеансе. На массовых прогонах (много договоров ДУ на одну дату, типичный случай — Расчет СЧА/РСА) сеанс занят, нормального окна с процентом нет.

Нужно ускорить массовое перезаполнение за счёт параллельной обработки *по портфелям (ДоговорДУ)* и показать пользователю понятный процент и итог.

h2. Что меняется для пользователя

После кнопки *Перезаполнить* открывается штатное окно ожидания БСП (кружок, процент, Отмена), как у регламентных операций.

Строка прогресса: процент рисует окно БСП отдельно; в тексте деталей % не дублируется:
{code}
Пожалуйста, подождите… 41%
860/2100 док. | потоков 4 | ФЗ в базе 11 | порция 7/42 | осталось примерно 8 мин
{code}
* *%* (в шапке окна) и *док.* — обработанные / всего документов прогона (СЧА + риск, если флаг включён)
* *потоков* — живые воркеры этой обработки
* *ФЗ в базе* — все активные фоновые задания ИБ (включая чужие)
* *порция N/M* — текущая порция / всего порций
* *осталось …* — оценка времени до конца, только с 10% (до 10% хвост не пишется). Часы и минуты, без секунд; меньше минуты — «осталось меньше минуты». Это ориентир, не гарантия.

В конце — сводка в сообщениях. При флаге риска расшифровка, например:
{code}
Перезаполнение завершено. Вид: Расчет СЧА/РСА. Договоров: 3086. Документов всего: 6161 (Расчет СЧА/РСА: 3086, контроль риска: 3075, без документа риска у 11 договоров). Успешно: 6161, с ошибкой: 0. Потоков: 12. Затрачено: 9 мин 20 сек.
{code}
Без флага риска — короче: вид, договоров, документов, успешно / с ошибкой, потоков, время. Ошибки по отдельным документам — отдельными строками. Успешно обработанные портфели при частичных сбоях не откатываются.

Отбор на форме *не меняем*: как сейчас, «Настройка списка». Новых полей периода/договора в шапке нет.
Перед запуском обязательны оба края периода по дате в этом отборе (дата с и дата по). Если периода нет — предупреждение, перезаполнение не стартует.
Если период задан — вопрос с расшифровкой: вид, период, прочие условия отбора, флаг риска (для СЧА/РСА). «Нет» — выход, «Да» — старт.

h2. Ветвление по видам

* *Установка котировок ц/б (по пулам)* — как сейчас (последовательный клиентский цикл). Договора ДУ в шапке нет, в параллель не переводим. Добавляется только замер времени.
* *Остальные виды* обработки — новый путь: одно родительское фоновое задание, пачки по договорам ДУ, скользящее окно потоков, окно процента.

Виды на новом пути: начисление %% по банковским счетам, начисление купонного дохода, погашение облигаций, погашение НКД, переоценка активов / взаиморасчетов / денежных средств, расчет СЧА/РСА (опционально контроль риска), реформация баланса, установка котировок ц/б.

h2. СЧА/РСА + флаг «Перезаполнять контроль допустимого уровня риска»

Отдельного этапа «сначала все СЧА, потом все риски» нет.

По каждому договору в пачке: сначала документы СЧА/РСА этого договора, сразу затем контроль риска *того же* договора (если документ риска есть за тот же календарный день). Риск не запускается параллельно со своим СЧА. Ошибка на СЧА этого договора — риск по нему не считать, остальные договоры пачки продолжать.

h2. Параллельность (без новых констант)

* Число потоков: существующая константа *МаксимальноеКоличествоПараллельныхПотоков*
* Размер порции (целых договоров в пачке), по умолчанию 50: *МаксимальныйРазмерПорцииДоговоровВПотокеРегл*
* Один ДоговорДУ не режется на два потока
* Если потоков 0 или фоновые задания запрещены — пачки идут последовательно внутри одного задания диспетчера, окно процента всё равно показывается

h2. Замеры времени

Ключ: {{ДУ.ГрупповоеПерезаполнениеДокументов}}
Один замер на прогон (старт в начале, финиш в конце с полным весом = все документы прогона). Промежуточных замеров по пачкам нет.
Комментарий: Вид, Договоров, Документов, Риск, Потоков, Успешно, Ошибок, Порция.
Для вида «по пулам» — тот же ключ, Потоков=1.

h2. Не входит в этот этап

* Переделка UI отбора (панель настроек списка, поля периода/договора в шапке, отдельный компоновщик СКД)
* Создание новых констант
* Изменение логики заполнения самих документов (используются те же процедуры объектов, что сейчас)

h2. Критерии приёмки

# «По пулам» — поведение как сейчас (+ замер)
# Остальные виды — окно с растущим процентом, без клиентского цикла по документам
# Лимит потоков из константы; один ДоговорДУ не в двух заданиях сразу
# СЧА+риск: риск только после СЧА того же договора; риск ищется по договору и календарному дню отобранных СЧА
# Сводка и ошибки в сообщениях; запись в ЗамерыВремени
# Потоки 0 / без фоновых — прогон доходит до конца в одном задании с прогрессом и замером
# Без периода (оба края даты в настройке списка) кнопка не запускает перезаполнение
# Перед стартом — вопрос с расшифровкой отбора; по «Нет» выход
