# Исправление: отбор по бумаге при перезаполнении СЧА с контролем риска

Расширение `IM9434_Риск`, версия 1.0.0.10, 06.11.2026.

## Проблема

В обработке "Групповое перезаполнение документов" при виде "Расчет СЧА/РСА" с включенным флагом "Перезаполнять
контроль допустимого уровня риска" отбор по содержимому расчета СЧА (например, "Ссылка.Расчет СЧА.Показатель" -
бумага в таблице "Расчет СЧА") приводит к ошибке "Поле не найдено "Ссылка.РасчетСЧА.Показатель"". Обработка применяет
тот же отбор к документам "Контроль допустимого уровня риска", а у них такого поля нет. Ошибка возникает до начала
перезаполнения, документы не меняются. Без флага перезаполнение идет, но документы риска не пересчитываются.

## Что делает исправление

При включенном флаге "Перезаполнять контроль допустимого уровня риска" отбор списка применяется только к документам
"Расчет СЧА/РСА". На документы "Контроль допустимого уровня риска" этот отбор не переносится.

Документы контроля берутся по уже найденным расчетам: тот же договор ДУ и тот же день. Другие документы контроля,
даже если они попали бы под дату или договор отбора сами по себе, не перезаполняются.

Расширение меняет только форму обработки. Фоновое перезаполнение документов работает по типовому коду, без
изменений. Если документов контроля риска по найденным расчетам нет, выводится типовое сообщение "Документы контроля
допустимого уровня риска по отобранным СЧА/РСА не найдены.".

## Установка

1. Загрузить расширение `IM9434_Риск.cfe` в информационную базу.
2. **Снять флажок "Безопасный режим"** у расширения (и защиту от опасных действий). В безопасном режиме платформа
   не применяет расширение к форме обработки, и исправление не работает, хотя расширение показано как активное.
3. Пользователям перезайти в программу.

## Проверка (база разработки, 06.11.2026)

Тестовые данные: два расчета СЧА/РСА за 12.09.2026 по договорам ДоговорДУ_1 (бумага "ЗПИФ недвижимости РД") и
ДоговорДУ_2 (другая бумага), по документу контроля риска на тот же день для каждого договора. Отбор: период
12.09.2026, "Ссылка.Расчет СЧА.Показатель содержит ЗПИФ недвижимости РД", флаг контроля риска включен.

| Случай | Результат |
|---|---|
| Без расширения | Ошибка "Поле не найдено "Ссылка.РасчетСЧА.Показатель"", ничего не перезаполнено |
| С расширением, отбор по бумаге | Ошибки нет. Договоров 1, документов 2 (СЧА 1, контроль риска 1), успешно 2. Перезаписаны СЧА и документ риска договора 1, документы договора 2 не тронуты |
| С расширением, отбор только по дате | Договоров 2, документов 4 (СЧА 2, контроль риска 2), успешно 4. Контроль взят по договорам и дням найденных расчетов, а не отдельным отбором |

Изменение документов проверялось по версии данных до и после прогона.

## Отбор списка по виду документа

Версия расширения 1.0.0.8. Автосохранение отбора списка выключено: открытие на "Погашение облигаций" больше не
перезаписывает отбор "Расчет СЧА/РСА". Когда вид документа открывается впервые и своей записи у него еще нет,
в его запись копируется прежний общий сохраненный отбор. Копия делается только для этого вида, старая общая запись
не удаляется. Дальше отбор пишется при смене вида и при закрытии формы.

Строка по полю расчета СЧА видна только на виде "Расчет СЧА/РСА". На "Погашение облигаций" она не подставляется
и не вызывает диалог "поле не найдено". После закрытия формы и нового открытия строка на месте.

Проверено на базе разработки 06.11.2026: отбор "Ссылка.Расчет СЧА.Показатель" содержит "ЗПИФ недвижимости РД"
пропадает на погашении облигаций, возвращается при выборе "Расчет СЧА/РСА" и остается после закрытия и
повторного открытия формы.

Версия 1.0.0.9. В 1.0.0.8 сохраненный отбор вида не подставлялся целиком, если в нем была хотя бы одна строка с
полем другого вида документа. Типичный отбор пользователя (строка "Ручная корректировка" есть только у погашения
облигаций, строка по бумаге - только у расчета СЧА) не подставлялся ни на одном виде, а при закрытии формы в записи
видов сохранялся пустой отбор. Теперь не подставляются только такие строки, остальной отбор (период, договоры, пулы)
подставляется. Проверено на базе разработки на отборе такого состава: период и строка по бумаге на "Расчет
СЧА/РСА" на месте, после закрытия и повторного открытия тоже, перезаполнение по бумаге - 1 расчет СЧА и 1 документ
контроля риска.

Запись и чтение отбора идут через стандартные функции библиотеки: у пользователя без права "Сохранение данных
пользователя" отбор просто не запоминается, ошибки нет.
