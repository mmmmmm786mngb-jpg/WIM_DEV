Промпт полной разработки: IMDEV-9434

Параллельное групповое перезаполнение документов ДУ. Служебный промпт для агента. Не для бизнеса.

Выполни разработку до конца: исходники расширения, загрузка в базу, снятие безопасного режима, выгрузка .cfe. Не спрашивай подтверждений на шаги, которые уже заданы ниже. Не коммить в git, пока явно не попросят.
Имена процедур и функций. Новые — по стандартам 1С (PascalCase, глагол, без номера задачи и без IM9434_): ВыполнитьГрупповоеПерезаполнение, ОбработатьПачкуДокументов, ОбработатьЗавершениеПерезаполнения, ЗапуститьПерезаполнениеНаСервере.

Префикс расширения (метаданные, NamePrefix): IM9434_.
Новый код группируй в область #Область IMDEV_9434 … #КонецОбласти.
Не плодить мелкие обёртки: крупные процедуры, логику держать внутри них.
Новый общий модуль не создавать. Фоновые процедуры — модуль менеджера обработки (не модуль объекта).

1. Цель

Обработка ГрупповоеПерезаполнениеДокументов. Кнопка Перезаполнить:

  • вид «Установка котировок ц/б (по пулам)» — типовой последовательный цикл (тело оригинала без ПродолжитьВызов), плюс замер в ЗамерыВремени;
  • любой другой вид — родительское ФЗ БСП, окно процента, пачки по ДоговорДУ, скользящее окно воркеров.
  • для всех видов (включая пулы): перед стартом обязательны оба края периода по полю Дата в пользовательском отборе списка; иначе предупреждение и выход. Если период задан — ПоказатьВопрос с расшифровкой отбора; по «Нет» выход, по «Да» — продолжение.

Константы не создавать. Читать:

  • потоки: Константы.МаксимальноеКоличествоПараллельныхПотоков.Получить()
  • размер порции договоров: ОбщегоНазначенияДУ.ПолучитьЧисловуюКонстанту("МаксимальныйРазмерПорцииДоговоровВПотокеРегл", 50)
  • если потоков = 0 или Не ФоновыеЗаданияСервер.ФоновыеЗаданияРазрешены() — крутить пачки последовательно внутри диспетчера, окно процента всё равно.

Прогресс: процент передаётся в первом параметре СообщитьПрогресс (его рисует окно БСП); во втором параметре — только детали без ведущего N% (иначе процент пишется дважды). Разделитель блоков — | . После 10% в конец добавляется оценка оставшегося времени:

Пожалуйста, подождите… 41%
860/2100 док. | потоков 4 | ФЗ в базе 11 | порция 7/42 | осталось примерно 8 мин
  • % в шапке окна БСП и док. = обработанные / всего документов прогона (СЧА + риск при флаге)
  • потоков = живые воркеры этой обработки
  • ФЗ в базе = все активные фоновые задания ИБ (ФоновыеЗадания.ПолучитьФоновыеЗадания со Состояние = Активно), включая чужие
  • порция N/M = текущий индекс порции / всего порций
  • осталось … — только если процент >= 10. До 10% хвост не писать. Считать линейно: ОсталосьСек = ПрошлоСек * (ВсегоДокументов - Обработано) / Обработано (старт — ТекущаяУниверсальнаяДата() в начале диспетчера). Текст: осталось примерно 8 мин, осталось примерно 1 ч 15 мин; меньше 60 сек — осталось меньше минуты. Это оценка, не гарантия. Сборку строки удобно держать в одной локальной функции модуля менеджера (например ТекстПрогрессаПерезаполнения), без отдельного общего модуля.

СЧА + флаг риска: в одном воркере по одному договору сначала СЧА/РСА, сразу затем контроль риска. Риск к отобранным СЧА подбирать по ДоговорДУ + календарному дню (не тем же отбором списка СЧА). Отдельного этапа «все СЧА, потом все риски» нет.

Замер: ключ ДУ.ГрупповоеПерезаполнениеДокументов, сервер ОценкаПроизводительности.НачатьЗамерДлительнойОперации в начале и один ЗакончитьЗамерДлительнойОперации в конце с полным весом (все документы прогона, включая риск при флаге). По пачкам ЗафиксироватьЗамерДлительнойОперации не вызывать. Комментарий: Вид=...; Договоров=...; Документов=...; Риск=Да/Нет; Потоков=...; Успешно=...; Ошибок=...; Порция=.... При любой ошибке документа — ВыполненСОшибкой.

Модуль расширения: .../DataProcessors/ГрупповоеПерезаполнениеДокументов/Forms/Форма/Ext/Form/Module.bsl

ПроцедураНовая / перехватЗачем
IM9434_Перезаполнить перехват &ИзменениеИКонтроль("Перезаполнить") Единственное имя с номером задачи. Копия типового тела. Непулы: вставка + Возврат до клиентского цикла. Пулы: оригинальный цикл без ПродолжитьВызов, плюс замер

Всё серверное для запуска (СКД-выборка, запрос ДоговорДУ, ДлительныеОперации.ВыполнитьВФоне) держать через одну &НаСервере процедуру, например ЗапуститьПерезаполнениеНаСервере — не плодить ещё три серверных обёртки, номер задачи в имя не добавлять.

Типовые ПолучитьМассивДокументовДляПерепроведения, ПереполнитьДокументы, УправлениеФормой не перехватывать.

Как править тело Перезаполнить. Сначала cfe-patch-method с -InterceptorType ModificationAndControl — получится полная копия оригинала. Дальше только маркеры (с нулевой колонки, без отступа):

  • Непомеченные строки байт в байт как в типовой (включая комментарий // ASP-139357 {).
  • Добавления — #Вставка … #КонецВставки.
  • Вырезать типовое — только через #Удаление … #КонецУдаления (строки оригинала оставить внутри). Для этой задачи типовой цикл не удалять: для пулов он должен выполняться.
  • &Вместо и ПродолжитьВызов не использовать.

Точка вставки сразу после ОчиститьСообщения(); — проверка периода и вопрос по отбору (для всех видов, в том числе пулов). Без подтверждения дальше не идти.

Вторая точка вставки — сразу после блока маппинга вида (КонецЕсли; после пулов), до ПолучитьМассивДокументовДляПерепроведения:

#Вставка
    Если Объект.ВидДокумента <> "Установка котировок ц/б (по пулам)" Тогда
        РезультатЗадания = ЗапуститьПерезаполнениеНаСервере();
        // ОжидатьЗавершение на клиенте (см. ниже)
        Возврат;
    КонецЕсли;
#КонецВставки

Так непулы не доходят до типового Для каждого Ссылка и второго цикла риска. Пулы падают в оригинальный код: СКД с отбором формы, клиентский цикл, ПереполнитьДокументы. Замер пулов — отдельные #Вставка до цикла (старт, вес = число ссылок) и после финального сообщения (один ЗакончитьЗамерДлительнойОперации с полным весом). Типовой цикл между ними не трогать.

Непулы: ЗапуститьПерезаполнениеНаСервере внутри себя вызывает тот же ПолучитьМассивДокументовДляПерепроведения (отбор формы), добирает ДоговорДУ, при флаге риска — второй макет тем же отбором, затем ДлительныеОперации.ВыполнитьВФоне("Обработки.ГрупповоеПерезаполнениеДокументов.ВыполнитьГрупповоеПерезаполнение", ...). На клиенте как регламенты:

ПараметрыОжидания.ТекстСообщения = НСтр("ru='Групповое перезаполнение документов…'");

ПроцедураЭкспортНазначение

Строку ПроцедураЗаполнения передавать в пачку как есть (со скобками и аргументами, как на форме).

Запуск воркера из диспетчера. Платформенный ФоновыеЗадания.Выполнить принимает только метод общего модуля. ПараметрыМетода = Новый Массив;

ТекЗадание = ФоновыеЗадания.Выполнить(
    "ДлительныеОперации.ВыполнитьСКонтекстомКлиента",

    КлючЗадания,

Нельзя из диспетчера (он сам уже ФЗ) звать ДлительныеОперации.ЗапуститьФоновоеЗаданиеСКонтекстомКлиента и ВыполнитьВФоне на пачки: при ТекущийРежимЗапуска() = Неопределено пойдёт прямой ФоновыеЗадания.Выполнить("Обработки....") — ошибка «Метод объекта не обнаружен». Если параллель недоступна — тот же ОбработатьПачкуДокументов вызывать синхронно из диспетчера (не плодить третий метод).

4.2. Почему менеджер обработки, а не объект и не новый общий модуль

Платформа: ФоновыеЗадания.Выполнить(<ИмяМетода>) — только экспорт неглобального общего модуля. Родительское задание с формы всё равно идёт через БСП: ДлительныеОперации.ВыполнитьВФоне кладёт имя в обёртку ДлительныеОперации.ВыполнитьСКонтекстомКлиента, а та вызывает ВыполнитьМетодКонфигурации. Проверка имени там разрешает три части Обработки.<Имя>.<Метод> (менеджер находится через МенеджерОбъектаПоИмени). В этой CF так уже сделано: удаление помеченных. 

// Родитель с формы (клиентский сеанс) — так можно:
ДлительныеОперации.ВыполнитьВФоне(
    "Обработки.ГрупповоеПерезаполнениеДокументов.ВыполнитьГрупповоеПерезаполнение",
    ПараметрыПроцедуры,
    ПараметрыВыполнения);

// Воркер из диспетчера (уже ФЗ) — прямой ВыполнитьВФоне / Выполнить("Обработки....") нельзя.
// ВыполнитьБПБезопасно тоже нельзя: ИмяТипаОбработки() закомментирован.
// Нужна обёртка ДлительныеОперации.ВыполнитьСКонтекстомКлиента (см. п. 3.2).

Модуль объекта: методы живут на экземпляре. Строка Обработки.Имя.Метод к ним не ведёт. Создавать объект внутри ФЗ ради пустых реквизитов обработки незачем.

IM8663 кладёт воркер в модуль менеджера справочника и зовёт его через ОбщегоНазначения.ВыполнитьБПБезопасно — для справочника три части разрешены. Для обработки тот же трюк с ВыполнитьБПБезопасно не работает. Не копировать запуск IM8663 один в один.

5. Алгоритм диспетчера (внутри одной процедуры)

  1. Старт ОценкаПроизводительности.НачатьЗамерДлительнойОперации("ДУ.ГрупповоеПерезаполнениеДокументов").
  2. Вход: массивы/ТЗ документов вида и (опционально) риска: Ссылка, ДоговорДУ; имена процедур заполнения; вид; флаг риска; N потоков; размер порции.
  3. Сгруппировать по ДоговорДУ. Один договор — только в одной пачке.
  4. Нарезать пачки: класть целые договоры, пока число договоров пачки не превысит размер порции (если у одного договора документов больше порции — пачка из этого договора целиком).
  5. Всего документов прогона = число СЧА/вида + число риска (если флаг). Это знаменатель %.
  6. Скользящее окно: пока есть очередь или живые задания:
    • пока живых воркеров < N и есть пачки — запустить воркер (или синхронный вызов);
    • ФоновыеЗадания.ОжидатьЗавершенияВыполнения с таймаутом ~5 сек;
    • разобрать завершённые: ошибки в журнал/сообщения, прибавить обработанные документы;
    • СообщитьПрогресс(Процент, Текст): в тексте без ведущего процента — 860/2100 док. | потоков 4 | ФЗ в базе 11 | порция 7/42 | осталось примерно 8 мин; после 10% хвост | осталось ….
  7. Сводка в СообщениеПользователю и в структуру результата. При флаге риска: договоров; документов всего с разбивкой «вид + контроль риска»; сколько договоров без документа риска (или «риск найден по всем договорам»); успешно / ошибок; потоков; время. Без флага: вид, договоров, документов, успешно / ошибок, потоков, время.
  8. Один ЗакончитьЗамерДлительнойОперации с полным весом = все документы прогона. ЗафиксироватьЗамерДлительнойОперации по пачкам не вызывать.
  9. ПоместитьВоВременноеХранилище результата.

Порядок в воркере по одному ДоговорДУ: все документы основного вида этого договора по дате/ссылке, затем документы риска этого договора. Ошибка на СЧА — риск этого договора не запускать, остальные договоры пачки продолжать.

6. Стиль 1С

  • Ключевые слова: Не, И, Или, Тогда, КонецЕсли (не НЕ/не).
  • Переменные PascalCase. Процедуры/функции — глагол, PascalCase.
  • Новые процедуры и функции без IM9434_ и без номера задачи в имени. Префикс NamePrefix — только у перехватчиков типовых методов (IM9434_Перезаполнить).
  • Комментарии по-русски. У экспортных — документирующий комментарий (описание, параметры, возврат).
  • Без HTML-сущностей в BSL (&Параметр, не &amp;).
  • Без концевых пробелов.
  • Маркеры #Вставка/#Удаление/#КонецВставки/#КонецУдаления — с колонки 0, без отступа.
  • Для Перезаполнить — только &ИзменениеИКонтроль (cfe-patch-method ModificationAndControl). Не &Вместо, не ПродолжитьВызов.

7. Порядок работ

  1. cfe-init → cfe-borrow обработки с формой: -Object "DataProcessor.ГрупповоеПерезаполнениеДокументов.Form.Форма", -BorrowMainAttribute Form, -Module ManagerModule. Не вызывать meta-compile ради общего модуля.
  2. cfe-patch-method ModificationAndControl на Перезаполнить модуля формы, затем вставки по п. 3.1.
  3. Написать диспетчер и воркер в Ext/ManagerModule.bsl расширения; на форме — обработчик завершения и серверный старт.
  4. cfe-validate с -ConfigPath CF.
  5. Загрузка в базу без пользователя и пароля. Если навык требует -UpdateDB — обновить расширение в ИБ: 
    /db-load-xml <каталог IM9434> -Extension IM9434
    -InfoBaseServer localhost -InfoBaseRef WIM_DU
  6. Снять безопасный режим (иначе перехват модуля формы не применится); при необходимости также -UnsafeActionProtection off: 
    /db-cfe-admin set-properties -Name IM9434 -SafeMode off
    -InfoBaseServer localhost -InfoBaseRef WIM_DU
  7. /db-cfe-admin check -Name IM9434 (apply + modules).
  8. Выгрузить CFE: 
    /db-dump-cf -Extension IM9434
    -InfoBaseServer localhost -InfoBaseRef WIM_DU
    -OutputFile bases/Wim_Du/projects/IMDEV-9434 ГруппПерезаполнение/Расширения/IM9434.cfe
  9. Кратко отчитаться: что создано, какие методы, путь cfe, результат check.

8. Приёмка (самопроверка по коду)

  • Пулы не идут в диспетчер.
  • Непулы не оставляют клиентский цикл по документам.
  • Один ДоговорДУ не в двух воркерах.
  • Риск только после СЧА того же договора.
  • Прогресс: процент только в первом параметре СообщитьПрогресс; текст — 860/2100 док. | потоков 4 | ФЗ в базе 11 | порция 7/42 | осталось примерно 8 мин. Знаменатель включает риск при флаге. Оценка «осталось …» только с 10%.
  • ФЗ в базе считает все активные задания ИБ.
  • Есть одна запись замера ДУ.ГрупповоеПерезаполнениеДокументов на прогон: старт в начале, финиш в конце с полным весом. Промежуточных замеров по пачкам нет.
  • Нет новых констант. Заполнение документа в воркере — через Выполнить("ДокументОбъект." + ПроцедураЗаполнения), как в типовой ПереполнитьДокументы (без каскада по видам методов).
  • Нет нового общего модуля. Диспетчер и воркер только в модуле менеджера обработки. Модуль объекта не заимствован.
  • UI отбора не менялся: нет новых полей шапки, панели настроек списка и компоновщика СКД. Выборка через типовую ПолучитьМассивДокументовДляПерепроведения.
  • Без обоих краёв периода по Дата в отборе списка запуск не идёт. Перед стартом есть вопрос с расшифровкой отбора.
  • Воркеры стартуют через ДлительныеОперации.ВыполнитьСКонтекстомКлиента, не через ВыполнитьБПБезопасно и не через прямой ФоновыеЗадания.Выполнить("Обработки....").
  • Область IMDEV_9434 на новом коде.
  • Перехват Перезаполнить — &ИзменениеИКонтроль, не &Вместо. Типовой клиентский цикл в теле сохранён и выполняется только для пулов.
  • Новые процедуры без номера задачи в имени. Номер есть только у перехватчика IM9434_Перезаполнить.
