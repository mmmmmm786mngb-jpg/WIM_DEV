Выгрузка всех форм/таблиц XBRL-пакета ОРТИКОН в Excel — полностью, за вменяемое время, без сбоев

IMDEV-9182 Все формы пакета Таксономия 7.1 Замена медленного XBRL-конвертера

Цель

Обеспечить выгрузку всех форм и таблиц из XBRL-пакета ОРТИКОН (НСО ПУРЦБ, таксономия 7.1) в многолистовый Excel в полном объёме одним запуском, за вменяемое время и без сбоев — как инструмент визуализации для оценки качества и правильности данных в отчётности.

Пакеты уже достигают порядка сотен МБ; отдельные формы (например, 0420431) содержат очень много строк — внешний конвертер на таких объёмах работает медленно и ненадёжно. Нужно решение в 1С на весь экземпляр отчёта XBRL, а не на одну выбранную форму.

1. Основание и проблема

Источник постановки: заявка IMDEV-9182 (запрос на изменение, компонент AvancoreDU).

В регуляторной отчетности НСО ПУРЦБ необходим инструмент визуализации данных XBRL в Excel — для оценки качества и правильности данных по формам пакета. Типичные ограничения текущих средств:

  • XBRL-пакет ОРТИКОН имеет огромный размер (уже порядка ~500 МБ);
  • отдельные формы содержат очень большое число строк (в заявке как пример указана 0420431; решение должно работать для всех форм точки входа таксономии, а не только для неё);
  • штатный XBRL-конвертер часто позволяет выгружать данные только частями: процесс занимает больше часа, возможны сбои; доработка конвертера силами ДУ практически невозможна (чужое ПО);
  • портал Аванкор XBRL загружает и проверяет пакет свыше 8 часов — как рабочий вариант визуализации нецелесообразен, пока ситуация не улучшится;
  • «ПрограмБанк» для текущей таксономии не используется.
Требуемое решение: выгружать все формы/таблицы XBRL-пакета в Excel в полном объёме одним запуском, за вменяемое время и без сбоев. Реализация — внешняя обработка 1С, читающая экземпляр XBRL / ZIP ОРТИКОН (таксономия 7.1) и формирующая XLSX средствами платформы, без зависимости от внешнего конвертера ЦБ и без многочасового портала.

Разработать внешнюю обработку внВыгрузкаXBRLОртиконВXLSX со следующим составом:

3. Входы и выходы

3.1. Вход

  • Файл .xbrl (экземпляр отчёта) или .zip, внутри которого есть экземпляр XBRL (типичный пакет ОРТИКОН / выгрузки НСО ПУРЦБ).
  • Режим работы: с таксономией (основной) или быстрый без таксономии (сырые имена концептов).

3.2. Выход

  • Файл .xlsx (одна книга, много листов).
  • Формирование через штатные средства платформы (пакет отображаемых документов / запись табличных документов в XLSX), без автоматизации Excel через COM и без внешнего Python на сервере 1С.

4. Функциональные требования

4.1. Разбор XBRL

  • Обязательно. Потоковое чтение экземпляра: контексты (организация, период, измерения сценария/сегмента), факты, ссылка на схему (schemaRef).
  • Обязательно. Поддержка ZIP: извлечение экземпляра во временный каталог с последующей очисткой.
  • Обязательно. Корректная обработка больших файлов (десятки МБ экземпляра, десятки тысяч фактов/контекстов) без загрузки всего XML в строку.

4.2. Режим «с таксономией ЦБ» (основной)

  • Извлечь вшитый ZIP таксономии из макета обработки.
  • Построить словарь русских подписей (базы ссылок label: dictionary / mem-int / dim-int / purcb / nfo и связанные таблицы точки входа).
  • По схемам представления таблиц (tab/*-rend.xml точки входа) определить состав таблиц точки входа, порядок колонок и подписи показателей.
  • Сопоставить факты/контексты таблицам точки входа (в т.ч. технические оси / итоги / контексты без осей).
  • Подставлять русские подписи заголовков и значений-членов осей.
  • Кэшировать разбор таксономии между запусками в рамках сессии объекта обработки (ускорение повторных конвертаций).

4.3. Режим «быстро без таксономии»

  • Раскладка по измерениям/блокам без обязательного разбора подписей и схем представления таблиц.
  • Допустим вывод технических имен концептов (для диагностики).

4.4. Прогресс и фон

  • Конвертация в фоновом задании БСП с окном ожидания, процентом и текстом этапа.
  • При недоступности фона — синхронный запасной режим с понятным статусом на форме.
  • Рекомендуемый запуск: из справочника «Дополнительные отчеты и обработки» (безопасный режим выключен).

6. Особые формы отчетности

Обработка выгружает все таблицы точки входа пакета (оглавление + листы данных, включая пустые заглушки). Ниже — особенности отдельных форм, выявленные при сверке с эталоном ЦБ (не ограничивают состав выгрузки).

6.1. Крупные формы (пример: 0420431)

  • Обязательно. Формы с большим числом строк выгружаются целиком за один проход вместе с остальным пакетом (не «частями», как у внешнего XBRL-конвертера).
  • Обязательно. Устойчивая работа на крупном пакете (сотни МБ) без обрыва на середине любой формы.
  • Объёмы строк ключевых блоков сопоставимы с эталоном конвертера ЦБ на том же пакете (допустимы отличия компоновки шапок, не допускается потеря существенной доли данных).
  • Для большинства форм — плоская раскладка измерений в колонки.

6.2. Форма 0420415 (операции с ЦБ) — сводная компоновка

Для таблиц 0420415 с типизированными осями (*Taxis) — компоновка «как в эталоне ЦБ»:

  • Строка = период + значения типизированных осей (Taxis);
  • Колонки мер = показатель + закрытые члены осей (Concept|Member), а не «плоское» размножение каждой комбинации в отдельную строку.

Ключ слияния строк должен быть стабильным (в т.ч. упорядоченные типизированные оси), чтобы объём строк был сопоставим с эталоном.

6.3. Форма 0420437 (сведения о контрагентах)

  • Колонка «Роль контрагента» — русская подпись члена из mem-int-label, а не сырая ссылка вида //www.cbr.ru/.../mem-int#....
  • Разбор локального имени члена: фрагмент после #, варианты с/без суффикса Member.

6.4. Формы с ОКАТО

  • Члены оси ОКАТО: код - наименование региона (с учётом субъектов без технической подписи «код - название»).

8. Нефункциональные требования

  • Обязательно. Работа только на платформе 1С (без обязательного Python/Excel на сервере).
  • Обязательно. Безопасный режим выключен в сведениях БСП; запуск из «Дополнительные отчеты и обработки».
  • Обязательно. Выгрузка всего пакета (все формы/таблицы) — целиком за один запуск, без ручной нарезки «частями» (в отличие от текущего XBRL-конвертера).
  • Обязательно. Устойчивость: типичный крупный пакет (~сотни МБ) отрабатывается до конца без падения; при ошибке — понятное сообщение, без «тихого» обрезанного Excel.
  • Обязательно. Время полного прогона — существенно лучше текущего конвертера (>1 часа на частях) и портала Аванкор (>8 часов). Ориентир приёмки: минуты / десятки минут на типовом сервере ДУ, а не часы.
  • Желательно. Хронометраж этапов в итоговом описании (распаковка, чтение XBRL, таксономия, запись XLSX).
  • Обязательно. Очистка временных каталогов/файлов после конвертации.
  • Код BSL: PascalCase, стандартный регистр ключевых слов 1С, документирующие комментарии на экспортных методах.

9. Интерфейс и регистрация БСП

9.1. Форма

  • Заголовок с названием и версией.
  • Поле/команда выбора файла .xbrl / .zip.
  • Основная кнопка: «Конвертировать в XLSX (таксономия ЦБ)» (клавиша Enter по умолчанию).
  • Дополнительная: «Быстро без таксономии».
  • Поле статуса (путь файла, этапы, ошибки, итог).
  • Диалог сохранения результата .xlsx.

9.2. Регистрация

  • Вид: дополнительная обработка.
  • Команда открытия формы.
  • БезопасныйРежим = Ложь.
  • Краткая информация: два режима, макет таксономии.

10. Критерии приемки

# Критерий Как проверить
1 Все формы/таблицы пакета выгружены одним запуском (оглавление + листы данных, включая пустые заглушки точки входа) Состав листов соответствует оглавлению точки входа / эталону ЦБ на том же ZIP; нет ручной нарезки «частями»
2 Без сбоев на типовом пакете размера «проблемы» (~сотни МБ) Прогон до конца; XLSX открывается; данные крупных форм не обрезаны
3 Вменяемое время — заметно быстрее внешнего конвертера (>1 ч частями) и портала Аванкор (>8 ч) Замер полного времени прогона; фиксация в описании результата / протоколе теста
4 Результат пригоден для визуальной оценки качества данных по формам пакета Экспертная проверка специалистами Back-Office Settle на реальном пакете
5 Объёмы ключевых блоков сопоставимы с эталоном (в т.ч. крупные формы вроде 431, а также 409/415/437 и др.) Сверка с эталоном СУПЕРТЕСТА на том же пакете
6 Качество представления: 415 (сводная компоновка, дроби), 437 (роли RU), OKATO, числовые типы ячеек Регресс по эталонам СУПЕРТЕСТА
7 Запуск из «Дополнительные отчеты и обработки» без ошибок безопасного режима Регистрация EPF и повторный прогон
Главный вопрос приёмки: «Можем ли мы выгрузить весь XBRL-пакет (все формы) в Excel за приемлемое время без сбоев?» — если да, заявка IMDEV-9182 закрывается по сути. Попиксельное совпадение с интерфейсом конвертера ЦБ не требуется. Форма 0420431 в постановке — лишь пример «тяжёлой» формы, а не ограничение рамок задачи.

11. Тестовые данные (материалы проекта)

В каталоге проекта предусмотреть набор для регрессии:

  • крупный ZIP с экземпляром ОРТИКОН (целевой сценарий «тяжёлого» пакета);
  • ZIP: месячный (апрель) и квартальный (июнь) пакеты НСО ПУРЦБ;
  • эталонные XLSX конвертера ЦБ по тем же периодам (полный набор форм пакета: 409–415, 431, 437 и др.);
  • контрольные выгрузки обработки для сравнения версий.

Минимальный регресс перед релизом версии:

  1. полный пакет → XLSX: состав всех листов оглавления / точки входа, время, отсутствие сбоя;
  2. апрельский/июньский ZIP → объёмы ключевых форм vs эталон (в т.ч. крупные и «особые»: 415/437).

12. Ограничения и вне рамок задачи

  • Вне рамок задачи. Доработка чужого XBRL-конвертера ЦБ/ОРТИКОН и портала Аванкор XBRL.
  • Вне рамок задачи. Замена штатной выгрузки XML/XBRL в ЦБ; обработка только читает готовый экземпляр отчёта.
  • Вне рамок задачи. Полная эмуляция интерфейса конвертера ЦБ (объединённые шапки, служебные списки, попиксельное совпадение).
  • Вне рамок задачи. Поддержка произвольных таксономий вне вшитого релиза 7.1 (смена таксономии — отдельная задача: замена макета).
  • Вне рамок задачи. Конвертация документов 1С «из ТЧ регл. отчёта» (другой контур).
  • При отсутствии таблицы в экземпляре пустой лист — норма, не ошибка.
