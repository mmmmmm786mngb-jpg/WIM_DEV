1. Введение

По исследованию IMDEV-9393 в таблице текущей длительности ключевых операций Розничного ДУ по строке «Оплата вознаграждения» стоял прочерк: в внОплатаКЗПоКлиентамРДУ замер не был реализован. Без него нельзя было оценить квартальный прогон и прогноз на рост базы до 250 тыс. договоров.

IMDEV-9416 — вставить замеры времени в эту обработку. База для доработки — корректный оригинал версии 2.0 (не копия 1.19 из смежной задачи). В оптимизации собрана версия 2.1 (замеры), затем 2.2 (совместимость старых настроек).

Источник плана проверки: отчет План ИТ тестирования замеров времени 9416 (скриншоты формы и регистра ЗамерыВремени от 07.09.2026).

2. Технология замеров

Подсистема БСП «Оценка производительности»

Результат пишется в регистр сведений ЗамерыВремени. Один замер = весь пакет документов этапа, не один документ в цикле.

КонтурМодульКак запускается
Клиент (поручения, поступления, списания) ОценкаПроизводительностиКлиент ЗамерВремени(Ключ, Ложь, Ложь) — без автозавершения;
затем вес, комментарий и ЗавершитьЗамерВремени.
Длительность включает клиент-серверные вызовы по строкам ТЧ.
Сервер (блокировка ДС) ОценкаПроизводительности НачатьЗамерВремени / ЗакончитьЗамерВремени вокруг цикла в модуле объекта.

Клиентский замер сначала копится в буфере сеанса и сбрасывается в регистр обработчиком записи (обычно раз в минуту). После прогона форму лучше не закрывать сразу.

Вес и комментарий

Вес — число уникальных договоров, по которым в пакете реально вызывали создание документа (если 0 — подставляется 1).

Договоров=18420; Кандидатов=18420; Создано=18391; Ошибок=29; ВидДокумента=НачислениеВознаграждения; Период=30.09.2026; Отказ=Да; УдельныйВес=12.45 об/с

Для поручений дополнительно Сравнивать=..., для поступлений и списаний — ДатаВвода=.... Признак «выполнен с ошибкой» совпадает с Отказ=Да.

Скриншоты прогона

Инцидент 1. Настройки

Симптом: после разовой загрузки настроек гиперссылка открытия формы настроек: «Поле объекта не обнаружено (СтатьяЗатратСписаниеНДФЛ)».

ВнешняяОбработка.ОплатаКзПоКлиентамРДУ.МодульОбъекта:
СтатьяЗатратСписаниеЗадолженность = Настройки.Значения.СтатьяЗатратСписаниеНДФЛ;

ВнешняяОбработка.ОплатаКзПоКлиентамРДУ.Форма.ФормаНастроек:
ТекОбъект.УстановитьПользовательскиеНастройки(НастройкиОбработки);

Причина: в хранилище дополнительных обработок лежала более ранняя структура без ключей НДФЛ, а чтение шло напрямую.

Исправление: версия 2.2, Свойство() для двух ключей НДФЛ. После записи настроек из актуальной формы ключи появятся в хранилище.

ИСПРАВЛЕНО в 2.2

Инцидент 2. «Документ не соответствует виду сравнения»

Кнопка поступлений (и списаний) разрешена только если сравнение — «Брокерским счетом» или «Расчетным счетом».

Режимы «Учитывать остатки на брокерском счете» и «Не учитывать остатки…» — это сценарий блокировки ДС. Для них предназначена кнопка блокировки; поступление и списание штатно запрещены.

Это логика оригинала 2.0, не регресс замеров. Прогон поступлений выполнен после выбора подходящего вида сравнения.

6. Возможности после задачи

  • На ПРОД появятся ключи ДУ.ОплатаКЗРДУ.* по квартальным ручным прогонам оплаты КЗ.
  • Таблица IMDEV-9393 сможет заменить прочерк «нет замеров» на фактическую длительность. Ориентир с UAT: блокировка ~6,6 мин на 9,2 тыс. договоров при 23,17 об/с; линейно на 250 тыс. это порядка 3 ч только по блокировке, без клиентских этапов.
  • По комментарию замера видно объем (договоры / кандидаты / создано / ошибки), вид документа, период и скорость об/с — на блокировке это подтверждено подсказкой регистра.
  • Клиентские этапы показывают время пользователя, включая вызовы сервера по строкам.
  • Старые настройки обработки больше не блокируют открытие формы настроек.
