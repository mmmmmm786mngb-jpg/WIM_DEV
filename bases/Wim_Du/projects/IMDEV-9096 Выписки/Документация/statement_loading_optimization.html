Показатель Baseline Test1 (после OPT-02) Вывод

Мультимножество ключей
(Дата, НомерСчета, Договор, Банк, N)		 629 записей 629 записей 0 расхождений — функционально идентично
Позиционное сравнение (индекс строки) — 7 строк отличаются только перестановка порядка, не смена данных
7 «расхождений» по индексу — не регрессия. Все 7 строк относятся к одному блоку ЕРС RUR (40701810000030000413, р/с_ВТБ_ДС_RUR_ЕРС, дата 09.06.2026). Набор договоров один и тот же: УК ВТБ УА, ДУ 9832, 9448, 7782, 9919, 8711, 8115 — изменился только порядок строк при разбиении одной выписки на несколько строк ТЧ (логика в ПрочитатьОбъекты, ~2702–2712). Причина появилась после OPT-02 (пакетный кэш договоров), не после OPT-05/OPT-18.
Рекомендуемый критерий приёмки (согласован с optimization_plan.html):
  • сравнивать мультимножество бизнес-ключей, а не порядок строк в ТЧ;
  • при необходимости — дополнительно сортировать обе выборки по (Дата, НомерСчета, Договор, Банк) перед построчным diff;
  • перестановка строк внутри одного ЕРС-блока при неизменном составе договоров — допустима.
