IMDEV-9096: параллельная фоновая загрузка по кнопке «Разобрать отмеченные»

Версия ТЗ: 1.0 | Дата: 25.06.2026 | База: Wim_Du | EPF: внЗагрузкаВыписокДУ (ЗагрузкаВыписок)

Цель: ускорить массовое создание документов по отмеченным выпискам через фоновые задания БСП (ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки) с ограничением не более N одновременных фонов. Единица работы - группа выписок с одинаковыми (БанковскийСчет, ДоговорДУ) (вариант 3 / OPT-13).

1. Введение

Сегодня кнопка РазобратьОтмеченные выполняет процедуру МассоваяЗагрузкаНаСервере синхронно: для каждой отмеченной выписки создается новый объект КлиентБанк, выполняется полный цикл РазобратьДанныеИмпорта + Загрузить. При большом числе выписок это блокирует сеанс и многократно загружает деревья правил для одного счета.

Предлагаемая доработка: сгруппировать выписки, запускать группы в фоне (до N параллельно), внутри группы - последовательно, с обновлением формы после завершения каждой группы. При отсутствии регистрации в ДополнительныеОтчетыИОбработки - автоматический откат на текущий синхронный алгоритм.

Связь с замерами IMDEV-8927: общий замер ДУ.ЗагрузкаВыписок.СозданиеДокументов.РазобратьОтмеченные сохраняется; в комментарий добавляется Групп=... и Параллельность=N.

4.2. Сообщения пользователю (критично)

Проблема: в синхронном режиме вызовы Сообщить() внутри КлиентБанк.Загрузить и правил разбора попадают в окно сообщений клиента автоматически, т.к. все выполняется в одном серверном вызове из МассоваяЗагрузка. В фоновом задании сообщения остаются в очереди задания и не отображаются, пока их явно не заберут.

Текущее поведение (сохранить):

  • Окно сообщений 1С - предупреждения и ошибки из КлиентБанк, правил, конфигурации.
  • Текстовый документ «Лог загрузки выписок» - через ПоказатьЛогВыписки(ОбщийЛог) после завершения кнопки.
  • Колонки Выписки.Лог, ДокументыКИмпорту.Лог - детализация по выписке/платежу.

Решение для фонового режима: после подтверждения завершения задания в оркестраторе МассоваяЗагрузкаПуломГруппНаСервере выполнить строго в таком порядке: (1) результат из временного хранилища, (2) сообщения из фона, (3) обновление данных формы.

// Шаг 1 - результат (после ЭтоЗаданиеЗавершено = Истина)
СтрокаXML = ПолучитьИзВременногоХранилища(АдресРезультата);
РезультатГруппы = ТекОбъект.РаспаковатьДанныеИзXML(СтрокаXML);

// Шаг 2 - сообщения из фона (работает в Wim_Du)
Сообщения = ДлительныеОперации.СообщенияПользователю(Истина, ИдентификаторЗадания);
Для Каждого Сообщение Из Сообщения Цикл
    Сообщение.Сообщить(); // повторная постановка в очередь текущего сеанса
КонецЦикла;

// Шаг 3 - данные формы и ОбщийЛог
ПрименитьРезультатГруппыКДаннымФормы(РезультатГруппы, ОбщийЛог);
Замечания:
  • Использовать только ДлительныеОперации.СообщенияПользователю(Истина, ИдентификаторЗадания) - фильтрует служебные сообщения прогресса БСП. Не ФоновоеЗадание.ПолучитьСообщенияПользователю напрямую.
  • Порядок обязателен: сначала результат, затем сообщения, затем ПрименитьРезультатГруппыКДаннымФормы.
  • При аварийном завершении, если хранилище пусто - СформироватьРезультатОшибкиГруппы по ФоновоеЗадание.ИнформацияОбОшибке, затем шаги 2-3.
  • Внутри ЗагрузитьГруппуВыписокВФоне не вызывать ПолучитьСообщенияПользователю - сбор только снаружи, по ИдентификаторЗадания.

4.3. Проверка завершения фонового задания (критично)

Запрещено в оркестраторе: ДлительныеОперации.ЗаданиеВыполнено(ИдентификаторЗадания). В CF Wim_Du при ЗавершеноАварийно / отмене функция вызывает ВызватьИсключение и прерывает обработку остальных групп пула.

Рекомендуемый способ - обертка без исключений через менеджер фоновых заданий:

ФоновоеЗадание = ФоновыеЗадания.НайтиПоУникальномуИдентификатору(ИдентификаторЗадания);
Если ФоновоеЗадание = Неопределено
    Или ФоновоеЗадание.Состояние <> СостояниеФоновогоЗадания.Активно Тогда
    // задание завершено (успешно, с ошибкой или отменено) - можно обрабатывать группу
КонецЕсли;

В ТЗ это оформлено как ПолучитьФоновоеЗаданиеПоИдентификатору + ЭтоЗаданиеЗавершено(ФоновоеЗадание) (приложение C.4.0). Объект задания передается в ОбработатьЗавершеннуюГруппуВФоне без повторного поиска.

9. Риски

  • Блокировки БД при высоком N на одной базе - начать с N=3.
  • Большой объем XML при большом числе платежей - передавать в ПакетГруппы только нужные колонки.
