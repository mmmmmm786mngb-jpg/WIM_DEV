IMDEV-8899 / этап 2 / постановка для разработчика

Оптимизация вечерних регламентов ДУ 1.5

Основание: замеры отладчика 15-16.05.2026, ~17 154 договоров ДУ, 5-10 потоков. Материалы: «Тест по замеру отладчиком новой конфигурации.docx», «Анализ причин замедления после внедрения 14_05_26.docx».

1. Контекст и цель

Отдельная задача на исследование и оптимизацию участков, выявленных после устранения основного узкого места по IMAPPS-35992 (индексация + потоки — вынесены в отдельное согласование с бизнесом).

Цель: сократить время полного вечернего расчета (~17 тыс. договоров ДУ) за счет оптимизации запросов, отсечения «пустых» договоров и устранения коллизий номеров документов.

2. Оценка времени полного расчета (базовая линия)

При длительности ~2 часа на 17 тыс. договоров ДУ (5 потоков, после индексации IMAPPS-35992):

4. Состав работ

3.1

ПереоценкаАктивов — запрос, строка 880

  • Выгрузить и проанализировать текст запроса на строке 880.
  • Проверить план выполнения, индексы, избыточность соединений и повторные вызовы на каждый договор ДУ.
  • Предложить оптимизацию: пакетный запрос, кэш, срез по договорам, временные таблицы.
  • Замер «до/после» в том же сценарии (детальная отладка).
3.2

ЗначенияПараметровДоговораДУ — запрос, строка 73

  • 136 443 вызовов — кандидат на кэширование или пакетное чтение параметров.
  • Исследовать возможность однократной выборки параметров по пачке договоров ДУ вместо вызова на каждую операцию.
  • Проверить индексы регистра сведений по ключам отбора в запросе.
3.3

РасчетСЧА_РСА — запрос, строка 154

  • В общем замере (1 поток, только РСА+СЧА): этот запрос давал до 20,38% времени.
  • Отдельно: ~20% времени — поиск существующего расчета по неиндексированному полю (критерий отбора при удалении/поиске).
  • Оптимизировать запрос и/или проиндексировать поля отбора; проверить отбор при удалении.
  • Распределение внутри РСА+СЧА: ~12% — запись документа План, ~82% — расчеты (учесть при приоритизации).
3.4

РегламентныеПериоды — НайтиСтроки, строка 686

  • 17 154 линейных поисков в таблице значений/списке операций на каждый договор.
  • Заменить на индексированную структуру (Соответие, предварительная группировка) или кэш списка операций на период.
3.5

ПланРегламентныхОперацийДУ.МодульМенеджера — запрос, строка 21

  • Запрос менеджера документа при массовом формировании — проверить возможность пакетной обработки.
  • Связать с блоком «работа с планами» (~30 мин в общей разбивке).

5. Дополнительные доработки

+1

Документ РасчетСЧА_РСА — коллизия номера при записи

При параллельной записи возможен дубль номера документа. Реализовать по аналогии с МО (IMDEV-8665):

  • Перед записью: УстановитьНовыйНомер()
  • До 30 попыток записи/проведения
  • При ошибке с текстом «не уникально» (регистронезависимо) — повторить
  • Иначе — пробросить исключение с информативным сообщением

Эталон: Wim_Mo, обработка внРасчетMVиWAP, процедура СоздатьИПровестиОдинДокументРасчета (строки ~1644-1662).

+2

Предварительный отсев договоров ДУ без расчета

Для видов расчетов, которые как правило не формируют документов (прочие расчеты без движений: переоценка ДС, дефолтные, контроль уменьшения стоимости портфеля и т.п. — ~20 мин в общей оценке):

  • Разработать предварительные запросы, отсекающие договоры ДУ, по которым расчет заведомо не нужен.
  • Не запускать полный цикл регламентных процедур для отсеченных договоров.
  • Зафиксировать критерии отсечения по каждому виду операции (таблица в описании задачи).
  • Замер: сокращение времени блока «прочие расчеты» и общего времени расчета.
