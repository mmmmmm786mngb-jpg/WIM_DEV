h2. Что сделать в расширении rev2 — Этап 2 оптимизации вечерних регламентов

{panel:title=3.1 | Переоценка активов — ускорение блока по РЕПО (~7,8% замера)|borderStyle=solid|borderColor=#D4C4B8|titleBGColor=#E8DDD5|bgColor=#FAF6F3}
*Что будет сделано:*
* Перед массовой переоценкой — один пакетный запрос по всем договорам: есть ли остатки по сделкам РЕПО.
* Для договоров целевого пула (розничное ДУ), по которым РЕПО нет, — пропуск лишнего шага заполнения табличной части по РЕПО в документе «Переоценка активов».
* Для договоров с РЕПО расчет останется без изменений.

*Зачем бизнесу:* не тратить время переоценки на запросы и обработку РЕПО там, где по договору РЕПО нет.

*Объекты расширения:* перехваты {{РегламентныеПериоды}} (модуль менеджера: {{ЗаполнитьСоответствиеПропускРЕПОВетки}}), {{ИсполняемыеПроцедурыЗакрытияПериода}}, {{ПереоценкаАктивов}}.
*Включение:* константа КФ {{ИспользоватьПредварительныеЗапросыДляВечернихРегламентов}} = Истина (включает пакетную предподготовку вечерних операций в базовой конфигурации).
{panel}

{panel:title=3.2 | Параметры договора ДУ — ускорение чтения настроек (~7,5% замера)|borderStyle=solid|borderColor=#A8C5DA|titleBGColor=#C5D9E8|bgColor=#F0F6FA}
*Что будет сделано:*
* Упростить запрос чтения параметров договора из регистра «Значения параметров договора ДУ» (вместо тяжелой конструкции с временными таблицами — прямой срез последних значений).

*Зачем бизнесу:* система перестанет многократно (десятки и сотни тысяч раз за один вечерний расчет) обращаться к одним и тем же настройкам договора по одному — быстрее формирование планов и прочие расчеты, где нужны параметры.

*Объекты расширения:* перехват РС {{ЗначенияПараметровДоговораДУ}} (оптимизация единичного запроса).
{panel}

{panel:title=3.6 | Регламентные периоды — ускорение подбора операций по договору (~4,3% замера)|borderStyle=solid|borderColor=#B8D4CC|titleBGColor=#D5E8E0|bgColor=#F3FAF8}
*Что будет сделано:*
* Перед передачей списков в расчет — добавить «быстрые указатели» (составные индексы таблиц) по паре «договор ДУ + группа операций пользователя».
* Ускорить поиск нужных строк в списках операций и документов по договорам при формировании закрытия периода.

*Зачем бизнесу:* для каждого из ~17 тыс. договоров система быстрее определит, какие регламентные операции нужно выполнить.

*Объекты расширения:* перехват формы {{РегламентныеПериоды.РегламентныйПериод}}.
{panel}

{panel:title=3.7 | План регламентных операций ДУ — ускорение работы со связанными документами (~2,1% замера)|borderStyle=solid|borderColor=#D4C8A8|titleBGColor=#E8E0C5|bgColor=#FAF8F0}
*Что будет сделано:*
* При пометке на удаление подчиненных документов плана — разделить поиск связанных документов на два шага (сначала выборка связей, затем отбор не помеченных на удаление).
* Снизить нагрузку на базу при массовом вечернем расчете.

*Зачем бизнесу:* быстрее обработка планов регламентных операций (блок ~30 мин в общей оценке расчета).

*Объекты расширения:* перехват {{ПланРегламентныхОперацийДУ}} (модуль менеджера).
{panel}

{panel:title=+1 | Расчет СЧА/РСА — устранение коллизии номера при параллельной записи|borderStyle=solid|borderColor=#D4B8B8|titleBGColor=#E8D5D5|bgColor=#FAF3F3}
*Что будет сделано:*
* При записи/проведении документа «Расчет СЧА/РСА» — автоматическая обработка ошибки «номер не уникален»: назначение нового номера и повторная попытка (до 30 раз).
* По аналогии с уже работающим решением в конфигурации МО (IMDEV-8665).

*Зачем бизнесу:* меньше сбоев и ручных перезапусков вечернего расчета при работе в несколько потоков. На скорость напрямую не влияет, повышает надежность завершения регламента.

*Объекты расширения:* {{РасчетСЧА_РСА}} (модуль менеджера), перехват {{ИсполняемыеПроцедурыЗакрытияПериода}}.
{panel}

{panel:title=+2 | Предварительный отсев — ОТМЕНЕН|borderStyle=solid|borderColor=#D4B8C4|titleBGColor=#E8D5DD|bgColor=#FAF3F7}
*Статус:* по решению заказчика пункт **+2** (предварительный отсев блока «Прочие расчеты») **не входит** в поставку rev2.

*Что убрано из расширения:*
* Регистр сведений {{ВидыОптимизируемыхРегламентныхОперацийДУ}}.
* Отсев операций на форме {{РегламентныеПериоды.РегламентныйПериод}}.
* Пакетный метод {{ЗначенияПараметровДоговоровДУ}} в РС {{ЗначенияПараметровДоговораДУ}}.

*Что сохранено:* оптимизация РЕПО (п. 3.1) — функция {{ЗаполнитьСоответствиеПропускРЕПОВетки}} перенесена в модуль менеджера {{РегламентныеПериоды}}.
{panel}
