h2. Что сделать в расширении rev2 — Этап 2 оптимизации вечерних регламентов

{panel:title=3.1 | Переоценка активов — ускорение блока по РЕПО (~7,8% замера)|borderStyle=solid|borderColor=#D4C4B8|titleBGColor=#E8DDD5|bgColor=#FAF6F3}
*Что будет сделано:*
* Перед массовой переоценкой — один пакетный запрос по всем договорам: есть ли остатки по сделкам РЕПО.
* Для договоров целевого пула (розничное ДУ), по которым РЕПО нет, — пропуск лишнего шага заполнения табличной части по РЕПО в документе «Переоценка активов».
* Для договоров с РЕПО расчет останется без изменений.

*Зачем бизнесу:* не тратить время переоценки на запросы и обработку РЕПО там, где по договору РЕПО нет.

*Объекты расширения:* новый РС {{ВидыОптимизируемыхРегламентныхОперацийДУ}}; перехваты {{РегламентныеПериоды}}, {{ИсполняемыеПроцедурыЗакрытияПериода}}, {{ПереоценкаАктивов}}.
*Включение:* константа {{ИспользоватьПредварительныеЗапросыДляВечернихРегламентов}} = Истина.
{panel}

{panel:title=3.2 | Параметры договора ДУ — ускорение чтения настроек (~7,5% замера)|borderStyle=solid|borderColor=#A8C5DA|titleBGColor=#C5D9E8|bgColor=#F0F6FA}
*Что будет сделано:*
* Упростить запрос чтения параметров договора из регистра «Значения параметров договора ДУ» (вместо тяжелой конструкции с временными таблицами — прямой срез последних значений).

*Зачем бизнесу:* система перестанет многократно (десятки и сотни тысяч раз за один вечерний расчет) обращаться к одним и тем же настройкам договора по одному — быстрее формирование планов и прочие расчеты, где нужны параметры.

*Объекты расширения:* перехват РС {{ЗначенияПараметровДоговораДУ}} (оптимизация единичного запроса).
{panel}

{panel:title=3.6 | Регламентные периоды — ускорение подбора операций по договору (~4,3% замера)|borderStyle=solid|borderColor=#B8D4CC|titleBGColor=#D5E8E0|bgColor=#F3FAF8}
*Что будет сделано:*
* Перед передачей списков в расчет — добавить «быстрые указатели» (составные индексы таблиц) по паре «договор ДУ + группа операций пользователя».
* Ускорить поиск нужных строк в списках операций и документов по договорам при формировании закрытия периода.

*Зачем бизнесу:* для каждого из ~17 тыс. договоров система быстрее определит, какие регламентные операции нужно выполнить.

*Объекты расширения:* перехват формы {{РегламентныеПериоды.РегламентныйПериод}}.
{panel}

{panel:title=3.7 | План регламентных операций ДУ — ускорение работы со связанными документами (~2,1% замера)|borderStyle=solid|borderColor=#D4C8A8|titleBGColor=#E8E0C5|bgColor=#FAF8F0}
*Что будет сделано:*
* При пометке на удаление подчиненных документов плана — разделить поиск связанных документов на два шага (сначала выборка связей, затем отбор не помеченных на удаление).
* Снизить нагрузку на базу при массовом вечернем расчете.

*Зачем бизнесу:* быстрее обработка планов регламентных операций (блок ~30 мин в общей оценке расчета).

*Объекты расширения:* перехват {{ПланРегламентныхОперацийДУ}} (модуль менеджера).
{panel}

{panel:title=+1 | Расчет СЧА/РСА — устранение коллизии номера при параллельной записи|borderStyle=solid|borderColor=#D4B8B8|titleBGColor=#E8D5D5|bgColor=#FAF3F3}
*Что будет сделано:*
* При записи/проведении документа «Расчет СЧА/РСА» — автоматическая обработка ошибки «номер не уникален»: назначение нового номера и повторная попытка (до 30 раз).
* По аналогии с уже работающим решением в конфигурации МО (IMDEV-8665).

*Зачем бизнесу:* меньше сбоев и ручных перезапусков вечернего расчета при работе в несколько потоков. На скорость напрямую не влияет, повышает надежность завершения регламента.

*Объекты расширения:* {{РасчетСЧА_РСА}} (модуль менеджера), перехват {{ИсполняемыеПроцедурыЗакрытияПериода}}.
{panel}

{panel:title=+2 | Предварительный отсев — блок «Прочие расчеты» (~20 мин из ~2 ч)|borderStyle=solid|borderColor=#D4B8C4|titleBGColor=#E8D5DD|bgColor=#FAF3F7}
*Контекст:* при полном вечернем расчете на ~17 тыс. договоров ДУ последний блок — *«Прочие расчеты»* — занимает *~20 минут* из *~2 часов* (~17%). Это виды операций, по которым у РДУ *как правило не формируются документы и нет движений*: переоценка денежных средств, списание дефолтных облигаций, контроль уменьшения стоимости портфеля. Сейчас полный цикл по ним запускается по *всем* договорам — в том числе «вхолостую».

*Что будет сделано:*
* Создать регистр сведений «Виды оптимизируемых регламентных операций ДУ» — перечень видов операций, для которых допустим предварительный отсев.
* Перед расчетом на форме «Регламентный период» — один пакетный запрос на каждый вид операции из РС: «есть ли основание для расчета по договору».
* Если основания нет — снять флаг «Выполнять» у строки списка операций (полный цикл регламентной процедуры для договора не запускается).

*Как отсекаем — 7 видов операций (записи в РС):*

|| Вид операции || Оставляем «Выполнять», если... || Иначе (отсекаем) ||
| {{ПереоценкаДенежныхСредств_БУ}} | На договоре есть ненулевые остатки в *иностранной валюте* на банковских, брокерских, ВУ-счетах или в регистре ДС (УУ) — та же логика, что у документа «Переоценка денежных средств» | Нет валютных остатков ДС — переоценка не нужна |
| {{ПереоценкаДенежныхСредств_НУ}} | *(критерий как для БУ)* | *(критерий как для БУ)* |
| {{ПереоценкаДенежныхСредств_УУ}} | *(критерий как для БУ)* | *(критерий как для БУ)* |
| {{СписаниеДефолтныхОблигаций_БУ}} | По договору есть *дефолтные события эмитентов* по источникам публикаций из учетной политики (эквивалент непустого списка статусов эмитентов) | Нет дефолтных событий — списание не формируется |
| {{СписаниеДефолтныхОблигаций_НУ}} | *(критерий как для БУ)* | *(критерий как для БУ)* |
| {{СписаниеДефолтныхОблигаций_УУ}} | *(критерий как для БУ)* | *(критерий как для БУ)* |
| {{КонтрольУменьшенияСтоимостиПортфеля_УУ}} | СЧА за предыдущий период <> 0 *и* (были вводы/выводы активов *или* текущая СЧА меньше СЧА предыдущего периода) — как в операции 1020 | СЧА не уменьшилась и вводов/выводов не было — контроль не нужен |

_Примечание:_ для БУ/НУ/УУ внутри группы критерий отсева одинаковый; в РС — отдельная запись на каждый из 7 видов.

*Зачем бизнесу:* сократить *~20-минутный* блок «прочие расчеты» — не выполнять расчеты по договорам, где документы все равно не появятся. Результат там, где документы нужны, не меняется.

*Ограничения:*
* Отсев только для пула «Розничное ДУ»; при смешанном отборе договоров — не применяется.
* Включение: константа {{ИспользоватьПредварительныеЗапросыДляВечернихРегламентов}} = Истина.

*После загрузки расширения потребуется (настройка ИБ):*
# Заполнить РС {{ВидыОптимизируемыхРегламентныхОперацийДУ}} — 7 записей (по одной на вид из таблицы выше).
# Включить константу {{ИспользоватьПредварительныеЗапросыДляВечернихРегламентов}}.
# Выполнить функциональные тесты и замер вечернего расчета.

*Объекты расширения:* новый РС {{ВидыОптимизируемыхРегламентныхОперацийДУ}}; перехват формы {{РегламентныеПериоды.РегламентныйПериод}}.
{panel}
