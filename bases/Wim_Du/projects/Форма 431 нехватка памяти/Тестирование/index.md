# Проверка версии 1.08 (10.11.2026)

## Что проверено

1. **Компиляция.** `ОПТИМИЗИРОВАНО\внЗаполнениеРеглОтчетаПоДоговорамДУ_0420431_71_1.08.epf` собрана на dev WIM_DU
   (проверка обработчиков форм) и создана через COM `ВнешниеОбработки.Создать(..., Ложь)`: модуль объекта
   компилируется, `СведенияОВнешнейОбработке` возвращает версию 1.08. Так же создана 1.07 из `ОРИГИНАЛ`.
   Компиляция шла в контексте внешнего соединения; форма в тонком клиенте не открывалась (модуль формы не менялся).
2. **Сверка доходности 1.07 и 1.08** на одних данных, скрипт `Скрипты\run_compare.py`, протокол
   `сверка_1_07_1_08.txt`. Тестовая обработка `T431_Сверка.epf` = модуль 1.08 + функция `Т431_Сверка`
   (исходники `T431_src`, код функции `test_harness.bsl`). Функция в одном сеансе считает доходность
   каждого мандата кодом 1.07 (один вызов TWR, индекс строк, `КоличествоДнейВПериодеОтчёта`) и кодом 1.08
   (`ИтогиTWRПоМандатамПачками`) и сравнивает числа целиком, без округления.

## Данные стенда

В dev WIM_MO оценок не было. Скрипт `Скрипты\stand_mo.py fill` записал в регистр `РыночнаяСтоимостьПозиции`

`РасчетРыночнойСтоимости` с UUID `43100000-0431-0431-0431-000000000431` (сам документ не создан).
Варианты: 10 мандатов на весь период, 10 появляются в середине года, 5 начинаются с нулевой оценки,
5 с провалами оценки до нуля. Еще 3 мандата без оценок. Очистка: `python stand_mo.py clear`.

# Замер памяти (10.11.2026)

Стенд расширен до 448 мандатов с оценками (135 304 записи, `stand_mo.py fill 448`) и 3 без оценок.

процедура `Т431_Замер`), то есть серверный вызов ДУ с COM-соединением к МО внутри, как при заполнении.

(`run_compare.py`, протокол `сверка_1_07_1_08_448.txt`): 7 сценариев, 0 расхождений.

Выводы:
- Память расчета TWR считается в вызове ДУ: сеанс МО получает только запросы (единицы МБ).
- Пик определяется числом мандатов в одном вызове TWR: около 1,76 МБ на мандат за 304 дня плюс около 50 МБ.
  Пока стратегия меньше пачки, 1.08 экономит только индекс и хранимую таблицу строк по дням (около 20-40 МБ).

  снизу. Пачка 5000 по этой оценке дает около 9 ГБ на вызов за октябрь и около 11 ГБ за декабрь.

Размер пачки по умолчанию после замера - 500 (`РазмерПорцииМандатовTWR`): по оценке стенда около 1 ГБ памяти вызова за полный год.

# Свертка по позициям строк (10.11.2026)

В `ИтогиTWRПоМандатамПачками` пачка обычной стратегии сворачивается без обхода строк: копия колонки
`Разделитель` со счетчиком свертывается, по числу строк мандата вычисляются позиции первой и последней
строки, обе проверяются по ключу мандата. При расхождении пачка сворачивается прежним обходом строк
(`СвернутьПорциюПоСтрокам`), он же используется для особых стратегий.

Сверка с 1.07 на 2003 мандатах, обычная и особая стратегия, с дублями: 0 расхождений
(`сверка_позиции_2000.txt`). Для обычной стратегии все 5 пачек свернуты по позициям, ни одной построчно.
С принудительно отключенной сверткой по позициям (`run_compare.py quick rows`, `сверка_построчно_2000.txt`)
тоже 0 расхождений.

Замер, три прогона поочередно (`run_memory.py 3`):

| Вариант | Пик вызова ДУ | Время, прогоны 1 / 2 / 3 |
|---|---|---|
| 1.07, 1 вызов на 2000 мандатов | 3651-3669 МБ | 134,7 / 76,8 / 51,8 с |
| 1.08, 5 пачек, свертка по позициям | 949-954 МБ | 105,9 / 40,1 / 37,8 с |

1.08 быстрее 1.07 в каждом прогоне (на 21-48%) и расходует в 3,8 раза меньше памяти. До свертки по позициям
