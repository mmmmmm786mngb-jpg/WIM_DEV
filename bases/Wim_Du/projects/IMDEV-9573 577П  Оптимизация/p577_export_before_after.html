Схема P577: ПостроительDOM и ФабрикаXDTO

Макет около 66 КБ читается в DOM, из него строится фабрика. Этот шаг не заменяется: фабрика дальше пишет те же пространства имен и xsi:type.

Все строки одним деревом XDTO

  1. На каждую строку каждого раздела создается объект XDTO.
  2. Разделы 1-11 и сопроводительное письмо держатся в одном корне.
  3. Фабрика.ЗаписатьXML пишет этот корень целиком.
  4. На каждую ячейку вызывается Свойства().Получить().

стало

Поток ЗаписьXML, по одной строке

  1. ЗаписьXML открывается один раз: объявление, корень P577, Отчетность.
  2. Строка превращается в один объект XDTO, пишется в открытый файл и отпускается.
  3. Сопроводительное письмо дописывается в тот же поток.
  4. Значения по-прежнему проходят через ПривестиЗначениеДляВыгрузки.
тот же результат

Файл xml, двоичные данные, вложение xtdd

Те же теги, тот же порядок по схеме, тот же явный xsi:type, те же даты, числа и символ # для пустых значений.

Не меняется: оба входа, чтение схемы через DOM, фабрика, приведение значений, имя файла и расширение xtdd. Меняется: отчет больше не лежит вторым полным деревом рядом с табличными частями.

Память на пике, было

Табличные части + дерево XDTO всех строк + готовый файл как двоичные данные. И так на каждом из двух вызовов.

Память на пике, стало

Табличные части + одна строка XDTO + двоичные данные готового файла. Дерево всех разделов больше не собирается.
