# Верификация431 - проверка 1.08 против 1.07 на Т-1

Обработка открывается через «Файл - Открыть» в базе ДУ (Т-1), регистрация не нужна.

## Что делает

1. Отбирает договоры, как заполнение 0420431 (УК, период, типы клиентов, цессии), и по базам МО
   (`PROD_AVC_MO`, `PROD_AVC_Retail_MO` или база из поля) читает состав стратегий.
2. Берет стратегии: перечисленные в поле «Коды стратегий» или, если поле пустое и стоит флаг, все крупнее пачки.
3. По каждой стратегии отбирает не больше «Мандатов в проверке» (по умолчанию 10 000) мандатов с наибольшим
   числом дней оценки. Оба расчета получают одни и те же мандаты.
4. Считает доходность двумя способами, каждый отдельным серверным вызовом, сначала 1.08, затем 1.07:
   - 1.08 - область `РасчетTWRПачками` из модуля обработки 1.08 без изменений (пачка берется с формы);
   - 1.07 - один вызов TWR на все отобранные мандаты, индекс строк по мандату, расчет доходности как в 1.07.
   Если 1.07 упадет по памяти, это попадет в отчет, остальные шаги выполнятся.
5. Сравнивает доходность каждого мандата без округления, выводит время, число строк TWR и оценку памяти
   по замерам стенда (память на Т-1 не измеряется).
6. «Сохранить в файл» - лог в UTF-8 для передачи разработчику.

## Оценка памяти 1.07

По замерам стенда около 50 МБ + 1,9 МБ на мандат за полный год (с вводами-выводами): 2 000 мандатов - около 4 ГБ,
10 000 - около 19 ГБ. При лимите памяти на вызов меньше этого 1.07 упадет с ошибкой «Превышен максимальный расход
памяти сервера за один вызов» - это ожидаемый результат, 1.08 при этом посчитается.

## Сборка

`Скрипты\build_verify.py`: модуль объекта собирается из `object_template.bsl` и области `РасчетTWRПачками`
модуля `ОПТИМИЗИРОВАНО`, затем собирается `Верификация431.epf`. Модуль формы - `form_new.bsl` плюс функции
отбора из обработки замера сбора (уже включены в `src`).
