IMDEV-8663.1 / п. 8.13 — задание на доработку
Ускорение параллельного формирования регламентных операций (диспетчер порций)

1. Цель
Снизить время вечернего/утреннего РДУ за счёт изменения модели параллельности:
вместо схемы «один договор = одно фоновое задание» запускать фоновые задания
порциями договоров (чанками) со скользящим окном потоков.
Сохранить пакетную предподготовку пачками и передачу кэша таблиц в задания.

2. Что менять
Объект: Справочник.РегламентныеПериоды (модуль менеджера).

- Ожидание/разбор фоновых заданий порции: актуальный снимок ФоновоеЗадание,
  барьер пачки, отмена активных детей при ошибке родителя, сводка и прогресс.
- Диспетчер пачки: нарезка договоров на порции одной группы операций,
  запуск ФЗ через ОбщегоНазначения.ВыполнитьБПБезопасно
  -> метод менеджера создания планов по порции;
  внутри порции — синхронный вызов существующей СформироватьДокументыЗакрытияПериода.
- В ФЗ передавать срез ПараметрыСохранения: соответствия «договор -> таблица»
  только по договорам порции (не всю пачку целиком).
- Убрать/не использовать параллельную ветку «один договор = одно ФЗ»
  внутри СформироватьДокументыЗакрытияПериода.
- Добавить константы (имена без префикса расширения, удобно переносить в базовую CF):
  * МаксимальныйРазмерПорцииДоговоровВПотокеРегл
    (0 = по умолчанию 50; 1 = фактически «по одному договору на ФЗ»)
  * МаксимальныйРазмерПачкиДоговоровДляПредварительногоЗапросаРегл
    (0 = по умолчанию 3000)
  Чтение по имени через Метаданные.Константы.Найти; если константы нет — дефолт.
- Число параллельных потоков — как сейчас, из МаксимальноеКоличествоПараллельныхПотоков.

Пилот/поставка: расширение IM8663 (CFE), далее перенос в базовую конфигурацию вендором.

3. Что исправляем по code review (CR)
По результатам CR фоновых заданий регламента (см. code_review_background_jobs):

- BG-02: безусловное ожидание «хвоста» ФЗ в конце пачки/прогона
  (раньше ожидание могло не сработать, если у последнего договора нет операций).
- BG-14: разбор статуса аварии по актуальному снимку после
  ОжидатьЗавершенияВыполнения (не по устаревшему объекту ФоновоеЗадание).
- BG-03: явный барьер пачки перед следующей предподготовкой / завершением.
- BG-10: при исключении родителя — отмена ещё активных дочерних ФЗ.
- BG-11: журнал регистрации по аварийным заданиям + краткая сводка в конце прогона.
- BG-06/BG-07: порции договоров и скользящее окно потоков (вместо 1 договор = 1 ФЗ).

Не делаем по CR: обязательный таймаут с автоотменой зависаний; возврат к схеме
«один договор = одно задание» как основному режиму.

4. Планируемый результат
- Сокращение времени регламента на больших отборах за счёт меньшего числа ФЗ
  и меньшей накладной нагрузки платформы при той же прикладной логике операций.
- Закрытие дефектов/рекомендаций CR по ожиданию, снимку ФЗ, барьеру, отмене детей, сводке.
- Настраиваемые размеры порции и пачки без правки кода.
- Корректный прогресс/сводка, безопасное завершение при ошибках.

Предварительный замер на DR (тестовая база):
- ФЛ, не Розничное ДУ (~3000 договоров): ~40 мин -> ~20 мин.
- Розничное ДУ (~22 000 договоров): ~1,5 ч -> ~45 мин.

Ускорение зависит от стенда, числа потоков и состава операций; гарантировать
конкретный коэффициент в проде нельзя — ориентир по пилоту DR.
