Вердикт: логика IM8663 в базовую CF внесена. Пропусков по чеклисту HTML нет.

Есть точечные отличия от инструкции вендору: функция чтения константы вынесена в общий модуль, плюс обвязка (форма настроек и права ролей), которой в HTML не было. Алгоритм диспетчера, барьер пачки, воркер ФЗ и удаление схемы «1 договор = 1 ФЗ» совпадают с пилотом.

4.2 СформироватьРегламентныеОперации — шесть точек

  1. Init после проверки ПараметрыСохранения: ФоновыеЗаданияДоступны (потоки > 0 и ФоновыеЗаданияРазрешены), счётчики, ПроблемныеДоговоры, РазмерЧанкаПоУИД, таймер IM8663_НачалоРасчетаМС, РазмерЧанка из константы порции.
  2. РазмерПачки: литерал 3000 убран, чтение константы пачки + защита < 1.
  3. Цикл пачки: при доступных ФЗ — ОбработатьПачкуДиспетчером; иначе прежний последовательный цикл.
  4. Барьер пачки: ЗавершитьФоновыеЗаданияПорции(ПараметрыСохранения) после ветки.
  5. Финал: повторный барьер, расчёт времени, ТекстСводки, Результат.Сообщение = ТекстСводки вместо пустой строки.
  6. Исключение: ОтменитьАктивныеЗадания(ПараметрыСохранения) в начале.

Маркеры // IMDEV-8663.1.A / // IMDEV-8663.1.B в CF сохранены.

4.4 Новые методы — тела совпали

После снятия префикса IM8663_ тела четырёх процедур совпадают с CFE:

  • ЗавершитьФоновыеЗаданияПорции — ожидание, актуальный снимок, прогресс барьера, счётчики (этап A).
  • ОтменитьАктивныеЗадания — отмена активных детей (BG-10).
  • ОбработатьПачкуДиспетчером — очередь порций, срез соответствий, скользящее окно.
  • СоздатьПланыРегламентныхОперацийПоЧанку — Экспорт, цикл договоров → sync СформироватьДокументыЗакрытияПериода.

Ключи структуры IM8663_НачалоРасчетаМС, IM8663_Прогресс* и ключ ФЗ IM8663_%1_%2_%3_%4 оставлены как в пилоте. HTML требовал убрать префикс только у имён процедур и их вызовов, не у этих ключей.

5.2 СВЕРХ HTML форма НастройкаСистемы

HTML запрещал менять форму РегламентныйПериод (сборка ПараметрыСохранения). Форма периода не менялась.

Вендор дополнительно вывел обе константы на общую форму НастройкаСистемы рядом с МаксимальноеКоличествоПараллельныхПотоков.

Это не ломает диспетчер: значения констант можно задавать из интерфейса, а не только через Конфигуратор / консоль. В карте изменений этого шага не было.

5.3 СВЕРХ HTML права ролей

В CFE ролей не было. В CF на новые константы прописаны Read / View в шести ролях:

  • БазовыеПрава
  • СпециалистБэкОфиса
  • СпециалистБухгалтерии
  • Контролер
  • РитейлСейлз
  • ТолькоПросмотр

Права Update в этих ролях нет. Запись констант, как обычно, через ПолныеПрава (для новых объектов конфигурации). Это типовая обвязка CF, не часть ТЗ 8663.1.

5.4 Что расхождением не является

  • Ключи IM8663_* в структуре параметров и в ключе ФЗ — так было в пилоте; HTML снимал префикс только с имён процедур.
  • Новые UUID констант в CF — объекты созданы в базовой конфигурации, не импортом UUID расширения.
  • Комментарий в СформироватьДокументыЗакрытияПериода про удалённую ветку — перенесён из CFE, это нормально.

7. Внедрение на ИБ

Не код вендора, но обязательный шаг HTML. После выкладки этой CF на информационную базу расширение IM8663 нужно снять. Иначе платформа наложит перехваты CFE поверх уже изменённых типовых процедур — двойная логика диспетчера. В диффе исходников CF этот шаг не виден: это зона внедрения, не зона разработки вендора.
Если на ИБ ещё стоит пилот IM8663, сначала обновить конфигурацию БД из этой CF, затем отключить/удалить расширение и проверить, что фоновые порции стартуют со строкой Справочники.РегламентныеПериоды.СоздатьПланыРегламентныхОперацийПоЧанку (без префикса IM8663_).

8. Выводы

  1. Перенос IMDEV-8663.1 в базовую CF состоялся. Чеклист HTML (шаги 1-9 + 3а) по смыслу закрыт. Пропущенных точек вставки/удаления нет.
  2. Алгоритм пилота сохранён: диспетчер порций, скользящее окно, барьер пачки, отмена детей, sync-создание плана, запуск воркера через ВыполнитьБПБезопасно.
  3. Единственное содержательное отличие инструкции — функция чтения константы живёт в ОбщегоНазначенияДУ, а не в модуле менеджера. Поведение то же.
  4. Сверх объёма: поля на НастройкаСистемы и Read/View в шести ролях. На работу регламента не влияют; удобны для администрирования.
  5. 8663.2 в этот релиз не входил — соответствует HTML.
  6. Перед продом: снять расширение IM8663 с ИБ, чтобы не получить двойные перехваты.
