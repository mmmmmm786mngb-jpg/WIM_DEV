1. Задание одной фразой

Создай расширение IM8663 для базы Wim_Du: этап A (ожидание фоновых) плюс этап B (диспетчер чанков) сразу как единственный параллельный режим. Констант расширения нет. Размер чанка — переменная 50 в коде. Новых прикладных процедур — минимум (см. ТЗ раздел 3).

3. Skills репозитория (использовать, не изобретать XML вручную)

  1. cfe-init — scaffold расширения. -Name IM8663, -NamePrefix IM8663_, -Purpose Customization, -Vendor WIM_DEV, -Synonym «IMDEV-8663.1 фоновые задания регламентных операций», -ConfigPath = выгрузка CF из source-path.txt + \SRC\CF, -OutputDir = каталог Расширения/IM8663.
  2. cfe-borrow — заимствовать Catalog.РегламентныеПериоды ;; CommonModule.ФоновыеЗаданияСервер.
  3. cfe-patch-method — два перехвата ModificationAndControl на СформироватьРегламентныеОперации и СформироватьДокументыЗакрытияПериода (Catalog.РегламентныеПериоды.ManagerModule). После генерации каркаса вставить полное тело из текущей CF и разметить #Вставка / #Удаление по ТЗ. Не оставлять TODO.
  4. cfe-validate — в конце.

Форму РегламентныйПериод не заимствовать. Общий модуль ФоновыеЗаданияСервер: сервер, вызов сервера — как в базе; не включать лишние флаги.

5. Порядок реализации

Шаг 1. Каркас

Init и borrow. Константы метаданных не создавать.

Шаг 2. Этап A (можно проверить без B)

  1. Добавить две процедуры в область A по текстам ТЗ раздел 5. У IM8663_ЗавершитьФоновыеЗаданияПорции сразу заложить параметр ЖдатьВсех = Истина (ТЗ 6.3), чтобы на шаге 3 не переписывать сигнатуру.
  2. Перехват СформироватьРегламентныеОперации: инициализация ФоновыеЗаданияДоступны, счётчиков и РазмерЧанка = 50; после цикла договоров пачки — барьер, затем существующий замер; после всех пачек — барьер и сводка; в Исключение — отмена детей. Ветку диспетчера на этом шаге можно ещё не вставлять.
  3. Перехват СформироватьДокументыЗакрытияПериода: кэш ФоновыеЗаданияДоступны; #Удаление блока ожидания/разбора/очистки; #Вставка вызова завершения порции при Количество() >= КоличествоПотоков. Условие ТекЗначение = МаксимальноеЗначение из ожидания убрать.

Шаг 3. Этап B

  1. В том же перехвате родителя после предподготовки пачки — ветка ФоновыеЗаданияДоступны (ТЗ 6.2): диспетчер. Иначе последовательный цикл по договорам. Старый параллельный цикл «одно задание на договор» не оставлять.
  2. IM8663_ОбработатьПачкуДиспетчером — очередь, срез, скользящее окно. Не дробить на 5 процедур.
  3. Экспорт менеджера + тонкая обёртка в ФоновыеЗаданияСервер. Воркер вызывает существующую СформироватьДокументыЗакрытияПериода с КоличествоПотоков = 0 и ФоновыеЗаданияДоступны = Ложь на копии параметров. Нарезку таблиц не копировать.
  4. Метод ФоновыеЗадания.Выполнить: "ФоновыеЗаданияСервер.IM8663_СоздатьПланыРегламентныхОперацийПоЧанку", массив из одной структуры параметров.

6. Что нельзя

Запрещено
  • Править файлы в C:\1c\Cursor_1c\WORK\Wim_Du и любой SRC\CF базы.
  • Менять тело СоздатьПланРегламентныхОперацийДУ.
  • Делать отдельные процедуры «подготовить диспетчер / очередь / запуск / срез / окно / разбор».
  • Перехватывать ОжидатьЗавершенияТекущихФоновых.
  • Ставить автоотмену по таймауту 1800 сек.
  • Передавать в задание кэш всех 3 000 договоров пачки.
  • Заимствовать форму.
  • Создавать константы IM8663_ИспользоватьДиспетчер... и IM8663_РазмерЧанка....
  • Оставлять старый параллельный режим «один договор = одно задание» рядом с диспетчером.
  • Копировать модули из расширений IMDEV-8899 / IMDEV-8926 как основу. Сверять тела только с текущей CF.
  • Писать реализацию СЧА/РСА (это IMDEV-8663.2).

7. Критерии готовности кода (без прогона на базе)

  • Расширение валидируется cfe-validate.
  • Четыре прикладные процедуры + одна обёртка общего модуля, области и маркеры на месте.
  • Перехваты содержат полное актуальное тело CF плюс точечные #Вставка/#Удаление.
  • При потоках > 0 и доступных фоновых вызывается диспетчер, не цикл «один договор = задание».
  • При 0 потоков диспетчер не стартует.
  • Барьер пачки вызывается и после диспетчера, и после последовательного цикла.
  • Своих констант в расширении нет. РазмерЧанка = 50 задан в коде.
Тесты на живой базе Этот промпт не требует самому гонять вечерний регламент, если пользователь не попросил. Сценарии T-01…T-07 и D-02…D-11 описаны в ТЗ — после кода кратко написать, что проверять вручную. D-09/D-10 — отдельный прогон на копии, не часть первой сборки расширения.

8. Стиль 1С

  • Переменные и процедуры: PascalCase.
  • Попытка только там, где ошибка реально неопределена (воркер по договору чанка, отмена задания).
  • Не конкатенировать текст запроса; здесь запросов новых нет.
  • Не использовать Константы прикладной логики. Состояние диспетчера и размер чанка — структура в памяти родителя.
