2. `CommonModules/ФоновыеЗаданияСервер` — общий модуль **только с одной процедурой-заглушкой**:

```bsl
Процедура IM8663_СоздатьПланыРегламентныхОперацийПоЧанку(ПараметрыЧанка) Экспорт

```

Заглушка появилась потому, что платформенный `ФоновыеЗадания.Выполнить(<ИмяМетода>, ...)` принимает
только экспортные методы **неглобального общего модуля**. Модуль менеджера напрямую не принимается.

## 2. Цель

Полностью удалить заимствование общего модуля `ФоновыеЗаданияСервер` из расширения, сохранив запуск
процедуры модуля менеджера в фоновом задании. В расширении должен остаться **один** заимствованный
объект — справочник `РегламентныеПериоды`.

## 3. Что уже проверено (не перепроверять, использовать как данность)

В типовой конфигурации есть готовые универсальные обёртки — экспортные процедуры неглобальных
серверных общих модулей, которые вызывают целевой метод оператором `Выполнить` и допускают имя из
трёх частей вида `Справочники.<Имя>.<Метод>`:

| Обёртка | Файл типовой | Сигнатура |
|---|---|---|
| `ОбщегоНазначения.ВыполнитьБПБезопасно` | `SRC\CF\CommonModules\ОбщегоНазначения\Ext\Module.bsl`, стр. 158 | `(ИмяЭкспортнойПроцедуры, Параметры = Неопределено, ОбластьДанных = Неопределено)` |
| `ДлительныеОперации.ВыполнитьСКонтекстомКлиента` | `SRC\CF\CommonModules\ДлительныеОперации\Ext\Module.bsl`, стр. 638 | `(ВсеПараметры)` — структура `ИмяПроцедуры`, `ПараметрыПроцедуры` |

Дополнительные факты:

- В `ВыполнитьБПБезопасно` для трёхчастного имени список допустимых типов содержит `ИмяТипаСправочники()`,
  которая возвращает строку `"Справочники"`. Наш формат имени проходит проверку.
- Оба общих модуля имеют `Global = false` и `Server = true`, то есть пригодны для `ФоновыеЗадания.Выполнить`.
- Переход в безопасный режим и работа с разделителями в обеих обёртках закомментированы, поведение
  идентично прямому вызову.
- Типовая форма `Catalogs\РегламентныеПериоды\Forms\РегламентныйПериод\Ext\Form\Module.bsl`, стр. 988,
  уже запускает `ДлительныеОперации.ВыполнитьВФоне("Справочники.РегламентныеПериоды.СформироватьРегламентныеОперации", ...)`,
  то есть механизм в этой базе рабочий и обкатанный.
- Функции `ФоновыеЗаданияСервер.ФоновыеЗаданияРазрешены()` (стр. 8) и
  `ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ(...)` (стр. 244) находятся **в типовом**
  общем модуле. После удаления заимствования из расширения эти вызовы продолжат работать —
  их трогать не нужно.

## 4. Чего делать НЕЛЬЗЯ

- **Не использовать** `ДлительныеОперации.ЗапуститьФоновоеЗаданиеСКонтекстомКлиента` в диспетчере.
  Первая же её строка — `Если ТекущийРежимЗапуска() = Неопределено Тогда` — уводит в ветку прямого
  `ФоновыеЗадания.Выполнить(ИмяПроцедуры, ...)`. Диспетчер сам работает внутри фонового задания,
  клиентского приложения там нет, поэтому будет ошибка «Метод объекта не обнаружен».
- **Не использовать** `ДлительныеОперации.ВыполнитьВФоне` для запуска чанков: она требует
  `ИдентификаторФормы` для временного хранилища, навязывает целевой процедуре сигнатуру
  `(Параметры, АдресРезультата)` и в файловой ИБ при наличии активных заданий выполняет процедуру
  синхронно, что убивает параллельность диспетчера.
- **Не менять** запуск родительской операции с формы — он остаётся через `ДлительныеОперации.ВыполнитьВФоне`.
- **Не менять** типовую конфигурацию. Все правки — только в расширении.
- **Не переносить** `IM8663_СоздатьПланыРегламентныхОперацийПоЧанку` куда-либо: процедура остаётся
  в модуле менеджера справочника и обязана сохранить ключевое слово `Экспорт`.
- **Не редактировать** `Расширения/IM8663/Catalogs/РегламентныеПериоды/Ext/ManagerModule.bsl` вручную
  как единственный источник — см. п. 5.1, файл генерируется скриптом.

## 6. Тестирование

1. Открыть справочник «Регламентные периоды», выбрать период с небольшим числом договоров

3. Убедиться, что:
   - порции стартуют как отдельные фоновые задания, а не падают с «Метод объекта не обнаружен»;
   - прогресс идёт в формате «Обработано N из M, активно порций …»;
   - итоговая сводка содержит число успешных заданий и заданий с ошибкой;
   - документы «План регламентных операций ДУ» созданы по всем договорам отбора;

   `IM8663_ЗавершитьФоновыеЗаданияПорции`. После проверки вернуть корректное имя.

## 7. Известные риски

- **Видимость метода расширения через `Выполнить`.** Модуль менеджера расширения компилируется в один
  контекст с типовым, поэтому имя `Справочники.РегламентныеПериоды.IM8663_СоздатьПланыРегламентныхОперацийПоЧанку`
  должно разрешаться из кода типовой. Это штатное поведение платформы, но проверяется только на стенде —
  см. п. 6.3. Если метод не разрешается, откатиться к заглушке и зафиксировать причину.
- **Нет контроля синтаксиса.** Имя метода передаётся строкой и исполняется через `Выполнить`, опечатка
  проявится только в рантайме, в виде аварийно завершённого задания.
- **Ключ задания.** Уникальность требуется в разрезе имени метода, а имя теперь общее для конфигурации.
  Префикс `IM8663_` в ключе обязателен, без него возможен конфликт с чужой длительной операцией,
  запущенной через `ДлительныеОперации.ЗапуститьВыполнениеВФоне` (она использует ту же обёртку).
- **Диагностика.** В консоли заданий и журнале регистрации в поле «Имя метода» будет видна обёртка,
  а не целевая процедура. Порции различаются по наименованию задания.
