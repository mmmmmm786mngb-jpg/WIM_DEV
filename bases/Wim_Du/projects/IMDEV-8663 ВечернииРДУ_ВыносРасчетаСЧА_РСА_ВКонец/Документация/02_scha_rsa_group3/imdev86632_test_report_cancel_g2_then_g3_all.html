1. Введение

На форме регламентного периода список договоров для кнопки «Создать» берётся из динамического списка — пользователь может отметить «все». Для группы 3 это не значит «посчитать СЧА по всей базе». Перед стартом ОтобратьДоговорыДляГруппыСЧАНаСервере сужает список до договоров с проведённым планом группы 2. "Вечерние" операции за ту же дату. После «Отмены» вечернего расчёта автозапуск группы 3 не вызывается (ПослеУспешногоЗавершенияГруппы не идёт из окна ожидания порций). Поэтому ручной запуск группы 3 «по всем» должен создать столько же документов, сколько вечерних планов успело записаться.

Как смоделирована отмена во внешнем соединении Полный диспетчер по 600 договорам из COM не запускался: он создал бы рабочие документы вечерних операций. Состояние «после Отмены» собрано так же, как его видит отбор группы 3: первая порция (50 договоров, размер порции по константе) уже провела планы группы 2; остальные 550 порций родитель не стартовал; живые порции с ключом IM8663_ доработаны ожиданием и не создают группу 3. Дальше вызываются те же экспортные методы, что форма после выбора группы 3.

6. Возможности, которые подтверждены

  • После отмены группы 2 остаются только уже проведённые вечерние планы; группа 3 сама не стартует.
  • Запуск группы 3 по полному списку договоров сужается до договоров с планом группы 2.
  • Число документов группы 3 совпадает с числом успевших планов группы 2 (50 из 600).
  • По договору без вечернего плана план группы 3 не записывается.
  • Реквизит «План вечерних операций» заполняется из проведённого плана группы 2.

7. Выводы

Сценарий подтверждён: из 600 договоров после отмены группы 2 осталось 50 вечерних планов, группа 3 по полному списку создала столько же документов и не взяла остальные.

Сценарий совпадает с работой на форме: «Отмена» не откатывает уже записанные вечерние планы и не открывает автозапуск группы 3. Поздний ручной запуск группы 3 «по всем» безопасен — лишние договоры отбор отсекает.
