1. Задание (цель и результат)

Роль: ты — разработчик 1С:Предприятие 8.3 (управляемое приложение). Целевая база — Wim_Du 1.5.29.10, в неё вендор уже влил IMDEV-8663.1. Твоя поставка — две вещи: новое расширение IM86632 (префикс IM86632_, назначение Customization) и внешняя обработка для отдела поддержки (группа 3 и перенос пяти операций). Старое расширение IM8663 не трогать, не подключать и не расширять.

Цель задачи IMDEV-8663.2:

  1. Организационная часть. Вынести пять регламентных операций расчета СЧА/РСА из группы «2. "Вечерние" операции» в новую группу «3. "Расчет СЧА/РСА"», которая выполняется после того, как по всем договорам завершены все вечерние операции. Это снимает эффект, когда «медленный» расчет СЧА/РСА держит поток и тормозит остальные вечерние операции, и позволяет считать СЧА/РСА на полностью сформированных остатках.
  2. Оптимизационная часть (только РСА/СЧА, ОВ-4). Заменить расчет операции 1000 «по одному договору в цикле» на пакетный расчет по группе договоров с одинаковой сигнатурой параметров: один запрос на группу договоров вместо N запросов по одному договору. Готовые данные раскладываются по договорам и передаются в исполняемую процедуру через уже существующий механизм СоответствиеОперацияТаблица (IMAPPS-35037). Операции 1010/1020/1030 в этой задаче не оптимизируются — только переезд в группу 3.

Запуск групп (решение постановщика). Два режима на форме РегламентныйПериод, оба обязательны:

  1. Вручную, два нажатия (режим по умолчанию). Пользователь выбирает группу 2 и запускает, затем отдельно выбирает группу 3 и запускает. При пересчете только вечерних — предупреждение, что СЧА/РСА нужно пересчитать отдельно (ОВ-3, флаг выключен).
  2. Флаг на форме «После вечерних операций запускать расчет СЧА/РСА». Если установлен и запущена группа 2 — после её успешного завершения автоматически стартует группа 3 (тот же отбор договоров, отдельная длительная операция). Специальных сообщений нет: планы группы 3 и документы РасчетСЧА_РСА помечаются на удаление и пересчитываются штатно, как сейчас при повторном запуске той же группы.

5.2 Обработка для отдела поддержки — группа 3 и перенос операций

Это не «просто код» и не шаг разработчика в Конфигураторе. Группы «1. Утренние» / «2. Вечерние» — данные ИБ, не предопределенные элементы: ПерезаполнитьПредопределенныеДанные их не создает, Родитель у видов операций кодом не заполняется. Ту же природу имеет группа «3. Расчет СЧА/РСА». Поэтому поставка для внедрения — внешняя обработка (EPF) отделу поддержки: открыть, проверить план, подтвердить, получить протокол. На каждой информационной базе (тест, копия, прод) обработку запускают отдельно.
Запрещенные замены обработки:
  • экспортная функция только в модуле расширения IM86632 без формы;
  • вызов из ПриСозданииНаСервере формы РегламентныйПериод;
  • автозапуск при подключении расширения;
  • фрагмент для консоли запросов / «выполнить код»;
  • правка элементов справочника руками «по инструкции из пяти строк» как единственный способ (ручной контроль после обработки — да, вместо обработки — нет).
Алгоритм переноса живёт в модуле объекта обработки. Вход для человека — форма.

АР-9 — барьер групп внутри одной пачки

Основной сценарий — одна группа в одном вызове (АР-10). Барьер — страховка, если МассивРодителей всё же больше одного. Очередь чанков строится по группам подряд; без барьера скользящее окно потоков может запустить чанк группы 3, пока ещё считаются чанки группы 2.

Объявить локальную переменную сразу перед внешним циклом ожидания/запуска (Пока ИндексОчереди < ОчередьЧанков.Количество()). Вставку барьера ставить до ИндексОчереди = ИндексОчереди + 1, иначе «заглянутый» чанк следующей группы будет пропущен.

        ИндексОчереди = 0;

+#Вставка
+        ТекущаяГруппаЧанков = Неопределено; // IMDEV-8663.2 АР-9
+#КонецВставки
        ПараметрыСохранения.Вставить("ОбработаноВПачке", 0);
            Пока ПараметрыСохранения.СписокФоновыхЗаданий.Количество() < КоличествоПотоков
                И ИндексОчереди < ОчередьЧанков.Количество() Цикл

                Чанк = ОчередьЧанков[ИндексОчереди];
#Вставка
                // IMDEV-8663.2 АР-9: не стартовать чанки следующей группы, пока живы задания текущей.
                // Индекс очереди увеличивать только после прохождения барьера.
                Если ТекущаяГруппаЧанков <> Неопределено

Не складывать группу 2 и группу 3 в один МассивРодителей с формы. Барьер — защита диспетчера, не замена двух длительных операций.

Где: стр. 143–217 (область ТЕКСТ_ЗАПРОСА, БУ) и стр. 240–525 (текст запроса УУ), плюс блок СС незавершенных сделок (~527–617).

Что сделать: литералы запросов перенести в функции-конструкторы. Однодоговорной метод после рефакторинга вызывает те же конструкторы с Пакетно = Ложь. Пакетный путь — с Пакетно = Истина. Оборачивать однодоговорной метод пакетным нельзя (АР-4).

Как копировать запрос в 1С. Символ | в начале строки литерала — это синтаксис многострочной строки, его нет в Запрос.Текст в рантайме. Поэтому СтрЗаменить ищет фрагмент без | (например ХозрасчетныйОстатки.Счет КАК ИсточникПоказателя,). После | в литерале должна остаться табуляция, как в исходнике: иначе поиск по СГРУППИРОВАТЬ ПО не совпадёт (таб ≠ четыре пробела). Литералы в этом промпте сверены с областями ТЕКСТ_ЗАПРОСА CF 1.5.29.10 (стр. 143–205, 240–495, 534–582). Если выгрузка новее — сверить ещё раз; правила трансформации те же.

7. Тест-план и критерии приемки

7.1 Обязательный тест эквивалентности (главный критерий)

  1. На копии базы за фиксированную дату выполнить расчет с выключенной константой — эталон.
  2. Выгрузить эталон: по каждому договору — СуммаРСА, СуммаСЧА и построчно ТЧ РасчетРСА / РасчетСЧА (ИсточникПоказателя, Показатель, Сумма).

  4. Сверить: расхождений быть не должно ни в одной строке. Сверку делать запросом/обработкой, а не выборочно глазами.

9. Решения постановщика

ОВ-1 — решено. ВремяРеглОпераций группы «3. Расчет СЧА/РСА» копируется с группы «2. "Вечерние" операции». Операции просто переезжают из того же родителя, чтобы запускать их отдельным прогоном; время суток у планов не меняется. Порядок в дереве даёт код «3. ...». Дата расчета сумм по-прежнему из ОкончаниеРабочегоДня, не из времени группы.
ОВ-2 — решено. Строки 26–30 ПолучитьСуммыРСА_СЧА (ВалютаРегл, площадка, курсы по TM-3363) — мертвый код: результаты не используются, Отказ не выставляется. В пакетном методе эти вызовы не воспроизводить. Однодоговорную процедуру не вычищать — не объем этой задачи.
ОВ-3 — решено. Ручной запуск двумя нажатиями — основной сценарий и всегда доступен. При пересчете только вечерних (флаг выключен) — предупреждать, что СЧА/РСА нужно пересчитать отдельно; планы группы 3 с вечера не чистить. Флаг на форме «После вечерних операций запускать расчет СЧА/РСА»: если включен — после успеха группы 2 автоматически стартует группа 3, отдельных сообщений нет, документы помечаются на удаление и пересчитываются штатно, как сейчас. Подробности — п. 5.9–5.10, АР-10.
ОВ-4 — решено. Пакетно оптимизируем только расчет РСА/СЧА (операция 1000). Операции 1010/1020/1030 в этой задаче только переносятся в группу 3, расчет не меняется.
