1. Цель

Два связанных дефекта после разделения групп «2. Вечерние операции» и «3. Расчет СЧА/РСА».

NПроблемаЧто сделать
1 Кнопка «Отмена» окна длительной операции гасит только родительское задание. Дочерние порции с ключом IM8663_… живут. Повторное «Создать» ловит ошибку уникальности ключа ФЗ и/или второй план за день. При отмене и перед новым «Создать» остановить активные ФЗ с ключом IM8663_ на эту дату и дождаться остановки. Снимок планов — только после этого. Штатное перепроведение найденного плана не переписывать.
2 Группа 3 стартует по всему отбору формы. Связи между планом СЧА/РСА и планом вечерних нет: РасчетСЧА_РСА.ДокументОснование указывает на план группы 3, а не на вечерний. Группа 3 (ручной «Создать» и автозапуск) — только договоры с проведенным планом группы 2 за дату. На плане группы 3 — реквизит ПланВечернихОпераций (ссылка на этот вечерний план).
Как уже работает «Создать», если план есть в снимке. ПолучитьДоговораДУпоДинамическомуСписку один раз заполняет ДокументыПоДоговорам. Диспетчер для найденной строки вызывает ПолучитьОбъект(), чистит ТЧ, записывает проведением и заново выполняет операции при НЕ УчитыватьВыполненные. Это штат CF. Не продавать как новую работу и не менять этот контур. Ошибка «два документа в один день» возникает, когда плана нет в снимке, а в базе уже есть проведенный: тогда идёт СоздатьДокумент() и ПроверитьНаличиеСуществующегоДокумента. Снимок пустой, пока живые порции ещё пишут планы после «Отмена».
Честная граница проверки (в коде так и закладывать). Фильтр группы 3 смотрит на проведенный план группы 2, а не на каждый вид документа внутри плана (котировки, НКД, переоценка поштучно). Если план есть, а документ внутри не записался — группа 3 договор всё равно возьмёт. Пуловые / общие операции (План общих рег операций) в объём не входят.

2. Запрещено

  • Править базовую CF Wim_Du. Только расширение IM86632.
  • Вызывать cfe-init, пересоздавать расширение, откатывать UX этапа 2 и пакет этапов 3–4.
  • Переименовывать ключ порции IM8663_%1_%2_%3_%4 (дата yyyyMMdd + индекс пачки + номер чанка + XMLСтрока группы).
  • Заимствовать / перехватывать ФоновыеЗаданияСервер.
  • Перехватывать целиком ПолучитьДоговораДУпоДинамическомуСписку (большой метод, дрейф). Фильтр — после её вызова, в уже существующем перехвате формы.
  • Раскомментировать массовую отмену/пометку планов в этой функции.
  • Писать в РасчетСЧА_РСА.ДокументОснование ссылку на вечерний план (критерий «Связанные документы» сломается). Связь — отдельный реквизит на плане группы 3.
  • Менять состав операций, флажок автозапуска, пакетный расчет 1000, константу, «Создать с учетом выполненных», обработку поддержки переноса в группу 3.
  • Добавлять новый флажок на форму периода. Отбор и связь — штатное правило запуска.
  • Схлопывать два проведенных плана в один. Уникальность CF не трогать.
  • Одновременно держать IM86632 и IM86632T1 на одной ИБ (одинаковый префикс). IM86632T1 в этой задаче не править, пока явно не попросили скопировать те же правки.

4. Задача 1. Отмена порций

4.1. Почему нельзя звать типовой ОтменитьАктивныеЗадания

В CF это неэкспортный метод менеджера: обходит ПараметрыСохранения.СписокФоновыхЗаданий текущего прогона. После «Отмена» окна ДТО структура сессии формы уже не та: родитель погашен, список детей потерян, а платформенные задания с ключом IM8663_… живы.

Ключ родителя ДТО — Строка(Новый УникальныйИдентификатор), не IM8663_. Гасить нужно детей по префиксу ключа.

4.2. Алгоритм ОтменитьПорцииРегламентаЗаДату

  1. Префикс: "IM8663_" + Формат(ДатаПериода, "ДФ=yyyyMMdd"). Не трогать порции других дат.
  2. ФоновыеЗадания.ПолучитьФоновыеЗадания с отбором Состояние = Активно. Отбор по Ключ в платформе — точное равенство, не префикс; поэтому цикл по активным и СтрНачинаетсяС(Задание.Ключ, Префикс).
  3. Для совпавших: Задание.Отменить(), собрать массив.
  4. Ждать ФоновыеЗадания.ОжидатьЗавершенияВыполнения (как диспетчер CF, шаг 5 сек), не ОжидатьЗавершения: отменённое задание для второго метода — аварийное завершение, будет исключение.
  5. Цикл, пока среди отобранных есть СостояниеФоновогоЗадания.Активно.
  6. Не заимствовать ФоновыеЗаданияСервер. Платформенный менеджер ФоновыеЗадания из модуля менеджера справочника доступен.
Ключ порции не содержит пользователя. Два сеанса на одну дату и так конфликтуют по уникальности ключа. Отмена всех активных IM8663_ этой даты — то же правило, что у ключа. Не добавлять в ключ пользователя и не переименовывать шаблон.

5. Задача 2. Отбор группы 3 и связь

5.1. Фильтр списка договоров

После снимка списка: если ГруппаРегламентныхОпераций.Код равен КодГруппыСЧА формы (реквизит уже есть) и код группы 3 в ИБ найден:

  • заменить массив результатом ДоговорыСПроведеннымВечернимПланом;
  • если 0 элементов — Отказано = Истина, текст вроде: «Нет договоров с проведенным планом вечерних операций за выбранную дату. Группа «3. Расчет СЧА/РСА» не запущена.»

Для группы 2 массив не фильтровать (иначе вечерние не на чем стартовать).

СписокОпераций во временном хранилище может содержать «лишние» договоры — диспетчер крутит СписокДоговоровДУ. Достаточно сузить этот массив.

5.2. Заполнение реквизита при записи плана

В &После("ПередЗаписью") модуля объекта плана:

  1. Если ОбменДанными.Загрузка или уже Отказ или пометка удаления — выход.
  2. Если группа документа не группа 3 — выход (вечерний план реквизит не заполняет).
  3. ПланВечернихОпераций = НайтиПроведенныйВечернийПлан(Дата, ДоговорДУ).
  4. Если пусто — сообщение пользователю, Отказ = Истина. После клиентского фильтра это защита от записи вручную / гонки.

Типовой ПередЗаписью плана заканчивается около проверки закрытого периода и пометки удаления. &После выполняется после него — реквизит попадёт в запись.

5.3. Формы

  • План: поле объекта Объект.ПланВечернихОпераций, ReadOnly, кнопка открытия. После ГруппаОперацийПользователя.
  • Расчет СЧА/РСА: типовое поле ДокументОснование уже есть (только просмотр). Добавить реквизит формы (не реквизит документа) и поле после основания. Заполнить в &После("ПриЧтенииНаСервере"); если на типовой форме нет ПриСозданииНаСервере — не выдумывать тяжёлый перехват, достаточно чтения существующего документа (сценарий приёмки: открыть расчет СЧА/РСА).
  • Цепочка для пользователя: расчет СЧА/РСА → план группы 3 (основание) → ПланВечернихОпераций → котировки / НКД / переоценка (уже подчинены вечернему плану).

5.4. Права

В Roles/ПраваНаРегламентыСЧА_РСА/Ext/Rights.xml добавить View и Edit на Document.ПланРегламентныхОперацийДУ.Attribute.ПланВечернихОпераций. Роль целиком через role-compile не пересобирать — затрёт права на константу.

6. Порядок скиллов и правок

Путь расширения: каталог Расширения/IM86632 проекта IMDEV-8663. Путь CF: выгрузка Wim_Du из source-path.txt базы Wim_Du, подкаталог SRC/CF. Повторный cfe-borrow безопасен: свои модули не затирает.
  1. cfe-borrow (одним вызовом или двумя):
    • Document.ПланРегламентныхОперацийДУ.Form.ФормаДокумента с -BorrowMainAttribute Form и -Module ObjectModule;
    • Document.РасчетСЧА_РСА.Form.ФормаДокумента с -BorrowMainAttribute Form (документ уже заимствован).
  2. meta-edit add-attribute на XML документа плана: ПланВечернихОпераций: DocumentRef.ПланРегламентныхОперацийДУ, синоним «План вечерних операций». Без префикса. Не index, не req (заполнение кодом; для группы 2 поле пустое).
  3. form-edit на Form.xml плана: поле после ГруппаОперацийПользователя. Если DSL не ставит ReadOnly — дописать в XML ReadOnly>true.
  4. form-edit на Form.xml расчета СЧА/РСА: реквизит формы + поле после ДокументОснование, ReadOnly.
  5. cfe-patch-method -ModulePath Document.ПланРегламентныхОперацийДУ.ObjectModule -MethodName ПередЗаписью -InterceptorType After затем дописать тело (не оставлять пустой &После).
  6. Вручную: новые экспортные методы менеджера; обёртки на форме периода; маркеры #Вставка в двух клиентских перехватах; заполнение поля на форме СЧА; права роли; версия расширения 1.0.0.2.
  7. cfe-validate с ConfigPath выгрузки Wim_Du. Потом загрузка в ИБ штатным контуром проекта.
Не вызывать cfe-patch-method с ModificationAndControl заново на СформироватьРегламентныеОперации / ОбработатьРезультатЗадания формы: тело уже с вставками UX. Только точечные #Вставка.

7. Скелеты BSL

Стиль: ключевые слова 1С с заглавной первой буквой; новые экспортные методы — с полным документирующим комментарием (Описание, Параметры, Возвращаемое значение, Пример). Отступы — 4 пробела. Параметры запросов — &Имя, без HTML-сущностей в .bsl.
