Перенос операций СЧА/РСА в группу 3

Обработка готова к работе. Откройте файл ПереносОперацийСЧА_РСАВГруппу3.epf, нажмите «Проверить», убедитесь в плане и только после этого подтверждайте запись. Повторный запуск безопасен: дубль группы не создаётся.

1. Зачем эта обработка

Расчет СЧА/РСА и связанные контроли сейчас входят в группу «2. Вечерние» операции. Нужно вынести их в отдельную группу «3. Расчет СЧА/РСА», чтобы вечернее закрытие и расчет СЧА/РСА запускались раздельно.

Группы утренних и вечерних операций — это данные информационной базы, а не объекты конфигурации. Поэтому перенос делает внешняя обработка: человек видит план, подтверждает и получает протокол.

На каждой базе обработку запускают отдельно (тест, копия, рабочая). То, что группа 3 появилась на одной базе, не переносится на другую автоматически.

2. Что будет перенесено

Пять видов операций справочника «Виды операций закрытия периода»:

Вид операцииЧто это для пользователя
Расчет РСАРасчет РСА
Расчет СЧАРасчет СЧА
Расчет доходности портфеляКонтроль доходности
Контроль уменьшения стоимости портфеляКонтроль уменьшения стоимости
Контроль превышения уровня рисковКонтроль уровня рисков

Порядок операций (1000 / 1010 / 1020 / 1030) не меняется. Настройки закрытия периода не копируются: они хранятся по виду операции, а не по группе.

Время создания регламентных операций у новой группы берётся с группы вечерних.

3. Как открыть

  1. Войдите в базу 1С под пользователем с правами на изменение справочника видов операций закрытия периода.
  2. Меню Файл → Открыть и выберите файл ПереносОперацийСЧА_РСАВГруппу3.epf.
  3. Либо подключите файл в «Дополнительные отчеты и обработки» и откройте команду обработки.

При открытии обработка сама выполняет проверку: заполняются таблица «План действий» и поле «Протокол».

4. Кнопки на форме

КнопкаКогда доступнаЧто делает
Проверить Всегда Только чтение. Обновляет план и протокол. В справочник ничего не пишет.
Выполнить перенос Есть что перенести в группу 3, ошибок нет После ответа «Да» создает группу 3 (если её ещё нет) и переносит пять операций.
Вернуть в вечерние Найдена группа вечерних и хотя бы одна из пяти операций уже в группе 3 После ответа «Да» возвращает эти операции в группу «2. Вечерние». Группу 3 не удаляет.
Если кнопка серая — сначала нажмите «Проверить» и прочитайте протокол. Типичные причины: перенос уже выполнен, нет группы «2. Вечерние», не найден вид операции.

5. Перенос в группу 3

1Проверить. В таблице должны быть:

  • создание группы «3. Расчет СЧА/РСА» или строка, что группа уже есть;
  • пять видов со статусом «Перенести в группу 3».

Если есть строка «Ошибка: не найдено» — запись не выполняйте, передайте разработчику протокол.

2Выполнить перенос. Прочитайте текст вопроса: сколько операций будет перенесено, будет ли создана группа. Нажмите «Да». «Нет» ничего не записывает.

3Проверить результат по протоколу и справочнику:

  • появилась группа «3. Расчет СЧА/РСА»;
  • в ней — расчет РСА, расчет СЧА и три контрольные операции;
  • повторное «Проверить» показывает «Уже в группе 3», кнопка переноса недоступна.

4Контроль на форме регламентного периода. В списке групп должна быть «3. Расчет СЧА/РСА». Запуск «2. Вечерние» больше не должен создавать документы «Расчет СЧА/РСА». Их создает запуск группы 3.

Повторный «Выполнить перенос» после успешного первого запуска ничего не ломает: сообщение «Перенос уже выполнен», записи нет.

6. Возврат в вечерние

Кнопка нужна, если перенос сделали слишком рано или нужно временно вернуть операции в вечернюю группу.

  1. Нажмите «Проверить». Кнопка «Вернуть в вечерние» должна стать доступной.
  2. Подтвердите вопрос. В тексте будет число операций к возврату.
  3. Пять видов снова окажутся в группе «2. Вечерние».
  4. Группа «3. Расчет СЧА/РСА» остаётся в справочнике (может быть пустой). Обработка её не удаляет.
Планы регламентных операций. Если по группе 3 уже создавались планы, обработка покажет предупреждение в таблице плана, но возврат не заблокирует. Планы группа 3 сама по себе не чистит. После возврата вечерний запуск снова начнет считать СЧА/РСА вместе с остальными вечерними операциями.

7. Если после обновления конфигурации операции «уехали»

После обновления предопределенных данных родитель пяти видов может откатиться. Это штатная ситуация.

  1. Снова откройте ту же обработку.
  2. Нажмите «Проверить»: в плане снова будет перенос в группу 3.
  3. Нажмите «Выполнить перенос» и подтвердите.

Группа 3 при этом не создаётся второй раз, если она уже есть.

8. Чего обработка не делает

  • Не меняет методику расчета СЧА/РСА.
  • Не создает и не проводит документы «Расчет СЧА/РСА».
  • Не помечает на удаление уже созданные планы и документы.
  • Не удаляет группу 3 при возврате.
  • Не включает пакетный расчет и не ставит расширение.

9. Журнал регистрации

Каждый перенос и каждый возврат пишется в журнал регистрации, событие IMDEV-8663.2. Если одна операция не записалась, в протоколе будет строка ошибки, остальные обработка не откатывает. Повторный запуск доведёт оставшиеся.
