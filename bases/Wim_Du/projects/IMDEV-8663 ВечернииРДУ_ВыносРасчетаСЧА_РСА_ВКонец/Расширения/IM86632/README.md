# Расширение IM86632

Доработка IMDEV-8663.2: вынос расчета СЧА/РСА в группу `3. "Расчет СЧА/РСА"`.

Префикс `IM86632_` только у перехватов типовых методов. Новые процедуры, константа, роль, реквизиты и элементы формы — без префикса: вендор перенесет их в базовую конфигурацию.

## Состав

- Константа `ИспользоватьПредварительныеЗапросыДляРегламентовСЧА_РСА` (Булево, по умолчанию Ложь). Пока выключена — группа 3 считается однодоговорным путем, как на этапе 2.
- Роль `ПраваНаРегламентыСЧА_РСА` — права на константу (DefaultRole расширения). При переносе в CF права влить в `ПолныеПрава` и `АдминистрированиеРегламентныхОпераций`, роль как отдельный объект CF не тащить.
- Форма `РегламентныеПериоды.РегламентныйПериод`: флажок «После вечерних операций запускать расчет СЧА/РСА». Если настройки пользователя нет — флажок включён. Форма этапа 2 не менялась на этапах 3–4.
- Коды групп — один источник в модуле менеджера: `КодВечернейГруппыОпераций()`, `КодГруппыРасчетаСЧА_РСА()`.
- Предупреждение при перезапуске вечерних, если планы группы 3 уже есть.
- После успешного завершения группы 2: либо сообщение пересчитать группу 3, либо вторая длительная операция группы 3 (если флажок включен).
- Этап 3: труба пакетных данных операции 1000 (предподготовка пачки, ключи диспетчера, 7-й параметр, fallback на однодоговорной расчет).
- Этап 4: пакетный расчет РСА/СЧА по сигнатуре параметров договора. Операции 1010/1020/1030 не трогаются.

Группу 3 в справочнике создает обработка поддержки `ПереносОперацийСЧА_РСАВГруппу3`. Без нее флажок скрыт, форма не падает.

## Порядок внедрения

1. Прогнать обработку поддержки на информационной базе.
2. Подключить расширение IM86632 (константа выключена).
3. Сверить документы СЧА/РСА однодоговорным путем (этап 2 уже проверен).
4. Включить константу пакетного расчета на тестовом контуре и сверить суммы.

Старое расширение IM8663 на базу не подключать.
