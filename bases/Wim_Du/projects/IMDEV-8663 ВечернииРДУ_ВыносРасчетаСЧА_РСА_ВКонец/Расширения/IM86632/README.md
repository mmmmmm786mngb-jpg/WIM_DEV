# Расширение IM86632

Доработка IMDEV-8663.2: вынос расчета СЧА/РСА в группу `3. "Расчет СЧА/РСА"`.

На этом шаге (этап 2) расширение дает только UX разделения запуска. Пакетные запросы, ключи диспетчера и 7-й параметр операции 1000 не подключаются.

Префикс `IM86632_` только у перехватов типовых методов. Новые процедуры, константа, роль, реквизиты и элементы формы — без префикса: вендор перенесет их в базовую конфигурацию.

## Состав этапа 2

- Константа `ИспользоватьПредварительныеЗапросыДляРегламентовСЧА_РСА` (Булево, по умолчанию Ложь).
- Роль `ПраваНаРегламентыСЧА_РСА` — права на константу (DefaultRole расширения). При переносе в CF права влить в `ПолныеПрава` и `АдминистрированиеРегламентныхОпераций`, роль как отдельный объект CF не тащить.
- Форма `РегламентныеПериоды.РегламентныйПериод`: флажок «После вечерних операций запускать расчет СЧА/РСА». Если настройки пользователя нет — флажок включён.
- Коды групп — один источник в модуле менеджера: `КодВечернейГруппыОпераций()`, `КодГруппыРасчетаСЧА_РСА()`. На форме реквизиты `КодВечернейГруппы` и `КодГруппыСЧА` (строки с кодами, не ссылки).
- Предупреждение при перезапуске вечерних, если планы группы 3 уже есть.
- После успешного завершения группы 2: либо сообщение пересчитать группу 3, либо вторая длительная операция группы 3 (если флажок включен). Сравнение выбранной группы — по коду, не по ссылке.

Группу 3 в справочнике создает обработка поддержки `ПереносОперацийСЧА_РСАВГруппу3`. Без нее флажок скрыт, форма не падает.

Этап 2 проверен: разделение групп не меняет документы СЧА/РСА; автозапуск группы 3 по флагу работает.

## Порядок внедрения

1. Прогнать обработку поддержки на информационной базе.
2. Подключить расширение IM86632 (константа выключена).
3. Позже включить пакетный расчет (этапы 3-4).

Старое расширение IM8663 на базу не подключать.
