IMAPPS-40325. Перечень изменений для переноса в базовую конфигурацию
======================================================================

Конфигурация: Доверительное управление, версия 1.5.30.4.
Модули справочника "РегламентныеПериоды" в версиях 1.5.30.4 и 1.5.30.6 совпадают,
поэтому перечень применим к обеим версиям. В обеих версиях ошибка не исправлена.

ОШИБКА
Два пользователя одновременно формируют вечерние регламентные операции за одну дату
по разным портфелям. Один из запусков завершается ошибкой:
  Ошибка при формировании регламентных операций: {Справочник.РегламентныеПериоды.МодульМенеджера(2127)}:
  Ошибка при вызове метода контекста (Выполнить): Задание с таким значением ключа уже выполняется.

ПРИЧИНА
Ключ фонового задания порции (ОбработатьПачкуДиспетчером) составлялся из даты периода,
номера пачки, номера порции и группы операций: IM8663_<дата>_<пачка>_<порция>_<группа>.
Нумерация пачек и порций у каждого запуска начинается с единицы, поэтому параллельные
запуски за одну дату и группу получают одинаковые ключи. Платформа не допускает двух
активных фоновых заданий с одним ключом.
Вторая проблема того же происхождения: ожидание порций после отмены формирования искало
порции только по дате и ждало порции чужого запуска.

ИСПРАВЛЕНИЕ
- у каждого запуска свой идентификатор (форма периода создает его при нажатии "Создать");
- ключ порции: IM8663_<дата>_<идентификатор запуска>_<пачка>_<порция>_<группа>;
  начало ключа IM8663_<дата> сохранено, поэтому функции поиска порций за дату
  (ЕстьАктивныеПорцииРегламентаЗаДату, АктивныеПорцииРегламентаЗаДату) не меняются;
- ожидание после отмены ищет только порции своего запуска.

ИСТОЧНИК
Расширение IMAPPS40325 версии 1.0.0.1 (назначение: исправление, префикс IM40325_).
В расширении правки сделаны перехватом с контролем изменений (&ИзменениеИКонтроль)
в 5 методах. Ниже они переписаны для прямого внесения в конфигурацию:
- маркеры #Вставка/#Удаление не нужны, приведен итоговый код;
- реквизит формы в расширении называется IM40325_ИдентификаторЗапускаПорций,
  в конфигурации - ИдентификаторЗапускаПорций (без префикса).

Для сравнения и объединения приложен файл конфигурации ДУ_1.5.30.4_IMAPPS-40325.cf:
рабочая 1.5.30.4 с этими же изменениями. Синтаксическая проверка модулей
(тонкий клиент, сервер) ошибок не выявила.

КАК ВНОСИТЬ
Правок: 10 в двух модулях и один новый реквизит формы. Новых объектов метаданных нет.
Каждая правка: найти в модуле фрагмент из блока НАЙТИ (он встречается в модуле ровно
один раз) и заменить его целиком текстом из блока ЗАМЕНИТЬ НА. Найденный фрагмент
в новом тексте сохранен, добавленные строки дополнены. Отступы - табуляция, как
в модуле; в функции ЗапуститьОжиданиеПорцийНаСервере в оригинале пробелы, они сохранены.
Правки модуля менеджера независимы друг от друга, порядок внесения любой.
Реквизит формы добавить до правок модуля формы: код формы обращается к нему.

ПРАВКА 5. Новая область IMAPPS_40325_ПорцииЗапускаРегламента с экспортной функцией ЕстьАктивныеПорцииЗапуска (вызывается из формы).

	#Область ASP_215902_IMDEV_8663_2_СвязьГрупп
----- ЗАМЕНИТЬ НА -----

	#Область IMAPPS_40325_ПорцииЗапускаРегламента
	
	// IMAPPS-40325. Уникальный ключ порций регламента при параллельных запусках
	//
	// Проверяет, есть ли за дату активные порции диспетчера указанного запуска. Порции других
	// запусков за ту же дату не учитываются. Порции не отменяет и не ждет.
	//
	// Параметры:
	//  ДатаПериода - Дата - дата регламентного периода
	//  ИдентификаторЗапуска - Строка - идентификатор запуска из параметров сохранения;

	//

	Функция ЕстьАктивныеПорцииЗапуска(ДатаПериода, ИдентификаторЗапуска) Экспорт
		
		Возврат ЗначениеЗаполнено(АктивныеПорцииЗапуска(ДатаПериода, ИдентификаторЗапуска));
		
	КонецФункции
	
	#КонецОбласти
	
	#Область ASP_215902_IMDEV_8663_2_СвязьГрупп
----- КОНЕЦ ПРАВКИ -----

ПРАВКА 6. Новые служебные функции ИдентификаторЗапускаИзПараметров и АктивныеПорцииЗапуска.
Место: после функции АктивныеПорцииРегламентаЗаДату, перед функцией ДатаРасчетаСЧА_РСА (область СлужебныеПроцедурыФункции)
----- НАЙТИ -----
		Возврат Порции;
		
	КонецФункции
	
	// Описание: Возвращает дату-время расчета СЧА/РСА для указанного регламентного периода.
----- ЗАМЕНИТЬ НА -----
		Возврат Порции;
		
	КонецФункции
	
	// IMAPPS-40325. Уникальный ключ порций регламента при параллельных запусках
	//
	// Возвращает идентификатор запуска диспетчера, который входит в ключ фоновых заданий порций.
	// Ничего не создает: если идентификатора в параметрах нет, возвращает пустую строку.
	//
	// Параметры:
	//  ПараметрыСохранения - Структура - параметры запуска регламента, ключ ИдентификаторЗапуска
	//
	// Возвращаемое значение:
	//  Строка - идентификатор запуска или пустая строка
	//
	Функция ИдентификаторЗапускаИзПараметров(ПараметрыСохранения)
		
		ИдентификаторЗапуска = "";
		Если ТипЗнч(ПараметрыСохранения) = Тип("Структура") Тогда
			ПараметрыСохранения.Свойство("ИдентификаторЗапуска", ИдентификаторЗапуска);
		КонецЕсли;
		
		Если Не ЗначениеЗаполнено(ИдентификаторЗапуска) Тогда
			Возврат "";
		КонецЕсли;
		
		Возврат ИдентификаторЗапуска;
		
	КонецФункции
	
	// IMAPPS-40325. Уникальный ключ порций регламента при параллельных запусках
	//
	// Собирает активные фоновые задания порций диспетчера за дату, запущенные указанным запуском.
	// Ключ порции: IM8663_<yyyyMMdd>_<идентификатор запуска>_<пачка>_<порция>_<группа>.
	// Без идентификатора запуска возвращает все порции за дату, как АктивныеПорцииРегламентаЗаДату.
	//
	// Параметры:
	//  ДатаПериода - Дата - дата регламентного периода
	//  ИдентификаторЗапуска - Строка - идентификатор запуска; пустая строка - все порции за дату
	//
	// Возвращаемое значение:
	//  Массив из ФоновоеЗадание - активные порции
	//
	Функция АктивныеПорцииЗапуска(ДатаПериода, ИдентификаторЗапуска)
		
		Если Не ЗначениеЗаполнено(ИдентификаторЗапуска) Тогда
			Возврат АктивныеПорцииРегламентаЗаДату(ДатаПериода);
		КонецЕсли;
		
		Порции = Новый Массив;
		Если Не ЗначениеЗаполнено(ДатаПериода) Тогда
			Возврат Порции;
		КонецЕсли;
		
		ПрефиксКлюча = "IM8663_" + Формат(ДатаПериода, "ДФ=yyyyMMdd") + "_" + ИдентификаторЗапуска + "_";
		
		Отбор = Новый Структура;
		Отбор.Вставить("Состояние", СостояниеФоновогоЗадания.Активно);
		НайденныеЗадания = ФоновыеЗадания.ПолучитьФоновыеЗадания(Отбор);
		
		Для Каждого ТекЗадание Из НайденныеЗадания Цикл
			Если СтрНачинаетсяС(Строка(ТекЗадание.Ключ), ПрефиксКлюча) Тогда
				Порции.Добавить(ТекЗадание);
			КонецЕсли;
		КонецЦикла;
		
		Возврат Порции;
		
	КонецФункции
	
	// Описание: Возвращает дату-время расчета СЧА/РСА для указанного регламентного периода.

ПРОВЕРКА ПОСЛЕ ВНЕСЕНИЯ
1. Синтаксическая проверка модулей справочника "РегламентныеПериоды" - без ошибок.
2. Два пользователя одновременно формируют вечерние операции (группа "2. Вечерние")
   за одну дату по разным портфелям: оба запуска завершаются без ошибки, в журнале
   регистрации нет события "РегламентныеОперации" с текстом "Задание с таким значением
   ключа уже выполняется".
3. Во время запусков ключи фоновых заданий порций имеют вид
   IM8663_<дата>_<идентификатор запуска>_<пачка>_<порция>_<группа> и у двух запусков
   различаются идентификатором.
4. После переноса в конфигурацию расширение IMAPPS40325 отключить и удалить из базы.
