IMDEV-9153. Оптимизация начисления ВУК РДУ в регламентные даты

Объект доработки: внешняя обработка внНачислениеВознаграждения_РозничноеДУ (справочник «Дополнительные отчёты и обработки»).
База: WIM_DU. Формат документа: техническое задание (что необходимо реализовать).

1. Цель

Ускорить массовое начисление вознаграждения за управление (ВУК) по договорам розничного ДУ и обеспечить его автоматический запуск по расписанию 4 раза в год. Существующая бизнес-логика начисления (расчёт сумм, формирование справок-расчётов PDF, режим расторжения) должна остаться без изменений.

2. Что необходимо сделать

Задача 1. Многопоточное начисление.

Ручной запуск «Начислить» (кнопки «Выбрать» → «Начислить», кроме режима расторжения) должен выполняться в несколько потоков:

  • договоры из табличной части разбиваются на пачки по 100 договоров;
  • каждая пачка обрабатывается в фоновом задании;
  • одновременно в памяти сервера — не более потоков, чем задано в константе МаксимальноеКоличествоПараллельныхПотоков (обработка «волнами»: набрали лимит → дождались → следующая волна);
  • в пачке параллельно выполняются: создание начисления, формирование PDF, снятие движений регистра ОбязательстваПоДС.
Задача 2. Регламентный (плановый) запуск.

Добавить команду для запуска по расписанию (тип «Вызов серверного метода»), которую можно повесить на регламентное задание дополнительной обработки. Расписание — 4 раза в год в 00:15:

  • каждое 1 января, 1 апреля, 1 июля, 1 октября;
  • реализовать командой в этой же обработке (переиспользовать движок из Задачи 1);
  • предусмотреть проверку даты запуска (страховка от запуска не в регламентную дату).
Задача 3. Корректное удаление регистратора ОперацияБух.

Проблема: документ-регистратор ОперацияБух нельзя удалять параллельно — возникают блокировки/взаимоблокировки.

Удаление разделить на две фазы:

ФазаЧто делаемКак
Фаза 1 Снятие движений регистра ОбязательстваПоДС Параллельно, внутри пачек (остаётся там, где есть). Сам документ не удаляем — только собираем ссылки регистраторов.
Фаза 2 Удаление документов ОперацияБух Последовательно, в один поток, после завершения всех фоновых пачек.
На один договор — один регистратор. Ссылки регистраторов передаются из фонов в основной сеанс через временное хранилище (движения к моменту Фазы 2 уже сняты).
Задача 4. Краткое письмо об итогах.

Так как регламентный запуск идёт без пользователя, по завершении отправлять краткое письмо-уведомление:

  • содержимое — только счётчики (всего договоров, пачек, ошибок начисления; удалено регистраторов / ошибок удаления);
  • дополнительно замерять и выводить общее время выполнения начисления (формат «ч мм сс») — как на форме, так и в письме;
  • отправка средствами БСП (РаботаСПочтовымиСообщениями);
  • настройки письма (флаг отправки, список рассылки, учётная запись почты) вынести на Форму настроек обработки.

3. Границы доработки

  • Не менять алгоритм расчёта сумм, формирование справок-расчётов и логику режима расторжения.
  • Режим расторжения оставить последовательным (как в оригинале).
  • Предусмотреть fallback: если фоновые задания недоступны или лимит потоков ≤ 1 — работать в прежнем последовательном режиме.
  • Объём изменений — минимальный: расширяется только точка входа начисления, добавляются вспомогательные процедуры и одна регламентная команда.

4. Результат

  • Пересобранная внешняя обработка внНачислениеВознаграждения_РозничноеДУ.epf с версией 2.00.
  • Новая команда для постановки на регламентное задание (4 раза в год, 00:15).
  • Настройки рассылки письма на форме настроек.
