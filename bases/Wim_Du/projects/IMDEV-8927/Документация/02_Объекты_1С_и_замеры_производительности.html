Раздел 1. Архитектура запуска ключевых операций ДУ

1.1. Регламентное задание для дополнительных обработок (БСП)

Все внешние обработки EPF, имеющие признак "ДополнительнаяОбработка" в функции СведенияОВнешнейОбработке(), регистрируются в справочнике Справочник.ДополнительныеОтчетыИОбработки и выполняются по расписанию через регламентное задание РегламентноеЗадание.ЗапускДополнительныхОбработок.

1.2. Регламентные операции ДУ (Утренние/Вечерние)

Утренние и вечерние регламенты — это не отдельные обработки, а пакетный прогон процедур закрытия периода через документ Документ.ПланРегламентныхОперацийДУ.

Документ.ПланРегламентныхОперацийДУ → ОбъектМодуль.ВыполнитьРегламентныеПроцедуры(Отказ, УчитыватьВыполненные, СоответствиеОперацияТаблица)
↓
Справочник.ВидыОперацийЗакрытияПериода → МодульМенеджера.ВыполнитьИсполняемуюПроцедуруЗакрытияПериода(ПараметрыВыполнения, Отказ, ТекстОтказа)
↓
CommonModule.ИсполняемыеПроцедурыЗакрытияПериода.Операция_XXXX_ИмяОперации(ЗакрытиеПериода, Дата, ДоговорДУ, СписокОпераций, Отказ, ТекстОтказа)

Имя процедуры (Операция_0010_УстановкаКотировок и т.д.) хранится в реквизите ИсполняемаяПроцедура элемента справочника ВидыОперацийЗакрытияПериода и читается из строки методом Выполнить() на сервере. Группировка операций (Утренние / Вечерние) задаётся реквизитом ГруппаОперацийПользователя с предопределёнными кодами:

  • "1. \"Утренние\" операции" — начисления % по депозитам, РЕПО, НКД, погашения, амортизации.
  • "2. \"Вечерние\" операции" — переоценка активов, расчёт РСА/СЧА, расчёт доходности.

1.3. Легенда оценки вероятности

90–100% точное совпадение по имени и сигнатуре регистрации
80–89% высокая релевантность (одна сущность с уточнениями)
70–79% вероятный кандидат, требует подтверждения у владельца
50–69% возможный участник цепочки
30–49% косвенная связь
< 30% предположение, нужен поиск дополнительных артефактов

2.1. Сводка по найденным вызовам в EPF

Из 342 каталогов SRC/epf у 195 обработок есть функция СведенияОВнешнейОбработке() с заполненными ПараметрыРегистрации — они подключены через Справочник.ДополнительныеОтчетыИОбработки. Остальные 145 каталогов — либо вспомогательные обработки без регистрации БСП (запускаются вручную из меню "Файл — Открыть"), либо устаревшие версии.

Итог по сопоставлению: для 17 из 20 ключевых операций найден объект конфигурации с вероятностью ≥ 75%. Для №13 ("Сверка API сигнал vs Реестры платежей") требуется уточнение архитектуры у бизнес-владельца сверки. №7 и №19 имеют корректное направление вызова (платёжные поручения), но точная цепочка зависит от регламентных настроек.

Раздел 3. Как правильно вставить замер производительности в ключевую операцию

В конфигурации Wim_Du уже подключена библиотечная подсистема БСП "Оценка производительности" (общий модуль ОценкаПроизводительности, 296 общих модулей в CF). Использовать нужно её — без самописных таймеров.

3.1. Программный интерфейс БСП (что вызывать в коде)

Все методы — экспортные, лежат в общем модуле ОбщийМодуль.ОценкаПроизводительности (с серверным контекстом).

Метод Назначение Когда применять
Функция НачатьЗамерВремени() → Число Возвращает время старта (UTC, мс) или 0, если замеры выключены константой ВыполнятьЗамерыПроизводительности. Простая короткая операция, измеряется одной парой "старт-стоп".
Процедура ЗакончитьЗамерВремени(КлючеваяОперация, ВремяНачала, ВесЗамера = 1, Комментарий = Неопределено, ВыполненСОшибкой = Ложь) Записывает результат в РС.ЗамерыВремени. ВесЗамера — кол-во обработанных строк (договоров, сделок и т.п.). Парный вызов к НачатьЗамерВремени().
Процедура ЗакончитьЗамерВремениТехнологический(КлючеваяОперация, ВремяНачала, ВесЗамера = 1, Комментарий = Неопределено) Пишет в отдельный РС.ЗамерыВремениТехнологические — не показывается бизнес-пользователю. Замеры внутри инфраструктуры (фоновые задания, диагностика).
Функция НачатьЗамерДлительнойОперации(КлючеваяОперация) → Соответствие Возвращает ОписаниеЗамера для длительной операции с вложенными шагами. Длительные операции (регламенты, пакетные обработки).
Процедура ЗафиксироватьЗамерДлительнойОперации(ОписаниеЗамера, КоличествоДанных, ИмяШага, Комментарий = "") Фиксирует промежуточный шаг (например, "Запрос данных", "Запись регистра"). Накапливает длительность по имени шага. Внутри цикла или между этапами длительной операции.
Процедура ЗакончитьЗамерДлительнойОперации(ОписаниеЗамера, КоличествоДанных, ИмяШага = "", Комментарий = "") Закрывает длительный замер, рассчитывает удельное время (длительность / вес), пишет одной транзакцией. Парный вызов к НачатьЗамерДлительнойОперации().
Процедура СоздатьКлючевыеОперации(КлючевыеОперации) Регистрирует ключевые операции (массив структур ИмяКлючевойОперации, ЦелевоеВремя) в Справочник.КлючевыеОперации. Из обработчика обновления конфигурации или из ПриДобавленииПодсистемы.
Процедура УстановитьЦелевоеВремя(КлючевыеОперации) Обновляет целевое время уже зарегистрированных ключевых операций. При изменении SLA в Excel-файле "Ключевые операции 15".

3.2. Стандартный шаблон замера (короткая операция)

Применять для команд EPF, у которых одна точка входа — например, внСверкаДенежныхСредств_обр.ВыполнитьКоманду(). 

// Описание: Точка входа команды дополнительной обработки. Запускается БСП через
// регламентное задание ЗапускДополнительныхОбработок.
//
// Параметры:
//  ИдентификаторКоманды    - Строка    - идентификатор команды из СведенийОВнешнейОбработке
//  ПараметрыВыполненияКоманды - Структура - стандартные параметры БСП
//
Процедура ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполненияКоманды) Экспорт

    ВремяНачала = ОценкаПроизводительности.НачатьЗамерВремени();

    Попытка
        ВыполнитьСверку(ПараметрыВыполненияКоманды);
        ВыполненСОшибкой = Ложь;
    Исключение
        ВыполненСОшибкой = Истина;

            "СверкаДенежныхСредств",
            УровеньЖурналаРегистрации.Ошибка,
            ,
            ,
            ОписаниеОшибки());

    КонецПопытки;

    ОценкаПроизводительности.ЗакончитьЗамерВремени(
        "ДУ.СверкаДенежныхСредств",   // Имя ключевой операции — должно совпадать с Excel
        ВремяНачала,
        1,                              // ВесЗамера: 1 запуск
        ИдентификаторКоманды,           // Комментарий: какая именно команда отработала
        ВыполненСОшибкой);

3.3. Длительная операция с вложенными шагами (для регламентов ДУ)

Применять в ОбщийМодуль.ИсполняемыеПроцедурыЗакрытияПериода.Операция_* и в Документ.ПланРегламентныхОперацийДУ.ВыполнитьРегламентныеПроцедуры() — там, где обработка идёт по списку договоров и состоит из нескольких этапов. 

// Описание: Расчёт РСА/СЧА за указанную дату по группе договоров ДУ.
// Вызывается через ВыполнитьИсполняемуюПроцедуруЗакрытияПериода
// при проведении документа ПланРегламентныхОперацийДУ.
//
Процедура Операция_1000_РасчетРСА_СЧА(
            ЗакрытиеПериода, Дата, ДоговорДУ, СписокОпераций, Отказ, ТекстОтказа) Экспорт

    ОписаниеЗамера = ОценкаПроизводительности.НачатьЗамерДлительнойОперации(
        "ДУ.ВечерниеРегламенты.РасчетРСА_СЧА");

    // Шаг 1: Получение исходных данных
    ВремяНачалаШага = ТекущаяУниверсальнаяДатаВМиллисекундах();
    ИсходныеДанные = ПолучитьИсходныеДанные(Дата, ДоговорДУ);
    ОценкаПроизводительности.ЗафиксироватьЗамерДлительнойОперации(
        ОписаниеЗамера,
        ИсходныеДанные.Активы.Количество(),
        "ПолучениеДанных",
        "Дата=" + Формат(Дата, "ДЛФ=DT"));

    // Шаг 2: Расчёт стоимости активов
    Расчёт = РассчитатьСтоимостьАктивов(ИсходныеДанные);
    ОценкаПроизводительности.ЗафиксироватьЗамерДлительнойОперации(
        ОписаниеЗамера,
        Расчёт.КоличествоПозиций,
        "РасчетСтоимости");

    // Шаг 3: Запись документа
    Документ = СоздатьИЗаписатьРасчётСЧА(Расчёт, Дата, ДоговорДУ, Отказ);
    ОценкаПроизводительности.ЗафиксироватьЗамерДлительнойОперации(
        ОписаниеЗамера,
        ?(Документ = Неопределено, 0, 1),
        "ЗаписьДокумента");

    // Завершение длительного замера: считается удельное время и общая длительность,
    // вес = СписокОпераций.Количество() (договоров в пачке)
    ОценкаПроизводительности.ЗакончитьЗамерДлительнойОперации(
        ОписаниеЗамера,
        СписокОпераций.Количество(),
        "Финал",
        "Договор=" + Строка(ДоговорДУ));

КонецПроцедуры
Как читать длительные замеры: БСП пишет в регистр сразу несколько строк: ДУ.ВечерниеРегламенты.РасчетРСА_СЧА.ПолучениеДанных, ...РасчетСтоимости, ...ЗаписьДокумента, ...Удельный (удельное время на 1 договор) и ДУ.ВечерниеРегламенты.РасчетРСА_СЧА (общая длительность). По удельной строке удобно выявлять регрессии.

3.4. Замер цикла обработки (количество как ВесЗамера)

Применять, когда операция бежит по списку (например, проведение документов или загрузка сделок). 

// Описание: Загрузка сделок Т-1 через web-сервис ВТБ.
// Точка входа — команда ФоновоеВыполнениеT1 обработки внЗагрузкаСделокDU-NEW.
//
Процедура ЗагрузитьСделкиТМинус1(ПараметрыВыполненияКоманды)

    ВремяНачала = ОценкаПроизводительности.НачатьЗамерВремени();

    МассивСделок = ПолучитьСделкиИзВебСервиса();
    КоличествоОбработанных = 0;

    Для Каждого СтрокаСделки Из МассивСделок Цикл
        Попытка
            СоздатьИПровестиСделку(СтрокаСделки);
            КоличествоОбработанных = КоличествоОбработанных + 1;
        Исключение
            ЗаписатьВЖурналРегистрации(СтрокаСделки, ОписаниеОшибки());
        КонецПопытки;
    КонецЦикла;

    // ВесЗамера = реально обработанное количество, а не общее в пачке.
    // Это даёт корректное удельное время "секунд / 1 сделку".
    ОценкаПроизводительности.ЗакончитьЗамерВремени(
        "ДУ.ЗагрузкаСделок.ТМинус1",
        ВремяНачала,
        КоличествоОбработанных,
        "Получено=" + МассивСделок.Количество());

3.7. Соглашения по именованию ключевых операций

Чтобы измерения отобразились в типовых отчётах "Производительность системы" и "АПДекс", придерживайтесь соглашения:
  • Имя строится через точку: <Подсистема>.<Группа>.<Действие> — например, ДУ.ВечерниеРегламенты.РасчетРСА_СЧА.
  • В качестве "Подсистема" используйте ДУ (укажет на ДУ-15).
  • Не ставьте пробелы и символы вне ASCII в имени — ВСЕ имена сравниваются хешем MD5 в общем модуле БСП. Кириллица допустима, но избегайте кавычек и слэшей.
  • Длительные операции с вложенными шагами автоматически порождают записи ...<ИмяШага> и ...Удельный.
  • Целевое время в БСП хранится в секундах, а в Excel приведено в часах — умножайте на 3600 при регистрации.

3.8. Чек-лист для постановки задач IMDEV (на основании Jira IMDEV-8927)

  1. Завести в Справочник.КлючевыеОперации 20 элементов из колонки "Имя ключевой операции" (см. примеры в п. 3.5).
  2. Для каждого объекта из таблицы в Разделе 2 поставить под-задачу IMDEV "Добавить замер в <EPF/Документ/ОбщийМодуль>" с шаблоном:
    • что измеряется (одна точка входа или цикл по договорам);
    • имя ключевой операции и тип (короткая / длительная);
    • что писать в ВесЗамера и Комментарий.
  3. Включить замеры в копии ПРОМ через ОценкаПроизводительности.ВключитьЗамерыПроизводительности(Истина).
  4. Прогнать суточный цикл операций ДУ-15 с реальными объёмами и сравнить фактическое время с колонкой "Целевое время на 100 000 договоров" из Excel.
  5. По результатам наполнить отчёт "Производительность системы" (типовой отчёт БСП) и создать тикеты на оптимизацию для отстающих операций.
