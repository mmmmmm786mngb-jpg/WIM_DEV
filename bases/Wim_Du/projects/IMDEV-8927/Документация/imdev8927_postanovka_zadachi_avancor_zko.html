Вендор: Аванкор. Базовая конфигурация Wim_Du (AvancoreDU). Доработки выполнены во временном расширении zko (префикс zko_, синоним «Замеры регламентных операций ДУ», поставка zko.cfe). Цель передачи документа — включить замеры производительности БСП в штатную поставку и снять зависимость от расширения.

Связанные задачи: IMDEV-8927 (анализ точек замера), IMDEV-8471 (внедрение замеров). Замеры для операций №16–18 реализованы только в расширении zko; остальные ключевые операции — во внешних обработках (EPF), в этот документ не входят.

Источник кода: Расширения/zko/Catalogs/РегламентныеПериоды/Ext/ManagerModule.bsl. Маркеры в коде: комментарии // IMDEV-8927 и блоки #Вставка / #КонецВставки.

IMDEV-8927: Постановка задачи вендору Аванкор

Назначение документа Перенос доработок из расширения zko в базовую конфигурацию. Документ предназначен для передачи вендору с целью включения замеров производительности регламентных операций ДУ в типовую поставку.

18 Начисление вознаграждения (ежеквартально, тот же контур регламентов)

1. Зачем это было сделано

Ключевые операции №16–18 выполняются не через внешние обработки, а через цепочку регламентного закрытия периода ДУ: фоновое задание вызывает процедуру СформироватьРегламентныеОперации модуля менеджера справочника РегламентныеПериоды, которая последовательно формирует документы закрытия по списку договоров.

Для мониторинга производительности (задача IMDEV-8471, подсистема БСП Оценка производительности) необходимо фиксировать длительность этой процедуры с разбивкой по пачкам договоров и с отдельными именами ключевых операций для утренней, вечерней и прочих групп регламентов.

Итог: в точке массового формирования регламентных операций добавлен длительный замер БСП (НачатьЗамерДлительнойОперации / ЗафиксироватьЗамерДлительнойОперации / ЗакончитьЗамерДлительнойОперации). Вес шага равен числу договоров в обработанной пачке — для расчета удельного времени на один договор. Изменения должны быть перенесены в базовую конфигурацию, чтобы не зависеть от расширения zko.

2. Что было сделано в расширении zko

В расширении zko заимствован справочник РегламентныеПериоды. В модуле менеджера выполнена подмена экспортной процедуры:

  • СформироватьРегламентныеОперации → zko_СформироватьРегламентныеОперации (&ИзменениеИКонтроль)

Добавлена вспомогательная функция zko_ИмяКлючевойОперацииЗамераПоГруппе (в базу переносится без префикса zko_).

2.1. Имена ключевых операций

Имя ключевой операции формируется по группе операций пользователя (ГруппаОперацийПользователя из ПараметрыСохранения.МассивРодителей):

Группа (реквизит Код) Имя ключевой операции в БСП Ключевая операция Excel
1. "Утренние" операции ДУ.РегламентныеОперации.1. Утренние операции №17
2. "Вечерние" операции ДУ.РегламентныеОперации.2. Вечерние операции №16
Другие / пустая группа ДУ.РегламентныеОперации.<Код без кавычек> или ...БезГруппы №18 и прочие регламенты

Двойные кавычки в коде группы удаляются: БСП сравнивает имена ключевых операций по хешу MD5 и не рекомендует кавычки в имени.

2.2. Пять точек вставки в СформироватьРегламентныеОперации

№ Место в процедуре Суть изменения
1 Начало процедуры, до инициализации результата Объявление переменной ОписаниеЗамераПроизводительности = Неопределено.
2 После определения ГруппаОперацийПользователя и ВыполнятьПакетнуюЗагрузку, перед циклом по пачкам Вызов ИмяКлючевойОперацииЗамераПоГруппе(...) и ОценкаПроизводительности.НачатьЗамерДлительнойОперации(...).
3 Конец каждой итерации цикла по пачкам договоров ЗафиксироватьЗамерДлительнойОперации с шагом "ОбработкаПачкиДоговоров", вес = РазмерТекущейПачки.
4 После успешного завершения всех пачек, перед финальным прогрессом 100% ЗакончитьЗамерДлительнойОперации с весом 0 (вес уже накоплен по пачкам), комментарий с числом договоров и потоков.
5 Блок Исключение Если замер был начат — ЗакончитьЗамерДлительнойОперации с весом 0 и текстом ошибки.

2.3. Функция ИмяКлючевойОперацииЗамераПоГруппе

Новая серверная функция модуля менеджера (не экспортная). Префикс имени: ДУ.РегламентныеОперации.. Если ГруппаОперацийПользователя не заполнена — возвращает ДУ.РегламентныеОперации.БезГруппы.

Функция ИмяКлючевойОперацииЗамераПоГруппе(ГруппаОперацийПользователя)

	ПрефиксКлючевойОперации = "ДУ.РегламентныеОперации.";

	ИмяГруппы = "";
	Если ЗначениеЗаполнено(ГруппаОперацийПользователя) Тогда
		ИмяГруппы = СокрЛП(ГруппаОперацийПользователя.Код);
	КонецЕсли;

	Если ПустаяСтрока(ИмяГруппы) Тогда
		Возврат ПрефиксКлючевойОперации + "БезГруппы";
	КонецЕсли;

	ИмяГруппы = СтрЗаменить(ИмяГруппы, """", "");

	Возврат ПрефиксКлючевойОперации + ИмяГруппы;

КонецФункции

2.4. Пример фрагментов замера (из расширения)

// Старт замера (после определения ГруппаОперацийПользователя)
ИмяКлючевойОперацииЗамера = ИмяКлючевойОперацииЗамераПоГруппе(ГруппаОперацийПользователя);
ОписаниеЗамераПроизводительности = ОценкаПроизводительности.НачатьЗамерДлительнойОперации(ИмяКлючевойОперацииЗамера);

// В конце итерации по пачке
ОценкаПроизводительности.ЗафиксироватьЗамерДлительнойОперации(
	ОписаниеЗамераПроизводительности,
	РазмерТекущейПачки,
	"ОбработкаПачкиДоговоров",
	СтрШаблон(НСтр("ru='Пачка %1, договоров: %2'"), ИндексПачки + 1, РазмерТекущейПачки));

// Успешное завершение (вес 0 — не дублировать накопленный по пачкам)
ОценкаПроизводительности.ЗакончитьЗамерДлительнойОперации(
	ОписаниеЗамераПроизводительности,
	0,
	"",
	СтрШаблон(
		НСтр("ru='Обработано договоров: %1; Потоков: %2'"),
		ТекущийНомер,
		Константы.МаксимальноеКоличествоПараллельныхПотоков.Получить()));

3. Что необходимо перенести в базовую конфигурацию

В базовый модуль менеджера справочника РегламентныеПериоды (Catalogs/РегламентныеПериоды/Ext/ManagerModule.bsl) нужно перенести:

  1. Функцию ИмяКлючевойОперацииЗамераПоГруппе — целиком из расширения (без префикса zko_).
  2. В процедуру СформироватьРегламентныеОперации — все пять блоков между маркерами #Вставка / #КонецВставки, помеченных комментарием // IMDEV-8927, с заменой вызова zko_ИмяКлючевойОперацииЗамераПоГруппе на ИмяКлючевойОперацииЗамераПоГруппе.

Маркеры // IMDEV-8927, #Вставка / #КонецВставки при переносе в базу можно удалить; в расширении они использовались для идентификации фрагментов.

Примечание по процедуре СформироватьРегламентныеОперации. В расширении zko процедура перехвачена целиком (&ИзменениеИКонтроль) и может содержать и другие доработки (например, разбивку списка договоров на пачки — IMDEV-8926). При переносе в базу вендору нужно включить только фрагменты IMDEV-8927 (замеры БСП) в актуальную типовую версию процедуры, не откатывая прочие исправления базовой конфигурации.

4. Проверка после переноса

  • Константа ВыполнятьЗамерыПроизводительности = Истина.
  • Запуск вечерних регламентов (группа «2. "Вечерние" операции») — в РС.ЗамерыВремени появляются записи с ключевой операцией ДУ.РегламентныеОперации.2. Вечерние операции и шагами ...ОбработкаПачкиДоговоров, ...Удельный.
  • Запуск утренних регламентов — аналогично для ДУ.РегламентныеОперации.1. Утренние операции.
  • Вес промежуточных шагов соответствует числу договоров в пачке; итоговый ЗакончитьЗамерДлительнойОперации вызывается с весом 0.
  • При принудительной ошибке в середине формирования замер завершается в блоке Исключение (без «висящих» незакрытых замеров).
