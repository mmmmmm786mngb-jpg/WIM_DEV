Введение

Задача IMDEV-9095 — ускорить массовое создание операций по счету брокера при распределении доходов по ценным бумагам. Проведено сравнительное тестирование двух конфигураций:

  • БЫЛО — базовая конфигурация без индексации и без расширения zob.
  • СТАЛО — включена индексация реквизита ДокументОснование документа ОтражениеОперацийВРегистрахВУ (DontIndex → Index) и подключено расширение zob с блоком ВЫРАЗИТЬ в запросах остатков.

По материалам Выберем.docx отдельно подтверждено: только индексация даёт сокращение времени запроса с ~219 с до ~2 с на том же участке кода (стр. 2447 ОбщегоНазначенияДУ).

Функциональное тестирование

По документу Выберем.docx проверялись этапы:

  1. Базовый прогон (СТАРАЯ конфигурация).
  2. Подключение расширения zob.
  3. Отдельно — только индексация ДокументОснование (подтверждён кратный выигрыш на запросе).
  4. Сводный тест 01.06.2026: БЫЛО vs СТАЛО.

Функциональных расхождений в данных при сравнении БЫЛО/СТАЛО в отчёте не зафиксировано; критерий успеха замера — время полного сценария при корректном создании операций.

Декомпозиция выигрыша 290,8 с

  • ~247 с — индексация ДокументОснование (П.1).
  • ~24 с — потери от ВЫРАЗИТЬ в zob (П.3), частично нивелирующие эффект.
  • Остаток — прочие узлы проведения, обмен данными, курсы валют (в пределах шума прогона).

Гипотеза: при внедрении только индексации (без zob) ожидаемое время ближе к ~604 с (~10,0 мин), т.е. ещё ~24 с быстрее текущего СТАЛО.

Выводы и рекомендации

  1. Внедрять только индексацию реквизита ДокументОснование документа ОтражениеОперацийВРегистрахВУ — подтверждённый и доминирующий эффект (-98,8% на горячем запросе, -31,7% на всём сценарии).
  2. Не внедрять расширение zob с блоком ВЫРАЗИТЬ: горячий запрос к остаткам стал медленнее на 14,7%, суммарно модуль переоценки — на 11,6%.
  3. Ускорение с 918 с до 628 с в тесте СТАЛО достигается преимущественно за счёт индексации, что совпадает с выводом в Выберем.docx.
  4. Для дальнейшей оптимизации П.3 имеет смысл рассматривать кеш остатков (бегущий кеш по моменту времени), а не модификацию условий ВЫРАЗИТЬ в тексте запроса.
  5. Расширение zob в базе теста следует отключить перед продуктивным релизом, если принято решение о внедрении только индексации.
