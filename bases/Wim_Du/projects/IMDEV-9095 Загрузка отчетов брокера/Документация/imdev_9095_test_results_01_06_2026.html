1. Проблема

Обработка «Распределение доходов по ценным бумагам» при массовой команде «Создать всё» создаёт и проводит сотни документов ОперацияПоСчетуБрокера (НКД, погашение и др.). На тестовой базе один прогон занимал ~15 минут — неприемлемо для регламентной работы.

Профилировщик (PFF) показал: основное время уходит не в код самой обработки, а в проведение документа — переоценка валютных остатков и формирование отражения в регистрах ВУ. Две строки кода конфигурации дают в сумме 412 с = 44,9% времени сценария (стр. 2447 — 27,2%, стр. 1219 — 17,7%).

СоздатьВсёНаСервере() [~918 с] └─ СоздатьОперацииПоНКД() └─ ОбОперация.Записать(Проведение) [~846 с, ~920 вызовов] └─ ОперацияПоСчетуБрокера.ОбработкаПроведения() ├─ переоценка валютных остатков ──► стр. 1219 └─ отражение в регистрах ВУ ──► стр. 2447

3. Гипотезы и план доработки

Для каждой горячей строки сформулирована отдельная гипотеза. Третья точка (проведение в EPF) сознательно не менялась.

Точка Гипотеза Планируемое решение Где менять
П.1 Индекс по ДокументОснование ускорит поиск существующего отражения ВУ с O(n) до O(log n) В метаданных документа ОтражениеОперацийВРегистрахВУ установить ДокументОснование: DontIndex → Index. Код не трогать. Конфигурация Wim_Du
П.3 Явное ВЫРАЗИТЬ(СубконтоN КАК Тип) в условии виртуальной таблицы Остатки поможет СУБД выбрать план запроса и сократить время выполнения Расширение zob: перехват ПодготовитьТаблицуВалютныхОстатковПоДокументу через &ИзменениеИКонтроль; перед Запрос.Выполнить() подставлять ВЫРАЗИТЬ по фактическому типу субконто. Расширение zob.cfe
П.2 Ускорение ОбОперация.Записать(Проведение) в EPF — за счёт дочерних узлов, не отдельной доработки Без изменений в обработке —
Резерв Кеш остатков (бегущий кеш по моменту времени) уберёт повторные запросы в цикле Не реализовывалось в этом этапе; рассматривается при необходимости дальнейшего ускорения Расширение / конфигурация

Реализация П.3 в расширении zob (кратко)

  • Модуль УчетДоходовРасходовСервер — заимствование + &ИзменениеИКонтроль.
  • Вспомогательные функции в том же модуле: zob_ПолучитьТипДляВыразитьСубконто, zob_УстановитьВыразитьДляСубконтоВУсловии.
  • В цикле по ТаблицаДляПереоценки — замена условий СубконтоN = &СубконтоN на ВЫРАЗИТЬ(СубконтоN КАК ...) = &СубконтоN.
