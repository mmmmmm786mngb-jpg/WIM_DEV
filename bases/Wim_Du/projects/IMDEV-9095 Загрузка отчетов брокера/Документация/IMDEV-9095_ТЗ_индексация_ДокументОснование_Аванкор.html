1. Суть задачи

При массовом создании документов ОперацияПоСчетуБрокера (обработка распределения доходов по ценным бумагам, команда «Создать всё») на каждое проведение выполняется поиск существующего документа ОтражениеОперацийВРегистрахВУ по реквизиту ДокументОснование.

Реквизит ДокументОснование сейчас не индексируется (DontIndex), из-за чего запрос при проведении выполняется медленно. Требуется включить индексацию.

3. Почему нужно изменение

  • Запрос вызывается при каждом проведении операции по счету брокера с формированием отражения ВУ (~980-1000 раз за один массовый прогон).
  • Без индекса СУБД выполняет полный перебор таблицы документов ОтражениеОперацийВРегистрахВУ.
  • По замерам PFF эта строка занимала 27,2% времени всего сценария (249,9 с из 918,5 с).
  • После включения индексации в тестовой базе время той же строки сократилось до 2,9 с (0,5% сессии) — ускорение в 86 раз (-98,8%).
  • Общее время массового сценария сократилось с 15,3 мин до 10,5 мин (-31,7%).

4. Что сделать (объём работ)

  1. Для реквизита Документ.ОтражениеОперацийВРегистрахВУ.ДокументОснование установить индексирование: Index.
  2. Программный код не изменять.
  3. Выполнить обновление конфигурации базы данных (реструктуризация индекса).
  4. Передать патч/релиз с описанием изменения в метаданных.

5. Критерии приемки

  • В метаданных: ДокументОснование.Indexing = Index.
  • Функциональность формирования ОтражениеОперацийВРегистрахВУ не нарушена.
  • На тестовой базе время выполнения Запрос.Выполнить() (стр. 2447) при массовом проведении — порядка секунд, а не сотен секунд.

7. Ограничения

  • Изменяются только метаданные указанного реквизита.
  • Программный код модулей конфигурации и внешние обработки не затрагиваются.
Резюме: одно изменение в метаданных — ДокументОснование: DontIndex → Index. Подтверждённый эффект: ускорение критичного запроса в 86 раз, сокращение времени массового сценария на 32%.
