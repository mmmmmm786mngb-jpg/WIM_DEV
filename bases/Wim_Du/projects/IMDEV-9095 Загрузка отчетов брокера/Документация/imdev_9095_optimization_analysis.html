1. Введение

Задача IMDEV-9095 — ускорение контура распределения доходов по ценным бумагам в РДУ (обработка «Распределение доходов по ценным бумагам»). Пользователь заполняет табличные части по данным учета ДУ, затем создает и проводит документы ОперацияПоСчетуБрокера.

Scope оптимизации 9095 — только этап «Создать всё». Этап «Заполнить всё» по фактическим замерам занимает около 6 секунд на ~810 строк и не является узким местом. Замер «Заполнение» в EPF сохранен для мониторинга (паттерн IMDEV-9096), но в план оптимизации не входит.

[Пользователь] | v [Заполнить всё] ---> ЗаполнитьТаблицуНКД / Погашение / Дивиденды | (запросы к РегистрБухгалтерии.Хозрасчетный) | BASELINE: 6,1 с (~810 строк) v [Создать всё] ---> СоздатьОперацииПоНКД / Погашение / Дивидендам цикл: Записать(РежимЗаписиДокумента.Проведение) BASELINE: 36 мин 5 с (801 документ) | v [ОперацияПоСчетуБрокера] ---> проведение, переоценка валют, обмен данными

2.3. Методика интерпретации PFF

  • total — полное время строки с учетом вложенных вызовов (с).
  • pure — чистое время самой строки без дочерних вызовов (с).
  • hits — число выполнений строки; для Записать(Проведение) = число документов.
  • Модули конфигурации (Документ.ОперацияПоСчетуБрокера, УчетДоходовРасходовСервер) показывают стоимость проведения «изнутри».

6. Рекомендации по оптимизации (с приоритетами по замеру)

Приоритет Проблема Факт из замера Ожидаемый эффект Рекомендация
1 Построчное Записать(Проведение) 500 с / 754 док; 93% времени НКД Кратное (x3-x10 при пакете) Запись без проведения + групповое/фоновое проведение чанками (50-100); или длительная операция БСП с прогрессом.
2 Тяжелое проведение документа 494 с в модуле документа; 235 с переоценка валют Снижается вместе с п.1 При пакетном подходе меньше транзакций; оценить возможность отключения переоценки для массовой загрузки (согласование с аналитиками).
3 ЗначенияПараметровДоговораДУ на каждое проведение 9,4 с (801 x, ~12 мс) ~10-15 с Кэш параметров договора и валюты учета до цикла по ДоговорДУ.
4 НайтиПоНаименованию в цикле 1,47 с (753 x) ~1,5 с Кэш ссылок на статьи ДДС/затрат до цикла (строки 223, 495-496, 513, 708).
5 ПолучитьКурсВалюты в цикле 0,63 с в EPF + 2,1 с в модуле ~2-3 с Кэш по ключу (Валюта + Период); для RUB не вызывать.
6 ТекущаяДата() в комментарии 0,04 с пренебрежимо Вычислить один раз до цикла.
— Заполнение ТЧ 6,1 с — Не оптимизировать в рамках 9095.

Важно: кэш справочников и курсов — «быстрый win», но дает единицы секунд на 800 документов. Основной резерв — изменение модели проведения (не 801 синхронных транзакций в UI-потоке).

8. Выводы и план работ

Подтверждено замером

  • Заполнение: 6,1 с на ~810 строк — быстро, вне scope 9095.
  • Создание: 36 мин на 801 документ — узкое место задачи.
  • 93% времени НКД — строка Записать(Проведение) (500 с из 503 с процедуры).
  • Проведение тянет за собой УчетДоходовРасходовСервер (переоценка) и параметры договора ДУ.
  • Кэш в EPF — вторичен (единицы секунд vs сотни секунд на проведение).
  1. Baseline зафиксирован — Замеры_01_07_2026.pff, 801 док, 2,7 с/док.
  2. Проектирование: пакетная запись / фоновое проведение / длительная операция БСП.
  3. Быстрые правки EPF: кэш статей ДДС, курсов, параметров договора (после п.2 или параллельно).
  4. Контрольный замер после изменений — тот же сценарий, сравнение с baseline.
  5. Релиз: синхронизация v1.03 с WORK/Wim_Du/SRC/epf/ после приемки.
