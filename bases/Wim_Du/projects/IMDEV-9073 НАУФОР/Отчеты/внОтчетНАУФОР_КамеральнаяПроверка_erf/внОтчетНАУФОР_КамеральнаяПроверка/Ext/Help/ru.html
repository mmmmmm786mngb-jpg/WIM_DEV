Анкета УК для НАУФОР _Камеральная проверка формат

Задача IMDEV-9073. Версия отчета: 1.44.

Назначение

Внешний отчет для выгрузки данных в НАУФОР в рамках внеплановой камеральной проверки управляющей компании.

На выбранную отчетную дату формируется таблица по действующим договорам ДУ выбранной УК. В таблице 14 нумерованных колонок по требованиям НАУФОР и 3 технические колонки (всего 17 физических).

Работа с отчетом

  1. Заполните параметры на форме (обязательны отчетная дата и управляющая компания).
  2. Нажмите Сформировать - результат появится в табличном документе на форме.
  3. При необходимости сохраните результат кнопками Excel (.xlsx) или Word (.docx).
  4. Справка - кнопка с пиктограммой «?» в строке параметров.

Ориентация печати: альбомная. Фиксация шапки: первые 3 строки.

Порядок формирования данных

Для каждой строки отчета (один договор ДУ) данные собираются в такой последовательности:

  1. Отбор договоров ДУ по параметрам формы и правилам исключения (см. ниже).
  2. Расчет дат первой и последней сделок по договору (колонки 13-14).
  3. Заполнение СЧА на отчетную дату (техническая колонка).
  4. Определение квалификации инвестора по клиенту договора (колонки 9-10).
  5. Заполнение данных инвестиционного профилирования (колонки 11-12).
  6. Расчет пролонгации, типа клиента и прочих колонок при выводе в табличный документ.
  7. Обводка рамок и выделение оранжевым фоном дат сделок периода проверки.

Отбор договоров ДУ

В выгрузку попадают элементы справочника ДоговорДУ, для которых одновременно:

  • договор не помечен на удаление;
  • Дата окончания пустая или позже отчетной даты (сравнение по концу календарного дня);
  • Дата заключения (ДатаНачала) не позже отчетной даты;
  • Управляющая компания совпадает с параметром;
  • при заполненном Тип клиента ДУ - совпадение типа;
  • при выборе лицензии - тип клиента входит в список допустимых для ПУРЦБ и/или НПФ.

Исключение «Только лицензия ПУРЦБ»

Применяется только при включенном флаге Лицензия НПФ.

  • флаг выключен - договоры с «Только лицензия ПУРЦБ» этим правилом не отсекаются;
  • флаг включен - договор исключается, если ТолькоЛицензияПУРЦБ = Истина, заполнена ДатаРепортингаПУРЦБ и отчетная дата строго позже даты репортинга;
  • в день даты репортинга договор еще включается.

Исключение по уведомлению о расторжении

Реквизит: ДатаПолученияУведомленияОРасторженииДоговораДУ.

  • исключается, если дата заполнена и не позже отчетной даты (по календарному дню);
  • включается, если дата пустая или позже отчетной даты.

Типы клиентов по лицензиям

Лицензия НПФ: пенсионные резервы НПФ; пенсионные накопления (через НПФ и ПФР); военная ипотека; собственные средства НПФ; СРО; фонд целевого капитала.

Лицензия ПУРЦБ: физические лица; юридические лица; фонд целевого капитала; СРО; страховые компании; собственные средства СК.

Строки сортируются по наименованию клиента, затем по номеру договора.

Тип клиента (колонки 6-8)

По значению ТипКлиентаДУ заполняется ровно одна из колонок 6, 8 или 9:

  • Физические лица - «Физическое лицо»;
  • Фонд целевого капитала, СРО - «Некоммерческая организация»;
  • ЮЛ, резервы и накопления НПФ, военная ипотека, собственные средства НПФ/СК, страховые и гарантийные фонды - «Коммерческая организация».

Проверка ФЦК/СРО выполняется раньше проверки коммерческих типов.

Квалификация инвестора (колонки 9-10)

Источник: регистр сведений ДействующиеКвалИнвесторы, срез на конец отчетного дня по клиенту договора и управляющей компании отчета.

  • ВключенВРеестр = Истина - «квалифицированный» (колонка 9);
  • иначе, в том числе при отсутствии записи - «неквалифицированный» (колонка 10).

Инвестиционное профилирование (колонки 11-12)

Источник: проведенные, не помеченные на удаление документы ИнвестиционныйПрофиль по договору ДУ с датой не позже конца отчетного дня.

  • Колонка 11 - максимальная дата таких документов;
  • Колонка 12 - «Да», если найдено 2 и более документов с разными календарными датами; иначе «Нет».

Дата последней пролонгации (колонка 3)

Расчет выполняется только при заполненном реквизите договора ДатаВводаСредствВДУ («Дата ввода средств в ДУ»). Если поле пустое - колонка 3 пустая (пролонгировать нечего).

Точка отсчета периодов пролонгации - дата ввода средств в ДУ, а не дата заключения договора. Дата заключения используется только в колонке 2.

Дополнительно используются реквизиты карточки договора: СрокДействия, ДействуетДо, ПролонгацияДоговора, ДатаПриостановкиУправления, ДатаВозобновленияУправления.

Верхняя граница расчета

Минимум из:

  • начала календарного дня отчетной даты;
  • начала дня «Действует до», если заполнено;
  • дня, предшествующего дате приостановки, если на отчетную дату управление приостановлено.

Шаг пролонгации

  • СрокДействия <= 100 - срок в годах; шаг ДобавитьМесяц(СрокДействия * 12);
  • СрокДействия > 100 - срок в днях; шаг - фиксированное число календарных дней (например 1825).

В колонку выводится дата последнего наступившего периода пролонгации, не превышающего верхнюю границу. Если полных периодов не было - ячейка пустая.

Дополнительно: при заполненном «Действует до» без флага «Пролонгация договора» колонка пустая; при «Действует до» раньше отчетной даты и пустом сроке - колонка пустая. Без срока действия или без даты ввода средств - колонка пустая.

Даты сделок (колонки 13-14)

Общие условия отбора сделок

Для каждого договора собираются сделки из перечисленных ниже источников. Учитываются только документы, которые:

  • проведены и не помечены на удаление;
  • относятся к договору из строки отчета;
  • имеют календарный день даты сделки не позже отчетной даты;
  • соответствуют отбору по виду операции (купля/продажа, РЕПО и т.д.).

Если подходящих сделок нет - обе колонки пустые.

Два режима расчета

Режим выбирается по длительности действия договора на отчетную дату, а не по полю «Срок действия» в карточке.

Договор действует более 5 лет - если с даты заключения (ДатаНачала) по отчетную дату прошло строго больше 5 календарных лет:

ДобавитьМесяц(НачалоДня(ДатаНачала), 60) < НачалоДня(ОтчетнаяДата)

Условие Колонка 13 (первая сделка) Колонка 14 (последняя сделка) Оформление
С даты заключения по отчетную дату не более 5 лет MIN по всем сделкам до отчетной даты MAX по всем сделкам до отчетной даты «*» в кол. 13 только если дата > 31.12.2024
С даты заключения по отчетную дату более 5 лет MIN сделок с 29.04.2024 по отчетную дату MAX сделок с 29.04.2024 по отчетную дату Оранжевый фон в кол. 13 и 14; «*» в кол. 13 при заполненной дате

29.04.2024 - фиксированное начало периода камеральной проверки. Сделки раньше этой даты в расчет для «длинных» договоров не попадают.

Оформление колонок 13-14

  • Суффикс «*» (только колонка 13):
    • для договоров старше 5 лет - всегда, если дата первой сделки заполнена;
    • для остальных договоров - если дата первой сделки строго позже 31.12.2024.
  • Оранжевый фон (RGB 255, 192, 0) - колонки 13 и 14, если дата рассчитана по периоду с 29.04.2024 (договор старше 5 лет и сделка в периоде найдена). Фон задается после обводки рамок и сохраняется при экспорте в Excel.
  • Если у договора старше 5 лет нет сделок с 29.04.2024 - колонки 13 и 14 остаются пустыми (без «*» и без оранжевого фона).

СЧА (техническая колонка 16)

Источник: регистр сведений РегистрРСА_СЧА, запись с Период = начало отчетного дня (точное совпадение, не срез последних).

Если записи нет или СЧА = 0 - ячейка пустая. Формат числа: 2 знака после запятой, разделитель тысяч.

Оформление табличного документа

  • строка 1 - заголовок «Анкета УК для НАУФОР _Камеральная проверка формат на dd.MM.yyyy»;
  • строка 2 - наименования 17 колонок;
  • строка 3 - нумерация колонок по правилам НАУФОР;
  • данные - с 4-й строки;
  • все ячейки данных обведены сплошной рамкой;
  • сортировка - по клиенту, затем по номеру договора.
