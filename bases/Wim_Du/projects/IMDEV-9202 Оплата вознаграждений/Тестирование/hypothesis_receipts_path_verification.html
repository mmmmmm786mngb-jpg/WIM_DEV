IMDEV-9202: проверка гипотезы путей создания поступлений РДУ

Проект: Оплата вознаграждений | База: WIM_DU (Wim_Du) | Обработка: внТестСбросПоступленийРДУ.epf v1.14+

Инструкция описывает проверку гипотезы о том, как в Аванкоре создаются поступления на расчетный счет при операциях «Списание с брокерского счета» для пула Розничное ДУ: отдельно через Оплата КЗ (ВУК/НДФЛ) и массово через банковскую выписку (переводы при расторжении).

Все шаги выполняются только через внешнюю обработку внТестСбросПоступленийРДУ.epf.

1. Гипотеза

Гипотеза:

  1. Поступления по поручениям с комментарием «Оплата ВУК» (и аналогично НДФЛ) создаются обработкой внОплатаКЗПоКлиентамРДУ, а не из банковской выписки.
  2. Когда приходит банковская выписка, пользователь вручную убирает строку с оплатой ВУК и оставляет сумму только по переводу при расторжении.
  3. Кнопка «Зачисления на р/с Розничного ДУ» в выписке создает поступления по переводам расторжения через внПоступленияНаРасчетныйСчет_РозничноеДУ.

Косвенное подтверждение: поступления Оплата ВУК и массовые переводы в один день могут иметь разное время первой версии, разных авторов и разные комментарии поручений — обработка v1.14 показывает это в таймлайне.

2. Два пути в коде

ОплатаКЗ внОплатаКЗПоКлиентамРДУ

  • Цепочка: НачислениеВознаграждения → поручение «Поручение в Мидл» (Оплата ВУК) → (опционально списание) → поступление
  • Кнопка: «Сформировать поступление на р/с»
  • Основание поступления при создании: как правило поручение с комментарием Оплата ВУК
  • Отпечаток: ДоговорКонтрагента = ЕБС, заполнен брокерский СчетКонтрагента, в назначении нет «по распоряжению от ...»

РДУ выписка внЗагрузкаВыписокДУ + внПоступленияНаРасчетныйСчет_РозничноеДУ

  • Поручения: массовая пачка, комментарий «Перевод ДС при расторжении»
  • Кнопка в выписке: «Зачисления на р/с Розничного ДУ»
  • Основание = плановая позиция = то же поручение
  • Дата документа = входящая дата + 9 часов
  • Отпечаток: часто ДоговорКонтрагента = ЕРС, в назначении есть «по распоряжению от ...» (текст из выписки)
Оплата ВУК/НДФЛ Массовый перевод (расторжение) | | ОплатаКЗ EPF Выписка ДУ Поручение в Мидл Зачисления на РС Сформировать поступление внПоступления РДУ | | ЕБС, брокерский счет ЕРС, текст выписки без "по распоряжению от" с "по распоряжению от"

4. Проверка через обработку

4.1. Открыть обработку

  1. В 1С: Файл → Открыть → выберите внТестСбросПоступленийРДУ.epf из каталога Тестирование.
  2. Либо откройте из Дополнительные отчеты и обработки, если EPF уже зарегистрирована (при обновлении файла на диске переподключите обработку).
  3. В заголовке формы проверьте версию: v. 1.14 или выше.

4.2. Задать период

На вкладке «Сброс и статистика»:

ПолеЗначение
Период сдата проверки, напр. 13.08.2026
пота же дата
Дата операциита же дата (для согласованности)
Пулподставится Розничное ДУ
ЕРСиз настроек обработки РДУ (подставится автоматически)

4.3. Запустить анализ путей

  1. Перейдите на вкладку «Анализ путей».
  2. Снимите галочку «Только строгий отпечаток РДУ» (первый проход — расширенный отбор, видны все списания с брокерского счета пула).
  3. Нажмите «Анализ путей создания» (кнопка на вкладке или в командной панели формы).
  4. Дождите завершения. Результат:
    • таблица «Анализ путей»;
    • таблица «Таймлайн создания (по версиям)»;
    • таблица «Цепочка Оплата ВУК» (для поступлений не из выписки);
    • полный текст отчета в поле Лог на вкладке «Сброс и статистика».

4.4. Уточняющий проход (строгий отпечаток)

  1. Установите галочку «Только строгий отпечаток РДУ».
  2. Снова нажмите «Анализ путей создания».
  3. Сравните количество строк: строгий отбор показывает только документы, созданные по шаблону ПоступленияНаРасчетныйСчет_РозничноеДУ (основание = поручение, дата = вх.дата + 9ч, БУ/ВУ/УУ, RUB).
  4. Ожидание: поступления Оплата ВУК в строгий отбор не попадают (они создаются другим путем).

4.5. Статистика по комментариям поручений

На вкладке «Сброс и статистика» нажмите «Заполнить». В таблице по дням колонка «Комментарии поручений» покажет разбивку, например:

Оплата ВУК - 3; Перевод ДС при расторжении - 18

Текст в поле «Лог»

После анализа в Логе три блока:

  • Сводка по гипотезам — сколько документов в каждом пути.
  • Сравнение времени создания — по первым версиям из ВерсииОбъектов.
  • Цепочка Оплата ВУК — связанные начисление, списание, поручение, поступление.

Таблица «Цепочка Оплата ВУК (не из выписки)»

Для каждого поступления Оплата ВУК без «по распоряжению от» показываются 4 шага:

ШагДокументСвязь
1НачислениеВознагражденияэвристика: договор ДУ + сумма + дата
2СписаниеСРасчетногоСчетаДокументОснование = Начисление или эвристика по дню
3Поручение (Оплата ВУК)создано в ОплатаКЗ, «Поручение в Мидл»

Для каждого шага: ответственный, статус, автор и время первой версии, время последней версии, история статусов (до 8 записей).

7. Критерии подтверждения / опровержения гипотезы

Гипотеза подтверждается, если:

  • Все строки с ПоручениеКомментарий = Оплата ВУК имеют ГипотезаПути с ОплатаКЗ (уверенность Высокая).
  • Все строки с комментарием «Перевод ДС при расторжении» имеют ГипотезаПути = РДУ: Зачисления из выписки.
  • В таймлайне группы Оплата ВУК и Расторжение / РДУ выписка имеют разные окна времени создания (строка >>> Разные окна создания в Логе).
  • Авторы/ответственные в группах часто различаются.
  • При строгом отборе РДУ остаются только массовые переводы (без Оплата ВУК).

Гипотеза не подтверждается или частично, если:

  • Оплата ВУК и расторжение созданы в одно и то же время одним автором (один пакетный процесс).
  • Много строк «Смешанный: EBS + текст выписки» — договор ЕБС, но назначение из выписки.
  • Оплата ВУК попадает в строгий отбор РДУ с «по распоряжению от» — поступление пересоздано через выписку, а не через ОплатаКЗ.

Шаги в обработке

  1. Открыть EPF v1.14+, период 13.08.2026 — 13.08.2026.
  2. Вкладка «Анализ путей», без строгого отбора → «Анализ путей создания».
  3. В таблице «Анализ путей» отфильтровать ПоручениеКомментарий = Оплата ВУК — ожидается 3 строки.
  4. Отфильтровать комментарий содержит расторжени — ожидается 18 строк.
  5. Открыть «Таймлайн создания» — сравнить время и авторы двух групп.
  6. Прочитать в Логе блок === Сравнение времени создания ===.
  7. Для ВУК посмотреть «Цепочка Оплата ВУК» — 4 шага с версиями.
  8. Включить строгий отбор РДУ и убедиться, что 3 ВУК не попали в список.
