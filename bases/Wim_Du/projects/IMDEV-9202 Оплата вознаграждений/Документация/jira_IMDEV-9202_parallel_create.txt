h2. IMDEV-9202: Ускорить "Создать" для "Поступления на расчетный счет: Розничное ДУ" (параллельные порции)

{panel:title=Причина}
По профилю замера на 17.08.2026, 45 документов:
- узкое место: проведение каждого создаваемого документа
- в профиле около 97% времени уходит на вызов Поступление.Записать(РежимЗаписиДокумента.Проведение)

Запрос на "поиск переводов" (ПорученияПоДС) на копии ПРОД подтвержден как быстрый.
Вывод: ускорение достигается только параллельным созданием/проведением документов в разных потоках/фоновых воркерах.
{panel}

{panel:title=Что ускоряем (единственное медленное место)}
Ускорить массовое создание/проведение документов "Поступление":
- текущая логика: последовательная очередь документов
- целевое: распараллелить создание/проведение через чанки
{panel}

h2. Алгоритм (как сейчас)

{noformat}
СоздатьПоступленияДС(ВидОперации)
  Настройки = Настройки(ВидОперации)
  Для каждого Строка Из ПорученияПоДС Цикл
    Если ПоступлениеНаРасчетныйСчет = ПустаяСсылка Тогда
      Поступление(Строка, Настройки)  // внутри: Записать(Проведение)
    КонецЕсли
  КонецЦикла
{noformat}

h2. Алгоритм (как должно быть)

{noformat}
СоздатьПоступленияДС(ВидОперации)
  Настройки = Настройки(ВидОперации)
  Список = ПорученияПоДС (для ВидОперации Перевод или ВводВДУ)

  Если Список.Количество() <= ПорогПоследовательно Тогда
    // оставить как сейчас
  Иначе
    Поделить Список на порции по РазмерПачки

    Для каждого Порция Цикл
      ЗапуститьВФоне(ВоркерСоздатьПачку, ДанныеПорции, Настройки, ВидОперации)
    КонецЦикла

    Дождаться завершения всех воркеров
  КонецЕсли

  // при необходимости: собрать/обновить ТЧ как в текущей логике
{noformat}

h2. Цели (KPI)

{panel}
F1. Функциональная цель
- набор созданных документов и ключевые реквизиты совпадают с baseline (до доработки)
- поручения получают ожидаемый статус (как в текущем поведении)

F2. Производительность
- 45 документов (17.08.2026): ускорение не гарантируется (при размере пачки 50 получится 1 пачка, режим будет фактически последовательным)
- большие объемы: при количестве документов >= 2 * РазмерПачки включается параллельный режим (несколько порций/воркеров), это видно по логу/индикаторам; wall-clock "Создать" уменьшается относительно последовательного выполнения
- в логах должны быть измерения времени:
  - процедура поиска переводов `ПорученияПоДС` (время выполнения запроса/заполнения ТЧ)
  - процедура создания `СоздатьПоступленияДС` (общее время)
  - процедура воркера `создать пачку` (время по пачкам), отдельно для режимов последовательный/параллельный

F3. Надежность
- ошибка по одной строке не ломает остальные порции
- дубли не создаются (сохраняется проверка "если Поступление пустое")
{panel}

h2. Принципы доработки (правила)
# Не менять логику отбора поручений ПорученияПоДС (приоритеты/состав результата не меняем).
# Не менять состав/заполнение документа Поступление: реквизиты как сейчас, проведение остается внутри.
# Ускорение за счет параллелизма: несколько независимых проведений одновременно.
# Во фон передавать только сериализуемые данные (структуры/примитивы), без объектов формы.
# Порог и параметры параллелизма вынести в настройки (чтобы откатывать/подбирать).

h2. Скоуп работ
{panel:title=Изменить}
Внешняя обработка "Поступления на расчетный счет: Розничное ДУ" (v1.04):
- обновить процедуру/функцию СоздатьПоступленияДС(ВидОперации) :
  - добавить диспетчер порций
  - запуск воркеров параллельно
- добавить встроенные замеры времени (как в других обработках проекта):
  - вокруг процедуры поиска переводов `ПорученияПоДС` (запрос/заполнение ТЧ)
  - вокруг `СоздатьПоступленияДС` (общее время)
  - вокруг воркера `создать пачку` (время по пачкам)
- добавить воркер-процедуру "создать пачку":
  - принимает данные пачки + Настройки
  - вызывает текущую логику создания документа (Поступление(...))
- проверить БезопасныйРежим в СведенияОВнешнейОбработке:
  - убедиться, что он не блокирует фоновые выполнения

Форма обработки:
- добавить только один параметр:
  - КоличествоПотоков (дефолт 3), чтение/запись в хранилище настроек выполнить так же, как для остальных параметров обработки

РазмерПачки (50) и ПорогПоследовательно (10) фиксируются в коде (без вывода на форму)
{panel}

{panel:title=Не делать}
- не править конфигурацию проведения документа "Поступление"
- не править отбор "ПорученияПоДС" (для перевода и ввод ВДУ)
{panel}

h2. Комментарий для разработчика (контрольные точки)
- ускорение должно убрать критический путь "Записать(Проведение)" за счет одновременной обработки пачек
- логировать режим (последовательно/параллельно), число потоков, размер пачки
- документальное подтверждение приемки: baseline совпадает, время <= целевого ориентира
- при объеме меньше/равном РазмерПачки ускорение может не проявиться (1 порция = 1 воркер)
