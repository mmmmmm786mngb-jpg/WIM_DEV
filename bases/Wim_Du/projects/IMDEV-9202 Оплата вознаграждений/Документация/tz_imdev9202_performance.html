Один документ останется ~300 мс. Ускорение — 12 проведений одновременно, не «облегчение» проводки.

2. Скоуп

Делаем

  • «Создать»: параллельные потоки (функция Поступление).
  • Потоки 12, пачка 50, порог очереди 10.
  • Лог режима и ошибок.
  • Безопасный режим выключить.

Не делаем

  • Отбор поручений (Новый, пул, ЕРС).
  • Состав реквизитов поступления.
  • Выписки, TIBCO, «Разобрать отмеченные».
  • Проведение в конфигурации, отключение обмена/статусов.

4. Приемка и проверка

  1. Сброс дня тестовой EPF (статус поручений «Новый»).
  2. v1.04: «Начитать» + «Создать» → JSON + .pff «Было».
  3. Сброс. Новая версия → JSON + .pff «Стало».
  4. Снимки совпадают (ключ: договор + номер/дата поручения).
  5. Прогон 11.08.2026 (~5 000): время, без дублей, статусы корректны. Вызов из «Загрузка выписок» без правок вызывающего кода.

Этап 2 (после параллели): замер «Начитать» на большом дне — ускорять запрос только если он тормозит.
