Сравнение папок: .../ОРИГИНАЛ/ и .../Оптимизация/ проекта IMDEV-9202 (Wim_Du).

1. внЗагрузкаВыписокДУ (6.00 → 6.05)

Цель правок: (1) фон поступлений не наследует безопасный режим; (2) две платежки Перевод в одной выписке (группа «расторжение» + остаток); (3) диагностика при несходстве сумм.

  • Уровень 1: обработка внЗагрузкаВыписокДУ
    • Уровень 2: Ext/ObjectModule.bsl
      • ИЗМЕНЕНА СведенияОВнешнейОбработке()
        Версия 6.00 → 6.05. Комментарий IMDEV-9202. БезопасныйРежим без изменений (уже Ложь).
      • ИЗМЕНЕНА ЗачисленияНаРСРозничногоДУ()
        Создание внешней обработки поступлений без безопасного режима (иначе воркеры БСП падают).
        Было:  ВнешниеОбработки.Создать(ИмяФайла);
Стало: ВнешниеОбработки.Создать(ИмяФайла, Ложь);  // IMDEV-9202
      • ИЗМЕНЕНА СоздатьДокументы_РозничноеДУ(...)
        • Для вида Перевод: если итог ТЧ ≠ сумме платежки → ОтобратьПорученияПодСуммуПлатежки(..., "Перевод ДС при расторжении").
        • После успешного создания первой пачки → СоздатьОстатокПереводаПоВторойПлатежке.
        • Сравнение сумм через Окр(..., 2).
        • При несходстве — развёрнутый текст диагностики (вид, № платежки, суммы, число строк, разница).
        • Вид ВводВДУ: логика сверки/создания как в оригинале (без двух платежек).
      • ДОБАВЛЕНА ОтобратьПорученияПодСуммуПлатежки(ТабличнаяЧасть, СуммаПлатежки, ПодстрокаКомментария)
        Читает комментарий поручений. Если сумма строк с подстрокой = платежке — оставляет группу; если платежке равен остаток без группы — оставляет остаток; иначе ТЧ не меняет. Порядок строк выписки не используется.
      • ДОБАВЛЕНА СоздатьОстатокПереводаПоВторойПлатежке(ПерваяСтрока, НоваяОбработка, ТекстСообщения)
        Повторный ПорученияПоДС(Перевод) (уже проведённые не попадают). Если остаток 0 — выход. Иначе ищет вторую входящую на тот же счёт получателя с суммой остатка и другим номером, создаёт вторую пачку. Строки дописываются в ТЧ выписки; форма открывается один раз с обеими пачками.
      • БЕЗ ИЗМЕНЕНИЙ
        Формы, макеты, ЗагрузитьГруппуВыписокВФоне (IMDEV-9096), прочие процедуры модуля.

2. внПоступленияНаРасчетныйСчет_РозничноеДУ (1.04 → 1.10)

Цель правок: параллельное создание/проведение документов; фикс дублей в запросе начитки; работа фона без безопасного режима; идемпотентность и дозаполнение порций.

  • Уровень 1: обработка внПоступленияНаРасчетныйСчет_РозничноеДУ
    • Уровень 2: внПоступленияНаРасчетныйСчет_РозничноеДУ.xml
      • ДОБАВЛЕН реквизит объекта КоличествоПотоков (число, неотрицательное).
    • Уровень 2: Ext/ObjectModule.bsl
      • ИЗМЕНЕНА СведенияОВнешнейОбработке()
        Версия 1.04 → 1.10. БезопасныйРежим: Истина → Ложь.
      • ИЗМЕНЕНА ПорученияПоДС(ВидОперации)
        • JOIN к НачислениеЗадолженности только при виде ВводВДУ (иначе размножение строк ВТ и раздувание Итог("СуммаДС")).
        • Итоговый пакет: ВЫБРАТЬ РАЗЛИЧНЫЕ.
        • Замер: ключ ДУ.ПоступленияНаРасчетныйСчетРДУ.ПорученияПоДС.
      • ИЗМЕНЕНА СоздатьПоступленияДС(ВидОперации)
        Вместо последовательного цикла — вызов диспетчера СоздатьПоступленияПоТабличнойЧасти для Перевод и ВводВДУ.
      • ИЗМЕНЕНА Поступление(ПоручениеПоДС, Настройки)
        В начале — идемпотентность: если уже есть проведённое поступление по основанию (ПоступлениеПоДокументуОснованию), возвращает его без повторного создания. Заполнение реквизитов и проведение — как в оригинале.
      • ДОБАВЛЕНА СоздатьПоступленияПоТабличнойЧасти(ТабличнаяЧасть, Настройки)
        Диспетчер. Параллель, если строк > 50, потоков > 1, обработка в доп. обработках и фон разрешён. Дефолт потоков = 5. Воркеры через ДлительныеОперации.ВыполнитьВФоне (ОжидатьЗавершение = 0). При сбое фона — selective retry порции, дальше последовательно. Сводка в окно сообщений + замер ...Создать.
      • ДОБАВЛЕНА ОбработатьПачкуПоступлений(ПараметрыВыполнения, АдресХранилища) Экспорт
        Воркер: создание пачки через Поступление(); ошибка одной строки не рвёт всю порцию; замер ...Пачка.
      • ДОБАВЛЕНА СоздатьПачкуПоследовательно(...)
        Откат/добивка строк конкретной порции; сверка с БД перед созданием.
      • ДОБАВЛЕНА ДозаполнитьНедостающиеСтрокиПорции(...)
        Для строк порции без ссылки в ТЧ — reconcile из БД или досоздание (идемпотентно).
      • ДОБАВЛЕНА ЗафиксироватьОшибкуПорции(...)
        Журнал IMDEV-9202.ПоступленияНаРасчетныйСчетРДУ + массив сообщений (лимит 20).
      • ДОБАВЛЕНА ТекстОшибкиДлительнойОперации(...)
        Краткое представление ошибки из ответа БСП.
      • БЕЗ ИЗМЕНЕНИЙ логика заполнения полей в Поступление() (кроме проверки идемпотентности), Настройки(), сохранение пользовательских настроек.
    • Уровень 2: Forms/ФормаНастроек/Ext/Form.xml
      • ДОБАВЛЕНО поле КоличествоПотоков (привязка к реквизиту объекта).
    • Уровень 2: Forms/Форма/Ext/Form/Module.bsl
      • ИЗМЕНЕНА ПриСозданииНаСервере — дефолт потоков = 5.
    • Уровень 2: Forms/ФормаНастроек/Ext/Form/Module.bsl
      • ИЗМЕНЕНА ПриСозданииНаСервере — дефолт потоков = 5.
Связка двух обработок. Выписка вызывает поступления через ВнешниеОбработки.Создать(..., Ложь). Без этого параллельный режим поступлений при старте из выписки не работает (безопасный режим наследуется фоном).
