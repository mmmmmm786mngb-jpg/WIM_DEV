Доработка типовых внешних обработок: загрузка выписок ДУ и поступления на р/с Розничного ДУ

Требуется доработать две типовые обработки так, чтобы массовое создание документов ПоступлениеНаРасчетныйСчет работало из формы поступлений и по кнопке из загрузки выписок, с параллельным проведением и корректной разбивкой двух платежек Перевод в одной выписке.

Цель. Пользователь загружает выписку за день, нажимает «Зачисления на р/с Розничного ДУ», получает одну форму поступлений с заполненными поручениями по платежкам дня и создаёт документы. На объёме дня (сотни и тысячи поручений) создание должно идти параллельными порциями. Две входящие платежки вида Перевод в одной выписке (расторжение + остаток) не должны терять поручения и не должны требовать второго запуска кнопки.
Содержание: текущее поведение · обработка 1 (выписки) · обработка 2 (поступления) · сценарии UX · приёмка · вне скоупа · эталон алгоритма

1. Текущее поведение типовых обработок (AS-IS)

1.1. Загрузка выписок, версия 6.00

  • Кнопка «Зачисления на р/с Розничного ДУ» ищет в ТЧ выписки две входящие строки по жёстким правилам (счёт плательщика / получателя / назначение) и для каждой вызывает создание документов поступлений.
  • Первая найденная строка (брокерский счёт 30601810100012100828, получатель 40701810000030000413, в назначении брокер 13W6XW) обрабатывается как вид операции Перевод.
  • Вторая найденная строка (плательщик 40702810116000014928, тот же получатель, назначение про компенсацию) обрабатывается как вид ВводВДУ. Это правило поиска не менять.
  • Обработка поступлений создаётся вызовом ВнешниеОбработки.Создать(ИмяФайла) без второго параметра. Фон БСП наследует безопасный режим: воркеры падают с ошибкой «Установлен безопасный режим. Выполнение операции запрещено» в ДополнительныеОтчетыИОбработки.
  • Для Перевод начитываются все непроведённые поручения вида Перевод. Если в выписке две платежки Перевод, сумма поручений не равна сумме первой найденной строки: сверка не проходит, часть поручений не создаётся, либо пользователь вынужден повторно жать кнопку.
  • Порядок строк в ТЧ выписки не гарантирован: сумма «расторжения» может стоять как в меньшей, так и в большей платежке.

1.2. Поступления РДУ, версия 1.04

  • Регистрация: БезопасныйРежим = Истина, версия 1.04.
  • СоздатьПоступленияДС создаёт документы последовательным циклом по табличной части (прямой вызов Поступление(...)).
  • Нет реквизита числа потоков, нет диспетчера порций, нет отката только одной неудавшейся пачки.
  • На объёме дня (ориентир: порядка 45+ документов уже заметно; реальный день 07.08 — тысячи поручений Перевод) проведение занимает основное время. Цель по производительности: пакет из 45 документов быстрее 5 секунд при доступном фоне.
Не ломать. Запрос поручений не фильтровать по дате и не фильтровать по комментарию на уровне запроса. Исключение непроведённых поступлений (ПлановаяПозиция + Проведен) и статус поручения Новый оставить как в типовой. Поиск двух строк выписки (Перевод / ВводВДУ) не переписывать и не объединять в один «умный» поиск. Не вводить жадный подбор подмножества сумм (subset-sum) и не группировать все комментарии заранее.

2. Обработка 1. Загрузка выписок ДУ — требуемые доработки

Файл типовой обработки. Модуль объекта. Целевая версия в СведенияОВнешнейОбработке: 6.03.

2.1. Снять безопасный режим при создании обработки поступлений

В экспортной функции ЗачисленияНаРСРозничногоДУ() создание внешней обработки поступлений из файла каталога:

НоваяОбработка = ВнешниеОбработки.Создать(ИмяФайла, Ложь);

Второй параметр Ложь обязателен. Без него фоновые задания БСП наследуют безопасный режим, и параллельное создание из выписки не работает. Цикл поиска двух строк выписки не менять.

2.2. Две платежки Перевод в одной выписке

Менять только процедуру СоздатьДокументы_РозничноеДУ и добавить две служебные процедуры. Ветку ВводВДУ (сверка суммы и вызов создания) не трогать.

Для вида Перевод после начитки ПорученияПоДС(Перевод):

  1. Если ПорученияПоДС.Итог("СуммаДС") не равен сумме найденной строки выписки — вызвать отбор по комментарию поручения.
  2. Подстрока комментария фиксированная: Перевод ДС при расторжении (чтение Документ.Поручение.Комментарий).
  3. Если сумма строк с этой подстрокой равна сумме платежки — в ТЧ оставить только их.
  4. Иначе если (итог всех строк минус сумма группы расторжения) равен сумме платежки — оставить строки без этой подстроки.
  5. Иначе ТЧ не менять (случай одной платежки на всю сумму поручений или суммы не бьются — поведение как сейчас).
  6. Порядок строк выписки в отборе не использовать: группа комментария может соответствовать любой из двух платежек Перевод.
  7. Если после отбора суммы совпали — создать первую пачку штатным СоздатьПоступленияДС с ВхНомер и НазначениеПлатежа этой строки.
  8. Затем создать остаток второй платежкой (см. 2.3).
Если ВидОперации = Перевод Тогда
    Если Итог(СуммаДС) <> СуммаПлатежки Тогда
        ОтобратьПорученияПодСуммуПлатежки(..., "Перевод ДС при расторжении");
    КонецЕсли;
КонецЕсли;
// сверка и СоздатьПоступленияДС — как в типовой
Если ВидОперации = Перевод Тогда
    СоздатьОстатокПереводаПоВторойПлатежке(...);
КонецЕсли;

2.3. Остаток Перевод по второй входящей строке

Новая процедура СоздатьОстатокПереводаПоВторойПлатежке:

  1. Повторно вызвать ПорученияПоДС(Перевод). Уже проведённые поступления в запрос не попадают — в ТЧ остаётся только несозданный остаток.
  2. Если остаток 0 — выход. Это день с одной платежкой Перевод на всю сумму. Форма открывается как раньше.
  3. Иначе найти в ТЧ выписки другую входящую строку: тот же ПолучательСчет, другой номер документа, сумма равна остатку поручений.
  4. Создать вторую пачку с её входящим номером и назначением платежа.
  5. Строки второй пачки дописать в ПорученияПоДС_РДУ. Форму поступлений открыть один раз с обеими пачками.
  6. В шапке формы входящий номер будет от последней созданной пачки — это допустимо. У документов поступлений входящие номера должны быть правильными (от своей платежки).

Если строку компенсации (ВводВДУ) найти не удалось, сообщение «Не удалось найти строку…» не должно блокировать создание Перевод. Обе банковские строки Перевод; вторая жёсткая маска поиска по-прежнему относится к ВводВДУ и остаётся как в типовой.

2.4. Что не делать в выписках

  • Не менять обе найденные строки на вид Перевод.
  • Не строить общий алгоритм «все входящие платежки дня».
  • Не фильтровать поручения по комментарию, если итог ТЧ уже равен сумме найденной платежки.
  • Не требовать от пользователя второго нажатия кнопки и второй открытой формы.

3. Обработка 2. Поступления на р/с Розничного ДУ — требуемые доработки

Файл типовой обработки. Целевая версия 1.08. Обработка должна работать и с формы, и при вызове из выписок.

3.1. Регистрация в справочнике дополнительных обработок

  • СведенияОВнешнейОбработке: версия 1.08, БезопасныйРежим = Ложь.
  • После доработки обработку нужно загрузить в справочник ДополнительныеОтчетыИОбработки. Поиск из выписок идёт по ИмяОбъекта = ПоступленияНаРасчетныйСчет_РозничноеДУ.

3.2. Реквизит числа потоков

  • Добавить реквизит объекта КоличествоПотоков (число).
  • Вывести поле на форму настроек (привязка к Объект.КоличествоПотоков).
  • На основной форме и на форме настроек в ПриСозданииНаСервере: если значение меньше 1, установить 5.

3.3. Диспетчер вместо последовательного цикла

СоздатьПоступленияДС не вызывает Поступление в цикле по всей ТЧ. Делегирование:

СоздатьПоступленияПоТабличнойЧасти(ПорученияПоДС, Настройки(...));
// аналогично для ПорученияПоДСВвод / ВводВДУ

Правила диспетчера СоздатьПоступленияПоТабличнойЧасти:

Воркер ОбработатьПачкуПоступлений — точка входа для ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки. Создаёт документы пачки, возвращает результат через временное хранилище (XML хранилища значения). Ошибки БСП показывать пользователю реальным текстом, не заглушкой «Порция не вернула результат.»

3.4. Замеры производительности

  • Вокруг запроса/заполнения ПорученияПоДС — ОценкаПроизводительности.
  • Ключ создания: ДУ.ПоступленияНаРасчетныйСчетРДУ.Создать.
  • Ключ пачки: ДУ.ПоступленияНаРасчетныйСчетРДУ.Пачка.

5. Критерии приёмки

  1. Типовая выписка собрана в EPF версии 6.03, типовые поступления — 1.08. Обе загружены в справочник дополнительных обработок. У поступлений безопасный режим выключен.
  2. Кнопка «Зачисления на р/с Розничного ДУ» открывает одну форму поступлений; при двух платежках Перевод в ТЧ обе пачки.
  3. На контрольном дне 07.08 поручения расторжения и остаток создаются за один запуск, входящие номера документов соответствуют платежкам.
  4. День с одной платежкой на всю сумму визуально и по составу документов совпадает с текущей типовой.
  5. Параллельное создание работает и с формы поступлений, и из выписки. В журнале нет ошибки безопасного режима БСП на воркерах.
  6. Если фон недоступен, документы всё равно создаются (последовательный откат той пачки, без обрыва уже созданных).
  7. Ветка ВводВДУ и жёсткий поиск второй строки выписки не изменены по смыслу.
  8. Запрос поручений без фильтра по дате и без фильтра по комментарию.

6. Вне скоупа

  • Изменение конфигурации (документы, регистры, общие модули платформы кроме вызовов уже существующих БСП / оценки производительности).
  • Переписывание загрузки выписки из банка, разбора 1CClientBankExchange, web-service ВТБ.
  • Изменение правил поиска строк ВводВДУ.
  • Фильтр поручений по дате «как в пользовательском отборе формы».
  • Жадный подбор произвольного подмножества поручений под сумму платежки.
