Алгоритм работы: Начисление вознаграждения за управление: Розничное ДУ

Источник: ОРИГИНАЛ/внНачислениеВознаграждения_РозничноеДУ_epf (версия в метаданных: 1.09, имя объекта НачислениеВознаграждения_РозничноеДУ). Документ подготовлен для разбора IMDEV-9153.

Важно про регламент 23:45: в обработке есть только одна фоновая команда — НачислениеВознагражденияПриРасторженииРозничноеДУФоновое. Она считает не квартальный ВУК по всем РДУ, а только договоры с расторжением, и только если текущий день — рабочий по регламентированному календарю. Команда обычного (не расторжение) начисления — только открытие формы, без фонового API.

1. Команды БСП

КомандаТипЧто делает

НачислениеВознагражденияПриРасторженииРозничноеДУФоновое ВызовСерверногоМетода Фон: РежимРасторжения = Истина → отбор + создание документов

Именно вторая команда обычно вешается на регламентное задание (в т.ч. ежедневно в 23:45).

3. Сценарий фонового запуска (23:45 ежедневно)

ВыполнитьКоманду("...ПриРасторжении...Фоновое"):
  ДатаНачисления = НачалоДня(ТекущаяДатаСеанса())

  ЕСЛИ ДатаНачисления <> БлижайшийРабочийДень(ДатаНачисления) ТОГДА
      // выходной / праздник по КалендарныеГрафики (РегламентированныйКалендарь)
      // НИЧЕГО НЕ ДЕЛАЕТ
      ВОЗВРАТ
  КОНЕЦЕСЛИ

  Загрузить настройки (Пул, ставка, счета, каталоги)
  РежимРасторжения = Истина
  ДоговорыКНачислению()
  СоздатьНачисления()
Поэтому регламент «каждый день 23:45» на практике отрабатывает только в рабочие дни. В выходные команда стартует и сразу выходит без начислений.

4. Выбираются ли все договоры РДУ?

Нет. Даже при пуле «Розничное ДУ» берётся не весь пул, а пересечение нескольких фильтров. В фоновом режиме расторжения — ещё уже: только договоры с уведомлением о расторжении.

4.1. Базовый отбор договоров (ВТ_ДоговорыДУКРасчету)

УсловиеСмысл
Пул = &Пул или Ссылка В (&ДоговорыДУ) Либо весь указанный пул, либо явный список с формы
ДатаОкончания пустая или > ДатаРасчета Договор ещё «живой» на дату расчёта
Если РежимРасторжения = Ложь (форма, обычный ВУК)
ДатаПолученияУведомленияОРасторженииДоговораДУ пустая Только нерасторгнутые
Если РежимРасторжения = Истина (фон 23:45)
Дата уведомления о расторжении заполнена и <= ДатаРасчета Есть расторжение
ДатаВводаСредствВДУ + 13 дней < Дата уведомления Уведомление не раньше чем через 14-й день после ввода средств (в коде: ДОБАВИТЬКДАТЕ(..., ДЕНЬ, 13) < ДатаУведомления)

Также подтягивается договор вознаграждения:

ДоговорыКонтрагентов.ДоговорДУ = ДоговорДУ
И РольДоговора = СоглашениеОВознаграждении

(ЛЕВОЕ соединение — договор вознаграждения может быть пустым).

4.2. Дополнительные отборы после соединения данных

В итоговую выборку попадают только договоры, у которых:
  1. Есть вводы ДС — внутреннее соединение с ВводыВыводыДУ (Активность, Сумма > 0). Без ввода договор не попадёт.
  2. Есть сумма к начислению из обязательств (ОбязательстваПоДС с пустым Основание) или это режим расторжения.
  3. Нет уже проведённого документа НачислениеВознаграждения с флагами: Розница = Истина и комментарий "Дополнительное вознаграждение" (защита от дубля «доп. вознаграждения» при расторжении).
  4. После выборки в цикле: СуммаВознаграждения + СуммаУдержанияПриРасторжении > 0.
Итого для фона 23:45: не «все РДУ», а РДУ пула + живые + с расторжением (по правилам) + с вводом ДС + с ненулевой суммой.

5. Откуда берётся сумма

Это не вызов MF-алгоритма и не монитор 0060.

ИсточникКогда
Остатки ОбязательстваПоДС (основание пустое) на ДатаРасчета Обычное начисление / база по договору
Обороты обязательств за период до квартала расторжения Досрочное расторжение
Удержание при расторжении: % от суммы инвестиций (3% / 2% / 1% / 0% по сроку дней) Досрочное расторжение
Обороты Хозрасчётный: счёт вознаграждения УК ↔ расчётные счета Уже выплаченное (для справки в режиме расторжения)

«Сумма за весь срок» в обычном режиме для справки: Окр(СуммаИнвестиций / 100 * СтавкаВознаграждения * СрокДоговора, 2).

6. Создание документа НачислениеВознаграждения

Для каждой строки ТЧ:
  1. Если СуммаВознаграждения > 0 — создать основное начисление.
  2. Если расторжение и СуммаУдержанияПриРасторжении > 0 — создать/обновить документ с комментарием "Дополнительное вознаграждение".
  3. Сформировать PDF справку-расчёт.
  4. Удалить «сырые» обязательства ДС (ОперацияБух + движения без основания).

8. Связь с IMDEV-9153

ВопросОтвет по коду оригинала
Закрывает ли эта обработка «квартальный ВУК всем РДУ в 00:15 1.01/04/07/10»? Нет. Фоновая команда — про расторжение, ежедневный рабочий день.
Можно ли повесить на 23:45 обычное начисление? Через текущий API — нет (нет серверной команды без режима расторжения).
Почему документы с Розница + ФиксированнаяСумма? Так жёстко заполняет НачислениеВознаграждения() этой обработки.
Чем отличается монитор 3.1 / наша внАвтоНачислениеВУК_РДУ? План + операция 0060 + способ из параметров ДУ (часто ПоАлгоритму → MF), без флага Розница.
Если на ПРОД регламент 23:45 реально стоит на этой фоновой команде — это автоматизация начислений при расторжении РДУ, а не замена квартального ручного запуска из монитора.
