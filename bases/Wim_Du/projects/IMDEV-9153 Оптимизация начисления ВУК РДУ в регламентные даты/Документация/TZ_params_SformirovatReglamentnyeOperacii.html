IMDEV-9153. ТЗ на сборку параметров для запуска СформироватьРегламентныеОперации

Цель: описать необходимый и достаточный набор параметров, чтобы из новой дополнительной обработки (фоновое / регламентное выполнение) корректно вызвать существующий экспортный метод базовой конфигурации: 

Справочники.РегламентныеПериоды.СформироватьРегламентныеОперации(ПараметрыПроцедуры, АдресХранилищаРезультат)

Сценарий: автоначисление ВУК по договорам пула «Розничное ДУ», группа операций «3.1 Вознаграждение за управление», операция «Вознаграждение управляющей компании (БУ)».

Статус: черновик для разработки / BA. Детали поведения (выходные, пересчёт, письмо об ошибках) могут уточняться по ответам заказчика.

1. Контекст и границы

  • Не переписывать монитор и не копировать UI-логику дерева флажков.
  • Использовать уже существующий многопоточный контур монитора (на ПРОД константа потоков = 12).
  • Внешняя обработка MF (MF_РасчетВознаграждения_РозничноеДУ) вызывается внутри проведения НачислениеВознаграждения — отдельно её вызывать не нужно.
  • В СписокОпераций для автозапуска — одна операция: УК (БУ).

2. Сигнатура вызова

ПараметрТипНазначение
ПараметрыПроцедуры Структура Входные данные запуска (см. раздел 4)
АдресХранилищаРезультат Строка (адрес ВХ) Куда метод положит результат {Успешно, Сообщение}

Подготовка адреса:

АдресХранилищаРезультат = ПоместитьВоВременноеХранилище(Неопределено);

3. Предусловия (до сборки параметров)

  1. Дата периода = календарный конец предыдущего квартала относительно даты запуска РЗ.
    Примеры:
    • запуск 01.04.2026 00:15 -> ДатаПериода = 31.03.2026
    • запуск 01.07 -> 30.06
    • запуск 01.10 -> 30.09
    • запуск 01.01 -> 31.12 предыдущего года
  2. В справочнике Регламентные периоды должен существовать элемент на ДатаПериода. Если нет — создать автоматически (ДатаПериода + запись).
  3. Если период существует, но по договорам закрыт — поведение по согласованию с BA (пропуск / ошибка / не трогать закрытие). По умолчанию для черновика: зафиксировать ошибку и не продолжать массовый запуск «вслепую».

Рекомендуется после заполнения добавить индексы (как в мониторе):

6. Алгоритм сборки (пошагово)

  1. Определить ДатаЗапуска / проверить, что день — 1 января / 1 апреля / 1 июля / 1 октября.
  2. Вычислить ДатаПериода = конец предыдущего квартала.
  3. Найти группу операций «3.1 Вознаграждение за управление»; прочитать у неё ВремяРеглОпераций.
  4. Найти вид операции ВознаграждениеУК_БУ.
  5. Проверить/создать элемент РегламентныеПериоды на ДатаПериода.
  6. Сформировать СписокДоговоровДУ (пул «Розничное ДУ» + отборы BA).
  7. Если список пуст — завершить с понятным сообщением (без вызова метода).
  8. Собрать СписокОпераций: по одной строке на договор, время и группа — строго из 3.1.
  9. Собрать ДокументыПоДоговорам запросом.
  10. Собрать ПараметрыСохранения и ПараметрыПроцедуры.
  11. Вызвать СформироватьРегламентныеОперации.
  12. Прочитать результат из временного хранилища; записать в ЖР / (опционально) отправить письмо.

8. Критерии корректности сборки

  • Метод запускается без ошибки валидации входных параметров.
  • Создаются/проводятся ПланРегламентныхОперацийДУ с группой 3.1.
  • Создаются/проводятся подчиненные НачислениеВознаграждения (УК, не за успех).
  • Время/дата планов совпадает с ручным запуском из монитора на ту же ДатаПериода (в т.ч. время из группы 3.1).
  • Параллельность соответствует константе потоков (до 12 на ПРОД).
  • Повторный контрольный прогон: ручной монитор vs обработка на одном наборе договоров — сопоставимый результат.
