Задача: IMDEV-9153. База: Wim_Du. Объект: внешняя обработка внНачислениеВознаграждения_РозничноеДУ (ObjectModule.bsl рабочей копии в проекте). Дата фиксации требований: 22.07.2026.

Два этапа доработок.
Этап 1 (это ТЗ): оптимизация обычного режима без смены бизнес-логики отбора обязательств — пакетный запрос заранее + удаление после успешного начисления + отчётность (ЖР + письмо).

1. Цель и границы

Снизить число запросов и обращений к регистру при очистке обязательств по ДС в обычном (не расторжение) режиме начисления ВУК РДУ, сохранив смысл отбора движений (регистраторы на минимальный период по договору).

  • Изменение формулы суммы / способа начисления
  • Рефакторинг режима расторжения

2. Текущее поведение (AS-IS)

Процедура СоздатьНачисления для каждой строки ТЧ:

  1. Создаёт документ начисления (при сумме > 0)
  2. Формирует PDF-справку
  3. Вызывает УдалитьОбязательствоДС(Договор, Расторжение) — отдельный запрос и очистка на каждый договор

В обычном режиме запрос берёт МИНИМУМ(Период) по договору и регистраторы ОперацияБух (Приход, пустое Основание). Далее: прочитать набор → удалить строки с фильтром по договору → записать → ОперацияБух.Удалить().

В текущем коде ошибки записи начисления и сохранения PDF часто «глотаются» (пустой Исключение / без сводки). Для этапа 1 требуется явная фиксация успехов и ошибок с итоговым сообщением.

3. Ограничения платформы / метаданных

ФактСледствие для алгоритма
Документ.ОперацияБух: Posting = Deny, RegisterRecordsDeletion = AutoDeleteOff Удаление документа не снимает движения автоматически. Нужна запись пустого набора ОбязательстваПоДС по отбору регистратора (без Прочитать), затем удаление документа.
У ОперацияБух один договор ДУ (основной реквизит) Фильтр строк набора по ДоговорДУ не нужен — очищается весь набор регистратора. Гонки между пачками по одному регистратору не ожидаются (этап 2 опирается на разрез по договорам).

4. Требуемое поведение (TO-BE) — обычный режим

Расторжение: путь УдалитьОбязательствоДС(..., Истина) и ТекстЗапросаРасторжение() не менять.

4.1. Подготовка (один раз перед циклом)

  1. Собрать массив договоров из ДоговорыДУКНачислению (для обычного режима — договоры, по которым будет начисление суммы > 0; либо весь список ТЧ — см. примечание в приложении).
  2. Выполнить один запрос (логика текущего ТекстЗапроса(), параметр В (&Договоры)): пары ДоговорДУ → Регистратор.
  3. Поместить результат в соответствие в памяти.

4.2. Цикл по договорам

  1. Начисление (если сумма > 0).
    Успех записи/проведения → положительный факт.
    Ошибка → зафиксировать ошибку; обязательство не очищать; перейти к следующему договору (PDF по решению реализации: либо не формировать, либо формировать и тоже учитывать — рекомендация: при ошибке начисления PDF не формировать и очистку не делать).
  2. PDF (ФормироватьСправкуРасчет).
    Успех → положительный факт.
    Ошибка → зафиксировать ошибку (начисление при этом может быть успешным). Очистку обязательства при успешном начислении всё равно выполнять (ошибка PDF не блокирует очистку).
  3. Очистка обязательства — только если начисление успешно и найден регистратор в заранее собранном соответствии:
    записать пустой набор по отбору регистратора (без Прочитать) → удалить ОперацияБух.
    Ошибка очистки/удаления → зафиксировать, продолжить следующие договоры.

4.3. Финал

Сформировать сводку и отправить: письмо + запись в Журнал регистрации (успехи и ошибки по начислению, PDF, очистке регистра).

7. Критерии приёмки

  1. На тестовом наборе N договоров обычного режима выполняется один запрос отбора регистраторов на весь прогон (не N запросов).
  2. Очистка регистра и удаление ОперацияБух выполняются только после успешного начисления.
  3. При ошибке очистки прогон продолжается; ошибка попадает в итоговую сводку.
  4. Успех/ошибка начисления и PDF отражаются в письме и ЖР.
  5. Режим расторжения работает как до доработки (регрессия).
  6. После успешной очистки остаток по обязательствам ДС (Приход, пустое Основание) по договору на снятом регистраторе отсутствует; «осиротевших» движений после удаления документа нет.

		Результат.Ссылка = НачислениеВознаграждения(ДоговорДУ, Расторжение);
		// IMDEV-9153: этап 1 — успех = документ записан/проведён без исключения и ссылка заполнена.
		Результат.Успех = ЗначениеЗаполнено(Результат.Ссылка);
		Если Не Результат.Успех Тогда
			Результат.ТекстОшибки = "Документ начисления не создан";
		КонецЕсли;
	Исключение
		Результат.Успех = Ложь;
		Результат.ТекстОшибки = ОписаниеОшибки();
	КонецПопытки;

	Возврат Результат;

КонецФункции

Дополнительно в самой НачислениеВознаграждения убрать пустой обработчик: либо пробрасывать исключение наружу, либо возвращать незаполненную ссылку и писать текст ошибки (но не молчать). Рекомендуемый минимум: 

	Попытка
		Начисление.Записать(РежимЗаписиДокумента.Проведение, РежимПроведенияДокумента.Неоперативный);
	Исключение
		// IMDEV-9153: этап 1 — не скрывать ошибку проведения: проброс в НачислениеВознагражденияСРезультатом.
		ВызватьИсключение;
	КонецПопытки;
