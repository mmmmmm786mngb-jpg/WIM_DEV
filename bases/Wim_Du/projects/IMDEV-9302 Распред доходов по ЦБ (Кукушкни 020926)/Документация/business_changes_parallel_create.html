Ускорение обработки «Распределение доходов по ценным бумагам»

Задача IMDEV-9302 · для пользователей бэк-офиса Розничного ДУ
Обработка: Дополнительные отчеты и обработки → «Распределение доходов по ценным бумагам»

Коротко: смысл работы не меняется. Меняется только то, как система выполняет кнопку «Создать всё»: документы создаются несколькими параллельными порциями, а на экране появляется окно хода выполнения (сделано / осталось / оценка времени). Результат тот же — операции по счетам брокера по отмеченным строкам.

1. Зачем это нужно

Когда доходов много (сотни строк по купонам, погашениям, дивидендам), нажатие «Создать всё» занимает заметное время — обозначим его как N минут (зависит от объёма дня и загрузки сервера). Форма занята, пока система по одной строке создаёт и проводит документы.

Цель доработки — сократить время ожидания относительно N при том же результате учёта.

2. Что не меняется

  • Тот же порядок работы: сначала Заполнить, потом проверка строк, потом Создать.
  • Те же три вкладки: НКД (купон), Погашение, Дивиденды.
  • Те же параметры: пул, период, брокер, дата создания документов.
  • По-прежнему создаются документы «Операция по счету брокера» (зачисление) — по одной операции на каждую отмеченную строку.
  • Если операция по строке уже была найдена при заполнении — она обновляется и проводится снова (как сейчас).
  • Кнопки создания по одной вкладке («Создать НКД», «Создать погашение», «Создать дивиденды») работают как раньше — по очереди.
  • Автоматический ночной регламент не добавляется — запуск по-прежнему ручной.

3. Что меняется

Было

«Создать всё» идёт строго по очереди: сначала все отмеченные купоны, потом погашения, потом дивиденды — каждая операция одна за другой.

Как очередь в одно окно.

Станет

«Создать всё» разобьёт отмеченные строки на порции и обработает несколько порций одновременно (в пределах лимита сервера).

Пока идёт работа, откроется окно хода выполнения: сколько уже сделано, сколько осталось и ориентировочное время до конца (по тому же принципу, что в других длительных обработках).

Как несколько окон обслуживания + табло прогресса.

Для пользователя: нажали «Создать всё» → видите окно прогресса → по окончании в таблицах ссылки на операции и сообщения об успехе или ошибках. Состав создаваемых документов не меняется.

4. Как пользоваться после доработки

  1. Открыть обработку из справочника «Дополнительные отчеты и обработки» (не из произвольного файла) — так сервер сможет запускать параллельные порции.
  2. Указать пул, период, брокера, дату создания.
  3. Нажать Заполнить всё — строки появятся на трёх вкладках.
  4. Проверить суммы, при необходимости снять галочки с лишних строк.
  5. Нажать Создать всё — дождаться окна прогресса и его завершения (выполнено / осталось / оценка времени).
  6. Просмотреть сообщения: созданные операции и ошибки (если были).
Важно: пока открыто окно прогресса «Создать всё», не закрывайте форму и не запускайте кнопку повторно — дождитесь завершения или отмены в окне ожидания.

5. Если параллель не включится

Система автоматически вернётся к прежнему «по очереди» режиму, если:

  • на сервере запрещены фоновые задания;
  • лимит параллельных потоков равен 1 или не задан;
  • обработку открыли не через справочник доп. обработок.

В этом случае результат тот же, просто без ускорения и без окна прогресса (работа идёт «по очереди», как сейчас). Для пользователя кнопка и набор полей не меняются.

6. Ошибки по отдельным строкам

Как и сейчас: сбой по одной строке не отменяет остальные. По проблемным строкам будет сообщение об ошибке; успешные операции останутся созданными. Можно исправить данные и повторить создание только по нужным отмеченным строкам.

7. Ожидаемый эффект

ПоказательОриентир
Сейчас (массовый прогон «Создать всё») N минут — фактическое время на вашем объёме «как есть»
После доработки ожидаем время меньше N за счёт нескольких порций сразу; насколько именно — уточняется замером «до / после» на одном и том же наборе строк
Состав документов без изменений: те же «Операции по счету брокера»
Ускорение касается именно этапа «Создать всё». Кнопка «Заполнить всё» (подбор строк из учёта) в этой доработке не меняется.

8. Краткие ответы на частые вопросы

Вопрос Ответ
Появятся ли лишние документы? Нет. Правило то же: одна отмеченная строка — одна операция. Параллель только ускоряет создание.
Нужно ли что-то менять в ежедневном сценарии? Нет. Заполнить → проверить → Создать всё.
Нужен ли новый регламент / автозапуск ночью? Нет, в этой задаче не планируется.
Можно ли по-прежнему создавать только купоны или только дивиденды? Да, кнопки по вкладкам остаются.
Кто получает доступ? Те же пользователи, у кого уже есть эта обработка в доп. отчётах и обработках.

Задача IMDEV-9302: ускорение кнопки «Создать всё» за счёт параллельных порций (как при ускорении начисления ВУК РДУ, IMDEV-9153) и окна хода выполнения с процентом и оценкой времени (как в длительных обработках, IMDEV-9182). Регламентный автозапуск не добавляется.
