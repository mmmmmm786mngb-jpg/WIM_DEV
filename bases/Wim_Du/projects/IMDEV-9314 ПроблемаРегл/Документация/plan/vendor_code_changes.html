IMDEV-9314. Внесение в типовую, релиз 1.5.29.7

Документ Установка котировок ц/б, модуль объекта. Меняются только две функции: ЗафиксированныеКотировкиБУ и ЗафиксированныеКотировкиУУ. Функцию ЗафиксированныеКотировкиНУ не трогать. Сигнатуры вызова не менять. Построчное сравнение: БУ, УУ.

1. Почему

Вечерний регламент на больших ИДУ тормозит на заполнении котировок. Замер: функции БУ и УУ дают около 40% времени (тысячи вызовов, каждый срез по 1–1.5 с).

В релизе 1.5.29.7 в виртуальных таблицах стоит Актив В (&СписокЦБ). Платформа разворачивает список в N отдельных параметров SQL и режет срез по этому IN. На договоре с сотнями/тысячами ЦБ это упирается в лимит параметров и даёт тяжёлый план.

Нужно: один табличный параметр вместо IN-списка; срез зафиксированных котировок сначала во временную таблицу с индексом; актив отбирать JOIN-ом, а не условием внутри виртуальной таблицы. Схема одна для БУ и УУ, различаются только регистр и набор полей.

После JOIN в ИНДЕКСИРОВАТЬ ПО писать поле с префиксом таблицы (Котировки.Актив, КотировкиЦБНаБиржеСрезПоследних.Актив). Без префикса платформа падает: «Неоднозначное поле Актив».
2. Что менять в модуле объекта

Где: Документ.УстановкаКотировокЦБ, модуль объекта, релиз 1.5.29.7 (БУ около строки 331, УУ около строки 473).

Шаг Было (1.5.29.7) Стало
1. Параметр списка ЦБ УстановитьПараметр("СписокЦБ", СписокЦБ) и в запросе Актив В (&СписокЦБ) Собрать таблицу значений с колонкой Актив, передать одним параметром &ТаблицаАктивов. Параметр СписокЦБ из запроса убрать.
2. Срез биржевых котировок КотировкиЦБНаБирже.СрезПоследних(..., Актив В (&СписокЦБ) И Биржа В (&СписокБирж)) В параметрах среза оставить только Биржа В (&СписокБирж). Отбор по активу — ВНУТРЕННЕЕ СОЕДИНЕНИЕ втАктивы.
3. Срез зафиксированных котировок Срез сразу в АктуальныеКотировки с Актив В (&СписокЦБ) и LEFT JOIN к биржевым мин/макс Сначала срез в втСрезЗафиксированных (только договор и Расчетная = ЛОЖЬ), индекс по (Актив, Валюта). Потом JOIN с втАктивы и LEFT JOIN с ВТ_КотировкиЦБ в АктуальныеКотировки.

Сбор таблицы активов — отдельная функция модуля объекта ТаблицаАктивовИзСпискаЦБ, её вызывают обе функции. Приём с таблицей значений уже есть в этом же модуле для приоритета бирж (&ПриоритетБирж). Состав полей результата не менять: вызывающий код читает ту же ВТ АктуальныеКотировки.
3. Готовый код для вставки

Добавить в модуль объекта функцию (вызывают БУ и УУ)

// Описание: Собирает таблицу значений активов из списка ЦБ для параметра запроса.
// Один параметр &ТаблицаАктивов вместо IN (&СписокЦБ), чтобы не упираться в лимит параметров SQL.
//
// Параметры:
// СписокЦБ - Массив, СписокЗначений - ссылки на справочник Активы
//
// Возвращаемое значение:
// ТаблицаЗначений - колонка Актив (СправочникСсылка.Активы)
//
Функция ТаблицаАктивовИзСпискаЦБ(СписокЦБ) // IMDEV-9314
	
	ТаблицаАктивов = Новый ТаблицаЗначений;
	ТаблицаАктивов.Колонки.Добавить("Актив", Новый ОписаниеТипов("СправочникСсылка.Активы"));
	
	Если Не ЗначениеЗаполнено(СписокЦБ) Тогда
		Возврат ТаблицаАктивов;
	КонецЕсли;
	
	Для Каждого ТекАктив Из СписокЦБ Цикл
		СтрокаТЗ = ТаблицаАктивов.Добавить();
		Если ТипЗнч(ТекАктив) = Тип("ЭлементСпискаЗначений") Тогда
			СтрокаТЗ.Актив = ТекАктив.Значение;
		Иначе
			СтрокаТЗ.Актив = ТекАктив;
		КонецЕсли;
	КонецЦикла;
	
	Возврат ТаблицаАктивов;
