Коллеги, краткое описание, как устроено фоновое распределение при формировании регламентных операций (справочник РегламентныеПериоды, модуль менеджера, база Wim_Du).

1. Два уровня фона

Работает не один фон, а два уровня:

Уровень Что делает Где в коде
Внешний Форма запускает длительную операцию БСП, чтобы интерфейс не зависал и был прогресс. Forms\РегламентныйПериод\...\Module.bsl
ДлительныеОперации.ВыполнитьВФоне(...)
Внутренний Внутри менеджера по каждому договору поднимается отдельное фоновое задание на создание плана операций. Одновременно работает пул потоков. Ext\ManagerModule.bsl
СформироватьДокументыЗакрытияПериода

Лимит параллельности берётся из константы МаксимальноеКоличествоПараллельныхПотоков и кладётся в ПараметрыСохранения.КоличествоПотоков.
2. Диспетчер в модуле менеджера

Экспортная процедура СформироватьРегламентныеОперации:

  1. Проверяет входные параметры (дата, список договоров, параметры сохранения).
  2. Режет список договоров на пачки по 3000 (экономия памяти).
  3. Для утренних/вечерних операций подгружает пакетный кэш только по текущей пачке.
  4. По каждому договору сообщает прогресс и вызывает СформироватьДокументыЗакрытияПериода.

Фрагмент (пачки + вызов по договору):

РазмерПачки = 3000;
Для ИндексПачки = 0 По Цел((КоличествоДоговоров - 1) / РазмерПачки) Цикл
    // ... подготовка пачки и кэша ...
    Для Каждого ТекДоговор Из СписокПачки Цикл
        ДлительныеОперации.СообщитьПрогресс(...);
        СформироватьДокументыЗакрытияПериода(
            ДатаПериода, ТекДоговор, УчитыватьВыполненные,
            НаименованиеФоновогоЗадания, ТекущийНомер, КоличествоДоговоров,
            ПараметрыСохранения);
    КонецЦикла;
КонецЦикла;
3. Само «фоновое распределение» (пул заданий)

В СформироватьДокументыЗакрытияПериода для договора собирается таблица операций и кэш, затем:

Если КоличествоПотоков > 0 и фоновые задания разрешены — создаётся отдельное ФЗ:
ФоновыеЗадания.Выполнить("ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ", ...)
Иначе — то же создание плана выполняется синхронно в текущем сеансе (без параллели).

Логика пула:

  1. Каждое запущенное ФЗ добавляется в МассивФоновыхЗаданий.
  2. Когда набрано N = КоличествоПотоков заданий или обработан последний договор — вызывается ожидание завершения порции.
  3. После ожидания массив очищается, набирается следующая порция.
  4. На последнем договоре дополнительно собираются аварийно завершённые задания с тем же наименованием и выводятся их ошибки.

Фрагмент (запуск + барьер ожидания):

Если КоличествоПотоков > 0 И ФоновыеЗаданияСервер.ФоновыеЗаданияРазрешены() Тогда
    ТекФоновоеЗадание = ФоновыеЗадания.Выполнить(
        "ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ",
        МассивПараметров,, НаименованиеФоновогоЗадания);
    ПараметрыСохранения.МассивФоновыхЗаданий.Добавить(ТекФоновоеЗадание);

    Если ПараметрыСохранения.МассивФоновыхЗаданий.Количество() = КоличествоПотоков
        ИЛИ ТекЗначение = МаксимальноеЗначение Тогда
        ОжидатьЗавершенияТекущихФоновых(ПараметрыСохранения.МассивФоновыхЗаданий);
        ПараметрыСохранения.МассивФоновыхЗаданий.Очистить();
    КонецЕсли;
Иначе
    ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ(...); // синхронно
КонецЕсли;

Ожидание крутится, пока все задания порции не перестанут быть в состоянии Активно (ОжидатьЗавершенияТекущихФоновых / ВсеЗаданияЗавершены).
4. Простыми словами (аналогия)

Одно большое фоновое задание (БСП) держит общий процесс и прогресс. Внутри него договоры идут пачками по 3000. По каждому договору стартует маленькое задание «создать план». Одновременно живёт не больше N таких заданий: набрали N — подождали — очистили — набрали следующую порцию. В конце проверяют упавшие задания.

Это не распределение сумм/СКД, а параллельная раздача работы по договорам пулом фоновых заданий.
Вывод по коду: работает ли фоновое распределение?

Да — по коду механизм реализован и должен работать (при выполнении условий ниже).

Почему так:

  • Есть полный цикл: запуск ФЗ → накопление в пул → ожидание при достижении лимита/конца списка → очистка → следующая порция.
  • Есть явный fallback на синхронный вызов, если фон недоступен или КоличествоПотоков = 0.
  • Есть обработка аварийных заданий на последнем договоре.
  • Внешний слой БСП корректно вызывает экспортную процедуру менеджера.

Когда параллель реально включится:

  • константа МаксимальноеКоличествоПараллельныхПотоков > 0;
  • ФоновыеЗаданияСервер.ФоновыеЗаданияРазрешены() = Истина (обычно серверная ИБ, не файловая/отладка с ограничениями).

Оговорка: код выглядит рабочим по статическому разбору. Это не замена прогона на стенде. Имеет смысл проверить на тестовой базе: константа > 1, несколько договоров, в консоли фоновых заданий видно пачку параллельных СоздатьПланРегламентныхОперацийДУ, прогресс на форме доходит до 100%.
