# План версии 1.21 (по ревью 1.20)

Основа - 1.20 (УСКОРЕНО_1_20 остается как есть, в том виде, что смотрел ревьюер). Новая папка УСКОРЕНО_1_21,
версия "1.21". Решения пользователя 21.10.2026: блокировать все четыре запуска на время любого; добавить колонку
времени получения цены; сделать страницу для трейдера; активные запуски проверять по всей базе (не по пользователю)
и на заново открытой форме включать кнопки, когда задания закончились.

## Инварианты (проверяются на каждом этапе)

1. Алгоритм создания поручений, кеш цены, настройки и регламентная покупка не меняются: поручения и статусы
   портфелей совпадают с 1.16 (320 из 320), регламент - 20 из 20 и пустой второй запуск.
2. Таблица цен ведется только для запусков с формы; регламентное задание сообщений прогресса не пишет.
3. После потоков пачка отправляется ровно один раз (замер ОтправкаПачки).
4. Одновременно идет не больше одного запуска с формы - по всей базе, у всех открытых форм обработки.
5. Базовая конфигурация не меняется, правки только во внешней обработке; без е с точками, длинных тире и елочек.

## Этап 1. Один запуск за раз

- Пока идет любой из запусков (покупка, продажа, реинвестирование, продажи под блокировки), недоступны все четыре
  кнопки.
- В начале каждой из четырех команд - проверка активных заданий: если запуск идет (на этой или другой форме, у
  любого пользователя), сообщение "Дождитесь завершения текущего запуска" и выход.
- Кнопки снова доступны по завершении запуска: успешно, с ошибкой, при падении потоков.
- При открытии формы: поиск активных заданий по именам (сейчас - "ПродажиРеинвестирование", "ПродажиПодБлокировки";
  добавляются "РОСТ.ПокупкаИзФормы", "РОСТ.ПродажаИзФормы") по всей базе, без отбора по пользователю; при любом
  найденном задании недоступны все четыре кнопки.
- На форме, открытой во время чужого или прежнего запуска (оповещение о его завершении она не получит), обработчик
  ожидания раз в 5 с проверяет задания и включает кнопки, когда их не осталось.
- Решение принято явно: запуск одного трейдера закрывает кнопки остальным, чтобы проверка лимитов не шла
  параллельно по одним портфелям.
- Файлы: модуль формы.
- Приемка: во время продажи недоступны кнопки покупки, реинвестирования, блокировок и наоборот; за запуск одна
  проверка лимитов; форма, закрытая и открытая во время покупки, показывает недоступные кнопки и включает их
  сама после завершения покупки.

## Этап 2. Видимая отправка пачки после потоков

- Перед отправкой пачки строка хода "Проверка лимитов и отправка: N поручений"; отправка запускается
  обработчиком ожидания, чтобы форма успела перерисоваться.
- Файлы: модуль формы.
- Приемка: строка видна на снимке формы; пачка уходит один раз.

## Этап 3. Таблица и тексты

- Колонка "Цена получена" (часы, минуты, секунды; формат платформы "ДФ=ЧЧ:мм:сс", время сеанса): момент ответа
  стакана; для цены из кеша - время исходного запроса к бирже; у потоков - время самой свежей цены.
- Время цены - отдельное поле сообщения прогресса; возраст цены по-прежнему считается от универсальных
  миллисекунд, колонка "Возраст цены, с" остается.
- При ошибках (важность 2) итог "Завершено с ошибками, см. лог. Поручений создано: N".
- Подсказки к колонкам "Поручений по цене" (у потоков - по самой свежей цене) и "Поручений всего" (сумма по
  потокам).
- Файлы: модуль объекта (время цены в сообщении), модуль формы, форма (колонка, подсказки).
- Приемка: колонка и тексты видны на форме; время совпадает с моментом ответа заглушки стакана (журнал /calls,
  конец запроса) с допуском 1 с.

## Этап 4. Автопроверки кода

- 1c-bsl-validate: вызовы общих модулей в модулях объекта и формы.
- Ревью по каталогу дефектов (1c-code-review) измененных процедур.
- Приемка: замечаний по новому коду нет или они разобраны.

## Этап 5. Проверка на стенде (dev ФО, стакан 1 с, срок кеша 60 с)

- Тестовая сборка 1.21-тест: генератор сборок, тестовый режим и ожидание заглушки включены по умолчанию (фоновое
  задание формы создает свой экземпляр обработки). В поставку не входит.
- Автоматически на тестовой сборке: регресс обвязкой и путем формы против 1.16 (срок 60 и 0); регламентная
  покупка два запуска подряд.
- Вручную на форме (тестовая сборка): покупка (впервые руками), продажа, реинвестирование, продажи под
  блокировки; попытка второго запуска во время первого; закрыть форму во время покупки и открыть снова; падение
  потоков; запуск с ошибками в данных.
- Поставка 1.21 (без тестового режима): на dev до конца не прогоняется - без тестового режима она обращается к
  рабочему адаптеру, которого на стенде нет. Для нее: регистрация на dev (модуль объекта компилируется), открытие
  формы (модуль формы компилируется), построчное сравнение с тестовой сборкой - отличия только в тестовых вставках
  (имитация стакана, процедура отправки пачки для стенда, режим по умолчанию, версия).
- Приемка: инварианты 1-4 выполнены, все ручные сценарии проходят, сравнение поставки и тестовой сборки без
  отличий кроме тестовых вставок.

## Этап 6. Документы

- УСКОРЕНО_1_21/Описание версии 1.21.md.
- Тестирование/1_21: протокол HTML и отчет md (по образцу 1.20), видео: покупка, запрет второго запуска, колонка
  "Цена получена".
- Документация/: страница для трейдера (HTML) - что показывает таблица "Цены в работе", какие кнопки ее
  заполняют, что значат колонки и строка хода, почему кнопки недоступны во время запуска (в том числе запуск
  другого трейдера), что делать при сообщении об ошибке. Без путей, технических имен и упоминания инструментов
  разработки.
