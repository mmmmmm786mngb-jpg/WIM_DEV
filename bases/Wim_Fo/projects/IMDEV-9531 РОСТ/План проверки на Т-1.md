# План проверки 1.21 на Т-1 (копия ПРОД)

Цель: на Т-1 руками прогнать реинвестирование и продажи под блокировки версии 1.21 на 100-200+ портфелях, на тех
же портфелях, что были в реальных запусках на ПРОД. Поручения на биржу не уходят, цена стакана имитируется с паузой 1 с.

## Почему сейчас список пустой

Тестовый режим обработки берет позиции не на сегодня, а на прошлый день:

| Закладка | Дата позиции в тестовом режиме | Что еще нужно для попадания в список |
|---|---|---|
| Реинвестирование | вчера (календарный день, в понедельник - воскресенье) | облигация с выплатой купона ровно в дату купона на форме; статус портфеля не из исключенных (расторжение, продажа, вывод); нет проведенных поручений по этой облигации сегодня |
| Продажи под блокировки | прошлый торговый день | позиция LQDT; остаток прогноза по неторговым поручениям "Вывод" на конец сегодня меньше 0; статус не из исключенных; нет поручений по LQDT сегодня |

Вероятные причины пустого списка на Т-1 (подтвердить диагностикой, этап 1):

- реинвестирование 18.09: в копии нет фактической позиции на вчера, либо портфели уже не держат облигацию с купоном
  18.09, либо у портфелей статусы из исключенных;
- блокировки: поручения на вывод создаются на ПРОД днем, в ночной копии поручений на вывод "сегодня" нет, поэтому
  нет и отрицательного прогноза.

## Решение: служебная обработка "Т-1: данные для РОСТ" (открывается через Файл - Открыть)

Отдельная внешняя обработка, в поставку не входит, в ПРОД не попадает. Все кнопки, которые пишут данные, работают
только после проверки базы (этап 0) и сохраняют прежние значения для отката.

### Этап 0. Защита от запуска не на той базе

- На форме видна строка соединения базы. Кнопки записи доступны, только если в ней есть имя базы Т-1, введенное
  пользователем в поле подтверждения (имя базы ПРОД не пропускается никогда).
- Перед записью - вопрос с числом портфелей и документов, которые будут изменены.

### Этап 1. Диагностика (только чтение)

Кнопка "Почему пусто" для каждой закладки показывает счетчики по шагам отбора того же запроса, что в обработке:

- реинвестирование: облигаций с купоном в дату; портфелей с фактической позицией на дату позиции; последняя дата,
  на которую фактическая позиция в копии есть; портфелей с облигацией купона; отсеяно по статусу; отсеяно по
  поручениям сегодня;
- блокировки: портфелей с LQDT на прошлый торговый день; с отрицательным прогнозом вывода; отсеяно по статусу и
  по поручениям сегодня;
- исторические запуски: сколько поручений реинвестирования было 18.09 и сколько продаж LQDT под блокировки по
  дням за последние 2 месяца (по поручениям автора заявок обработки) - чтобы выбрать день с 200+ портфелями.

Результат диагностики вы присылаете мне, по нему уточняется этап 2.

### Этап 2. "Вернуть реинвестирование на дату купона"

Параметры: дата купона (18.09), число портфелей (по умолчанию 200 - один пакет).

1. Портфели берутся из реальных поручений реинвестирования за эту дату: покупки облигации с купоном в эту дату,
   созданные автором заявок обработки РОСТ.
2. Для них фактическая позиция на дату купона (как ее видела обработка на ПРОД 18.09: облигация и деньги)
   копируется на дату позиции тестового режима (вчера). Суммы реинвестирования получаются те же, что 18.09.
3. Статус портфеля ставится "Окончание обработки" (не из исключенных), прежний статус и дата статуса сохраняются.
4. Поручения по облигации сегодня не создаются, поэтому флажок "Не показывать портфели с поручениями" можно оставить.

Для повторного прогона (например, срок кеша 0 и 60) кнопку нажимают снова: она снимает поручения, созданные
обработкой РОСТ сегодня по этим портфелям (пометка удаления), и возвращает статус.

### Этап 3. "Вернуть продажи под блокировки за день"

Параметры: день с реальными продажами LQDT под блокировки (из диагностики), число портфелей (по умолчанию 200).

1. Портфели берутся из реальных поручений продажи LQDT, созданных обработкой РОСТ в этот день.
2. Фактическая позиция этих портфелей на прошлый торговый день перед тем днем (LQDT и деньги) копируется на прошлый
   торговый день от сегодня.
3. Для каждого портфеля создается и проводится неторговое поручение "Вывод" сегодняшним днем на ту же сумму, что
   реальное поручение на вывод того дня (комментарий "IMDEV-9531 Т-1 тест"). Получается тот же отрицательный
   прогноз и та же сумма продажи.
4. Статус - "Окончание обработки", прежний сохраняется.

### Этап 4. "Откатить"

Пометка удаления созданных поручений на вывод и поручений РОСТ сегодняшнего дня по подготовленным портфелям,
восстановление сохраненных фактических позиций и статусов. Сохранение - в файл рядом с обработкой (или в хранилище
настроек), чтобы откат работал и после закрытия формы.

### Этап 5. Сборка обработки РОСТ "1.21-т1" (из предыдущего обсуждения)

- тестовый режим включен в теле модуля (цена - котировка из регистра, к адаптеру биржи обращений нет);
- пауза 1 с на запрос цены без заглушки: ожидание текущего фонового задания с таймаутом 1 с;
- проверка лимитов без отправки: ОтправитьПослеПроверки = Ложь (типовая проверка лимитов идет целиком, на биржу не
  отправляется; статусы акцепта поручений типовая проверка меняет);
- версия "1.21-т1".

### Этап 5а. Сборка обработки РОСТ "1.16-т1" для сравнения

Та же обвязка, что у "1.21-т1", поверх исходной 1.16 (ОРИГИНАЛ_1_16, она же сейчас на ПРОД): тестовый режим в
теле модуля, пауза 1 с перед каждой ценой (в 1.16 кеша нет - пауза на каждое поручение, как запрос стакана на ПРОД),
проверка лимитов без отправки. Остальной код 1.16 не меняется, в том числе многократная отправка пачки после потоков
(ошибка 1.16, исправлена в 1.20): в 1.16 проверка лимитов пройдет несколько раз, это и есть поведение ПРОД.

Обе сборки загружаются в один и тот же элемент РОСТ на Т-1 командой "Загрузить из файла": настройки элемента
(статусы, актив LQDT, почта) сохраняются. После загрузки 1.21 в "Настройки" поставить срок кеша 60 (в 1.16 этой
настройки нет).

### Этап 5б. Фиксация и сравнение прогонов (в служебной обработке)

- "Зафиксировать прогон" (параметр - метка, например "1.16" или "1.21"): сохраняет поручения РОСТ сегодняшнего дня по
  подготовленным портфелям (портфель, бумага, направление, количество, цена, сумма, проведение) и время запуска по
  замерам (начало и конец, шаги ЦенаИзСтакана, ЦенаИзКеша, ПроверкаИОтправка, ОтправкаПачки).
- "Сброс для повторного прогона": пометка удаления поручений РОСТ сегодняшнего дня по подготовленным портфелям
  (проведение отменяется, движения и прогноз денег уходят), возврат статуса "Окончание обработки". Позиции и
  поручения "Вывод" подготовки остаются - второй прогон идет на тех же данных.
- "Сравнить прогоны": таблица по портфелям - совпало, расхождение (какое поле), есть только в одном прогоне; итог
  "N из N совпали" и время 1.16 против 1.21 по каждой операции.

Цена в тестовом режиме - котировка из регистра, одинаковая в обоих прогонах, поэтому поручения должны совпасть
полностью (как 320 из 320 на dev).

### Этап 6. Проверка на dev перед передачей

- Служебную обработку, "1.16-т1" и "1.21-т1" прогнать на dev ФО полным циклом: диагностика, подготовка, 1.16,
  фиксация, сброс, 1.21, фиксация, сравнение, полный откат. Убедиться, что поручения не отправлены и пауза 1 с есть
  (замер ЦенаИзСтакана около 1 с).
- Передать: три обработки и короткую инструкцию по шагам на Т-1.

## Порядок на Т-1

1. Открыть служебную обработку (Файл - Открыть), диагностика - прислать мне результат.
2. Подготовка: "Вернуть реинвестирование" (18.09, 200 портфелей), "Вернуть продажи под блокировки" (день по
   диагностике, 200 портфелей).
3. Загрузить в элемент РОСТ "1.16-т1". Реинвестирование: обновить список, отметить 200, "Создать поручения в
   потоке". Блокировки: так же. Дождаться завершения.
4. "Зафиксировать прогон" с меткой 1.16, затем "Сброс для повторного прогона".
5. Загрузить "1.21-т1", срок кеша 60. Повторить шаг 3.
6. "Зафиксировать прогон" с меткой 1.21, "Сравнить прогоны".
7. "Откатить" - вернуть Т-1 в исходное состояние (или не откатывать: Т-1 перезаписывается ночной копией).

Все шаги - в один день: дата позиции тестового режима считается от сегодняшней даты.
