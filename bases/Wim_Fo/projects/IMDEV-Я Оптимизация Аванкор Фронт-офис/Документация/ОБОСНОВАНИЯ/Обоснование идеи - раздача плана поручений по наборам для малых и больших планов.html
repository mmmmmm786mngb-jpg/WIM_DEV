Почему план проверки поручений можно раздавать заданиям с учетом наборов данных
Одна причина, два режима: малый план раздается частями наборов, большой режется штатными кусками по порядку наборов

Шаг "Обработка проверки" делит план между фоновыми заданиями, и каждое задание строит временную таблицу для каждого своего набора данных. Штатная нарезка берет строки подряд и не смотрит на наборы, поэтому одни и те же таблицы строятся во многих заданиях. Расширение меняет только номер задания в строке плана - так, чтобы задание получало строки одного-двух наборов. Для малого и большого плана это делается по-разному, доказательство корректности у них общее.

Словесное обоснование

Что делает штатный код. РаботаСЛимитами.ПланОбработкиПроверки проходит строки плана и пишет в каждую НомерИсполнителя: по КоличествоНаЗадание + 1 строк подряд на номер, где КоличествоНаЗадание - строк на поток, но не меньше 10. На каждый номер запускается фоновое задание, и оно читает только свои строки (ПланПроверкиИсполнителя(Вместилище, Параметры.Данные[0])).

Где теряется время. Для каждого своего набора задание один раз строит таблицу набора (ДобавитьВТ_ТаблицаНабораДанных): позиции всех портфелей проверки по набору, статика активов, портфелей, мест хранения, контрагентов, рейтинги. Строки плана к этому моменту идут не по наборам, поэтому кусок подряд идущих строк задевает несколько наборов, и один набор строится во многих заданиях.

Малый план (строк на поток меньше 50, выборка из нескольких поручений). Кусок - два десятка строк, а построение таблицы - секунды. Наборы режутся на части до 50 строк, части раскладываются по заданиям от крупных к мелким в наименее загруженное. Строк у задания становится больше, но таблиц оно строит одну-две. На Т-1: 28 построений - 11, проверка 2 поручений 31,5 с - 22,6 с.

Большой план (строк на поток от 50, выборка из десятков и сотен поручений). Кусок в тысячи строк содержит строки всех наборов, и каждое задание строит полные таблицы всех наборов. Размер куска остается штатным, меняется только, какие строки в него попадают: номера выдаются так, как если бы строки шли набор за набором. Кусок задевает один набор, на стыке - соседние. Для 500 поручений, 12 потоков и 8 наборов: 96 построений - 19, у задания 1-3 вместо 8.

Почему результат тот же в обоих режимах. Меняется только колонка НомерИсполнителя, которую конфигурация читает в одном месте - отбором строк задания. Каждая строка получает ровно один номер, номера идут от 0 без пропусков, их не больше числа потоков. Таблица набора строится по дате, реквизитам набора, биржам и вместилищу и не зависит от того, какое задание ее строит. Состав плана, порядок строк, лимиты, пороги, расчет зон и запись результатов не меняются.

Где не применяется. Регламентный постконтроль (в плане нет поручений), один поток, один набор - номера штатные.

Раздел 1

Причина: три факта из кода и замер Т-1

1. Таблица - одна на задание и набор

Задание строит таблицу, если ее нет в его менеджере временных таблиц: Менеджер.Таблицы.Найти("ВТ_ТаблицаНабораДанных" + КлючНабора). При смене набора удаляются только таблицы без ключа набора. Построений в задании столько, сколько разных наборов в его строках.

2. Таблица - по всем портфелям проверки

Отбор КэшВмПозиция: НаборДанных = &НаборДанных И Вместилище = &Вместилище. Вместилище одно на проверку, поэтому таблица растет с размером выборки поручений, а не с куском задания.

3. Строки идут не по наборам

ПланПроверки упорядочивает строки по набору и лимиту, но ОтобранныеСтрокиПланаПроверки пропускает их через временную таблицу без упорядочивания. На Т-1 порядок не сохранился:

Два режима: какой когда

УсловиеРежимПочему так
Нет поручений в плане, один поток или один наборШтатноПовторных построений нет или правка не относится к предконтролю.

Порог 50 строк - FO_LimitCheckOpt_МинимумСтрокЧастиНабора(). На малом плане режим частей дает меньше построений, чем режим подряд (на Т-1 11 против предела 18), на большом - режим подряд не меняет нагрузку заданий.

Условный пример: 500 поручений по ~115 строк, 57 250 строк плана, 12 потоков, 8 наборов в пропорциях Т-1. Штатный кусок - 4 772 строки.

Путь самого медленного задания, которого ждет главный сеанс: было 8 x Построение + 4 772 x Проверка строки   стало 1-3 x Построение + 4 772 x Проверка строки

Раздел 6

Обоснование по шагам

Утв.
1

Меняется только номер задания

Вставки стоят после штатного отбора строк и не добавляют, не удаляют и не переставляют строк. АвтоНомер, вместилище, лимит, портфель, группа, поручение, установка лимитов - штатные.

Утв.
2

Номер задания нигде больше не участвует

В конфигурации НомерИсполнителя читается одним отбором: Т.НомерИсполнителя = &НомерИсполнителя в КэшВмПланПроверки.ПланПроверкиИсполнителя. Расчет зон, пороги и запись результатов его не видят.

Утв.
3

Каждая строка проверяется ровно один раз

части каждая строка набора попадает в одну часть, каждая часть - в одно задание; первые задания получают по части, пока все пустые, поэтому пустых номеров нет. подряд позиции строк в последовательности по наборам - 0..N-1 без повторов, номер - Цел(позиция / РазмерКуска), номера 0..Цел((N-1) / РазмерКуска) все заняты.

Утв.
4

Заданий не больше, чем потоков

Задание берет только первый номер (Параметры.Данные[0]). части заданий Мин(потоков, частей). подряд кусок штатный: КоличествоНаЗадание + 1 больше "строк / потоков", поэтому кусков не больше потоков. Штатный цикл иногда добавляет лишний пустой номер, когда строки делятся на куски нацело; здесь его нет.

Утв.
5

Данные набора одинаковы в любом задании

Таблица набора строится по Секрет (дата, реквизиты набора, биржи котировок, вместилище) и не видит строк задания. Отбор по портфелям при проверке собирается из тех же строк, что и раньше.

Утв.
6

Построений меньше

части в задании одна-две части, наборов столько же. подряд в последовательности по наборам каждый набор - один отрезок, кусок пересекает отрезки подряд, каждая граница наборов добавляет не больше одного построения: всего не больше "заданий + наборов - 1".

Вывод
=

Результат тот же, путь задания короче

Каждая строка плана проверяется один раз, с теми же параметрами и по той же таблице набора. Сокращается только число построений таблиц наборов в заданиях.
