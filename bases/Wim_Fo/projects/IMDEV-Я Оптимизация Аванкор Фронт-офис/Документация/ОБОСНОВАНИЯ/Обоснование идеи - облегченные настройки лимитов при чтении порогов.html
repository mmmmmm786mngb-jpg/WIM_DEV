Почему задание чтения порогов может читать облегченные настройки лимитов
Тот же класс лимита у всех лимитов и те же таблицы порогов там, где они нужны, без распаковки полных настроек каждого лимита

Шаг "Пороги" запускает два фоновых задания чтения сведений о порогах. Каждое задание сначала читает полные настройки своих лимитов из кэша настроек и распаковывает их из хранилища значения, хотя дальше из них берется только класс лимита, а таблицы порогов - лишь у лимитов класса с расширенным подтверждением. На Т-1 это 3,6 с из 3,9 с задания, и главный сеанс ждет его 4 с за пределами замера шага. Расширение читает облегченные настройки, в которых класс лимита есть, и полные - только там, где они действительно нужны.

Кратко

Словесное обоснование

Что делает штатный код. Задание Исполнители.ПроверкаИОтправка_ЧтениеСведенийОПорогах получает структурные лимиты своей части, читает их полные настройки Справочники.Лимиты.НастройкиИзКэша(Лимиты) - реквизит КэшНастроекЛимитов.Настройки, хранилище значения с большими структурами и таблицами - и передает их в РегистрыСведений.ПорогиЛимитов.СведенияОПорогах. Результат записывается в КэшВмПороги.

Почему это медленно. На Т-1 (2 поручения, 55 структурных лимитов, 2 задания) одно задание из своих 3,9 с потратило 3,64 с на чтение полных настроек: запрос 1,19 с и распаковка хранилища значения 2,37 с, около 85 мс на лимит. Сам запрос сведений о порогах занял 0,15 с. Главный сеанс закрывает замер "Пороги" до ожидания этих заданий, поэтому 4,07 с ожидания не видны ни в одном замере шага, но входят в общее время проверки. На УАТ (44 поручения) такое ожидание - 4,65 с.

Что из настроек нужно дальше. СведенияОПорогах читает настройки лимита в одном месте - НовыеТаблицыНастроекПорогов: берет КлассЛимита, и только если класс требует расширенного подтверждения (КлассыЛимитов.РасширенноеПодтверждение), - таблицы ПорогиЛимита и РеквизитыНастроекПорогов. Если классы лимитов выключены, настройки не читаются вовсе. Еще задание пишет в журнал число настроек.

Что делает расширение. Перехват задания заменяет одну строку: вместо полных настроек всех лимитов - облегченные (НастройкиИзКэша(Лимиты, Истина), реквизит НастройкиЭкспресс), и полные - только для лимитов, у которых класс требует расширенного подтверждения, или у которых облегченных настроек нет. Остальной код задания и СведенияОПорогах не меняются.

Почему результат тот же. Облегченные и полные настройки записывает одна процедура Справочники.Лимиты.СохранитьНастройкиЛимита из одних и тех же полных настроек, и КлассЛимита входит в облегченные. Значит, у каждого лимита класс тот же; у лимитов расширенного подтверждения таблицы порогов берутся из полных настроек, как раньше; лимит без облегченных настроек идет штатным путем. Каждый лимит по-прежнему получает свою запись в соответствии настроек, поэтому и число настроек в журнале то же.

Подтверждение. На базе разработчика у всех 139 структурных лимитов класс в облегченных настройках совпал с полным. Предконтроль 1, 2, 10, 50 поручений и постконтроль 75 020 строк - 0 расхождений с прогонами без расширения; с включенными классами и расширенным подтверждением у класса Compliance (59 лимитов по полным настройкам, 80 по облегченным) - тоже 0.

Раздел 4

Обоснование по шагам

Утв.
1

Настройки нужны только одной функции

В задании настройки уходят в Указания.НастройкиЛимитов, а оттуда - в СведенияОПорогах. В модуле ПорогиЛимитов их читает только НовыеТаблицыНастроекПорогов; вставки перехвата СведенияОПорогах из оптимизации 2 их не касаются. Результат задания - записи КэшВмПороги, настройки в результат не попадают.

Утв.
2

Класс лимита одинаков в обеих настройках

Облегченные настройки строятся в СохранитьНастройкиЛимита копированием ключей из полных (ЗаполнитьЗначенияСвойств), в том числе КлассЛимита, и записываются в ту же запись регистра КэшНастроекЛимитов одновременно с полными.

Утв.
3

Таблицы порогов - у тех же лимитов, что раньше

Штатная функция берет таблицы у лимитов, класс которых требует расширенного подтверждения. Расширение для таких лимитов читает полные настройки - причем независимо от того, включены ли классы лимитов, то есть с запасом.

Утв.
4

Лимит без облегченных настроек идет штатным путем

Если облегченных настроек нет или в них нет КлассЛимита, лимит получает полные настройки; если нет и их - штатный цикл вызывает НастройкиВнутреннейПроверкиЛимита_Расчет, как без расширения.

Вывод
=

Те же сведения о порогах, быстрее

НовыеТаблицыНастроекПорогов получает для каждого лимита тот же класс и те же таблицы там, где их использует, поэтому сведения о порогах в КэшВмПороги и дальше зоны проверки не меняются. Не читаются только полные настройки лимитов, которым они не нужны.

Прямая проверка предпосылок

Серверная проверка по всем 139 внутренним структурным лимитам: класс в облегченных настройках совпал с полным у 139, расходится у 0, облегченных настроек нет у 0. По правилу расширения полные получат 59 лимитов класса с расширенным подтверждением, у всех 59 в полных настройках есть таблицы порогов.
