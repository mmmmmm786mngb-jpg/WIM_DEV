Код: конфигурация "Аванкор: Фронт-офис" 1.4.9.5, расширение FO_LimitCheckOpt (ранее FO_PortionIndex)

Почему сборку портфелей порции можно вести через индекс
Тот же список портфелей в том же порядке, но без повторного просмотра всего списка

В задании "Обработка проверки" для каждой порции плана собирается список уникальных портфелей. Штатный код делает это вызовом БСП ДополнитьМассив(..., Истина) на каждой строке порции, и этот вызов каждый раз заново просматривает весь уже собранный список. Расширение ведет один индекс на порцию и проверяет каждый портфель одним обращением. Ниже показано, почему результат совпадает с штатным до элемента и до порядка.

Словесное обоснование

Что делает штатный код. Задание "Обработка проверки" идет по порциям плана. Для каждой порции заводится пустой массив ПортфелиПорции, затем в цикле по строкам порции к нему добавляются портфели строки: один портфель, если строка по портфелю, или все портфели группы, если строка по группе. Добавление идет вызовом ДополнитьМассив(ПортфелиПорции, ПортфелиГруппы, Истина) - флаг Истина означает "добавлять только те значения, которых еще нет".

Почему это медленно. Процедура БСП ОбщегоНазначенияКлиентСервер.ДополнитьМассив с флагом уникальности при каждом вызове создает новое соответствие и заносит в него все элементы приемника, то есть весь уже собранный список портфелей порции. Приемник растет до размера порции, поэтому на порцию из n строк работа растет как n x n / 2. В рознице порция - около 25 тысяч портфелей: замер насчитал 1,97 млрд проходов и 12 606 секунд из 12 609 на эту одну строку кода.

Что делает расширение. Рядом с массивом ПортфелиПорции заводится соответствие ИндексПортфелейПорции - создается там же, где массив, и так же пустым. Для каждого портфеля строки проверяется индекс: если портфеля в нем нет, портфель добавляется и в массив, и в индекс. Это ровно те действия, которые делает ДополнитьМассив, но без пересборки соответствия из всего приемника на каждом вызове.

Почему результат тот же. Штатная процедура на каждом вызове строит соответствие "все, что уже есть в приемнике", и по нему решает, добавлять ли значение. Индекс расширения в каждый момент содержит ровно те же значения: он создается пустым вместе с пустым массивом, и каждое значение попадает в массив и в индекс одновременно. Других изменений массива внутри цикла нет. Значит, на каждой проверке ответ "уже есть / еще нет" совпадает со штатным, а значит совпадают и добавленные значения, и их порядок - порядок первого появления.

Что не меняется. Процедура БСП ДополнитьМассив не трогается, другие ее вызовы работают как раньше. Дальше массив ПортфелиПорции используется так же - как параметр запроса порции и как СписокПортфелей для расчета лимита. Расчет зон, порогов, базисов и запись результатов не меняются.

Подтверждение. На базе разработчика краткий итог проверки с правкой и без нее совпал по всем полям на 75-276 тысячах строк. На рознице Т-1 проверка с правкой заняла 0 ч 18 мин против 5 ч 58 мин без нее на той же базе, при том же числе строк плана 553 432.

Раздел 3

Обоснование по шагам

Утв.
1

Массив и индекс начинают пустыми и вместе

Индекс создается сразу после ПортфелиПорции = Новый Массив(), внутри цикла по порциям. Для каждой новой порции оба создаются заново, пустыми. Штатная процедура при первом вызове тоже строит соответствие по пустому приемнику.

Утв.
2

Массив меняется только в этом месте

Внутри цикла по строкам порции в ПортфелиПорции добавляет только эта вставка; удалений и других добавлений нет. Каждое значение добавляется в массив и в индекс одной и той же веткой. Значит, перед каждой проверкой ключи индекса - ровно элементы массива (инвариант).

Утв.
3

Каждое решение "добавлять / нет" совпадает со штатным

Штатная процедура решает по соответствию "все элементы приемника + уже добавленные на этом вызове". По инварианту индекс содержит то же самое. Условие одно: значения в соответствии нет (= Неопределено). Сравнение ключей соответствия одинаковое - по ссылке на портфель.

Утв.
4

Порядок тот же

Обе версии обходят строки порции в одном порядке и внутри строки - портфели источника в одном порядке, добавляя в конец массива при первом появлении. Итоговый массив совпадает поэлементно, включая порядок.

Вывод
=

Потребители получают тот же массив

После цикла массив уходит в параметр запроса Портфели_b481 и в СписокПортфелей расчета лимита - без изменений. Меняется только число операций: вместо n x n / 2 проходов по списку - n обращений к индексу.

Раздел 5

Проверка на данных

Замер до правки

Розница, замер производительности регламента: строка ДополнитьМассив - 12 606 с из 12 609 с, 1,97 млрд проходов по приемнику. Расчет n x n / 2 по размеру порций дает 2,2 млрд - сходится.

Замер после правки

Розница Т-1: 553 432 обращения к индексу, около 5 с. Вся проверка - 0 ч 18 мин против 5 ч 58 мин на той же базе без правки; число строк плана то же.

Сверка результата

База разработчика: краткий итог по каждой паре "лимит - фокус" с правкой и без - 0 расхождений на 177 000, 275 900 и 75 020 строках.
