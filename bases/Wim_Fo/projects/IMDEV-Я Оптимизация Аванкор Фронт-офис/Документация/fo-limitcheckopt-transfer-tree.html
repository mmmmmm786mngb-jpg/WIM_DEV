Дерево изменений расширения FO_LimitCheckOpt

Базовая конфигурация "Аванкор: Фронт-офис" 1.4.9.5. Расширение FO_LimitCheckOpt (синоним "Оптимизация проверки лимитов", назначение Patch, префикс FO_LimitCheckOpt_). Новых объектов метаданных нет: три заимствованных объекта, правки только в модулях.

В типовую копировать тело правок. Аннотацию &ИзменениеИКонтроль не копировать. Маркеры #Вставка, #КонецВставки, #Удаление, #КонецУдаления не переносить: вставленный текст оставить, удаленный текст убрать из штатной процедуры. Префикс с имен перехватчиков снять и править штатные процедуры на месте. Новые функции уже без префикса, их копировать целиком в тот же модуль.

  • идея 1 Индекс портфелей порции вместо ДополнитьМассив

    Задание "Обработка проверки" собирает уникальные портфели порции одним соответствием на порцию, а не вызовом ДополнитьМассив(..., Истина) на каждой строке. Состав и порядок массива ПортфелиПорции те же. Процедура БСП ДополнитьМассив не меняется, другие ее вызовы в модуле остаются. Обоснование

    • ОбщийМодуль.Исполнители - заимствован, метаданные не менять
      • Модуль
        • изменение ПроверкаИОтправка_ОбработкаПроверки - в расширении имя FO_LimitCheckOpt_ПроверкаИОтправка_ОбработкаПроверки. В типовой править штатную функцию. Цикл по строкам порции, область портфелей и групп.
          • добавление сразу после ПортфелиПорции = Новый Массив(): ИндексПортфелейПорции = Новый Соответствие
          • удаление строка ДополнитьМассив(ПортфелиПорции, ПортфелиГруппы, Истина)
          • добавление на ее место цикл по ПортфелиГруппы: если портфеля нет в индексе, добавить в массив и в индекс
  • идея 2 Сведения о порогах только для пар плана

    Первый запрос пакета ТекстЗапросаПолученияПорогов строит пары "лимит - портфель" из КэшВмПланПроверки по вместилищу плюс пустой портфель каждого лимита. Остальной пакет не меняется. Если плана нет или штатный текст первого запроса изменился, выполняется штатный запрос. Обоснование

    • РегистрСведений.ПорогиЛимитов - заимствован, состав регистра не менять
      • МодульМенеджера
        • изменение СведенияОПорогах - в расширении FO_LimitCheckOpt_СведенияОПорогах. Меняется только назначение текста запроса.
          • удаление Запрос.Текст = ТекстЗапросаПолученияПорогов()
          • добавление Запрос.Текст = ТекстЗапросаПолученияПороговПоПлану(Вместилище, Параметры.Лимиты) и параметр Вместилище
        • добавление ТекстЗапросаПолученияПороговПоПлану - область СведенияОПорогахПоПарамПлана. Подменяет первый запрос пакета либо возвращает штатный текст.
        • добавление ЕстьПланПроверки - есть ли строки КэшВмПланПроверки по вместилищу и лимитам задания.
        • добавление ТекстПарЛимитПортфельПоПлану - текст временной таблицы ВТ_ПортфелиЛимиты: пары плана и пустой портфель лимита.
  • идея 3 Нарезка плана проверки поручений по заданиям

    Меняется только номер задания у строки плана с поручением. Три правила ниже. Перехват и диспетчер общие, их переносить один раз. Регламент без поручений и один поток остаются на штатной нумерации. Обоснование

    • Общее для трех подидей

      Один перехват вызывает диспетчер. Диспетчер выбирает правило частей или подряд и отдельно готовит круг для лимитов по алгоритму.

      • ОбщийМодуль.РаботаСЛимитами - заимствован, метаданные не менять
        • Модуль
          • изменение ПланОбработкиПроверки - в расширении FO_LimitCheckOpt_ПланОбработкиПроверки. Три вставки, штатные строки не удаляются.
            • добавление после отбора стандартных лимитов: вызов НомераИсполнителейПоНаборам
            • добавление в цикле по строкам плана, после штатного Строка.НомерИсполнителя = НомерИсполнителя: если раскладка есть, подставить НомерИсполнителяСтроки
            • добавление после цикла: если раскладка есть, Результат.НомераИсполнителей взять из нее
          • добавление НомераИсполнителейПоНаборам - область НарезкаПланаПроверкиПоЗаданиям. Диспетчер: штатно, части, подряд, подготовка круга алгоритмов.
          • добавление НомерИсполнителяСтроки - выдает номер строке: ветка круга, ветка подряд, ветка частей.
          • добавление МинимумСтрокЧастиНабора - порог 50 строк. Ниже порога режим частей, иначе подряд.
          • добавление ОтобратьЛимитыПоАлгоритму - лимиты со способом настройки "по алгоритму". Нужна диспетчеру и кругу.
    • подидея 3.1 Малый план: части наборов

      Когда строк на поток меньше 50, набор режется на части не больше 50 строк. Части раздаются от крупных к мелким в наименее загруженное задание. Условие выбора - в НомераИсполнителейПоНаборам, ветка Иначе.

      • ОбщийМодуль.РаботаСЛимитами
        • Модуль
          • добавление НомераПоЧастямНаборов - единственная процедура только этой подидеи. Номер строки потом берет НомерИсполнителяСтроки при РазмерКуска = 0.
    • подидея 3.2 Большой план: подряд по наборам

      Когда строк на поток 50 и больше, строки нумеруются так, как если бы шли набор за набором, и режутся штатными кусками. Условие выбора - в НомераИсполнителейПоНаборам, ветка ДоляПотока >= МинимумСтрокЧастиНабора().

      • ОбщийМодуль.РаботаСЛимитами
        • Модуль
          • добавление НомераПодрядПоНаборам - единственная процедура только этой подидеи. Номер строки берет НомерИсполнителяСтроки при РазмерКуска > 0.
    • подидея 3.3 Лимиты по алгоритму: по кругу

      Строки лимитов со способом настройки "по алгоритму" не входят в наборы и раздаются по кругу, начиная с последнего задания. Отдельной процедуры нет: это ветки уже перечисленных общих функций.

      • ОбщийМодуль.РаботаСЛимитами
        • Модуль
          • изменение НомераИсполнителейПоНаборам - внутри добавленной функции: ОтобратьЛимитыПоАлгоритму, строки алгоритмов убираются из наборов, ИсполнителейАлгоритмов и добивка номеров. Второй раз функцию не копировать.
          • изменение НомерИсполнителяСтроки - ветка ЛимитыПоАлгоритму: номер ИсполнителейАлгоритмов - 1 - (ВыданоАлгоритмов % ИсполнителейАлгоритмов). Второй раз функцию не копировать.
          • добавление ОтобратьЛимитыПоАлгоритму - запрос к Справочник.Лимиты, способ настройки "по алгоритму". Та же функция, что в общем перехвате.
  • идея 4 Облегченные настройки лимитов при чтении порогов

    Задание чтения сведений о порогах берет облегченные настройки (НастройкиИзКэша(Лимиты, Истина)). Полные настройки читаются только у лимитов без класса в облегченных настройках и у лимитов класса с расширенным подтверждением. СведенияОПорогах и НовыеТаблицыНастроекПорогов не меняются. Обоснование

    • ОбщийМодуль.Исполнители - тот же модуль, что в идее 1
      • Модуль
        • изменение ПроверкаИОтправка_ЧтениеСведенийОПорогах - в расширении FO_LimitCheckOpt_ПроверкаИОтправка_ЧтениеСведенийОПорогах. Одна замена вызова.
          • удаление НастройкиИзКэша = Справочники.Лимиты.НастройкиИзКэша(Лимиты)
          • добавление НастройкиИзКэша = НастройкиЛимитовДляЧтенияПорогов(Лимиты)
        • добавление НастройкиЛимитовДляЧтенияПорогов - область НастройкиЛимитовДляЧтенияПорогов. Облегченные для всех, полные для нужных.
        • добавление ЕстьКлассЛимитаВНастройках - в облегченных настройках есть свойство КлассЛимита.
        • добавление КлассыРасширенногоПодтверждения - запрос к Справочник.КлассыЛимитов по признаку РасширенноеПодтверждение.

Не переносить

  • Роль FO_LimitCheckOpt_ОсновнаяРоль и язык Русский. Это оболочка расширения.
  • Аннотации расширения и префиксы перехватчиков.
  • ОбщегоНазначенияКлиентСервер.ДополнитьМассив. Другие вызовы в Исполнители остаются.
  • Метаданные регистров ПорогиЛимитов, КэшВмПланПроверки, КэшВмПороги, справочников лимитов и классов лимитов.
  • Распорядители.ПроверкаИОтправка, ПроверкаЛимитов.КэшВмКратко, Справочники.Лимиты.НастройкиИзКэша и СохранитьНастройкиЛимита. Их вызывают как есть.

Порядок в коде проверки

  1. Идея 3. РаботаСЛимитами.ПланОбработкиПроверки пишет план с новыми номерами заданий.
  2. Идеи 2 и 4. Исполнители.ПроверкаИОтправка_ЧтениеСведенийОПорогах читает настройки, затем ПорогиЛимитов.СведенияОПорогах строит пороги по парам плана.
  3. Идея 1. Исполнители.ПроверкаИОтправка_ОбработкаПроверки собирает портфели порции через индекс.

Идеи независимы по результату проверки: каждую можно перенести отдельно. Идея 2 читает план, который пишет штатный ПланОбработкиПроверки и с идеей 3 тоже.
