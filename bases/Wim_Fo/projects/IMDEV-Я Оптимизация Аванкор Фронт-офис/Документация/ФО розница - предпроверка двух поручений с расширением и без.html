Что получилось

Сравнение: два прогона кнопки "Проверить" на блоттере по одним и тем же двум поручениям, на одной базе и одном сервере: сначала без расширения FO_LimitCheckOpt, затем с ним. План проверки одинаковый - 72 строки. Проверка заняла 40,8 с и 25,5 с.

Какие идеи сработали: облегченные настройки лимитов при чтении порогов - чтение настроек 5,6 с - 0,3 с, задание порогов 6,0 с - 0,8 с; нарезка плана по правилу малого плана - таблицы наборов данных строятся 3 раза вместо 6, 7,5 с вместо 18,2 с работы заданий. Вместе они сократили проверку примерно на 5 с.

Какие идеи здесь не проявились - и так и должно быть: индекс портфелей порции (порции из нескольких портфелей, сборка занимала тысячные доли секунды) и сведения о порогах только для пар плана (в плане двух поручений все 10 пар нужны). Их эффект - на ночном регламенте.

Остальная разница - в шаге "Чтение наборов данных" (16,3 с и 5,9 с). Код этого шага расширение не меняет, и к оптимизациям эта разница не относится.

Раздел 1

Идеи из обоснований и что показал прогон

сработалаОблегченные настройки лимитов при чтении порогов

Задание порогов не распаковывает полные настройки каждого лимита, а берет класс лимита из облегченных настроек.

Без расширениячтение настроек лимитов 5,63 с; задания порогов 0,6 с и 6,0 с
С расширениемчтение настроек лимитов 0,26 с; задания порогов 0,6 с и 0,8 с

Шаг "Пороги" 2,8 с - 1,6 с, ожидание порогов перед обработкой короче на 2,2 с.

сработалаНарезка плана по заданиям - правило 1, малый план

Если строк на задание меньше 50, наборы данных режутся на части и раскладываются по наименее загруженным заданиям, чтобы таблица набора строилась меньше раз.

Без расширения6 построений таблиц наборов в 5 заданиях - 18,2 с; работа 6 заданий - 48,9 с
С расширением3 построения, по одному на каждый из 3 наборов (меньше не бывает) - 7,5 с; работа 6 заданий - 25,9 с

12 строк на задание - правило применено. Самое долгое задание 10,6 с - 8,9 с, шаг "Обработка проверки" 11,4 с - 10,1 с.

не применяетсяНарезка - правило 2, большой план

При 50 и более строках на задание куски режутся подряд по наборам.

План из 72 строк на 6 заданий - малый, работает правило 1.

не применяетсяНарезка - правило 3, лимиты по алгоритму

Вызовы внешних алгоритмов лимитов раздаются заданиям по кругу.

Без расширениявызовов внешних алгоритмов нет
С расширениемвызовов внешних алгоритмов нет

В плане розницы нет лимитов со способом настройки "по алгоритму".

эффекта нетИндекс портфелей порции

Портфели порции собираются через индекс, без повторного просмотра уже собранного списка.

Без расширения165 вызовов сборки - 0,006 с
С расширением144 обращения к индексу - 0,001 с

Порции из нескольких портфелей - собирать почти нечего. Эффект идеи - на ночном регламенте розницы: обработка проверки 6 ч 45 мин - 8 мин 46 с.

эффекта нетСведения о порогах только для пар плана

Сведения о порогах строятся только для пар "лимит - портфель" из плана проверки.

Без расширения10 сведений о порогах
С расширением10 сведений о порогах

Все 10 пар есть в плане двух поручений - отбрасывать нечего. Эффект идеи - на регламенте обычного ФО: 2,19 млн сведений - 173 тыс.

Раздел 3

Задания обработки проверки

Без расширения таблицы трех наборов данных строились 6 раз в 5 заданиях (одно построение - 2,1-5,5 с); с расширением каждый набор строится один раз, в своем задании. Длительность шага определяет самое долгое задание. С расширением это задание с одним построением таблицы набора (3,6 с), запросами статики активов, рейтингов и состава портфелей и проверками по вариантам порогов своего набора. Постоянные запросы выполняет каждое задание независимо от числа строк, поэтому на плане из 72 проверок нарезка вдвое сокращает суммарную работу заданий, а длительность шага - на 1,3 с. На Т-1 обычного ФО по двум поручениям наборов больше, и то же правило дало 28 построений - 11 и шаг обработки 16,6 с - 8,9 с.

Раздел 4

Выводы

На малом плане работают две идеи - облегченные настройки лимитов и нарезка плана по правилу малого плана. Их вклад - около 5 с на проверку двух поручений; обе отработали так, как описано в обоснованиях.

Индекс портфелей порции и пороги только для пар плана на малом плане эффекта не дают и не должны: их задача - большой объем. На ночном регламенте розницы индекс сократил обработку проверки с 6 ч 45 мин до 8 мин 46 с.

Результат проверки с расширением и без совпал - описано в отдельном отчете о сверке. Следующий шаг по предпроверке - большая выборка на рознице (50-200 поручений): на таком объеме работают правило 2 нарезки и индекс портфелей.
