# План тестовых данных для проверки лимитов

База почти пустая: есть портфель, классы лимитов и активы. Нет лимитов, наборов данных, поручений и действующих установок. Пустой элемент справочника до расчета не доходит.

Проверка берет в план только лимиты с признаком «Тестовый» = Нет. Поэтому объекты называются с префиксом FO_GEN и остаются обычными, не тестовыми.

## Цепочка

1. Константы: фоновые задания выключены, потоков на сеанс 1, замеры производительности включены.
2. Источник FO_GEN источник, вид «Поручение», и набор FO_GEN набор. Лимит FO_GEN лимит того же вида. Постконтроль такой лимит не берет, он оставлен для будущего предконтроля.
3. Источник FO_GEN источник позиции, вид «Текущая позиция», набор FO_GEN набор позиции, лимит FO_GEN лимит состав. Вид лимита «Состав», способ «Внутренний», подтвержден, признак «Тестовый» выключен. После записи сохраняется кэш настроек.
4. Документ «Установка лимитов» на существующий портфель «Технический портфель», операция «По портфелю». В табличной части оба лимита. Проведение пишет действующие лимиты.
5. Справочник настроек УКР FO_GEN УКР и проведенный документ «Установка дополнительных настроек лимитов» со ссылкой на него. Без этого проверка останавливается до расчета.
6. Постконтроль вызывается напрямую: портфель и лимит состава, без поручений, с актуальной позицией. План получается из одной строки.
7. Длительности читаются из регистра «Замеры времени».

Поручения не создаются. Предконтроль потребует документ «Поручение» с распределением по портфелям.

## Повторный запуск

Скрипт ищет объекты по наименованию FO_GEN и не создает вторую проведенную установку на тот же лимит.
