Расширение пакетной проверки для обеих баз фронт-офиса

Обычный фронт-офис и розница. Один код. Перехват методом «Изменение и контроль». Имена лимитов в условии пачки не участвуют.

Сделать расширение, которое на уже загруженных лимитах и портфелях одним проходом по временной таблице набора считает все совместимые лимиты этого набора. В пачку входят три формы: структура с порогом от базиса портфеля, состав с коротким квалификатором, поручение, у которого отбор живет в квалификаторе. Лимит, который не распознан, идет прежним вызовом ПроверкаЛимитов.Проверить. Настройки справочника и назначения на портфели не меняются.

1. Что создать

  • Расширение FO_LimitShare, назначение Patch, префикс FO_LimitShare_.
  • Заимствовать общий модуль Исполнители.
  • Перехватить ПроверкаИОтправка_ОбработкаПроверки декоратором &ИзменениеИКонтроль.
  • Расчет пачки вынести в новый серверный общий модуль расширения. Это не перехватчик.
  • В теле перехватчика менять только точки из раздела 6. Добавленное обернуть #Вставка ... #КонецВставки. Удаляемый оригинал оставить между #Удаление и #КонецУдаления. Маркеры с первой колонки. Остальные строки оригинала не менять.
Не менять другие расширения. Не ставить заглушки на отправку, почту, статусы и внешние обработки. Не отбирать лимиты по наименованию, коду или папке справочника. Не делать отдельную ветку «только розница».

3. Три формы одной пачки

Пачка собирается из лимитов текущего исполнителя, Параметры.Данные[0]. Чужой план не читать. Общее условие для всех трех форм:

  • один и тот же набор данных, временная таблица которого уже построена;
  • нет модификатора, репрайсинга и своего деноминатора;
  • каждое дерево отбора, и основное, и квалификатор, сводится к полям и сравнениям, которые умеет вычислитель;
  • сравнения первой версии: равно, не равно, в списке, не в списке, в группе, не в группе, в группе из списка, не в группе из списка. «В группе» один раз раскрывается в множество ссылок. Больше, меньше и сравнение строк отправляют лимит на старый путь.
ФормаДополнительное условиеЧто делает проход

ПоручениеОтбор только в квалификаторах, деревья простые. Основной текст может быть пустым. Считать только когда источник набора это поручение и во временной таблице уже есть строки порученийОдин проход по строкам поручения, каждый лимит применяет свой квалификатор

Число квалификаторов само по себе лимит из пачки не выкидывает. Выкидывает непонятое сравнение или формула варианта порога, которая не сводится к сумме строк и портфельному базису.

Поля отбора заранее не задавать. Их список берется из деревьев тех лимитов, которые уже вошли в пачку.

4. Как считать

  1. После построения временной таблицы набора собрать все лимиты исполнителя этого набора, которые проходят раздел 3. Портфели пачки раскрывать так же, как сейчас: ПортфелиГрупп и флаг ПоГруппе. Лимиту принадлежат только его строки плана.
  2. Один запрос к временной таблице. Для структуры и состава: портфель, поля отбора пачки, сумма стоимости, группировка по портфелю и этим полям, контекст Портфель В (&Портфели). Для поручения в контекст добавить поручение, как в текущем УсловияОтбораКонтекста.
  3. Базис каждого вида посчитать один раз на портфель и вид базиса. Для лимитов пачки не вызывать повторно БазисыОтАктивов и РыночнаяСтоимость. Уже готовые ОбъемыОблигаций, ДанныеКапитализаций и ВеличиныОттока только читать.
  4. Структуре отдать сумму своих групп и ее порог. Составу и поручению отдать строки, которые не прошли квалификатор, в том виде, в каком их ждет текущая запись результата.
  5. На каждый лимит пачки вызвать тот же РаботаСЛимитами.ЗаписатьПорциюРезультатов, снять служебные временные таблицы и сдвинуть счетчик на то же число строк плана.
  6. Пометить лимиты обработанными. В цикле оригинала их тело не выполнять.

Зона, отказ, сумма и базис пары «портфель, лимит» или «поручение, лимит» должны совпасть со старым путем.

6. Куда ставить маркеры

Функция Исполнители.ПроверкаИОтправка_ОбработкаПроверки.

  1. Рядом с НаборДанныхТекущий = Неопределено добавить соответствие уже обработанных лимитов.
  2. В начале Для Каждого Лимит Из Лимиты, после проверки ПараметрыИсх = Неопределено: обработанный лимит пропустить.
  3. Сразу после НаборДанныхТекущий = НаборДанных, когда таблица набора уже есть: вызвать пачку. Для источника «Поручение» в пачку класть только форму «Поручение». Для остальных источников класть структуру и состав, поручение не класть.
  4. Если текущий лимит сам вошел в пачку, дальше по нему не вызывать построчный базис и ПроверкаЛимитов.Проверить.

Построение временной таблицы, итоговую запись и ПодготовитьЗавершение не переписывать.

7. Как проверить

  1. Один план прогнать без расширения и с ним. Сначала один поток, фоновые задания выключены.
  2. Обычный фронт-офис: несколько портфелей с полным набором структурных лимитов одного набора. По каждому лимиту сверить зону, отказ, сумму и базис.
  3. Розница: один портфель шаблона, все 14 лимитов. Пять структурных и шесть составных одного набора должны сойтись с эталоном и не вызвать Проверить повторно. Лимит другого набора и лимит с непонятым сравнением должны пройти старым путем и тоже сойтись.
  4. Пред-контроль: одно поручение, на котором висит несколько лимитов вида «Поручение» одного набора. Зоны по каждому лимиту совпали, проход по таблице поручения один.
  5. В замерах ключ «Обработка проверки» на полном пост-контроле короче хотя бы на 25%. Чтение набора не выросло. На рознице целевой ориентир этого ключа в несколько раз, не 1,2.
  6. Повторить сверку зон при боевом числе потоков.

8. Граница

  • Не менять чтение КэшВмПозиция и не сливать разные наборы в один запрос.
  • Не менять план, число исполнителей и КэшВмПланПроверки.
  • Не смотреть на флаг «Подтвержден»: на обеих базах он не отделяет работающие лимиты.
  • Внешние алгоритмы, модификатор, репрайсинг, свой деноминатор и непонятое сравнение остаются на ПроверкаЛимитов.Проверить.
