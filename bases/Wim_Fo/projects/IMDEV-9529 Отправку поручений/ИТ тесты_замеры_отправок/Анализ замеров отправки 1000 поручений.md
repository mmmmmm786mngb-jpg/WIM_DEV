# Анализ замеров отправки 1000 поручений (Т-1, 14.10.2026)

База ФО (розн) Т-1, обработка "Тест отправки поручений" (FO_SendFixStub 1.0.0.5), отправка фоновым заданием, FIX
отключен (пакет пишется в JSON). Поручения 08.10-14.10.2026, 1000 шт. Замер отладчиком:

- `Новый3.pff` - тонкий клиент (форма обработки);
- `Новый2.pff` - фоновое задание распорядителя (`Распорядители.Отправка`);
- `Новый1.pff` - фоновое задание адаптера FIX (`Исполнители.Отправка_ОтправкаПоручений`).

## Итог

| Показатель | Значение |
|---|---:|
| Ключевая операция "Отправка" (`ЗамерыВремени`), вес 1000 | **58,46 с** = 58 мс/поручение |
| Отправлено / отклонено | 1000 / 0 |
| Время по часам формы | 66,13 с |
| Подготовка 1000 поручений (имитация проверки, не входит в отправку) | 161,2 с |

Время растет линейно: 21 поручение - 1,93 с, 204 - 12,05 с (59 мс/пор.), 1000 - 58,46 с (58 мс/пор.). На PROD
модель по сентябрьским замерам 0,6 с + 45 мс/поручение (1000 -> ~46 с); Т-1 медленнее PROD на ~25%.

Разница 66,1 - 58,5 с - ожидание окончания в тестовой форме: стандартное окно длительной операции опрашивает
задание с растущим интервалом (1 с, x1,4, до 15 с), 10-я проверка пришлась на ~65,7 с. В блоттере интервал
опроса фиксирован 1 с, задержка не больше 1 с. Для сравнения брать ключевую операцию.

## Выводы

1. **Отправка 1000 поручений на Т-1 - 58,5 с, 58 мс на поручение, рост линейный.** Прогноз на 10 000 поручений
   ~10 мин на Т-1 (~7,5 мин на PROD) сохраняется.
2. **Основное время - запись статусов:** "Отправлено, ожидается" по каждому поручению 36,5 с и фиксация транзакции
   4,8 с - вместе 41,3 с, **71%** ключевой операции. Каждое поручение - отдельная запись набора регистра
   `СтатусыПоручений`, чтение предыдущей записи и запись набора `СтатусыПорученийБлокировки`. Запись статусов по
   решению заказчика не меняется.
3. **Формирование FIX - 3,8 с (6,5%)**, контрольная сумма 2,5 с с накладными расходами замера. Ускорение
   контрольной суммы даст не больше 2-2,5 с из 58.
4. **Сложение строк пакета при 1000 поручений незаметно (0,11 с).** Квадратичный рост начинает влиять от
   ~10 000 поручений.
5. **Сетевая отправка здесь не измерена** (заглушка 0,02 с). На PROD это один HTTP POST пакета на прокси.
6. Без изменения записи статусов доработки отправки (контрольная сумма, сборка пакета, синхронный вызов
   адаптера) дают порядка 3-5 с из 58,5 (5-9%). Вывод о нецелесообразности доработки отправки подтверждается.

## Рекомендации к замерам

- Контрольный прогон 1000 поручений **без включенного замера отладчиком**: ключевая операция покажет время без
  накладных расходов замера (ожидаемо на 5-8 с меньше).
- Время по часам тестовой формы завышено опросом окна длительной операции; при необходимости в обработке можно
  задать фиксированный интервал опроса 1 с, как в блоттере.
