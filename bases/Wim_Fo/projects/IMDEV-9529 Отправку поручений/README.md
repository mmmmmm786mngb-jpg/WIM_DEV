## Ключевые факты (по коду на 05.10.2026)

- Цепочка: `ФормаБлоттер.ПроверитьИОтправить` -> `КоПорученияКлиент` -> `РаботаСПоручениямиКлиент` ->
  `РаспорядителиКлиент.ПроверкаИОтправка_*` -> `Распорядители.ПроверкаИОтправка` (pre-trade) ->
  `Распорядители.Отправка` -> фоновое задание `Исполнители.Отправка_ОтправкаПоручений` ->
  `Обработки.Адаптер<Вид>.ПорученияОтправить`.
- В базе один адаптер "(UID 1189634) QUIK FIX Банк ВТБ (ПАО)", **Вид = FIX**
  (скриншот карточки: `2026_10_05_14_26_28_UID_1189634_QUIK_FIX_Банк_ВТБ_ПАО_Адаптер_.png`): пакет FIX NewOrderSingle
  одним HTTP POST `<АдресHTTPСервиса>/send` на WebSocket-прокси (общие настройки `ВебСокетПрокси`),
  SenderCompID FORDU_PROD, TargetCompID FORDU_VTB24. Таймаут HTTP 2 с.
- Потоков отправки = число адаптеров в плане, то есть 1: одно фоновое задание, без параллельности.
  `ЗахватитьНомераИсходящие` держит исключительную блокировку счетчика `СообщенияАдаптеровСчетчики`
  до ответа прокси.
- Расширения VTB и ВТБ_Прод цепочку отправки не перехватывают.
- В веб-клиенте кнопка не работает: `ВыполнитьМетодОбработкиПоручений` под `#Если Не ВебКлиент`.

## Варианты распараллеливания (на будущее, сейчас не рассматриваются)

Текущий этап - понять, что в отправке занимает время. Варианты ниже записаны только для справки.

- **A.** Параллельная подготовка и фиксация статусов фоновыми заданиями, одна последовательная
  отправка пакета с назначением MsgSeqNum в родителе.
- **B.** Несколько FIX-сессий у брокера (несколько адаптеров FIX) с распределением поручений;
  механизм "одно задание на адаптер" уже есть.
- Перед выбором - замер составляющих `Распорядители.Отправка` (проверки, сборка и запись статусов, HTTP).
