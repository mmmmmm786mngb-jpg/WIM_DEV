Ускорение отправки поручений: расширение FO_SendOpt

Редакция 1, 12.10.2026Объем 3 доработки, только код отправкиФорма расширение конфигурации

Что делаем. Три доработки в новом расширении FO_SendOpt: синхронный вызов адаптера при одном адаптере, быстрая контрольная сумма сообщения FIX, сборка пакета FIX через СтрСоединить.

Что получаем. Около 19% времени отправки на 204 поручениях (~2,3 с из 12 с), около 23% на обычной отправке из десятков поручений; на очень больших пакетах убирается нелинейный рост времени.

Что не меняется. Проверка лимитов, статусы и события поручений, текст сообщений FIX, логика транзакций и откатов.

1. Цель и границы

Цель по постановке IMDEV-9529: оптимизировать процедуру отправки поручений на биржу (кнопка "Проверить и отправить" в блоттере и в форме поручения) без изменения проверки лимитов.

ВходитНе входит

  • Обработка.АдаптерFIX: формирование сообщений и пакета FIX
  • проверка лимитов (Распорядители.ПроверкаИОтправка до блока отправки), запись статусов проверки
  • запись статуса "Отправлено" (РегистрСведений.СтатусыПоручений)
  • прочие распорядители: отмена, изменение, разделение и др.
  • адаптеры QUIK, FIX-Ray, WINVESTOR (кроме общего генератора пакета FIX, см. доработку 3)

3. Доработки

1

Синхронный вызов адаптера при одном адаптере

~0,4-1,9 с на отправку
Сейчас

Распорядители.Отправка группирует биржевые поручения по адаптерам и через ИсполнитьРаспоряжение запускает Исполнители.Отправка_ОтправкаПоручений фоновым заданием на каждый адаптер (число потоков = число адаптеров), затем ждет завершения (РезультатИсполненияРаспоряжений). В базе один адаптер вида FIX, поэтому задание всегда одно и ничего не распараллеливает.

Изменение

Перехват служебной функции Распорядители.Распоряжение(Данные, Исполнитель, КоличествоПотоков, СжечьПослеПрочтения) (&Вместо): если исполнитель - Исполнители.Отправка_ОтправкаПоручений и в плане отправки один элемент (один адаптер), число потоков = 0; иначе вызов без изменений.

При числе потоков 0 типовой ИсполнитьРаспоряжение выполняет исполнителя в текущем сеансе распорядителя, а РезультатИсполненияРаспоряжений сразу читает результат из временного хранилища. Это существующий путь типового кода (используется в режиме тестирования конфигурации).

&Вместо("Распоряжение")
Функция FO_SendOpt_Распоряжение(Данные, Исполнитель, КоличествоПотоков = 0, СжечьПослеПрочтения = Истина)
	Если Исполнитель.Метод = "Исполнители.Отправка_ОтправкаПоручений" И Данные.Количество() = 1 Тогда
		КоличествоПотоков = 0;
	КонецЕсли;
	Возврат ПродолжитьВызов(Данные, Исполнитель, КоличествоПотоков, СжечьПослеПрочтения);
КонецФункции
Эффект

Нет запуска фонового задания, сериализации распорядителя, ожидания и передачи результата: 0,4 с на 21 поручение, около 1,9 с на 204 поручения по замерам. Точная доля станет известна после прогона.

Риски
  • Внебиржевые поручения той же отправки обрабатываются после биржевых, а не параллельно с ними (в замерах внебиржевых в отправке не было).
  • При двух и более адаптерах поведение прежнее (задание на адаптер, параллельно).
  • Отправка выполняется в сеансе распорядителя, который уже работает в привилегированном режиме и вне транзакции: права и границы транзакции адаптера не меняются.
2

Быстрая контрольная сумма сообщения FIX

~1,7 мс на поручение
Сейчас

Обработка.АдаптерFIX, модуль объекта, КонтрольнаяСуммаСтрокой: цикл по каждому символу сообщения с вызовом функции КодСимволаANSI (около 220 вызовов на сообщение, 45 404 вызова на 204 поручения, 0,51 с). КодСимволаANSI для кода меньше 128 возвращает КодСимвола, иначе - код в windows-1251, а для символов вне windows-1251 - -1.

Изменение

Перехват КонтрольнаяСуммаСтрокой (&Вместо): код символа берется прямо в цикле через КодСимвола; КодСимволаANSI вызывается только для символов с кодом 128 и выше. Расчет суммы, остатка от деления на 256 и формат результата - как в типовом коде.

Для Индекс = 1 По СтрДлина(ТекстСообщения) Цикл
	Код = КодСимвола(ТекстСообщения, Индекс);
	Если Код >= 128 Тогда
		Код = КодСимволаANSI(ТекстСообщения, Индекс);
	КонецЕсли;
	СуммаКодовСимволов = СуммаКодовСимволов + Код;
КонецЦикла;
Эффект

Около 0,35 с на 204 поручения (оценка: 2,5 мс -> ~0,8 мс на сообщение), около 8 с на 4 500 поручений.

Риски

Результат совпадает с типовым для любой строки: для кодов меньше 128 оба варианта дают КодСимвола, остальные символы идут через ту же КодСимволаANSI.

3

Сборка пакета FIX через СтрСоединить

страховка больших объемов
Сейчас

Обработка.АдаптерFIX, модуль объекта: ДополнитьПакет накапливает пакет в переменной модуля сложением строк (ПакетСообщений = ПакетСообщений + Сообщение), ПакетСообщений() возвращает его с заменой разделителя | на SOH (для FIX-Ray - с дополнительной обработкой). Каждое сложение копирует уже собранную строку: время растет квадратично.

Изменение

Переменная модуля расширения - массив частей пакета. Перехват ДополнитьПакет (&Вместо) добавляет сообщение в массив и возвращает Истина. Перехват ПакетСообщений (&Вместо) собирает строку СтрСоединить(Части) и выполняет те же замены, что типовая функция, включая ветку FIX-Ray.

Эффект

До 5 000 сообщений незаметен; 10 000 - минус 1,3 с, 50 000 - минус 35 с, 100 000 - минус 2,4 мин.

Риски

Затрагивает все сообщения, собираемые генератором FIX (адаптеры FIX и FIX-Ray: заявки, отмены, сервисные сообщения). Пакет совпадает с типовым: те же строки в том же порядке, те же замены.

  • Пакетное чтение текущих статусов и одна блокировка при записи статуса "Отправлено": около 5 мс на поручение; требует изменения процедуры АдаптерFIX.ПорученияОтправить целиком (&ИзменениеИКонтроль).
