IMDEV-9529 · расширение FO_SendFixStub 1.0.0.2 · Т-1 (AVC_PP_Retail_FO)

Прогон отправки поручений на Т-1 с заглушкой FIX

Порядок: установка расширения, проверка перед отправкой, первый тестовый прогон на одном поручении, затем рабочие прогоны для замеров - без отладчика и под отладчиком.

Это регламент или обработка?

Ни то, ни другое: это команда формы блоттера. Отправку запускает пользователь кнопкой "Проверить и отправить" в форме Обработка.Блоттер.ФормаБлоттер (раздел "Поручения и сделки" → "Блоттер"). Регламентное задание в отправке не участвует. Сервер выполняет работу в двух фоновых заданиях, которые запускаются от вашего сеанса:

Блоттер, кнопкаПроверить и отправить
→
Фоновое задание 1Распорядители.ПроверкаИОтправка (длительная операция БСП): проверка лимитов
→
Фоновое задание 2Исполнители.Отправка_ОтправкаПоручений: адаптер FIX
→
ЗаглушкаJSON-файл + журнал регистрации вместо HTTP

Версия 1.0.0.2: нарушения лимитов игнорируются. Проверка лимитов выполняется полностью (ее время остается в замере, контрольная ведомость показывает фактические нарушения), но перед записью статусов у результатов снимаются признаки нарушения. Все проверенные поручения получают статус "Проверено" и уходят в заглушку. Не отправятся только поручения без назначенных лимитов. В журнале регистрации событие IMDEV-9529.ЗаглушкаFIX: "Нарушения лимитов проигнорированы: поручений N из M". Действует и на кнопку "Проверить" без отправки.

Отдельно на Т-1 работает регламентное задание синхронизации адаптеров (АванкорСинхронизацияСостояний). К отправке оно не относится; с заглушкой его запросы к прокси тоже блокируются.

1. Установка (каждый день прогона)

  1. Добавить расширение

    Администрирование → Печатные формы, отчеты и обработки → Расширения → Добавить из файла → Расширения\FO_SendFixStub.cfe. Или в конфигураторе: Конфигурация → Расширения конфигурации → Загрузить из файла.

  2. Свойства расширения

    • Активно - да;
    • Безопасный режим - нет (в безопасном режиме запись файлов недоступна);
    • защита от опасных действий - без предупреждений.

  3. Константа РежимТестирования = Ложь

    Иначе отправка выполняется синхронно, без фонового задания адаптера, и прогон не повторяет PROD.

  4. Перезапустить сеанс

    Закрыть 1С и зайти заново. Фоновые задания получают набор расширений того сеанса, из которого запущены.

Т-1 каждую ночь заменяется копией PROD. Расширение пропадает вместе с прочими изменениями, на следующий день его ставят заново.

2. Проверка перед любой отправкой

  1. Имя базы

    Справка → О программе: в строке соединения должно быть Ref="AVC_PP_Retail_FO". Заглушка включается только в базах AVC_PP_Retail_FO, AVC_PP_FO, WIN_FO_server.

    Стоп: имя другое - не отправлять. Без включенной заглушки пойдет настоящая отправка в прокси, настройки которого скопированы с PROD. Сообщить имя - добавлю его в список и пересоберу расширение.

  2. Расширение применилось

    В списке расширений FO_SendFixStub активно, без безопасного режима, ошибок применения нет.

3. Первый тестовый прогон: одно поручение

  1. Подготовить поручение

    Блоттер → выделить одно вчерашнее биржевое поручение → Скопировать... (копирование выбранных). Копия создается проведенной, без биржевого номера, ее можно отправлять.

  2. Точка останова (рекомендуется)

    Конфигуратор/EDT, подключение к Т-1, Отладка → Подключение → Автоматическое подключение: Фоновое задание. Точка останова в начале функции Распорядители.Отправка (общий модуль Распорядители).

  3. Отправить

    Выделить копию → Проверить и отправить → подтвердить вопрос.

  4. На точке останова - вычислить выражение

    Адаптеры.ЗаглушкаОтправкиFIXВключена() → должно быть Истина. До этой точки ни одна заявка не отправляется.

    Стоп: Ложь или "метод не найден" - остановить отладку (Shift+F5), не продолжать выполнение.

  5. Продолжить и проверить результат

    • Форма результатов обработки: поручение в статусе "Отправлено, ожидается подтверждение".
    • Журнал регистрации, отбор по событию IMDEV-9529.ЗаглушкаFIX: запись "Нарушения лимитов проигнорированы: поручений 0 или 1 из 1" и запись Команда /send, заявок 35=D: 1, длина тела ..., запись файла N мс, файл ....
    • Файл из этой записи на сервере Т-1 (каталог временных файлов пользователя службы 1С + IMDEV-9529_FIX, например C:\Users\USR1CV8\AppData\Local\Temp\IMDEV-9529_FIX\): поле orders = 1, в messages - заявка с вашим инструментом и ценой.
    Тест пройден: статус "Отправлено", событие журнала есть, orders = 1. Можно переходить к рабочим прогонам.
    Если поручение не ушло (ошибка проверки лимитов, отклонение цены, "адаптер не готов"): прислать текст из формы результатов, разберу. Записи IMDEV-9529.ЗаглушкаFIX при этом не будет - это нормально.

4. Рабочие прогоны

Наборы поручений готовятся так же: выделить N вчерашних биржевых поручений (Ctrl+A по отбору) → Скопировать.... С версией 1.0.0.2 отправляются все проверенные поручения, в том числе с нарушениями лимитов; поле orders в файле должно совпасть с размером набора (кроме поручений без назначенных лимитов).

А Без отладчика - время по ключевой операции

  1. Отладчик не подключен. Наборы по очереди: 100 → 1 000 → 4 500 → 10 000.

  2. Каждый набор: выделить → Проверить и отправить → дождаться формы результатов. Зафиксировать время по часам (начало - нажатие, конец - форма результатов).

  3. Время ключевой операции "Отправка": Администрирование → Оценка производительности (или выгрузка замеров, как с PROD). Вес замера = число поручений в отправке.

  4. Из журнала регистрации по каждому прогону - время записи файла заглушкой (его вычесть).

На 10 000 проверяется, остается ли время линейным (около 54 мс на поручение на PROD; Т-1 медленнее, сравнивать прогоны Т-1 между собой).

Б Под отладчиком - где именно тратится время

  1. Конфигуратор/EDT: Автоматическое подключение → Фоновое задание. Точки останова снять.

  2. Набор 1 000 поручений выделен в блоттере.

  3. Отладка → Замер производительности (включить) → Проверить и отправить → дождаться формы результатов → Замер производительности (выключить).

  4. В результатах сортировать по чистому времени. Отдельно смотреть два фоновых задания: проверку лимитов и задание адаптера (Исполнители.Отправка_ОтправкаПоручений, АдаптерFIX.ПорученияОтправить).

  5. Сохранить замер в файл .pff и положить в папку задачи - разнесу строки по блокам раздела 4 постановки.
