{panel:title=IMDEV-9530. Замеры производительности ключевых операций Аванкор ФО (Розница)|borderStyle=solid|borderColor=#52648A|titleBGColor=#DDE3EE|bgColor=#F4F6F9}
*Коротко:* по списку из 16 ключевых операций ФО определены объекты, в которые ставятся замеры. Замеры пишутся штатной подсистемой БСП "Оценка производительности" и видны в стандартном отчете. По 3 операциям замер уже есть, по 13 добавляем новый код: 6 операций в конфигурации (через расширения), 7 во внешних обработках.

*Принцип веса:* вес замера по возможности - число портфелей (договоров), где портфеля в операции нет - число обработанных объектов. Детали (число строк, депозитов, поручений, потоков) пишутся в комментарий замера.

*Статус:* (/) анализ завершен, объекты подтверждены по коду и по данным ПРОД, план согласован. Замер регистра ДополнительныеСведения (часть строки 6) выполнен в задаче IMDEV-9532 и здесь считается выполненным.
{panel}

h3. (i) Что проверено на ПРОД

* Константа "Выполнять замеры производительности" включена на ПРОД и тестовых базах: существующие замеры строк 1, 2, 4, 14 уже пишутся.
* Сделки загружает один адаптер вида FIX ("QUIK FIX Банк ВТБ (ПАО)"), адаптеры вида QUIK помечены на удаление: строка 14 закрыта существующим замером.
* Предопределенное задание "Загрузить индексы (ММВБ)" выключено: индексы загружает только внешняя обработка.
* Загрузка депозитов на ПРОД - версия обработки 1.18.

h3. Порядок работ

h4. А. Работы ИТ ВИМ

*А1. Внешние обработки (7 штук, строки 3, 5, 9-13).* Выпускаются новые версии, замеры вызывают подсистему БСП напрямую. Наименование, команды и расписание обработок не меняются; новая версия загружается поверх текущей в "Дополнительные отчеты и обработки".
# Лимиты и поручения: распространение правил (1.15), торговые поручения РОСТ (1.16), неторговые поручения РОСТ (1.07).
# Загрузки: депозиты (1.19), котировки ММВБ (1.03), индексы (1.04), TCRIS (1.02).
# Проверка на тестовой копии: запуск каждой обработки по команде фонового выполнения, сверка ключей, шагов и результата работы с текущей версией.

*А2. Расширение FO_KeyOpsPerf (строки 2, 6-8, 15, 17).* Новое расширение ВИМ, базовая конфигурация не меняется, собственных общих модулей нет. Вендору не передается и после его релиза остается.
# Каркас расширения: заимствование обработок ОбменДаннымиБэкОфис, ГрупповоеИсполнениеСделок, ПроверкаЛимитовПоПортфелям и общего модуля АванкорВыполнениеРегламентныхЗаданий.
# Прием пакетов из МО: замер пакета, каждого непустого раздела (кроме ДополнительныеСведения) и операций после обмена.
# Исполнение сделок, упаковка данных, постконтроль.
# Проверка на стенде МО-ФО (строки 6-8): записи по каждому непустому разделу, данные загрузки совпадают со снимком без замеров, эффект IMDEV-9532 сохранен.

*А3. Сквозная проверка.* Расширения и новые версии обработок на тестовой копии, сутки работы по расписанию, сверка всех 16 строк с записями замеров, сравнение длительности загрузок с днем без замеров.

*А4. Установка на ПРОД.* Расширения подключаются без безопасного режима: в безопасном режиме подсистема оценки производительности замер не записывает.

h4. Б. Связь с задачей IMDEV-9532 (вендор Аванкор)

Из этой задачи вендору ничего не передается: расширение FO_KeyOpsPerf остается у ИТ ВИМ.

Замер регистра ДополнительныеСведения (флаги лимитов при загрузке остатков) пересекается с оптимизацией IMDEV-9532 и *выполнен в задаче IMDEV-9532*: расширение FO_PositionLoadOpt 1.0.0.5 = оптимизация 1.0.0.4 без изменений логики + замер внутри ее перехвата. Вендору передается эта версия вместо 1.0.0.4, в рамках IMDEV-9532.
* Ключ {{ОбменБэкОфис.РегистрыСведений.ДополнительныеСведения}}, вес - число портфелей, комментарий - строк в пакете и сколько записано. Разница показывает, сколько флагов оптимизация пропустила без записи.
* Замер работает и без FO_KeyOpsPerf (проверено на стенде: 0 ошибок). FO_KeyOpsPerf этот регистр не замеряет, двойных записей нет.
* После выхода релиза с перенесенным кодом IMDEV-9532: на тестовой копии с релизом снимаем FO_PositionLoadOpt, проверяем применимость FO_KeyOpsPerf к релизу и что ключ ДополнительныеСведения пишет уже базовая конфигурация.

h3. Как смотреть результаты

Обработка "Оценка производительности" (стандартный отчет БСП) или запрос к регистру "Замеры времени" по ключам из таблицы. Каждая запись содержит длительность, вес, номер сеанса и комментарий; по номеру сеанса и пересечению интервалов видна параллельность загрузки из МО (на ПРОД 5 потоков).
