раздела "Загрузка данных": строки 7, 8, 10, 11, 12. Дата составления: 13.11.2026.

Замеры: выгрузки РС `ЗамерыВремени` ПРОД за 16.10-02.11.2026 (17 запусков каждой ежедневной операции) -
`Замеры_октябрь2026_ФО_Розница.xlsx` (папка IMDEV-9748) и `ЗамерыВремени_с_октября2026_ФО_Обычное.xlsx`

Все пять операций прогнаны на разработческих базах на объемах ПРОД (подробно -
`Тестирование/Нагрузочное тестирование уровня 5.md`). Что уточнилось:

- **Котировки МО - ФО**: 5 тыс строк за ~2,5 с обе стороны - из кандидатов на оптимизацию исключить.
- **Индексы**: запись 83% (по одной, 32 мс), но абсолют мал - "не узкое место" подтверждено.

## 1. Строка 10. Загрузка котировок ММВБ - приоритет 1

**Что это.** Внешняя обработка `внЗагрузкаКотировокММВБ`, ежедневно в 09:00 в обеих базах ФО. Читает котировки
за день из сервиса котировок (WS `StockPrice`, таймаут 120 с), создает 1-2 документа котировок на 43,6-43,9 тыс
строк (розница - около 800 активов, обычный ФО - 1183).

**Замеры ПРОД 16.10-02.11** (ключи `ЗагрузкаКотировокММВБ*`):

| Шаг | Розница, среднее | Розница, максимум | Обычный ФО, среднее | Обычный ФО, максимум |
|---|---:|---:|---:|---:|
| Вся загрузка | 115,7 с | 131,8 с | 141,1 с | 169,4 с |
| Чтение | 98,6 с | 112,5 с | 110,2 с | 126,9 с |
| Запись | 13,7 с | 19,0 с | 25,6 с | 39,6 с |

**Слабое место.** Шаг "Чтение" (85% в рознице, 78% в обычном ФО) включает сразу три разные вещи:

1. вызов WS-сервиса `StockPrice` и ожидание ответа (внешняя система, время не наше);
2. разбор ответа: перенос 44 тыс строк XDTO в таблицу, поиск активов по коду ММВБ (`ДополнитьТаблицуСсылками` -
   одним запросом), перенос в табличную часть `СписокЗагрузки`;
3. построчный вывод лога: `Лог.Вывести(СтрокаТаблицы)` на каждую из 44 тыс котировок - табличный документ на
   44 тыс областей каждый запуск.

**План.**

1. Разбить шаг "Чтение" дополнительными замерами на три подшага (сервис / разбор / лог) - правка только
   замерной версии (ЗАМЕРЫ IMDEV-9530), прогон на Т-1. Так станет видно, сколько времени наше, а сколько -
   сервис котировок.
2. Если лог заметен - выводить в табличный документ только ошибки ("Актив не найден", "Повтор котировки") и
   итоговые строки; полный список котировок в лог не выводить.
3. Если разбор заметен - убрать двойной перенос строк (XDTO -> таблица -> СписокЗагрузки -> документ),
   заполнять документ напрямую.
4. Время самого сервиса - вынести в отдельный разговор (TIBCO, не 1С); зафиксировать его долю цифрой.

**Эффект.** Наша часть шага чтения (разбор + лог) - потенциально единицы секунд вместо десятков; точная цифра
после шага 1. Запись (14-26 с на 44 тыс строк документами) пока не трогать.

## 2. Строка 12. Загрузка TCRIS - приоритет 2

**Что это.** Внешняя обработка `ЗагрузкаДопРеквизитаTCRIS`, ежедневно в обеих базах. Читает ~1,17 тыс строк из
внешней базы Rates (SQL), сопоставляет контрагентов по ИНН (710-776 строк, 480-536 контрагентов), пишет
значение TCRIS в РС `ДополнительныеСведения`.

**Замеры ПРОД 16.10-02.11** (ключи `ЗагрузкаTCRIS*`): вся операция - розница 34,5 с, обычный ФО 32,0 с
(максимум 37,9 / 41,7 с). Из них чтение Rates 0,3 с, сопоставление 0,6-1,0 с, **запись 31,0-33,2 с (96%)**.

**Слабое место.** Запись: на каждого контрагента - `МенеджерЗаписи.Записать(Истина)` в `ДополнительныеСведения`
(своя транзакция на запись, около 64 мс). Пишется каждый день всем 480-536 контрагентам, даже если значение
TCRIS не изменилось - а меняется оно обычно у единиц.

**План.**

1. Перед циклом одним запросом прочитать текущие значения TCRIS всех сопоставленных контрагентов.
2. Писать только изменившиеся значения (ожидаемо единицы в день).
3. Согласовать способ записи: оставить менеджер записи для изменившихся или писать через программный интерфейс
   подсистемы свойств; заодно проверить `НайтиПоНаименованию("TCRIS")` - заменить на поиск по имени свойства.
4. Тест на стенде по образцу IMDEV-9748: оригинал против ускоренной, те же значения в регистре, отчет.

**Эффект.** Ожидаемо 1-3 с вместо 32-35 с в каждой базе. Низкий риск: обработка своя (колонка "ИТ ВИМ"),
вендор не нужен.

## 3. Строка 7. Загрузка мандатов (МО - ФО) - приоритет 3

**Что это.** Каждый час с 09:00. Со стороны МО - обработка `внВыгрузкаСчетовМандатов_МО_ФО` (выгрузка
справочников: Портфель, Субпортфель, МестоХранения, ТорговыеСчета пакетами XDTO в веб-сервис ФО), со стороны
ФО - обработка конфигурации `ОбменДаннымиБэкОфис` (диспетчер загрузки справочников из пакета).

**Замеры.** На ПРОД данных нет: ключи `ОбменБэкОфис.*` на стороне ФО появились в конфигурации 1.4.10, в
выгрузках за октябрь по обычному ФО всего 3 одиночные записи ("Строк: 0-1" - ручные проверки), в рознице ни
одной. На стороне МО замеров в обработке выгрузки нет вовсе.

**План.**

1. ФО: убедиться, что после обновления ПРОД до 1.4.10.x ключи `ОбменБэкОфис.Пакет` и по видам справочников
   пишутся штатно; если конфигурация еще 1.4.9.5 - дождаться обновления или поставить замерную версию.
2. МО: добавить замеры в `внВыгрузкаСчетовМандатов_МО_ФО` - весь запуск и в разрезе каждого справочника
   (рекомендация карты операций IMDEV-9530: мандаты в первую очередь - Портфель, Субпортфель, МестоХранения,
   ТорговыеСчета), вес - число объектов пакета.
3. Неделя наблюдений на ПРОД, затем вывод: есть ли что оптимизировать. Операция ежечасная, поэтому даже
   десятки секунд на запуск - это десятки минут в день.

**Эффект.** Пока только видимость. Решение об оптимизации - по результатам замеров.

## 4. Строка 8. Загрузка котировок (МО - ФО) - приоритет 4

**Что это.** Ежедневно в 09:00: МО-обработка `внВыгрузкаКотировокМО_ФО` выгружает документы котировок в ФО
через тот же веб-сервис, на ФО принимает `ОбменДаннымиБэкОфис` (загрузка документов).

**План.** Делать вместе со строкой 7, механизм один: замеры МО-обработки (запуск + пакеты), ключи
`ОбменБэкОфис.*` на ФО, неделя наблюдений, вывод. Отдельной работы не планировать, пока замеры не покажут
проблему: это не ММВБ-котировки, объем заметно меньше.

## Порядок работ

1. **TCRIS** - самая дешевая и самая предсказуемая: своя обработка, готовый образец теста (IMDEV-9748),
   эффект минус ~30 с в день на базу. Можно начинать сразу.
2. **Котировки ММВБ, шаг 1** (детализация чтения замером на Т-1) - параллельно с TCRIS; дальнейшее по цифрам.
3. **Мандаты + котировки МО - ФО** - замеры с двух сторон, неделя наблюдений, затем решение.
4. **Индексы** - без отдельной задачи.

Для каждой работы, которая дойдет до правки кода: папка задачи по образцу IMDEV-9748 (ОРИГИНАЛ, УСКОРЕНО,
Тестирование, Документация), оригиналы уже скопированы в `ОРИГИНАЛЫ` этого проекта.
