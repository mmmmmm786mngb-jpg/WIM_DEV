# IMDEV-9748. Отчет о тестировании обработки 1.08 (03.11.2026)

Обработка `внЗагрузкаНеторговыхПорученийРОСТ`: версия 1.07 (ПРОД, выгрузка `WORK\WIM_Fo\src\epf` от 29.10, совпадает
со сборкой замеров IMDEV-9530) против итоговой 1.08. Состав 1.08 согласован 03.11.2026 после первой серии тестов:

1. Письмо без созданных поручений уходит только при ошибке (`ВажностьОшибки = 2`); тело письма оформляется
   HTML-абзацами через имеющуюся в модуле `СформироватьТелоПисьма`.
2. Не выполняется запрос `ПолучитьСуммуКупоны` (резерв 13.1): его результат нигде не используется.
4. Отказ 1С:ДО по одному портфелю не прерывает запуск: ошибка пишется в лог по портфелю, обработка переходит к
   следующему; при неудачном подключении к 1С:ДО в лог пишется текст ошибки; общее исключение пишется как
   "Ошибка выполнения" вместо "Ошибка рассылки отчета по почте".

Пункт 3 (условие `Объект ССЫЛКА Справочник.Портфели` в отборе портфелей) был в первой сборке, по итогам серии 1
эффекта не дал и из 1.08 убран.

Итог: **15 из 15 проверок пройдено** (серия 3, итоговая сборка; серия 2 на той же логике с закомментированными
исходными строками дала те же результаты). Данные базы совпадают с 1.07 везде, кроме
сценария С9, где 1.08 по замыслу пункта 4 создает поручение, которое 1.07 пропускает. Письма отличаются ровно
в задуманных случаях. Протокол с проверками и образцами писем: `Протокол тестирования 1.08.html`.

## Стенд

Разработческая база ФО `WIN_FO_server`, платформа 8.3.27.2214. Каталог стенда: `Тестирование/Стенд`.

- Обе версии регистрируются в один элемент дополнительных обработок; перед каждым запуском записываются двоичные
  данные версии и ее настройки. У каждой версии свои портфели с брокерским субпортфелем и свое свойство статуса,
  поэтому версии не видят данных друг друга. Серия 1 (первая сборка с пунктом 3): портфели `T9748_A_*` / `T9748_B_*`;
  серия 2 (пункты 1, 2, 4, исходные строки закомментированы): `T9748_C_*` / `T9748_D_*`; серия 3 (итоговая сборка
  без закомментированных строк): `T9748_E_*` / `T9748_F_*`, по 22 на версию.
- Обработку запускает тестовая обработка `T9530_ТестРОСТ` 1.7 из базы (сценарий "Неторговые", фоновое задание,
  `ЭтоТест = Истина`: сумма на брокерском счете без адаптера FIX).
- 1С:ДО - заглушка `mock_dm_service.py` (ответ `GetAgreementAmount` по номеру договора из файла правил, SOAP Fault
  для "fail"). Почта - заглушка `mock_smtp.py`: учетная запись `T9748 Тестовая почта` (127.0.0.1:18525), каждое
  письмо сохраняется в `results/mail/*.eml` и разбирается (тема, важность, вложения, HTML).
- `run_tests.py prep | scenarios | extra | bench | queries | collect | close` (серия задается переменной
  `T9748_SERIES`, по умолчанию 3), сверка и протокол - `build_report.py`. Данные: `results/state_3.json`,
  итог проверок: `results/checks_3.json`; серия 2 - `state_2.json`, `checks_2.json`; серия 1 - `state_1.json`,
  `checks_1.json`, `Протокол тестирования 1.08 серия 1.html`.

## Анализ

**Пункт 1 (письма).** Убираются только письма с 0 поручениями и предупреждениями; в 1.07 они не содержали ни
отчета, ни причины, кроме строки "Не найдено портфелей". Письма с поручениями и с ошибками остаются. По замерам
ПРОД это около 22 писем в день меньше. Получатели перестают видеть факт "есть предупреждение без поручений" -
нужно их согласие (вопрос 1 в комментарии Jira).

Побочный эффект оформления HTML: текстовую альтернативу письма платформа строит из HTML, и в 1.08 в ней строки
идут подряд (в 1.07 наоборот: текстовая часть с переносами, HTML одной строкой). Outlook показывает HTML-часть.
Замечание низкой важности.

**Пункт 2 (купоны)** - единственный, дающий время; результат расчета не меняется (данные С3, С8 совпали).

**Пункт 4 (отказ 1С:ДО)** - исправление надежности. В 1.07 одна ошибка 1С:ДО останавливает весь запуск: остальные
портфели ждут следующего запуска через 10 минут, письма нет, журнал указывает на почту. В 1.08 остальные портфели
обрабатываются (С9: поручение создано), ошибка видна в письме {FAIL} с именем портфеля и текстом ошибки сервиса.
При постоянном отказе 1С:ДО по одному портфелю 1.08 будет присылать {FAIL} каждые 10 минут - это ожидаемо: ошибка
требует разбора. Пустой текст ошибки подключения (С7) исправлен.

Ошибки ПРОД 27.10 14:10 (0 поручений) могли быть путем С5; ошибка 02.11 14:00 с 1 созданным поручением - другой
путь (при исключении из `СоздатьПоручения` счетчик поручений остается 0). Точно - по журналу регистрации ПРОД.

## Ход тестирования и отклонения стенда

- Серия 1 (первая сборка с пунктом 3): 15/15, данные совпали; по ней пункт 3 признан нейтральным (отбор совпал по
  всем 6 свойствам-статусам базы, время в пределах шума: в регистре дополнительных сведений dev 16 094 из 16 134
  строк принадлежат портфелям) и убран. Тогда же найден дефект отказа 1С:ДО, ставший пунктом 4.
- Стенд, не обработка: в серии 1 два запуска сначала оказались без замера - ошибка привязки замеров к запускам в
  скрипте стенда (перекрытие окон времени), после исправления у всех запусков полный набор замеров.
- Стенд, не обработка: в сериях 2 и 3 самый первый запуск после подготовки данных (С1, версия 1.07, 11 с вместо 1 с)
  вернул на стенд пустой лог. В том же запуске обработка отправила письмо с правильным текстом "Не найдено
  портфелей", в журнале "Расчет произведен успешно", замер записан с комментарием "Поручений создано: 0" - то есть
  обработка отработала верно, а результат тестовой обработки не дошел до скрипта стенда через временное хранилище.
  В серии 1 первый запуск (8 с) вернул лог нормально; на версии 1.08 первым запуском не воспроизводилось, так как
  первой всегда идет 1.07. С1 повторен для обеих версий, холодный запуск оставлен в данных как
  `С1.НетПортфелей.холодный`; в стенд добавлен признак `результат_получен`, все последующие запуски серии 3 вернули
  результат.
- Ошибка проверки С9 в сборщике протокола (сравнение булева признака "Проведен" со строкой) исправлена, данные
  были верны.
- Серия 3 повторена после удаления закомментированных исходных строк из кода 1.08: логика та же, результаты
  совпадают с серией 2.
