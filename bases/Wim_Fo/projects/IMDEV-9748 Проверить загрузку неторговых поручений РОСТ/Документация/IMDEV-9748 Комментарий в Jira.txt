Обработка работает *234 с в день* (около 0,8% окна 10:00-18:40), медиана запуска 3,6 с, максимум 35,6 с; 10-минутный интервал не перекрывается ни разу. *Оптимизация по скорости не требуется* - все резервы в коде вместе дают меньше 1-2 минут в день. Есть замечание по письмам и вопросы к заказчику (ниже).

h3. Из чего складывается время

* Создание поручений = *2,6 с + 0,63 с на каждое поручение* (по всем 587 запускам). Постоянная часть - пустой запуск, медиана 2,1 с: статусы "ДС выведены", позиция по брокерскому счету, запросы свободного остатка, отбор портфелей, вызовы 1С:ДО.
* Запуск 10:00 каждый день создает 0 поручений (6-13 с), запуск 10:10 создает основной пакет дня: 11-42 поручения за 10-28 с.
* Запуски в начале часа примерно вдвое медленнее остальных - совпадают с почасовыми заданиями ФО, это нагрузка на сервер, а не код обработки.
* Все выбросы свыше 20 с - отправка письма (почтовый сервер): 19.10 14:00 - 30,1 с, 23.10 11:00 и 11:10 - по 21,0 с.

h3. Письма без созданных поручений

Обработка не отправляет письмо, только если поручений 0 и нет ни ошибок, ни предупреждений. По длительности шага рассылки письмо ушло во всех 258 запусках без поручений (44% запусков, около 22 писем в день) с пометкой {{WARN}}. Причина предупреждения (по портфелю уже есть поручение, деньги не отправлены на брокерский счет, не хватает средств) выводится только в отчет, а отчет прикладывается к письму, только когда создано хотя бы одно поручение. В таком письме остается одна фраза "Данных для создания неторговых поручений не найдено." без портфелей и причины. Кроме того, текст письма уходит как HTML без разметки, и переносы строк, скорее всего, теряются.

h3. Предложение

Оптимизацию по скорости не делать, задачу закрыть (совпадает с решением 06.10 по IMDEV-9531 обработку не менять). Если заказчик согласует изменение писем - отдельной задачей пункты П, Д и заодно дешевые 13.1-13.2.
