# IMDEV-9748. Замеры ПРОД (розница) 16.10-02.11.2026

Источник: `Замеры_октябрь2026_ФО_Розница.xlsx` (выгрузка РС `ЗамерыВремени` ПРОД розница, 34 347 замеров
с 03.10 по 03.11, конфигурация 1.4.9.5). Время - локальное (колонка "Дата записи локальная").

## Что относится к обработке

ВО `внЗагрузкаНеторговыхПорученийРОСТ` пишет три ключа (точки замера добавлены в IMDEV-9530):

| Ключ | Что измеряет | Вес | Замеров |
|---|---|---|---|
| `ЗагрузкаНеторговыхПорученийРОСТ` | Весь запуск: `СоздатьПоручения` + `РассылкаОтчета`; признак ошибки = `ВажностьОшибки = 2` | Макс(поручений, 1) | 587 |
| `.СозданиеПоручений` | `СоздатьПоручения` целиком: статусы "ДС выведены", позиция FIX, три запроса остатка, портфели, 1С:ДО, запись поручений | Макс(поручений, 1) | 587 |
| `.Рассылка` | `РассылкаОтчета`: xlsx-вложение и отправка письма | 1 | 587 |

Комментарий замера содержит "Поручений создано: N". Вес совпадает с Макс(N, 1) во всех 587 запусках. Остальные
ключи выгрузки (лимиты, "Создание торговых поручений РОСТ" - отдельная обработка задачи 9531, "Распорядитель",
"Отправка" и др.) к этой обработке не относятся.

Период: первый замер 16.10 16:10 (день установки сборки с замерами), далее 11 полных рабочих дней 19.10-02.11.
Запуски каждые 10 минут 10:00-18:30, 52 в день, пропусков нет. Выходные (24-25.10, 31.10-01.11) - запусков нет
(выход по `КалендарьБиржи` до начала замера).

## Стоимость шага создания

Линейная зависимость по 587 запускам: `СозданиеПоручений` = 2,64 с + 0,63 с x N (N - созданные поручения).

- Постоянная часть (пустой запуск не в начале часа): медиана 2,1 с, среднее 2,3 с. Это статусы "ДС выведены",
  позиция FIX, запросы `ПолучитьСуммуКупоны`, `ПолучитьСуммуСделкиПродажи`, `ПолучитьСуммуСделкиПодПокупки`,
  `ПолучитьПортфелиДляСозданияПоручений` и вызовы `GetAgreementAmount` по портфелям в статусах поиска. На эту
  часть направлены резервы 13.1 и 13.2.
- На поручение: 0,63 с (оценка анализа 28.10 по одному дню - 0,55 с). Максимум за период - 42 поручения за
  27,8 с (19.10 10:10).

## Наблюдения

1. **Пакет утром в 10:10.** Запуск 10:00 каждый день создает 0 поручений и длится 5,8-13,4 с, запуск 10:10
   создает основную массу за день: 11-42 поручения, 9,9-28,2 с. По замерам причину не видно; вероятно, к 10:00
   еще нет денег на брокерском счете (позиция FIX) или данных в 1С:ДО. Для оптимизации не критично.
2. **Начало часа медленнее.** Запуски в :00 - пустое создание в среднем 4,1 с против 2,1-2,4 с в остальные
   минуты, рассылка 1,2-2,9 с против 0,3-0,7 с. Совпадает с запуском почасовых заданий ФО (лимиты, проверки) -
   конкуренция за сервер, а не код обработки.
3. **Письмо уходит на каждом запуске.** `РассылкаОтчета` выходит без письма только при N = 0 и
   `ВажностьОшибки = 0`. Во всех 258 пустых запусках шаг рассылки занял от 0,22 с (медиана 0,34 с) - значит,
   письмо отправлялось и в них: `ВажностьОшибки` поднята до 1 (строки "уже есть поручение" или "ДС поступили на
   ЕРС, на брокерский счет не отправлены"). Итого около 52 писем в день, рассылка - 41 с в день и все выбросы
   свыше 20 с:
   - 19.10 14:00 - 30,1 с (запуск 35,6 с, максимум периода);
   - 23.10 11:00 и 11:10 - по 21,0 с.
   Выбросы - время почтового сервера, в коде не ускоряются. Нужно ли письмо при N = 0 и только
   предупреждениях - вопрос к заказчику.
4. **Две ошибки.** 27.10 14:10 и 02.11 14:00 - `ВажностьОшибки = 2` (исключение, отказ 1С:ДО или FIX, ошибка
   записи). Текст есть только в журнале регистрации ("Расчет произведен с ошибками") и в письме; по замерам
   причину не установить.

## Вывод

Данные за 11 рабочих дней подтверждают оценку анализа 28.10: обработка узким местом не является - 234 с работы
в день (около 0,8% окна 10:00-18:40), медиана запуска 3,6 с, 10-минутный интервал не перекрывается ни разу.
19.10, по которому делалась оценка, - один из самых тяжелых дней периода.

Эффект резервов по замерам:

- 13.1 + 13.2 - снижают постоянные 2,1-2,6 с на запуск; при снижении на 1 с экономия около 52 с в день.
- 13.3 - меньше вызовов 1С:ДО по портфелям с поручением; по замерам вызовы отдельно не видны, эффект оценить
  нельзя.
- Отказ от письма при N = 0 без ошибок (наблюдение 3) - около 0,34 с x ~23 запуска = 8 с в день и меньше
  писем; меняет поведение, на согласование.

Ни один резерв заметного выигрыша по времени не дает. Рекомендация: оптимизацию по скорости не делать;
если обработку все же менять - 13.1-13.2 как дешевые правки плюс решение по письмам при N = 0.

Открытые вопросы:

- Почему запуск 10:00 никогда не создает поручений, а 10:10 создает пакет (ожидаемо ли это).
- Причина ошибок 27.10 14:10 и 02.11 14:00 - нужен журнал регистрации ПРОД за эти минуты.
- Нужны ли письма каждые 10 минут без созданных поручений.
- `ОтправитьПоручения` не вызывается - поручения этой обработкой не отправляются (вопрос из анализа 28.10).
