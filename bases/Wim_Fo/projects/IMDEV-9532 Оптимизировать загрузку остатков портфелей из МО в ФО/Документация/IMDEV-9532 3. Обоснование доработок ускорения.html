Шаг 4 пакета, запись флагов после позиции, занимает около 60% времени выгрузки остатков. На каждый портфель он пишет три флага лимитов, и каждая запись сохраняет версию портфеля в истории изменений. Два флага из трех к этому моменту уже имеют присланное значение: "позиция выгружена = Нет" записал шаг 1 (флаг до позиции), "есть ошибки = Нет" не меняется. Доработка 1 пропускает запись, если значение флага в регистре уже такое же, поэтому регистр после пакета тот же, что при штатной записи. Доработка 2 убирает два запроса на строку: поиск свойства и чтение его типа выполняются один раз на пакет.

На стенде в 5 потоков шаг 4 стал быстрее в 2,7-2,9 раза, выгрузка целиком на 33%. Данные ФО после 14 парных прогонов совпали построчно. Для ПРОД ожидается 25-28 минут вместо 41.

1. Как работает загрузка

Жизненный цикл флагов за одну утреннюю выгрузку

МО отправляет портфели пакетами по 45 штук, на пакет пять обращений к ФО (ниже). Шаги 1 и 4 приходят в ФО как строки регистра ДополнительныеСведения и записываются процедурой ОбработатьДанные_ДополнительныеСведения: одна запись менеджером записи на строку. Последний вызов пакета запускает фоновый перерасчет РСА, который снимает признак перерасчета и ставит "позиция выгружена = Да".

2. Куда уходит время

Что стоит за одной записью флага

Цепочка одной записи

  1. ПередЗаписью набора записей регистра: версия портфеля. Портфель читается целиком, упаковывается, считается контрольная сумма, в историю пишется новая версия и данные предыдущей.
  2. Запись строки регистра ДополнительныеСведения.
  3. ПриЗаписи: подписка расширения ВТБ_Прод, четыре поиска свойств по реквизиту "Имя", и подписки управления доступом.

Перед записью штатный код еще выполняет два запроса: поиск свойства по наименованию и чтение его типа значения.

Факты с ПРОД

  • История изменений включена, для справочника "Портфели" вариант "при записи" (проверено на тестовой копии ПРОД 29.09.2026).
  • Около 10 версий на портфель в день, у выбранных портфелей накоплено 3 213-3 263 версии с октября-ноября 2025.
  • Профиль выгрузки пакетами по 45 портфелей (01.07.2026, 470 пакетов): флаги после позиции (шаг 4) - 59,5% времени (в среднем 22,0 с на пакет), флаг до позиции (шаг 1) - 20,6% (7,6 с), позиция (шаг 2) - 13,6% (5,0 с), перерасчет РСА - 2,7% (1,0 с).
  • Утренняя выгрузка 29.09.2026: 23 041 портфель, 5 потоков, около 41 минуты.
3. Доработка 1

Пропуск записи флага, значение которого не изменилось

Правило. Строка пакета не записывается, если ее значение булево и в регистре у этого объекта уже есть запись этого свойства с тем же значением. Во всех остальных случаях запись выполняется штатно.

Почему результат тот же

1
Регистр после пакета тот же
Запись менеджером записи заменяет значение по ключу "объект - свойство". Если по этому ключу уже лежит то же значение, после записи регистр не меняется. Пропускается ровно такая запись. Повторы ключа внутри пакета сравниваются с только что записанным значением, поэтому последовательность записей дает тот же итог.
по построению
2
Обработчики записи ни на что не влияют для таких строк
Подписка ВТБ_Прод действует только для свойств эталонного портфеля и только при заполненном ссылочном значении: для флагов Да/Нет она ничего не делает. Наборы значений доступа не зависят от неизменной строки. Небулевы значения исключены из правила специально: на их запись есть обработчики с действиями, например распространение правил при записи эталонного портфеля.
разобрано по коду
3
История изменений теряет только дубли
Версия пишется перед записью и фиксирует состояние портфеля до нее. Перед неизменившимся флагом это состояние совпадает с соседней версией. Настройки истории изменений не трогаются, версии с изменениями пишутся как раньше.
настройки без изменений
4
Параллельный фоновый перерасчет не ломает логику
Текущие значения читаются перед решением о записи. Если перерасчет меняет флаг между чтением и решением, итог совпадает с тем порядком штатного кода, в котором штатная запись выполнилась до записи перерасчета. Шаг 4 идет после загрузки позиции (шаг 2), поэтому любой перерасчет портфеля после этого момента считает уже новую позицию.
допустимый порядок
5
Скрытые правами записи
Запрос текущих значений выполняется с РАЗРЕШЕННЫЕ. Недоступная запись считается отсутствующей, и флаг пишется, как в штатном коде. Веб-сервис при этом работает в привилегированном режиме, и ограничение на практике не срабатывает.
безопасный вариант

Стоимость проверки

Один запрос к регистру по объекту на пакет, при первой булевой строке объекта. На шаге 1 флаг всегда меняется, поэтому там добавляется только этот запрос, около 1 мс на портфель на стенде. На шаге 4 он заменяет две записи с версиями портфеля.

4. Доработка 2

Поиск свойства и приведение значения один раз на пакет

Правило. Свойство ищется по наименованию один раз на наименование в пакете. Результат штатной функции приведения значения запоминается для пары "свойство - значение из пакета", если значение из пакета примитивное (Булево, Строка, Число, Дата).

Оба действия детерминированы в пределах пакета: наименования свойств и значения справочников не меняются за время одного вызова веб-сервиса. Кэш живет только внутри вызова и не переносится между пакетами. Ненайденное свойство тоже запоминается, а ошибка обмена записывается по каждой строке, как раньше.

8. Приемка

План проверки на тестовой копии ПРОД

  1. Подключить расширение, но оставить неактивным. Выполнить выгрузку остатков в 5 потоков. Зафиксировать время, письмо об итогах, ошибки обмена.
  2. Активировать расширение с выключенным безопасным режимом. Повторить выгрузку на той же копии. Флаги после первого прогона уже в штатном состоянии, поэтому прогоны сравнимы.
  3. Критерии приемки: число загруженных портфелей и ошибок в письме совпадает; распределение флагов лимитов (запрос 1) совпадает; новых версий на портфель на 2 меньше (запрос 2); время выгрузки меньше.
