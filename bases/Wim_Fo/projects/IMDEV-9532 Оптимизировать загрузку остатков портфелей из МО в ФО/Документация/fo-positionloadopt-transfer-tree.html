Аванкор, фронт-офис, перенос в базовую конфигурацию, IMDEV-9532

Дерево изменений расширения FO_PositionLoadOpt

Базовая конфигурация "Аванкор: Фронт-офис" 1.4.9.5. Расширение FO_PositionLoadOpt версии 1.0.0.5 (синоним "Оптимизация загрузки остатков портфелей из МО", назначение Patch, префикс FO_PositionLoadOpt_). Новых объектов метаданных и ролей нет: два заимствованных объекта, правки только в модулях. Отдельно к переносу добавлен индекс реквизита документа Поручение: его нельзя сделать расширением, это изменение метаданных конфигурации.

Версия 1.0.0.5 = 1.0.0.4 без изменений логики + замер производительности загрузки регистра дополнительных сведений: четыре вставки в ту же процедуру, новых функций нет (блок "замер" ниже). Предыдущая версия 1.0.0.4 отличается только отсутствием этих вставок.

В типовую копировать тело правок. Аннотацию &ИзменениеИКонтроль не копировать. Маркеры #Вставка, #КонецВставки, #Удаление, #КонецУдаления не переносить: вставленный текст оставить, удаленный текст убрать из штатной процедуры. Префикс с имен перехватчиков снять и править штатные процедуры на месте. Новые функции уже без префикса, их копировать целиком в тот же модуль.

Небулевы значения пишутся всегда: на их запись в конфигурации есть подписки с действиями. На шаге "флаги после позиции" из трех записей на портфель обычно остается одна. Обоснование

  • идея 3 Технические флаги обмена писать без версии портфеля

    Перед записью набора регистра дополнительных сведений версия портфеля не создается, если отбор набора установлен по свойству и это один из трех флагов лимитов, которые МО присылает в пакете: "Лимиты позиция_выгружена", "Лимиты требуется_перерасчет_РСА", "Лимиты есть_ошибки_выгрузки_позиции". Правило стоит в регистре, поэтому действует и для загрузки обмена, и для перерасчета РСА. Дата пересчета РСА и все остальные свойства версионируются как раньше, настройка истории изменений не меняется. Изменение истории изменений согласуется с ее владельцем. Обоснование

  • замер Замер производительности загрузки регистра (версия 1.0.0.5)

    Ключевая операция для оценки производительности загрузки остатков: время загрузки дополнительных сведений одного пакета. Пишется штатной подсистемой БСП "Оценка производительности" одной записью регистра "Замеры времени" на пакет и только если пакет содержит дополнительные сведения и включена константа "Выполнять замеры производительности". Ключ ОбменБэкОфис.РегистрыСведений.ДополнительныеСведения, вес - число разных найденных портфелей (если портфелей нет - строк пакета), комментарий Строк: N; Портфелей: M; Записано: K; Пакет: УИД. Разница "Строк" и "Записано" показывает, сколько флагов идея 1 пропустила без записи. Результат загрузки не меняется: замер только считает строки и время.   • метаданные Индекс реквизита ВнешнийКод документа Поручение

    Не входит в расширение: индексирование заимствованного реквизита в расширении не меняется. Добавляется в конфигурации Аванкор.

    Где тратится время. Выгрузка остатков МО по каждому портфелю с блокировками отправляет в ФО пакет поручений "Вывод" (операция веб-сервиса ЗагрузитьПоручения). ФО ищет каждое поручение по внешнему коду: ОбработатьДанные_Поручения -> Поручение() -> ДокументПоРеквизиту("Поручение", "ВнешнийКод", ...), запрос с отбором по ВнешнийКод.

    Почему медленно. Реквизит ВнешнийКод не индексируется, поэтому каждый поиск перебирает всю таблицу поручений. В замере обычной ФО один поиск занимал 0,5-1,9 с, это около половины времени загрузки пакета поручений. С ростом числа поручений поиск замедляется.

    Что сделать. У реквизита ВнешнийКод (Строка, 36) документа Поручение установить свойство "Индексировать". Логика и данные не меняются, при обновлении базы данных строится индекс по реквизиту.

        • метаданные ВнешнийКод - свойство "Индексирование": "Не индексировать" -> "Индексировать". Поиск ДокументПоРеквизиту по этому реквизиту выполняется для поручений при каждой загрузке.
        • по желанию Идентификатор - тот же поиск используется, когда внешний код в пакете не заполнен. В замерах этот путь не встречался, индекс не обязателен.

Не переносить

  • Язык Русский и свойства расширения. Это оболочка расширения, ролей в нем нет.
  • Аннотации расширения, маркеры #Вставка и #Удаление, префиксы перехватчиков.
  • Штатные НайтиПоНаименованию, ПреобразоватьЗначениеДополнительногоСведения, ВерсионированиеОбъектов.ЗаписатьВерсиюОбъекта, ОценкаПроизводительности. Их вызывают как есть.
  • Метаданные регистра ДополнительныеСведения и плана видов характеристик ДополнительныеРеквизитыИСведения, настройку истории изменений портфелей.
  • Обработки перерасчета РСА и выгрузки остатков МО, расширение ВТБ_Прод. Они не меняются.

Порядок в коде загрузки пакета

  1. Идея 2. Для строки пакета свойство и значение берутся из кэша пакета.
  2. Идея 1. Если булев флаг уже имеет это значение, строка пропускается, запись не выполняется.
  3. Идея 3. При записи флага лимитов обработчик ПередЗаписью регистра не создает версию портфеля.
  4. Индекс. Отдельно от пакета флагов: при загрузке поручений блокировок поиск поручения по внешнему коду идет по индексу.
  5. Замер. Время отсчитывается от начала процедуры; после цикла по строкам пакета пишется одна запись замера с числом строк, портфелей и записанных строк.

Идеи независимы по результату загрузки: каждую можно перенести отдельно. Идеи 1 и 2 вносятся в одну процедуру, общий блок с кэшами переносится один раз. Индекс не зависит от расширения и дает эффект сам по себе. Замер не влияет на результат загрузки и переносится вместе с процедурой.
