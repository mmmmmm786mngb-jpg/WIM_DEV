# Диагностика сервиса депозитов ПИФ на Т-1

Обработка `ДиагностикаСервисаДепозитовПИФ.epf` (версия 1 от 28.10.2026) только читает данные: ничего не записывает,
не проводит и не отправляет. Она выполняет запрос функции `ТаблицаДепозитов` веб-сервиса deposits (операция
`getDeposits`) по частям с замером каждой части, вариант запроса с оптимизациями со сверкой результата построчно,
проверяет реквизиты банковских счетов и роли пользователя сервиса. Результат - текстовый лог, его нужно прислать
обратно.

Запускать на копии Т-1 базы ПИФ, не на ПРОД: прогон нагружает сервер СУБД так же, как 2-3 вызова сервиса подряд.

## Запуск

1. Открыть Т-1 ПИФ пользователем с полными правами (нужен список пользователей ИБ для раздела 1).
   База работает в обычном приложении: обработка открывается в толстом клиенте, форма управляемая - это штатно.
2. Файл - Открыть - `ДиагностикаСервисаДепозитовПИФ.epf`. Если платформа спросит про защиту от опасных действий -
   разрешить.
3. Поле "Дата запроса" - оставить текущую (Фронт-офис вызывает сервис в 05:00 с текущей датой).
4. Поле "Пользователь сервиса" - имя пользователя ИБ ПИФ, под которым Фронт-офис вызывает сервис deposits
   (логин из настроек обработки загрузки депозитов ФО). Если неизвестно - оставить пустым: раздел 1 все равно
   покажет всех пользователей с ролью РаботаСWS.
5. Флажок "Повторить исходный запрос в конце" - оставить включенным.
6. Флажок "Подсчет проводок по годам" - включить, если время позволяет (полный просмотр регистра Управленческий,
   ожидаемо 10-30 минут сверху).
7. "Собрать лог" и дождаться окончания. Ожидаемое время без подсчета проводок - 25-35 минут: исходный запрос
   выполняется дважды (по замеру из ФО это 11,5 минут на вызов) плюс вариант с оптимизациями.
   Клиент в это время не отвечает - это нормально, окно не закрывать.
8. "Сохранить в файл (txt)" и прислать файл.

## Что в логе

| Раздел | Зачем |
|---|---|
| 0 | Конфигурация, дата запроса, состояние итогов регистра Управленческий (без итогов Остатки и Обороты читают проводки) |
| 1 | Есть ли у пользователя сервиса роль РаботаСWS. Без нее сервис не включает привилегированный режим, и запрос по регистру идет с ограничением доступа на уровне записей - возможная причина медленного ответа, которую не видно в замере под администратором |
| 2 | Первая дата регистра, депозитные счета по году открытия, объем регистра АлгоритмыРасчетаПроцентов |
| 3 | Исходный запрос сервиса по частям (6 частей + сборка ответа): время и строки каждой части - где именно уходят 11 минут |
| 4 | Вариант с оптимизациями: начало периода у оборотов и движений по самой ранней дате открытия депозитов, одно чтение ДвиженияССубконто вместо двух, соединение по ссылке на валюту, срез алгоритмов с отбором. Время по частям и построчная сверка итога и промежуточных частей с исходным (СОВПАДАЕТ / ЕСТЬ РАСХОЖДЕНИЯ) |
| 5 | Можно ли брать дату выдачи и начальную сумму из реквизитов счета (ДатаОткрытия, НоминалДепозита): сколько пустых, совпадающих, отличающихся; пустой datestart |
| 6 | Вопросы по смыслу: задвоение строк в частях, повторное использование счетов под новые депозиты, начисленные проценты в marketvalue против остатка счета 76.20.2 |
| 7 | Повтор исходного запроса на прогретом кэше и сверка с первым прогоном |
| 8 | Число проводок по годам и движений выдачи без начала периода и с ним (только с флажком) |
| 9 | Сводка замеров всех прогонов |

## Что скрыто

Номера банковских счетов выводятся как порядковый номер и последние 4 цифры, банки не выводятся. Имена пользователей
ИБ выводятся только для служебных учетных записей (svc, ws, fo, сервис, обмен и т.п.), остальные - как
"<пользователь>". Суммы депозитов и процентов выводятся в примерах расхождений разделов 4-6.

Текст запроса взят из конфигурации ПаевыеФонды 2.12.9.5. Если на Т-1 другая версия (раздел 0), лог все равно
полезен, но вывод о совпадении с сервисом нужно сверить с модулем сервиса этой версии.
