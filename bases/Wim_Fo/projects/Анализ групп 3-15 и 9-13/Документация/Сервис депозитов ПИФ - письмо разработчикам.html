Аванкор ПИФ 685-692 с (11,5 мин) 72

Вся загрузка депозитов во Фронт-офисе занимает 12-20 минут, обработка на стороне Фронт-офиса - секунды. Сервис вызывают две базы Фронт-офиса одновременно (ФО и ФО Розница), поэтому ПИФ в 05:00 выполняет этот запрос дважды.

Как устроен запрос

Функция ТаблицаДепозитов выполняет один пакетный запрос из шести частей по регистру бухгалтерии Управленческий:

Часть пакета Что читает Оценка нагрузки
1. ОстаткиДепозитов Остатки на дату по расчетным, валютным и специальным счетам с отбором по реквизитам банковского счета умеренная (используются итоги)
2. ПроцентыПоДепозитам Обороты по счету процентов без начала периода с отбором по корреспондирующему счету и субконто высокая: вся история проводок
3. ПроцентыЗаДень Те же обороты за один день низкая
4. ДатыВыдачи ДвиженияССубконто без начала периода: самая ранняя дебетовая проводка по каждому депозитному счету очень высокая: вся история
5. ПервоначальныеСуммы Повторно та же виртуальная таблица ДвиженияССубконто за всю историю, соединение с ДатыВыдачи по выражению очень высокая: история читается второй раз
6. Итог Соединение частей и среза последних АлгоритмыРасчетаПроцентов без отбора низкая-умеренная

Главная причина медленной работы, по нашей оценке, - части 4 и 5: ДвиженияССубконто самая тяжелая виртуальная таблица регистра бухгалтерии (раскрывает каждую проводку по субконто и корреспонденции), и здесь она читается дважды с начала истории ради двух значений на каждый счет - даты первой выдачи и суммы этой выдачи. Вторая по весу - часть 2. Точное распределение просим подтвердить замером по частям (способ ниже).

Что предлагаем исправить и почему

  1. Убрать части 4 и 5: дату выдачи и начальную сумму брать из реквизитов банковского счета. В справочнике БанковскиеСчета уже есть реквизиты ДатаОткрытия и НоминалДепозита. Если они заполнены у всех действующих депозитных счетов и совпадают с тем, что сейчас вычисляет запрос, обе части не нужны, и чтение истории проводок исчезает полностью. Заполненность проверяется запросом из раздела "Как проверить".
    Если реквизиты заполнены не у всех счетов - запасной вариант: читать ДвиженияССубконто один раз и с началом периода, равным самой ранней дате открытия действующих депозитов (раньше даты открытия проводок выдачи по счету быть не может), а не дважды с начала истории. Еще дешевле - сохранять вычисленную начальную сумму (после выдачи она не меняется) и досчитывать только новые счета.
  2. Часть 2: задать начало периода у оборотов по счету процентов. Обороты с отбором по корреспондирующему счету и субконто не могут использовать итоги регистра, поэтому без начала периода платформа читает все проводки по счету процентов за всю историю. Началом периода можно взять ту же самую раннюю дату открытия действующих депозитов: результат не изменится, если до открытия депозита процентов по его счету не было.
    Если по смыслу нужен остаток начисленных и еще не выплаченных процентов, правильнее брать остатки по счету процентов (с итогами, быстро) - но это меняет смысл поля marketvalue, см. вопросы ниже.
  3. Соединять по ссылке на валюту, а не по наименованию. В частях 4, 5 и в итоговом соединении валюта сравнивается как ЕСТЬNULL(Валюта.Наименование, ...): это разыменование в условии соединения, оно мешает использовать индексы временных таблиц. Достаточно сравнивать саму ссылку на валюту (пустая ссылка - валюта регламентированного учета).
  4. Срез АлгоритмыРасчетаПроцентов - с отбором и через временную таблицу. Сейчас срез последних берется по всем объектам регистра и соединяется с запросом напрямую. Нужен отбор Объект В (счета из ОстаткиДепозитов) в параметрах среза и помещение результата во временную таблицу с индексом.
  5. (По желанию) Кэш ответа на дату. Две базы Фронт-офиса запрашивают в 05:00 одно и то же на одну дату. Если сохранять ответ сервиса на день запроса (например, на час), второй вызов отдаст готовый результат. Параллельно мы уточняем у бизнеса, нужна ли загрузка депозитов в ФО Розница вообще: если нет, второй вызов исчезнет.

Как проверить

1. Где именно время. На тестовой копии выполнить части пакета по отдельности с общим менеджером временных таблиц и замером каждой:

МенеджерВТ = Новый МенеджерВременныхТаблиц;
Номер = 0;
Для Каждого ТекстЧасти Из СтрРазделить(ТекстЗапроса, ";", Ложь) Цикл
	Номер = Номер + 1;
	Запрос = Новый Запрос(ТекстЧасти);
	Запрос.МенеджерВременныхТаблиц = МенеджерВТ;
	Запрос.УстановитьПараметр("ДатаЗапроса", ДатаЗапроса);
	Запрос.УстановитьПараметр("ПустаяДата", '00010101');
	Запрос.УстановитьПараметр("НаименованиеВалютыРегламентированногоУчета", НаименованиеВалюты);
	Начало = ТекущаяУниверсальнаяДатаВМиллисекундах();
	Запрос.Выполнить();
	ОбщегоНазначения.СообщитьПользователю(СтрШаблон("Часть %1: %2 мс", Номер,
		ТекущаяУниверсальнаяДатаВМиллисекундах() - Начало));
КонецЦикла;

2. Можно ли брать дату и номинал из счета. Сколько действующих депозитных счетов без даты открытия или номинала:

ВЫБРАТЬ
	КОЛИЧЕСТВО(*) КАК Счетов,
	СУММА(ВЫБОР КОГДА Счета.ДатаОткрытия = ДАТАВРЕМЯ(1, 1, 1) ТОГДА 1 ИНАЧЕ 0 КОНЕЦ) КАК БезДатыОткрытия,
	СУММА(ВЫБОР КОГДА Счета.НоминалДепозита = 0 ТОГДА 1 ИНАЧЕ 0 КОНЕЦ) КАК БезНоминала
ИЗ
	Справочник.БанковскиеСчета КАК Счета
ГДЕ
	Счета.НачислениеПроцентов
	И НЕ Счета.ПометкаУдаления
	И (Счета.ДатаЗакрытия = ДАТАВРЕМЯ(1, 1, 1)
		ИЛИ Счета.ДатаЗакрытия >= &ДатаЗапроса)

Затем сверить для этих счетов ДатаОткрытия и НоминалДепозита с полями datestart и initialvalue текущего ответа сервиса.

3. Приемка. Ответ сервиса до и после правок на одну дату совпадает построчно (сейчас 72 депозита, все поля), время ответа - не более 1 минуты.

Вопросы по смыслу (возможные ошибки в текущей логике)

  1. marketvalue = остаток на счете + все начисленные проценты за всю историю (обороты по счету процентов, без учета выплаченных или капитализированных). Так задумано? Если проценты по депозиту выплачивались или капитализировались, стоимость депозита может быть завышена.
  2. Начальная сумма берется по самой первой выдаче на этот банковский счет за всю историю. Если счет использовался для нескольких депозитов подряд, Фронт-офис получит сумму первого депозита, а не текущего. Используются ли счета повторно?
  3. Задвоение депозита. Если в момент первой выдачи по счету есть две дебетовые проводки с одинаковым временем, часть 5 вернет две строки, и депозит придет во Фронт-офис дважды.
  4. datestart берется из среза АлгоритмыРасчетаПроцентов и будет пустым, если алгоритм для счета не задан. Не правильнее ли брать ДатаОткрытия счета?

Для сведения: сервис deposits базы ДУ построен похоже (начальный номинал считается по таблице движений денежных средств без начальной даты), но отвечает за 70 секунд - это вторая очередь.
