# Для разработчиков: объекты 1С по строкам

Для каждой строки: чем запускается процесс, откуда берет настройки и данные, к каким внешним системам обращается
и какие объекты 1С создает или меняет. Сокращения: ВО - внешняя обработка (справочник
`ДополнительныеОтчетыИОбработки`), РС - регистр сведений, РН - регистр накопления, РЗ - регламентное задание,
ОМ - общий модуль. Источник - выгрузки CF 1.4.10.0 и ВО с ПРОД (`WORK\WIM_Fo\src`).

## Строка 3. Установка лимитов (распространение правил на новых клиентов)

**Запуск**

| Шаг | Объект 1С | Что делает |
|---|---|---|
| 1 | Веб-сервис `Avancore`, операция `DownloadPosition` | МО присылает пакет остатков; в комментарии пакета - JSON с параметрами обмена, в том числе `ТребуетсяРаспространениеПравил` |
| 2 | Обработка `ОбменДаннымиБэкОфис.ЗагрузитьПакет` -> `ВыполнитьОперацииПослеОбмена` | После загрузки данных пакета берет ВО из константы `ОперацииПослеОбмена` |
| 3 | ВО `внОперацииПослеОбмена` 1.10, `ВыполнитьОбработку(ОбъектЗапрос)` | Разбирает JSON; ветки взаимоисключающие: перерасчет РСА, иначе удаление блокировок, иначе распространение правил |
| 4 | ВО `внРаспространениеПравилСОдногоКлиентаНаСписокКлиентов` 1.16 (настройка `ОбработкаРаспространенияПравил`), `ВыполнитьРаспространениеПравилПослеОбмена` | Распространение правил; выполняется в сеансе веб-сервиса (в замерах ПРОД - пользователь `svc_web`) |
| - | Та же ВО, команда `ФоновоеВыполнение` | Не распространение, а отдельная проверка: портфели без установки лимитов за последние сутки (`НайтиПортфелиБезУстановокЛимитов`) и письмо |
| - | Та же ВО, форма | Ручное распространение (`ВыполнитьРаспространение`) |

**Настройки:** `ХранилищеНастроек` ВО распространения - классы лимитов `КлассЛимитовКомплаенс` / `КлассЛимитовРиски`,
свойства дополнительных сведений по классам (дата автоустановки, эталонный портфель, внешний код эталона, лимиты
заведены, дата распространения), списки типов клиентов, настройки рассылки (справочник `НастройкиРассылкиПисем`),
признак `ЭтоБазаРозничногоДУ`.

**Читает:** справочник `Портфели`, РС `ДополнительныеСведения`, срез РС `ДействующиеЛимитыПоПортфелю`, документ
`УстановкаЛимитов` (табличная часть `Лимиты`), РС `ПорогиЛимитов`.

**Создает и меняет**

| Объект 1С | Что пишется |
|---|---|
| Документ `УстановкаЛимитов` | Новый документ на пару портфель+класс (`ВидОперации = ПоПортфелю`, лимиты из эталонной установки), проведение. Движения документа: РС `ДействующиеЛимитыПоПортфелю`, `ДействующиеЛимитыПоГруппамПортфелей`, `ДействующиеЛимитыПоТипуКлиента`, `ДействующиеЛимитыПоСтратегии` |
| РС `ПорогиЛимитов` | Порог по каждому лимиту эталона без действующего порога (портфель, лимит, начало дня); в рознице с `ОбменДанными.Загрузка` |
| РС `ДополнительныеСведения` | По портфелю: дата автоустановки лимитов, эталонный портфель, внешний код эталона (обычный ФО), дата распространения правил, "лимиты заведены". По документу `УстановкаЛимитов`: признак стратегии |
| Почта (`РаботаСПочтовымиСообщениями`) | Письмо с вложением XLS (временный файл, не удаляется) на каждую пару; итоговое письмо по классу; в обычном ФО под сервисным пользователем - письмо об успешном автораспространении |
| Фоновое задание "Запись версий лимитов" (только розница) | `ВыполнитьЗаписьВерсийЛимитов`: пауза, затем версии элементов справочника `Лимиты` через `ВерсионированиеОбъектов` (РС `ВерсииОбъектов`) |
| Параметр сеанса `ОтключениеОбновленияКлючейДоступа` | В рознице перед постановкой задания включается полное отключение обновления ключей доступа |
| РС `ЗамерыВремени` | Ключи `РаспространениеПравилЛимитов*` (IMDEV-9530) |

После распространения `внОперацииПослеОбмена` вызывает свою процедуру `ПроверкаНаличияЗаписиСтатусаПортфеляВРегистре`.

## Строка 15. Исполнение сделок

**Запуск**

| Шаг | Объект 1С | Что делает |
|---|---|---|
| 1 | РЗ `АванкорИсполнениеСделок` ("Исполнение сделок"), предопределенное | Расписание хранится в базе (по таблице ключевых операций - 23:55) |
| 2 | ОМ `АванкорВыполнениеРегламентныхЗаданий.ИсполнениеСделок` | Дата запуска со смещением фактической позиции, событие ЖР "Аванкор. Исполнение сделок", создание обработки с `НаДату` |
| 3 | Обработка `ГрупповоеИсполнениеСделок.СоздатьДокументыИсполнения(Истина)` | `ЗаполнитьТаблицуСделок` (без отбора по портфелям), затем цикл создания документов |
| - | Форма обработки `ГрупповоеИсполнениеСделок` (подсистема `ЗаявкиИСделки`) | Ручной запуск: "Заполнить" (отбор по портфелям и группам портфелей), "Создать документы" (`СоздатьДокументыИсполнения(Ложь, ...)`), "Настроить расписание" |

**Читает:** РН `ПлановаяПозиция` (виртуальная таблица остатков на конец дня), документ `Сделка` (`ДатаПоставки`,
`ВидОперации`, `Внебиржевая`, `Поручение.Биржа.Внебиржевая`), справочник `Активы`.

**Создает и меняет**

| Объект 1С | Что пишется |
|---|---|
| Документ `ИсполнениеПоСделке` | Документ на каждую строку остатка (бумага или деньги по сделке), `Дата = НаДату`, проведение |
| РН `ПлановаяПозиция` | Расход остатка плановой позиции по сделке |
| РН `ЗадолженностьПоБумаге` / `ЗадолженностьПоВалюте` | Расход задолженности по поручению сделки (если поручение есть) |
| РС `СделкиДляОбмена` | Запись с текстом XDTO для обмена (при включенной опции API `GetListOfDeals`) |
| РС `РасширенияПоручений` | Пересчет данных исполнения поручения сделки (`ОбновитьДанныеИсполнения`), на каждый документ |
| РС `СтатусыПоручений` | Расчетные статусы поручения (`ОбработатьРасчетныеСтатусыРасш`) |
| Журнал регистрации | Событие "Аванкор. Исполнение сделок" при старте |
| РС `ЗамерыВремени` | Ключи `ИсполнениеСделок*` - в 1.4.10.0 базовым кодом, в 1.4.9.5 только с FO_KeyOpsPerf |

## Строка 9. Загрузка депозитов

**Запуск**

| Шаг | Объект 1С | Что делает |
|---|---|---|
| 1 | РЗ БСП `ЗапускДополнительныхОбработок` | Запуск команды дополнительной обработки по расписанию (05:00, пользователь `svc_avancore`) |
| 2 | ВО `внЗагрузкаДепозитовИзВнешнихИсточников` 1.19, команда `ФоновоеВыполнение` (вызов серверного метода) | `ВыполнитьКоманду`: `ЗаполнитьДепозиты` -> `ОбновитьФактическуюПозицию` -> письмо |
| - | Та же ВО, команда `ОткрытиеФормыОбработки` | Ручной режим: загрузка из всех источников, только из Аванкора, только из Calipso, сопоставление депозитов с местами хранения, обновление позиции, рассылка, очистка депозитов |

**Настройки:** `ХранилищеНастроек` ВО - адреса веб-сервисов ДУ и ПИФ, логин и пароль, учетная запись почты и список
рассылки, `ОбработкаПерерасчетаСтоимости` (ссылка на ВО пересчета), `ОчищатьДепозитыПередЗагрузкой` (в фоновом
запуске не используется).

**Внешние системы**

| Источник | Вызов |
|---|---|
| База ДУ, веб-сервис `deposits` | `getDeposits(ДатаЗапроса)`: модуль `WebServices/deposits` базы ДУ (`ТаблицаДепозитов`, `ЗаполнитьНачальныйНоминал`) |
| База ПИФ, веб-сервис `deposits` | `getDeposits(ДатаЗапроса)`: модуль `WebServices/deposits` базы ПИФ |
| SQL Server `MasterData` (Calipso) | COM `ADODB.Connection` / `ADODB.Command`, таблица `t_Calipso_LoanDeposit` |

**Читает:** справочники `Валюты`, `Портфели` (`КодПортфеля`), `МестаХранения`, `Субпортфели` (`МестоХранения`,
`КодСчета`), `Активы`; РС `ДополнительныеСведения` (свойство `ИдентификаторДепозита` у места хранения); ПВХ
`ДополнительныеРеквизитыИСведения`.

**Создает и меняет**

| Объект 1С | Что пишется |
|---|---|
| РС `ВТБ_ФактическаяПозицияДепозитов` (расширение ВТБ_Прод) | Запись или обновление на дату по месту хранения (ДУ, ПИФ) или по субпортфелю (Calipso); удаление записей, которых нет в источниках |
| Справочник `БанковскиеСчета` | Реквизит `ПроцентнаяСтавка` депозитного счета (запись объекта, ДУ и ПИФ) |
| Фоновое задание БСП "Пересчет фактической позиции и РСА" | ВО `внПерерасчетСтоимостиФактическойПозицииИ_РСА_СЧА` 1.18, `ВыполнитьПерерасчетВФоне`: пишет РС `ФактическаяПозиция`, `РегистрРСА_СЧА`, `ДополнительныеСведения`, лог в РС `ВТБ_ЛогиПересчетов`. При пустом списке портфелей берет все портфели с признаком пересчета |
| Фоновое задание БСП "Рассылка после пересчета фактической позиции и РСА" | Та же ВО пересчета, `СформироватьЛогИВыполнитьРассылку`; ставится через 10 с после пересчета |
| Почта | Письмо `{OK}` / `{WARN}` / `{FAIL}` "Обновление депозитов" |
| РС `ЗамерыВремени` | Ключи `ЗагрузкаДепозитов*` (IMDEV-9530) |
| Только ручной режим | РС `ДополнительныеСведения` - `ИдентификаторДепозита` у места хранения (`УстановитьИДДепозита`); очистка РС `ФактическаяПозиция` по депозитным местам хранения (`ОчиститьДепозиты`) |

## Строка 13. Загрузка неторговых поручений РОСТ

**Запуск**

| Шаг | Объект 1С | Что делает |
|---|---|---|
| 1 | РЗ БСП `ЗапускДополнительныхОбработок` | Команда дополнительной обработки по расписанию, каждые 10 минут с 10:00, пользователь `svc_avancore` |
| 2 | ВО `внЗагрузкаНеторговыхПорученийРОСТ` 1.07, команда `ФоновоеВыполнение` (вызов серверного метода) | `ВыполнитьКоманду`: выход в нерабочий день по `КалендарьБиржи` (`КалендарныеГрафики`), затем `СоздатьПоручения` и `РассылкаОтчета` |
| - | Та же ВО, команда `ЗагрузитьПоручения` | Открытие формы обработки |

**Настройки:** `ХранилищеНастроек` ВО - `КалендарьБиржи`, `АдаптерFIX`, `КодСчетаБрокер`, адрес, логин и пароль
сервиса 1С:ДО, статусы портфеля (`СтатусДляПоиска`, `СтатусДСОтправленыБрокеру`, `СтатусДляПеревода`,
`СтатусДСВыведены`, `СтатусПоданоПоручениеНаВыводДС_СБрокера`), свойства дополнительных сведений (статус портфеля,
дата операции, `ПризнакПозицияВыгружена`, `ПризнакДатаПересчетаРСА`), `АктивРубли`,
`НеКонтролироватьДостаточностьДС`, почта и список рассылки.

**Внешние системы**

| Источник | Вызов |
|---|---|
| Адаптер FIX (справочник `Адаптеры`) | Менеджер адаптера, метод `Позиция` - остаток денег на брокерском счете `КодСчетаБрокер` |
| 1С:ДО, веб-сервис `DMService` | `GetAgreementAmount(НомерДоговора)` на каждый портфель в статусах поиска - сумма поступления и признак отправки на брокерский счет (JSON) |

**Читает:** РС `ДополнительныеСведения` (статусы и даты статусов портфелей), РС `ФактическаяПозиция` и
`КупонноеРасписаниеПоОблигациям`, документ `КупонноеРасписание` (сумма купонов, результат не используется), документ
`Сделка` (табличная часть `РаспределениеПоПортфелям`), документ `Поручение`, справочники `Портфели`, `Субпортфели`.

**Создает и меняет**

| Объект 1С | Что пишется |
|---|---|
| Документ `Поручение` | Неторговое поручение `Ввод` на сумму поступления по портфелю, проведение. Движения документа по метаданным: РН `ПланПоПоручению`, `ПрогнозПоПоручению`, `ПрогнозПоПоручениюАктивыВРЕПО`, `УтилизацияПорученийКазначейства` |
| РС `РегистрРСА_СЧА` | РСА и СЧА портфеля = сумма поступления |
| РС `ДатаАктуальностиФактическойПозиции` | Дата актуальности позиции портфеля - текущий день |
| РС `ДополнительныеСведения` | Статус портфеля и дата статуса; `ПризнакПозицияВыгружена`; `ПризнакДатаПересчетаРСА` |
| РС `ВТБ_СтатусыПортфелей` (расширение ВТБ_Прод) | История статусов портфеля |
| Почта | Письмо с вложением xlsx (через временное хранилище) при созданных поручениях или ошибках |
| Журнал регистрации | "Расчет произведен успешно" или "Расчет произведен с ошибками" |
| РС `ЗамерыВремени` | Ключи `ЗагрузкаНеторговыхПорученийРОСТ*` (IMDEV-9530) |

Поручение, РСА/СЧА, дата актуальности, статус и признаки пишутся в одной транзакции на портфель. Смена статусов
"ДС выведены" и "ДС отправлены брокеру" - вне транзакции.
