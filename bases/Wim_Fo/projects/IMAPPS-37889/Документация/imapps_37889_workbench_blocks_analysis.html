Блокировки занижают стоимость портфеля в воркбенче

ДЛЯ БИЗНЕС-ПОЛЬЗОВАТЕЛЯ

1. Ситуация по обращению

Управляющий выгрузил блокировку 20 000 000 руб. по клиенту A62021 (профиль RUB). После этого в воркбенче в колонке «Стоимость, общая по владельцу» вместо ожидаемого уменьшения портфеля на 20 млн появилось отрицательное значение.

Аналогичная ситуация наблюдалась 28.06.2026 по другому клиенту.

С блокировкой 20 000 000 руб.

Без блокировки портфель отображается корректно.

3. Почему пользователь видит «неправильные» цифры

Краткий ответ: система, по всей видимости, дважды вычитает одну и ту же блокировку при расчете итоговой стоимости портфеля. Поэтому минус получается сильнее, чем должен быть.

Ожидаемый расчет (один раз)

Фактическая сумма по деньгам (RUB): 30 512 322,63
Минус блокировка: - 20 000 000,00
= 10 512 322,63 руб. (доступная стоимость портфеля)

Если отталкиваться от общей стоимости без блокировки (~30,36 млн), ожидаемый результат после блокировки: ~10,36 млн руб.

Фактический расчет в воркбенче (два раза)

30 512 322,63
- 20 000 000,00 (первый раз)
- 20 000 000,00 (второй раз)
= -9 487 677,37 руб.

Это почти совпадает с тем, что видит пользователь: -9 489 323,91 руб. Небольшая разница (~1 646 руб.) может быть из-за округлений, НКД, задолженности или других активов в том же портфеле.

Схема для понимания

Шаг Что делает система Результат для примера
1 Показывает фактическую сумму по RUB 30 512 322,63
2 Отдельно показывает блокировку в колонке «Стоимость, блокировка» -20 000 000,00
3 При расчете «общей по владельцу» уменьшает доступные деньги на сумму блокировки -20 000 000 (скрыто в формуле)
4 И еще раз учитывает ту же блокировку во внутренней сумме «блокировка в стоимости» -20 000 000 (повторно)
Итог Пользователь видит отрицательную «общую по владельцу» -9 489 323,91

Важно: сама выгрузка блокировки на 20 млн, скорее всего, корректна. Ошибка в том, как воркбенч складывает факт, блокировку и итоговую стоимость.

4. Какие цифры должны быть после исправления

Показатель Сейчас (ошибка) Должно быть (ориентир)
Сумма факт. 30 512 322,63 без изменений
Стоимость, блокировка -20 000 000,00 -20 000 000,00 (информативно)
Стоимость, общая по владельцу -9 489 323,91 ~10 360 000 - 10 512 000

После исправления блокировка по-прежнему должна отображаться отдельной колонкой, но итоговая стоимость уменьшается только один раз.

5. Предположительная причина (для бизнеса)

  • Блокировка попадает в расчет позиции портфеля и как уменьшение количества денег, и как отдельная сумма блокировки.
  • Воркбенч при подсчете «общей стоимости по владельцу» использует обе эти составляющие одновременно.
  • Для денег (RUB) это особенно заметно: цена = 1, поэтому двойное вычитание 20 млн сразу дает минус ~9,5 млн.
  • Проблема системная: повторяется на разных клиентах, не связана с конкретной суммой 20 млн.

7. Цепочка расчета и место ошибки

7.1. Отображение колонки «Стоимость, общая по владельцу»

Поле ОбщаяСтоимостьПозиций в макете воркбенча маппится на синоним «Стоимость, общая по владельцу» (ВоркбенчКлиентСерверПовтИсп). На уровне группировки портфеля итог берется из ПортфельОбщаяСтоимость, который заполняется из КэшСеансовПортфели.ОбщаяСтоимость (не из ОбщаяСтоимостьБезБлокировок).

// CommonModule.ВоркбенчПолныеПрава, запрос объединенных данных (~стр. 3679-3684)
ЕСТЬNULL(СтоимостиПортфелей.ОбщаяСтоимость, 0) КАК ПортфельОбщаяСтоимость,
...
ЕСТЬNULL(КэшПортфелиСубпортфели.ОбщаяСтоимость, 0) КАК ОбщаяСтоимостьПозиций,

7.2. Формула ОбщаяСтоимость в кэше портфелей

// CommonModule.ВоркбенчПолныеПрава, ТекстЗапросаСтоимостиПортфелей (~стр. 2351-2391)

// Количество УЖЕ уменьшено на блокировку через поля *_бр:
Количество = (КолФакт - КолФакт_бр) + (КолПлан - КолПлан_бр) + (КолПрогноз - КолПрогноз_бр)

// Стоимость_бр СОДЕРЖИТ суммы блокировок:
Стоимость_бр = ФактическаяПозиция_бр + ПлановаяПозиция_бр + ПрогнознаяПозиция_бр + СуммаРЕПО

// Итоговая стоимость:
ОбщаяСтоимость = СУММА(Цена * Количество + Стоимость_бр)

// Отдельная метрика (тоже подозрительна - тройное вычитание при наличии _бр):
ОбщаяСтоимостьБезБлокировок = СУММА(Цена * (Количество - КоличествоБлокировка) + Стоимость_бр)

7.3. Откуда в позиции берется блокировка

При Параметры.Воркбенч = Истина вызывается МодифицироватьПрогнозВоркбенч():

// CommonModule.РасчетПозицииПортфелей, МодифицироватьПрогнозВоркбенч (~стр. 1501-1515)
КОГДА Т.СуммаБлокировкаОстаток <> 0
    ТОГДА Т.КоличествоБлокировкаОстаток   -- в КоличествоПрогнознаяПозицияОтправленные
...
КОГДА Т.СуммаБлокировкаОстаток <> 0
    ТОГДА Т.СуммаБлокировкаОстаток       -- в ПрогнознаяПозиция_бр

Блокировка в регистре ПрогнозПоПоручению записывается отрицательной (Documents.Поручение: СуммаБлокировка = -1 * Сумма). При загрузке в кэш воркбенча КоличествоБлокировка дополнительно инвертируется (-Т.КоличествоБлокировка).

7.4. Колонка «Стоимость, блокировка» в СКД

// DataProcessor.Воркбенч.Templates.Макет, calculatedField
СтоимостьБлокировка = Окр(КоличествоБлокировка * Цена, 2)

Для RUB (Цена = 1) это дает -20 000 000 - корректно как информативный столбец. Ошибка не в этой колонке, а в том, что та же блокировка повторно влияет на ОбщаяСтоимость.

9. Варианты исправления

Вариант A (рекомендуемый): исправить формулу ОбщаяСтоимость

Файл: CommonModule.ВоркбенчПолныеПрава, ТекстЗапросаСтоимостиПортфелей()

Суть: блокировка должна учитываться один раз - либо через уменьшение Количество (поля *_бр), либо через Стоимость_бр, но не через оба механизма одновременно.

Направление правки:

  • Для валютных активов: ОбщаяСтоимость = Цена * (КоличествоФакт + КолПлан + КолПрогноз) без добавления блокировочной части в Стоимость_бр, если она уже вычтена из Количество;
  • или: не уменьшать Количество на *_бр для чистых блокировок, а оставить учет только в Стоимость_бр.

Риск: средний - затрагивает все портфели в воркбенче; нужна регрессия по ЦБ, RUB, РЕПО, плановым и прогнозным позициям.

Вариант B: исправить формирование позиции для блокировок

Файл: CommonModule.РасчетПозицииПортфелей, МодифицироватьПрогнозВоркбенч()

Суть: для записей с СуммаБлокировкаОстаток <> 0 заполнять только один канал учета:

  • либо ПрогнознаяПозиция_бр (сумма),
  • либо КоличествоПрогнознаяПозиция_бр / КоличествоПрогнознаяПозицияОтправленные (количество),
  • но не оба одновременно в цепочке, которая потом суммируется в ТекстЗапросаСтоимостиПортфелей.

Риск: средний - влияет на все блокировки из прогноза/плана, в т.ч. выгруженные из МО (LOCK).

Вариант C: исправить только отображение итога

Файлы: макет СКД Воркбенч.Макет, запрос ОбъединенныеДанные

Суть: для колонки «Стоимость, общая по владельцу» использовать метрику, где блокировка учтена один раз, например:

  • ОбщаяСтоимость + Сумма(СтоимостьБлокировка) (аналогично РаботаСЛимитами: ОбщаяСтоимость + СуммаБлокировка),
  • или явно ПортфельОбщаяСтоимостьБезБлокировок с корректной формулой (после исправления п. 7.2).

Риск: низкий для UI, но высокий для согласованности: доли, лимиты и распределение могут продолжить использовать неверную ОбщаяСтоимость из кэша.

Вывод: вариант C - как временный workaround; предпочтительны A или B.

Вариант D: пересмотреть ОбщаяСтоимостьБезБлокировок

Сейчас: Цена * (Количество - КоличествоБлокировка) + Стоимость_бр, при том что Количество уже net-of-*_бр. Это потенциально тройное вычитание блокировки в метриках долей (ДоляПозиции в макете использует ОбщаяСтоимостьБезБлокировок).

Исправлять вместе с вариантом A.
