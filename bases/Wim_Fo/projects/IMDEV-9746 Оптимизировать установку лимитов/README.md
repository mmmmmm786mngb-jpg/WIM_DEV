# IMDEV-9746. Оптимизировать операцию "Установка лимитов"

Строка 3 списка ключевых операций ФО: распространение правил лимитов на новых клиентов после обмена (ВО `внОперацииПослеОбмена`, `ВыполнитьРаспространениеПравилПослеОбмена`). Задача выделена из анализа ключевых операций ФО (папка `Анализ групп 3-15 и 9-13`), материалы скопированы оттуда 31.10.2026. 03.11.2026 разобраны замеры ПРОД 16.10-02.11 (розница и обычный ФО); кода по задаче пока нет.

Итог 03.11.2026: 24 с на клиента в обычном ФО (3.4) - обработчики регистра `ПорогиЛимитов` (версия лимита и кэш настроек на каждый из ~25 наборов порогов), в рознице они отключены `ОбменДанными.Загрузка` по настройке "Это база розничного ДУ". В рознице 1.48 с на пару, узким местом не является; открыт риск устаревания `КэшНастроекЛимитов` для лимитов с расширенным подтверждением - проверить на Т-1.

Стенд 03.11.2026 (разработческая ФО, данные как на Т-1, перевод на ПРОД коэффициентом по итогам шагов): обычный ФО - обработчики `ПорогиЛимитов` 82% времени операции (кэш настроек 40%, версия лимита 27%, заполнение последней версии 12%); розница - письма 30%, записи `ДополнительныеСведения` 25%, проведение `УстановкаЛимитов` 22%, поиск 14%. Таблицы - раздел 1.1 анализа замеров. Настройки разработческой базы возвращены, тестовые данные T9746 оставлены.

Кратко из анализа: на ПРОД розница 19.10 - 42 запуска, 10-25 с на запуск, около 1,55 с на пару портфель+класс; обычный ФО - около 24 с на одного клиента (причина не разобрана, п. 3.4). Резервы 3.1 (одно письмо на класс), 3.2 (пауза 2 с на пару в `ВыполнитьЗаписьВерсийЛимитов`), 3.3 (лишний проход `ПорогиЛимитов`); дефект - временные XLS не удаляются.
