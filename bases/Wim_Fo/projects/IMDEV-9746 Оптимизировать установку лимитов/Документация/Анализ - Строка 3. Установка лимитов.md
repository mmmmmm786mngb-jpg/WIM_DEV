# IMDEV-9746. Анализ: Строка 3. Установка лимитов: распространение правил на новых клиентов

Выдержка из анализа ключевых операций ФО от 28.10.2026 (папка `Анализ групп 3-15 и 9-13`, файлы
`Анализ групп 1 и 2.md` и `Объекты 1С по строкам.md`). Номера пунктов (3.1, 3.2, ...) - как в исходном анализе.

## Строка 3. Установка лимитов: распространение правил на новых клиентов

**Как работает.** `внОперацииПослеОбмена.ВыполнитьОбработку` после обмена (признак `ТребуетсяРаспространениеПравил`)
вызывает `ВыполнитьРаспространениеПравилПослеОбмена`. Для каждого класса лимитов (в рознице два: комплаенс и
риски, в обычном ФО - один):

1. `НайтиНовыхКлиентовРозничногоДУ` / `НайтиНовыхКлиентов` - запрос по всем портфелям нужных типов клиентов без
   даты автоустановки, с эталонным портфелем по внешнему коду и его действующей `УстановкаЛимитов`.
2. Для каждого найденного портфеля: 2-3 записи `ДополнительныеСведения` (дата автоустановки, эталонный портфель,
   внешний код), затем `СоздатьУстановкиЛимитов`:
   - два запроса к срезу `ДействующиеЛимитыПоПортфелю` и `ПолучитьПорогиЛимитовЭталонногоПортфеля`;
   - запись `ПорогиЛимитов` по каждому лимиту без действующего порога (в рознице с `ОбменДанными.Загрузка`);
   - создание и проведение документа `УстановкаЛимитов` (проведение вендорское);
   - признак стратегии, дата распространения, "лимиты заведены" - еще 2-3 записи `ДополнительныеСведения`;
   - **отдельное письмо с вложением XLS на каждую пару портфель+класс** (`РассылкаСообщения` внутри
     `СоздатьУстановкиЛимитов`, стр. 1145).
3. Итоговое письмо по классу.
4. В рознице после метода - фоновое задание `ВыполнитьЗаписьВерсийЛимитов`.

**Замеры ПРОД (розница 19.10).** 42 запуска, 349 с за день, 10.1-24.2 с на запуск, 4-10 пар портфель+класс за
запуск (2-5 новых клиентов). Шаги: `СозданиеУстановок` 266.5 с на 172 пары (~1.55 с на пару),
`ПоискНовыхКлиентов` 46.6 с на 84 поиска (~0.55 с), итоговая `Рассылка` 31.6 с на 84 письма (~0.38 с).
Обычный ФО 19.10: 16 запусков, из них 3 с клиентом, каждый ~24 с на **одного** клиента одного класса
(`СозданиеУстановок` 23.5 с) - в 15 раз медленнее розницы на пару, причину надо смотреть отдельно
(число лимитов эталона, проведение, письмо `РассылкаОбУспешномАвтораспространении`).

**Оценка.** Узким местом не является: запуск укладывается в 10-25 с между обменами. Риск - массовое заведение
клиентов: 1000 новых клиентов в рознице = 2000 пар x 1.55 с = ~52 мин в сеансе обмена.

**Резервы.**

| # | Что | Эффект | Где |
|---|---|---|---|
| 3.1 | Одно письмо с общим XLS на класс вместо письма на каждую пару | ~0.4 с на пару, около 25% шага `СозданиеУстановок`; минус ~170 писем в день в рознице | ВО, нужно согласие получателей рассылки |
| 3.2 | Убрать ожидание `ВызватьПаузу(КоличествоПортфелей * 2000)` до 3 раз в `ВыполнитьЗаписьВерсийЛимитов` (стр. 485) | Фоновое задание сейчас спит 2 с на пару (8 пар - 16 с, 2000 пар - 67 мин на цикл). Установки к старту задания уже созданы синхронно, ожидание, судя по коду, ничего не ждет | ВО, проверить, нет ли асинхронной обработки у вендора после проведения `УстановкаЛимитов` |
| 3.3 | Последний запрос `ЗаписатьВерсиюЛимитаПоВсемПортфелям` читает `ПорогиЛимитов` по всем портфелям только чтобы получить список лимитов | Лишний проход большого регистра в каждом запуске (в фоне, в замер не входит) | ВО |
| 3.4 | Разобрать 24 с на одного клиента в обычном ФО | Понять причину | обычный ФО, ЖР / ТЖ |

**Дефекты.**

- Временные XLS-файлы не удаляются: `ПолучитьИмяВременногоФайла(".xls")` + `ЛогПорогов.Записать` в
  `РассылкаСообщения` (стр. 1222), удаления нет. Файл на каждую пару, ~170 в день в рознице, копятся в
  каталоге временных файлов сервера 1С.
- `ВерсионированиеОбъектов.ЗаписатьВерсиюОбъекта` пишется по каждому лимиту эталона в каждом запуске - стоит
  проверить рост регистра версий по справочнику лимитов на ПРОД (42 запуска в день).

## Объекты 1С: Строка 3. Установка лимитов (распространение правил на новых клиентов)

**Запуск**

| Шаг | Объект 1С | Что делает |
|---|---|---|
| 1 | Веб-сервис `Avancore`, операция `DownloadPosition` | МО присылает пакет остатков; в комментарии пакета - JSON с параметрами обмена, в том числе `ТребуетсяРаспространениеПравил` |
| 2 | Обработка `ОбменДаннымиБэкОфис.ЗагрузитьПакет` -> `ВыполнитьОперацииПослеОбмена` | После загрузки данных пакета берет ВО из константы `ОперацииПослеОбмена` |
| 3 | ВО `внОперацииПослеОбмена` 1.10, `ВыполнитьОбработку(ОбъектЗапрос)` | Разбирает JSON; ветки взаимоисключающие: перерасчет РСА, иначе удаление блокировок, иначе распространение правил |
| 4 | ВО `внРаспространениеПравилСОдногоКлиентаНаСписокКлиентов` 1.16 (настройка `ОбработкаРаспространенияПравил`), `ВыполнитьРаспространениеПравилПослеОбмена` | Распространение правил; выполняется в сеансе веб-сервиса (в замерах ПРОД - пользователь `svc_web`) |
| - | Та же ВО, команда `ФоновоеВыполнение` | Не распространение, а отдельная проверка: портфели без установки лимитов за последние сутки (`НайтиПортфелиБезУстановокЛимитов`) и письмо |
| - | Та же ВО, форма | Ручное распространение (`ВыполнитьРаспространение`) |

**Настройки:** `ХранилищеНастроек` ВО распространения - классы лимитов `КлассЛимитовКомплаенс` / `КлассЛимитовРиски`,
свойства дополнительных сведений по классам (дата автоустановки, эталонный портфель, внешний код эталона, лимиты
заведены, дата распространения), списки типов клиентов, настройки рассылки (справочник `НастройкиРассылкиПисем`),
признак `ЭтоБазаРозничногоДУ`.

**Читает:** справочник `Портфели`, РС `ДополнительныеСведения`, срез РС `ДействующиеЛимитыПоПортфелю`, документ
`УстановкаЛимитов` (табличная часть `Лимиты`), РС `ПорогиЛимитов`.

**Создает и меняет**

| Объект 1С | Что пишется |
|---|---|
| Документ `УстановкаЛимитов` | Новый документ на пару портфель+класс (`ВидОперации = ПоПортфелю`, лимиты из эталонной установки), проведение. Движения документа: РС `ДействующиеЛимитыПоПортфелю`, `ДействующиеЛимитыПоГруппамПортфелей`, `ДействующиеЛимитыПоТипуКлиента`, `ДействующиеЛимитыПоСтратегии` |
| РС `ПорогиЛимитов` | Порог по каждому лимиту эталона без действующего порога (портфель, лимит, начало дня); в рознице с `ОбменДанными.Загрузка` |
| РС `ДополнительныеСведения` | По портфелю: дата автоустановки лимитов, эталонный портфель, внешний код эталона (обычный ФО), дата распространения правил, "лимиты заведены". По документу `УстановкаЛимитов`: признак стратегии |
| Почта (`РаботаСПочтовымиСообщениями`) | Письмо с вложением XLS (временный файл, не удаляется) на каждую пару; итоговое письмо по классу; в обычном ФО под сервисным пользователем - письмо об успешном автораспространении |
| Фоновое задание "Запись версий лимитов" (только розница) | `ВыполнитьЗаписьВерсийЛимитов`: пауза, затем версии элементов справочника `Лимиты` через `ВерсионированиеОбъектов` (РС `ВерсииОбъектов`) |
| Параметр сеанса `ОтключениеОбновленияКлючейДоступа` | В рознице перед постановкой задания включается полное отключение обновления ключей доступа |
| РС `ЗамерыВремени` | Ключи `РаспространениеПравилЛимитов*` (IMDEV-9530) |

После распространения `внОперацииПослеОбмена` вызывает свою процедуру `ПроверкаНаличияЗаписиСтатусаПортфеляВРегистре`.
