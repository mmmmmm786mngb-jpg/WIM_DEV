# Диагностика лимитов на Т-1 (IMDEV-9746)

Обработка `ДиагностикаЛимитовТ1.epf` (версия диагностики 1 от 03.11.2026) только читает данные: ничего не
записывает, не проводит и не отправляет. Результат - текстовый лог, его нужно прислать обратно. Нужен для решения
по пункту 2а (обновлять кэш настроек лимита только для классов с расширенным подтверждением) и для проверки риска
кэша в рознице.

## Запуск

1. Открыть Т-1 (тонкий клиент) пользователем с полными правами.
2. Файл - Открыть - `ДиагностикаЛимитовТ1.epf`. Если платформа спросит про защиту от опасных действий - разрешить.
3. Поле "Дней истории" - 30.
4. "Собрать лог". На разработческой базе сбор идет 5-10 с; на Т-1 ожидаемо до нескольких минут (раздел 3 считает
   пороги по лимитам эталонов во всем регистре порогов).
5. "Сохранить в файл (txt)" и прислать файл.
6. Повторить в обеих базах: обычный ФО (AVC_PP_FO) и ФО розница (AVC_PP_Retail_FO).

## Что в логе и зачем

| Раздел | Что | Для чего |
|---|---|---|
| 0 | Константа `ИспользоватьКлассыЛимитов`, настройки версионирования лимитов, установок лимитов и портфелей, версии лимитов за 30 дней с данными и без данных | Подтвердить условия, на которых построен стенд |
| 1 | Классы лимитов: расширенное подтверждение, число лимитов и подтвержденных | Для каких классов проверка лимитов берет пороги из кэша - сколько даст пункт 2а |
| 2 | Настройки обработки распространения: режим розницы, классы и их расширенное подтверждение, сервисные пользователи (служебные svc - по имени, остальные маской), типы клиентов | Отправляется ли письмо об успешном автораспространении (svc_web в списке) |
| 3 | Лимиты действующих установок эталонных портфелей: число портфелей с порогом по каждому лимиту, сводка по классам | Реальный объем вместо подобранных на стенде 3000 портфелей на лимит |
| 4 | Для клиентов, распространенных за 30 дней (до 200): есть ли их пороги в таблице порогов кэша настроек лимита | Риск розницы: пороги новых клиентов не попадают в кэш |
| 5 | Для 5 лимитов эталонов с наибольшим числом портфелей: время запроса порогов, сериализации объекта лимита, контрольной суммы, сжатия данных версии и расчета настроек кэша - без записи в базу | Скорость Т-1 против стенда: проверка перевода стенда на ПРОД |
| 6 | Портфели, у которых за один день проведено больше одной установки лимитов по портфелю одного класса | Создает ли фоновое распространение (подписка на запись сведения "эталонный портфель лимитов") повторные установки - от этого зависит пункт 5 (пауза в фоновом задании) |

Имена сотрудников в лог не попадают, суммы и данные клиентов не выводятся (только число портфелей и наименования
лимитов).
