Параллельная выгрузка МО → ФО: пачки мандатов

IMDEV-8829 • EPF внВыгрузкаОстатковМО_ФО • Статус: проектирование (код не менялся)

Инструкция администратора (внедрение) • ТЗ на доработку (окончательное) • Цепочки WS 754/768/872 • Приоритеты оптимизации • Замеры (пакет 45)

Идея: все мандаты с остатками (~21 115) делятся на N непересекающихся пачек. Каждая пачка обрабатывается в отдельном фоновом сеансе МО со своим списком мандатов (ОтборМандат / СписМандатОтбор). Потоки одновременно вызывают DownloadPosition на ФО, не пересекаясь по портфелям.

1. Сейчас и целевая схема

Сейчас Один фоновый сеанс

Регламент / ФоноваяВыгрузка
  -> 1 сеанс МО
  -> цикл ~21 115 мандатов
  -> пакеты по 45-50 (КоличествоПортфелейВПакете)
  -> 4 x DownloadPosition на пакет
  -> ~4-5 часов

Один WSПрокси, один ИдентификаторСеанса, последовательные WS-вызовы.

Цель N фоновых сеансов

Координатор (новая команда)
  -> разбить мандаты на N пачек
  -> N x ФоноваяВыгрузка (пачка i)
       -> свой СписМандатОтбор
       -> свой цикл + пакеты
       -> свой WS к ФО
  -> финиш: одна рассылка РСА

Ускорение за счет параллельной нагрузки на ФО (ожидание: ~2-3x, не N раз).

Единица параллелизма — не отдельный мандат и не отдельный WS-вызов, а фоновый сеанс на пачку мандатов. Внутри пачки логика остается как сейчас: пакеты по КоличествоПортфелейВПакете и 4 WS на пакет.

3. Как делятся мандаты на пачки

3.1. Источник списка мандатов

Тот же отбор, что в СформироватьОтборДляФоновогоЗадания:

  • остатки ДенежныеСредства + ЦенныеБумаги на T-1;
  • фильтры по типу счета / типу мандата (как в запросе фоновой выгрузки);
  • опционально УК, ОтборМандат из настроек узла.

Из счетов мандатов получаем уникальные ссылки Справочник.Мандаты (ПолучитьМассивМандатовДляОтбора).

3.2. Алгоритм разбиения (пример N = 5)

Параметр Пример Комментарий
Всего мандатов 21 115 Из замеров PP Retail
КоличествоПачек 5 Настройка узла / координатора

МассивМандатов = ПолучитьВсеМандатыДляВыгрузки();  // уникальные, отсортированные
РазмерПачки = Цел(МассивМандатов.Количество() / КоличествоПачек);

Для НомерПачки = 0 По КоличествоПачек - 1 Цикл
    Начало = НомерПачки * РазмерПачки;
    Конец  = ?(НомерПачки = КоличествоПачек - 1, МассивМандатов.ВГраница(), Начало + РазмерПачки - 1);

Критично Один мандат — только в одной пачке. Пересечение пачек приведет к гонкам записи ФактическаяПозиция и доп. сведений портфеля на ФО.

6. Роль координатора и общий сеанс РСА

Сейчас в Опубликовать один ИдентификаторСеанса = Новый УникальныйИдентификатор на весь прогон. Логи перерасчета РСА на ФО пишутся с этим ID; финальная ВыполнитьРассылкуПоПерерасчетуРСА собирает результат.

Шаг Кто выполняет Действие
1 Координатор Создать ИдентификаторСеансаОбмена, передать всем воркерам в настройках
2 Координатор ОпубликоватьСделкиРЕПОМО (один раз, до воркеров)
3 Воркеры 1..N Полный Опубликовать по своей пачке с общим ID сеанса
4 Координатор Дождаться завершения всех фоновых заданий (barrier)
5 Координатор ВыполнитьРассылкуПоПерерасчетуРСА + почтовая рассылка (один раз)

10. План пилота (после реализации)

  1. N = 2, тестовый узел, ~10% мандатов (ОтборМандат).
  2. Сверка позиций ФО с последовательной выгрузкой по тем же мандатам.
  3. Замер времени: координатор + max(воркеры) vs текущие ~4-5 ч.
  4. N = 3, затем 5 при стабильной нагрузке на ФО.
  5. Retail PP: заменить регламентную команду на пачковую.
