Инструкция: внедрение параллельной выгрузки МО → ФО

IMDEV-8829 • EPF внВыгрузкаОстатковМО_ФО • файл сборки: ВыгрОстМО_ФО.epf • база Wim_Mo

ТЗ на доработку • Архитектура • Запуск из регламентов (было) • Оглавление

Цель: включить параллельную выгрузку остатков на ФО Retail через новую команду ФоноваяВыгрузкаПачками. Регламентное задание ОбменыПодсистемыТранспорт не меняется — меняются только обработка в справочнике, настройки и команда на узле обмена.

Настройки узлаАдресWS, КоличествоПортфелейВПакете и др.+ КоличествоПачекМандатов
Как работает новая команда: координатор делит мандаты на N пачек, запускает N фоновых заданий (каждое — штатная ФоноваяВыгрузка по своей пачке), ждёт завершения всех и один раз выполняет финальную рассылку РСА.

2. Замена обработки в справочнике «Дополнительные отчёты и обработки»

2.1. Подготовка

  • Файл: bases/Wim_Mo/projects/IMDEV-8829 внВыгрузкаОстатковМО_ФО/ВыгрОстМО_ФО.epf
  • Резервная копия старой обработки: ВыгрОстМО_ФО_БезПаралели_Retail.rar (в каталоге проекта)
  • Права: администратор / право на загрузку доп. обработок

2.2. Пошагово в интерфейсе 1С (Wim_Mo)

  1. Открыть справочник «Дополнительные отчёты и обработки».
    Найти элемент с именем объекта внВыгрузкаОстатковМО_ФО (наименование: «Выгрузка остатков МО ФО», вид: Обмены).
  2. Загрузить новый EPF поверх существующего элемента.
    Способ зависит от вашего процесса:
    • через форму элемента справочника (команда загрузки / обновления файла);
    • или через DevOps-процедуру деплоя EPF (если используется).
    Не создавайте второй элемент справочника с тем же назначением — узел обмена ссылается на конкретную ссылку доп. обработки. Нужно обновить существующий элемент.
  3. Проверить список команд после загрузки. Должны быть:
    ИдентификаторПредставлениеНазначение
    ЗагрузкаFront_MIDВыгрузка остатков МО ФОРучной запуск (форма)
    ФоноваяВыгрузкаВыгрузка остатков МО ФО (в фоне)Воркер / откат
    NEWФоноваяВыгрузкаПачкамиВыгрузка остатков МО ФО (пачками, в фоне)Координатор для регламента
  4. Открыть форму настроек обработки (гиперссылка «Установить настройки» или аналог в карточке элемента / узла).
  5. Заполнить настройки (раздел 3) и нажать «Установить». Настройки сохранятся в ХранилищеНастроек элемента справочника.
Если настройки раньше задавались только на узле обмена (DevOps-текстом в ХранилищеНастроек узла), а не через форму — это нормально. После замены EPF проверьте, что на узле по-прежнему есть АдресWS и КоличествоПортфелейВПакете, и добавьте КоличествоПачекМандатов.

3.2. Заполнение через форму настроек

  1. Открыть форму настроек обработки (из справочника или из узла обмена).
  2. Указать Адрес WS — URL Retail PP (см. таблицу выше).
  3. Указать Количество портфелей в пакете = 45 или 50.
  4. Указать Количество пачек мандатов = 2 (пилот) или 3 (рабочий режим).
  5. Узлы для регистрации ненайденных — оставить как были.
  6. Нажать «Установить».

3.3. Заполнение через DevOps (текстовый формат настроек узла)

Если настройки задаются текстом в ХранилищеНастроек узла обмена, добавьте строку для нового параметра:

Реквизит=АдресWS#!#Строка#!#http://smsk02mg138u/AVC_PP_RETAIL_FO/ws/avancore_ws.1cws?wsdl
Реквизит=КоличествоПортфелейВПакете#!#Число#!#45
Реквизит=КоличествоПачекМандатов#!#Число#!#3
Реквизит=ОтборМандат#!#Булево#!#Ложь
Важно: настройки могут храниться и в справочнике доп. обработок, и на узле обмена. При регламентном запуске приоритет у настроек узла (они передаются в ПараметрыДополнительнойОбработки). Убедитесь, что КоличествоПачекМандатов прописан там, откуда реально читает ваш узел.

4.2. Что изменить на узле

  1. Открыть план обмена «Источники обмена» → найти узел выгрузки остатков (например ВыгрузкаОстатков_ФОРозн для Retail PP).
  2. Проверить ссылку на внешнюю обработку: должна указывать на внВыгрузкаОстатковМО_ФО (обновлённый элемент справочника).
  3. Изменить поле «Имя метода» (ИмяМетода):
    БылоСтало
    ФоноваяВыгрузкаФоноваяВыгрузкаПачками
    Вводить точно идентификатор команды, без пробелов: ФоноваяВыгрузкаПачками (не «пачками в фоне» и не представление из списка).
  4. Проверить ХранилищеНастроек узла: должны быть АдресWS, КоличествоПортфелейВПакете, КоличествоПачекМандатов.
  5. Записать узел. Регламентное задание и его расписание не трогать.

5. Проверка после внедрения

5.1. Ручной прогон (до регламента)

  1. На тестовом/PP узле установить КоличествоПачекМандатов = 2.
  2. Запустить обмен по узлу вручную (команда «Выполнить обмен» / аналог в подсистеме обменов).
  3. В «Регламентные и фоновые задания» должны появиться задания:
    • 1 координатор (текущий сеанс);
    • N воркеров с именем «IMDEV-8829 Выгрузка остатков МО-ФО, пачка 1..N».
  4. Проверить бизнес-процессы выгрузки по узлу — по одному на каждую пачку.
  5. Сверить позиции на ФО с последовательной выгрузкой (на том же наборе мандатов).
  6. Убедиться, что финальная рассылка РСА пришла один раз, не N раз.

5.2. Что смотреть при ошибке

СимптомДействие
Метод объекта не обнаружен (ВыполнитьЗадание) Загрузить актуальный EPF (исправлено: используется ФоновыеЗадания.Выполнить)
Команда ... не обнаружена Проверить ИмяМетода на узле: точно ФоноваяВыгрузкаПачками
HTTP 413 КоличествоПортфелейВПакете не должно быть 0; держать 45-50
Упал 1 из N воркеров Смотреть протокол обмена / лог конкретной пачки; координатор зафиксирует аварийное задание

7. Чек-лист внедрения (кратко)

  1. Загрузить ВыгрОстМО_ФО.epf в существующий элемент справочника внВыгрузкаОстатковМО_ФО.
  2. Убедиться, что появилась команда ФоноваяВыгрузкаПачками.
  3. Прописать настройки: АдресWS (Retail), КоличествоПортфелейВПакете (45-50), КоличествоПачекМандатов (2-3).
  4. На узле обмена сменить ИмяМетода: ФоноваяВыгрузка → ФоноваяВыгрузкаПачками.
  5. Ручной прогон на PP, проверка N фоновых заданий и позиций на ФО.
  6. После стабилизации — включить в PROD регламент (расписание не менять).
