Техническое задание: параллельный запуск Опубликовать пачками мандатов

IMDEV-8829 • EPF внВыгрузкаОстатковМО_ФО (модуль объекта ВыгрОстМО_ФО) • База Wim_Mo → WIM_Fo • Статус: окончательное ТЗ на доработку

Архитектура параллелизма (обзор) • Цепочки WS 754/768/872 • Приоритеты оптимизации • Оглавление

Задача. Ускорить выгрузку остатков МО → ФО за счёт параллельной обработки. Все мандаты с остатками (~21 115) делятся на N непересекающихся пачек; каждая пачка обрабатывается в отдельном фоновом задании штатной процедурой Опубликовать. Координатор один раз создаёт общий идентификатор сеанса, запускает воркеры, дожидается их завершения (барьер) и один раз выполняет финальную рассылку РСА.

Ключевое ограничение реализации. Минимум новых процедур/функций; повторное использование существующего механизма отбора по мандатам (ОтборМандат / СписМандатОтбор) и штатного запуска обработки обмена через БСП. Все правки обрамляются комментариями с номером задачи IMDEV-8829.

2. Принцип решения (минимальные изменения)

Единица параллелизма

Не отдельный мандат и не WS-вызов, а фоновое задание на пачку мандатов. Внутри пачки логика Опубликовать не меняется: пакеты по КоличествоПортфелейВПакете и 4 WS на пакет.

Механизм запуска воркеров

Координатор запускает каждую пачку как фоновое задание: ФоновыеЗадания.ВыполнитьЗадание("ДополнительныеОтчетыИОбработки.ВыполнитьКоманду", ...) с командой ФоноваяВыгрузка и настройками пачки. Это тот же путь, что использует регламент, поэтому весь существующий код обмена переиспользуется без изменений транспорта.

Пачечный режим маркируется одним новым реквизитом — ИдентификаторСеансаОбмена (Строка). Пусто → обычная выгрузка (обратная совместимость). Заполнено → воркер: список мандатов задан координатором, общий сеанс, финальную рассылку не выполняет.

4.3. NEWРазбитьМандатыНаПачки

// IMDEV-8829 ++
// Описание: Делит массив мандатов на N непересекающихся пачек примерно равного размера.
//   Остаток от деления добавляется в последнюю пачку.
//
// Параметры:
//   МассивМандатов  - Массив         - исходный список мандатов.
//   КоличествоПачек - Число          - требуемое число пачек (>= 1).
//
// Возвращаемое значение:
//   Массив - каждый элемент это Массив мандатов одной пачки.
//
Функция РазбитьМандатыНаПачки(МассивМандатов, КоличествоПачек)

    Пачки = Новый Массив;
    Всего = МассивМандатов.Количество();
    Н = Мин(Макс(КоличествоПачек, 1), Всего);
    РазмерПачки = Цел(Всего / Н);

    Для НомерПачки = 0 По Н - 1 Цикл
        Начало = НомерПачки * РазмерПачки;
        Конец = ?(НомерПачки = Н - 1, Всего - 1, Начало + РазмерПачки - 1);
        Пачка = Новый Массив;
        Для Индекс = Начало По Конец Цикл
            Пачка.Добавить(МассивМандатов[Индекс]);
        КонецЦикла;
        Пачки.Добавить(Пачка);
    КонецЦикла;

    Возврат Пачки;

8. Обратная совместимость

  • Команда ФоноваяВыгрузка и её поток остаются без функциональных изменений; при пустом ИдентификаторСеансаОбмена поведение идентично текущему.

10. Порядок внедрения и чек-лист тестирования

  1. Добавить реквизит ИдентификаторСеансаОбмена (Строка) в обработку.
  2. Внести 5 правок (разделы 5.1–5.5) и 4 новые процедуры (раздел 4), все с маркерами IMDEV-8829.
  3. Собрать EPF, синтакс-контроль, тест обычной ФоноваяВыгрузка — поведение не изменилось.
  4. Тест координатора N=2 на ~10% мандатов (через УК / тестовый отбор): сверить позиции ФО с последовательной выгрузкой тех же мандатов.
  5. Замер: время координатора + max(воркеры) против текущих ~4–5 ч.
  6. Проверить единственность финальной рассылки РСА (один комплект писем).
  7. Постепенно N=3, затем 5 при стабильной нагрузке ФО; переключить команду регламента узла на ФоноваяВыгрузкаПачками.
