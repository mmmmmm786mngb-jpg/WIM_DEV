Три WS-вызова 754 / 768 / 872: МО → ФО

Проект IMDEV-8829 внВыгрузкаОстатковМО_ФО • Источники: внВыгрузкаОстатковМО_ФО (МО), ОбменДаннымиБэкОфис + WebServices.Avancore (ФО CF), внОперацииПослеОбмена (ФО EPF)

Замеры (скриншоты DOCX) • Рекомендации по оптимизации

На стороне ФО все три вызова — один метод DownloadPosition. Различие определяется составом XDTO-пакета, который МО формирует перед вызовом. Ниже: проблемные строки, общая процедура на МО, затем три блока обработки на ФО.

1. Три проблемные строки (профилировщик, пакет 45)

Строка Вызов на МО Среднее 470 пакетов % Назначение
754 Прокси.DownloadPosition(ПакетХДТОФлагПозицииНеВыгружена) ~7,6 с 3 586 с 20,6% Предварительные флаги: позиция еще не выгружена
768 Прокси.DownloadPosition(ПакетХДТО) ~5,0 с 2 365 с 13,6% Основная позиция: ДС, ЦБ, СЧА/РСА
872 Прокси.DownloadPosition(ПакетХДТОФлагПозиции) ~22,0 с 10 349 с 59,5% Пост-флаги: выгрузка завершена / ошибка / требуется перерасчет РСА

Суммарно три строки: ~16 300 с из ~17 357 с Опубликовать (~93,7%).

2. Общая процедура на МО: где и как вызываются

2.1. Контейнер

  • Модуль: ВнешняяОбработка.внВыгрузкаОстатковМО_ФО.МодульОбъекта
  • Процедура: Опубликовать(ПересчитатьРыночнуюСтоимость, ПересчитатьКомплаинс, ДатаПубликации)
  • Цикл: по мандатам из запроса к ТЧ ДенежныеСредства + ЦенныеБумаги (+ СделкиРЕПОМО, РЕПОДеньги)
  • Условие отправки пакета: КоличествоВПакете = КоличествоПакет (из реквизита КоличествоПортфелейВПакете) или последний мандат

2.2. Последовательность на один пакет (45 мандатов)

Цикл по мандатам (накопление в пакет): ДобавитьВПакетМандат() -- для каждого мандата в пакете + строки РЕПО (СделкиРЕПОМО, РЕПОДеньги) в ПакетХДТО Когда пакет заполнен: [1] СформироватьПакетФлагПозицияНеВыгружена -> DownloadPosition // строка 751 (~754 в профиле) [2] DownloadPosition(ПакетХДТО) // строка 765 (~768) ... обработка ответа, возможная корректировка СоответствиеПортфелей ... ... блокировки, удаление блокировок ... [3] СформироватьПакетФлагПозицияВыгружена СформироватьПакетФлагПозицияВыгруженаСОшибкой -> DownloadPosition(ПакетХДТОФлагПозиции) // строка 870 (~872) [4] ВыполнитьПерерасчетРСА -> отдельный DownloadPosition // строка 877 (не входит в топ-3) Сброс: КоличествоВПакете = 0, НовыйПакет = Истина
Важно: строки 754, 768, 872 — это три последовательных DownloadPosition внутри одного цикла пакета. Сразу после 872 (в том же блоке) идет 4-й вызов ВыполнитьПерерасчетРСА (строка 1526 в профиле) — он не входит в топ-3, но выполняется вслед за 872.

На пакет из 45 мандатов: 45 элементов Портфели[], 45 записей доп. сведений.

4.2. Последовательность на ФО

  1. ЗагрузитьПакет → ЗагрузитьДанные
  2. ЗагрузитьДанные видит секцию Справочники → ОбработатьДанные_Справочники
  3. Цикл по Справочники.Портфели → для каждого элемента: ОбработатьДанные_Портфель
  4. Внутри ОбработатьДанные_Портфель:
    • ПортфельПоиск по ВнешнийКод
    • При НеполноеОбновление: без полной перезаписи реквизитов/ТЧ портфеля (если ТЧ в XDTO пустые)
    • При выполнении условия ЭтоНовыйОбъект Или ОбновлятьСправочныеДанныеИзБэкОфиса: ПопытатьсяЗаписатьОбъектСправочника (минимальные изменения)
    • Ключевой шаг: ОбработатьДополнительныеСведения(Объект.Ссылка, СправочникОбъектXDTO, Отказ)
  5. ОбработатьДополнительныеСведения (на каждый портфель):
    • РегистрыСведений.ДополнительныеСведения — НаборЗаписей.Прочитать() по объекту
    • Для каждого ключа: ПВХ.ДополнительныеРеквизитыИСведения.НайтиПоНаименованию(Ключ)
    • Обновление строки в таблице набора, НаборЗаписей.Записать()
  6. ОбработатьКэшНенайденныхЭлементов
  7. ВыполнитьОперацииПослеОбмена → внОперацииПослеОбмена: выход (нет JSON в комментарии)

6. Блок 872 — обработка на ФО

6.1. Набор данных, который получает ФО

Один XDTO-пакет формируется двумя процедурами МО (успех + ошибка). В одном DownloadPosition могут быть до 45+ записей Портфели[].

Источник на МОУсловиеДоп. сведения на портфель (ДУ)
СформироватьПакетФлагПозицияВыгружена СоответствиеПортфелей[Мандат] = Ложь (успех) Лимиты позиция_выгружена = Ложь
Лимиты требуется_перерасчет_РСА = Истина
Лимиты есть_ошибки_выгрузки_позиции = Ложь
СформироватьПакетФлагПозицияВыгруженаСОшибкой СоответствиеПортфелей[Мандат] = Истина (ошибка) те же 3 ключа, но есть_ошибки_выгрузки_позиции = Истина
Для ПИФ: только Лимиты позиция_выгружена = Истина (1 свойство)

На типичном пакете ДУ (45 мандатов, без ошибок): 45 портфелей × 3 свойства = 135 операций записи доп. сведений.

6.2. Последовательность на ФО

Тот же путь, что у 754 (Справочники.Портфели), но объем работы в ОбработатьДополнительныеСведения в 3 раза больше на портфель ДУ.

  1. DownloadPosition → ЗагрузитьПакет → ЗагрузитьДанные
  2. Цикл ОбработатьДанные_Портфель для каждого элемента Портфели[]
  3. Для каждого портфеля: ОбработатьДополнительныеСведения (до 3 ключей ПВХ)
  4. внОперацииПослеОбмена: не запускает перерасчет РСА (комментарий пуст)
Флаги Лимиты требуется_перерасчет_РСА в пакете 872 только записываются в РегистрСведений.ДополнительныеСведения. Синхронный перерасчет РСА на ФО в этом вызове не выполняется. Перерасчет запускается отдельным 4-м DownloadPosition из ВыполнитьПерерасчетРСА (JSON в Заголовок.Комментарий) → внОперацииПослеОбмена → фоновое задание внПерерасчетСтоимостиФактическойПозицииИ_РСА_СЧА.ВыполнитьПерерасчетВФоне.
