Инструкция разработчику: закрытие замечания UAT по НРД метод 3

Задача IMDEV-8611. Обработка: Разработка_Epf/внОпределениеССНПФАтомфонд/Ext/ObjectModule.bsl.

1. Основание для исправления

Замечание пользователя (Karplyukova, Zhanna)
Для рублевых облигаций можно применять только методы 1 и 2 НРД. Если НРД вернул котировку, рассчитанную методом 3, эту цену не применять, а выполнять расчет по DCF.

В текущем коде обработки цена НРД на уровне 2 выбирается без фильтра по НомерМетодаРасчета, а в уровне 3 есть отдельная ветка, которая как раз берет НРД метод 3. Это противоречит замечанию UAT для рублевых облигаций.

2. Что уже есть в обработке и что используем без переписывания

Участок Статус Как использовать
ЦенаАктиваУровень2(...) Есть ветка DCF для облигаций при отсутствии НРД Использовать эту же ветку как fallback для случая "НРД метод 3 у рублевой облигации".
ЦенаАктиваУровень3(...) Есть полный расчет DCF (блок IMAPPS-11191) Не копировать формулы заново. При необходимости оставить как общий fallback.
ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы(...) Вызывается в обработке Использовать как источник СтруктураЦенПоСпредам для DCF.

3. Точные изменения в коде

3.1 Изменение 1: фильтр НРД по методу в ЦенаАктиваУровень2

Процедура сейчас: Процедура ЦенаАктиваУровень2(Актив, Дата, СтруктураНастроек, ТаблицаКотировокНРД, ЗаполненнаяСтрокаКотировок, ТаблицаКотировокПоАктиву, Мандат). В обоих циклах Для каждого НайденнаяСтрока из НайденныеСтрокиНРД Цикл добавить проверку на метод 3 для рублевых облигаций. 

// Вставить в цикл чтения строк НРД до присвоения ЦенаНРД
ЭтоРублеваяОблигация = (Актив.ВидАктива.ПринадлежитЭлементу(ПланыВидовХарактеристик.ВидыАктивов.Облигации)
    И Актив.ВалютаНоминальнойСтоимости = Справочники.Валюты.РоссийскийРубль);

НомерМетода = ?(ЗначениеЗаполнено(НайденнаяСтрока.НомерМетодаРасчета), НайденнаяСтрока.НомерМетодаРасчета, 0);

Если ЭтоРублеваяОблигация И НомерМетода = 3 Тогда
    // По замечанию UAT метод 3 НРД для рублевой облигации не применяем.
    // Не берем эту строку как ЦенаНРД, ищем следующую.
    Продолжить;
КонецЕсли;

3.2 Изменение 2: используем уже существующий DCF в этой же процедуре

После фильтра из п. 3.1 у рублевой облигации может не остаться подходящей цены НРД. Это штатно попадет в блок Иначе внутри ЦенаАктиваУровень2, где уже реализован DCF через ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы и ЦенаМедианаСпред. Новой процедуры РассчитатьКотировкуDCF создавать не обязательно.

Минимальный вариант решения
Ограничиться фильтром метода в уровне 2 и оставить текущий DCF-блок без изменений. Это самый безопасный путь: минимум риска для уже рабочей обработки.

3.3 Изменение 3: защита в ЦенаАктиваУровень3 (рекомендуется)

В начале ЦенаАктиваУровень3 есть поиск НРД с НомерМетодаРасчета = 3 и возврат результата как уровня 3. Для соблюдения замечания UAT добавить условие, что этот путь не используется для рублевых облигаций. 

// Перед блоком поиска НРД метода 3 в ЦенаАктиваУровень3
ЭтоРублеваяОблигация = (Актив.ВидАктива.ПринадлежитЭлементу(ПланыВидовХарактеристик.ВидыАктивов.Облигации)
    И Актив.ВалютаНоминальнойСтоимости = Справочники.Валюты.РоссийскийРубль);

Если ЭтоРублеваяОблигация Тогда
    // Для рублевых облигаций не используем котировку НРД метода 3.
    // Пропускаем НРД-ветку и идем к DCF-блоку (IMAPPS-11191).
Иначе
    // Текущая логика поиска НРД метода 3 остается для прочих инструментов.
КонецЕсли;

5. Проверка после изменений

  • Кейс A: рублевая облигация, НРД метод 1 или 2 - цена НРД применяется, уровень 2.
  • Кейс B: рублевая облигация, НРД метод 3 - цена НРД не применяется, рассчитывается DCF (текущий DCF-блок уровня 2 или 3).
  • Кейс C: не рублевая облигация - текущее поведение не ломается.
  • В справке расчета для кейса B должен быть источник DCF или DCF по ставке, а не НРД.
Если нужно полностью исключить возможность попадания НРД метода 3 в итог для любых веток рублевой облигации, обязательно применить п. 3.3 (защита в ЦенаАктиваУровень3).
