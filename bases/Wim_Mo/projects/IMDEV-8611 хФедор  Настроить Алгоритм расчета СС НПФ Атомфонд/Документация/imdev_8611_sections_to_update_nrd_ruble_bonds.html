Исходное замечание

Автор: Карплюкова, Жанна (UAT IT test, 06.05.2026).

Текст: Уточнение по применению цен НРД: для рублевых облигаций можем применять только 1 и 2 методы расчета НРД. Если НРД дает котировку, рассчитанную по методу 3, мы ее не применяем, а рассчитываем модель DCF.

Причина необходимости правок в задании

В текущем виде документ developer_task_imdev_8611.html в нескольких местах закрепляет правило эксперта: брать готовую котировку НРД и поле уровня цены, не воспроизводя внутри обработки методику НРД. Это корректно как техническое упрощение, но не учитывает бизнес-ограничение НПФ: для рублевых облигаций котировку НРД, полученную по методу 3 в данных НРД, нельзя использовать для цели определения СС; в этом случае нужно перейти к расчету по модели DCF (как указано в замечании).

Суть разрыва
Без доработки ТЗ разработчик по тексту задания может всегда принимать строку НРД на уровне 2. По замечанию постановщика для рублевой облигации при методе 3 в НРД уровень 2 должен считаться неприменимым, а цена должна определяться через DCF (фактически отдельная ветка расчета, не «просто прочитать поле НРД»).

Приложение: что такое DCF и где в Wim_Mo смотреть переход на расчет по DCF

Расшифровка DCF

DCF (англ. Discounted Cash Flow) — дисконтированный денежный поток: приведение ожидаемых будущих денежных поступлений (выплат по облигации) к текущей стоимости с использованием ставки дисконтирования. Для облигации в модели обычно задают график выплат (купоны, тело, при необходимости ограничения по оферте), подбирают или берут из настроек компоненты ставки (кривая безрисковой доходности, кредитный спред по рейтингу) и считают приведенную стоимость потоков.

В методике Атомфонд для СС в рублях параметр DCF используется в формуле с дисконтированием (п. 1.2.6.b в developer_task_imdev_8611.html): итоговая СС связывается с дисконтированной чистой ценой и НКД. Переход «не брать цену НРД метода 3, а считать DCF» означает: для рублевой облигации не подставлять готовую котировку НРД, а получить цену облигации через такую же по смыслу цепочку, что и в существующих обработках МО (см. таблицу ниже).

Паттерн «переход на DCF» в коде

  • Подготовка данных для облигации: вызов расчета через общий модуль финпоказателей (спред, денежный поток, рейтинг).
  • Если после биржи и отбора по НРД котировка не принята — вход в процедуру уровня 3 (или выделенную функцию DCF), где дисконтируются выплаты, результат попадает в ОпределяемаяКотировка, в справке фиксируются DCF / DCF по ставке.
  • Итоговая СС в рублях для методики Атомфонд согласовать с формулами п. 1.2.6.b в основном задании.
Важно для Атомфонд vs текущая логика Альянса
В ЦенаАктиваУровень3 обработки Альянса есть поиск строки НРД с НомерМетодаРасчета = 3 и использование ее как отдельной котировки уровня 3. По замечанию Жанны для рублевых облигаций как раз нельзя применять цену НРД, рассчитанную методом 3: ее нужно отфильтровать на уровне 2 и перейти к расчету DCF, а не копировать поведение «взять НРД метод 3 в цену» из Альянса без изменений.

Шаг 5. Что проверить после правки

  • Сценарий 1: рублевая облигация, НРД метод 1 или 2 — остается поведение уровня 2 (цена НРД применяется).
  • Сценарий 2: рублевая облигация, НРД метод 3 — НРД не принимается, заполняется котировка по DCF.
  • Сценарий 3: метод 3 и DCF недоступен — котировка не заполняется на уровне 2, отрабатывает штатный fallback уровня 3 и логирование.
  • В справке расчета явно виден источник: либо НРД, либо DCF / DCF по ставке.
Важно
В существующей реализации в ЦенаАктиваУровень3 уже есть поиск НРД по НомерМетодаРасчета = 3. Для выполнения замечания пользователя этот путь для рублевых облигаций нужно отключить или обойти условием, иначе метод 3 все равно попадет в итоговую цену.
