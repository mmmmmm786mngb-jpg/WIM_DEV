Шаги Excel к результату п. 11.1 и код 1С под каждый шаг

Цель: воспроизвести цепочку листа DCF (и обращение к КБД), которая в методике dcf_excel_4946280_methodology.html зафиксирована в п. 11.1: сумма приведенных J, B34 = 1047,637, чистая цена B30 = B33 = 1007,057 при B14 = 40,58, контрольные J39 ~ 89,55 и J40 ~ 958,09 при B27 = 0,165.
Файл эталона: DCF/DCF/4946280_DCF 4B02-01-00540-R-001P_30042026.xls.

В конфигурации Wim_Mo путь «как у заказчика по одной ставке на весь поток» обычно сводят к вызовам общего модуля РасчетФинансовыхПоказателей (см. ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы и внутри — ЦенаПриЗаданномЗначенийКредитногоСпреда). Ниже у каждого шага Excel дано: сначала формула листа, затем вариант явной реализации на встроенном языке и краткая отсылка к штатным процедурам, если они закрывают тот же смысл.

Шаг 0. Исходные данные на листе DCF

Excel: дата оценки B6; НКД B14; в таблице потоков (строки 39–40) даты B39:C40, погашение номинала D39:D40, текущий номинал E39:E40, годовая купонная ставка % F39:F40. В примере п. 11.1: D40=1000, G40 через формулу купона, I40=106 дней от оценки до выплаты второй строки, B27=0,165.

1С: те же величины получают из справочников и документов: дата оценки, НКД через Справочники.Облигации.КупонПоОблигации с последующим переводом в деньги как в модуле (см. расчет Купон в ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы), график платежей — через РасчетФинансовыхПоказателейПовтИсп.ДенежныйПотокПоОблигации(Мандат, Актив, ДатаОценки, ДатаОценки) с округлением колонки Итого до 2 знаков.

ДенежныйПоток = РасчетФинансовыхПоказателейПовтИсп.ДенежныйПотокПоОблигации(Мандат, Актив, ДатаОценки, ДатаОценки);
Для Каждого Стр Из ДенежныйПоток Цикл
    Стр.Итого = Окр(Стр.Итого, 2);
КонецЦикла;

Шаг 1. Средневзвешенная дата окончания периодов B16

Excel: =SUMPRODUCT(C39:C40,D39:D40)/SUM(D39:D40) — средняя дата конца периода, взвешенная по D.

1С (явно, по смыслу SUMPRODUCT): в Excel взвешивание идет по серийным номерам дат. В 1С удобно перевести каждую дату конца периода в «смещение в днях» от опорной даты (одинаковой для всех строк), сложить взвешенную сумму и вернуть дату:

ОпорнаяДата = Дата(1, 1, 1);
СуммаВесов = 0;
СуммаВзвешенныхДней = 0;
Для Каждого Стр Из ТаблицаПотокаExcel Цикл
    СуммаВесов = СуммаВесов + Стр.ПогашениеНоминалаD;
    ДнейОтОпоры = (НачалоДня(Стр.ДатаОкончанияC) - ОпорнаяДата) / (24 * 60 * 60);
    СуммаВзвешенныхДней = СуммаВзвешенныхДней + ДнейОтОпоры * Стр.ПогашениеНоминалаD;
КонецЦикла;
Если СуммаВесов = 0 Тогда
    B16 = Неопределено;
Иначе
    B16 = ОпорнаяДата + (СуммаВзвешенныхДней / СуммаВесов) * (24 * 60 * 60);
КонецЕсли;

В эталоне п. 11.1 при D39 = 0 и D40 = 1000 получится B16, совпадающая с датой конца строки с ненулевым D (как C40 в книге).

Уточните в справке вашей версии платформы: разность двух значений типа Дата — в секундах или в днях. Фрагмент выше предполагает секунды (деление и умножение на 24*60*60).

Примечание: в штатном контуре 1С для ставки с кривой используют не B16, а дюрацию РасчетФинансовыхПоказателей.СредневзвешенныйСрокДоПогашенияОферты(Актив, ДатаОценки, ДенежныйПоток) (другая формула — см. п. 13.4 основной методики).

Шаг 2. Срок в годах B17

Excel: =ROUND((B16-B6)/365,4).

B17 = Окр((B16 - ДатаОценки) / 365, 4);

1С (штатно): после получения ДенежныйПоток — Окр(РасчетФинансовыхПоказателей.СредневзвешенныйСрокДоПогашенияОферты(Актив, ДатаОценки, ДенежныйПоток), 4) как прокси срока для кривой (не тождество B17 Excel, если поток отличается от двух строк книги).

Шаг 3. Лист КБД: срок P2 и безрисковая ставка R2, поле B18 на DCF

Excel: КБД!P2 = DCF!B17; далее Q2, гауссовы слагаемые AC2, и R2 = ROUND((EXP(Q2/10000)-1),4); на DCF: B18 = КБД!R2.

1С (паритет с книгой): перенести константы и формулы листа КБД в отдельную функцию на входе B17 и вернуть ставку в долях единицы с Окр(..., 4).

1С (штатно в Wim_Mo): одна выборка с кривой по валюте и дюрации:

СтавкаКБД = РегистрыСведений.ПараметрыКривойБезрисковойДоходности.СтавкаПоКривойБезрисковойДоходности(
    ВалютаНоминала,
    ДатаОценки,
    Дюрация);

Шаг 4. Кредитный спред (медиана) B24

Excel: в книге заказчика для группы рейтинга введено значение в долях годовой ставки (в примере 0,0321, то есть 3,21 п.п. к безрисковой, сумма с B18 дает B27 = 0,165).

1С (прикладной результат «как B24» для дисконта): медиана спреда не вводится вручную, а берется из диапазона по уровню кредитного рейтинга актива. Публичная точка входа — функция РасчетФинансовыхПоказателей.ДиапазоныСпредаПоАктиву(Мандат, Актив, Дата): она возвращает структуру с полями Мин, Макс, Медиана в внутренних единицах (целые величины порядка сотен); в формулу ставки они попадают как Окр(Спред / 10000, 4) (см. ЦенаОблигацииПоСтавке в модуле РасчетФинансовыхПоказателей).

// Получить диапазон и перевести медиану в долю годовых, сопоставимую с Excel B24
ДиапазонСпредов = РасчетФинансовыхПоказателей.ДиапазоныСпредаПоАктиву(Мандат, Актив, ДатаОценки);

Если ДиапазонСпредов = Неопределено Тогда
    // Нет сопоставления рейтинга или нет данных — обработать по правилам проекта
Иначе
    // Как в ЦенаОблигацииПоСтавке перед дисконтированием:
    B24КакДоляГодовых = Окр(ДиапазонСпредов.Медиана / 10000, 4);
    МинКакДоля       = Окр(ДиапазонСпредов.Мин / 10000, 4);
    МаксКакДоля      = Окр(ДиапазонСпредов.Макс / 10000, 4);
КонецЕсли;

Цепочка внутри конфигурации (файл CommonModules/РасчетФинансовыхПоказателей/Ext/Module.bsl, порядок вызовов):

  1. ДиапазоныСпредаПоАктиву — запрос к регистрам РейтингиПоВыпускам / РейтингиПоЭмитентам на дату, сопоставление с СопоставлениеРейтингов, выбор УровеньКредитногоРейтинга (при пустом результате в коде подставляется уровень C — см. ветку «пустой результат» в модуле).
  2. РасчетФинансовыхПоказателейПовтИсп.ДиапазоныРейтинговыхГрупп(Мандат, Дата) — по сути ДиапазоныРейтинговыхГрупп того же модуля: четыре выборки доходностей из РегистрСведений.ДанныеИндекса по тикерам RUCBITRBBB3Y, RUCBITRBB3Y, RUCBITRB3Y, RUGBITR3Y (функция ТикерыИндексовДляРасчетаСпредов).
  3. МедианыПоРейтинговымГруппам — по 20 точкам (дополнение таблиц до 20 строк — ДобитьТаблицуДоходностиДо20Строк) для каждой даты строятся спреды корпоративных индексов к госбумагам в процентах, затем по отсортированным рядам считается МедианаПоМассивуДанных (центральный элемент или полусумма двух центральных).
  4. ДиапазоныПоЗначениямМедиан — из медиан по уровням A/B/C и реквизита мандата ПоказательОтклоненияДляРасчетаСпредов формируются целочисленные Мин, Макс, Медиана для выбранного уровня рейтинга (медианы предварительно Окр(..., 0)).

Это не тождество ячейке B24 из файла Excel заказчика: там фиксированное число для примера, здесь — модель по рыночным индексам и рейтингам ИБ. Численное совпадение с книгой возможно только при согласованных входных доходностях и настройке отклонения.

Шаг 5. Полная ставка дисконтирования B27

Excel: =B18+B24.

1С: не хранят отдельной переменной B27, а передают в дисконт сумму Окр(СтавкаКБД, 4) + Окр(МедианаСпреда / 10000, 4) внутри ЦенаОблигацииПоСтавке → ЦенаПриЗаданномЗначенийКредитногоСпреда.

СтавкаПолная = Окр(СтавкаКБД, 4) + Окр(ДиапазонСпредов.Медиана / 10000, 4);

Шаг 6. Длительность периода H и срок до выплаты I

Excel: H = C - B (дни периода), I = C - $B$6 (дней от даты оценки до конца периода).

1С (явно по строкам таблицы как в Excel):

Для Каждого Стр Из ТаблицаПотокаExcel Цикл
    Стр.HДнейПериода = (Стр.ДатаОкончанияC - Стр.ДатаНачалаB) / (24 * 60 * 60);
    Стр.IДнейДоВыплаты = (Стр.ДатаОкончанияC - НачалоДня(ДатаОценки)) / (24 * 60 * 60);
КонецЦикла;

1С: в готовом потоке из документа даты уже согласованы с расчетом; проверка I — сравнить Стр.Дата с ДатаОценки так же, как в ЦенаПриЗаданномЗначенийКредитногоСпреда (разность в днях от НачалоДня(ДатаОценки)).

Шаг 7. Купон за период G

Excel: =ROUND(E*F/100*H/365,2).

G = Окр(Стр.ТекущийНоминалE * Стр.СтавкаКупонаПроцентовF / 100 * Стр.HДнейПериода / 365, 2);

1С: при использовании ДенежныйПотокПоОблигации купон и тело уже свернуты в Итого по датам; явное G нужно только для построчной сверки с Excel.

Шаг 8. Приведенный платеж J по строке

Excel: =(D+G)/((1+$B$27)^(I/365)).

J = (Стр.ПогашениеНоминалаD + G) / Pow(1 + B27, Стр.IДнейДоВыплаты / 365);

1С (штатно): сумма всех таких слагаемых считается в РасчетФинансовыхПоказателей.ЦенаПриЗаданномЗначенийКредитногоСпреда(ДенежныйПоток, СтавкаПолная, НачалоДня(ДатаОценки), "Дата", "Итого", , ДелительОблигации), где ДелительОблигации = Перечисления.МетодыРасчетаНКД.ДелительПоМетодуРасчетаНКД(...) (часто 365, как в Excel).

Шаг 9. Сумма J с округлением — «грязая» приведенная цена B34

Excel: B34 = ROUND(SUM(J:J),4) — в примере 1047,637.

1С: внутри ЦенаПриЗаданномЗначенийКредитногоСпреда накапливается сумма дисконтированных Итого с итоговым Окр по правилам функции (отличается от ROUND(...,4) Excel — см. п. 13.5 методики); для построчной сверки с Excel можно в цикле суммировать J и затем Окр(СуммаJ, 4).

СуммаJ = 0;
Для Каждого Стр Из ТаблицаПотокаExcel Цикл
    СуммаJ = СуммаJ + Стр.JПриведенный;
КонецЦикла;
B34 = Окр(СуммаJ, 4);

Шаг 10. Чистая цена B30 и совпадение с B33

Excel: B30 = ROUND(SUM(J:J),4) - B14, B33 = B30 — в примере 1007,057 при B14 = 40,58.

1С: после ЦенаОблигацииПоСтавке при net = Истина в ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы выполняется Окр(ЦенаМедианаСпред, 4) - Купон в деньгах, затем приведение к процентам от номинала. Смысл совпадает с B34 - B14.

ЦенаЧистаяДен = Окр(ЦенаГрязнаяДен, 4) - НКДВДеньгахКакВМодуле;

Либо одной строкой, как в продукте: РасчетФинансовыхПоказателей.ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы(Актив, Мандат, ДатаОценки, Истина, Истина) — поле ЦенаМедианаСпред уже в процентах к номиналу; для сравнения с B30 в деньгах умножьте на номинал и разделите на 100 с учетом округлений модуля.

Шаг 11. Перевод в долю к номиналу (контроль 100,7057 из п. 12 методики)

Excel: B30 / 1000 * 100 при номинале строки 1000 — 100,7057 %.

1С: после вызова ЦенаОблигацииПоКредитномуСпредуРейтинговойГруппы с net = Истина результат уже в процентах (внутри — как Окр(ЦенаВДеньгах / НоминальнаяСтоимость * 100, 6) в процедуре приведения). Для ручной сверки:

КотировкаПроцент = Окр(ЦенаЧистаяДен / НоминальнаяСтоимость * 100, 6);
