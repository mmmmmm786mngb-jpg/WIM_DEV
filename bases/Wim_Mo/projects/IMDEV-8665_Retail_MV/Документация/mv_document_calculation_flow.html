Документ `РасчетРыночнойСтоимости`: что делает `ЗаполнитьДокумент()` и что пишет при проведении

Отчет описывает поведение "как сейчас" по базовой конфигурации `Wim_Mo`, модуль: SRC/CF/Documents/РасчетРыночнойСтоимости/Ext/ObjectModule.bsl. Контекст запуска из обработки `внРасчетMVиWAP` соответствует строкам, где создается документ, вызывается Док.ЗаполнитьДокумент() и затем Док.Записать(РежимЗаписиДокумента.Проведение).

1. Точка входа из `внРасчетMVиWAP`

В ветке расчета MV для каждого мандата и даты выполняется именно эта последовательность:

Док = Документы.РасчетРыночнойСтоимости.СоздатьДокумент();
Док.Валюта    = Выборка.Валюта;
Док.Курс      = КурсВалюты.Курс;
Док.Кратность = КурсВалюты.Кратность;
Док.Дата      = НачалоДня(ТекДата) + 23*60*60 + 59*60 + 59;
Док.Мандат    = Выборка.Мандат;
Док.ЗаполнитьДокумент();
Док.Записать(РежимЗаписиДокумента.Проведение);
Значит, при массовом пересчете сама обработка только задает шапку документа, а вся предметная логика состава сумм и движений находится внутри документа `РасчетРыночнойСтоимости`.

2. Что делает `ЗаполнитьДокумент()`

2.1. Проверки и подготовка шапки

  1. Если не заполнены `Мандат` или `Дата` - выход без расчета.
  2. Если не задана `Валюта` документа:
    • берется `Мандат.ВалютаМандата`,
    • если пусто - `RUB`,
    • получается курс через `РаботаСКурсамиВалют.ПолучитьКурсВалюты(Валюта, Дата)`.
  3. Очищается табличная часть `СчетаМандата`.
  4. Запускается `ПерезаполнитьВсеТЧ(Истина)`.

2.2. Общая идея `ПерезаполнитьВсеТЧ`

Процедура заполняет все расчетные табличные части документа и в конце пересчитывает агрегат `СчетаМандата`.

  1. Сначала отдельными процедурами: ЗаполнитьТЧЦенныеБумаги, ЗаполнитьТЧПлановыеЦБ.
  2. Потом собирает пакет запросов для остальных ТЧ и выполняет его одним вызовом: ЗаполнитьТЧНКД, ЗаполнитьТЧПлановыйНКД, ЗаполнитьТЧДенежныеСредства, ЗаполнитьТЧПроцентыПоРЕПО, ЗаполнитьТЧ_ДС_ПереданныеРЕПО, ЗаполнитьТЧ_ДС_ПолученныеРЕПО, ЗаполнитьТЧПроцентыПоБанковскимСчетам, ЗаполнитьТЧДоходыКПолучению, ЗаполнитьТЧРасходыКОплате, ЗаполнитьТЧПлановыеДС.
  3. В конце выполняет `ПересчитатьДокумент()`.

3.1. Подробно: "пакетное заполнение остальных ТЧ"

Под "пакетным заполнением" понимается блок, где процедуры подготовки ТЧ собирают тексты запросов в один общий пакет (`ПараметрыСборкиПакета.ТекстЗапросаПакета`), а затем выполняется единый вызов ЗаполнитьТабличнуюЧасть_Служебная(МассивТЧ, ТекстЗапросаПакета, ...).

Для каждой ТЧ ниже результатом является набор строк с минимумом полей: СчетМандата, Валюта, Сумма, далее конвертация в СуммаВВалютеДокумента выполняется общей служебной процедурой.
Табличная часть Источник / как формируется запрос Что попадает в ТЧ
НКД Встроенный текст запроса в ЗаполнитьТЧНКД: ЦенныеБумаги.Остатки + ЗафиксированныеКотировки + fallback на КотировкиЦБНаБирже + учет ДоходыКПолучению.Обороты по купонам. По счету/активу считается НКД-сумма; если есть проблемный актив по фикс-котировке, берется биржевой fallback.
ПлановыйНКД Встроенный текст запроса в ЗаполнитьТЧПлановыйНКД: ПлановаяПозицияПоЦеннымБумагам.Остатки + ЗафиксированныеКотировки + fallback на КотировкиЦБНаБирже. Плановый НКД по плановым остаткам; используется для дальнейшего расчета только `РыночнаяСтоимостьПлан`.

ПроцентыПоРЕПО Текст из общего модуля: РасчетСтоимостиАктивов.ТекстЗапросаПроцентыПоСчетамРЕПО(). Проценты по счетам РЕПО (факт), далее участвуют в сложении фактической рыночной стоимости.
ДенежныеСредстваОтданныеВРЕПО Текст из общего модуля: РасчетСтоимостиАктивов.ТекстЗапросаДСПереданныеРЕПО(). Денежные средства, переданные в РЕПО; учитываются в фактической сумме со знаком плюс.
ДенежныеСредстваПолученныеПоРЕПО Текст из общего модуля: РасчетСтоимостиАктивов.ТекстЗапросаДСПолученныеРЕПО(). Денежные средства, полученные по РЕПО; позже в `ПересчитатьДокумент` вычитаются из фактической рыночной стоимости.
ПроцентыПоБанковскимСчетам Текст из общего модуля: РасчетСтоимостиАктивов.ТекстЗапросаПроцентыПоБанковскимСчетам(). Процентные начисления по банковским счетам; участвуют в фактической стоимости со знаком плюс.
ДоходыКПолучению Текст из менеджера регистра: РегистрыНакопления.ДоходыКПолучению.ТекстЗапросаДоходыКПолучению(). Начисленные доходы к получению; прибавляются к фактической стоимости.
РасходыКОплате Текст из менеджера регистра: РегистрыНакопления.РасходыКОплате.ТекстЗапросаРасходыКОплате(). Расходы к оплате; в итоге `СчетаМандата` вычитаются (уменьшают факт и план).
ПлановаяПозицияПоДенежнымСредствам Текст из общего модуля: РасчетСтоимостиАктивов.ТекстЗапросаПлановыеДенежныеСредства(). Плановые денежные средства; в `ПересчитатьДокумент` добавляются только в `РыночнаяСтоимостьПлан`.

Как это отрабатывает технически

  1. Каждая процедура `ЗаполнитьТЧ...(..., ПараметрыСборкиПакета)` при `СборкаПакета=Истина` только добавляет свой запрос в общий текст и регистрирует свою ТЧ в массив.
  2. Один общий запуск `ВыполнитьПакет()` возвращает набор результатов, которые раскладываются по соответствующим ТЧ по индексу.
  3. Для каждой строки ТЧ рассчитывается `СуммаВВалютеДокумента` через валютный пересчет (`РаботаСКурсамиВалют...`).
  4. После заполнения всех ТЧ вызывается `ПересчитатьДокумент()`, где и формируется финальный агрегат по `СчетаМандата`.

4. Как собирается итог `СчетаМандата`

После заполнения всех ТЧ выполняется `ПересчитатьДокумент()`, который формирует агрегированные суммы по каждому счету мандата.

  1. Обнуляет `РыночнаяСтоимость` и `РыночнаяСтоимостьПлан` в `СчетаМандата`.
  2. Складывает `СуммаВВалютеДокумента` из ТЧ: ЦенныеБумаги, ДенежныеСредства, ПроцентыПоРЕПО, ДенежныеСредстваОтданныеВРЕПО, НКД, ПроцентыПоБанковскимСчетам, ДоходыКПолучению.
  3. Вычитает суммы из ТЧ: РасходыКОплате, ДенежныеСредстваПолученныеПоРЕПО.
  4. Добавляет только в план (`РыночнаяСтоимостьПлан`) суммы из: ПлановаяПозицияПоДенежнымСредствам, ПлановаяПозицияПоЦеннымБумагам, ПлановыйНКД.
На выходе `СчетаМандата` содержит уже итоговые суммы по счетам, и именно они потом пишутся в регистры при проведении.

5. Что делает `ОбработкаПроведения()`

5.1. Проверка ручной корректировки

Сначала вызывается ПроведениеСервер.РучнаяКорректировкаОбработкаПроведения(...). Если механизм ручной корректировки перехватывает проведение, процедура выходит.

5.2. Основные записи движений

Для каждой строки табличной части `СчетаМандата` создаются движения в два регистра сведений:

Регистр Измерения/ключи Ресурс
РегистрСведений.РыночнаяСтоимостьПозиции Период=Дата, Мандат, Валюта, СчетМандата Сумма = СчетаМандата.РыночнаяСтоимость
РегистрСведений.РыночнаяСтоимостьПлановойПозиции Период=Дата, Мандат, Валюта, СчетМандата Сумма = СчетаМандата.РыночнаяСтоимостьПлан

5.3. Дозануление "исчезнувших" счетов

После основных записей модуль специально добавляет нулевые движения по тем счетам, которые были в срезе на предыдущую дату, но не попали в текущий документ.

  1. Дата среза: Дата - 1 день.
  2. Список счетов для зануления в факте: СписокСчетовМандатаРыночнойСтоимости(...) по РегистрСведений.РыночнаяСтоимостьПозиции.СрезПоследних.
  3. Список счетов для зануления в плане: СписокСчетовМандатаРыночнойСтоимостиПлановойПозиции(...) по РегистрСведений.РыночнаяСтоимостьПлановойПозиции.СрезПоследних.
  4. Для каждого такого счета пишется движение с Сумма = 0.
Это важная часть поведения: проведение не просто "добавляет новые суммы", а еще явно очищает старые счета, чтобы срез последних не оставлял устаревшие значения.

6. Полный список объектов записи при проведении

Прямые записи (`Движения...Добавить()`) идут только в два регистра сведений:

  • РегистрСведений.РыночнаяСтоимостьПозиции
  • РегистрСведений.РыночнаяСтоимостьПлановойПозиции

При удалении проведения используется: ПроведениеСервер.УдалитьДвиженияРегистратора(ЭтотОбъект, ...), то есть снимаются движения регистратора этого документа.

7. Текстовая диаграмма процесса документа

Создан документ РасчетРыночнойСтоимости (из внешней обработки)
    -> ЗаполнитьДокумент()
        -> проверка шапки (Мандат, Дата)
        -> установка Валюта/Курс/Кратность при необходимости
        -> очистка СчетаМандата
        -> ПерезаполнитьВсеТЧ(Истина)
            -> ЗаполнитьТЧЦенныеБумаги
                -> МандатДляКотировки = ВТБ_АлгоритмыРасчета.МандатРозничноеДУ(Мандат)
                -> запрос ЗафиксированныеКотировки.СрезПоследних(..., Мандат = МандатДляКотировки)
                -> если зафиксированной котировки нет, добор из КотировкиЦБНаБирже.СрезПоследних(...)
            -> ЗаполнитьТЧПлановыеЦБ
                -> МандатДляКотировки = ВТБ_АлгоритмыРасчета.МандатРозничноеДУ(Мандат)
                -> та же логика: сначала ЗафиксированныеКотировки, затем fallback к КотировкиЦБНаБирже
            -> пакетное заполнение остальных ТЧ
                -> СборкаПакета=Истина: каждая ЗаполнитьТЧ... добавляет свой текст запроса в общий пакет
                -> в служебной процедуре вычисляется МандатДляКотировки
                -> ЗаполнитьТЧНКД
                    -> ЦенныеБумаги.Остатки + ЗафиксированныеКотировки (по МандатДляКотировки)
                    -> fallback к КотировкиЦБНаБирже
                    -> корректировка с учетом ДоходыКПолучению.Обороты
                -> ЗаполнитьТЧПлановыйНКД
                    -> ПлановаяПозицияПоЦеннымБумагам.Остатки + ЗафиксированныеКотировки
                    -> fallback к КотировкиЦБНаБирже
                -> ЗаполнитьТЧДенежныеСредства
                    -> текст: РасчетСтоимостиАктивов.ТекстЗапросаДенежныеСредства()
                -> ЗаполнитьТЧПроцентыПоРЕПО
                    -> текст: РасчетСтоимостиАктивов.ТекстЗапросаПроцентыПоСчетамРЕПО()
                -> ЗаполнитьТЧ_ДС_ПереданныеРЕПО
                    -> текст: РасчетСтоимостиАктивов.ТекстЗапросаДСПереданныеРЕПО()
                -> ЗаполнитьТЧ_ДС_ПолученныеРЕПО
                    -> текст: РасчетСтоимостиАктивов.ТекстЗапросаДСПолученныеРЕПО()
                -> ЗаполнитьТЧПроцентыПоБанковскимСчетам
                    -> текст: РасчетСтоимостиАктивов.ТекстЗапросаПроцентыПоБанковскимСчетам()
                -> ЗаполнитьТЧДоходыКПолучению
                    -> текст: РегистрыНакопления.ДоходыКПолучению.ТекстЗапросаДоходыКПолучению()
                -> ЗаполнитьТЧРасходыКОплате
                    -> текст: РегистрыНакопления.РасходыКОплате.ТекстЗапросаРасходыКОплате()
                -> ЗаполнитьТЧПлановыеДС
                    -> текст: РасчетСтоимостиАктивов.ТекстЗапросаПлановыеДенежныеСредства()
                -> единый ВыполнитьПакет() возвращает набор выборок для всех ТЧ
                -> служебное заполнение строк ТЧ + расчет СуммаВВалютеДокумента
            -> ПересчитатьДокумент()
                -> сбор в СчетаМандата: факт +/-
                -> досчет плана
    -> Записать(Проведение)
        -> ОбработкаПроведения()
            -> проверка ручной корректировки
            -> запись движений в:
                -> РыночнаяСтоимостьПозиции
                -> РыночнаяСтоимостьПлановойПозиции
            -> зануление счетов, не попавших в документ, по срезу предыдущего дня

8. Вывод по вашему вопросу

В контексте строк вызова из `внРасчетMVиWAP` (`СоздатьДокумент -> ЗаполнитьДокумент -> Проведение`) документ `РасчетРыночнойСтоимости` полностью самодостаточно: сам читает источники для расчета, сам пересчитывает табличные части и сам формирует итоговые движения в регистры факта/плана.

С практической точки зрения нагрузку дают: сложные запросы по ЦБ/котировкам/плановым данным, пакетное заполнение ТЧ и массовая запись движений по всем счетам, включая дозануление "исчезнувших" счетов.

8.1. Операционная схема по каждой ТЧ (вход -> выход -> эффект)

1) НКД
   Вход:
     - РегистрНакопления.ЦенныеБумаги.Остатки
     - РегистрСведений.ЗафиксированныеКотировки (по МандатДляКотировки)
     - fallback: РегистрСведений.КотировкиЦБНаБирже
     - контроль: РегистрНакопления.ДоходыКПолучению.Обороты
   Запрос/логика:
     - расчет НКД по бумагам с исключением бумаг, где купон уже отражен доходом
   Выход в ТЧ:
     - СчетМандата, Валюта, Сумма, СуммаВВалютеДокумента
   Эффект в ПересчитатьДокумент:
     - факт: плюс
     - план: плюс

2) ПлановыйНКД
   Вход:
     - РегистрНакопления.ПлановаяПозицияПоЦеннымБумагам.Остатки
     - РегистрСведений.ЗафиксированныеКотировки
     - fallback: РегистрСведений.КотировкиЦБНаБирже
   Запрос/логика:
     - расчет планового НКД по плановым остаткам
   Выход в ТЧ:
     - СчетМандата, Валюта, Сумма, СуммаВВалютеДокумента
   Эффект в ПересчитатьДокумент:
     - факт: нет
     - план: плюс

3) ДенежныеСредства
   Вход:
     - данные регистров через текст РасчетСтоимостиАктивов.ТекстЗапросаДенежныеСредства()
   Запрос/логика:
     - подбор остатков ДС по счетам мандата
   Выход в ТЧ:
     - СчетМандата, Валюта, Сумма, СуммаВВалютеДокумента
   Эффект в ПересчитатьДокумент:
     - факт: плюс
     - план: плюс

4) ПроцентыПоРЕПО
   Вход:
     - данные регистров через текст РасчетСтоимостиАктивов.ТекстЗапросаПроцентыПоСчетамРЕПО()
   Запрос/логика:
     - начисленные проценты по операциям РЕПО
   Выход в ТЧ:
     - СчетМандата, Валюта, Сумма, СуммаВВалютеДокумента
   Эффект в ПересчитатьДокумент:
     - факт: плюс
     - план: плюс
