внРасчетMVиWAP: текущая схема вызовов и фактическая логика

Документ фиксирует работу обработки "как сейчас" по XML-исходникам проекта bases/Wim_Mo/projects/IMDEV-8665_Retail_MV/epf/внРасчетMVиWAP_epf. Основной фокус: ветка выполнения от Процедура ВыполнитьКомандуПересчет_MV_и_WAP и ниже, включая все внутренние вызовы, фильтры, циклы по датам, удаление/создание документов и итоговую рассылку.

1. Состав обработки

Элемент Путь Назначение
Корневой XML объекта внРасчетMVиWAP.xml Описание внешней обработки, реквизитов, табличных частей и форм.
Модуль объекта внРасчетMVиWAP/Ext/ObjectModule.bsl Главная бизнес-логика, регистрация команд БСП, регламентные и ручные сценарии.
Основная форма внРасчетMVиWAP/Forms/Форма/Ext/Form/Module.bsl Клиентские команды ручного запуска: заполнение мандатов, запуск MV, WAP, расчета СС и финпоказателей.
Форма настроек внРасчетMVиWAP/Forms/ФормаНастроек/Ext/Form/Module.bsl Передача пользовательских настроек для фонового/регламентного запуска.

Реквизиты объекта, влияющие на расчет

  • НачДата, КонДата - рабочий интервал расчета.
  • ПоВсем - считать по всем мандатам или только по табличной части.
  • Мандаты - табличная часть со столбцами Мандат и Факт.
  • ИспользоватьКалендарь, Календарь - правила отбора рабочих дат.
  • ПропуститьРасчет, ПропуститьРасчетПоМандату, ПропуститьРасчетДата - встроенное исключение для одного мандата на глубине 10 дней.
  • ПочтовыйЛогин, СписокРассылки, СписокРассылкиСаппорт - итоговые уведомления.

2. Где начинается интересующая ветка

Для фоновых сценариев обработка регистрирует команды через СведенияОВнешнейОбработке(), а затем БСП вызывает экспортную процедуру ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполненияКоманды).

Представление Идентификатор Что реально вызывается
Пересчет по расписанию MV и WAP за 10 дней Пересчет_MV_и_WAP_10d ВыполнитьКомандуПересчет_MV_и_WAP(10, Ложь), затем (..., Истина)
Пересчет по расписанию MV и WAP за 2 раб. дня Пересчет_MV_и_WAP_2d ВыполнитьКомандуПересчет_MV_и_WAP(2, Ложь), затем (..., Истина)
Пересчет по расписанию MV и WAP RETAIL за 3 дня Пересчет_MV_и_WAP_3d_Retail ВыполнитьКомандуПересчет_MV_и_WAP(3, Ложь), затем (..., Истина)
Пересчет по расписанию MV и WAP RETAIL за 1 день Пересчет_MV_и_WAP_1d_Retail ВыполнитьКомандуПересчет_MV_и_WAP(1, Ложь), затем (..., Истина)
Важная фактическая особенность: даже в RETAIL-командах ветка запускается дважды подряд - сначала для "не физлиц" (Ложь), потом для "физлиц" (Истина). Внутренний фильтр строится по ТипыМандата.I.

3. Текстовая диаграмма вызовов

БСП / доп. обработка
    -> ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполненияКоманды)
        -> УстановитьНастройки(ПараметрыВыполненияКоманды)
            -> УстановитьПользовательскиеНастройки(Настройки)
        -> если команда = Пересчет_MV_и_WAP_*:
            -> ВыполнитьКомандуПересчет_MV_и_WAP(КоличествоДней, Ложь)   // ЮЛ/не I
            -> ВыполнитьКомандуПересчет_MV_и_WAP(КоличествоДней, Истина) // ФЛ/I

ВыполнитьКомандуПересчет_MV_и_WAP(КоличествоДней, ФизЛицо)

    -> принудительно ставит ПоВсем = Истина
    -> задает КонДата = КонецДня(начало текущих суток минус 60 секунд) = конец календарного вчера (не 60 суток)

            -> получает список рабочих дней периода

            -> берет КонДата - КоличествоДней календарных дней

            -> сдвигает на предыдущий рабочий день
    -> Попытка
        -> СформироватьMV(Ошибка, КоличествоДней, Ложь, ФизЛицо)
            -> получает список мандатов
            -> цикл по датам от НачДата до КонДата
                -> УдалитьДокументыРасчетРыночнойСтоимости(ТекДата, МассивМандатов, Ошибка)
                -> цикл по каждому мандату
                    -> НеобходимоПропуститьРасчет(...)
                    -> ПолучитьКурсВалюты(...)
                    -> Документы.РасчетРыночнойСтоимости.СоздатьДокумент()
                    -> Док.ЗаполнитьДокумент()
                    -> Док.Записать(Проведение)
        -> если Ошибка = Истина:
            -> пишет сообщения о проблеме MV-этапа
        -> СформироватьWAP(Ошибка, "", КоличествоДней, Ложь, ФизЛицо)
            -> получает список мандатов
            -> цикл по датам от НачДата до КонДата
                -> УдалитьДокументыРасчетСредневзвешеннойСтоимости(ТекДата, МассивМандатов, Ошибка)
                -> цикл по каждому мандату
                    -> НеобходимоПропуститьРасчет(...)
                    -> Документы.РасчетСредневзвешеннойСтоимости.СоздатьДокумент()
                    -> Док.ЗаполнитьДокумент()
                    -> Док.Записать(Проведение)
        -> если Ошибка = Истина:
            -> пишет сообщения о проблеме WAP-этапа
    -> Исключение
        -> фиксирует текст исключения
        -> ставит Ошибка = Истина
    -> ПолучитьСообщенияПользователю(Истина)
    -> объединяет СписокРассылки + СписокРассылкиСаппорт
    -> формирует тему письма по глубине/типу запуска
    -> РассылкаСообщения(...)
        -> ПропискаРассылки(...)
        -> РаботаСПочтовымиСообщениями.ОтправитьСообщение(...)

4. Детальный разбор `ВыполнитьКомандуПересчет_MV_и_WAP`

4.1. Инициализация

  1. Сбрасываются локальные флаги: Ошибка = Ложь, текст ошибки и текст письма.
  2. Определяется рабочий календарь: если пользовательский календарь не заполнен, берется регламентированный.
  3. ПоВсем = Истина ставится принудительно. Это означает, что ветка фонового пересчета игнорирует ручной отбор мандатов в табличной части и работает по всей выборке.
  4. КонДата задается как КонецДня(НачалоДня(ТекущаяДата()) - 60). В языке 1С из даты вычитается число секунд, поэтому - 60 это минус одна минута от полуночи текущего дня, а КонецДня дает последнюю секунду предыдущего календарного дня (фактически 'вчера' относительно даты сеанса), а не смещение на 60 суток.
Ранее здесь ошибочно трактовалось выражение как 'минус 60 суток'. По правилам платформы 1С это минус 60 секунд от начала текущих суток, то есть конечная дата интервала привязана к концу календарного предыдущего дня. Если бы требовалось именно 60 календарных дней назад, в коде нужно было бы вычитать 60 * 24 * 60 * 60 секунд (или эквивалент через календарные функции).

4.2. Вычисление начальной даты

  • Для КоличествоДней = 2 используется отдельный сценарий: строится список рабочих дней за 20-дневный интервал до КонДата, после чего берется элемент "за 2 рабочих дня".
  • Для остальных значений используется обычное вычитание календарных дней: НачДата = КонДата - N дней.
  • Затем выполняется контроль: если НачДата нерабочая, дата сдвигается на предыдущий рабочий день.

4.3. Запуск двух этапов

  1. Первый этап: СформироватьMV(...).
  2. Второй этап: СформироватьWAP(...).
  3. Оба этапа запускаются внутри одного блока Попытка.
  4. После каждого этапа при установленном флаге Ошибка пользователю отправляется сообщение, но выполнение не прерывается автоматически.

4.4. Что происходит после этапов

  • Собираются все сообщения пользователя через ПолучитьСообщенияПользователю(Истина).
  • Формируется объединенный список адресатов: основная рассылка плюс саппорт.
  • Тема письма зависит от глубины запуска и типа прохода: r26.2.ЮЛ, r26.2.ФЛ и т.д.
  • Итог отправляется через РассылкаСообщения.

5. Что делает `СформироватьMV`

5.1. Получение списка мандатов

Процедура строит запрос к документу УстановкаРеглОпераций.Настройки. Отбираются мандаты по виду операции РасчетРыночнойСтоимости, по признаку активности договора и, при необходимости, по типу мандата.

Условие Как работает сейчас
Отбор по всем/не по всем Если ПоВсем = Истина, фильтр по табличной части отключается строковой заменой текста запроса.
Отбор по физлицам ФизЛицо = Истина - только ТипМандата = I; Ложь - все, кроме I; Неопределено - без фильтра.
Состав возвращаемых полей Мандат, валюта мандата, дата окончания договора.

5.2. Цикл по датам

  1. Берется ТекДата = НачалоДня(НачДата).
  2. На каждую дату вызывается УдалитьДокументыРасчетРыночнойСтоимости.
  3. После удаления начинается цикл по всем выбранным мандатам.

5.3. Цикл по мандатам

  • Если договор мандата уже закончился до текущей даты - мандат пропускается.
  • Если срабатывает НеобходимоПропуститьРасчет(Дата, Мандат, КоличествоДней), мандат пропускается.
  • Если не заполнена валюта мандата - фиксируется ошибка и мандат пропускается.
  • Получается курс валюты через ПолучитьКурсВалюты; внутри используется кэш по ключу "дата + код валюты".
  • Создается документ РасчетРыночнойСтоимости на время 23:59:59.
  • Заполняются реквизиты Валюта, Курс, Кратность, Мандат.
  • Вызывается Док.ЗаполнитьДокумент(), затем Док.Записать(Проведение).
  • Если проведение не удалось, ошибка логируется, но цикл продолжается на следующем мандате.

5.4. Вспомогательные вызовы внутри MV

Процедура / функция Фактическая роль
УдалитьДокументыРасчетРыночнойСтоимости Удаляет все документы РасчетРыночнойСтоимости за конкретную дату и список мандатов, чтобы затем пересоздать их заново.
НеобходимоПропуститьРасчет Возвращает Истина только если включен флаг пропуска, дата меньше/равна контрольной, мандат совпадает и глубина равна 10.
ПолучитьКурсВалюты Берет курс из регистра КурсыВалют.СрезПоследних; при отсутствии курса вызывает исключение.

6. Что делает `СформироватьWAP`

Структурно эта процедура почти зеркальна СформироватьMV, но работает с другим типом документов.

6.1. Общая последовательность

СформироватьWAP
    -> получить список мандатов тем же запросом к УстановкаРеглОпераций
    -> цикл по датам от НачДата до КонДата
        -> УдалитьДокументыРасчетСредневзвешеннойСтоимости(...)
        -> цикл по мандатам
            -> пропуск по дате окончания договора
            -> пропуск через НеобходимоПропуститьРасчет(...)
            -> проверка валюты
            -> Документы.РасчетСредневзвешеннойСтоимости.СоздатьДокумент()
            -> Док.ЗаполнитьДокумент()
            -> Док.Записать(Проведение)

6.2. Отличия от MV

  • Нет обращения к ПолучитьКурсВалюты.
  • Удаляется и создается документ РасчетСредневзвешеннойСтоимости, а не РасчетРыночнойСтоимости.
  • Остальные проверки, фильтры и общий порядок циклов совпадают по структуре.

7. Вспомогательные ветки, которые реально участвуют в сценарии

7.1. `УстановитьНастройки` и `УстановитьПользовательскиеНастройки`

  • Перед выполнением команды из БСП обработка пытается прочитать структуру настроек из ПараметрыДополнительнойОбработки.
  • Если структура есть, в объект переносятся календарь, почтовый логин, списки рассылки, флаги пропуска расчета.
  • Таким образом, фоновые задания не берут значения "из формы", а используют сохраненные пользовательские настройки.

7.2. `РассылкаСообщения`

  • Если получатели есть и заполнен ПочтовыйЛогин, формируется письмо.
  • Тема автоматически получает префикс {OK} или {FAIL}.
  • В тему также добавляется "прописка" рассылки через ПропискаРассылки с номером рассылки и именем ИБ.
  • Отправка идет через РаботаСПочтовымиСообщениями.ОтправитьСообщение.

7.3. `ПолучитьСообщенияПользователю(Истина)`

В конце основной процедуры в письмо попадает не только локально накопленный текст ошибки, но и все пользовательские сообщения, которые были сформированы в MV/WAP и других вызовах. Поэтому итоговое письмо фактически является сводным логом выполнения.

8. Ручной сценарий из основной формы

В основной форме есть отдельные кнопки ручного запуска, но они не используют ВыполнитьКомандуПересчет_MV_и_WAP. Там поток другой: 

Форма -> клиентская команда
    -> серверная обертка формы
        -> прямой вызов метода объекта:
            СформироватьMV(...)
            или СформироватьWAP(...)
            или СформироватьУстановкуСС(...)
            или СформироватьРасчетФинПоказателей(...)
Это важно для анализа "как сейчас": регламентный пересчет и ручной запуск используют общие нижние процедуры, но разные точки входа.

9. Фактические особенности и наблюдения по текущему поведению

  1. Фоновый пересчет всегда ставит `ПоВсем = Истина`. Табличная часть `Мандаты` в этой ветке не ограничивает выборку.
  2. Конечная дата: КонецДня(НачалоДня(ТекущаяДата()) - 60) по факту дает конец предыдущего календарного дня (вычитание 60 секунд в 1С), а не 'минус 60 суток'.
  3. MV и WAP выполняются последовательно. Даже если на этапе MV уже есть ошибки, WAP все равно запускается.
  4. Удаление и создание документов происходят заново на каждую дату и каждый мандат. Это основная структура нагрузки.
  5. Для глубины 2 используется рабочий календарь, для остальных глубин - обычное вычитание дней с последующей коррекцией начала периода.
  6. Письмо объединяет обычную рассылку и саппорт. Поэтому саппорт всегда получает те же письма, что и основной список.
  7. В `УстановитьПараметры()` значение `СписокРассылкиСаппорт` сериализуется из `СписокРассылки`. То есть в текущем коде при сохранении настроек support-список фактически берет данные основной рассылки.
