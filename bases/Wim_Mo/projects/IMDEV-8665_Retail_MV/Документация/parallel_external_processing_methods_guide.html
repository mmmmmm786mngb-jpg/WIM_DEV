Параллельные (фоновые) методы модуля объекта внешней обработки

Методика для базы Wim_Mo и обработки внРасчетMVиWAP, подключенной через Справочник.ДополнительныеОтчетыИОбработки. Используется упрощенный общий модуль ДлительныеОперации конфигурации МО: ЗапуститьВыполнениеВФоне и серверная процедура ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки.

Куда вносить доработки из черновика. Не изменяйте типовой общий модуль ДлительныеОперации базовой конфигурации: это усложнит обновления и слияния с поставкой. Скопируйте код из файла-черновика в новый общий модуль, например ДлительныеОперацииВнешниеОбработки (или другое согласованное имя). Признаки: Сервер; если из формы вы будете вызывать экспорт напрямую с клиента, добавьте Вызов сервера. Исходник черновика в репозитории: bases/Wim_Mo/projects/IMDEV-8665_Retail_MV/Черновики_8665/long_operations_external_processing_adapter.bsl.

1. Цепочка выполнения (идея)

  1. Форма или серверный код вызывает ваш общий модуль-адаптер (из черновика).
  2. Адаптер формирует структуру ПараметрыЗадания с полями ДополнительнаяОбработкаСсылка, ИмяМетода, ПараметрыВыполнения, ЭтоВнешняяОбработка и вызывает ДлительныеОперации.ЗапуститьВыполнениеВФоне(..., "ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки", ...).
  3. Внутри ВыполнитьПроцедуруМодуляОбъектаОбработки платформа получает объект внешней обработки через подсистему доп. обработок (при заполненной ссылке в справочнике) и выполняет ваш метод модуля объекта.
  4. Результат фона кладется во временное хранилище по адресу, который создает ЗапуститьВыполнениеВФоне (поле АдресХранилища в возвращаемой структуре).

Альтернатива с ручным ДополнительныеОтчетыИОбработки.ПолучитьОбъектВнешнейОбработки и РаботаВБезопасномРежиме.ВыполнитьМетодОбъекта в МО обычно не нужна: загрузка объекта по ссылке уже встроена в ВыполнитьПроцедуруМодуляОбъектаОбработки.

2. Контракт процедуры в модуле объекта EPF

Имя процедуры произвольное, но сигнатура строго такая (требование реализации в ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки в МО):

  • Первый параметр получает то, что вы передали в адаптер как параметры метода (структура пачки, контекст и т.д.).
  • Второй параметр - адрес результата во временном хранилище; в конце работы положите туда итог через ПоместитьВоВременноеХранилище.
// Пример имени: ВыполнитьПачкуНСК (замените на свое).
Процедура ВыполнитьПачкуНСК(ПараметрыВыполнения, АдресРезультата) Экспорт

    Результат = Новый Структура;
    Результат.Вставить("Успех", Истина);
    Результат.Вставить("Сообщение", "Фрагмент завершен");
    // Тут вызывается ваша бизнес-логика по ПараметрыВыполнения.

    Если ЗначениеЗаполнено(АдресРезультата) Тогда
        ПоместитьВоВременноеХранилище(Результат, АдресРезультата);
    КонецЕсли;

3. Пример: общий модуль-адаптер (после переноса из черновика)

Экспортные функции в новом модуле (имена как в черновике):

  • ПараметрыЗаданияМетодаДополнительнойОбработки(...) - только сборка структуры, если нужно отдельно от запуска.
  • ЗапуститьМетодДополнительнойОбработкиВФоне(ИдентификаторФормы, СсылкаДопОбработки, ИмяМетода, ПараметрыМетода, ...) - полный запуск.

Возврат ЗапуститьМетодДополнительнойОбработкиВФоне совпадает с ДлительныеОперации.ЗапуститьВыполнениеВФоне: ключи АдресХранилища, ИдентификаторЗадания, ЗаданиеВыполнено (и при необходимости дополнительное ВХ).

5. «Параллельность»: несколько фоновых заданий

Параллелизм на практике - это несколько вызовов ЗапуститьМетодДополнительнойОбработкиВФоне подряд (или из цикла по пачкам):

  • у каждого вызова свой ИдентификаторЗадания и свой АдресХранилища в возвращаемой структуре;
  • в ПараметрыМетода передавайте различие пачек (номер диапазона, список мандатов и т.д.);
  • храните соответствие «номер пачки - ИдентификаторЗадания - АдресХранилища» в структуре на форме или во временном хранилище оркестратора.
На стороне сервера 1С несколько активных фоновых заданий действительно могут выполняться одновременно (в пределах нагрузки кластера и лицензий). Синхронизация записей в базу и конфликты по данным нужно проектировать отдельно (области в параметрах пачки, блокировки, идемпотентность).

6. Запуск из модуля объекта той же обработки

Допускается: экспортная функция в ObjectModule.bsl EPF, внутри - вызов того же адаптера (ДлительныеОперацииВнешниеОбработки.ЗапуститьМетодДополнительнойОбработкиВФоне) с переданной ссылкой ДополнительныеОтчетыИОбработки на эту же обработку. Форма вызывает метод объекта с сервера. Экземпляр объекта, из которого вызвали запуск, и экземпляр в фоне - разные: фон заново получает объект по ссылке.

Краткий чек-лист
  1. Создать новый общий модуль; перенести код из long_operations_external_processing_adapter.bsl.
  2. В EPF добавить экспортную процедуру с сигнатурой (ПараметрыВыполнения, АдресРезультата).
  3. Убедиться, что обработка опубликована в справочнике и ссылка корректна для выбранной базы.
  4. С сервера вызвать адаптер; на клиенте при необходимости опросить завершение и прочитать результат из ВХ.
  5. Для нескольких пачек - несколько запусков и учет массива идентификаторов заданий.
