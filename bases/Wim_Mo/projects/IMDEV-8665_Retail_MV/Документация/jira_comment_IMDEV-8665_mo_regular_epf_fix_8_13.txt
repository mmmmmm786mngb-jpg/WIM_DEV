h2. IMDEV-8665: исправление EPF для обычного МО (не Retail)

{panel:title=Что сделано|borderStyle=solid|borderColor=#0d6efd|titleBGColor=#EAF2FF|bgColor=#F5F9FF}
* Версия внешней обработки {{внРасчетMVиWAP}}: *2.200* -> *2.201* (каталог {{epf - МО обычное}}).
* В процедуре {{СформироватьПачкуДокументовВФоне}} (модуль объекта EPF) уточнено условие создания служебного документа {{СлужебныйДок}}:

{code}
// Было:
Если Не ФизЛицо = Истина Тогда
    СлужебныйДок = Неопределено;

// Стало:
Если Не ФизЛицо = Истина
    Или Найти(Врег(Константы.ЗаголовокСистемы.Получить()), "RETAIL") = 0 Тогда
    СлужебныйДок = Неопределено;
{code}

* Метаданные обработки ({{внРасчетMVиWAP.xml}}) *не менялись* — правка только в BSL.
{panel}

{panel:title=Для чего и причина изменений|borderStyle=solid|borderColor=#fd7e14|titleBGColor=#FFF4E6|bgColor=#FFFBF5}
*Оптимизация IMDEV-8665* (служебный документ MV на пачку мандатов + {{КопироватьПоМандату}}, пакет WAP через {{ПолучитьДанныеРасчета}}) рассчитана на *Retail MO*:
** котировки из {{ЗафиксированныеКотировки}} для розничных мандатов типа *B* идут через один мандат *{{РозничноеДУ}}* ({{ВТБ_АлгоритмыРасчета.МандатРозничноеДУ}});
** в пакетных запросах расширения {{MV_WAP}} котировки подключаются по *активу*, без различения мандата в join — это корректно только при едином источнике котировок.

*На обычном МО* у разных мандатов *разные* {{МандатДляКотировки}} (часто сам мандат, не только {{РозничноеДУ}}). Один служебный документ на пачку с одним параметром {{&МандатДляКотировки}} дает *неверные котировки / ошибки заполнения*.

*Исправление:* на среде без {{RETAIL}} в {{ЗаголовокСистемы}} для физлиц отключен быстрый путь — каждый документ MV/WAP создается через {{ЗаполнитьДокумент()}} со своим мандатом в шапке (как в базовой конфигурации).

*На Retail MO* ({{RETAIL}} в заголовке) поведение *без изменений* — служебный документ и ускорение пачки сохраняются.
{panel}

{panel:title=Какие виды оптимизации IMDEV-8665 где работают|borderStyle=solid|borderColor=#6c757d|titleBGColor=#F1F3F5|bgColor=#FAFAFA}
По документации задачи ({{changes_tree_IMDEV-8665.html}}, {{jira_comment_IMDEV-8665_final_8_13.txt}}):

*Остаются и для обычного МО, и для MO Retail:*
* *Параллельность (EPF):* фоновое удаление и создание/проведение документов MV/WAP пачками ({{ДлительныеОперации}}, {{СформироватьДокументыПараллельно}}, {{УдалитьДокументыФоновоУниверсально}}); настройка {{ЧислоПараллельныхФоновыхЗаданий}}.
* *Кеш (расширение {{MV_WAP}}):* {{ПолучитьКурсВалюты}}, {{ПолучитьВалютыРасчета}} (кеш сеанса).
* *Ускорение старта фоновых заданий:* перехват {{ДлительныеОперации.ЗапуститьВыполнениеВФоне}} (интервал ожидания 0,2 / 4 с).

*Только MO Retail* ({{RETAIL}} в {{ЗаголовокСистемы}}, расчет по физлицам):
* *Пакетное заполнение MV на пачку мандатов:* служебный документ ({{МассивМандатов}}, {{ПерезаполнитьВсеТЧ}}, индекс, {{КопироватьПоМандату}}); запросы расширения с {{Мандат В (&Мандат)}} и единым {{МандатДляКотировки}} ({{РозничноеДУ}}).
* *Пакетная предзагрузка WAP на пачку:* один {{ПолучитьДанныеРасчета}} на массив мандатов в служебном документе.

*Отключено на обычном МО* (правка EPF 2.201 — {{СлужебныйДок = Неопределено}}):
* перечисленные два пункта «только Retail»; вместо них — штатное {{ЗаполнитьДокумент()}} *на каждый мандат* (корректный свой {{МандатДляКотировки}} и join котировок по мандату+активу).
* Для юрлиц на обеих средах быстрый путь служебного документа и раньше не использовался.

*Артефакт:* {{bases/Wim_Mo/projects/IMDEV-8665_Retail_MV/epf - МО обычное/}} (версия 2.201); расширение {{MV_WAP}} — без изменений по этой правке.
{panel}
