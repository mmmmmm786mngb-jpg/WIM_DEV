## Цель

Разобрать и задокументировать, как в конфигурации `Wim_Mo` работает регламент закрытия
портфелей (мандатов) — полный путь от клиентской процедуры
`СформироватьРегламентныеОперации()` формы `РегламентныйПериод` справочника
`РегламентныеПериоды` до выполнения регламентных процедур закрытия периода и
создания подчинённых документов. Отдельный акцент — **разделение на фоновые задания**.

## Точка входа

**Справочник** `РегламентныеПериоды` → **форма** `РегламентныйПериод` → команда
«Сформировать регл. операции» → клиентская процедура:

```bsl
&НаКлиенте
Процедура СформироватьРегламентныеОперации()
```

Модуль формы: `SRC/CF/Catalogs/РегламентныеПериоды/Forms/РегламентныйПериод/Ext/Form/Module.bsl`,
строки **650–695**.

## Ключевые объекты конфигурации, задействованные в регламенте

| Объект | Назначение |
|---|---|
| `Справочник.РегламентныеПериоды` (форма `РегламентныйПериод`) | Точка входа и UI. Разбиение на пачки по 5 мандатов (MID-153) |
| `Справочники.РегламентныеПериоды.ПолучитьАдресВременногоХранилища` | Подготовка: собирает `СписокОпераций`, `МассивРодителей`, распроводит старые документы, задаёт `КоличествоПотоков` |
| `Справочники.РегламентныеПериоды.СформироватьДокументыЗакрытияПериода` | Диспетчер: развилка «фон / синхронно», барьер ожидания, сбор ошибок |
| `ОбщийМодуль.ФоновыеЗаданияСервер.СоздатьПланРегламентныхОпераций` | Тело фонового задания — создаёт/обновляет `ПланРегламентныхОпераций`, проводит его, вызывает `ВыполнитьРегламентныеПроцедуры` |
| `Документ.ПланРегламентныхОпераций.ВыполнитьРегламентныеПроцедуры` | Исполнитель операций: цикл по ТЧ `Операции`, создание подчинённых документов |
| `Справочник.ВидыОперацийЗакрытияПериода` | Каталог операций закрытия, хранит ссылку на исполняемую процедуру |
| `РегистрСведений.НастройкиЗакрытияПериода` | План регл. операций по мандатам и периодичности |
| `РегистрСведений.ИсполнениеОпераций` | Факт выполнения регл. операций (проверка и запись) |
| `ОбщийМодуль.ИсполняемыеПроцедурыЗакрытияПериода` | Тело исполняемых процедур (расчёты, переоценки, котировки) |
| `Константы.МаксимальноеКоличествоПараллельныхПотоков` | Лимит параллелизма. Сейчас в коде жёстко заменено на `0` (заглушка RMC-52) |

## Текущее состояние разделения на фоновые задания

В менеджерном модуле `Справочники.РегламентныеПериоды.ПолучитьАдресВременногоХранилища`
хранится строка:

```bsl
КоличествоПотоков = 0; // Заглушка RMC-52 // Константы.МаксимальноеКоличествоПараллельныхПотоков.Получить();
```

Из-за неё диспетчер всегда идёт в ветку `Иначе` и вызывает
`ФоновыеЗаданияСервер.СоздатьПланРегламентныхОпераций` **синхронно**. Ветка с
`ФоновыеЗадания.Выполнить(...)` и `ФоновыеЗадания.ОжидатьЗавершения(...)`
полностью реализована, но не активируется до снятия заглушки и возврата чтения
константы `МаксимальноеКоличествоПараллельныхПотоков`.

Подробности — в HTML в папке `Документация/`.
