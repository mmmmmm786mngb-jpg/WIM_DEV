# Перенос расширения WimPar в основную конфигурацию WIM_MO

Документ описывает, как перенести содержимое расширения `WimPar` напрямую
в основную конфигурацию `WIM_MO` без установки самого расширения.
Все изменения — точечные, не затрагивают существующие объекты основной
конфигурации, за исключением добавления новой команды/кнопки в форму
`Справочник.РегламентныеПериоды.Форма.РегламентныйПериод`.

> Источник исходников: `bases/Wim_Mo/projects/XXXX_РегламентЗакрытияПортфелей/Расширения/WimPar/src/`

## 0. Предпосылки

- Платформа `8.3.27+` уже установлена.
- `CompatibilityMode` основной конфигурации `WIM_MO` — `Version8_3_21` или выше.
  Если база сейчас на `Version8_3_6`, перед переносом нужно поднять режим
  совместимости основной конфигурации (Конфигуратор → Конфигурация →
  свойства корневого узла → «Режим совместимости»).
- В Конфигураторе включён режим хранения в каталоге исходников (для
  последующего контроля и диффа).
- Есть резервная копия конфигурации (`DumpCfg` / бэкап БД).

## 1. Что именно переносится

| № | Объект в расширении | Куда переносится в основной конфигурации | Имя в основной конфигурации (после снятия префикса) |
|---|---|---|---|
| 1 | `Constant.WimPar_МаксимальноеКоличествоПараллельныхПотоков` | Константы | `МаксимальноеКоличествоПараллельныхПотоков` |
| 2 | `CommonModule.WimPar_ПараллельноеВыполнение` | Общие модули | `ПараллельноеВыполнениеРегламентаПортфелей` *(имя можно сохранить без префикса или взять из соглашений проекта)* |
| 3 | `Catalog.РегламентныеПериоды.Form.РегламентныйПериод` — новая команда `WimPar_СформироватьПараллельно` и кнопка `WimPar_СформироватьПараллельноКнопка` в группе `WimPar_ГруппаПараллельного` | Существующая форма того же справочника | Команда `СформироватьПараллельно`, кнопка `СформироватьПараллельноКнопка`, группа `ГруппаПараллельного` |
| 4 | Код модуля формы (обработчик команды и подготовка сессии) | Модуль формы `РегламентныйПериод` | имена процедур без префикса `WimPar_` |

Заимствованные объекты (`CommonPicture.ДокументПроведенКоннекторВерх`,
`Language.Русский`, сама форма и справочник) уже существуют в основной
конфигурации и переноса не требуют.

## 2. Рекомендация по префиксам

В расширении все добавленные объекты имеют префикс `WimPar_`. При переносе
в основную конфигурацию есть два подхода:

1. **Сохранить префикс `WimPar_`** — удобно, если по аналогии планируется
   несколько «портфельных» доработок: `WimPar_...`, `WimRep_...`.
   Плюс: новые объекты легко отличать от стандартных.
2. **Снять префикс** — если проект живёт как единая основная конфигурация
   без деления на «модули». В этом случае имена чище, но нужно убедиться,
   что они не конфликтуют с существующими.

В этом документе дальше приводятся имена **со снятым префиксом** как вариант
по умолчанию. При желании оставить префикс — просто не делайте замену имён
на шагах 3–6.

## 3. Перенос константы

### 3.1 Создать константу в основной конфигурации

- Конфигурация → Общие → Константы → ПКМ → Добавить.
- Свойства:
  - **Имя:** `МаксимальноеКоличествоПараллельныхПотоков`
  - **Синоним:** `Максимальное количество параллельных потоков`
  - **Тип:** Число, длина 3, дробная часть 0, знак — неотрицательный
  - **Подсказка:** `Максимальное количество фоновых заданий, которые параллельно формируют регламентные операции по мандатам. 0 или 1 — синхронный режим.`
- Подсистема / подсистемы: согласно принятым в проекте соглашениям
  (например, «Администрирование» или «Параметры учёта»). В расширении
  этого не было, так как BSP-подсистемы не заимствовались.

### 3.2 Задать начальное значение

- Запустить 1С:Предприятие → открыть форму константы и установить
  нужное значение (например, `4` — по числу ядер/воркеров сервера).

## 4. Перенос общего модуля

### 4.1 Создать общий модуль в основной конфигурации

- Конфигурация → Общие → Общие модули → ПКМ → Добавить.
- Свойства общего модуля:
  - **Имя:** `ПараллельноеВыполнениеРегламентаПортфелей`
  - **Синоним:** `Параллельное выполнение регламента портфелей`
  - **Сервер:** Истина
  - **Внешнее соединение:** Истина
  - **Вызов сервера:** Истина
  - **Клиент (управляемое приложение):** Ложь
  - **Клиент (обычное приложение):** Ложь
  - **Привилегированный:** Ложь

### 4.2 Скопировать тело модуля

Исходник:

`bases/Wim_Mo/projects/XXXX_РегламентЗакрытияПортфелей/Расширения/WimPar/src/CommonModules/WimPar_ПараллельноеВыполнение/Ext/Module.bsl`

В этом файле — пять экспортных методов (`ПолучитьКоличествоПотоков`,
`ФоновыеЗаданияРазрешены`, `РазделитьМандатыНаПартиции`,
`ПерезаписатьКоличествоПотоковВХранилище`, `СформироватьПартициюМандатов`,
`ОжидатьЗавершенияЗаданий`). Содержимое скопировать в модуль
`ОбщиеМодули.ПараллельноеВыполнениеРегламентаПортфелей.Модуль` без
изменений, затем:

- Заменить обращение `Константы.WimPar_МаксимальноеКоличествоПараллельныхПотоков`
  на `Константы.МаксимальноеКоличествоПараллельныхПотоков` (если сняли префикс).
- Заменить имя метода в запуске ФЗ в модуле формы (см. шаг 6) с
  `"WimPar_ПараллельноеВыполнение.СформироватьПартициюМандатов"` на
  `"ПараллельноеВыполнениеРегламентаПортфелей.СформироватьПартициюМандатов"`.

## 5. Перенос UI-расширения формы

Открыть основную форму `Справочник.РегламентныеПериоды.Форма.РегламентныйПериод`
в Конфигураторе.

### 5.1 Добавить команду формы

- В редакторе формы → закладка «Команды» → добавить команду:
  - **Имя:** `СформироватьПараллельно`
  - **Заголовок:** `Создать операции (параллельно)`
  - **Действие:** `СформироватьПараллельно` (имя клиентской процедуры в модуле формы — см. шаг 6).
  - **Представление:** Картинка и текст.
  - **Картинка:** `CommonPicture.ДокументПроведенКоннекторВерх` (взять ту же,
    что использует расширение, либо заменить на любую другую по вкусу).

### 5.2 Добавить группу и кнопку

- В редакторе формы → закладка «Элементы» → добавить на корневой уровень
  новую **обычную группу**:
  - **Имя:** `ГруппаПараллельного`
  - **Заголовок:** `Параллельное закрытие`
  - **Тип группы:** Горизонтальная или «командная панель» — по решению разработчика.
- Внутрь группы добавить **кнопку**:
  - **Имя:** `СформироватьПараллельноКнопка`
  - **ИмяКоманды:** `Форма.Команда.СформироватьПараллельно`
  - **Заголовок:** `Создать операции (параллельно)`

> В расширении эта группа добавляется на корневой уровень формы, так как
> штатная `AutoCommandBar` уже заполнена системными кнопками. В основной
> конфигурации можно разместить кнопку прямо в `AutoCommandBar`, если это
> удобнее — поведение команды не изменится.

## 6. Перенос кода модуля формы

Открыть модуль `Справочник.РегламентныеПериоды.Форма.РегламентныйПериод.Модуль`.
Добавить в конец модуля код из файла:

`bases/Wim_Mo/projects/XXXX_РегламентЗакрытияПортфелей/Расширения/WimPar/src/Catalogs/РегламентныеПериоды/Forms/РегламентныйПериод/Ext/Form/Module.bsl`

При копировании выполнить следующие замены имён (если решено снять
префикс `WimPar_`):

| Имя в расширении | Имя в основной конфигурации |
|---|---|
| `WimPar_СформироватьПараллельно` (команда / клиентская процедура) | `СформироватьПараллельно` |
| `WimPar_ПодготовитьПараллельнуюСессию` | `ПодготовитьПараллельнуюСессию` |
| `WimPar_ВыполнитьСинхронноВсеМандаты` | `ВыполнитьСинхронноВсеМандаты` |
| `WimPar_ОжидатьЗавершенияНаСервере` | `ОжидатьЗавершенияНаСервере` |
| `WimPar_ОбновитьИнтерфейсПослеЗавершения` | `ОбновитьИнтерфейсПослеЗавершения` |
| `WimPar_ПараллельноеВыполнение.ПолучитьКоличествоПотоков()` | `ПараллельноеВыполнениеРегламентаПортфелей.ПолучитьКоличествоПотоков()` |
| `WimPar_ПараллельноеВыполнение.ФоновыеЗаданияРазрешены()` | `ПараллельноеВыполнениеРегламентаПортфелей.ФоновыеЗаданияРазрешены()` |
| `WimPar_ПараллельноеВыполнение.ПерезаписатьКоличествоПотоковВХранилище(...)` | `ПараллельноеВыполнениеРегламентаПортфелей.ПерезаписатьКоличествоПотоковВХранилище(...)` |
| `WimPar_ПараллельноеВыполнение.РазделитьМандатыНаПартиции(...)` | `ПараллельноеВыполнениеРегламентаПортфелей.РазделитьМандатыНаПартиции(...)` |
| `WimPar_ПараллельноеВыполнение.ОжидатьЗавершенияЗаданий(...)` | `ПараллельноеВыполнениеРегламентаПортфелей.ОжидатьЗавершенияЗаданий(...)` |
| `"WimPar_ПараллельноеВыполнение.СформироватьПартициюМандатов"` (строка имени метода для `ФоновыеЗадания.Выполнить`) | `"ПараллельноеВыполнениеРегламентаПортфелей.СформироватьПартициюМандатов"` |

Внутри процедуры `ПодготовитьПараллельнуюСессию` используются следующие
штатные методы, которые **уже есть** в основной конфигурации (менять их не
нужно):

- `Справочники.РегламентныеПериоды.ПериодПоДате(ДатаПериода)`
- `Справочники.Мандаты.СписокМандатовПоДинамическомуСписку(ДатаПериода, Мандаты)`
- `Справочники.РегламентныеПериоды.ПолучитьАдресВременногоХранилища(...)`
- `Справочники.РегламентныеПериоды.СформироватьДокументыЗакрытияПериода(...)`
- `ФоновыеЗаданияСервер.ФоновыеЗаданияРазрешены()`

Реквизит формы `ДатаПериода`, `Мандаты`, `ДеревоРеглОпераций`,
`ГруппаРегламентныхОпераций`, `АдресВременногоХранилища` также уже есть
на форме — их создавать не нужно.

## 7. Проверка корректности переноса

1. Конфигурация → Проверка конфигурации → «Проверить логически» — убедиться,
   что нет неразрешённых ссылок.
2. Обновить конфигурацию БД (`Обновить конфигурацию БД` / `UpdateDBCfg`) —
   проверить, что динамическое обновление не требует реструктуризации
   (кроме новой константы), и отсутствуют ошибки проверки метаданных.
3. В 1С:Предприятии:
   - Открыть форму константы `МаксимальноеКоличествоПараллельныхПотоков`,
     установить значение `0` и нажать на новую кнопку «Создать операции
     (параллельно)» — должно сработать как синхронный режим (сообщение
     «синхронное закрытие завершено, обработано мандатов = N»).
   - Установить значение `3` или `4` и повторить — в фоновых заданиях
     (Администрирование → Текущие задания) должны появиться N записей с
     именем `WimPar: параллельное закрытие <период> [1]`, `[2]`, `[3]`.
     После завершения форма должна показать сообщение `WimPar: параллельное
     закрытие завершено. Успешно: N партиций`.
   - Проверить журнал регистрации — не должно быть ошибок уровня «Ошибка».

## 8. Удаление временных артефактов

После успешного переноса в основную конфигурацию расширение `WimPar` больше
не нужно. При необходимости:

- В Конфигураторе → Расширения конфигурации → удалить `WimPar` (если оно
  было установлено в базу ранее).
- В исходниках проекта папка
  `bases/Wim_Mo/projects/XXXX_РегламентЗакрытияПортфелей/Расширения/WimPar/`
  остаётся как справочный артефакт и может быть удалена либо помечена как
  «исторический материал» в README.

## 9. Контрольный список переноса

- [ ] Основная конфигурация переведена на `CompatibilityMode ≥ Version8_3_21`
- [ ] Создана `Константа.МаксимальноеКоличествоПараллельныхПотоков` (тип Число, 3/0, неотрицательное)
- [ ] Создан `ОбщийМодуль.ПараллельноеВыполнениеРегламентаПортфелей` (Сервер, Внешнее соединение, Вызов сервера)
- [ ] Код общего модуля скопирован из расширения и адаптированы имена констант
- [ ] В форму `РегламентныйПериод` добавлены команда `СформироватьПараллельно`, группа `ГруппаПараллельного` и кнопка `СформироватьПараллельноКнопка`
- [ ] В модуль формы скопированы процедуры и выполнены замены имён
- [ ] Проверка конфигурации пройдена
- [ ] Обновление конфигурации БД пройдено
- [ ] Синхронный режим (значение константы 0/1) протестирован
- [ ] Параллельный режим (значение константы ≥ 2) протестирован
- [ ] Расширение `WimPar` удалено из списка активных расширений базы

## 10. Откат

В случае проблем после переноса:

1. Восстановить конфигурацию из бэкапа (`LoadCfg`) или сделать откат
   изменений в Git/хранилище конфигурации.
2. Константа `МаксимальноеКоличествоПараллельныхПотоков` пустого значения
   (`0`) — синхронный режим — безопасное значение по умолчанию; кнопку
   можно скрыть через «Видимость» без удаления кода.
3. Если требуется оперативный откат только UI-части (кнопки), достаточно
   в форме снять «Использование» у группы `ГруппаПараллельного` — код при
   этом остаётся в модуле, но пользователь его не видит.
