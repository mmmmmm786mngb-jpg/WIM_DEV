Суть задания IMDEV-8829: выгрузка позиций Retail ДУ в Аванкор ФО

Проект: Retail_DU (база МО) · Jira IMDEV-8829 · Epic: оптимизация производительности (Розничное ДУ) · Источники: регламенты ИБ Retail_DU, EPF внВыгрузкаОстатковМО_ФО, конфигурация Wim_Mo

Одной строкой: «Регламентное задание по выгрузке позиций» в Retail_DU - это ОбменыПодсистемыТранспорт → узел ВыгрузкаОстатков_ФОРозн → внешняя обработка остатков МО→ФО (внВыгрузкаОстатковМО_ФО, команда ФоноваяВыгрузка), старт в 06:00. Именно его имеют в виду в Jira, когда пишут про рост времени с числом договоров.

Проблема (из Jira): регламент выполняется автоматически; с ростом числа договоров ДУ пропорционально растет время выгрузки позиций. Уже около 4-5 часов; есть риск не успеть выгрузить все позиции в Аванкор ФО (РДУ) до начала торгов.

Цель оптимизации: уложиться в окно до торгов (ориентир - завершение к ~10:00 МСК при утренней сессии), сохранив корректность позиций, ЦБ, ДС, РЕПО и связанных данных в фронт-офисе.

2. Цепочка выполнения (от регламента до WS)

  1. 06:00 - срабатывает регламент ОбменыПодсистемыТранспорт для узла ВыгрузкаОстатков_ФОРозн.
  2. ОписаниеОбменов.ВыполнитьОбработкуПоРегламентномуЗаданию → ПланыОбмена.ИсточникиОбмена.ВыполнитьРегламентноеЗадание → ОписаниеОбменовОбменСервер.ВыполнитьОбмен.
  3. Для способа обмена «Внешняя обработка» вызывается ДополнительныеОтчетыИОбработки.ВыполнитьКоманду с идентификатором из настроек узла (обычно ФоноваяВыгрузка).
  4. внВыгрузкаОстатковМО_ФО.ВыполнитьКоманду подставляет настройки из хранилища настроек узла и вызывает ОписаниеОбменов.ВыполнитьКомандуПоОбменам.
  5. ОписаниеОбменов.Выгрузить создает бизнес-процесс ВыгрузкаДанных с двумя точками: ПодготовитьДанные и ЗаписатьДанные.
  6. ПодготовитьДанные - отбор счетов мандатов, заполнение табличных частей обработки из регистров МО.
  7. ЗаписатьДанные → Опубликовать() - формирование XDTO-пакетов по портфелям (мандатам) и вызовы WS DownloadPosition на стороне Аванкор ФО.
  8. По завершении - рассылка уведомления «Загрузка остатков МО -> ФО», запись в протокол обмена.

3.3. Табличные части (что собирается как «позиция»)

После ПодготовитьДанные в обработке заполнены ТЧ, из которых Опубликовать строит пакеты:

  • ЦенныеБумаги - остатки ЦБ по счетам мандатов
  • ДенежныеСредства - остатки ДС
  • СЧА_РСА - данные СЧА/РСА
  • ДвиженияДС_План - плановые движения ДС
  • Блокировки - блокировки активов
  • ИсполненияПоСделкам - исполнения
  • РЕПОДеньги, СделкиРЕПОМО - сделки и деньги по РЕПО

3.4. Этап подготовки: отбор мандатов

Функция СформироватьОтборДляФоновогоЗадания выбирает счета мандатов с остатками на дату КонецДня(Вчера) из регистров ДенежныеСредства и ЦенныеБумаги, с фильтрами по типу счета и мандата. При ОтборМандат = Истина добавляется условие по списку мандатов - так на узле Retail обычно ограничивают выгрузку розничным ДУ.

3.5. Этап публикации: почему растет время с числом договоров

Процедура Опубликовать - основной потребитель времени:

  • Группирует ДС и ЦБ по мандату (портфелю / договору ДУ).
  • Накапливает портфели в пакеты по КоличествоПортфелейВПакете (по умолчанию 50).
  • На каждый полный пакет - минимум два вызова WS: DownloadPosition (флаги «позиция не выгружена») и DownloadPosition (сами позиции).
  • Дополнительно: сделки РЕПО, виртуальные субпортфели, обработка ответов, регистрация ненайденных на других узлах.

Закономерность: при росте числа договоров растет число итераций цикла по портфелям и число сетевых вызовов WS. Линейная или близкая к линейной зависимость длительности от числа портфелей - ожидаемое поведение текущей архитектуры.

5. Где смотреть в базе и что мерить

5.1. Навигация в 1С

  1. Администрирование → Регламентные и фоновые задания → найти ОбменыПодсистемыТранспорт с ключом ВыгрузкаОстатков_ФОРозн.
  2. План обмена «Источники обмена» → узел ВыгрузкаОстатков_ФОРозн - внешняя обработка, команда, WS, хранилище настроек.
  3. Дополнительные отчеты и обработки → «Выгрузка остатков МО ФО».
  4. После прогона: бизнес-процессы ВыгрузкаДанных с привязкой к узлу; журнал регистрации / протокол обмена.

5.2. Метрики для оптимизации

МетрикаКак получить

6. Направления оптимизации (для backlog)

  • Увеличение КоличествоПортфелейВПакете при допустимой нагрузке на WS/ФО (trade-off: размер пакета и время ответа).
  • Параллельная выгрузка пакетов (если платформа и ФО допускают - требует анализа блокировок и идемпотентности).
  • Сокращение объема данных в пакете (не выгружать неизменившиеся портфели, дельта).
  • Оптимизация запросов в Заполнить / ПодготовитьДанные (индексы, отбор на уровне СУБД).
  • Разделение тяжелых блоков (РЕПО, СЧА) на отдельные регламенты с другим расписанием - только при согласовании с бизнесом ФО.

7. Итог

Суть IMDEV-8829 - ускорить и стабилизировать ежедневную выгрузку позиций (остатков) из МО Retail ДУ в Аванкор ФО, запускаемую регламентом 06:00 по узлу ВыгрузкаОстатков_ФОРозн через обработку внВыгрузкаОстатковМО_ФО. Котировки, MV/WAP, загрузка транзакций и выгрузка счетов/ЦБ - соседние процессы утреннего контура, но не тот регламент, о котором в Jira сказано «пропорционально растет время выгрузки позиций».
