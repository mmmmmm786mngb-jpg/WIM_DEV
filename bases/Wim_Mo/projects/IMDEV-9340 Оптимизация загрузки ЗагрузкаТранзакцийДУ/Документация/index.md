## Кратко по плану тестирования

Два узла обмена ДУ -> МО. Основная нагрузка — `ЗагрузкаТранзакцийДУ` (каждые 5 мин в рабочее время, иначе каждые 30 мин). Обмен по правилам конвертации 2.1, COM из ДУ.

**Выгрузка (9106, уже на проде):** кэш в `ПолучитьМестоХранения`, оптимизация `ПроверкаДоговорДУРозничный`. Замер 28.07.2026, 2000 зарегистрированных / 3005 в сообщении Аванкора: 96 с -> 59 с (**39%** только выгрузка). Выгрузка и загрузка по времени примерно равны (~50/50), поэтому в 9106 записали **~15%** на весь цикл.

**Загрузка (9340):** алгоритм `ПроставитьФактическиеДатыОснования` — не перезаписывать фактические даты, если они уже совпадают. 130 с -> 120 с (**~10%** этапа загрузки, **~5%** цикла). Итого по плану: **15% + 5% = 20%**.

Оговорка плана: выигрыш загрузки считается на **уже существующих** объектах (повторная запись не делается). Пункт «заполнить даты при выгрузке» не сделали: у ПКО отключено обновление найденного объекта (Днепровский / Катунин).

Для более серьёзного ускорения в плане указан переход на веб-сервис или COM-обмен, не точечные правки правил.
