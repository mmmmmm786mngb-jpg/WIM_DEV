# Техническое задание: расширение Obezl (исходный вариант и сверка с фактом)

> **Назначение папки ОЛД.** Этот файл фиксирует исходную задумку (многомодульная архитектура) и подробную таблицу «план vs факт».  
> **Актуальное рабочее ТЗ для разработки:** [`../technical_spec_obezl_single_processor.md`](../technical_spec_obezl_single_processor.md).  
> **Карта полей для бизнеса и приемки:** [`anonymization_map.html`](anonymization_map.html).

**Сверка с кодом:** май 2026, обработка `Obezl_Запуск`, расширение `Obezl`, база `Wim_Mo` (копия).

---

## 1. Цель

Обезличивание данных в **копии** базы `Wim_Mo` для передачи вендору / тестовых сред:

- сохранение ссылочной целостности;
- параллельная обработка пачками (до 8 фоновых заданий);
- единый сценарий с формы (одна кнопка «Обезличить»);
- без пользовательских настроек на форме — все правила в коде.

---

## 2. Область обработки (факт)

| № | Объект метаданных | Действие |
|---|-------------------|----------|
| 1 | `Справочник.Контрагенты` | Маскирование по отбору (клиенты + фонды) |
| 2 | `Справочник.Мандаты` | Переименование (префикс ДУ или карта) |
| 3 | `Справочник.СчетаМандатов` | Наименование по карте мандата / скобки |
| 4 | `Справочник.СчетаДЕПО` | Наименование (первая пара скобок) |
| 5 | `Справочник.БрокерскиеСчета` | `НомерБанковскогоСчета` |
| 6 | `Справочник.БанковскиеСчета` | Номер, комментарий, цифры в наименовании |
| 7 | `РегистрСведений.ВерсииОбъектов` | Полная очистка после успешных этапов |

Предопределенные элементы справочников **не изменяются**. Прочие объекты конфигурации **не трогаются**.

## 3. Архитектура: план vs факт

### 3.1 Состав (план — не реализован)

| Компонент (план) | Назначение |
|------------------|------------|
| `Obezl_ОбезличиваниеСервер` | Правила обезличивания |
| `Obezl_ПараллельноеВыполнение` | Разбиение на пачки, фон |
| `Obezl_СлужебныйЛог` | Журнал |
| `Obezl_СоответствияНаименований` | Регистр карты мандатов |
| `Obezl_СтатусВыполнения` | Регистр статуса |
| Несколько кнопок / этапов на форме | Пошаговый UI |

### 3.2 Состав (факт)

| Файл / объект | Роль |
|---------------|------|
| `DataProcessors/Obezl_Запуск/Ext/ManagerModule.bsl` | Оркестратор `Obezl_ОркестраторОбезличивания`, разбиение на пачки, ожидание фона, прогресс |
| `DataProcessors/Obezl_Запуск/Ext/ObjectModule.bsl` | Отбор ссылок, карта и снимок, `Obezl_ВыполнитьПачку`, правила по объектам |
| `Forms/Форма/Ext/Form/Module.bsl` | Кнопка «Обезличить», БСП длительные операции, опрос завершения |
| Расширение `ДлительныеОперации` | `ЗапуститьВыполнениеВФоне` → `ВыполнитьПроцедуруМодуляОбъектаОбработки` |
| Переменная модуля `КартаМандатов` | `Соответствие` в памяти сеанса объекта обработки |
| Временное хранилище | Снимок «до», результат оркестратора, результаты пачек |

**Удалено из кода (май 2026):** отдельные процедуры «шаг 2» / «шаг 3», `Obezl_ОркестраторШаг2`, синхронный `ВыполнитьОбезличиваниеШаг2`, отдельный прогон фондов — логика встроена в основной проход.

### 3.3 Точки входа (только фон)

| Процедура | `Экспорт` | Кто вызывает |
|-----------|-----------|--------------|
| `Obezl_ОркестраторОбезличивания` | Да | Форма через БСП (`Обработки.Obezl_Запуск.Obezl_ОркестраторОбезличивания`) |
| `Obezl_ВыполнитьПачку` | Да | Фоновое задание по имени метода |
| `ПолучитьСсылкиДляЭтапа`, `ПолучитьСсылкиСчетовМандатовПоВладельцам` | Да | Менеджер → объект |
| `СформироватьКартуМандатов`, `СформироватьСнимокДоОбезличивания` | Да | Оркестратор |
| `ОчиститьВерсииОбъектов`, `ОчиститьСлужебныеДанные` | Да | Оркестратор после этапов |

Внутренние процедуры (`ОбработатьПачку`, `ОбезличитьКонтрагента`, …) **без** `Экспорт`.

## 4. Таблица «план vs факт» (развернутая)

| Тема | План (исходный документ) | Факт (код) |
|------|--------------------------|------------|
| Модули | Несколько `Obezl_*` | Одна обработка `Obezl_Запуск` |
| Карта мандатов | Регистр `Obezl_СоответствияНаименований` | `Соответствие` в памяти, ключ = `Строка(УникальныйИдентификатор())` |
| Статус | Регистр `Obezl_СтатусВыполнения` | Структура итога + временное хранилище |
| Этапы мандатов | Отдельно «Мандаты», отдельно «СчетаМандатов» | Один этап `МандатыИСчета`: в пачке сначала все мандаты, затем счета с `Владелец` из этой пачки |
| Контрагенты | Только `Клиент = Истина` | `Клиент` **или** (`Фонд` и не `Клиент`), не предопределенные |
| Имя контрагента | `Контрагент %1` с порядковым номером | `{Префикс} {UUID32}`: `Контрагент` / `Фонд` + GUID без дефисов |
| Мандат | Только `Мандат NNNNN` | Приоритет: `ПрефиксДоговораДУ` → `Мандат {префикс}`; иначе карта `Мандат 00001`… |
| Банковские счета | Маска номера + комментарий | + замена **каждой** группы цифр в `Наименовании`; если номер после маски только нули — синтетический номер из подстановки |
| Фонды | Отдельная кнопка / процедура | В запросе этапа `Контрагенты` (ОБЪЕДИНИТЬ) |
| UI | Несколько команд | Одна команда «Обезличить» |
| Доп. прогоны | — | **Не реализуются** (удалены шаг 2/3) |
| Параллельность | «До N потоков» | Макс. 8 пачек, целевой размер пачки 1000 ссылок (`РазбитьНаПачки`) |
| Журнал | Служебный модуль | `ЗаписьЖурналаРегистрации("Obezl", …)` в менеджере |
| Снимок | Не детализирован | Таблица `Объект, Ссылка, Поле, ЗначениеДо` до изменений |
| Отмена | — | Отмена родительского фонового задания → отмена активных пачек |
| Частичный сбой | — | `ЧастичныйУспех`, этап продолжается, ошибка пачки в журнале |

## 5. Поток выполнения (фактический, пошагово)

1. **Старт** — UUID запуска, запись в журнал `Obezl`.
2. **Снимок** — `СформироватьСнимокДоОбезличивания()` → адрес во временном хранилище в итоге.
3. **Карта мандатов** — для каждого мандата (кроме предопределенных): `СтароеНаименование` (краткое до), `НовоеНаименование` = `Мандат` + 5 цифр по порядку обхода запроса.
4. **Контрагенты** — пачки в фоне (`Obezl_ВыполнитьПачку`).
5. **МандатыИСчета** — для каждой пачки мандатов: фоновая структура `{Мандаты, СчетаМандатов}`; в фон передается копия `КартаМандатов` (сериализация `ЗначениеВСтрокуВнутр`).
6. **СчетаДЕПО**, **БрокерскиеСчета**, **БанковскиеСчета** — отдельные этапы пачками.
7. **Финиш** — при `Успешно`: `ОчиститьВерсииОбъектов()`, `ОчиститьСлужебныеДанные()` (сброс `КартаМандатов`).
8. **Итог** — `Успешно`, `ЧастичныйУспех`, `ТекстДиагностики`, `ДеталиЭтапов`, `АдресСнимкаДоОбезличивания`.

Прогресс UI: 5 этапов с долей завершенных пачек внутри этапа (`ДлительныеОперации.СообщитьПрогресс`).

## 6. Правила по объектам (краткая выжимка)

Подробно — в [`anonymization_map.html`](anonymization_map.html) и разделе 6 актуального ТЗ.

### 6.1 Контрагенты

- **Маска цифр** (`МаскаЦифр`): ИНН, ОГРН, КПП, TIN, ОКПО, ОКАТО.
- **Наименования:** `СтрШаблон("%2 %1", Суффикс, Префикс)` → `"Контрагент {uuid}"` или `"Фонд {uuid}"`.
- **Англ.:** `Counterparty {uuid}`.
- **КонтактнаяИнформация:** обход реквизитов ТЧ по метаданным; строки/числа; ссылки и перечисления не меняются.
- **ДополнительныеРеквизиты:** строковые значения → `Значение обезличено`.
- **Не меняется:** `КодКлиента`.

### 6.2 Мандаты

- Заполнен `ПрефиксДоговораДУ` → `"Мандат " + префикс` (карта не используется).
- Иначе → из карты; если ключа нет — **запись не выполняется** (ранний выход).
- Синхронизация: `НаименованиеПолное`, `ПолноеНаименование` (через `Попытка`).

### 6.3 Счета мандатов

- В той же фоновой пачке, что мандаты-владельцы.
- Замена подстроки старого краткого наименования мандата на новое из карты.
- Иначе при наличии `(` … `)` — `Обезличено_{uuid32}` внутри первой пары скобок.
- **Запись только если** наименование изменилось.

### 6.4 Счета ДЕПО

- Первая пара `(` … `)` → `Обезличено_{uuid32}`; префикс и суффикс строки сохраняются.
- **Запись только если** скобки найдены.

### 6.5 Брокерские счета

- Только `НомерБанковскогоСчета` → маска цифр.

### 6.6 Банковские счета

1. `НомерСчета` → маска цифр.
2. `Комментарий` → пустая строка, если был заполнен.
3. В `Наименовании` каждая группа цифр 0–9 → фрагмент той же длины из подстановки (`Код` элемента или цифры из GUID).
4. Если номер после маски — только нули → номер из подстановки той же длины (циклически).
5. **Запись только если** было хотя бы одно изменение.

### 6.7 ВерсииОбъектов

`НаборЗаписей.Прочитать()` → `Очистить()` → `Записать()`. При ошибке (память) — журнал и исключение.

## 7. Снимок «до обезличивания»

Колонки: `Объект`, `Ссылка`, `Поле`, `ЗначениеДо`.

| Этап снимка | Поля в снимке |
|-------------|----------------|
| Контрагенты | ИНН, ОГРН, КПП, TIN, ОКПО, ОКАТО, Наименование, НаименованиеПолное |
| Мандаты | Наименование, НаименованиеПолное, ПолноеНаименование |
| СчетаМандатов | Наименование |
| СчетаДЕПО | Наименование |

| БанковскиеСчета | НомерСчета |

## 8. Параллельность и отказоустойчивость

- Один элемент не попадает в две пачки одного этапа.
- Алгоритм `РазбитьНаПачки`: не более 8 пачек; размер пачки ~ `Количество / ЧислоПачек` с учетом остатка.
- Ошибка в пачке не останавливает оркестратор: `ЧастичныйУспех = Истина`, текст в журнал по этапу.
- Повторный запуск **не восстанавливает** исходные данные (идемпотентность «вперед»).
- Отмена пользователем родительского задания → `ОтменитьАктивныеПачки`.

## 9. Критерии приемки

Полный чеклист — раздел 9–10 в [`../technical_spec_obezl_single_processor.md`](../technical_spec_obezl_single_processor.md).

Кратко:

1. Клиенты и фонды обезличены по отбору.
2. Мандаты с `ПрефиксДоговораДУ` — `Мандат {префикс}`.
3. Счета мандатов согласованы с мандатом в одной пачке.
4. Банковские счета: маскированный/синтетический номер, пустой комментарий, в наименовании нет исходных длинных цифровых групп.
5. `ВерсииОбъектов` пуст.
6. Один запуск с формы, без ручных доп. этапов.
7. Предопределенные не изменены.
8. Выборочная проверка бизнесом по [`anonymization_map.html`](anonymization_map.html).
