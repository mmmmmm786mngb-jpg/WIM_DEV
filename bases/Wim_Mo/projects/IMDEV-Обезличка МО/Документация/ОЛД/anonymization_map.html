Карта обезличивания (фактическая реализация Obezl)

Проект: IMDEV-Обезличка МО
База: Wim_Mo (только копия, не продуктив)
Расширение: Obezl, обработка Obezl_Запуск
Исходники: Расширения/DataProcessors/Obezl_Запуск/
Сверено с кодом: май 2026

Введение

Документ описывает как работает сейчас единственный сценарий: кнопка «Обезличить» на форме обработки. Отдельных кнопок по этапам, процедур «шаг 2» / «шаг 3» и программных доп. прогонов нет (удалены из кода). Правила префикса договора ДУ у мандатов, маскирования банковских счетов и обработки фондов встроены в один оркестратор.

Архитектура и технология

Цепочка вызовов

  1. Форма Obezl_Запуск.Форма → БСП ДлительныеОперации.
  2. Менеджер: Obezl_ОркестраторОбезличивания (фон, Экспорт).
  3. Пачки: Obezl_ВыполнитьПачку в модуле объекта (фон, Экспорт).
  4. Внутри пачки: ОбработатьПачку → процедуры Обезличить* (без Экспорт).

Параллельность

  • До 8 фоновых пачек на этап (РазбитьНаПачки в ManagerModule.bsl).
  • Целевой размер пачки: около 1000 ссылок (фактическое число пачек = min(8, ceil(N/1000)) с перераспределением остатка).
  • Прогресс в UI: 5 этапов (ДлительныеОперации.СообщитьПрогресс).
  • Отмена родительского задания отменяет активные пачки этапа.

Служебные данные

  • Карта мандатов — Соответствие в переменной модуля объекта; ключ Строка(Ссылка.УникальныйИдентификатор()); значение: СтароеНаименование, НовоеНаименование.
  • Снимок «до» — таблица значений во временном хранилище (АдресСнимкаДоОбезличивания в итоге).
  • Регистры Obezl_* в БД не создавались.
  • После успеха: ОчиститьСлужебныеДанные сбрасывает карту; ОчиститьВерсииОбъектов — полная очистка регистра версий.

Журнал

Событие Obezl, формат: [UUID запуска][ИмяЭтапа] сообщение.

Контактная информация контрагента (детально)

Обход: все реквизиты ТЧ КонтактнаяИнформация по метаданным; обрабатываются только типы Строка и Число; пустые строки пропускаются; ссылки и перечисления не изменяются.

Токен уникальности: UUID владельца (контрагента) без дефисов; номер строки ТЧ — 5 цифр с ведущими нулями.

Карта мандатов

  • Строится один раз до параллельных этапов: СформироватьКартуМандатов.
  • Для каждого мандата сохраняется СтароеНаименование = краткое наименование до изменения.
  • НовоеНаименование = Мандат + пробел + порядковый номер (формат 5 цифр: 00001, 00002, …).
  • При обработке мандата с заполненным ПрефиксДоговораДУ карта для имени не используется (но старое имя в карте остается для замены в счетах мандата).
  • Во фон передается копия соответствия (сериализация параметров пачки).

Примеры (бизнес-смысл)

  • Мандат с ПрефиксДоговораДУ = 3987 → Мандат 3987 (не случайное Мандат 00042 из карты).
  • Счет мандата с наименованием, содержащим старое краткое имя мандата, получает подстановку нового имени из карты в той же фоновой пачке.
  • Банковский счет: в наименовании не остаются исходные 20-значные номера — каждая цифровая группа заменена фрагментом из кода или GUID.
  • Фонд-контрагент: наименование вида Фонд a1b2c3… (32 hex), идентификаторы замаскированы нулями с сохранением длины.
  • Контрагент-клиент: Контрагент …, email вида user_{uuid}_00001@example.invalid.

Ограничения и риски

  • Повторный запуск не восстанавливает исходные данные (нужен бэкап копии).
  • Очистка ВерсииОбъектов через полный набор записей может потребовать много памяти на больших базах — при ошибке запись в журнал и прерывание.
  • Ошибка одной пачки помечает ЧастичныйУспех, но оркестратор может продолжить (данные могут быть обезличены не полностью).
  • Элементы без скобок в наименовании счета ДЕПО / без замены по карте у счета мандата могут остаться без изменения наименования.

Контроль после выполнения

1) Контрагенты (клиенты и фонды): нет исходных ИНН/телефонов/email в согласованных полях и ТЧ КИ.
2) Мандаты с ПрефиксДоговораДУ: наименование "Мандат <префикс>".
3) Остальные мандаты: "Мандат NNNNN" из карты (NNNNN — 5 цифр).
4) Счета мандатов: в наименовании нет старого краткого имени мандата (или Обезличено_ в скобках).
5) Банковские счета: номер замаскирован или синтетический; комментарий пуст; в наименовании нет длинных исходных цифровых групп.
6) Регистр ВерсииОбъектов пуст.
7) Журнал Obezl по UUID запуска — этапы завершены; при ЧастичныйУспех — разбор ошибок пачек.
