# Техническое задание: Obezl (единая обработка без регистров)

## 1. Цель

Разработать расширение конфигурации `Obezl` для обезличивания данных в копии базы `Wim_Mo` с учетом согласованных бизнес-правил, зависимостей между объектами и ускорения обработки за счет параллельного выполнения.

Все параметры и правила должны быть зашиты в коде. Настраиваемые пользователем параметры не предусматриваются.

Ключевое ограничение: вся логика выполняется в одной обработке `Obezl_Запуск` без создания дополнительных регистров сведений и без добавления новых общих модулей.

## 2. Область обработки

Обрабатывать только объекты:

1. `Справочник.Контрагенты`
2. `Справочник.Мандаты`
3. `Справочник.СчетаДЕПО`
4. `Справочник.СчетаМандатов`
5. `Справочник.БрокерскиеСчета`
6. `Справочник.БанковскиеСчета`
7. `РегистрСведений.ВерсииОбъектов` (полная очистка)

Другие объекты не изменять.

## 3. Глобальные правила

1. Запуск только на копии базы.
2. Предопределенные элементы справочников не изменять.
3. Ссылочную целостность объектов сохранять.
4. Логику отбора и маскирования не выносить в настройки формы, все условия зашиты в серверном коде обработки.
5. Временные соответствия и промежуточные состояния хранить только в памяти и/или во временном хранилище в рамках выполнения обработки.
6. После успешного завершения очищать временные структуры в памяти.

## 4. Фиксированные параметры (зашиты в коде)

1. Количество параллельных фоновых заданий: `8`.
2. Размер чанка для пакетной обработки справочников: `1000` элементов.
3. Шаблон русского наименования контрагента: `"Контрагент %1"`.
4. Шаблон английского наименования контрагента: `"Counterparty %1"`.
5. Шаблон наименования мандата: `"Мандат %1"`.
6. Шаблон email: `"user%1@example.invalid"`.
7. Шаблон телефона: `"+7000000%1"`.
8. Значение для обезличивания адресных полей: `"Обезличено"`.
9. Значение для строковых доп. реквизитов: `"Значение обезличено"`.
10. Режим очистки `ВерсииОбъектов`: `полная`.

## 5. Архитектура решения

## 5.1 Объекты расширения

Используется только:

1. Обработка `Obezl_Запуск` (модуль менеджера, модуль объекта, форма запуска и статуса).

Запрещено создавать в рамках данного ТЗ:

1. Дополнительные регистры сведений.
2. Дополнительные общие модули.
3. Дополнительные объекты метаданных, не требуемые для запуска одной обработки.

## 5.2 Принцип хранения промежуточных данных

1. Соответствия `Мандат: старое -> новое` формируются до этапа переименования мандатов и хранятся в памяти (`Соответствие`, `ТаблицаЗначений`) и/или во временном хранилище.
2. Состояние выполнения и агрегированные результаты чанков хранятся в переменных обработки и/или во временном хранилище.
3. Долговременное хранение состояния в регистрах сведений не используется.
4. Для счетов мандатов и мандатов-владельцев используется один фоновый контекст на пачку: в параметрах пачки передается полная карта соответствий (сериализация `ЗначениеВСтрокуВнутр`), внутри задания сначала обрабатываются все мандаты пачки, затем все `СчетаМандатов`, у которых `Владелец` входит в эту же пачку мандатов. Это исключает рассинхронизацию карты и порядка записи при разнесении по разным фоновым заданиям.

## 5.3 Базовый шаблон параллельности

Для реализации параллельности использовать рабочий паттерн из обработки:

- `bases/WIM_FIn/projects/IMDEV-7330 Оптимизация 1С ФИН_Расчет НДФЛ/Расширения/NDFL_RDU/DataProcessors/ОтменаПроведенияНачисленийНДФЛ.xml`
- `bases/WIM_FIn/projects/IMDEV-7330 Оптимизация 1С ФИН_Расчет НДФЛ/Расширения/NDFL_RDU/DataProcessors/ОтменаПроведенияНачисленийНДФЛ/Ext/ManagerModule.bsl`
- `bases/WIM_FIn/projects/IMDEV-7330 Оптимизация 1С ФИН_Расчет НДФЛ/Расширения/NDFL_RDU/DataProcessors/ОтменаПроведенияНачисленийНДФЛ/Ext/ObjectModule.bsl`

Что обязательно реализовать внутри `Obezl_Запуск`:

1. Оркестратор в менеджер-модуле, который:
   - делит данные на пачки;
   - запускает пачки через БСП `ДлительныеОперации.ВыполнитьВФоне`;
   - отслеживает статусы фоновых заданий;
   - агрегирует итоги пачек в единый результат.
2. Метод обработки пачки в модуле объекта с контрактом:
   - вход через структуру параметров;
   - возврат результата пачки через временное хранилище.
3. Контроль отмены родительского задания:
   - при отмене оркестратора отменяются активные пачки.
4. Прогресс выполнения:
   - процент;
   - текст этапа;
   - число завершенных пачек из общего количества.
5. Сбор ошибок по пачкам:
   - фиксировать номера упавших пачек;
   - не прерывать весь процесс при падении одной пачки;
   - возвращать итог с признаком частичного успеха.

## 5.4 Поток выполнения

1. Предпроверка.
2. Снятие снимка до обезличивания (в т.ч. мандаты и счета мандатов по отдельным этапам снимка).
3. Формирование в памяти карты соответствий наименований мандатов (`СтароеНаименование`, `НовоеНаименование` по шаблону `Мандат %1`).
4. Обезличивание `Контрагенты` (параллельно по чанкам).
5. Обезличивание **связки** `Мандаты` + `СчетаМандатов` по владельцу (параллельно по чанкам мандатов): в одном фоновом задании на пачку сначала обрабатываются мандаты чанка, затем все счета с `Владелец` из этого чанка; передается та же карта соответствий.
6. Обезличивание `СчетаДЕПО`.
7. Обезличивание `БрокерскиеСчета`.
8. Обезличивание `БанковскиеСчета`.
9. Полная очистка `РегистрСведений.ВерсииОбъектов`.
10. Финальный контроль и запись отчета.

Учет прогресса в оркестраторе: **5** пользовательских этапов (пункты 4-8); снимок и карта мандатов выполняются до распараллеливания этапа 5.

## 5.5 Сценарий запуска пользователем

1. После установки расширения пользователю доступна обработка `Obezl_Запуск`.
2. Пользователь открывает форму обработки `Форма`.
3. На форме доступна команда и кнопка `Обезличить`.
4. При нажатии кнопки выполняется запуск оркестратора обезличивания.
5. На форме отображается текущий статус выполнения (этап/сообщение) и итоговый результат.
6. Повторный запуск после завершения допускается (идемпотентный режим).

## 6. Детальные правила по объектам

## 6.1 Справочник.Контрагенты

Обрабатывать только элементы, где `Клиент = Истина`.

Изменять:

1. `ИНН` - маска по длине (цифры).
2. `ОГРН` - маска по длине (цифры).
3. `КПП` - маска по длине (цифры).
4. `TIN` - маска по длине (цифры), как для строковых идентификаторов из цифр и символов с сохранением длины.
5. `ОКПО` - маска по длине (цифры).
6. `ОКАТО` - маска по длине (цифры). В метаданных конфигурации `Wim_Mo` поле кода по ОКАТО называется **`ОКАТО`** (синоним «Код по ОКАТО»), не `КодПоОКАТО`.
7. `Наименование` (стандартное представление элемента) - по шаблону `"Контрагент %1"` (суффикс от `УникальныйИдентификатор()`).
8. `НаименованиеПолное` - по шаблону `"Контрагент %1"`.
9. `НаименованиеКраткое` - по шаблону `"Контрагент %1"`.
10. `НаименованиеПолноеАнгл` - по шаблону `"Counterparty %1"`.
11. `НаименованиеКраткоеАнгл` - по шаблону `"Counterparty %1"`.
12. Табличная часть `КонтактнаяИнформация` - обход реквизитов строки по метаданным ТЧ (`Метаданные().ТабличныеЧасти.КонтактнаяИнформация.Реквизиты`):
    - обрабатываются только типы **`Строка`** и **`Число`**;
    - реквизиты ссылочных типов и перечислений (в т.ч. `Тип`, `Вид`) **не изменяются**;
    - **`АдресЭП`** - шаблон email (`userNNNNN@example.invalid`);
    - **`НомерТелефона`** - шаблон телефона (`+7000000NNNNN`);
    - **`НомерТелефонаБезКодов`** - маска цифр по длине;
    - **`Страна`**, **`Регион`**, **`Город`** - `"Обезличено"`;
    - **`ДоменноеИмяСервера`** - `example.invalid`;
    - **`Представление`** - `"Обезличено"`;
    - **`ЗначенияПолей`** (XML контактных данных) - очистка в пустую строку;
    - строка, состоящая **только из цифр**, - маска цифр с сохранением длины;
    - прочие непустые строки - `"Обезличено"`;
    - числовые реквизиты - **`0`**.
13. Табличная часть `ДополнительныеРеквизиты`:
   - `Значение` (строковые значения) - `"Значение обезличено"`.
   - `ТекстоваяСтрока` - `"Значение обезличено"`.

Примечание: присвоение динамических реквизитов строк ТЧ `КонтактнаяИнформация` выполняется через `Выполнить` с экранированием строк; при запрете выполнения внешнего кода в среде развертывания потребуется замена на явный перечень полей.

Не изменять:

1. `КодКлиента`.

## 6.2 Справочник.Мандаты

Изменять только (в рамках этапа совместно с `СчетаМандатов`, см. п. 6.3):

1. `Наименование` - по шаблону `"Мандат %1"` (нумерация по порядку обхода при построении карты).
2. `НаименованиеПолное` - то же значение, что и новое `Наименование` (реквизит конфигурации `Wim_Mo`).
3. `ПолноеНаименование` - при наличии стандартного реквизита у элемента справочника - то же новое наименование (запись в блоке `Попытка`/`Исключение` при отличии метаданных).

Остальные реквизиты не изменять.

## 6.3 Справочник.СчетаМандатов

Изменять только:

1. `Наименование`.

Правило:

1. До этапа обезличивания собрать соответствия `СсылкаМандата` (ключ - строка ссылки), `СтароеНаименование`, `НовоеНаименование` в память. Пара **старое/новое** берется из снимка на момент построения карты и не перечитывается из базы при обработке счета.
2. Этап обработки: **не отдельный** параллельный этап по всем счетам, а **та же фоновая пачка**, что и у мандатов-владельцев: после записи всех мандатов чанка обрабатываются все `СчетаМандатов`, для которых `Владелец` входит в множество ссылок мандатов этого чанка (запрос по списку владельцев).
3. В `Наименовании` счета заменить только подстроку, совпадающую со **`СтароеНаименование`** из карты, на **`НовоеНаименование`**. Остальная часть строки не изменяется. Подстановка по **краткому** (`Наименование`) мандата на момент снятия карты; если в тексте счета фигурирует только полное имя без краткого, замена по этому правилу может не сработать.
4. Если замена по паре из п. 3 **не выполнена** (нет данных в карте по владельцу, пустое старое имя, подстрока не найдена), но в `Наименовании` счета есть круглые скобки `(` и `)` с корректным порядком, то по правилу как у `СчетаДЕПО`: заменить **текст первой пары скобок** (внутри скобок) на литерал **`Обезличено`**, закрывающая скобка `)` сохраняется, префикс до `(` без изменений, хвост после `)` без изменений.
5. В агрегированном итоге оркестратора учет по этапу ведется под ключом **`МандатыИСчета`** (суммарно обработанные строки мандатов и счетов за этап).

## 6.4 Справочник.СчетаДЕПО

Правило:

1. В `Наименовании` заменить только текст внутри круглых скобок на `"Обезличено"`.
2. Текст вне круглых скобок не менять.
3. Остальные реквизиты не изменять.

## 7. Требования к параллельной обработке

1. Параллельность реализовать через БСП `ДлительныеОперации` по шаблону `NDFL_RDU`.
2. Один и тот же элемент не должен обрабатываться одновременно в двух заданиях. Мандат входит ровно в одну пачку мандатов; счет мандата обрабатывается только в задании той пачки, куда попал его `Владелец`.
3. Деление на чанки по ссылкам/ключам с равномерным распределением на `8` потоков (для этапа `МандатыИСчета` чанкование задается по списку мандатов; счета подтягиваются в задание по запросу владельцев чанка).
4. Состояние каждого чанка вести во временных структурах обработки (в памяти/временном хранилище) с возможностью показа на форме.
5. При ошибке в чанке:
   - пометить чанк как ошибка;
   - продолжить обработку остальных чанков;
   - в конце вернуть сводку ошибок.

## 8. Требования к отказоустойчивости

1. Идемпотентность повторного запуска.
2. Безопасная обработка пустых/битых значений.
3. Логирование начала и окончания каждого этапа.
4. Логирование количества обработанных элементов по каждому этапу оркестратора (для связки мандатов и счетов - суммарно под именем этапа `МандатыИСчета`).
