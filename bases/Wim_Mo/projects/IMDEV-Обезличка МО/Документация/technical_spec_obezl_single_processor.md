# Техническое задание: Obezl (единая обработка)

**Статус:** соответствует фактической реализации в расширении `Obezl` (обработка `Obezl_Запуск`, модули `ManagerModule.bsl` / `ObjectModule.bsl`).

**Актуальность:** май 2026.

## 1. Цель

Разработать расширение конфигурации `Obezl` для обезличивания данных в **копии** базы `Wim_Mo` с учетом согласованных бизнес-правил, зависимостей между объектами и ускорения обработки за счет параллельного выполнения.

Все параметры и правила зашиты в коде. Настраиваемые пользователем параметры не предусматриваются.

Вся логика выполняется в одной обработке `Obezl_Запуск` **без** дополнительных регистров сведений и **без** отдельных общих модулей `Obezl_*`.

## 2. Область обработки

Обрабатывать только объекты:

1. `Справочник.Контрагенты` (клиенты и фонды — см. отбор)
2. `Справочник.Мандаты`
3. `Справочник.СчетаМандатов`
4. `Справочник.СчетаДЕПО`
5. `Справочник.БрокерскиеСчета`
6. `Справочник.БанковскиеСчета`
7. `РегистрСведений.ВерсииОбъектов` (полная очистка)

Другие объекты не изменять. Предопределенные элементы справочников не изменять.

## 3. Глобальные правила

1. Запуск только на копии базы (не на продуктиве).
2. Ссылочную целостность сохранять.
3. Логику отбора и маскирования не выносить в настройки формы.
4. Карта соответствий мандатов и снимок «до» — в памяти и/или во временном хранилище на время сеанса обработки.
5. После успешного завершения: очистка регистра `ВерсииОбъектов`, сброс `КартаМандатов` в модуле объекта (`ОчиститьСлужебныеДанные`).
6. Основной сценарий — **одна** кнопка `Обезличить` на форме; отдельные кнопки по этапам в UI **не используются**.

## 4. Фиксированные параметры (код)

| Параметр | Значение | Где |
|----------|----------|-----|
| Макс. число пачек (потоков) | 8 | `ManagerModule.bsl`, `РазбитьНаПачки` |
| Целевой размер пачки | 1000 элементов | там же |
| Событие журнала | `Obezl` | `Лог()` в менеджер-модуле |
| Этапов с прогрессом в UI | 5 | оркестратор: Контрагенты, МандатыИСчета, СчетаДЕПО, БрокерскиеСчета, БанковскиеСчета |

## 5. Архитектура

### 5.1 Состав расширения

- `DataProcessor.Obezl_Запуск` — модуль менеджера (оркестратор), модуль объекта (правила обезличивания, пачки), форма `Форма`.
- Заимствование: `Справочник.Контрагенты` (при необходимости в расширении).
- Расширение модулей БСП: `ДлительныеОперации` (запуск фона).

**Не создавалось:** `Obezl_ОбезличиваниеСервер`, `Obezl_ПараллельноеВыполнение`, регистры `Obezl_СоответствияНаименований`, `Obezl_СтатусВыполнения`.

### 5.2 Точки входа

| Процедура | Назначение |
|-----------|------------|
| `Obezl_ОркестраторОбезличивания` | Основной полный прогон (фон, вызов с формы) |
| `Obezl_ВыполнитьПачку` | Обработка одной фоновой пачки |

### 5.3 Поток основного оркестратора

1. Идентификатор запуска (UUID), лог «Старт».
2. `СформироватьСнимокДоОбезличивания()` → временное хранилище в результате.
3. `СформироватьКартуМандатов()` — пары `СтароеНаименование` / `НовоеНаименование` (`Мандат NNNNN`, 5 цифр) по ключу `Строка(Ссылка.УникальныйИдентификатор())`.
4. Этап **Контрагенты** (пачки).
5. Этап **МандатыИСчета**: на каждую пачку мандатов — сначала все мандаты пачки, затем `СчетаМандатов` с `Владелец` из этой пачки; в пачку передается та же `КартаМандатов`.
6. Этап **СчетаДЕПО** (пачки).
7. Этап **БрокерскиеСчета** (пачки).
8. Этап **БанковскиеСчета** (пачки).
9. `ОчиститьВерсииОбъектов()`, `ОчиститьСлужебныеДанные()`.
10. Итог в `АдресРезультата`: `Успешно`, `ЧастичныйУспех`, `ТекстДиагностики`, `ДеталиЭтапов`, `АдресСнимкаДоОбезличивания`.

Параллельность: `ДлительныеОперации.ЗапуститьВыполнениеВФоне` → `ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки`, метод `Obezl_ВыполнитьПачку`. Прогресс: `ДлительныеОперации.СообщитьПрогресс`. Отмена родительского задания отменяет активные пачки.

### 5.4 UI

Форма `Obezl_Запуск.Форма`: команда и кнопка **Обезличить** → `Obezl_ОркестраторОбезличивания`. Отображение статуса длительной операции и итога.

## 6. Правила по объектам (фактическая реализация)

### 6.1 Справочник.Контрагенты

**Отбор** (запрос `ПолучитьСсылкиДляЭтапа("Контрагенты")`):

- `Клиент = Истина` и не предопределенный  
- **объединение с** `Фонд = Истина`, `Клиент = Ложь`, не предопределенный

**Идентификаторы** (функция `МаскаЦифр` — каждая цифра → `0`, длина сохраняется): `ИНН`, `ОГРН`, `КПП`, `TIN`, `ОКПО`, `ОКАТО`.

**Наименования:** шаблон `"{Префикс} {Суффикс}"`, где `Суффикс` = UUID ссылки без дефисов (32 символа), `Префикс` = `Контрагент` или `Фонд` (для элементов с `Фонд = Истина`). Поля: `Наименование`, `НаименованиеПолное`, `НаименованиеКраткое`; англ. — `Counterparty {Суффикс}`.

**КонтактнаяИнформация** (`ОбезличитьКонтактнуюИнформациюПоМетаданным`): обход реквизитов ТЧ по метаданным; типы `Строка` и `Число`; ссылки и перечисления не трогаются.

- `АдресЭП` → `user_{токен}_{номер}@example.invalid`
- `НомерТелефона` → `+7999{первые8токена}{номер}`
- `НомерТелефонаБезКодов` → маска цифр
- `Страна`, `Регион`, `Город` → `Обезличено`
- `ДоменноеИмяСервера` → `example.invalid`
- `Представление` → `Обезличено`
- `ЗначенияПолей` → пустая строка
- строка только из цифр → маска цифр
- прочие непустые строки → `Обезличено`
- числа → `0`

**ДополнительныеРеквизиты:** строковое `Значение` и `ТекстоваяСтрока` → `Значение обезличено`.

`КодКлиента` **не изменяется**.

### 6.2 Справочник.Мандаты

В этапе **МандатыИСчета** (`ОбезличитьМандат`):

1. Если заполнен `ПрефиксДоговораДУ` → `Наименование = "Мандат " + Префикс` (приоритет над картой).
2. Иначе — `НовоеНаименование` из `КартаМандатов` (`Мандат 00001` … по порядку построения карты).
3. Синхронизация: `НаименованиеПолное`, `ПолноеНаименование` (через `Попытка`).

### 6.3 Справочник.СчетаМандатов

В той же фоновой пачке, что мандат-владелец (`ОбезличитьСчетМандата`):

1. Замена подстроки **старого** краткого наименования мандата из карты на **новое**.
2. Если замена не сработала и есть `(` … `)` — внутри первой пары скобок: `Обезличено_{UUID32}` (закрывающая `)` сохраняется).

### 6.4 Справочник.СчетаДЕПО

`ОбезличитьСчетДЕПО`: в `Наименовании` заменяется текст **первой** пары `(` … `)` на `Обезличено_{UUID32}`; префикс и хвост строки без изменений.

### 6.5 Справочник.БрокерскиеСчета

Только `НомерБанковскогоСчета` → `МаскаЦифр`.

### 6.6 Справочник.БанковскиеСчета

`ОбезличитьБанковскийСчет` (интегрировано в основной прогон; логика совпадает с бывшим «доп. режимом»):

1. `НомерСчета` → маска цифр (`МаскаЦифр`).
2. `Комментарий` → очистка, если был заполнен.
3. В `Наименовании` каждая группа подряд идущих цифр заменяется фрагментом той же длины из **подстановки**: `Код` элемента (после `СокрЛП`) или, если код пуст — цифровая строка из UUID ссылки (`УникальныйИдентификаторСсылкиБезДефисовИТолькоЧИсла`).
4. Если после маски `НомерСчета` состоит только из нулей — подставляется фрагмент подстановки той же длины (циклическое повторение базы).

### 6.7 РегистрСведений.ВерсииОбъектов

`НаборЗаписей.Прочитать()` → `Очистить()` → `Записать()`. При ошибке (память на больших базах) — запись в журнал и проброс исключения.

## 7. Снимок до обезличивания

`СформироватьСнимокДоОбезличивания`: таблица `Объект`, `Ссылка`, `Поле`, `ЗначениеДо` по этапам Контрагенты, Мандаты, СчетаМандатов, СчетаДЕПО, БрокерскиеСчета, БанковскиеСчета — перечень полей совпадает с обрабатываемыми реквизитами в `ДобавитьСнимокПоЭтапу`.

## 8. Параллельная обработка и отказоустойчивость

- Один элемент не обрабатывается в двух пачках одновременно.
- Ошибка пачки → `ЧастичныйУспех`, лог этапа, остальные пачки продолжаются.
- Идемпотентность: повторный запуск не восстанавливает исходные данные.
- Журнал: `[ИдентификаторЗапуска][Этап] сообщение`.

## 9. Критерии приемки

1. Обработаны контрагенты-клиенты и контрагенты-фонды по отбору п. 6.1.
2. Мандаты: при наличии `ПрефиксДоговораДУ` — имя `Мандат {префикс}`; иначе — из карты `Мандат NNNNN`.
3. Счета мандатов синхронизированы с мандатом владельца в одной пачке.
4. Банковские счета: маскированный номер, пустой комментарий, в наименовании нет исходных цифровых групп (заменены подстановкой).
5. `ВерсииОбъектов` пуст.
6. Запуск с формы одной кнопкой `Обезличить`, без обязательных ручных доп. этапов.
7. Предопределенные элементы не изменены.
8. Подтверждение бизнеса по выборочным проверкам (см. карту обезличивания HTML).

## 10. Контрольные проверки

1. Выборка контрагентов: `Клиент` или (`Фонд` и не `Клиент`) — нет реальных ИНН, телефонов, email в ТЧ КИ.
2. Мандаты с префиксом ДУ — шаблон `Мандат <префикс>`.
3. Банковские счета — номер из нулей/подстановки; в наименовании нет длинных исходных номеров счетов.
4. `ВерсииОбъектов` — 0 записей.
5. Журнал регистрации `Obezl` по идентификатору запуска — этапы завершены.
