# Логический тест: обезличивание `СчетаМандатов.Наименование` по карте мандата

Связанный код: `ObjectModule.bsl` — `СформироватьКартуМандатов`, `КлючМандатаВКарте`, `ДанныеМандатаПоКлючу`, `ОбезличитьМандат`, `ОбезличитьСчетМандата`; `ManagerModule.bsl` — пачки `МандатыИСчета`.

## 1. Условие записи при одной итерации `ОбезличитьСчетМандата`

Для ссылки счета `Счет` выполняется цепочка:

1. `Объект = Счет.ПолучитьОбъект()`.
2. `Мандат = Объект.Владелец` (если пусто — попытка `Объект.Мандат`).
3. **Ветка по карте** (только если `Мандат` заполнен): `Ключ = КлючМандатаВКарте(Мандат)`, `ДанныеМандата = ДанныеМандатаПоКлючу(Ключ)`. Если структура есть и `ЗначениеЗаполнено(Старое)` и `СтрНайти(Наименование, Старое) > 0` — `СтрЗаменить` по паре, флаг «наименование изменено».
4. **Резерв по скобкам** (если по карте наименование **не** изменено): как у `СчетаДЕПО` — первая пара `(` … `)` с `Поз2 > Поз1` заменяется на литерал `Обезличено` между префиксом и закрывающей скобкой с хвостом.
5. Если наименование менялось на шаге 3 или 4 — один вызов `Записать()`.

**Итог:** запись возможна при успешной замене по карте **или** при сработавшем резерве по скобкам. Если мандат пуст, карта не используется, но резерв по скобкам все равно проверяется.

## 2. Пошаговая имитация (успешный сценарий)

**Исходные данные:**

- Мандат `М1`: `Наименование = "Рога и Копыта"`.
- Карта построена первым проходом оркестратора: для `М1` в структуре хранится `СтароеНаименование = "Рога и Копыта"`, `НовоеНаименование = "Мандат 00001"`.
- Ключ в карте: `КлючМандатаВКарте(М1)` = строка GUID `М1`.
- Счет `С1`, `Владелец = М1`, `Наименование = "Счет 001 / Рога и Копыта"`.

**В той же фоновой пачке после `ОбезличитьМандат(М1)`:**

- В БД у мандата уже `Наименование = "Мандат 00001"` (карта при этом **не пересчитывается** — в ней по-прежнему `Старое = "Рога и Копыта"`).

**`ОбезличитьСчетМандата(С1)`:**

- `Мандат = М1`, ключ GUID совпадает с записью в карте.
- `СтрНайти("Счет 001 / Рога и Копыта", "Рога и Копыта")` > 0.
- Результат: `"Счет 001 / Мандат 00001"`, запись выполнена.

## 3. Сценарии, когда «визуально совпадает», а код **не** меняет наименование

### 3.1. Нет строки в карте (`ДанныеМандата = Неопределено`) или `СтрНайти` = 0

**Симптом (раньше):** мандат обезличился, счет по подстроке — нет.

**Причина по карте:** ключ/сериализация или несовпадение подстроки (см. ниже). После правки ключа на GUID рассинхрон реже.

**Сейчас:** если подстрока не заменилась, срабатывает **резерв по первой паре скобок** при наличии `(` и `)` в наименовании.

**Проверка в базе (ручная):** залогировать `Ключ`, наличие `ДанныеМандата`, `СтрНайти`, затем факт срабатывания резерва по скобкам.

### 3.2. Нет владельца у счета

Карта по мандату не применяется. Резерв по скобкам в `ОбезличитьСчетМандата` все равно может обработать наименование, если в строке есть корректная первая пара `()`. На этапе `МандатыИСчета` в пачку счета попадают только по **`Владелец В (...)`** — без владельца элемент **не вызывается** этим этапом оркестратора.

### 3.3. `СтрНайти` = 0 при «одинаковом» тексте на экране

Подстрока для поиска — **строго** `СтароеНаименование` из **модуля объекта мандата в момент построения карты** (`Объект.Наименование` при обходе мандатов), а не полное наименование и не представление из формы.

Возможные расхождения:

| Причина | Пояснение |
|--------|-----------|
| В счете фигурирует **другое поле** мандата (например, фрагмент `НаименованиеПолное`), а в карту попало только **краткое** `Наименование` | `СтрНайти` не находит подстроку |
| **Неразрывный пробел** (U+00A0), **другой дефис**, **двойной пробел** в одной строке и одинарный в другой | Визуально похоже, байты разные |
| **Регистр латиницы** в смешанных строках | `СтрНайти` чувствителен к регистру для латиницы |
| В наименовании счета текст **схож**, но с **опечаткой** / сокращением относительно мандата | Подстрока не совпадает дословно |

### 3.4. Пустое или «ломающее» `Старое`

Если `Старое` пустое, `ЗначениеЗаполнено(Старое)` — ложь, замена не выполняется.

### 3.5. Повторный запуск после частичного успеха

При повторном запуске карта строится заново: `СтароеНаименование` берется из **текущего** `Наименования` мандата в БД (уже `Мандат NNNNN`). В наименовании счета до сих пор **старое** человеческое имя — `СтрНайти(счет, "Мандат 00001")` может быть **0**. Нужна либо идемпотентная логика замены, либо однократный прогон до конца.

## 4. Чек-лист диагностики (порядок проверки)

1. Счет попадает в выборку пачки: `Владелец` входит в массив мандатов этой пачки (запрос `ПолучитьСсылкиСчетовМандатовПоВладельцам`).
2. В фоне после десериализации `КартаМандатов <> Неопределено`.
3. Для `Ключ = КлючМандатаВКарте(ВладелецСчета)` запись в карте есть.
4. `Старое` из структуры совпадает с **подстрокой** в `Объект.Наименование` счета (скопировать в отладчик из обоих источников, сравнить длины и коды символов).
5. Если карта не сработала: есть ли в наименовании первая пара `()` для резерва.

## 5. Пример резерва по скобкам

Исходное наименование счета: `ДУ МИИ870 (Козырева С.А.) 13W6XW`, замена по карте не выполнена.

После шага резерва (первая `(` и соответствующая `)`): префикс до `(` без изменений, вместо содержимого скобок — `Обезличено`, с позиции закрывающей `)` — хвост как в `ОбезличитьСчетДЕПО` (литерал `Обезличено` + продолжение строки с `)`).

Результат строки: `ДУ МИИ870 Обезличено) 13W6XW` (как у этапа ДЕПО: открывающая скобка «съедается» заменой блока до закрывающей).

## 6. Минимальный запрос контроля в базе (пример)

Проверить, что в тексте счета есть **точное** краткое наименование мандата из карты (до обезличивания — из снимка или копии):

- выбрать пару счет–владелец;
- сравнить `Мандаты.Наименование` (до прогона) с фрагментом `СчетаМандатов.Наименование` через `СтрНайти` в консоли запросов или обработке.

Если в карте только краткое имя, а в счете только полное — см. п. 3.3.
