внВыгрузкаОстатковМО_ФО

Проект: bases/Wim_Mo/projects/IMDEV-внВыгрузкаОстатковМО_ФО
База-источник (МО): Wim_Mo, запуск как внешняя обработка (EPF) в контуре PP Retail
База-приемник (ФО): Аванкор ФО Retail через веб-сервис avancore_ws

Обработка выгружает остатки (ЦБ, ДС, СЧА и связанные данные) из Middle Office в Front Office по SOAP. Единственный параметр, определяющий куда уходит выгрузка, — реквизит АдресWS (URL WSDL). Для PP Retail нужно указать WSDL розничного ФО, а не стандартный PROD DU (PROD_AVC_FO-DL), который подставляется по умолчанию.
Быстрый переход: Инструкция по тестированию в MO PP (T-1) Retail с отладчиком  |  Запуск из регламентов  |  Разбор отладчика

3. Инструкция по запуску для тестирования в базе MO PP (T-1) Retail

Цель: запустить внВыгрузкаОстатковМО_ФО.epf в PP Retail МО на дату T-1 (предыдущий рабочий день), сузить объем до одного мандата и пошагово замерить в отладчике, сколько времени занимает каждый этап и каждая тяжелая строка кода.

3.0. Подготовка отладчика (один раз)

  1. Запустите толстый клиент 1С с возможностью отладки (не тонкий клиент без отладки).
  2. Подключитесь к базе PP Retail MO (контур pre-production).
  3. Откройте конфигуратор или EDT и подключите отладчик к сеансу пользователя.
  4. Откройте модуль объекта EPF: C:\1c\Cursor_1c\WORK\Wim_Mo\SRC\epf\внВыгрузкаОстатковМО_ФО_epf\внВыгрузкаОстатковМО_ФО\Ext\ObjectModule.bsl
  5. Дополнительно откройте модуль формы: ...\Forms\Форма\Ext\Form\Module.bsl — точки входа Заполнить и Опубликовать.
  6. В окне «Точки останова» включите остановку на всех исключениях (по желанию).

3.1. Параметры на форме обработки (что заполнить)

T-1: в поле ДатаПоз укажите дату позиции «вчера» относительно даты теста. Например, если тест 30.06.2026, то ДатаПоз = 29.06.2026 (или последний рабочий день по календарю УК). Именно эта дата передается в Заполнить(Отбор, ДатаПоз) и в Опубликовать(..., ДатаПоз).

3.2. Настройка отбора по одному мандату

  1. Убедитесь, что Отбор по счетам выключен.
  2. В блоке «Отбор мандатов» (компоновщик СКД) добавьте условие, например:
    • Мандат.Код Равно «<код тестового мандата Retail>»
    • или Мандат Равно «<конкретная ссылка>»
  3. Включите использование условия (галочка в строке отбора СКД).
  4. Проверьте, что мандат активен на дату T-1 и имеет заполненный КодМандата (иначе «Опубликовать» пропустит его с ошибкой).

3.3. Пошаговый запуск (два этапа замера)

Этап A — только МО, без вызова ФО («Заполнить»)
Кнопка Заполнить → Form\Module.bsl → ЗаполнитьНаСервере → ObjectModule.Заполнить. На этом этапе выполняются тяжелые запросы к базе МО, WS не вызывается.
Этап B — выгрузка в ФО («Опубликовать»)
Сначала обязательно выполните «Заполнить» (табличные части должны быть заполнены). Кнопка Опубликовать → ОпубликоватьНаСервере → ObjectModule.Опубликовать. Здесь создается WS-прокси, формируются XDTO-пакеты и идут вызовы DownloadPosition / DownloadOrders.
  1. 1 Файл → Открыть → внВыгрузкаОстатковМО_ФО.epf.
  2. 2 Заполните параметры из таблицы выше (T-1, WSDL Retail, пакет = 1, отбор = 1 мандат, Отладка = Да).
  3. 3 Поставьте точки останова (см. таблицу 3.4) в ObjectModule.bsl.
  4. 4 Нажмите Заполнить. Отладчик остановится на каждой точке — фиксируйте время (см. 3.5).
  5. 5 Убедитесь, что на вкладках ТЧ появились строки (ЦБ, ДС, СЧА/РСА и т.д.).
  6. 6 Нажмите Опубликовать. Замеряйте отдельно: создание WS, цикл пакетов, каждый DownloadPosition.
  7. 7 При включенной «Отладке» откроется «Лог работы сервиса» — сохраните для анализа ошибок ФО.

3.5. Как фиксировать время в отладчике

Способ 1 — вручную по часам отладчика:

// В начале процедуры Заполнить (временно для замера):
ВремяНачала = ТекущаяДатаСеанса();

// Перед каждой тяжелой строкой — в окне «Выражение»:
(ТекущаяДатаСеанса() - ВремяНачала) * 86400  // секунды

// После строки обновите ВремяНачала для следующего замера

Способ 2 — точки останова с условием: на breakpoint включите действие «Выражение»: Сообщить("ЦБ: " + (ТекущаяДатаСеанса() - ВремяНачала) * 86400);

Способ 3 — замер производительности платформы: если в базе доступен «Замер производительности» (БСП / администрирование), включите его перед «Заполнить» и «Опубликовать» — получите дерево вызовов с временем без правки кода.

3.7. Частые проблемы при тесте на PP

  • «Заполнить» долго — сузьте отбор; проверьте тяжесть ЦенныеБумагиНаДату / ДенежныеСредстваНаДату.
  • «Опубликовать» падает на WSDL — проверьте VPN и URL Retail FO; откройте WSDL в браузере с рабочей станции.
  • Мандат пропущен — не заполнен КодМандата у мандата (сообщение в логе).
  • HTTP 413 — уменьшите Количество портфелей в пакете до 1 (для теста уже так).
  • Отладчик не останавливается — EPF выполняется на сервере: подключайте отладку к серверному сеансу (ragent), не только клиенту.

4. Как настроить подключение при запуске как внешней обработки (PP Retail МО)

  1. Подготовить файл EPF.
    Путь к исходникам в репозитории на диске: C:\1c\Cursor_1c\WORK\Wim_Mo\SRC\epf\внВыгрузкаОстатковМО_ФО_epf\
    Собрать внВыгрузкаОстатковМО_ФО.epf или взять готовый из каталога обработок PP.
  2. Открыть базу PP Retail MO в клиенте 1С:Enterprise (тонкий или толстый клиент) под учетной записью с правами на внешние обработки и выгрузку в ФО.
  3. Запустить внешнюю обработку: меню «Файл» → «Открыть» → выбрать внВыгрузкаОстатковМО_ФО.epf (либо через «Дополнительные отчеты и обработки», если обработка уже зарегистрирована в БСП).
  4. Указать адрес WSDL ФО Retail PP в поле «Адрес WS»: 
    http://smsk02mg138u/AVC_PP_RETAIL_FO/ws/avancore_ws.1cws?wsdl
    Скопировать URL целиком, включая ?wsdl. Сохранить настройки (кнопка на форме настроек или через регистрацию в БСП).
  5. Проверить доступность WSDL с рабочей станции (браузер или PowerShell): 
    Invoke-WebRequest -Uri "http://smsk02mg138u/AVC_PP_RETAIL_FO/ws/avancore_ws.1cws?wsdl" -UseDefaultCredentials
    Ожидается XML с описанием сервиса avancore_ws. Ошибка 401/403 — проблема прав IIS / домена.
  6. Заполнить служебные реквизиты МО: узлы обмена, УК, дату позиции, при необходимости отбор по мандату. Для первого прогона — МандатДляТеста и один мандат в отборе.
  7. Нажать «Заполнить» — формирование табличных частей (ЦБ, ДС и др.) в обработке без вызова ФО.
  8. Нажать «Опубликовать» — пакетная отправка через DownloadPosition на ФО Retail PP. В сообщении пользователю будет указан использованный АдресWS.

В продуктиве и на PP обработка не открывает форму и не «нажимает кнопки». Регламент вызывает команду ФоноваяВыгрузка, которая через подсистему обменов выполняет те же два шага, что и «Заполнить» + «Опубликовать», но на сервере и без участия пользователя.

5.1. Какая команда и откуда вызывается

В СведенияОВнешнейОбработке() зарегистрированы две команды БСП:

5.8. ОБНАРУЖЕН БАГ: КоличествоПортфелейВПакете = 0

Симптом из задачи и лога (ЗадачаМоФО.docx, ЛогРаботыСервиса.txt): при ~21 000 мандатах и ожидании пакетов по 50 вызов DownloadPosition (строка ~754) произошел один раз на весь объем; в логе XML-пакет на миллионы строк и ошибка: 
HTTP Status 413 / HTTP Error 413.1 - Request Entity Too Large
Ошибка выгрузки позиции по: АМИ0040031B - ДУ МИ40031 (Ажищев А.А.)

Причина: в Опубликовать размер пакета берется напрямую:

КоличествоПакет = КоличествоПортфелейВПакете;  // строка ~646

Условие отправки пакета на ФО:

Если КоличествоВПакете = КоличествоПакет
    Или КоличествоПортфелей = КоличествоПортфелейВсего Тогда
    // DownloadPosition ...
КонецЕсли;
КоличествоПортфелейВПакетеПоведение
50 (норма) Каждые 50 мандатов — отдельный DownloadPosition
1 Один мандат на вызов (удобно для отладки)
0 КоличествоВПакете = КоличествоПакет никогда не истинно (1 ≠ 0, 2 ≠ 0, ...). Срабатывает только ветка КоличествоПортфелей = КоличествоПортфелейВсего — все мандаты в одном SOAP-пакете → HTTP 413.

Почему на форме «50», а в регламенте «0»:

  • На форме при открытии есть подстраховка: ?(КоличествоПортфелейВПакете = 0, 50, ...) (Form\Module.bsl, ПриСозданииНаСервере).
  • В Опубликовать и при ФоноваяВыгрузка такой подстраховки нет.
  • Если в хранилище настроек узла реквизит не заполнен или равен 0 — в регламенте остается 0.
  • НастройкиПоУмолчанию задает 50, но только при первичной загрузке настроек DevOps, не при каждом запуске.

Что сделать:

  1. В узле плана обмена (ВыгрузкаОстатков_ФО / ВыгрузкаОстатков_ФОРозн) явно установить КоличествоПортфелейВПакете = 50 (или 10–25 при частых 413).
  2. Перед повторным прогоном проверить значение в отладчике на строке КоличествоПакет = ... (~646).
  3. Для доработки кода (рекомендация): добавить в Опубликовать ту же формулу, что на форме: КоличествоПакет = ?(КоличествоПортфелейВПакете = 0, 50, КоличествоПортфелейВПакете);
