Анализ возможности и постановка

Обработка «Перенос запросов к данным» · к оглавлению документации

Внешняя обработка для выгрузки и загрузки элементов справочника «Запросы к данным» в формате JSON. Подключается через подсистему «Дополнительные отчеты и обработки».

1. Что переносим

Справочник «Запросы к данным» хранит именованные тексты запросов с набором параметров. Он используется обработкой обмена с бэк-офисом: по коду запроса находится элемент справочника, запрос выполняется с подстановкой параметров, результат отдаётся во внешнюю систему.

2. Ключевая особенность: формат хранения значений параметров

Поле «Значение» хранится не как обычная строка, а как результат внутренней сериализации платформы. Фактические примеры, снятые с тестовой базы:

Тип значенияКак хранится
Строка{"S","Тест"}
Число{"N",123.45}
Булево{"B",1}
Дата{"D",00010101000000}
Ссылка (пустая) {"#",f66cadf1-c157-4f10-8f05-3140a16e3e04,57:00000000000000000000000000000000}
Ссылка (заполненная) {"#",f66cadf1-c157-4f10-8f05-3140a16e3e04,57:88485478dd6ede0f11f1ac43c8319dc9}

Из этого следуют два практических ограничения.

Привязка к конфигурации В ссылочном значении зашит внутренний идентификатор типа метаданных. Перенос значения «как есть» корректен только между базами с одной и той же конфигурацией — тест, препрод и пром одного релиза. При переносе в другую конфигурацию значение станет нечитаемым.
Привязка к конкретному объекту Ссылка указывает на объект по его уникальному идентификатору. Если в базе-приёмнике такого объекта нет, платформа не выдаст ошибку — получится «битая» ссылка, которая внешне выглядит заполненной. Такие случаи нужно отлавливать при загрузке и показывать в протоколе.

Принятое решение: в JSON пишется и точное внутреннее значение — для гарантированного обратного переноса в рамках одной конфигурации, и разложенное описание: имя типа, идентификатор объекта, текстовое представление. При загрузке используется внутреннее значение, а разложенное описание — для проверки, что объект в приёмнике действительно найден, и для понятного протокола расхождений.

4. Как это работает в интерфейсе

Обработка регистрируется как дополнительная обработка — глобальная, не привязанная к объекту. Команда — открытие формы. На форме две вкладки и общее поле протокола.

Элемент интерфейсаНазначение
Вкладка «Выгрузка в JSON» Поле выбора одного элемента, таблица всех элементов с флажками для выбора нескольких, команды обновления списка и простановки отметок, команда «Выгрузить в JSON»
Вкладка «Загрузка из JSON» Выбор файла, таблица предпросмотра изменений, команда «Записать изменения» с подтверждением
Поле «Протокол» Что найдено, что создано, что обновлено, по каким параметрам ссылки не разрешились
Файл сохраняется и читается через клиентский файловый диалог, а не прямой записью на сервере. Это единственный вариант, работающий при регистрации обработки в безопасном режиме.

Решения, принятые по умолчанию:

  • имя обработки — внПереносЗапросовКДанным;
  • вид для подключения — «Дополнительная обработка», команда «Открытие формы», безопасный режим;
  • файловые операции — только через клиентский диалог выбора и сохранения файла;
  • формат обмена — JSON, выгрузка в XML не делается.
