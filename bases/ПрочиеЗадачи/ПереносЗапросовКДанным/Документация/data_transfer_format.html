Формат файла обмена

Обработка «Перенос запросов к данным», версия формата 1.0 · к оглавлению документации

Файл выгрузки — текстовый JSON в кодировке UTF-8 без BOM. В одном файле передаётся один или несколько элементов справочника «Запросы к данным».

Блок описания значения

Поле ЗначениеОписание не участвует в записи данных: обработка переносит значение из ЗначениеВнутреннее без изменений. Описание нужно, чтобы файл можно было прочитать глазами и чтобы при загрузке было понятно, на какой объект должно указывать значение.

Вид описания зависит от значения.

Примитив — строка, число, дата, булево

"ЗначениеОписание": {
    "ВидЗначения": "Примитив",
    "ТипЗначения": "Дата",
    "Представление": "0001-01-01T00:00:00"
}

Ссылка на объект базы

"ЗначениеОписание": {
    "ВидЗначения": "Ссылка",
    "ТипЗначения": "СправочникСсылка.Активы",
    "ТипЗначенияXML": "CatalogRef.Активы",
    "ПолноеИмяОбъекта": "Справочник.Активы",
    "УникальныйИдентификатор": "c8319dc9-ac43-11f1-8848-5478dd6ede0f",
    "Представление": "RUB"
}

Если объекта в базе нет, Представление содержит текст платформы вида Объект не найден (...) — это видно и в файле, и в протоколе загрузки.

Значение не заполнено

"ЗначениеОписание": { "ВидЗначения": "Неопределено", "Представление": "" }

Значение не читается текущей конфигурацией

Так выглядит описание, если файл выгружен из базы на другой конфигурации:

"ЗначениеОписание": { "ВидЗначения": "НеРазобрано", "Представление": "", "ОшибкаРазбора": "..." }

Кроме перечисленных, возможны виды Перечисление — тогда добавляется поле ИмяЗначения, и Прочее для остальных типов.

Границы применимости

Файл рассчитан на перенос между базами с одной и той же конфигурацией Тест, препрод и пром одного релиза. Причина в том, что значения параметров хранятся во внутреннем формате платформы, где зашит внутренний идентификатор типа метаданных.

При загрузке в базу с другой конфигурацией обработка не прервётся: она выведет предупреждение о расхождении конфигураций, перенесёт текст запроса и состав параметров, а по каждому нечитаемому значению даст отдельную строку протокола.

Правила загрузки

  1. Элемент ищется по уникальному идентификатору, затем по коду запроса.
  2. Найденный элемент обновляется целиком, включая табличную часть параметров: старые строки удаляются, записываются строки из файла.
  3. Не найденный элемент создаётся с уникальным идентификатором из файла. Поэтому повторная загрузка того же файла обновляет тот же элемент, а не создаёт дубль.
  4. До записи обработка показывает перечень изменений: какие поля и строки параметров отличаются, что будет добавлено и что удалено. Запись выполняется только после подтверждения.
  5. Значения, ссылающиеся на отсутствующие в базе объекты, переносятся как есть, но по каждому такому значению в протокол попадает предупреждение.
