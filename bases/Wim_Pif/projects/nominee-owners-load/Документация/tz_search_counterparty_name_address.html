Техническое задание

Конфигурация: Аванкор: Паевые фонды (Wim_Pif)
Объект: внешняя обработка «Заполнение списка владельцев номинального держателя», модуль обычной формы
Процедура/функция: ПолучитьКонтрагент и вызовы из процедур чтения файла
Тип доработки: изменение алгоритма поиска контрагента, без изменения метаданных конфигурации
Основание: дубли пайщиков при смене фамилии и кода НРД (пара Гнездилова / Дорогокупец, начитка формата «Гарант» Excel)

1. Цель

Если по коду НРД и по полному ФИО + дате рождения контрагент не найден, не создавать новую карточку, когда в базе уже есть пайщик с теми же именем, отчеством, датой рождения и адресом. Фамилию в этом шаге не сравнивать.

2. Текущее поведение (как есть)

Функция ПолучитьКонтрагент сейчас:

  1. Шаг 1. Поиск по свойству «НРД id клиента» (ПолучитьКонтрагентаПоНРДid). Нашли - возврат, дальше не ищем.
  2. Шаг 2. Запрос: Наименование или НаименованиеПолное равно полному ФИО из файла и дата рождения совпадает. Номер паспорта сравнивается только если дата рождения пустая в файле или на карточке. Серия паспорта в запрос не передается. Поиск по серии+номеру ДУЛ закомментирован и не включать.
  3. 0 строк - пустая ссылка (потом СоздатьКонтрагента, если флаг включен). 1 строка - возврат. Больше одной - отбор по лицевому счету текущего фонда, иначе "РучнойВыбор".
Адрес из файла читается (для формата Гарант Excel: колонка 5 юридический, колонка 8 почтовый) и пишется только при создании карточки (ЗаписатьАдресКонрагентаНаСервере). В поиск адрес не передается и не сравнивается. Номер лицевого счета спецдепозитария из файла в этом формате пустой, в ключ поиска его не использовать.

3. Требуемое поведение (как должно стать)

Шаги 1 и 2 не менять. После шага 2, если контрагент не найден (0 строк), выполнить шаг 2а.

  1. Разобрать ФИО файла теми же ВыделитьСлово: фамилия, имя, отчество (фамилия для шага 2а не нужна).
  2. Шаг 2а не выполнять, если пустые: имя, отчество, дата рождения, или оба адреса (юр. и почтовый).
  3. Отобрать кандидатов: пайщик, не помечен на удаление, та же дата рождения, те же имя и отчество в срезе последних ФИОФизЛиц. Фамилию не сравнивать.
  4. Среди кандидатов оставить тех, у кого нормализованное представление адреса совпало с нормализованным адресом из файла (юр. или почтовый из файла vs любой адресный вид на карточке).
  5. 0 после отбора по адресу - как сейчас, пустая ссылка (создание новой карточки).
  6. 1 - это старый клиент, вернуть ссылку.
  7. Больше 1 - тот же разбор, что на шаге 2: лицевой счет текущего фонда / иначе "РучнойВыбор".
НРД id при успехе шага 2а. Если в файле id заполнен - записать его на найденную карточку через существующую ЗаписатьНРДid (даже если на карточке уже был другой). Иначе следующий файл с новым кодом НРД снова не найдет человека на шаге 1. Если прежнее значение отличалось - вывести сообщение пользователю, отдельное свойство не заводить. ФИО, паспорт и адрес на найденной карточке не обновлять.

4. Что не делать

  • Не менять метаданные конфигурации (новые реквизиты, ПВХ, регистры не нужны).
  • Не раскомментировать поиск по серии и номеру паспорта.
  • Не искать по коду лицевого счета с шапки обработки / по «ND…» на вкладке лицевых счетов - это счет номинала, общий на начитку.
  • Не менять шаги 1 и 2 и не менять СоздатьКонтрагента / СоздатьЛицевойСчет.
  • Не обновлять фамилию и ДУЛ на найденной карточке в этой задаче.

Вставить в ПолучитьКонтрагент в существующую ветку Иначе (сейчас там закомментированный запрос по ДУЛ). Закомментированный блок удалить, не оставлять мертвый код.

6.1. Нормализация адреса

Сравнивать не «как в Excel», а после нормализации: иначе расхождение пробела или ведущего «-» снова создаст дубль. Не заменять «ул» на «улица» - только технический мусор.

    Результат = ВРег(СокрЛП(Строка(АдресСтрока)));
    Результат = СтрЗаменить(Результат, "Ё", "Е");

    Пока СтрНачинаетсяС(Результат, "-") Цикл
        Результат = СокрЛП(Сред(Результат, 2));
    КонецЦикла;

    Результат = СтрЗаменить(Результат, " ", "");

// Описание: Проверяет, совпал ли адрес из файла с адресом на карточке
//
// Параметры:
// ЮрАдресФайла - Строка
// ПочтовыйАдресФайла - Строка
// Контрагент - СправочникСсылка.Контрагенты
//
// Возвращаемое значение:
// Булево
//
Функция АдресФайлаСовпадаетСКарточкой(ЮрАдресФайла, ПочтовыйАдресФайла, Контрагент)

    АдресаФайла = Новый Массив;
    Если Не ПустаяСтрока(СокрЛП(ЮрАдресФайла)) Тогда
        АдресаФайла.Добавить(НормализоватьАдресДляПоиска(ЮрАдресФайла));
    КонецЕсли;
    Если Не ПустаяСтрока(СокрЛП(ПочтовыйАдресФайла)) Тогда
        НормПочтовый = НормализоватьАдресДляПоиска(ПочтовыйАдресФайла);
        Если АдресаФайла.Найти(НормПочтовый) = Неопределено Тогда
            АдресаФайла.Добавить(НормПочтовый);
        КонецЕсли;
    КонецЕсли;

    Если АдресаФайла.Количество() = 0 Тогда
        Возврат Ложь;
    КонецЕсли;

    Для Каждого АдресФайла Из АдресаФайла Цикл
        Если СтрДлина(АдресФайла) < 12 Тогда
            Продолжить;
        КонецЕсли;
        Для Каждого АдресКарточки Из ПредставленияАдресовКонтрагента(Контрагент) Цикл
            Если АдресФайла = НормализоватьАдресДляПоиска(АдресКарточки) Тогда
                Возврат Истина;
            КонецЕсли;
        КонецЦикла;
    КонецЦикла;

    Возврат Ложь;

Переменные Имя и Отчество в функции уже считаются через ВыделитьСлово до запроса шага 2 - повторно разбирать ФИО не нужно.

Если СписЛогДубли пришел пустой строкой по умолчанию, перед Добавить привести к массиву (сейчас вызовы с массивом; для старого вызова с тремя параметрами шаг 2а все равно не сработает из-за пустого адреса). Надежный вариант в начале ПолучитьКонтрагент:

    Если ТипЗнч(СписЛогДубли) <> Тип("Массив") Тогда
        СписЛогДубли = Новый Массив;
    КонецЕсли;

6.6. Исправление ВыделитьСлово

Функция режет ФИО на фамилию / имя / отчество. Ею пользуются и ПолучитьКонтрагент (шаги 2 и 2а), и СоздатьКонтрагента. Сейчас она считает позицию пробела по строке без левых пробелов, а хвост отрезает от исходной строки. Лишний пробел в начале или несколько пробелов между словами сдвигают имя и отчество. Тогда шаг 2 не находит карточку, шаг 2а тоже смотрит не те имя/отчество, при создании пишется кривое НаименованиеПолное.

Как ломается. Вход с двумя пробелами в начале: Иванов Иван Иванович.
СокрЛ дает строку без левых пробелов, первый пробел в позиции 7.
Остаток сейчас: Сред от исходной строки с той же позицией - в имя попадает хвост фамилии, дальше все съезжает.
Как должно: и слово, и остаток считать от уже обрезанной строки, остаток снова через СокрЛ.

Тело функции заменить целиком. Сигнатуру и вызовы не менять (параметр без Знач, изменение исходной строки должно остаться).

// Описание: Отделяет первое слово ФИО, остаток возвращает в исходной строке
// Левые пробелы и повторные пробелы между словами не сдвигают имя и отчество
//
// Параметры:
// ИсходнаяСтрока - Строка - ФИО или его остаток; перезаписывается хвостом без первого слова
//
// Возвращаемое значение:
// Строка - первое слово без пробелов по краям
//
Функция ВыделитьСлово(ИсходнаяСтрока)

    ИсходнаяСтрока = СокрЛ(ИсходнаяСтрока);
    ПозицияПробела = Найти(ИсходнаяСтрока, " ");

    Если ПозицияПробела = 0 Тогда
        ВыделенноеСлово = СокрЛП(ИсходнаяСтрока);
        ИсходнаяСтрока = "";
        Возврат ВыделенноеСлово;
    КонецЕсли;

    ВыделенноеСлово = СокрЛП(Лев(ИсходнаяСтрока, ПозицияПробела));
    ИсходнаяСтрока = СокрЛ(Сред(ИсходнаяСтрока, ПозицияПробела + 1));

    Возврат ВыделенноеСлово;

КонецФункции

9. Ограничения

  • Сравнение адреса - по нормализованной строке представления, не ФИАС/ГАР. Написание «ул» vs «улица» в этой версии не считается совпадением.
  • Имя и отчество берутся из ФИОФизЛиц.СрезПоследних. Если среза нет, шаг 2а карточку не найдет.
  • Доработка только модуля обработки. Сборку EPF выполняет разработчик по принятому на проекте порядку.
