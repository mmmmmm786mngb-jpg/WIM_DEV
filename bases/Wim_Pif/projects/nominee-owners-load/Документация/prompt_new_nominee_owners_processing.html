Заполнение списка владельцев номинального держателя

Документация возможностей текущей обработки и постановка на новую внешнюю обработку тонкого клиента.
Конфигурация: Аванкор: Паевые фонды (Wim_Pif). Документ-приемник: СписокВладельцевНоминальногоДержателя.
Старая обработка: обычное приложение, Excel через COM, поиск контрагента построчно.

Как пользоваться файлом. Разделы 1-7 - описание «как есть» и какие реквизиты оставить/добавить. Раздел 8 - полный промпт: его можно отдать разработчику или агенту как задание на создание новой EPF. Новую обработку не подменять старой, пока не пройдут живые начитки тех же форматов.

1. Что умеет текущая обработка

Назначение: прочитать файл списка владельцев номинального держателя, сопоставить или создать пайщиков, подобрать/создать технические лицевые счета и банковские счета, заполнить документ списка владельцев.

1.1. Шапка и режимы

  • Выбор файла (xls / xml).
  • Фонд (ПИФ), номинальный держатель, лицевой счет номинала по фонду (подставляется при смене НД или фонда).
  • Дата создаваемого документа.
  • Дата исторических реквизитов и дата открытия создаваемых ЛС (по умолчанию - последний рабочий день прошлого месяца).
  • Папка справочника Контрагенты для новых элементов (сейчас в коде зашит UUID группы пайщиков, на форме поле «Папка для создания новых контрагентов»).
  • Флаги: создавать контрагентов при начитке; создавать лицевые счета; множить л/с, если клиент в списке больше одного раза.
  • Формат файла: Гарант Excel; ВТБ СД (XML); ЦДФ; Гарант для частичного погашения паев (Excel NEW).

1.3. Поиск и создание

  1. ФЛ: ПолучитьКонтрагент - сначала НРД id (ПВХ «НРД id клиента»), потом точное полное ФИО + дата рождения. Паспорт при заполненной ДР не сравнивают. Поиск по серии+номеру закомментирован.
  2. Несколько карточек с одним ФИО+ДР: берется та, у которой есть ЛС номинала или технический в текущем фонде; иначе строка «ручной выбор».
  3. Не нашли и флаг создания включен: СоздатьКонтрагента (наименование, полное ФИО, ДР, паспорт в РС, адреса, email, НРД id, внешний ID для ЛК, синхронизация реквизитов, ОбменДанными.Загрузка).
  4. ЮЛ: поиск по ИНН, иначе ОГРН / свидетельству о регистрации. Новую карточку ЮЛ обработка обычно не собирает так же, как ФЛ.
  5. ЛС: найти существующий номинальный/технический по пайщику и фонду; иначе создать технический с кодом ЛС с шапки (не из файла Гарант Excel - колонка счета там пустая).
  6. Банковский счет: найти по номеру и владельцу; иначе СоздатьБСчет (Р/с, БИК, рубль).
  7. Отдельная ветка «получатель платежа - иное лицо»: счет вешается на найденного по ИНН получателя.

1.4. После начитки (интерфейс)

  • Таблица строк: бежевый фон если нет контрагента, лазурный если ручной выбор.
  • Отборы: ненайденные контрагенты; незаполненная ДР; пустые и дубли ЛС (через вторую таблицу ТППустойКонтрагент).
  • Команда «Создать документы»: документ СписокВладельцевНоминальногоДержателя, ТЧ Владельцы (контрагент, паи, ЛС, банковский счет, НРД id). Строки без обязательных полей пропускаются с сообщением. Форма документа открывается.
  • Сообщения: незаполненные поля строки, нерезиденты, список дублей ФИО.
  • Кнопка «Создать контрагентов» на панели - пустой обработчик, в новую не переносить.

1.5. Чего текущая не умеет (закрыть в новой)

  • Найти человека после смены фамилии, если код НРД тоже новый (имя + отчество + ДР + адрес).
  • Корректно резать ФИО с лишними пробелами (ВыделитьСлово берет позицию из обрезанной строки, хвост - из исходной).
  • Пакетный поиск: сейчас запрос на каждую строку плюс Excel COM.
  • Протокол: кто найден «не тем ключом», кому заменили НРД id, кого выбрали из нескольких. Сейчас это теряется в Сообщить.

Подмена клиента - в строку подставили уже существующую карточку, хотя полное ФИО из файла и полное наименование карточки различаются, и/или НРД id из файла не равен id на карточке до записи. Типовой случай шага 2а: в файле новая фамилия, на карточке старая, совпали имя+отчество+ДР+адрес.

Замена НРД id - на найденную карточку записали другой код из файла (даже если ФИО совпало). Отдельная строка протокола, чтобы было видно смену идентификатора.

Выбор из нескольких - кандидатов больше одного, система сама взяла того, у кого есть ЛС в текущем фонде.

Ручной выбор - кандидатов больше одного, автовыбор не сработал, контрагент в строке пустой, пользователь выбирает руками. Строка остается в ТП с флагом РучнойВыбор.

В конце ПрочитатьФайл всегда открывать страницу «Протокол» (или показать табличный документ), даже если событий 0 - тогда одна строка «Событий сопоставления нет». Счетчики в шапке протокола: всего строк файла, найдено по НРД, по ФИО, по адресу, создано, подмен, выборов из нескольких, ручной выбор, не найдено.

6. Алгоритм сопоставления в новой обработке

  1. Прочитать файл целиком в таблицу значений (не COM-ячейка в цикле: табличный документ / XML в память).
  2. Пакетно шаг 1: все заполненные НРД id одним запросом к ЗначенияСвойствОбъектов.
  3. По оставшимся - пакетно шаг 2: полное ФИО (после исправленного ВыделитьСлово) + ДР.
  4. По оставшимся ФЛ с заполненными именем, отчеством, ДР и адресом - шаг 2а: имя+отчество+ДР, затем нормализованный адрес среди кандидатов. Срез ФИО не строить по всему регистру: сначала контрагенты-пайщики с этой ДР.
  5. ЮЛ - ИНН/ОГРН, как сейчас.
  6. 0 кандидатов + флаг создания - создать карточку и при необходимости ЛС/банк.
  7. 1 кандидат - подставить. Если ФИО или НРД id расходятся - протокол «Подмена» / «ЗаменаНРДid». Новый НРД id из файла записать на карточку (иначе следующий файл снова не найдет по шагу 1). ФИО и паспорт на найденной карточке не обновлять.
  8. Несколько кандидатов - как сейчас по ЛС фонда; успех = протокол «ВыборИзНескольких»; иначе РучнойВыбор и протокол.
Исправить ВыделитьСлово: позицию пробела и хвост брать из одной обрезанной СокрЛ строки. Вызовами пользуются поиск и создание.

7. Что не копировать из старой

  • Обычная форма, ЭлементыФормы, ПолучитьФорму.
  • Excel.Application по каждой ячейке.
  • Запрос в цикле по строке файла (кроме точечных досозданий объектов).
  • Закомментированный поиск по ДУЛ и зашитые паспорта иностранцев (MC2976866 и т.п.) - разбор ДУЛ сделать правилами по типу документа, без персональных констант.
  • Опечатки в именах (ФлСоздаватьКонрагентов, НовыЛицевойСчет) - в новой коде имена по стандарту 1С.
  • Создание объектов с обходом проверок оставить только там, где это уже принято (ОбменДанными.Загрузка при создании пайщика/ЛС), и сопроводить комментарием зачем.

8. Промпт на создание новой обработки

Скопировать блок ниже целиком в задание агенту/разработчику. Код в конфигураторе - с обычными &, <, >.

Ты создаешь НОВУЮ внешнюю обработку 1С для тонкого клиента (управляемая форма). Это замена
