Проверка обработки «Заполнение списка владельцев номинального держателя»

Дата проверки: 16.09.2026. База: Аванкор Паевые фонды (WIM_PIF). Обработка версии 1.0.2.

Введение

Обработка нужна, чтобы по файлу номинального держателя (Гарант Excel, XML ВТБ СД, ЦДФ) найти пайщиков в базе, при необходимости создать недостающие карточки и лицевые счета и записать документ «Список владельцев номинального держателя».

Проверяли два способа работы, как у пользователя:

  • Как в тонком / веб-клиенте — открыли форму, выбрали фонд, прочитали файл, сопоставили, создали недостающих, записали документ.
  • Как программная начитка — те же шаги без экрана, чтобы проверить все правила поиска, в том числе редкие случаи.

В базу специально заводили тестовые фонд, номинального держателя и пайщиков. Старая обработка при этом не отключалась.

Итог для пользователя: обработка работает. Поиск по НРД id, ФИО и дате рождения, имени+отчеству+адресу, ИНН, создание карточки и лицевого счета, чтение Excel и XML, протокол расхождений и документ списка владельцев — всё подтверждено. В веб-клиенте полный сценарий от файла до документа тоже прошел успешно.

Технология

Программная проверка идет через COM (Component Object Model) — штатный способ внешнего подключения к 1С. Используется библиотека pywin32 и объект платформы V83.COMConnector. Сессия поднимается методом Connect, в конце — CoUninitialize.

Параметры строки соединения:

  • Srvr — сервер 1С (здесь localhost)
  • Ref — имя информационной базы (WIM_PIF)
  • Usr / Pwd — пользователь и пароль
  • App — имя приложения для журнала (PyCOM)
  • Locale — локаль сеанса (ru_RU)

Примеры подключения:

pythoncom.CoInitialize()
com = win32com.client.Dispatch("V83.COMConnector")

# 1. Рабочее подключение теста (сервер, пользователь admin)
conn = com.Connect("Srvr='localhost';Ref='WIM_PIF';Usr='admin';Pwd='1';App='PyCOM';Locale=ru_RU;")

# 2. Тот же сервер, другое написание имени
conn = com.Connect("Srvr='localhost';Ref='WIM_PIF';Usr='Admin';Pwd='1';App='PyCOM';Locale=ru_RU;")

# 3. Файловый вариант (для сравнения, в этом прогоне не использовался)
conn = com.Connect("File='C:\\Bases\\WIM_PIF';Usr='admin';Pwd='1';App='PyCOM';Locale=ru_RU;")

Вызов методов обработки (безопасный режим выключен, иначе нельзя писать справочники и регистры):

protection = conn.NewObject("ОписаниеЗащитыОтОпасныхДействий")
protection.ПредупреждатьОбОпасныхДействиях = False
proc = conn.ВнешниеОбработки.Создать(ПутьКФайлу, False, protection)

# 1. Сведения для регистрации в дополнительных обработках
sved = proc.СведенияОВнешнейОбработке()

# 2. Разбор ФИО с лишними пробелами
parsed = proc.РазобратьФИО("  Gnezdova    Lyudmila   Petrovna  ")

# 3. Сопоставление строк файла с карточками
result = proc.СопоставитьСтрокиФайла(ТаблицаСтрок, ПараметрыНачитки)

# дополнительно: создание недостающих и документ
created = proc.СоздатьНедостающихПоСтрокам(result.ТаблицаСтрок, ПараметрыНачитки)
doc = proc.СоздатьДокументСписокВладельцев(created.ТаблицаСтрок, ПараметрыНачитки)

Важно: обработку создаем как ВнешниеОбработки.Создать(путь, Ложь). Второй параметр — безопасный режим. Если его не выключить, 1С не даст записать карточки, лицевые счета и документ. Для веб-клиента обработка открывается файлом или из справочника «Дополнительные отчеты и обработки» (вариант запуска — открытие формы).

Режимы на форме (отдельный прогон 16.09.2026)

Первый прогон закрыл путь «файл → документ» в формате Гарант Excel. Все режимы шапки проверили отдельно: 4 формата, 3 флажка, отборы таблицы. Программа 17/17, форма в браузере 33/34 (одна отметка из‑за файла с одной строкой — по смыслу успех). Подробности простым языком: отчет по режимам формы. Версия обработки после проверки флажка «Размножать лиц. счета» — 1.0.3.

Выводы

Обработку можно давать в работу. Правила поиска совпадают с ожидаемыми: сначала НРД id, затем ФИО и дата рождения, затем имя/отчество/адрес, для юрлиц — ИНН. Найденную карточку обработка не «исправляет» под файл, кроме записи нового НРД id в спорном случае с другой фамилией. Неизвестных пайщиков создает по команде, документ списка владельцев записывается.

В веб-клиенте тот же путь, что у сотрудника: файл → сопоставить → создать недостающих → документ. Если сопоставить пустую форму, система просит сначала прочитать файл.

Замечаний по ошибкам платформы и ошибкам в коде 1С в этом прогоне нет.
