1. Цели разработки

Задача IMDEV-7330 Сократить время массового формирования начислений НДФЛ на полном объёме клиентов без изменения налоговых сумм относительно типового (старого) алгоритма.
  1. Скорость. Параллельные пачки (оркестратор уже в 2.8.7.5) должны считать полный отбор 27 292 клиентов за часы, а не за двое суток. Эталон скорости: релиз 2.8.5.5 без доработок, 55 ч 05 мин, 500 объектов в час.
  2. Устойчивость. Несколько потоков не должны ронять расчёт на ожидании блокировки СУБД (SQL 1222 / HYT00). Пачка, упёршаяся в блокировку, повторяет запрос; хвост клиентов можно добрать.
  3. Корректность НКД. В массовом предрасчёте купон связывается с клиентом, который его оплатил. Чужой купон не попадает в расходы другого клиента пачки.
  4. Стоимость кэша НКД. Готовый кэш пачки передаётся параметром, а не через ПараметрыСеанса.ОбщиеЗначения (сериализация хранилища значения на каждого клиента).
  5. Регресс. Суммы документов «Начисление НДФЛ по портфелю» и «Начисление НДФЛ по управляющей компании» на выборке 27 292 равны эталону «по-старому». Допуск 0.01.

Три Patch-расширения (все 1.0.0.1) закрывают дыры релиза 2.8.7.5. Оркестратор пачек и массовый предрасчёт НКД в типовой уже есть, второй раз их не добавляют. После приёмки расширения снимают, код вливают в типовую.

Locks

Пауза 30 с после пачки > 1000 строк. Повтор запроса оборотов до 3 раз (60 и 180 с) только на SQL 1222 / HYT00. Вариант заполнения 4 - добор клиентов без документа.

NkdCoupon

В массовом запросе НКД купон хранится вместе с клиентом. Соединение по паре «этот клиент + этот купон». Одиночный расчёт одного клиента не меняется.

NkdParam

Кэш НКД пачки идёт параметром ВнешнийКэшНКД по стеку УК. Без параметра (форма документа) - старый путь с запросом. Сеанс ОбщиеЗначения не используется.

8. Возможности трёх расширений

РасширениеЧто даёт на полном объёмеВлияние на суммы
IMDEV7330_LocksЖивёт параллельный запуск: пауза между большими пачками, повтор оборотов при 1222, добор клиентов вариантом 4не меняет формулу налога

Одиночный расчёт с формы документа (без массового кэша) идёт прежним путём: параметр кэша не передали - запрос как в типовой.
