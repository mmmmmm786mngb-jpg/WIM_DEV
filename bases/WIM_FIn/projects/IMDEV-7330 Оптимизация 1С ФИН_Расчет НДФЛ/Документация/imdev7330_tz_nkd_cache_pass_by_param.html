1. Цель

Массовый кэш расходов НКД уже строится один раз на пачку (Перем СтруктураКэшНКД обработки). В типовой 2.8.7.5 он кладётся в ПараметрыСеанса.ОбщиеЗначения по ключу "КэшНКД". Тип параметра сеанса - ХранилищеЗначения: каждый Получить() / запись сериализует весь мешок сеанса.

PFF 6 потоков: около 43% own-time потока на эту сериализацию (УстановитьВнешнийКэшНКДРасходов ~0.88 с/вызов, ПолучитьВнешнийКэшНКДРасходов ~2.61 с/вызов). Это не SQL.

Цель: тот же объект Соответствие остаётся в памяти обработки и доходит до РасходыПоНКДПоВидуОбращаемости ссылкой (Возврат ПоКД, без копирования таблиц). Сеанс и ХранилищеЗначения в этом контуре не участвуют.

2. Как меняем

Образец уже есть у документа портфеля: Перем ВнешнийКэшОборотов + необязательный параметр РассчитатьНДФЛ(ПараметрыРасчетаВнешн = Неопределено). Для УК то же самое.

Правила
  • Новый параметр везде последний, тип Соответствие или Неопределено, умолчание Неопределено = путь запроса (форма УК, портфель, тесты без аргумента не ломаются).
  • У РассчитатьНДФЛ имя параметра - ВнешнийКэшНКДПараметр, чтобы не совпасть с Перем ВнешнийКэшНКД. В менеджере имя параметра - ВнешнийКэшНКД (менеджер Перем объекта не видит).
  • Перем кэша НКД только в модуле объекта документа УК. В модуль менеджера не класть.
  • Сбор кэша (ИнициализироватьКэшНКДПоМассивуПар, КлючКэшаНКД) не меняется.
  • Пять сигнатур с параметром в типовой 2.8.7.5 уже есть. При вливе параметр второй раз не добавлять, переносить только тела и Перем.
Не делать
  • Не писать кэш в ПараметрыСеанса.ОбщиеЗначения.
  • Не оставлять УстановитьВнешнийКэшНКДРасходов / ПолучитьВнешнийКэшНКДРасходов после влива (расширение их удалить не может - вендор удаляет в типовой).
  • Не трогать одноимённые процедуры документа портфеля и регистра НДФЛИнвестиционныеВычеты.
  • Не добавлять параметр в РасчетНДФЛ_ИнвестиционныйВычет - она читает Перем объекта.

Разбор было/стало с фрагментами кода: imdev7330_nkdparam_before_after.html.

3. Что меняем: дерево из расширения

Как переносить в типовую
  1. Из каждого перехвата: строки #Вставка вставить в тело типового метода; строки #Удаление убрать.
  2. Перем ВнешнийКэшНКД скопировать в модуль объекта документа УК (в типовой её ещё нет).
  3. Префикс IMDEV7330_NkdParam_, аннотации &ИзменениеИКонтроль и маркеры препроцессора в типовой не оставлять.
  4. После переноса тел удалить в модуле менеджера УК процедуры УстановитьВнешнийКэшНКДРасходов и ПолучитьВнешнийКэшНКДРасходов целиком. Поиск по CF: вызовов и ключа "КэшНКД" не осталось.
  5. Снять расширение IMDEV7330_NkdParam.

4. Приёмка

  1. Форма документа УК без обработки формирования: суммы как до доработки (кэш не передаётся).
  2. Обработка, пачка из 1 строки (порог 2, кэш не строится): документы УК считаются запросом, результат как раньше.
  3. Обработка, пачка больше порога: кэш один раз, каждый документ УК берёт срез по КлючКэшаНКД. Суммы инвествычета / НКД совпадают с эталоном на той же выборке.
  4. Документ портфеля: вызов менеджера УК без шестого аргумента компилируется и даёт прежний результат.
  5. PFF 6 потоков: в контуре НКД нет горячих ПараметрыСеанса.ОбщиеЗначения.Получить() / Новый ХранилищеЗначения.
  6. Поиск по CF после влива: нет УстановитьВнешнийКэшНКДРасходов, нет ПолучитьВнешнийКэшНКДРасходов, нет ключа "КэшНКД", нет Перем кэша НКД в модуле менеджера.
