IMDEV-7330: узел производительности — ВыполнитьПакет() в модуле менеджера документа по УК

Задача: IMDEV-7330, проект «Оптимизация 1С ФИН: расчет НДФЛ».
Объект: документ Документ.НачислениеНДФЛПоУправляющейКомпании, модуль менеджера: Documents\НачислениеНДФЛПоУправляющейКомпании\Ext\ManagerModule.bsl (выгрузка основной конфигурации: каталог базы из bases/WIM_FIn/source-path.txt, обычно WORK\WIM_FIn\src\cf\).
Узел: строка с вызовом Пакет = Запрос.ВыполнитьПакет(); в функции РасходыПоНКДПоВидуОбращаемости.
Данные замера (из профилировщика или отчета):
Строка модуля: 3069 (ориентир по сборке WIM_FIn на момент документирования).
Пример интерпретации метрик: 194 вызова или измерений; суммарное время около 100,75 с (запись через запятую как в локальных отчетах); доля от общего времени сеанса около 16,10%.
Точная семантика колонок зависит от инструмента замера (1С: замеры производительности, конвертный отчет и т.д.) — при сверке с файлом замеров убедитесь, что соответствие строкам модуля и счетчикам однозначно.

1. Что делает код в этой точке

Функция РасходыПоНКДПоВидуОбращаемости(ВидыОбращаемости, Клиент, Дата) (начало около строки 2846 в ManagerModule.bsl документа по УК) собирает один большой пакетный запрос к РегистрБухгалтерии.Хозрасчетный и связанным источникам, выполняет его одним вызовом Запрос.ВыполнитьПакет(), затем берет результаты из элементов массива Пакет: предпоследний результат — агрегация «по регистраторам», последний — «по партиям»; возвращается структура ПоПартиям / ПоРегистраторам.

1.1. Блоки пакета (логическая последовательность)

Блок Временная таблица / результат Содержание
1 ОплаченныеКупоныЗаПериод Хозрасчетный.ОборотыДтКт по счетам денежных средств и РасчетыПоОблигациям, отбор по клиенту через Портфель.Клиент, период НачалоПериода … КонецПериода (НачалоГода(Дата) … КонецДня(Дата)).
2 ВТ_РасходыПоНКД Три части ОБЪЕДИНИТЬ ВСЕ по Хозрасчетный.Обороты на счетах РасходыПоУплаченномуНКД: обычные обороты; отдельно для регистратора «ПереводНКДВЗадолженностьЭмитента» с учетом оплаченных купонов (КорСубконто2 / счет УплаченныйНКД); еще один фрагмент для того же документа с КорСубконто3 и РасчетыПоОблигациям.
3 РезультирующаяТаблица ВТ_РасходыПоНКД, соединение со Справочник.Облигации и РегистрСведений.ЗначенияПараметровПортфеля.СрезПоследних (признак расчета НДФЛ по НУ); вычисляются поля льгот, признак ОтражатьСтрокуВ3023 и др.
4 Итог пакета (предпоследний) Выбор из РезультирующаяТаблица с фильтрами по счетам, видам обращаемости, группировка по активу, периоду, партии, регистратору.
5 Итог пакета (последний) Аналогично, группировка «по партиям» (без регистратора в группировке).

После ВыполнитьПакет в коде применяется константа РасходыОтУКДУменьшаютДоходы для инверсии знака сумм при необходимости.

2. Почему это дорого по времени

  • Несколько проходов по виртуальным таблицам Хозрасчетный (ОборотыДтКт и несколько Обороты) за один пакет — на большом объеме движений каждый блок может стать планом с тяжелыми соединениями.
  • Подзапросы к ОплаченныеКупоныЗаПериод внутри условий по КорСубконто2 / КорСубконто3 усложняют оптимизацию на стороне СУБД.
  • ЛЕВОЕ СОЕДИНЕНИЕ со справочником Облигации по всем строкам ВТ_РасходыПоНКД увеличивает стоимость третьего шага.
  • Ранее ИнвестиционныйВычетУКД вызывал РасходыПоНКДПоВидуОбращаемости дважды на одну дату; в расширении NDFL_RDU это заменено одним вызовом с объединенным массивом видов (см. раздел 4).

3. Связь с цепочкой «Формирование начислений НДФЛ»

По описанию изысканий (imdev7330_ndfl_formation_research.md) для каждой строки ДатыДокументов после документа по портфелю выполняется СоздатьНачислениеНДФЛПоУК, внутри — поиск/создание документа по УК и РассчитатьНДФЛ(). Модуль менеджера документа по УК содержит общие функции расчета, включая НКД; узел ВыполнитьПакет в РасходыПоНКДПоВидуОбращаемости прямо учитывается в профиле при массовом формировании начислений.

4. Направления оптимизации (согласовано с проектом)

1. СУБД и текст запроса. Проанализировать план выполнения (технологический журнал MS SQL / СУБД конфигурации): индексы по периоду, счету, субконто, портфелю; возможность сократить число чтений Хозрасчетный за счет одной временной выборки с последующим фильтром в 1С.
2. Сократить число вызовов (сделано в расширении NDFL_RDU). В типовой конфигурации ИнвестиционныйВычетУКД дважды вызывал РасходыПоНКДПоВидуОбращаемости и сливал таблицы. В расширении добавлен перехват с директивой «вместо» для функции ИнвестиционныйВычетУКД: один вызов с массивом, собранным через ОбщегоНазначенияКлиентСервер.ДополнитьМассив из ОбращающиесяВиды() и НеОбращающиесяВиды(). Эквивалентно старой логике, потому что наборы видов не пересекаются, а дубликаты в параметре запроса ВидыОбращаемости не размножают строки результата. Полный снятие отбора по видам не делался: в перечислении есть, например, СделкаРЕПО и устаревшие значения — они не входили в пару вызовов и не должны внезапно попасть в инвестиционный вычет без отдельного решения.
3. Расширение NDFL_RDU. В проекте уже есть расширение NDFL_RDU с перехватом ТаблицаПродаж для документа по УК (ВТ вместо Регистратор В (&Регистратор) для больших массивов). Аналогичный подход для других тяжелых запросов — через анализ типового текста и согласование с методологией заимствования (см. imdev7330_ndfl_formation_processing_optimization.html).
4. Кэш на уровне параметров расчета. Если одна и та же пара Клиент, Дата встречается несколько раз в рамках одного сеанса формирования, кэшировать результат структуры ПоПартиям / ПоРегистраторам в памяти сеанса (с оговорками о согласовании данных и момента актуальности). Для IMDEV-7330 выбран вариант без нового общего модуля: хранение кэша делается прямо в модуле менеджера документа УК через ПараметрыСеанса.ОбщиеЗначения по ключу NDFL_RDU_КэшНКД, с обязательной очисткой в перехвате РассчитатьНДФЛ после ПродолжитьВызов() и в ветке Исключение.
Любая замена текста запроса в основной конфигурации без расширения может усложнить обновление типовой базовой поставки. Приоритет — изменения в CFE и проверка регрессии по НДФЛ (1530, НКД, инвествычет).
