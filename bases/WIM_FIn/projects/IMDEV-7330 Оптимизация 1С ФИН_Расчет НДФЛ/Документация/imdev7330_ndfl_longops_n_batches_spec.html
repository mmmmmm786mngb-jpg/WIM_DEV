1. Назначение и допущения

Команда формирования начислений НДФЛ по ТЧ ДатыДокументов выполняется в одной основной длительной операции БСП. Константа K (NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ) задаёт число окон разбиения; после пересечения с НомерСтрокиС / НомерСтрокиПо и упаковки по клиентам (НачислениеНДФЛПоУправляющейКомпании) остаются непустые пачки; по каждой стартует своя дочерняя ДО. Оркестратор ждёт завершения, сшивает лог и пишет итог во ВХ результата главной ДО.

В каждой пачке свой экземпляр обработки и свой кэш оборотов; межпоточная синхронизация кэша не требуется.

3. Поведение и поток в системе

Пользователь: «Создать документы» - окно ожидания БСП, процент и текст прогресса, по завершении - показ единого табличного документа лога; при частичных сбоях пачек - предупреждение и диагностика в итоге ДО.
  1. На сервере формы: NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере - снимок объекта, структура с Снимок и ИдентификаторФормы, NDFL_RDU_ДанныеВXML в поле ПараметрыXML процедуры фона, ВыполнитьВФоне на оркестратор.
  2. Оркестратор: разбор входа (ПараметрыXML или структура), чтение K, сбор индексов строк из снимка, NDFL_RDU_РазбитьСтрокиНаПачки(..., Снимок), NDFL_RDU_ПодготовитьПараметрыПачки по каждой непустой пачке.
  3. Подряд без паузы между стартами: для каждой пачки NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП - внутри вложенная ДО на NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ; в массиве хранятся УИД дочерних заданий.
  4. Цикл ожидания: по каждому УИД - НайтиПоУникальномуИдентификатору, обновление прогресса NDFL_RDU_ОбновитьПрогрессОркестратораПоЗаданиям, чтение результата пачки из АдресРезультатаПачки, сшивка.
  5. Итог во ВХ главной ДО - строка XML (NDFL_RDU_ЗаписатьРезультатОркестратораВоВременноеХранилище).

3.1 НомерСтрокиС, НомерСтрокиПо и воркер

Учёт пользовательского диапазона НомерСтрокиС / НомерСтрокиПо и прочих отборов входит в NDFL_RDU_СобратьИндексыСтрокПоСнимку (до геометрии окон). В шапке объекта воркера после копирования: НомерСтрокиС = 0, НомерСтрокиПо = 0 — отбор по номеру в шапке не дублируется (состав ТЧ воркера уже отфильтрован).

Воркер: свой Обработки.ФормированиеНачисленийНДФЛ.Создать(), NDFL_RDU_ЗаполнитьОбработкуИзПараметровПачки, СоздатьДокументы(ТабличныйДокумент) - срабатывает перехват NDFL_RDU_СоздатьДокументы с ПродолжитьВызов на урезанной ТЧ.

3.2 Разбиение по окнам и порядок номеров (IMDEV-7330)

Массив ИндексыСтрок после NDFL_RDU_СобратьИндексыСтрокПоСнимку — номера строк в порядке обхода строк табличной части в снимке.

  • Без полной ТЧ в третьем параметре: NDFL_RDU_РазбитьСтрокиНаПачки делит сам ИндексыСтрок на K последовательных блоков (равномерно по числу элементов).
  • С полной ТЧ: по выгрузке ТЧ находится Макс(НомерСтроки), задаётся РазмерОкна = Цел((МаксНомер + K - 1) / K). Для каждого НС из ИндексыСтрок вычисляется индекс окна Цел((НС - 1) / РазмерОкна) + 1 (не выше K); номер добавляется в буфер окна. Пустые окна в итог не попадают. Сложность раскладки по окнам — порядка O(M) по числу отобранных строк M, без K полных проходов по всей выгрузке ТЧ.
  • Порядок внутри пачки совпадает с порядком следования номеров в ИндексыСтрок. При подаче массива из другого источника (не из NDFL_RDU_СобратьИндексыСтрокПоСнимку) порядок внутри пачки может разойтись с вариантом «полный обход ТЧ для каждого окна».
  • Слияние по клиенту: NDFL_RDU_СлитьСоседниеПачкиПоОбщемуКлиенту строит соответствие НомерСтроки → Клиент одним проходом по полной выгрузке и сливает соседние непустые пачки при пересечении множеств клиентов на границе.

4.3 Прогресс в окне основной ДО (факт реализации)

Оркестратор вызывает NDFL_RDU_ОбновитьПрогрессОркестратораПоЗаданиям: по УИД пачек определяется число завершённых пачек и оценка обработанных строк; процент Процент = Окр(100 * ОбработаноСтрок / ВсегоСтрок, 0); текст для СообщитьПрогресс - шаблон НСтр("ru = 'Пачки: завершено %1 из %2; строк: %3 из %4'") (не формат «Пачка1-20%» по отдельным воркерам).

Отдельный локальный процент внутри каждой пачечной ДО в текущей реализации не обязателен для текста основного окна: агрегат строится оркестратором.

4.4 Итог главной ДО и тонкий клиент

Не выполнять на клиенте ПолучитьИзВременногоХранилища(АдресРезультата) с последующим NDFL_RDU_ДанныеИзXML и передачей полной структуры (в т.ч. СнимокОбъектаПосле с табличными данными) в контекст формы - риск ошибок на тонком клиенте.
  • Клиент не читает ВХ результата и не выполняет NDFL_RDU_ДанныеИзXML по содержимому итога: на сервер передаётся структура результата БСП (АдресРезультата строкой).
  • Сервер: NDFL_RDU_ОбработатьИтогНаСервере(РезультатДО, ПрименятьСнимок) читает итог по адресу, разбирает XML или структуру; при ПрименятьСнимок = Истина вызывает NDFL_RDU_ПрименитьСнимокОбъекта; возвращает на клиент лёгкую структуру полей (Успешно, ЧастичныйУспех, ТекстДиагностики, АдресТабличногоДокумента).
  • Клиент: NDFL_RDU_ПоказатьТабличныйДокументЛога только по адресу ВХ с табличным документом.
  • При статусе ДО «Ошибка»: NDFL_RDU_ПоказатьОшибку вызывает NDFL_RDU_ОбработатьИтогНаСервере(..., Ложь) чтобы при наличии итога во ВХ показать лог без изменения реквизита «Объект» формы.

5. Ошибки, отмена, тесты

  • Часть пачек с ошибкой: итог во ВХ с ЧастичныйУспех = Истина, статус главной ДО Выполнено; предупреждение на форме.
  • Все пачки упали: итог во ВХ (Успешно = Ложь), затем исключение снаружи перехвата оркестратора - статус ДО Ошибка.
  • Отмена пользователем: NDFL_RDU_ОтменитьЗаданияПачек по сохранённым УИД.
  • Тесты (направления): идентичность результатов 1 поток vs N пачек на одном наборе; отбор НомерСтрокиС/По; пустой набор; отмена; нагрузка и верхняя граница K.

6. БСП и референс Wim_Du (кратко)

  • Главная ДО: ПараметрыВыполненияВФоне(УникальныйИдентификатор) формы, ОжидатьЗавершение = 0, уникальный КлючФоновогоЗадания, АдресРезультата во ВХ формы.
  • Клиент: ДлительныеОперацииКлиент.ОжидатьЗавершение, окно и прогресс включены; оповещение дергает сервер только для разборки итога (п. 4.4).
  • Референс Wim_Du (РегламентныеПериоды, СформироватьРегламентныеОперации) - общий принцип ДО и СообщитьПрогресс; отличие: пачки НДФЛ стартуют одномоментно, а не мини-пулом «волнами» как основная модель задачи.

7. Диаграмма и внедрение

[Клиент, форма]  команда СоздатьДокументы (&Вместо)
       -> NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере()  // снимок + ПараметрыXML внутри
       -> ДлительныеОперации.ВыполнитьВФоне( ... NDFL_RDU_ОркестраторФормированияНДФЛ ... )

[Оркестратор, менеджер]  разбиение, для каждой пачки:
       -> NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП
       -> ВыполнитьВФоне( ВыполнитьПроцедуруМодуляОбъектаОбработки, NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ )
       -> цикл: НайтиПоУникальномуИдентификатору, ОбновитьПрогрессОркестратораПоЗаданиям, чтение АдресРезультатаПачки
       -> сшивка, ЗаписатьРезультатОркестратораВоВременноеХранилище (XML в АдресРезультата главной ДО)

[Клиент]  ОжидатьЗавершение -> NDFL_RDU_ОбработатьРезультат
       -> NDFL_RDU_ОбработатьИтогНаСервере(ПрименятьСнимок Истина) -> NDFL_RDU_ПоказатьТабличныйДокументЛога

[Воркер, объект обработки]  NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ
       -> ЗаполнитьОбработкуИзПараметровПачки(ЭтотОбъект, ...)
       -> СоздатьДокументы(ТабличныйДокумент)  // перехват NDFL_RDU_СоздатьДокументы, ПродолжитьВызов
       -> ПоместитьВоВременноеХранилище(РезультатПачки, АдресРезультатаПачки)

Внедрение: итерации 1-4 выполнены (форма и оркестратор, пачки и сшивка, прогресс, отмена и УИД); опционально - согласование верхней границы K и нагрузочные замеры. Подробный чек-лист: imdev7330_parallel_ndfl_implementation_plan.md.
