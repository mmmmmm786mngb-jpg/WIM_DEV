1. Назначение и допущения

Команда «Создать документы» по ТЧ ДатыДокументов либо выполняется синхронно на сервере формы (как в типовой обработке), либо поднимается одна основная длительная операция БСП с процедурой-оркестратором NDFL_RDU_ОркестраторФормированияНДФЛ в модуле менеджера обработки. Параллельный режим с ДО включается только если константа NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ (ниже — K) строго больше нуля и на форме не заполнен реквизит отбора Клиент (NDFL_RDU_ИспользоватьПараллельноеФормированиеНДФЛНаКлиенте в модуле формы). При K <= 0 или заполненном клиенте вызывается СоздатьДокументыНаСервере без оркестратора и без дочерних ДО пачек. Если оркестратор всё же запущен, эффективное число окон задаётся как Макс(1, Цел(K)), затем не более 50 (NDFL_RDU_ОркестраторФормированияНДФЛ и NDFL_RDU_РазбитьСтрокиНаПачки). После отбора индексов строк и разбиения по окнам (со слиянием соседних пачек по общему клиенту при наличии полной ТЧ в снимке) по каждой непустой пачке стартует своя дочерняя ДО; оркестратор ждёт завершения, сшивает табличные документы логов и пишет итог во ВХ результата главной ДО.

Принцип параллельного режима (для бизнес-заказчика). Пользователь по-прежнему работает с одной обработкой «Формирование начислений НДФЛ» и той же табличной частью ДатыДокументов на форме. При запуске формирования документов система определяет набор строк, которые должны войти в расчёт с учётом отборов (номера строк, клиенты, исключения и т.д.), затем делит этот набор на несколько пачек — условные «окна» по списку строк. Число таких окон задаётся константой расширения NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ (в остальном документе для краткости обозначение K); при K <= 0 или отборе по одному Клиент на форме параллельный режим с ДО не используется — расчёт идёт синхронно, как в типовой форме. Сверху в коде число окон также ограничено значением 50. Дальше каждая пачка обрабатывается той же самой бизнес-логикой, что и при обычном запуске, но в фоне поднимается отдельный экземпляр той же обработки, в который передаются только строки этой пачки (остальная шапка и контекст копируются так, чтобы расчёт вел себя предсказуемо). Таким образом, несколько фрагментов одного списка считаются параллельно в разных фоновых заданиях, без ручного деления работы между пользователями. Когда все пачки закончились, программа собирает результат в один итог: табличные документы логов пачек сшиваются в один файл для просмотра; обновление реквизита «Объект» формы из снимка после расчёта — только в ветках без нескольких успешных воркеров (см. п. 4.4). Если после разбиения фактически получилась одна пачка (мало строк или схлопывание по клиенту), отдельные параллельные задания не запускаются — выполняется привычный одиночный прогон той же обработки.
В каждой пачке свой экземпляр обработки и свои кэши оборотов по портфелям и НКД по парам (Клиент, Дата); межпоточная синхронизация кэшей не требуется.

3. Поведение и поток в системе

Пользователь: «Создать документы» - окно ожидания БСП, процент и текст прогресса, по завершении - показ единого табличного документа лога; при частичных сбоях пачек - предупреждение и диагностика в итоге ДО.
  1. На сервере формы: NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере — снимок объекта, структура с Снимок и ИдентификаторФормы, NDFL_RDU_ДанныеВXML в поле ПараметрыXML процедуры фона, ВыполнитьВФоне на оркестратор.
  2. Оркестратор: разбор входа (ПараметрыXML или структура), чтение K, NDFL_RDU_СобратьИндексыСтрокПоСнимку. Если после отбора индексов строк нет — запись итога во ВХ и выход.
  3. Если NDFL_RDU_РазбитьСтрокиНаПачки(..., Снимок) даёт не более одной непустой пачки — без дочерних ДО: один объект обработки из снимка, СоздатьДокументы, снимок после в итог, запись во ВХ главной ДО (XML) и выход.
  4. Иначе: инициализация прогресса во ВХ (АдресПрогресса), для каждой пачки из ПачкиИндексов — NDFL_RDU_ПодготовитьПараметрыПачки(Снимок, НомерПачки, ВсегоПачек, СтрокиПачки, ИдентификаторФормы, АдресПрогресса), где СтрокиПачки — массив номеров строк одной пачки; подряд без паузы NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП (вложенная ДО на NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ); в массиве — УИД дочерних заданий.
  5. NDFL_RDU_ОркестраторВыполнитьОжиданиеПачек: цикл до завершения всех ФЗ пачек; на каждой итерации — опрос по УИД через NDFL_RDU_ФоновоеЗаданиеПачкиПоИдентификатору, NDFL_RDU_ОбновитьПрогрессОркестратораПоЗаданиям (структура прогресса во ВХ по АдресПрогресса). Если функция вернула Истина — отмена родительского ФЗ: дочерние задания отменяются, во ВХ уже записан итог «прервано», дальнейшая сшивка не выполняется.
  6. После цикла: NDFL_RDU_ОркестраторСобратьРезультатыПачек читает из ВХ по АдресРезультатаПачки каждой пачки; NDFL_RDU_СшитьРезультатыПачекФормированияНДФЛ объединяет только табличные документы логов (поле СписокСообщений пачек в сшивку не входит).
  7. Итог главной ДО: NDFL_RDU_ЗаписатьРезультатОркестратораВоВременноеХранилище — во ВХ по АдресРезультата помещается XML-строка (NDFL_RDU_ДанныеВXML(Итог)).

3.1 НомерСтрокиС, НомерСтрокиПо и воркер

Учёт пользовательского диапазона НомерСтрокиС / НомерСтрокиПо и прочих отборов входит в NDFL_RDU_СобратьИндексыСтрокПоСнимку (до геометрии окон). В шапке объекта воркера после копирования: НомерСтрокиС = 0, НомерСтрокиПо = 0 — отбор по номеру в шапке не дублируется (состав ТЧ воркера уже отфильтрован).

Воркер: свой Обработки.ФормированиеНачисленийНДФЛ.Создать(), NDFL_RDU_ЗаполнитьОбработкуИзПараметровПачки, СоздатьДокументы(ТабличныйДокумент) - срабатывает перехват NDFL_RDU_СоздатьДокументы с ПродолжитьВызов на урезанной ТЧ.

3.2 Разбиение по окнам и порядок номеров (IMDEV-7330)

Массив ИндексыСтрок после NDFL_RDU_СобратьИндексыСтрокПоСнимку — номера строк в порядке обхода строк табличной части в снимке.

  • Без полной ТЧ в третьем параметре: NDFL_RDU_РазбитьСтрокиНаПачки делит сам ИндексыСтрок на K последовательных блоков (равномерно по числу элементов).
  • С полной ТЧ: по массиву ИндексыСтрок находятся МинНомерСтроки и МаксНомерСтроки, диапазон ДиапазонНомеров = Макс - Мин + 1, РазмерОкна = Цел((ДиапазонНомеров + K - 1) / K) (не меньше 1). Для каждого НомерСтроки из ИндексыСтрок: СмещениеОтМинимума = НомерСтроки - МинНомерСтроки, ИндексОкна = Цел(СмещениеОтМинимума / РазмерОкна) + 1 (с ограничением сверху K); номер добавляется в буфер окна. Пустые окна в итог не попадают. Сложность раскладки — порядка O(M) по числу отобранных строк M, без K полных проходов по всей выгрузке ТЧ.
  • Порядок внутри пачки совпадает с порядком следования номеров в ИндексыСтрок. При подаче массива из другого источника (не из NDFL_RDU_СобратьИндексыСтрокПоСнимку) порядок внутри пачки может разойтись с вариантом «полный обход ТЧ для каждого окна».
  • Слияние по клиенту: NDFL_RDU_СлитьСоседниеПачкиПоОбщемуКлиенту строит соответствие НомерСтроки → Клиент одним проходом по полной выгрузке и сливает соседние непустые пачки при пересечении множеств клиентов на границе.

4. Контракты, прогресс, клиент-сервер

4.1 Параметры пачки (структура, сериализация в ПараметрыXML)

Собирает NDFL_RDU_ПодготовитьПараметрыПачки(ИсходныйСнимок, НомерПачки, ВсегоПачек, СтрокиПачки, ИдентификаторФормы, АдресПрогресса = ""). ИдентификаторФормы — владелец ВХ для АдресРезультатаПачки и общего прогресса; в сериализуемую структуру пачки входят дублирующие поля и вложенная структура ПараметрыЗапуска (см. таблицу).

ПолеНазначение
НомерПачки, ВсегоПачекНомер пачки (с 1) и общее число пачек для воркера, заголовка ФЗ и прогресса.
ШапкаКлон полного снимка (NDFL_RDU_КлонироватьСнимок) — шапка и все ТЧ снимка; воркер получает полный контекст реквизитов.
СтрокиДатыДокументовТаблица значений — вырезка строк ТЧ ДатыДокументов по номерам из СтрокиПачки (с колонкой НомерСтроки).
ПараметрыЗапускаВложенная структура: АдресПрогресса, ИдентификаторФормы — общий прогресс оркестратора во ВХ.
ИдентификаторФормыДублируется на верхнем уровне (удобство при разборе на воркере).
АдресРезультатаПачкиАдрес ВХ под структуру результата пачки; создаётся через ПоместитьВоВременноеХранилище(..., ИдентификаторФормы).

Число ВсегоПачек для наименования дочернего фонового задания также передаётся аргументом в NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП (как и НомерПачки).

4.2 Результат пачки (ВХ АдресРезультатаПачки)

По адресу лежит структура, которую воркер помещает напрямую (ПоместитьВоВременноеХранилище(РезультатПачки, АдресРезультатаПачки) в модуле объекта). Обёртки вида «частичный прогресс / завершена» нет.

ПолеНазначение
НомерПачкиНомер пачки для журнала и диагностики.
ТабличныйДокументЛог пачки; участвует в NDFL_RDU_СшитьРезультатыПачекФормированияНДФЛ (последовательный Вывести).
СписокСообщенийТаблица значений сообщений пачки (NDFL_RDU_ТаблицаСообщенийПачки); в сшивку логов не включается.
ЕстьОшибка, ТекстОшибкиФлаг и текст при исключении в СоздатьДокументы воркера.

NDFL_RDU_ОркестраторСобратьРезультатыПачек читает эту структуру из ВХ; в УпавшиеПачки попадает порядковый номер пачки в запуске (с 1), если из ВХ пусто, тип не структура или ЕстьОшибка.

4.3 Прогресс в окне основной ДО (факт реализации)

Структура во ВХ по АдресПрогресса (владелец — ИдентификаторФормы формы): ВсегоПачек, ВсегоСтрок (число строк в отборе), ЗавершеноПачек, ОбработаноСтрок, ТекстЭтапа, ВремяСтартаМС, ВремяСтартаТекст (инициализация при старте параллельной ветки оркестратора).

Оркестратор в цикле ожидания вызывает NDFL_RDU_ОбновитьПрогрессОркестратораПоЗаданиям: по УИД дочерних ФЗ считается число завершённых пачек и суммарное число строк завершённых пачек (ОбработаноСтрок); процент Процент = Окр(100 * ОбработаноСтрок / ВсегоСтрок, 0) при ВсегоСтрок > 0.

Текст для ДлительныеОперации.СообщитьПрогресс — четыре строки, разделённые Символы.ПС (один шаблон СтрШаблон с подстановкой перевода строки как параметра): «Клиентов к расчету» = ВсегоСтрок (подпись для пользователя: объём отбора по строкам ТЧ); «Завершено потоков X из Y» — по ФЗ пачек; «Время старта» — ВремяСтартаТекст (ТекущаяДатаСеанса на старте прогресса); «Прошло мин:сек» — из ВремяСтартаМС через NDFL_RDU_СтрокаПрошедшихМинутСекунд (формат м:сс).

Локальный процент внутри каждой пачечной ДО для текста основного окна не используется: агрегат строит только оркестратор.

4.4 Итог главной ДО и тонкий клиент

Не выполнять на клиенте ПолучитьИзВременногоХранилища(АдресРезультата) с последующим NDFL_RDU_ДанныеИзXML и передачей полной структуры (в т.ч. СнимокОбъектаПосле с табличными данными) в контекст формы - риск ошибок на тонком клиенте.
  • Клиент не читает ВХ результата и не выполняет NDFL_RDU_ДанныеИзXML по содержимому итога: на сервер передаётся структура результата БСП (АдресРезультата строкой).
  • Сервер: NDFL_RDU_ОбработатьИтогНаСервере(РезультатДО, ПрименятьСнимок) читает из ВХ по АдресРезультата XML-строку (или структуру в особых случаях), при необходимости NDFL_RDU_ДанныеИзXML; при ПрименятьСнимок = Истина вызывает NDFL_RDU_ПрименитьСнимокОбъекта (поле СнимокОбъектаПосле в итоге; при успешном проходе нескольких пачек оркестратор передаёт СнимокОбъектаПосле = Неопределено, чтобы не смешивать частичные данные разных воркеров — реквизит «Объект» формы из итога тогда не обновляется). Возвращает на клиент лёгкую структуру полей (Успешно, ЧастичныйУспех, ТекстДиагностики, АдресТабличногоДокумента).
  • Клиент: NDFL_RDU_ПоказатьТабличныйДокументЛога только по адресу ВХ с табличным документом.
  • При статусе ДО «Ошибка»: NDFL_RDU_ПоказатьОшибку вызывает NDFL_RDU_ОбработатьИтогНаСервере(..., Ложь) чтобы при наличии итога во ВХ показать лог без изменения реквизита «Объект» формы.

5. Ошибки, отмена, тесты

  • Часть пачек с ошибкой: итог во ВХ с ЧастичныйУспех = Истина, статус главной ДО Выполнено; предупреждение на форме.
  • Все пачки упали: итог во ВХ (Успешно = Ложь), затем исключение снаружи перехвата оркестратора - статус ДО Ошибка.
  • Отмена пользователем: в NDFL_RDU_ОркестраторВыполнитьОжиданиеПачек при состоянии родительского ФЗ Отменено вызываются NDFL_RDU_ОтменитьЗаданияПачек по УИД пачек, во ВХ результата пишется сообщение о прерывании, сшивка пачек не выполняется.
  • Тесты (направления): идентичность результатов 1 поток vs N пачек на одном наборе; отбор НомерСтрокиС/По; пустой набор; отмена; нагрузка и верхняя граница K.

6. БСП: главная ДО, клиент, старт пачек (кратко)

  • Главная ДО: ПараметрыВыполненияВФоне(УникальныйИдентификатор) формы, ОжидатьЗавершение = 0, уникальный КлючФоновогоЗадания, АдресРезультата во ВХ формы.
  • Клиент: ДлительныеОперацииКлиент.ОжидатьЗавершение, окно и прогресс включены; оповещение дергает сервер только для разборки итога (п. 4.4).
  • Общий контур как у штатных длительных операций БСП: один фон по форме, прогресс родителя через ДлительныеОперации.СообщитьПрогресс, итог во ВХ по адресу из параметров. Здесь дочерние пачки после разбиения запускаются подряд без паузы между стартами (все заявки в очередь фона сразу); в типичной «волновой» схеме порция заданий сначала дорабатывается, затем запускается следующая волна с ограничением числа одновременных фоновых заданий.

7. Диаграмма потока и сопровождение

[Клиент, модуль формы]  команда (перехват типового «Создать документы»)
  -> NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере
       // снимок объекта, параметры в XML для фона
  -> ДлительныеОперации.ВыполнитьВФоне(..., NDFL_RDU_ОркестраторФормированияНДФЛ, ...)
       // АдресРезультата: во ВХ формы, владелец - УникальныйИдентификатор формы

[Сервер, менеджер]  NDFL_RDU_ОркестраторФормированияНДФЛ
  -> NDFL_RDU_СобратьИндексыСтрокПоСнимку
       // 0 строк: NDFL_RDU_ЗаписатьРезультатОркестратораВоВременноеХранилище, выход
  -> K = Мин(50, Макс(1, Цел(Константа))); NDFL_RDU_РазбитьСтрокиНаПачки(ИндексыСтрок, K, Снимок)
  -> если ПачкиИндексов.Количество() <= 1:
       один экземпляр обработки из снимка, СоздатьДокументы, снимок после, запись итога во ВХ (XML), выход
  -> иначе параллельная ветка:
       ПоместитьВоВременноеХранилище(структура прогресса) -> АдресПрогресса
       цикл по пачкам: NDFL_RDU_ПодготовитьПараметрыПачки(..., АдресПрогресса)
                     + NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП
            // внутри: ДлительныеОперации.ВыполнитьВФоне(ВыполнитьПроцедуруМодуляОбъектаОбработки, ...);
            // ПараметрыВыполненияВФоне с отдельным УИД владельца ВХ (не УИД формы)
       NDFL_RDU_ОркестраторВыполнитьОжиданиеПачек
            // опрос ФЗ по УИД, НайтиПоУникальномуИдентификатору, NDFL_RDU_ОбновитьПрогрессОркестратораПоЗаданиям
            // при отмене родителя: отмена дочерних, итог во ВХ, выход без сшивки
       NDFL_RDU_ОркестраторСобратьРезультатыПачек  // чтение ВХ по АдресРезультатаПачки каждой пачки
       NDFL_RDU_СшитьРезультатыПачекФормированияНДФЛ  // только ТабличныйДокумент
       NDFL_RDU_ЗаписатьРезультатОркестратораВоВременноеХранилище  // XML-строка в АдресРезультата главной ДО

[Клиент]  ДлительныеОперацииКлиент.ОжидатьЗавершение(..., оповещение NDFL_RDU_ОбработатьРезультат, ...)
  -> NDFL_RDU_ОбработатьРезультат
  -> NDFL_RDU_ОбработатьИтогНаСервере(РезультатДО, Истина)  // XML с ВХ, при успехе применить снимок к форме
  -> NDFL_RDU_ПоказатьТабличныйДокументЛога

[Сервер, модуль объекта]  NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ
  -> NDFL_RDU_ЗаполнитьОбработкуИзПараметровПачки(ЭтотОбъект, ...)
  -> СоздатьДокументы(ТабличныйДокумент)  // перехват NDFL_RDU_СоздатьДокументы: кэши оборотов и НКД по порогам, ПродолжитьВызов
  -> ПоместитьВоВременноеХранилище(РезультатПачки, АдресРезультатаПачки)

Сопровождение и план работ: в коде закрыты контуры формы (клиент/сервер ДО), менеджера (оркестратор, разбиение, прогресс, параметры и сбор пачек, сшивка) и объекта (воркер, перехваты, кэш). Дальнейшие действия вне кода (согласование верхней границы K, нагрузочные прогоны, регламент тестирования) фиксируются в imdev7330_parallel_ndfl_implementation_plan.md.

8. Схема на флипчарте

Один взгляд: от кнопки на форме до готового лога и обновлённых данных (порядок шагов сверху вниз).

1

Старт с формы

Пользователь запускает формирование документов; снимок обработки уходит на сервер и поднимается главная длительная операция БСП с оркестратором NDFL_RDU_ОркестраторФормированияНДФЛ.

2

Какие строки считаем

Оркестратор собирает индексы строк табличной части с учётом отборов. Если строк нет — сразу пишется итог во временное хранилище, без расчёта.

3

Сколько «окон» и пачек

Число окон задаётся константой NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ (в документе K): при K <= 0 или отборе по полю «Клиент» на форме параллельный режим не включается; иначе в оркестраторе K приводится к диапазону 1..50, строки режутся на пачки и при необходимости сливаются по клиенту.

4

Одна пачка или несколько

Если фактически одна пачка — один экземпляр обработки, СоздатьДокументы, запись итога. Если несколько — для каждой пачки своё фоновое задание с той же обработкой и только своими строками; общий прогресс во ВХ формы.

5

Ожидание и контроль

Оркестратор опрашивает дочерние задания по уникальному идентификатору, обновляет многострочный прогресс. При отмене пользователя дочерние задания останавливаются, итог фиксируется без сшивки пачек.

6

Сбор результата

Результаты пачек читаются из ВХ, табличные документы логов сшиваются в один; итог главной операции кладётся во ВХ как XML-строка.

7

Форма после завершения

Клиент по оповещению вызывает разбор итога на сервере и показывает единый табличный документ лога; снимок объекта на форму переносится только если в итоге передан непустой СнимокОбъектаПосле (одна пачка или одиночный прогон без дочерних ДО).

Техническая спецификация (as-built) расширения NDFL_RDU: оркестратор, многострочный прогресс, контракты ВХ, сшивка логов, кэши оборотов (пары Клиент/УК, порог 2) и НКД (пары Клиент/Дата, порог 2), условия включения параллельного режима на форме (K > 0, пустой клиент). Постановка задачи: imdev7330_постановка_параллельное_формирование_НДФЛ_БСП.html. Чек-лист и история внедрения: imdev7330_parallel_ndfl_implementation_plan.md.
