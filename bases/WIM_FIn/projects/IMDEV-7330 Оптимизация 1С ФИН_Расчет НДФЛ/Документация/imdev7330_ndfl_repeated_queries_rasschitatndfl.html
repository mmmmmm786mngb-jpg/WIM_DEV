Повторные вызовы одних и тех же запросов при РассчитатьНДФЛ

База конфигурации: WIM_FIn (исходники в рабочем каталоге WORK).
Объект: документ НачислениеНДФЛПоПортфелю, модуль объекта Documents\НачислениеНДФЛПоПортфелю\Ext\ObjectModule.bsl.
Назначение документа: фиксация дубликатов запросов в рамках одного вызова РассчитатьНДФЛ() с учётом ПараметрыРасчета() и вложенных процедур.

1. Введение

Процедура РассчитатьНДФЛ сначала вызывает ПараметрыРасчета(), затем набор функций Расчет1530, Расчет1531 и т.д. Часть подготовки параметров и расчёта кодов повторно выполняет один и тот же текст запроса (или пакет запросов) к базе данных. Это важно для оптимизации (IMDEV-7330): снижение числа обращений к РегистрБухгалтерии.Хозрасчетный и РегистрНакопления.КорректировкаФинРезультата.

2. Пакет РасходыПоНКДПоВидуОбращаемости (ВыполнитьПакет)

Функция РасходыПоНКДПоВидуОбращаемости один раз создаёт запрос и выполняет Запрос.ВыполнитьПакет(). Результаты ПоПартиям и ПоРегистраторам получаются из одного пакета (дополнительного обращения к СУБД по этому пакету нет). Дубликат возникает, когда саму функцию вызывают несколько раз с одним и тем же набором ВидыОбращаемости (обращающиеся или не обращающиеся ЦБ).

Набор видов Первый вызов Повторный вызов (тот же пакет) Условие повтора
НеОбращающиесяЦБ ПараметрыРасчета РасходыОтНКДНеОбращающихсяБумаг .ПоПартиям ИнвестиционныйВычетУКД РасходыПоНКДПоВидуОбращаемости(..., НеОбращающиесяЦБ).ПоРегистраторам Ветка инвествычета: ПолучатьИнвестиционныйВычетПоДоходам и константа учёта УКД/НКД; ОтразитьУКДиНКДВИнвестВычете не выходит сразу.
ОбращающиесяЦБ Расчет1530 РасходыПоНКДПоВидуОбращаемости(..., ОбращающиесяЦБ).ПоПартиям ИнвестиционныйВычетУКД тот же вызов с .ПоРегистраторам Те же условия, что и для не обращающихся.
Заметка: если ветка инвествычета не активна, полный пакет по каждому виду выполняется по одному разу в рамках описанной цепочки (но всё равно два разных вида = два пакета).

3. КорректировкаФинРезультатаКупонныйДоход (Запрос.Выполнить)

Отдельный запрос к регистру накопления КорректировкаФинРезультата с фильтром по ВидОбращаемости В(&ВидОбращаемости).

  • Дубль по НеОбращающиесяЦБ внутри одного ПараметрыРасчета(): сначала РасходыОтУКДНеОбращающихсяБумаг, затем РасходыОтНКДНеОбращающихсяБумаг оба вызывают КорректировкаФинРезультатаКупонныйДоход(ПараметрыРасчета, НеОбращающиесяЦБ).
  • Многократно по ОбращающиесяЦБ: после каждого ВыполнитьПакет в РасходыПоНКДПоВидуОбращаемости всегда вызывается КорректировкаФинРезультатаКупонныйДоход(ПараметрыРасчета, ОбращающиесяЦБ), даже если основной пакет считали для НеОбращающиесяЦБ. При полной цепочке (параметры + 1530 + инвествычет) запрос с параметром обращающихся видов может выполниться до четырёх раз за один расчёт.

4. ДоходыНКДПоСделкам

Запрос по табличному параметру &ОбщаяТаблицаДоходовРасходНКД (в логе отладки: НачислениеНДФЛПоПортфелю.ДоходыПоНКДПоВидуОбращаемости). При активной ветке инвествычета ДоходыНКДПоСделкам может выполниться дважды за один РассчитатьНДФЛ:

  • из ПараметрыРасчета через ДоходыОтНКД ДоходыОтНКДПриПродаже;
  • из ОтразитьУКДиНКДВИнвестВычете через ИнвестиционныйВычетНКДПриПродаже.

Таблица-параметр за один расчёт не меняется, но Выполнить() по сути повторяет обработку одного и того же текста запроса.

6. Идеи оптимизации

6.1. Один пакет вместо двух вызовов по видам обращаемости

Сейчас функция вызывается отдельно для ОбращающиесяЦБ и для НеОбращающиесяЦБ: каждый вызов заново строит общие ВТ и выполняет ВыполнитьПакет(). Правильнее доработать пакетный запрос: после общей РезультирующаяТаблица добавить четыре финальных блока (или эквивалентную схему без дублирования тела пакета):

  • итог «по партиям» и «по регистраторам» для обращающихся (аналог текущих двух последних запросов с отбором ВидыОбращаемостиЦБ В (&ОбращающиесяЦБ));
  • итог «по партиям» и «по регистраторам» для не обращающихся (условно имена вроде ПартииНеОбращающиеся, ПоРегистраторамНеОбращающиеся — точные имена ВТ/псевдонимов задаются при реализации).

Тогда за одно ВыполнитьПакет() получаются обе пары таблиц; вызывающий код читает нужные элементы пакета по индексам и возвращает структуру без второго прохода по регистру для другого набора видов. Свёртку «по партиям» из «по регистраторам» по-прежнему можно делать в памяти отдельно для каждого вида, если не переносить её в текст запроса.

6.2. Кэширование (если пакет всё же вызывается повторно)

Кэшировать нельзя «всю структуру ПараметрыРасчета» как ключ: нужен составной ключ из значений тех полей ПараметрыРасчета, которые реально участвуют в тексте запроса и в УстановитьПараметр, плюс то, что задаётся не из структуры. По модулю документа (функция РасходыПоНКДПоВидуОбращаемости, фрагмент после #Область ТекстЗапроса) к таким данным относятся:

ИсточникПоле / смысл
ПараметрыРасчета АктивыСЛьготируемымКДРоссийскихОрганизаций, АктивыСЛьготируемымКДРФИСоюзныхГосударств, АктивыСЛьготируемымКДРФ, НачалоПериода, ОбращающиесяЦБ (используется в тексте отдельно от аргумента ВидыОбращаемости), РасчетСуммыНДФЛВыполнятьПоСуммамНалоговогоУчета, СчетаДенежныхСредств, Дата_02082021, Дата_01012021, ОблигацииЭмитентовНерезидентов

Аргумент функцииВидыОбращаемости — до объединения пакета заменяется двумя фиксированными наборами из параметров расчёта

Счета из ПланыСчетов.Хозрасчетный в запросе не из ПараметрыРасчета, но от результата планов счетов тоже зависит выборка: при необходимости строгого кэша их нужно включить в ключ (или считать неизменными в пределах сеанса расчёта). Ключ кэша — сериализация перечисленных значений + признак набора видов, если пакет ещё не объединён по п. 6.1.

6.3. Прочие шаги

  • Один раз вычислить КорректировкаФинРезультатаКупонныйДоход(НеОбращающиесяЦБ) в ПараметрыРасчета и передавать в РасходыОтУКД... и РасходыОтНКД....
  • Рассмотреть один вызов КорректировкаФинРезультатаКупонныйДоход(ОбращающиесяЦБ) на расчёт вместо привязки к каждому выполнению НКД-пакета; проверить несоответствие параметров корректировки и вида обращённости в текущей реализации.
  • Кэшировать выгрузку ДоходыНКДПоСделкам по ключу из фактически используемых параметров запроса, если запрос остаётся отдельным.
