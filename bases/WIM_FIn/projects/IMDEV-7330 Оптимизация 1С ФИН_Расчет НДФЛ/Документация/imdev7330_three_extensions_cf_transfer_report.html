IMDEV-7330. Перенос трёх расширений в базовую конфигурацию ФИН

Проверка: попали ли доработки из патчей IMDEV7330_Locks, IMDEV7330_NkdCoupon, IMDEV7330_NkdParam в типовую конфигурацию WIM ФИН. Дата проверки: 14.09.2026. Версия CF: 2.8.8.1, вендор ООО «Аванкор».
OK

Все доработки трёх расширений перенесены

Тринадцать перехватов, новые процедуры и обязательное удаление сеансового кэша НКД найдены в базовой конфигурации 2.8.8.1. Потерянных блоков нет. После обновления базы на эту CF расширения IMDEV7330_Locks, IMDEV7330_NkdCoupon и IMDEV7330_NkdParam больше не требуются.

1. Что проверяли

Вендору передавали три Patch-расширения к релизу 2.8.7.5 (сводный файл для Аванкор imdev7330_three_extensions.html). В 2.8.7.5 уже были оркестратор пачек и массовый предрасчёт НКД. Три расширения закрывали оставшиеся дыры этого релиза.

Сейчас в типовой лежит конфигурация 2.8.8.1 (следующий релиз после 2.8.7.5). Нужно убедиться, что вендор вшил все три патча в базовую CF, а не оставил их только в расширениях.

Locks

Пауза 30 секунд между большими пачками, повтор запроса оборотов при SQL 1222, вариант заполнения 4 «клиенты на конец периода без НДФЛ».

Суммы налога расширение не меняет.

NkdCoupon

В массовом запросе НКД оплаченный купон хранится вместе с клиентом. Перевод НКД соединяется по паре «этот клиент + этот купон», а не по общей куче купонов пачки.

Одиночный расчёт одного клиента не меняется.

NkdParam

Кэш расходов НКД передаётся параметром ВнешнийКэшНКД из обработки в документ и дальше по стеку менеджера УК. Сеансовое хранилище больше не используется.

Обязательно удалить две сеансовые процедуры.

2. Как проверяли

Проверка сделана по исходникам XML/BSL типовой конфигурации, без запуска 1С.

  1. Состав патчей: какие объекты заимствованы и какие методы перехвачены (&ИзменениеИКонтроль), какие процедуры добавлены целиком.
  2. Из каждого блока #Вставка расширения берётся смысловой код и ищется в соответствующем модуле типовой CF.
  3. Новые процедуры без перехвата сверяются целиком (префикс IMDEV7330_* в типовой должен быть снят).
  4. Контроль обязательного удаления: процедур УстановитьВнешнийКэшНКДРасходов / ПолучитьВнешнийКэшНКДРасходов в CF быть не должно.

4. IMDEV7330_Locks — устойчивость к блокировкам

5. IMDEV7330_NkdCoupon — купон только своего клиента

Файл CF: Documents\НачислениеНДФЛПоУправляющейКомпании\Ext\ManagerModule.bsl, функция РасходыПоНКДПоКлиентамИДате (с строки 3292).

Старый массовый запрос складывал оплаченные купоны пачки в одну кучу без клиента. Перевод НКД смотрел «есть ли этот купон в куче» — купон одного клиента мог попасть в расчёт другого. Патч хранит пару (Клиент, Купон) и соединяет Перевод НКД по этой паре.

Вызовы РассчитатьНДФЛ() без аргумента (форма документа, тесты, прочие обработки) остаются допустимы: параметр имеет значение по умолчанию Неопределено, тогда расходы НКД считаются одиночным запросом. Так и задумано в патче.

7. Отличия от текста расширений — не ошибки

8. Вывод и что делать дальше

Заключение. Изменения трёх расширений полностью присутствуют в базовой конфигурации 2.8.8.1:

  • IMDEV7330_Locks — пауза между пачками, повтор запроса оборотов, индексы ВТ санкций, вариант заполнения 4 и пункт на форме;
  • IMDEV7330_NkdCoupon — массовый запрос НКД соединяет Перевод НКД по паре клиент + купон;
  • IMDEV7330_NkdParam — кэш идёт параметром по стеку УК, сеансовые процедуры кэша удалены.

Потерянных вставок нет. Патчи можно считать внедрёнными в типовую.

  1. После обновления рабочей / тестовой базы на CF 2.8.8.1 (или новее с этими правками) снять расширения IMDEV7330_Locks, IMDEV7330_NkdCoupon, IMDEV7330_NkdParam: они дублируют уже вшитый код. Не оставлять два перехвата на одном методе.
  2. Необязательная проверка в предприятии:
    • Locks: в обработке «Формирование начислений НДФЛ» есть пятый вариант заполнения; при параллельном запуске больших пачек в журнале регистрации могут появиться предупреждения «Повтор запроса после блокировки», а не сразу падение SQL 1222.
    • NkdCoupon: массовый расчёт пачки не должен переносить чужой оплаченный купон в расходы другого клиента (обработка диагностики IMDEV7330_DiagNkdCouponLeak).
    • NkdParam: расчёт из обработки идёт с кэшем пачки; расчёт кнопкой на форме документа без параметра по-прежнему считает одиночным запросом.
