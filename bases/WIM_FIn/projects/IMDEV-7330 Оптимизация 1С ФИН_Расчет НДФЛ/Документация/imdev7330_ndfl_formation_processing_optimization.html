Оптимизация создания документов из обработки «Формирование начислений НДФЛ»

Задача: IMDEV-7330.
Обработка: Обработка.ФормированиеНачисленийНДФЛ, модуль объекта: DataProcessors\ФормированиеНачисленийНДФЛ\Ext\ObjectModule.bsl (выгрузка WIM_FIn: WORK\WIM_FIn\src\cf\).
Фокус: цикл по портфелям при создании НачислениеНДФЛПоПортфелю, кэширование, оптимизация тяжёлого запроса НКД (черновики проекта).

1. Поиск документа по портфелю: один запрос на список, в цикле — из Соответствия

1.1. Как сейчас

В СоздатьНачислениеНДФЛПоПортфелю для строки ДатыДокументов вызывается СписокПортфелей(СтрокаДокументов), затем для каждого портфеля вызывается НайтиСоздатьДокументПоПортфелю(ТекПортфель, СтрокаДокументов.Дата). Внутри последней функции каждый раз выполняется запрос ВЫБРАТЬ ПЕРВЫЕ 1 к Документ.НачислениеНДФЛПоПортфелю с отбором по паре «портфель + конец дня даты документа». 

// Fragment: ObjectModule.bsl obrabotki (logika cikla)
СписокПортфелей = СписокПортфелей(СтрокаДокументов);
Для каждого ТекПортфель Из СписокПортфелей Цикл
    НачислениеНДФЛПоПортфелю = НайтиСоздатьДокументПоПортфелю(ТекПортфель, СтрокаДокументов.Дата);
    // РассчитатьНДФЛ, zapis ...
КонецЦикла;

1.2. Цель оптимизации

Идея: для фиксированной даты строки СтрокаДокументов.Дата и набора ссылок СписокПортфелей один раз выполнить один запрос, который вернёт все уже существующие документы начисления по портфелю на эту дату (по каждому портфелю — актуальная ссылка с учётом УПОРЯДОЧИТЬ ПО Дата УБЫВ, как в текущем ПЕРВЫЕ 1). Построить Соответствие (или Соответствие из пары ключей в строку): Ключ = Портфель (или Портфель + КонецДня(Дата)), Значение = ДокументСсылка или пустая ссылка.

В цикле по ТекПортфель: если в соответствии есть ссылка — ПолучитьОбъект() и дальше как сейчас; если нет — СоздатьДокумент() без предварительного запроса на поиск. Число обращений к СУБД по поиску документа снижается с O(N портфелей) до O(1) на этап поиска при неизменном списке портфелей и дате.

1.3. Замечание по ключу

Внешний цикл СоздатьДокументы идёт по разным СтрокаДокументов с разными датами: кэш соответствия «портфель → документ» имеет смысл строить на одну итерацию СоздатьНачислениеНДФЛПоПортфелю (после СписокПортфелей для этой строки), либо включать дату в ключ, если обобщать кэш на уровень всей процедуры.

2. Кэширование в Соответствие всего повторяющегося

2.1. Справочники и «лёгкие» обращения к данным

  • Повторяющиеся в рамках одного прогона значения из справочников (клиент, УК, параметры портфеля) — собирать через ОбщегоНазначения.ЗначенияРеквизитовОбъектов / пакетное чтение один раз на набор ссылок, результат складывать в Соответствие или Структуру с последующим чтением в цикле без N запросов к БД.
  • ОбщегоНазначенияДУПовтИсп.ЗначенияРеквизитовПортфеля(ТекПортфель) в цикле по портфелям (сейчас вызывается для каждого портфеля при проверке даты смерти) — кандидат на предварительное заполнение соответствия Портфель → Клиент (и при необходимости реквизиты клиента) после получения СписокПортфелей.
  • Константы (Константы.НачислениеНДФЛПоПортфелю.Получить()) не дергать внутри горячего цикла — один раз перед циклом.

2.2. Результаты одинаковых запросов

Обработка «Формирование начислений НДФЛ» для каждой строки и портфеля вызывает РассчитатьНДФЛ у документа НачислениеНДФЛПоПортфелю. Внутри одного расчёта уже зафиксированы повторные выполнения одних и тех же запросов (полный разбор, таблицы и схема вызовов — в отдельном файле imdev7330_ndfl_repeated_queries_rasschitatndfl.html). Имеет смысл учитывать это при нагрузочном сценарии «много портфелей × полный пересчёт».

  • Пакет РасходыПоНКДПоВидуОбращаемости (ВыполнитьПакет): при активной ветке инвествычета тот же пакет по НеОбращающиесяЦБ и по ОбращающиесяЦБ выполняется повторно после первого прохода в ПараметрыРасчета / Расчет1530 (см. разд. 2 и 6.1 в указанном HTML).
  • КорректировкаФинРезультатаКупонныйДоход: дважды с параметром НеОбращающиесяЦБ внутри одного ПараметрыРасчета() (РасходыОтУКДНеОбращающихсяБумаг и РасходыОтНКДНеОбращающихсяБумаг); запрос с ОбращающиесяЦБ может вызываться многократно из-за связки с каждым выполнением НКД-пакета (разд. 3 там же).
  • ДоходыНКДПоСделкам: при той же ветке инвествычета возможен второй Выполнить() с неизменной таблицей-параметром ОбщаяТаблицаДоходовРасходНКД (разд. 4 в том файле).

Связь с кэшем в Соответствие: если устранить дубли архитектурно не удаётся сразу, результат повторяющегося запроса можно кэшировать на время одного РассчитатьНДФЛ с ключом из фактических значений параметров, влияющих на выборку (не целиком «структура ПараметрыРасчета»): перечень полей для пакета НКД и идея объединения двух видов обращаемости в один пакет — в разд. 6.1–6.2 файла imdev7330_ndfl_repeated_queries_rasschitatndfl.html. Для ДоходыНКДПоСделкам ключ строится из состава табличного параметра и прочих установленных параметров запроса.

Общее правило: если один и тот же текст запроса с теми же значениями параметров вызывается из разных веток, сохранять выгрузку первого выполнения в соответствие и дальше брать из кэша до смены контекста расчёта.

Важно: кэш в памяти должен ограничиваться областью одного сеанса вызова СоздатьДокументы / одной строки ДатыДокументов, чтобы не устаревать при смене контекста и не раздувать память на очень больших списках портфелей.

3.1. Направления, уже зафиксированные в черновике

В репозитории проекта файл ПрмерыОПТИМИЗАЦИИ.md (папка IMDEV-7330) перечисляет типовые проблемы и целевой подход:

ПроблемаСмысл для оптимизации
Несколько вызовов Обороты() по одному счёту Объединить чтение регистра в один проход (одна ВТ с последующими отборами), где это возможно по смыслу учёта.
Подзапросы вида КорСубконтоX В (ВЫБРАТЬ ...) Вынести во ВТ с ПОМЕСТИТЬ и ИНДЕКСИРОВАТЬ ПО полям соединения; избегать коррелированных подзапросов в условии виртуальной таблицы.
Тяжёлые ВЫБОР с цепочками Портфель.Клиент, Актив Упростить выражения: заранее вычисляемые признаки в ВТ, меньше обращений к точкам через соединения.
ЛЕВОЕ СОЕДИНЕНИЕ со справочником по всей большой ВТ Сузить набор строк до соединения; при необходимости — отдельная ВТ «уникальные активы» и соединение только по ним.
Два почти одинаковых финальных запроса в пакете Рассмотреть один обобщённый запрос с разным использованием результата на стороне 1С или оставить два, но на общей сжатой ВТ без дублирования тяжёлых частей.

3.2. Дополнительно (связь с расчётом документа)

При полном пересчёте РассчитатьНДФЛ один и тот же пакет РасходыПоНКДПоВидуОбращаемости может вызываться несколько раз за один расчёт (см. HTML imdev7330_ndfl_repeated_queries_rasschitatndfl.html). Оптимизация текста запроса и снижение числа вызовов дополняют друг друга.
