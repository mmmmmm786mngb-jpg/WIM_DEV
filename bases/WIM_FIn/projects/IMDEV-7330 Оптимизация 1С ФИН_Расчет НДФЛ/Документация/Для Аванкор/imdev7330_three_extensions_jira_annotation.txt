IMDEV-7330. Три Patch-расширения для влива в типовую 2.8.7.5

Конфигурация: Доверительное управление, редакция 2, релиз 2.8.7.5 (ООО «Аванкор»).
Платформа: 8.3.27.

В 2.8.7.5 уже есть оркестратор пачек и массовый предрасчёт НКД. Второй раз их не добавлять.
Три расширения ниже закрывают оставшиеся дыры этого релиза. После приёмки расширения снять.

Вложения: IMDEV7330_Locks.cfe, IMDEV7330_NkdCoupon.cfe, IMDEV7330_NkdParam.cfe
(все версии 1.0.0.1). Карта объектов: imdev7330_триРасширения_ДеревоИзмененныхОбъектов.html.


1. IMDEV7330_Locks — устойчивость массового запуска

Когда несколько потоков считают НДФЛ одновременно, они могут столкнуться на одном запросе к СУБД
и получить ошибку ожидания блокировки (SQL 1222 / HYT00). Суммы налога расширение не меняет.

Что делает:
- после большой пачки (больше 1000 строк) ждёт 30 секунд перед запуском следующей;
- если запрос оборотов по портфелю упёрся в блокировку — повторяет его до трёх раз (паузы 60 и 180 секунд);
- добавляет вариант заполнения 4 «клиенты на конец периода без документа НДФЛ», чтобы добрать тех, кого упавшая пачка не посчитала.


2. IMDEV7330_NkdCoupon — купон только своего клиента

При массовом предрасчёте НКД по пачке оплаченные купоны складывались в одну общую кучу.
Перевод НКД смотрел, есть ли купон в этой куче. Куча общая, поэтому купон одного клиента
мог попасть в расчёт другого, а запрос раздувался.

Исправление: в массовом запросе купон хранится вместе с клиентом, который его оплатил.
Соединение идёт по паре «этот клиент + этот купон».
Одиночный расчёт одного клиента не меняется: там клиент и так один.


3. IMDEV7330_NkdParam — кэш НКД передаётся параметром

Кэш расходов НКД уже построен один раз на пачку. Типовой код перед каждым клиентом кладёт его
в параметр сеанса ОбщиеЗначения (хранилище значения) и каждый раз распаковывает весь сейф.
Это не SQL, это сериализация: на профиле уходила заметная доля времени потока.

Как надо: кэш передаётся из обработки в документ параметром ВнешнийКэшНКД и дальше по стеку
менеджера УК до lookup расходов. Если параметр не передали (форма документа, один клиент) —
работает старый путь с запросом.

В 2.8.7.5 параметр ВнешнийКэшНКД в сигнатурах уже объявлен, но не используется
(кэш по-прежнему читается из сеанса). Второй раз параметр не добавлять, переносить только тела методов.


Как переносить код

База — только 2.8.7.5. В более ранний релиз, где нет ОркестраторФормированияНДФЛ, вливать нельзя.

1) Как читать расширение.
Открыть модуль, найти процедуру с &ИзменениеИКонтроль.
Строки между #Вставка и #КонецВставки вставить в тело типового метода с тем же именем.
Строки между #Удаление и #КонецУдаления из типового метода убрать.
Новые процедуры без аннотации перехвата скопировать в тот же модуль целиком и снять префикс
IMDEV7330_Locks_ / IMDEV7330_NkdCoupon_ / IMDEV7330_NkdParam_.
Аннотации и маркеры #Вставка / #Удаление в типовой не оставлять.
Не копировать расширение целиком: в перехвате часто лежит копия всего метода.

2) Сначала Locks: повтор запроса оборотов, пауза в оркестраторе, вариант заполнения 4.

3) Затем NkdCoupon: в РасходыПоНКДПоКлиентамИДате заменить текст запроса целиком на текст из #Вставка.
Другие методы этим расширением не трогать.

4) Затем NkdParam: проброс уже объявленного параметра кэша по стеку УК,
вызов РассчитатьНДФЛ(СтруктураКэшНКД) из обработки, убрать запись кэша в сеанс.

5) ОБЯЗАТЕЛЬНО удалить из типовой две сеансовые процедуры:
УстановитьВнешнийКэшНКДРасходов и ПолучитьВнешнийКэшНКДРасходов.
Расширение их удалить не может. После переноса поиск по конфигурации:
вызовов и ключа "КэшНКД" быть не должно.

6) Снять три расширения. Не оставлять два перехвата на одном методе:
NkdCoupon правит только РасходыПоНКДПоКлиентамИДате,
NkdParam — только РасходыПоНКДПоВидуОбращаемости.
