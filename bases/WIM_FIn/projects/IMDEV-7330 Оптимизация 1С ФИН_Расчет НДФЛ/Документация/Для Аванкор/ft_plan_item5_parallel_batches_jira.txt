h3. 5. Распараллеливание расчётов по пачкам

*Статус:* доработка в расширении {{NDFL_RDU}}, обработка {{ФормированиеНачисленийНДФЛ}}.

*Назначение:* сократить время массового формирования начислений НДФЛ за счёт параллельной обработки пачек строк табличной части {{ДатыДокументов}} в фоновых заданиях при сохранении той же бизнес-логики, что и при однопоточном запуске.

----

h4. 5.1. Модуль формы

*Файл:* {{NDFL_RDU/DataProcessors/ФормированиеНачисленийНДФЛ/Forms/Форма/Ext/Form/Module.bsl}}

*Точка входа пользователя:* перехват команды {{&Вместо("СоздатьДокументы")}} — процедура {{NDFL_RDU_СоздатьДокументы}}.

*Условия выбора режима (обязательно):*

||Условие||Режим||Поведение||
|{{K = 0}} (константа {{NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ}})|Синхронный|Вызов {{СоздатьДокументыНаСервере}}, показ лога, без главной и дочерних ДО БСП — как в типовой форме|
|Заполнен отбор {{Объект.Клиент}}|Синхронный|То же — без оркестратора и без дочерних пачек|
|{{K > 0}} и {{Объект.Клиент}} не заполнен|Параллельный|Главная ДО БСП с оркестратором в модуле менеджера|

*Проверка на форме:* функция {{NDFL_RDU_ИспользоватьПараллельноеФормированиеНДФЛНаКлиенте}}.

*Параллельный сценарий (цепочка на форме):*

# {{NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере}} — снимок обработки ({{NDFL_RDU_СнимокОбъектаОбработки}}), сериализация параметров в XML ({{NDFL_RDU_ДанныеВXML}}), запуск главной ДО:
{code}
ДлительныеОперации.ВыполнитьВФоне(
    "Обработки.ФормированиеНачисленийНДФЛ.NDFL_RDU_ОркестраторФормированияНДФЛ",
    ПараметрыПроцедуры,
    ПараметрыВыполнения);
{code}
# {{NDFL_RDU_НачатьОжидание}} — окно ожидания БСП ({{ДлительныеОперацииКлиент.ОжидатьЗавершение}}), отображение прогресса.
# {{NDFL_RDU_ОбработатьРезультат}} — разбор статуса завершения главной ДО.
# {{NDFL_RDU_ОбработатьИтогНаСервере}} — чтение итога из ВХ *на сервере* (XML-строка, не десериализация тяжёлого снимка на клиенте).
# {{NDFL_RDU_ПоказатьТабличныйДокументЛога}} — показ пользователю единого сшитого табличного документа лога.
# {{NDFL_RDU_ПрименитьСнимокОбъекта}} — при полном успехе заполнение реквизита формы {{Объект}} из поля итога {{СнимокОбъектаПосле}}.

*Завершение и диагностика на форме:*

* статус *«Отменено»* — сообщение пользователю, снимок на форму не применяется;
* статус *«Ошибка»* — {{NDFL_RDU_ПоказатьОшибку}};
* *частичный успех* (флаги {{ЧастичныйУспех}}, {{ТекстДиагностики}} в итоге оркестратора) — лог показывается, дополнительно предупреждение об упавших пачках;
* по завершении — сообщение о длительности операции (замер с момента команды).

----

h4. 5.2. Модуль менеджера

*Файл:* {{NDFL_RDU/DataProcessors/ФормированиеНачисленийНДФЛ/Ext/ManagerModule.bsl}}

*Оркестратор главной ДО:* {{NDFL_RDU_ОркестраторФормированияНДФЛ}}.

*Обязанности оркестратора:*

# применить отбор строк (в т.ч. {{НомерСтрокиС}} / {{НомерСтрокиПо}}) до разбиения на пачки;
# разбить отобранные строки на пачки по константе {{K}} (эффективное число окон: {{Макс(1, Цел(K))}}, верхняя граница *50*);
# при одной фактической пачке — выполнить один проход {{СоздатьДокументы}} без создания дочерних ДО;
# для каждой непустой пачки — запустить дочернюю ДО ({{NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП}});
# опрашивать фоновые задания пачек по {{УникальныйИдентификатор}} без кэширования объекта {{ФоновоеЗадание}} между итерациями;
# обновлять прогресс главной ДО (агрегат по пачкам: строки, завершённые потоки, время);
# при отмене главной ДО — отменить дочерние задания ({{NDFL_RDU_ОтменитьЗаданияПачек}}), сшивку не выполнять;
# собрать результаты пачек ({{NDFL_RDU_ОркестраторСобратьРезультатыПачек}}), сшить *только табличные документы* логов ({{NDFL_RDU_СшитьРезультатыПачекФормированияНДФЛ}});
# записать итог главной ДО во ВХ в виде XML-строки ({{NDFL_RDU_ДанныеВXML}}).

*Запуск дочерней пачки:* через {{ДлительныеОперации.ВыполнитьВФоне}} с процедурой {{ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки}}, метод объекта — {{NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ}}.

----

h4. 5.3. Модуль объекта

*Файл:* {{NDFL_RDU/DataProcessors/ФормированиеНачисленийНДФЛ/Ext/ObjectModule.bsl}}

*Важно:* перехват {{NDFL_RDU_СоздатьДокументы}} в модуле объекта *не включает* параллельный режим. Он обеспечивает предрасчёт кэша и типовой цикл расчёта (в синхронном режиме и внутри воркера пачки).

*{{NDFL_RDU_СоздатьДокументы}} ({{&Вместо("СоздатьДокументы")}}):*
* сброс модульных переменных кэша оборотов и НКД;
* однократный предрасчёт {{ОбщиеОбороты}} и расходов НКД по текущей выборке (пороги и отборы — по реализации расширения);
* вызов {{ПродолжитьВызов(ТабличныйДокумент)}}.

*{{NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ}} (экспорт, воркер дочерней ДО):*
* отдельный экземпляр обработки, табличная часть урезана до строк пачки;
* в шапке воркера границы {{НомерСтрокиС}} / {{НомерСтрокиПо}} обнулены (отбор уже применён на уровне пачки);
* результат пачки помещается во временное хранилище по адресу, согласованному с оркестратором;
* исключение в воркере фиксируется в результате пачки ({{ЕстьОшибка}}, {{ТекстОшибки}}), оркестратор классифицирует упавшие пачки.

----

h4. 5.4. Константа и управление нагрузкой

*Константа:* {{NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ}} ({{K}}).

||Значение K||Семантика||
|{{0}}|Параллельный режим на форме отключён — только синхронный расчёт|
|{{> 0}}|Число окон разбиения; дополнительно ограничивается сверху значением *50* в коде оркестратора|

----

h4. 5.5. Разделение ответственности (краткая схема)

{code}
[Form]  NDFL_RDU_СоздатьДокументы          -> sync ИЛИ запуск главной ДО
            |
            v
[Manager] NDFL_RDU_ОркестраторФормированияНДФЛ -> пачки, ожидание, сшивка, итог XML во ВХ
            |
            v
[Object]  NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ -> расчёт одной пачки
            |
            v
[Form]    NDFL_RDU_ОбработатьРезультат     -> лог, снимок, отмена, частичный успех
{code}
