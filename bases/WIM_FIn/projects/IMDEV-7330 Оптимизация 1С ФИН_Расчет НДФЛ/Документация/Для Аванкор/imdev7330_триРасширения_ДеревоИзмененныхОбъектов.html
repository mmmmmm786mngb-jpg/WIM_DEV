Дерево изменяемых объектов трёх расширений IMDEV-7330

Что делают три патча, куда смотреть в дереве объектов и как перенести код в типовую 2.8.7.5.

1. Locks устойчивость массового запуска

Когда несколько потоков считают НДФЛ одновременно, они могут столкнуться на одном запросе к СУБД и получить ошибку ожидания блокировки (SQL 1222 / HYT00).

Расширение не меняет суммы налога. Оно делает три вещи: после большой пачки (больше 1000 строк) подождать 30 секунд перед следующей; если запрос оборотов по портфелю упёрся в блокировку — повторить его до трёх раз (паузы 60 и 180 секунд); добавить вариант заполнения 4 «клиенты на конец периода без документа НДФЛ», чтобы добрать тех, кого упавшая пачка не посчитала.

2. NkdCoupon купон только своего клиента

При массовом предрасчёте НКД по пачке оплаченные купоны складывались в одну общую кучу. Дальше перевод НКД смотрел: «есть ли такой купон в куче». Куча общая, поэтому купон одного клиента мог попасть в расчёт другого, а запрос раздувался.

Исправление одно: в массовом запросе купон хранится вместе с клиентом, который его оплатил. Соединение идёт по паре «этот клиент + этот купон». Одиночный расчёт одного клиента не меняется: там клиент и так один.

3. NkdParam кэш НКД передаётся параметром

Кэш расходов НКД уже построен один раз на пачку. Типовой код перед каждым клиентом кладёт его в параметр сеанса ОбщиеЗначения (хранилище значения) и каждый раз распаковывает весь сейф. Это не SQL, это сериализация: на профиле уходила заметная доля времени потока.

Как надо: коробка с кэшем передаётся из обработки в документ параметром ВнешнийКэшНКД, дальше по стеку менеджера УК до lookup расходов. Если параметр не передали (форма документа, один клиент) — работает старый путь с запросом. В 2.8.7.5 параметр в сигнатурах уже есть, но не используется: переносить только тела методов.

Порядок влива в 2.8.7.5

База для переноса — только релиз 2.8.7.5. Оркестратор пачек и массовый кэш НКД в типовой уже есть. Три расширения меняют уже существующие процедуры. В более ранний релиз, где нет ОркестраторФормированияНДФЛ, вливать нельзя.

  1. Как читать расширение. Открыть модуль. Найти процедуру с &ИзменениеИКонтроль. Строки между #Вставка и #КонецВставки вставить в тело типового метода с тем же именем. Строки между #Удаление и #КонецУдаления из типового метода убрать. Новые процедуры без аннотации перехвата скопировать в тот же модуль целиком и снять префикс IMDEV7330_Locks_ / IMDEV7330_NkdCoupon_ / IMDEV7330_NkdParam_. Аннотации и маркеры #Вставка / #Удаление в типовой не оставлять. Не копировать расширение целиком: в перехвате часто лежит копия всего метода.
  2. Сначала Locks. Перенести повтор запроса оборотов и две новые функции повтора, индексы во временных таблицах текста запроса оборотов, паузу 30 секунд в оркестраторе, ветку варианта заполнения 4 и пункт списка выбора на форме.
  3. Затем NkdCoupon. В типовой РасходыПоНКДПоКлиентамИДате заменить текст запроса целиком на текст из блока #Вставка. Другие методы этим расширением не трогать.
  4. Затем NkdParam. Параметр ВнешнийКэшНКД в сигнатурах 2.8.7.5 уже есть — второй раз не добавлять. Перенести тела: кэш с параметра в Перем объекта, проброс по стеку менеджера, lookup из параметра вместо чтения сеанса, вызов РассчитатьНДФЛ(СтруктураКэшНКД) из обработки. Три вызова УстановитьВнешнийКэшНКДРасходов в РассчитатьНДФЛ и обёртку сеанса в СоздатьНачислениеНДФЛПоУК убрать.
  5. Обязательно удалить из типовой две сеансовые процедуры: УстановитьВнешнийКэшНКДРасходов и ПолучитьВнешнийКэшНКДРасходов. Расширение их удалить не может. После переноса тел поиск по конфигурации: вызовов и ключа "КэшНКД" быть не должно.
  6. Снять три расширения IMDEV7330_Locks, IMDEV7330_NkdCoupon, IMDEV7330_NkdParam. Не оставлять два перехвата на одном методе: Coupon правит только РасходыПоНКДПоКлиентамИДате, Param — только РасходыПоНКДПоВидуОбращаемости.

Сборки CFE: Расширения/IMDEV7330_Locks.cfe, IMDEV7330_NkdCoupon.cfe, IMDEV7330_NkdParam.cfe. Дерево объектов ниже — карта точек для шагов 2-4.
