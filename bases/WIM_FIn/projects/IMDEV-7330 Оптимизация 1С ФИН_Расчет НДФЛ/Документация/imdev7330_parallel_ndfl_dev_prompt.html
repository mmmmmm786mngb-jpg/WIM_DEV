IMDEV-7330: промпт на доработку (параллельность уже реализованного контура NDFL_RDU)

Контекст: в расширении NDFL_RDU уже есть параллельное формирование начислений НДФЛ через БСП ДлительныеОперации: оркестратор в менеджере обработки, воркер пачки в модуле объекта, вход с формы по команде «Создать документы».
Постановка (PRD): imdev7330_постановка_параллельное_формирование_НДФЛ_БСП.html.
Техническая спецификация: imdev7330_ndfl_longops_n_batches_spec.html, imdev7330_ndfl_parallel_calculation.html.

1. Уже заложенная архитектура (не ломать)

  • Форма ФормированиеНачисленийНДФЛ, модуль формы: перехват &Вместо("СоздатьДокументы") — при K > 0 и пустом отборе Объект.Клиент запускается ДО оркестратора; иначе синхронный СоздатьДокументыНаСервере как в типовой форме.
  • K: константа расширения NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ (0 = параллельный режим выключен).
  • Менеджер обработки: снимок NDFL_RDU_СнимокОбъектаОбработки, разбиение строк ТЧ NDFL_RDU_ИмяТЧПарДляПараллельногоНДФЛ() (сейчас ДатыДокументов), NDFL_RDU_РазбитьСтрокиНаПачки, слияние соседних пачек по общему клиенту, запуск пачек ДлительныеОперации.ВыполнитьВФоне("ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки", ...) с методом NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ, опрос по ИдентификаторЗадания, сшивка лога и табличного документа.
  • Модуль объекта: NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ — десериализация параметров пачки из XML, заполнение объекта из снимка, вызов типового контура создания документов по строкам пачки; результат пачки во ВХ по АдресРезультатаПачки.

2. Правила для новых доработок в этом же контуре

  • Любой тяжелый предрасчет до цикла по строкам (кэш оборотов, НКД по клиентам и т.п.) выполнять в оркестраторе на полном снимке один раз, затем передавать в параметры каждой пачки сериализуемую структуру (расширить NDFL_RDU_ПодготовитьПараметрыПачки / снимок по контракту XML), а не дублировать запросы внутри каждого воркера.
  • В воркере объект обработки содержит только подмножество строк ТЧ и обнуленные отборы по номерам строк пачки — не рассчитывать на полный набор строк как в интерактивном объекте.
  • Сеансовые кэши (например ПараметрыСеанса.ОбщиеЗначения): не пересекать пачки; либо не использовать глобальную защелку в воркере, либо ключ с уникальным идентификатором пачки и гарантированная очистка.
  • Опрос ФЗ пачек: каждый раз получать задание через ФоновыеЗадания.НайтиПоУникальномуИдентификатору — не кэшировать объект ФоновоеЗадание между итерациями (состояние не обновится).
  • При отмене родительской ДО — отменять активные дочерние ФЗ пачек (паттерн уже в менеджере).
  • Прогресс БСП: обновлять через существующие процедуры оркестратора, не блокировать сеанс формы дольше типового ожидания ДО.

3. Критерии проверки после изменений

  • K = 0 и отбор по клиенту: поведение как у типовой обработки (без регрессий).
  • K > 1: корректная сшивка лога, отсутствие гонок по общим ресурсам, корректная отмена.
  • Сравнение результата массового прогона с эталоном при K = 1 (одна пачка) на тестовой выборке.
Не смешивать с оптимизацией справки-расчета по портфелю (ОбщаяСправкаРасчет2021): параллельный контур касается только обработки ФормированиеНачисленийНДФЛ и перехватываемых ею процедур.
