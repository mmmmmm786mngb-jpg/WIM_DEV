1. Цель и идея

Сейчас в обработке ФормированиеНачисленийНДФЛ.СоздатьДокументы выполняется единый последовательный цикл по табличной части ДатыДокументов (одна строка = одна тройка Клиент, УК, Дата). На каждой строке последовательно: 

// Process: ФормированиеНачисленийНДФЛ, modul object, procedure SozdatDokumenty (~стр. 6-127)
Для каждого СтрокаДокументов Из ДатыДокументов Цикл
    // ... отбор по номеру строки, по СписокКлиентовСЦБ ...
    СоздатьНачислениеНДФЛПоПортфелю(СтрокаДокументов, СписокСообщений);
    СоздатьНачислениеНДФЛПоУК(СтрокаДокументов, СписокСообщений, СписокНачислений);
КонецЦикла;

Внутри СоздатьНачислениеНДФЛПоПортфелю идёт ещё один цикл — по СписокПортфелей(СтрокаДокументов). Расчёт каждого документа (тяжёлый РассчитатьНДФЛ с массой запросов) выполняется в один поток сервера 1С. На массовых выборках это даёт линейный рост времени по числу клиентов и портфелей.

Идея оптимизации: в основном сеансе один раз подготовить общие кэши (массовый предрасчёт ОбщиеОбороты по портфелям и РасходыПоНКД по клиентам — см. два предыдущих плана), затем разбить выборку на N пачек клиентов и запустить пачки параллельно через ДлительныеОперации.ВыполнитьПроцедуруВНесколькоПотоков. В каждое фоновое задание передаются: пачка строк ДатыДокументов + срез кэшей по клиентам/портфелям этой пачки. После завершения всех заданий главная процедура собирает СписокСообщений из пачек, строит общий лог и вызывает оплату НДФЛ (как и сейчас).

Параметр N — значение константы НДФЛ_МаксимумПотоковПараллельногоРасчёта. По умолчанию 4 (с поправкой на число рабочих процессов кластера). При N ≤ 1 — старый последовательный путь без фоновых заданий.

2. Технология и состояние «как сейчас»

2.1. Что есть в БСП

Метод Назначение
ДлительныеОперации.ВыполнитьПроцедуруВНесколькоПотоков(ИмяПроцедуры, ПараметрыВыполнения, НаборПараметровПроцедуры) Запускает экспортную процедуру в N параллельных фоновых заданиях. На вход — Соответствие(Ключ → Массив параметров вызова). Возвращает структуру со статусом и адресом результата (Соответствие по ключам с результатами всех потоков).

В проекте уже есть пример многопоточного шаблона — ДлительныеОперации.ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей. Однако там другая модель (очередь в регистре сведений). Для нашей задачи проще использовать прямой вызов ВыполнитьПроцедуруВНесколькоПотоков с заранее подготовленным набором пачек.

2.2. Условия применимости

  • Вся серверная часть конфигурации развёрнута на 1С:Сервер (не файловая база). Многопоточные длительные операции в файловом режиме сводятся к последовательному выполнению.
  • Сессия — разделённая (или не используется разделение). В неразделённом сеансе ВыполнитьПроцедуруВНесколькоПотоков по соглашению БСП не работает; падать не будем — ниже добавлен fallback на последовательный путь.
  • Кластер настроен на достаточное число рабочих процессов; ограничение по сеансам не мешает запуску фонов.

4. Гранулярность пачек: по клиентам, не по портфелям

Запрос пользователя был «разбить портфели на N пачек». Это работает для документа НачислениеНДФЛПоПортфелю (по портфелю — свой документ, нет конкуренции за запись), но не работает для НачислениеНДФЛПоУправляющейКомпании:

  • Один документ УК создаётся по тройке (Клиент, УправляющаяКомпания, Дата), он один на всех портфелях клиента;
  • Если портфели одного клиента уйдут в разные пачки, два потока попытаются записать один и тот же документ УК — гонка по объектной блокировке + риск дубля до записи.
Решение. Разбиение делаем не по портфелям, а по клиентам. Пачка = непустое подмножество клиентов выборки; внутри пачки выполняется фрагмент главного цикла СоздатьДокументы только по строкам ДатыДокументов этих клиентов. Это автоматически обеспечивает «все портфели клиента — в одной пачке» и «все строки ДатыДокументов клиента — в одной пачке».

4.1. Алгоритм разбиения на пачки

  1. Собрать массив уникальных клиентов МассивКлиентов из ДатыДокументов с применением действующих отборов (НомерСтрокиС/По, НеСоздаватьДокументыПоКлиентамБезЦБ).
  2. Перемешать массив (опционально, для равномерности нагрузки) или отсортировать по количеству портфелей по убыванию (round-robin; даёт более ровные пачки при сильно разных клиентах).
  3. Round-robin распределение: 
    // IMDEV-7330 Round-robin: 0..N-1 → пачка 0, N..2N-1 в шахматке и т.д.
ПачкиКлиентов = Новый Соответствие; // Ключ = Номер пачки, Значение = Массив клиентов.
Для I = 0 По МассивКлиентов.Количество() - 1 Цикл
    Номер = I % МаксПотоков;
    Пачка = ПачкиКлиентов.Получить(Номер);
    Если Пачка = Неопределено Тогда
        Пачка = Новый Массив;
        ПачкиКлиентов.Вставить(Номер, Пачка);
    КонецЕсли;
    Пачка.Добавить(МассивКлиентов[I]);
КонецЦикла;
  4. Если получилось пачек меньше, чем МаксПотоков (например, клиентов меньше N), корректно — БСП не требует точного числа потоков.

5.3. Обработка ФормированиеНачисленийНДФЛ — главная функция параллельного режима

// DataProcessor FormirovanieNachisleniyNDFL, modul object (NDFL_RDU)
&НаСервере
Процедура NDFL_RDU_СоздатьДокументыПараллельно(ТабличныйДокумент, МаксПотоков)

    НачальноеВремя  = ТекущаяДатаСеанса();
    СписокСообщений = NDFL_RDU_ПустойСписокСообщений();
    СписокНачислений = Новый Массив;

    // 5.3.1 Применяем те же отборы, что в типовой СоздатьДокументы.
    КлиентыСЦБ = Неопределено;
    Если НеСоздаватьДокументыПоКлиентамБезЦБ Тогда
        КлиентыСЦБ = СписокКлиентовСЦБ();
    КонецЕсли;

    СтрокиОтобранные = NDFL_RDU_ОтобратьСтрокиДатыДокументов(КлиентыСЦБ);

    Если СтрокиОтобранные.Количество() = 0 Тогда
        ВывестиЛог(СписокСообщений, ТабличныйДокумент, НачальноеВремя);
        Возврат;
    КонецЕсли;

    // 5.3.2 Готовим общие кэши по всем клиентам выборки (ОДИН раз).
    МассивПортфелей      = NDFL_RDU_УникальныеПортфелиИзСтрок(СтрокиОтобранные);
    МассивПарКлиентДата  = NDFL_RDU_УникальныеПарыКлиентДата(СтрокиОтобранные);

    СтруктураКэшОборотов = Документы.НачислениеНДФЛПоПортфелю
        .NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям(МассивПортфелей);
    СтруктураКэшНКД      = Документы.НачислениеНДФЛПоУправляющейКомпании
        .NDFL_RDU_ПолучитьРасходыПоНКДПоКлиентам(МассивПарКлиентДата);

    // 5.3.3 Разбиваем КЛИЕНТОВ на пачки (round-robin).
    МассивКлиентов = NDFL_RDU_УникальныеКлиентыИзСтрок(СтрокиОтобранные);
    ПачкиКлиентов  = NDFL_RDU_РаспределитьПоПачкам(МассивКлиентов, МаксПотоков);

    // 5.3.4 Готовим набор параметров для каждой пачки.
    НаборПараметров = Новый Соответствие;
    НастройкиОбработки = NDFL_RDU_СохранитьНастройкиОбработки();

    Для Каждого Эл Из ПачкиКлиентов Цикл
        НомерПачки = Эл.Ключ;
        Клиенты    = Эл.Значение;

        ПараметрыПачки = Новый Структура;
        ПараметрыПачки.Вставить("НомерПачки",                  НомерПачки);
        ПараметрыПачки.Вставить("СтрокиДатыДокументовПачки",
            NDFL_RDU_ОтобратьСтрокиПоКлиентам(СтрокиОтобранные, Клиенты));
        ПараметрыПачки.Вставить("СписокКлиентовСЦБ",           КлиентыСЦБ);
        ПараметрыПачки.Вставить("СтруктураКэшОборотов",
            NDFL_RDU_СрезКэшаОборотовПоКлиентам(СтруктураКэшОборотов, Клиенты));
        ПараметрыПачки.Вставить("СтруктураКэшНКД",
            NDFL_RDU_СрезКэшаНКДПоКлиентам(СтруктураКэшНКД, Клиенты));
        ПараметрыПачки.Вставить("НастройкиОбработки",          НастройкиОбработки);

        // НаборПараметров.Вставить = Соответствие(Ключ → Массив параметров вызова).
        // Для NDFL_RDU_ВыполнитьПачкуРасчётаНДФЛ - 2 параметра, второй (АдресХранилища) ставит сама БСП.
        Параметры = Новый Массив;
        Параметры.Добавить(ПараметрыПачки);
        НаборПараметров.Вставить(НомерПачки, Параметры);
    КонецЦикла;

    // 5.3.5 Запуск.
    ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияФункции(Неопределено);
    ПараметрыВыполнения.НаименованиеФоновогоЗадания = "Расчёт НДФЛ - параллельный (IMDEV-7330)";
    ПараметрыВыполнения.ОжидатьЗавершение            = -1; // Не ждать в этом методе.
    // Имя процедуры - полное, для процедуры модуля объекта обработки используется
    // паттерн "Обработка.ИмяОбработки.МодульОбъекта.ИмяПроцедуры".
    ИмяПроцедуры = "NDFL_RDU_ВыполнитьПачкуРасчётаНДФЛ"; // см. 5.4 о размещении

    Запуск = ДлительныеОперации.ВыполнитьПроцедуруВНесколькоПотоков(
        ИмяПроцедуры, ПараметрыВыполнения, НаборПараметров);

    // 5.3.6 Ожидание + сбор результатов.
    NDFL_RDU_ОжидатьЗавершение(Запуск);
    СоответствиеРезультатов = ПолучитьИзВременногоХранилища(Запуск.АдресРезультата);

    // 5.3.7 Агрегация СписокСообщений / СписокНачислений из всех пачек.
    Для Каждого ЭлРез Из СоответствиеРезультатов Цикл
        Поток = ЭлРез.Значение; // см. ВыполнитьПроцедуру → структура с РезультатВыполнения и т.п.
        Если Поток = Неопределено Тогда
            Продолжить;
        КонецЕсли;
        АдресТЗ = Поток.АдресРезультата;
        Если ЗначениеЗаполнено(АдресТЗ) Тогда
            Результат = ПолучитьИзВременногоХранилища(АдресТЗ);
            Если Результат = Неопределено Тогда
                Продолжить;
            КонецЕсли;
            NDFL_RDU_ОбъединитьСписокСообщений(СписокСообщений, Результат.СписокСообщений);
            Для Каждого Сс Из Результат.СписокНачислений Цикл
                СписокНачислений.Добавить(Сс);
            КонецЦикла;
        КонецЕсли;
    КонецЦикла;

    // 5.3.8 Прежний пост-блок: оплата НДФЛ и лог - оставляем как есть в типовой.
    NDFL_RDU_ОплатаНДФЛИЛог(ТабличныйДокумент, СписокСообщений, СписокНачислений, НачальноеВремя);

КонецПроцедуры

Логика 5.3.8: блок «оплата НДФЛ» (типовая ветка Если СоздаватьОплатуНДФЛ И ВариантЗаполнения = 2 Тогда ...) и ВывестиЛог — выносим в отдельную процедуру и вызываем её один раз в основном сеансе. Оплата создаёт собственные документы списания, она не должна параллелиться (общие проводки, общая аналитика).

6. Сценарии и обратная совместимость

Сценарий A. МаксПотоков <= 1

поведение Перехват СоздатьДокументы сразу делает ПродолжитьВызов. Поведение полностью идентично типовому (последовательный путь).

Сценарий B. Файловая база

поведение NDFL_RDU_МожноЗапускатьМногопоточно вернёт Ложь → последовательный путь. Это страховка от ошибок инициализации фоновых заданий.

Сценарий C. Малая выборка (мало клиентов)

поведение ПачкиКлиентов.Количество() может быть меньше МаксПотоков. БСП запустит ровно столько потоков, сколько ключей в наборе. Можно ввести порог МинКлиентовДляФона (например, 10) и при меньшей выборке идти последовательно.

Сценарий D. Большая выборка (продакшн)

главный сценарий Сотни/тысячи клиентов. Кэши готовятся один раз; пачки идут параллельно. Ускорение — кратное числу потоков (с поправкой на конкуренцию по СУБД).

Сценарий E. Внешний обмен / API

поведение Внешний обмен зовёт НачислениеНДФЛПоПортфелю.РассчитатьНДФЛ() напрямую, не СоздатьДокументы. Параллелизм его не затрагивает.

Сценарий F. Один поток упал с исключением

обработка Внутренний Попытка ... Исключение в точке входа фона ловит ошибку, пишет её в СписокСообщений и в журнал регистрации. Остальные потоки продолжают. Главная процедура агрегирует ошибки и выводит в общий лог.

7. План тестирования

№ Что проверяем Как Ожидаемый результат
1 Идентичность результатов параллельного и последовательного режимов. Запустить обработку 2 раза за один период: МаксПотоков = 1 и МаксПотоков = 4. Сравнить созданные документы НДФЛ (по ссылке, суммам начислений и удержаний, расшифровкам). Нулевая разница в суммах и составе строк.

3 Серьёзная нагрузка / нет дублей УК. На тестовой базе с массой клиентов (≥ 50) запустить параллельно. Проверить, что на каждую тройку (Клиент, УправляющаяКомпания, Дата) создан ровно один документ НачислениеНДФЛПоУправляющейКомпании. Дублей нет; ошибок «Запись объекта была изменена другим пользователем» нет.
4 Сериализация кэшей в фон. Юнит-тест: сформировать СтруктураКэшОборотов и СтруктураКэшНКД, поместить в ХранилищеЗначения и обратно — ничего не теряется. Полное соответствие до и после.
5 Производительность. Замерить время СоздатьДокументы на одинаковой выборке при N = 1, 2, 4, 8. Логировать число вызовов ОбщиеОбороты и РасходыПоНКДПоВидуОбращаемости. 6 Ошибка в одном потоке. Внести искусственную ошибку для одного клиента (например, дата смерти). Запустить параллельный расчёт. Поток с ошибкой не рушит остальные; ошибка попадает в СписокСообщений и в общий лог.
7 Файловая база / неразделённый сеанс. Запустить обработку в файловой ИБ (или эмулировать). Автоматически срабатывает последовательный путь без ошибок.

8. Риски, ограничения, открытые вопросы

  • Конкуренция за регистр Хозрасчетный. Параллельное проведение НачислениеНДФЛПоПортфелю разными клиентами обычно безопасно (записи пишутся по своим Портфелям/Контрагентам), но при общих счетах и общих субконто возможны таймауты блокировок. Решения:
    • СУБД-уровень: серверные блокировки идут по полям в составе индексов Хозрасчетный.ПоИзмерениям; на разных портфелях обычно нет пересечений.
    • Если возникают таймауты — снизить МаксПотоков, либо включить УправляемыеБлокировки + явные блокировки по Портфель/Клиент.
  • Память. Кэши по всей выборке + срезы по пачкам = временный пик памяти. В NDFL_RDU_СрезКэшаОборотовПоКлиентам создаются новые Соответствие с теми же ТЗ-объектами (без копирования) — это дёшево.
  • Сериализация в фон. Параметры процедуры должны быть сериализуемыми. Если в кэше неожиданно окажутся объектные ссылки на МоментВремени или мутирующие обёртки, фон упадёт с ошибкой сериализации. Покрывается тестом № 4.
  • Реквизиты обработки в фоновом сеансе сбрасываются. Поэтому передаём НастройкиОбработки явно (см. NDFL_RDU_СохранитьНастройкиОбработки / NDFL_RDU_ПрименитьНастройкиОбработки).
  • Оплата НДФЛ. Блок «оплата НДФЛ» (создание документов СписаниеСРасчетногоСчета) не параллелится — он работает с общими пуловыми проводками и должен идти после завершения всех пачек.
  • Прогресс на форме. Текущий план — серверный цикл ожидания; пользователь видит «обработка идёт». Для UX полезнее перевод оркестратора в форму обработки с ДлительныеОперацииКлиент.ОжидатьЗавершение и индикатором (планируется отдельной итерацией).
  • Логирование. Сообщения, выведенные через Сообщить() внутри фона, теряются для пользователя; используем СписокСообщений через структуру и общую сборку в основном сеансе.

Главное преимущество. В сочетании с уже спланированными массовыми предрасчётами (ОбщиеОбороты по портфелям и РасходыПоНКД по клиентам) параллелизм даёт ускорение в N раз для всей обработки СоздатьДокументы: тяжёлые запросы выполняются один раз в основном сеансе, а лёгкие РассчитатьНДФЛ с попаданием в кэши идут одновременно для разных клиентов. Архитектурно — расширение NDFL_RDU добавляет:
  • одну константу управления — НДФЛ_МаксимумПотоковПараллельногоРасчёта;
  • один перехват СоздатьДокументы с прозрачным fallback на типовое поведение при МаксПотоков ≤ 1 или в файловом режиме;
  • одну экспортную точку входа фона NDFL_RDU_ВыполнитьПачкуРасчётаНДФЛ.
