*Основные точки нагрузки - две, суммарно ~38,2% общего времени:*

* *Строка 1 (22,13%)* - {{ОбщиеОбороты = Запрос.Выполнить().Выгрузить();}} в модуле объекта документа {{НачислениеНДФЛПоПортфелю}} (строка 7 544): запрос вызывается отдельно на каждый портфель текущего клиента.
* *Строка 2 (16,10%)* - {{Пакет = Запрос.ВыполнитьПакет();}} в модуле менеджера документа {{НачислениеНДФЛПоУправляющейКомпании}} (строка 3 069): запрос вызывается отдельно на каждую пару (Клиент, Дата) и фактически дублируется по разным документам начислений одного клиента.

*В первую очередь рассматриваем подход "один запрос на всех клиентов сразу":* каждую из этих двух тяжёлых точек переводим с режима "запрос на портфель / пару (Клиент, Дата)" на массовый запрос, который один раз отрабатывает по массиву портфелей или клиентов выборки, возвращает данные с разрезом по портфелю/клиенту, и далее идёт раздача из кэша через короткое замыкание в перехватах расширения {{NDFL_RDU}}. Это убирает повторные обращения к СУБД и позволяет использовать единые временные таблицы.

*Во вторую очередь - параллельные расчёты:* когда массовые предрасчёты готовы, основной цикл обработки {{ФормированиеНачисленийНДФЛ}} разбивается на N пачек клиентов и запускается параллельно через {{ДлительныеОперации.ВыполнитьПроцедуруВНесколькоПотоков}}. Кэши предрасчёта передаются в каждое фоновое задание срезом по клиентам пачки, чтобы внутри потока продолжало работать короткое замыкание и не было повторных тяжёлых запросов.

Прочие точки в таблице (строки 3-7) после этих двух шагов либо снимаются автоматически (используют те же предрасчитанные данные), либо имеют существенно меньший вес и оптимизируются по остаточному принципу.

*1. Строка 1 (22,13%) - {{ОбщиеОбороты}} в модуле объекта документа Портфеля.*
Массовый предрасчёт по массиву портфелей: один пакетный запрос на всю выборку, кэш в разрезе портфеля, короткое замыкание в перехвате {{NDFL_RDU_ОбщиеОбороты}}.
План: {{imdev7330_ndfl_mass_precalc_oborots.html}}

*2. Строка 2 (16,10%) - {{РасходыПоНКДПоВидуОбращаемости}} в модуле менеджера документа УК.*
Массовый предрасчёт по массиву клиентов на единую дату: один пакет вместо повторных вызовов на пары (Клиент, Документ начисления), кэш в разрезе (Клиент, Дата), короткое замыкание в перехвате модуля менеджера УК.
План: {{imdev7330_ndfl_uk_nkd_mass_precalc_byclient.html}}

*3. Распараллеливание расчётов по пачкам клиентов.*
После того как массовые предрасчёты готовы, обработка {{ФормированиеНачисленийНДФЛ.СоздатьДокументы}} разбивает выборку на N пачек клиентов (константа {{НДФЛ_МаксимумПотоковПараллельногоРасчёта}}) и запускает их параллельно через {{ДлительныеОперации.ВыполнитьПроцедуруВНесколькоПотоков}}. Кэши предрасчёта передаются срезом по клиентам пачки в каждое фоновое задание.
План: {{imdev7330_ndfl_parallel_calculation.html}}
