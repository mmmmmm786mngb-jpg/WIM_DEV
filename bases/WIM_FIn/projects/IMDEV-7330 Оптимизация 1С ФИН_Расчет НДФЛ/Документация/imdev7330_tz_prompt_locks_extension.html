IMDEV-7330. ТЗ-промпт на доработку: расширение устойчивости к блокировкам НДФЛ

1. Зачем

На прогоне DR 30.08.2026 при K = 8 две пачки упали на строке ОбщиеОбороты = Запрос.Выполнить().Выгрузить() до создания документов. Текст ошибки: 

Конфликт блокировок при выполнении транзакции:
Microsoft OLE DB Driver 19 for SQL Server: Lock request time out period exceeded.
HRESULT=80040E31, SQLSrvr: SQLSTATE=HYT00, state=38, Severity=10, native=1222, line=1

Нужно: пережить такую ошибку повтором запроса; если пачка всё же потеряна - добрать клиентов кнопкой заполнения; разнести старты пачек; ускорить соединения двух временных таблиц индексами.

  2. Шаг 2. Вариант заполнения 4 «По отсутствующим Начислениям НДФЛ»: кандидаты варианта 2 минус пары (Клиент, УК), у которых уже есть хотя бы один проведённый документ по портфелю или по УК (не пуловое основание). Раздел 5 отчёта.

4. Правила расширения для вендора

  1. Каждый изменяемый типовой метод оформляется так: 
    &ИзменениеИКонтроль("ИмяТиповогоМетода")
Функция IMDEV7330_Locks_ИмяТиповогоМетода(...)
    // полное актуальное тело из базы 2.8.7.3
    #Удаление
    // старая строка
    #КонецУдаления
    #Вставка
    // новая строка
    #КонецВставки
КонецФункции
    Тело вне маркеров должно побайтно совпадать с текущей базой. Нельзя переписывать метод «с нуля».
  2. Имя процедуры-перехватчика = префикс расширения + имя типового метода (IMDEV7330_Locks_ОбщиеОбороты).
  3. Новые процедуры (повтор запроса, вариант заполнения 4) добавляются в тот же модуль без аннотации перехвата. Для вендора: просто скопировать их в типовой модуль рядом с вызовом.
  4. Маркеры #Вставка / #Удаление в многострочном тексте запроса ставятся между строками с | (препроцессор 1С, затем склейка строки). Нельзя класть маркеры внутрь кавычек как текст запроса.
  5. Ключевые слова 1С: Не, Или, И, Тогда, КонецЕсли (первая заглавная). Переменные - PascalCase. Комментарии только на русском. Экспортные и новые служебные методы - с документирующим комментарием по стандарту проекта.
  6. Параметры запросов писать как &Имя, без HTML-сущностей в .bsl.
  7. Пауза только через АванкорСервер.Пауза(КоличествоМиллисекунд) - так принято в этой конфигурации (внутри для ФЗ вызывается платформенный ВызватьПаузу). Не выдумывать ПриостановитьВыполнение.
  8. При ВызватьИсключение после Попытка всегда передавать строку с ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()). Голый ВызватьИсключение; запрещён: вендор и журнал регистрации должны видеть исходный текст SQL 1222 / HYT00.
  9. Не создавать константы метаданных и общие модули. Локальные числа (3 попытки, 30000 мс, порог 1000 строк пачки) - переменные в теле процедуры.

6. Детализация шагов

6.1 Шаг 1. Повтор запроса при блокировке

Точка падения: Документ.НачислениеНДФЛПоПортфелю.МодульОбъекта, функция ОбщиеОбороты, строка ОбщиеОбороты = Запрос.Выполнить().Выгрузить();. К этому моменту документы не пишутся, повтор безопасен.

Состав:

  • Новая функция ЭтоОшибкаОжиданияБлокировки - фильтр по фрагментам текста (см. приложение А1).
  • Новая функция ВыполнитьЗапросСПовторомПриБлокировке - до 3 попыток, паузы 60 000 и 180 000 мс через АванкорСервер.Пауза.
  • В перехвате ОбщиеОбороты заменить одну строку выполнения запроса на вызов обёртки (приложение А2).
Ошибка и исключение В ветке Исключение сначала: ИнформацияОбОшибкеВыполнения = ИнформацияОбОшибке(); ТекстОшибки = ПодробноеПредставлениеОшибки(ИнформацияОбОшибкеВыполнения); Если это не блокировка или попытки кончились: ВызватьИсключение ТекстОшибки; - в текст исключения обязан попасть исходный текст платформы/SQL (native=1222, HYT00, «Конфликт блокировок...»). Перед повторным ВызватьИсключение записать тот же ТекстОшибки в журнал регистрации. Повторять только ошибки ожидания блокировки. Ошибки расчёта (тип значения, права, пустая ссылка) - сразу наружу с тем же текстом.

6.2 Шаг 2. Вариант заполнения 4

  • Реквизит ВариантЗаполнения уже число 1 знак - значение 4 допустимо, тип не менять.
  • В Form.xml у переключателя ВариантЗаполнения добавить пятый элемент списка: значение 4, представление «По отсутствующим Начислениям НДФЛ» (приложение А5).
  • ЗаполнитьДатыДокументов: ветка ИначеЕсли ВариантЗаполнения = 4 Тогда ЗаполнитьПоОтсутствующимНачислениямНДФЛ(); до КонецЕсли (приложение А3).
  • Новая экспортная процедура ЗаполнитьПоОтсутствующимНачислениямНДФЛ - полный запрос в приложении А4. Кандидаты - как в ЗаполнитьДокументамиНаДату (вариант 2). «Уже есть» - как в ЗаполнитьПоСуществующимНачислениямНДФЛ (вариант 0): проведённые документы портфеля и УК, без пулового основания, период Период.ДатаНачала ... КонецДня(Период.ДатаОкончания). Итог: левое соединение и ВТ_УжеРассчитаны.Клиент ЕСТЬ NULL.
  • УправлениеФормой: поля отбора варианта 2 (ФормироватьНачисленияТолькоПоПортфелямСДвижениямиПоНДФЛ, СхемаВыплаты) видны при 2 или 4. СоздаватьОплатуНДФЛ - только при 2 (добор без автооплаты). Период виден при <> 3 - для 4 уже так.
  • СоздатьДокументы не трогать: условие оплаты СоздаватьОплатуНДФЛ И ВариантЗаполнения = 2 остаётся.
Приёмка варианта 4 на текущих данных DR После прогона «с блокировками» на периоде 01.01.2026-31.12.2026 заполнение вариантом 4 должно дать порядка 6 436 клиентов / 7 116 портфелей (дыра Абабилов ... Дёмшин плюс ДУ 9961 Тренева Е.Л.).

6.3 Шаг 3. Пауза между стартами пачек

В ОркестраторФормированияНДФЛ цикл запуска (около строк 655-663 модуля менеджера): 

Для Каждого ПачкаИндексов Из ПачкиИндексов Цикл
    НомерПачки = НомерПачки + 1;
    ПараметрыПачки = ПодготовитьПараметрыПачки(...);
    МассивПараметровПачек.Добавить(ПараметрыПачки);
    ИдентификаторЗаданияПачки = ЗапуститьПачкуФормированияНДФЛЧерезБСП(...);
    МассивИдентификаторовЗаданийПачек.Добавить(ИдентификаторЗаданияПачки);
КонецЦикла;

После Добавить(ИдентификаторЗаданияПачки) паузу вызывать только если выполнены оба условия:

  • это не последняя пачка: НомерПачки < ВсегоПачек;
  • в только что запущенной пачке больше 1000 строк: ПачкаИндексов.Количество() > 1000 (ПачкаИндексов - массив номеров строк ТЧ этой пачки).

Тогда АванкорСервер.Пауза(30000). Если пачка маленькая (1000 строк и меньше) - следующий запуск сразу, без ожидания. После последней пачки паузы нет в любом случае. Остальное тело оркестратора копируется без изменений. Не перезапускать пачки (это шаг 7, OUT).

6.4 Шаг 4. Индексы двух временных таблиц

В перехвате ОбщиеОборотыТекстЗапроса две вставки (приложение А6):

  1. После ИЗ &ТаблицаПродажДляРасчетаЛьготПоКлиентамПодСанкциями КАК ВТ_АкцииРоссийскихЭмитентов и до ;: ИНДЕКСИРОВАТЬ ПО Регистратор, Портфель, Актив, Партия.
  2. После СГРУППИРОВАТЬ ПО у ВТ_ТаблицаВыручкиПоКлиентамПодСанкциями и до ;: ИНДЕКСИРОВАТЬ ПО Регистратор, Актив, Портфель.

Остальной текст запроса не менять: пустую правую границу Обороты(&НачалоПериода, , ...) не закрывать; составной индекс списка документов не трогать.

8. Критерии готовности

  1. Расширение собирается, подключается к WIM_FIn 2.8.7.3, не конфликтует с IMDEV7330_Fix (разные методы).
  2. Синхронный режим и K = 1: поведение как до доработки (вариант заполнения 0-3, суммы расчёта).
  3. Искусственно: если Выполнить() в ОбщиеОбороты один раз бросает текст с native=1222 / Lock request time out - вторая попытка проходит, в ЖР есть предупреждение с полным текстом ошибки.
  4. Ошибка без маркеров блокировки (например «Тип не определен») - без повтора, в исключении тот же подробный текст.
  5. Вариант 4 заполняет только пары без проведённых (не пуловых) начислений; на данных после сбоя - ожидаемый масштаб дыры.
  6. При K > 1 и размере пачки больше 1000 строк: старты соседних пачек разнесены примерно на 30 с, после последней паузы нет. Если в пачке 1000 строк и меньше - следующий запуск без паузы (как в плотном цикле сейчас).
  7. План запроса / замер одной пачки: временные таблицы санкций с индексами; результат ОбщиеОбороты на контрольной группе совпадает с эталоном.
