# IMDEV-7330: план внедрения параллельного формирования НДФЛ (NDFL_RDU)

Источник: согласованный план реализации (модуль менеджера для фона, модуль объекта для перехватов и кэша). Детальная спецификация требований: [imdev7330_ndfl_longops_n_batches_spec.html](imdev7330_ndfl_longops_n_batches_spec.html). **Полный пошаговый план внедрения:** [imdev7330_ndfl_extension_full_implementation_plan.md](imdev7330_ndfl_extension_full_implementation_plan.md).

## Исходные данные и ограничения

- Спецификация: `imdev7330_ndfl_longops_n_batches_spec.html`.
- Расширение: каталог `Расширения/NDFL_RDU/` (константа `NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ`, заимствованная форма обработки, перехват модуля объекта, расширение модуля менеджера обработки).
- Типовой поток без расширения: клиент `СоздатьДокументы` создаёт `ТабличныйДокумент`, вызывает `СоздатьДокументыНаСервере`, внутри — `Объект.СоздатьДокументы(ТабличныйДокумент)` после `РеквизитФормыВЗначение("Объект")`, затем показ лога.
- Перехват `NDFL_RDU_СоздатьДокументы` в модуле объекта: сброс/инициализация кэша, затем `ПродолжитьВызов(ТабличныйДокумент)`.

Жёсткий инвариант: не вызывать типовое `ПродолжитьВызов` дважды для одной логической даты/строки при разбиении; параметризовать сбор пар и кэш по массиву номеров строк пачки.

## Выбор механизма второго слоя (воркеры)

- Оркестратор: одно задание `ДлительныеОперации.ВыполнитьВФоне`, экспорт **`модуля менеджера`** `Обработки.ФормированиеНачисленийНДФЛ.NDFL_RDU_ОркестраторФормированияНДФЛ`.
- Воркеры: `ФоновыеЗадания.Выполнить` на экспорт **`Обработки.ФормированиеНачисленийНДФЛ.NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ`** (тот же менеджер). Внутри: `Обработки.ФормированиеНачисленийНДФЛ.Создать()` и вызов `СоздатьДокументы` на объекте (перехваты в модуле объекта).

### Итоговая схема размещения (стандарт 1С)

- **`ManagerModule.bsl`**: `NDFL_RDU_ОркестраторФормированияНДФЛ`, `NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ`, вспомогательно `NDFL_RDU_ПодготовитьПараметрыПачки`, `NDFL_RDU_РазбитьСтрокиНаПачки(ИндексыСтрок, КоличествоПачекПользователя)`, сшивка лога (ТЗ сообщений, сортировка, один ТД).
- **`ObjectModule.bsl`**: перехваты `NDFL_RDU_СоздатьДокументы` и др., кэш, `NDFL_RDU_СобратьПарыКлиентУКСУчетомОтборовДокументов`, `NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар` (параметризация по номерам строк).

### Прогресс

Общее ВХ состояния пачек; воркеры пишут процент пачки; оркестратор взвешивает по числу строк и вызывает `ДлительныеОперации.СообщитьПрогресс`; опционально текст вида `Пачка 3/8 • 67% • Мин: 41% • Макс: 89%`.

## Область: модуль формы

- `NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере` — лёгкие сериализуемые параметры, `ВыполнитьВФоне` на менеджер.
- `NDFL_RDU_НачатьОжиданиеПараллельногоФормирования`, `NDFL_RDU_ОбработатьРезультатПараллельногоФормирования` — клиент, БСП.

## Итерации

1. Один фон, оркестратор без ФЗ: `Создать()` + `СоздатьДокументы`.
2. Разбиение, ФЗ, ВХ прогресса, ТЗ лога, слияние.
3. Отмена, краевые случаи, отмена дочерних ФЗ.

## Прочее

- Базовая обработка `ФормированиеНачисленийНДФЛ` в выгрузке WIM_FIn не содержит отдельного файла `ManagerModule.bsl`; в расширении добавляется **расширение модуля менеджера** для экспортов фона.
