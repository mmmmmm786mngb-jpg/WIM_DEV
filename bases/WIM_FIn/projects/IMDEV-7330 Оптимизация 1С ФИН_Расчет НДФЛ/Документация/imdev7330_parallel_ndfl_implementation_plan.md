# IMDEV-7330: план внедрения параллельного формирования НДФЛ (NDFL_RDU)

Источник: согласованный план реализации. Детальная спецификация (актуализирована по коду): [imdev7330_ndfl_longops_n_batches_spec.html](imdev7330_ndfl_longops_n_batches_spec.html). **Развёрнутый план расширения:** [imdev7330_ndfl_extension_full_implementation_plan.md](imdev7330_ndfl_extension_full_implementation_plan.md).

## Исходные данные и ограничения

- Спецификация: `imdev7330_ndfl_longops_n_batches_spec.html` (в т.ч. [п. 4.4, итог ДО и тонкий клиент](imdev7330_ndfl_longops_n_batches_spec.html#client-server-result)).
- Расширение: каталог `Расширения/NDFL_RDU/` (константа `NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ`, заимствованная форма обработки, перехват модуля объекта, расширение модуля менеджера обработки).
- Типовой поток без расширения: клиент по команде «Создать документы» вызывает серверную процедуру с `РеквизитФормыВЗначение("Объект")`, затем `Объект.СоздатьДокументы(ТабличныйДокумент)` и показ лога.
- **По факту:** команда «Создать документы» в расширении перехвачена в **модуле формы** (`&НаКлиенте`, `&Вместо("СоздатьДокументы")`): полный синхронный прогон по всей ТЧ из этой команды не выполняется; стартует основная ДО БСП на оркестратор.
- Перехват `NDFL_RDU_СоздатьДокументы` в **модуле объекта**: сброс/инициализация кэша, затем `ПродолжитьВызов(ТабличныйДокумент)` — вызывается из воркера пачки на урезанной ТЧ.

Жёсткий инвариант: не вызывать типовое `ПродолжитьВызов` дважды для одной логической даты/строки при разбиении; параметризовать сбор пар и кэш по массиву номеров строк пачки.

## Выбор механизма второго слоя (воркеры пачек)

- **Оркестратор:** одно задание `ДлительныеОперации.ВыполнитьВФоне`, экспорт **модуля менеджера** `Обработки.ФормированиеНачисленийНДФЛ.NDFL_RDU_ОркестраторФормированияНДФЛ`. Вход: структура с полем `ПараметрыXML` (сериализация `NDFL_RDU_ДанныеВXML` со снимком обработки и `ИдентификаторФормы`) либо уже разобранные поля.
- **Пачки:** не `ФоновыеЗадания.Выполнить` по строке менеджера. Каждая пачка — **вложенная ДО БСП**: `ДлительныеОперации.ВыполнитьВФоне("ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки", ...)` с `ИмяМетода` = **`NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ`** (экспорт **модуля объекта** обработки). Обёртка в менеджере: `NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП`; возвращается `УникальныйИдентификатор` дочернего ФЗ.
- **Опрос пачек:** в массиве оркестратора хранятся только УИД заданий; при каждой итерации — `ФоновыеЗадания.НайтиПоУникальномуИдентификатору` (объект `ФоновоеЗадание` между опросами не кэшировать). Итог пачки — по `АдресРезультатаПачки` в параметрах пачки.

### Итоговая схема размещения (по коду)

- **`ManagerModule.bsl`:** `NDFL_RDU_ОркестраторФормированияНДФЛ`, `NDFL_RDU_ЗапуститьПачкуФормированияНДФЛЧерезБСП`, `NDFL_RDU_ФоновоеЗаданиеПачкиПоИдентификатору`, `NDFL_RDU_ОтменитьЗаданияПачек`, `NDFL_RDU_ОбновитьПрогрессОркестратораПоЗаданиям`, снимок/заполнение (`NDFL_RDU_СнимокОбъектаОбработки`, `NDFL_RDU_ЗаполнитьОбъектОбработкиИзСнимка`, приведение снимка), `NDFL_RDU_РазбитьСтрокиНаПачки`, `NDFL_RDU_ПодготовитьПараметрыПачки`, `NDFL_RDU_ЗаполнитьОбработкуИзПараметровПачки`, `NDFL_RDU_СшитьРезультатыПачекФормированияНДФЛ`, `NDFL_RDU_ЗаписатьРезультатОркестратораВоВременноеХранилище`, `NDFL_RDU_ДанныеВXML` / `NDFL_RDU_ДанныеИзXML`, вспомогательные функции разбиения и отмены родительской ДО.
- **`ObjectModule.bsl`:** перехваты `NDFL_RDU_СоздатьДокументы` и др., кэш, `NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ` (экспорт воркера пачки для БСП), `NDFL_RDU_СобратьПарыКлиентУКСУчетомОтборовДокументов`, `NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар` и др.

### Прогресс

Оркестратор агрегирует состояние пачек по УИД дочерних ФЗ и вызывает `ДлительныеОперации.СообщитьПрогресс` (текст вида `Пачка1-20%; Пачка2-25%; ...` и общий процент по согласованной формуле в коде).

## Область: модуль формы

- `NDFL_RDU_ЗапуститьПараллельноеФормированиеНаСервере` (`&НаСервере`): снимок объекта, `ПараметрыXML`, `ВыполнитьВФоне` на оркестратор, `АдресРезультата` во ВХ формы.
- `NDFL_RDU_НачатьОжиданиеПараллельногоФормирования`, `NDFL_RDU_ОбработатьРезультатПараллельногоФормирования` (`&НаКлиенте`): `ДлительныеОперацииКлиент.ОжидатьЗавершение`.
- После успеха: `NDFL_RDU_АдресРезультатаДлительнойОперации` (только строка адреса на клиенте) -> `NDFL_RDU_ОбработатьИтогДлительнойОперацииНаСервере(Адрес, Истина)` -> лёгкая структура + `NDFL_RDU_ПоказатьТабличныйДокументЛогаПоАдресу` (на клиенте из ВХ только табличный документ). Разбор полного итога с `СнимокОбъектаПосле` и ТЗ внутри ТЧ — **только на сервере** (п. 6.3 HTML-ТЗ).
- При статусе «Ошибка»: `NDFL_RDU_ПоказатьОшибкуЗапускаДлительнойОперации` — при наличии адреса разбор с `ПрименятьСнимок = Ложь` (лог без изменения данных формы) + текст ошибки БСП.

## Итерации (факт выполнения)

1. **Итерация 1:** форма на `ВыполнитьВФоне`, ветвление статусов, цепочка завершения с серверным разбором итога (без «тяжёлой» структуры на клиенте).
2. **Итерация 2:** константа `K`, разбиение по п. 5.1 ТЗ, одномоментный запуск пачек вложенными ДО, сшивка, запись итога оркестратора во ВХ строкой XML.
3. **Итерация 3:** агрегированный прогресс (`СообщитьПрогресс`).
4. **Итерация 4:** отмена дочерних заданий при отмене ДО оркестратора, учёт УИД и повторный `НайтиПоУникальномуИдентификатору`, краевые случаи.
5. **Опционально:** финальное согласование верхней границы константы `K` и нагрузочные замеры в эксплуатации.

## Прочее

- Базовая обработка `ФормированиеНачисленийНДФЛ` в выгрузке WIM_FIn может не содержать отдельного файла `ManagerModule.bsl`; в расширении добавляется **расширение модуля менеджера** для экспортов фона.
