Краткий вывод

Исход из замеров (до оптимизации): при массовом расчёте НДФЛ две зоны давали вместе около 38 % времени.

  • Около 22 % — получение оборотов по портфелям (документ начисления по портфелю): повторяющиеся обращения к данным без единого подготовительного шага на всю выборку портфелей.
  • Около 16 % — пакетные запросы в цепочке расчёта по управляющей компании: одни и те же данные по связке клиент — дата запрашивались многократно при разных документах начисления.

Статус реализации в расширении NDFL_RDU (план ниже): пункты 1–5 закрыты, в том числе массовый предрасчёт расходов НКД по клиентам и кэш для участка РасходыПоНКДПоВидуОбращаемости (п. 4). Повторный замер на тех же объёмах данных рекомендуется для подтверждения снижения доли строк 1–2 таблицы.

Задание 1 (приоритет по данным о продажах) — выполнено. Получение движений регистра накопления «Продажи» без длинного условия В(&МассивРегистраторов) на больших списках: список регистраторов передаётся табличным параметром, помещается во временную таблицу, индексируется по регистратору и соединяется с регистром. Аналогичные правки применены к вспомогательным выборкам по продажам в цепочке расчёта по портфелю.

Задание 2 (пустые документы по УК) — выполнено. При программном формировании начисления по управляющей компании после расчёта документ не записывается, если не заполнены табличные части «Начисления», «Удержания» и «Инвестиционный вычет по портфелям»; ситуация фиксируется в сообщении пользователю.

Задание 3 (параллельное формирование и кэш оборотов по портфелям) — выполнено. Пользователь по-прежнему запускает в одной обработке «Формирование начислений НДФЛ» расчёт по табличной части «ДатыДокументов». При включённом режиме параллельности система делит отобранные строки на несколько пачек и обрабатывает их в отдельных фоновых заданиях с той же бизнес-логикой, что и при однопоточном запуске; по завершении результаты сшиваются: единый лог в табличном документе, при успехе — возможность применить снимок данных формы к объекту обработки. Режим отключается константой (число окон 0) или отбором по одному клиенту на форме — тогда выполняется прежний синхронный сценарий. Перед запуском пачек подготавливается общий кэш оборотов по портфелям выборки и передаётся в расчёт портфельного документа, чтобы внутри пачки не выполнять повторно тяжёлый запрос по оборотам для тех же портфелей.

Задание 4 (массовый предрасчёт тяжёлых фрагментов) — выполнено. По портфелю: вместо многократного запроса оборотов по одному портфелю выполняется массовый запрос по всем портфелям текущей выборки, результат раскладывается по портфелям на следующих шагах. По УК: для расходов НКД выполняется предрасчёт по парам (клиент, дата) с группировкой по дате (один пакет запросов на дату по массиву клиентов), результат кэшируется и подставляется при вызовах РасходыПоНКДПоВидуОбращаемости из документа начисления по УК; перехват ИнвестиционныйВычетУКД сводит два вызова к одному с объединённым набором видов обращаемости.

Остальные строки таблицы замеров ожидается снизить за счёт меньшего числа обращений к тем же данным; для подтверждения нужен повторный профиль на прогоне после выката расширения.

План оптимизации

  1. Проблема ТаблицаПродаж (много отдельных обращений к данным) — решено в расширении. Реализация: NDFL_RDU/Documents/НачислениеНДФЛПоУправляющейКомпании/Ext/ManagerModule.bsl, перехват ТаблицаПродаж; для портфеля — NDFL_RDU/Documents/НачислениеНДФЛПоПортфелю/Ext/ObjectModule.bsl (ТаблицаПродажДляРасчетаЛьготПоКлиентамПодСанкциями, ОбщиеОборотыТекстЗапроса). Суть: табличный параметр регистраторов, помещение во временную таблицу, индексация и соединение с регистром вместо повторных мелких обращений.
  2. Запрет записи пустых документов УК — решено в расширении. Реализация: NDFL_RDU/DataProcessors/ФормированиеНачисленийНДФЛ/Ext/ObjectModule.bsl, перехват СоздатьНачислениеНДФЛПоУК. Суть: после расчёта документ не записывается, если пусты Начисления, Удержания и ИнвестиционныйВычетПоПортфелям.
  3. Строка 1 (22,13%) — ОбщиеОбороты в модуле объекта документа Портфеля — решено в расширении. Реализация: NDFL_RDU/Documents/НачислениеНДФЛПоПортфелю/Ext/ObjectModule.bsl (перехват ОбщиеОбороты, подготовка кэша в перехвате СоздатьДокументы обработки). Массовый предрасчёт по массиву портфелей выборки, кэш в разрезе портфеля, ранний возврат из кэша в NDFL_RDU_ОбщиеОбороты без повторного запроса. План: imdev7330_ndfl_mass_precalc_oborots.html.
  4. Строка 2 (16,10%) — РасходыПоНКДПоВидуОбращаемости в модуле менеджера документа УК — решено в расширении. Массовый предрасчёт по парам (Клиент, Дата) выборки: группировка по дате, один пакет запросов на дату по массиву клиентов, заполнение кэша в ПараметрыСеанса.ОбщиеЗначения, перехват РасходыПоНКДПоВидуОбращаемости с ранним возвратом из кэша без копирования таблиц. Подготовка кэша в перехвате СоздатьДокументы обработки ФормированиеНачисленийНДФЛ. Перехват ИнвестиционныйВычетУКД в NDFL_RDU/Documents/НачислениеНДФЛПоУправляющейКомпании/Ext/ManagerModule.bsl: один вызов РасходыПоНКДПоВидуОбращаемости с объединённым набором видов вместо двух последовательных вызовов. Спецификация: imdev7330_ndfl_uk_nkd_mass_precalc_byclient.html.
  5. Распараллеливание расчётов по пачкам — решено в расширении. Реализация: NDFL_RDU/DataProcessors/ФормированиеНачисленийНДФЛ/Ext/ManagerModule.bsl (оркестратор пачек), перехват СоздатьДокументы в ObjectModule.bsl. Число пачек: константа NDFL_RDU_ЧислоПараллельныхПачекФормированияНДФЛ. Запуск пачек: ДлительныеОперации.ВыполнитьВФоне с процедурой ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки (метод объекта NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ). План: imdev7330_ndfl_parallel_calculation.html.
