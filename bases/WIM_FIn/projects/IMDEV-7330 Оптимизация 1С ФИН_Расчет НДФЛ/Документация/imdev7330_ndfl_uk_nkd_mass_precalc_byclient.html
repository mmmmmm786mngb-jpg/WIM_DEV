1. Цель и идея

Сейчас РасходыПоНКДПоВидуОбращаемости в Документ.НачислениеНДФЛПоУправляющейКомпании.МодульМенеджера выполняется один пакетный запрос (4 временные таблицы, агрегации ПоПартиям / ПоРегистраторам) для каждой связки (Клиент, Дата), причём:

  • В типовой конфигурации функция вызывалась дважды в ИнвестиционныйВычетУКД(Клиент, Дата) — по обращающимся и необращающимся видам ЦБ, после чего таблицы сливались.
  • В расширении NDFL_RDU уже сделано: перехват &Вместо("ИнвестиционныйВычетУКД") собирает один объединённый массив видов и вызывает РасходыПоНКДПоВидуОбращаемости один раз на пару (Клиент, Дата) вместо двух.
  • Тем не менее ИнвестиционныйВычетУКД(Клиент, Дата) (а значит и РасходыПоНКДПоВидуОбращаемости) повторно вызывается из:
    • Документ.НачислениеНДФЛПоПортфелю.МодульМенеджера.НачисленияПоПортфелям (через Документы.НачислениеНДФЛПоУправляющейКомпании.РезультатРасчетаИнвестиционногоВычета) — на каждом расчёте начисления по портфелю клиента;
    • Документ.НачислениеНДФЛПоУправляющейКомпании.МодульОбъекта — на расчёте начисления УК того же клиента.

Запрос на 3069 параметризуется по одному &Клиент и периоду НачалоГода(Дата) … КонецДня(Дата). Для одной и той же пары (Клиент, Дата) результат одинаков в любом числе вызовов в рамках одного сеанса формирования. Замер дал 194 вызова — то есть запрос выполняется кратно числу пар (Клиент, ДокументНачисления, Дата) в выборке.

Идея оптимизации: один раз перед основным циклом ФормированиеНачисленийНДФЛ.СоздатьДокументы собрать массив уникальных пар (Клиент, Дата), выполнить один массовый пакетный запрос (с Портфель.Клиент В (&МассивКлиентов) и группировкой по полю Клиент), разложить результат в кэш (Клиент, Дата) → (ПоПартиям, ПоРегистраторам), а затем в реальных циклах по портфелям и УК кэш подключается перед РассчитатьНДФЛ() через NDFL_RDU_УстановитьВнешнийКэшНКДРасходов. В перехвате &Вместо("РасходыПоНКДПоВидуОбращаемости") модуля менеджера УК при наличии записи в кэше возвращать готовую структуру до выполнения тяжёлого пакета (без копирования таблиц).

Архитектурно это тот же приём, что в плане imdev7330_ndfl_mass_precalc_oborots.html (массовый ОбщиеОбороты по массиву портфелей), но применённый к точке «Клиент × Дата» в модуле менеджера документа УК. Подход согласован с планом по массовым оборотам по портфелям (отдельная ветка кода).

3. API предрасчёта и передача кэша в расчёт УК

Реализованы два согласованных элемента: подготовка кэша в модуле менеджера документа УК и включение кэша на время расчёта без изменения сигнатуры типовой РассчитатьНДФЛ().

  • A — подготовка кэша: экспортная функция модуля менеджера документа УК NDFL_RDU_ПолучитьРасходыПоНКДПоКлиентам(МассивПарКлиентДата). Вызывается из обработки ФормированиеНачисленийНДФЛ один раз перед основным циклом (при числе пар не меньше порога).
  • B — использование кэша при расчёте: обработка перед вызовом НачислениеНДФЛПоУК.РассчитатьНДФЛ() вызывает Документы.НачислениеНДФЛПоУправляющейКомпании.NDFL_RDU_УстановитьВнешнийКэшНКДРасходов(СоответствиеКэша). Перехват &Вместо("РассчитатьНДФЛ") в модуле объекта документа УК только сбрасывает кэш после ПродолжитьВызов и при ошибке; параметров у процедуры нет.

3.2. Метод NDFL_RDU_ПолучитьРасходыПоНКДПоКлиентам (подготовка кэша)

Параметры и возвращаемое значение

Имя Тип Назначение
МассивПарКлиентДата (вход) Массив структур Клиент, Дата Пары для расчёта. Дубли по одному клиенту и дате при сборе в обработке отсекаются по ключу NDFL_RDU_КлючКэшаНКД; внутри функции пары группируются по дате (NDFL_RDU_РазложитьПарыПоДате).

Виды обращаемости в кэше. Массовый запрос и NDFL_RDU_ИнвестиционныйВычетУКД используют один и тот же набор видов: NDFL_RDU_ВидыОбращаемостиДляМассовогоКэшаНКДУК() (объединение Перечисления.ВидыОбращаемостиЦБ.ОбращающиесяВиды() и НеОбращающиесяВиды()). Значения перечисления вне этой пары (например, СделкаРЕПО) в кэш не попадают — как при прежних двух вызовах в инвествычете. Агрегация по допустимым видам — в финальных блоках запроса; перехват при попадании в кэш возвращает готовую структуру (Возврат ПоКД, см. п. 4.5).

Где вызывается

  • Из обработки ФормированиеНачисленийНДФЛ, процедура NDFL_RDU_ИнициализироватьКэшНКДПоМассивуПар, которая вызывается из NDFL_RDU_СоздатьДокументы после NDFL_RDU_СобратьПарыКлиентДатаДляПредрасчетаНКД, если число пар не меньше 2 (локальная константа порога в процедуре инициализации).
  • Результат хранится в модульной переменной обработки NDFL_RDU_СтруктураКэшНКД. Перед каждым РассчитатьНДФЛ() по УК обработка вызывает NDFL_RDU_УстановитьВнешнийКэшНКДРасходов и передаёт всё соответствие; перехват РасходыПоНКДПоВидуОбращаемости сам выбирает запись по NDFL_RDU_КлючКэшаНКД(Клиент, Дата).

4. Реализация по объектам и файлам

4.1. Обработка ФормированиеНачисленийНДФЛ — сбор пар (Клиент, Дата)

Файл: NDFL_RDU\DataProcessors\ФормированиеНачисленийНДФЛ\Ext\ObjectModule.bsl.

Функция: NDFL_RDU_СобратьПарыКлиентДатаДляПредрасчетаНКД — те же отборы по номеру строки и флагу «не создавать по клиентам без ЦБ», что и для пар Клиент/УК; уникальность по ключу Документы.НачислениеНДФЛПоУправляющейКомпании.NDFL_RDU_КлючКэшаНКД(Клиент, Дата); в структуру пары попадает СтрокаДокументов.Дата (без принудительного КонецДня в поле — нормализация в ключе внутри NDFL_RDU_КлючКэшаНКД).

4.2. Обработка — инициализация кэша НКД

Процедура: NDFL_RDU_ИнициализироватьКэшНКДПоМассивуПар(МассивПарКлиентДата). Порог массового предрасчёта зашит в процедуре: 2 пары. При меньшем числе пар NDFL_RDU_СтруктураКэшНКД остаётся Неопределено, иначе вызывается Документы.НачислениеНДФЛПоУправляющейКомпании.NDFL_RDU_ПолучитьРасходыПоНКДПоКлиентам(...) и результат записывается в NDFL_RDU_СтруктураКэшНКД.

4.3. Обработка — перехват NDFL_RDU_СоздатьНачислениеНДФЛПоУК

Параметр «кэш» в сигнатуру типовой процедуры не добавлялся. Перед РассчитатьНДФЛ() при непустом NDFL_RDU_СтруктураКэшНКД вызывается МенеджерНачисленияУК.NDFL_RDU_УстановитьВнешнийКэшНКДРасходов(NDFL_RDU_СтруктураКэшНКД), затем типовой РассчитатьНДФЛ() без аргументов. После успешного расчёта и в Исключение выполняется сброс NDFL_RDU_УстановитьВнешнийКэшНКДРасходов(Неопределено) (дополнительный сброс в перехвате модуля объекта УК — см. п. 3.1 и п. 4.6).

Ветка СоздатьНачислениеНДФЛПоПортфелю описана в материале по оборотам; здесь только УК.

5. Сценарии и обратная совместимость

Сценарий A. Один документ, форма «Рассчитать»

Пользователь открыл НачислениеНДФЛПоУправляющейКомпании и нажал «Рассчитать НДФЛ».
поведение РассчитатьНДФЛ() вызывается без параметров → защёлка кэша остаётся Неопределено → перехват РасходыПоНКДПоВидуОбращаемости идёт по ПродолжитьВызов(). Поведение не меняется.

Сценарий B. Обработка с одной парой (Клиент, Дата)

поведение При МассивПарКлиентДата.Количество() < 2 предрасчёт НКД не выполняется: NDFL_RDU_СтруктураКэшНКД остаётся Неопределено, расчёт идёт типовым путём. Порог 2 совпадает с порогом предрасчёта оборотов по парам Клиент/УК в NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар.

Сценарий C. Большая выборка (продакшн)

главный сценарий Сотни клиентов, сотни документов. Один пакет на дату, в кэше — все клиенты этой даты. Дальше при попадании в кэш — выборка из соответствия в памяти без повторного пакетного запроса РасходыПоНКДПоВидуОбращаемости. Главный выигрыш по времени.

Сценарий D. Внешние вызовы РассчитатьНДФЛ() (обмен и пр.)

поведение Если обработка не вызывала NDFL_RDU_УстановитьВнешнийКэшНКДРасходов с непустым соответствием, перехват РасходыПоНКДПоВидуОбращаемости идёт по ПродолжитьВызов. Обратная совместимость: ускорение включается только в контуре NDFL_RDU_СоздатьДокументы при числе пар не меньше порога.

5 Изоляция защёлки кэша. Параллельно запустить два сеанса обработки (фон + интерактив). При живой защёлке через повторное использование на сеанс кэши не пересекаются. Каждый сеанс работает в своём кэше; гонок нет.
6 Производительность. Замер общего времени СоздатьДокументы и числа выполнений ОбщегоНазначенияДУ.ДобавитьВЛогОтладки(..., "НачислениеНДФЛПоУправляющейКомпании.РасходыПоНКДПоВидуОбращаемости") до и после оптимизации. Снижение общего времени; число попаданий в логе сократилось до количества уникальных (Клиент, Дата); точка Документ.НачислениеНДФЛПоУправляющейКомпании.МодульМенеджера, 3069 покинула топ замера.
7 Граничные условия. Пустая выборка ДатыДокументов; один клиент без портфелей; смешанные даты в одной обработке. Обработка не падает; идёт по старому пути; кэш не используется.

7. Риски, ограничения, открытые вопросы

  • Память кэша. Расходы НКД для большой выборки клиентов могут давать заметный объём строк. Решение: формировать кэш помесячно или по клиенту в случае превышения порога; альтернатива — выгружать ПоПартиям и ПоРегистраторам только в момент обращения к паре (ленивая подгрузка).
  • Согласованность периода. Типовая РасходыПоНКДПоВидуОбращаемости использует НачалоГода(Дата) и КонецДня(Дата). Это однозначно вычисляется по дате документа; строковый ключ в соответствии строится в NDFL_RDU_КлючКэшаНКД с нормализацией даты через КонецДня. Дата документа Портфеля и Дата документа УК на одном дне совпадают (см. цепочку через СтрокаДокументов.Дата). Если в обработке появятся разные даты в одной строке выборки — поведение должно остаться корректным за счёт ключа в кэше.
  • Виды обращаемости. В перечислении есть значения вне пары обращающиеся / необращающиеся (например, СделкаРЕПО). Они намеренно не входят в NDFL_RDU_ВидыОбращаемостиДляМассовогоКэшаНКДУК и в NDFL_RDU_ИнвестиционныйВычетУКД. В пакетном запросе в SQL действует отбор ВидыОбращаемостиЦБ В (&ВидыОбращаемости) с этим набором; итоговые суммы по допустимым видам — в SQL. Перехват при кэше возвращает готовую структуру без доработки на 1С (Возврат ПоКД).
  • Расширение VTB_NDFL_Exchange. В нём нет перехвата РасходыПоНКДПоВидуОбращаемости (только модули обмена), конфликта по &Вместо не будет. Тем не менее перед внедрением — формальная проверка Расширения/VTB_NDFL_Exchange/Documents/НачислениеНДФЛПоУправляющейКомпании/Ext/ObjectModule.bsl на отсутствие соприкосновений.
  • Защёлка vs модульная переменная. В модуле менеджера нет Перем. Использование хранения в ПараметрыСеанса.ОбщиеЗначения даёт хранение на время серверного вызова в сеансе. Ключевое требование — явная очистка: в перехвате РассчитатьНДФЛ (модуль объекта УК) и в NDFL_RDU_СоздатьНачислениеНДФЛПоУК после расчёта и при ошибке.
  • Срез по ЗначенияПараметровПортфеля внутри запроса привязан к КонецПериода = КонецДня(Дата). На массиве клиентов это всё ещё один срез на дату (через виртуальную таблицу), поэтому SQL получает один проход — как и в типовом варианте.
