IMDEV-7330: промпт на доработку (массовый предрасчет РасходыПоНКДПоВидуОбращаемости, документ УК)

Задача: сократить число тяжелых пакетных запросов в Документ.НачислениеНДФЛПоУправляющейКомпании.МодульМенеджера в функции РасходыПоНКДПоВидуОбращаемости при массовом формировании через обработку ФормированиеНачисленийНДФЛ.
База: WIM_FIn. Расширение: NDFL_RDU.
Полный план: imdev7330_ndfl_uk_nkd_mass_precalc_byclient.html

1. Область работ (IN)

  • Обработка ФормированиеНачисленийНДФЛ (модуль объекта, расширение NDFL_RDU): до цикла по ДатыДокументов собрать уникальные пары (Клиент, Дата), при пороге выборки вызвать один массовый предрасчет.
  • Документ.НачислениеНДФЛПоУправляющейКомпании в NDFL_RDU: экспортный метод предрасчета по массиву пар; перехват &Вместо("РасходыПоНКДПоВидуОбращаемости") с коротким замыканием по внешнему кэшу; защелка кэша между перехватом РассчитатьНДФЛ (объект) и перехватом РасходыПоНКДПоВидуОбращаемости (менеджер) через уже используемый в базе механизм ПараметрыСеанса.ОбщиеЗначения с уникальным ключом и обязательной очисткой в Попытка / после вызова.
  • Перехват &Вместо("РассчитатьНДФЛ") модуля объекта УК: опциональный параметр со структурой кэша; проброс в защелку на время расчета.
  • Согласовать с уже реализованным кэшем оборотов (план imdev7330_ndfl_mass_precalc_oborots.html): один проход по ДатыДокументов для сбора пар и портфелей, где уместно.

2. Вне области (OUT)

  • Справка-расчет и менеджер портфеля ветка ОбщаяСправкаРасчет2021 и вызовы Документы.НачислениеНДФЛПоУправляющейКомпании.РезультатРасчетаИнвестиционногоВычета из этой справки не менять и не включать в оптимизацию: справка считается по-старому.
  • Локальный расчет НКД в модуле объекта НачислениеНДФЛПоПортфелю (РасходыПоНКДПоВидуОбращаемости по портфелю) не подменять кэшем УК - это другой код и другой отбор.
  • Типовую конфигурацию не править; только расширение и уже перехватываемые объекты в NDFL_RDU.

3. Что правится по файлам (конкретика)

NDFL_RDU/.../ФормированиеНачисленийНДФЛ/Ext/ObjectModule.bsl

  • Точка входа перехвата NDFL_RDU_СоздатьДокументы (или уже выделенный блок подготовки перед типовым циклом): добавить сбор уникальных пар (Клиент, Дата) по ДатыДокументов с теми же отборами, что и для создаваемых документов (номер строки, клиенты с ЦБ и т.д., как в полном плане).
  • После сбора: при Количество() >= ПорогМассовогоПредрасчёта один вызов Документы.НачислениеНДФЛПоУправляющейКомпании.NDFL_RDU_ПолучитьРасходыПоНКДПоКлиентам(МассивПарКлиентДата), иначе переменная кэша НКД остаётся Неопределено.
  • Расширить сигнатуру и тело NDFL_RDU_СоздатьНачислениеНДФЛПоУК: принять опционально структуру/соответствие кэша НКД; при непустом кэше вызывать НачислениеНДФЛПоУК.РассчитатьНДФЛ(ПарамВнешн) с ключом целого кэша (как в плане), при пустом — без параметров как сейчас.
  • Согласовать с блоком кэша оборотов: один проход по ДатыДокументов для массива пар клиент/дата и для данных оборотов, если оба предрасчёта включены.
  • Параллельный режим (NDFL_RDU_ВыполнитьПачкуФормированияНДФЛ): при необходимости передавать в параметры пачки уже посчитанный срез кэша НКД по клиентам строк пачки либо вызывать предрасчёт в оркестраторе один раз на полный снимок — см. imdev7330_parallel_ndfl_dev_prompt.html.

  • Новая область/функции: составной ключ NDFL_RDU_КлючКэшаНКД(Клиент, Дата), разложение пар по дате, выборка строк по клиенту из общей ТЗ, массовый пакет по образцу типовой РасходыПоНКДПоВидуОбращаемости с заменой отбора на В(&МассивКлиентов) и колонкой Клиент в цепочке ВТ и итогах.

  • Перехват &Вместо("РасходыПоНКДПоВидуОбращаемости"): если защелка не пуста и есть данные по ключу (Клиент, КонецДня(Дата)) — вернуть результат фильтрации по видам на 1С; иначе ПродолжитьВызов().

  • Добавить перехват &Вместо("РассчитатьНДФЛ") с необязательным параметром ПараметрыРасчетаВнешн: перед ПродолжитьВызов() выставить защелку кэша НКД из структуры (целое соответствие по выборке), в Попытка после вызова и в Исключение — сброс защелки в Неопределено.
  • Если перехват РассчитатьНДФЛ уже есть под обороты — расширить ту же процедуру одним контрактом структуры (отдельные ключи для кэша оборотов и НКД), не плодить второй &Вместо на тот же метод.

Что не создаём и не трогаем

  • Новые объекты метаданных (общие модули, константы под ключ кэша) — только по необходимости; базовый вариант без новых объектов.
  • Типовые модули WIM_FIn, модуль объекта/менеджера НачислениеНДФЛПоПортфелю, код справки ОбщаяСправкаРасчет2021 — без изменений.

4. Технические правила

  • Массовый запрос: Портфель.Клиент В (&МассивКлиентов), период НачалоГода(Дата) ... КонецДня(Дата) группировать по датам (один пакет на дату на набор клиентов).
  • В SQL убрать фильтр по видам обращаемости из финальных блоков; отбор по ВидыОбращаемости выполнять на 1С при коротком замыкании (совместимо с NDFL_RDU_ИнвестиционныйВычетУКД).
  • После пакета учесть константу РасходыОтУКДУменьшаютДоходы (инверсия сумм) как в типовой функции.
  • Порог ПорогМассовогоПредрасчёта согласовать с оборотами (например одно значение в коде инициализации обработки).
  • Проверить отсутствие конфликта &Вместо с другими расширениями (например VTB_NDFL_Exchange) по документу УК.

5. Критерий готовности

  • Повторный запуск формирования с включенным / выключенным кэшем: идентичные суммы и строки в расшифровке инвестиционного вычета УК (сверка на тестовой базе).
  • Вызов РассчитатьНДФЛ() без параметров из формы и внешних сценариев - поведение как до доработки.
  • Замер: снижение числа попаданий в точку менеджера УК с пакетным запросом НКД при массовой обработке; зафиксировать в отчете тестирования.
