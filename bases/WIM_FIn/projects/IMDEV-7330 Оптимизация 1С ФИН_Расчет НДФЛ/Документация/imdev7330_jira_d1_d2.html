IMDEV-7330 — замечания по внедрению NDFL_RDU в 1Cv8_fin 2.8.7.3

Проверили перенос кода из расширения NDFL_RDU в базовую конфигурацию. Ниже два дефекта, которые просим исправить.

Д-1. Неснятый префикс NDFL_RDU_ в форме отмены проведения [критично]

Файл:
DataProcessors/ОтменаПроведенияНачисленийНДФЛ/Forms/Форма/Ext/Form/Module.bsl

Суть: префикс NDFL_RDU_ снят из объявлений методов, но остался в трёх обращениях к ним. Методов с таким именем в базовой конфигурации нет — сценарий «Отмена проведения начислений НДФЛ» не запускается.

СтрокаСейчас (ошибка)Должно быть
127 Обработки.ФормированиеНачисленийНДФЛ.NDFL_RDU_ДанныеВXML(...) Обработки.ФормированиеНачисленийНДФЛ.ДанныеВXML(...)
136 "Обработки.ОтменаПроведенияНачисленийНДФЛ.NDFL_RDU_ОркестраторОтменыПроведенияНачисленийНДФЛ" "Обработки.ОтменаПроведенияНачисленийНДФЛ.ОркестраторОтменыПроведенияНачисленийНДФЛ"
194 Обработки.ФормированиеНачисленийНДФЛ.NDFL_RDU_ДанныеИзXML(...) Обработки.ФормированиеНачисленийНДФЛ.ДанныеИзXML(...)

Последствия:

  • стр. 127 — сразу при нажатии команды: «Метод объекта не обнаружен (NDFL_RDU_ДанныеВXML)»;
  • стр. 136 — БСП не найдёт процедуру для ДлительныеОперации.ВыполнитьВФоне;
  • стр. 194 — итог фонового задания не разберётся из XML.

Исправление: удалить NDFL_RDU_ в строках 127, 136, 194.

Строку 131 (КлючФоновогоЗадания = "NDFL_RDU_ОтменаПров_" + ...) можно не трогать — это произвольный ключ задания, на работоспособность не влияет.

Проверка: открыть обработку «Отмена проведения начислений НДФЛ», запустить на дате с проведёнными начислениями — фоновое задание должно стартовать без ошибки «метод не обнаружен».

Д-2. Сброс сеансового кэша НКД обходится ранними Возврат [средний]

Файл:
Documents/НачислениеНДФЛПоУправляющейКомпании/Ext/ObjectModule.bsl
процедура РассчитатьНДФЛ()

Суть: в расширении перехват &Вместо("РассчитатьНДФЛ") гарантировал сброс внешнего кэша НКД через Попытка / Исключение / КонецПопытки после ПродолжитьВызов() — сброс выполнялся всегда, в том числе при раннем выходе и при исключении.

В базовой конфигурации сброс стоит только в конце процедуры (стр. ~85):

Документы.НачислениеНДФЛПоУправляющейКомпании.УстановитьВнешнийКэшНКДРасходов(Неопределено);

Два ранних Возврат этот сброс обходят:

  • стр. ~32 — Если Не ПроверитьЗаполнениеУКИКлиента() Тогда Возврат;
  • стр. ~44 — Если СписокПортфелей.Количество() = 0 Тогда ... Возврат;

Кэш живёт в ПараметрыСеанса.ОбщиеЗначения и может остаться «залипшим» до конца сеанса. В основном сценарии массового формирования вызывающая сторона обычно сбрасывает кэш сама, но при прямом вызове РассчитатьНДФЛ() (форма документа / ручной расчёт) контракт расширения нарушен.

Рекомендуемое исправление — перед каждым ранним Возврат (стр. 32 и 44) добавить сброс кэша:

Если Не ПроверитьЗаполнениеУКИКлиента() Тогда
    Документы.НачислениеНДФЛПоУправляющейКомпании.УстановитьВнешнийКэшНКДРасходов(Неопределено);
    Возврат;
КонецЕсли;

// ...

Если СписокПортфелей.Количество() = 0 Тогда
    ОбщегоНазначенияКлиентСервер.СообщитьПользователю("Не найдены портфели для расчета");
    Документы.НачислениеНДФЛПоУправляющейКомпании.УстановитьВнешнийКэшНКДРасходов(Неопределено);
    Возврат;
КонецЕсли;

Финальный сброс в конце процедуры (стр. ~85) оставить как есть.

Проверка: вызвать расчёт документа по УК с незаполненным клиентом (сработает ранний Возврат), затем сразу рассчитать другой документ по тому же клиенту/дате — суммы расходов НКД должны совпадать с расчётом «с нуля».

Конфигурация: 1Cv8_fin_2_8_7_3. Оба дефекта относятся к переносу кода из расширения NDFL_RDU (задача IMDEV-7330).
