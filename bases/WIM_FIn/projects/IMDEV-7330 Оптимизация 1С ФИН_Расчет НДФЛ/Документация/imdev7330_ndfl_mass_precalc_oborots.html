1. Цель и идея

Сейчас обработка ФормированиеНачисленийНДФЛ.СоздатьДокументы для каждой строки ДатыДокументов (то есть для каждого клиента/УК/даты) вызывает СоздатьНачислениеНДФЛПоПортфелю, внутри которой в цикле по портфелям клиента запускается полный РассчитатьНДФЛ(). На каждом портфеле выполняется тяжёлая функция ПараметрыРасчета(), в которую входят, в частности, ОбщиеОбороты(ПараметрыРасчета) и ОбщиеОбороты(ПараметрыРасчета, Истина).

В расширении NDFL_RDU функция NDFL_RDU_ОбщиеОбороты уже доработана: она поддерживает ПараметрыРасчета.Портфели (массив ссылок) и возвращает таблицу с колонкой Портфель. Это значит, что один пакетный запрос может за раз обработать обороты по любому числу портфелей.

Идея оптимизации: один раз перед основным циклом обработки собрать массив всех портфелей по всем клиентам выборки, выполнить NDFL_RDU_ОбщиеОбороты два раза (текущий и прошлый период) на этом массиве, разложить результат в кэш Портфель → ТаблицаОборотов, а в реальном цикле по клиенту/портфелю передать в РассчитатьНДФЛ(ПараметрыРасчетаВнешн) готовые таблицы по текущему портфелю. В момент, когда типовая ПараметрыРасчета() попытается вызвать ОбщиеОбороты(...), перехват NDFL_RDU_ОбщиеОбороты вернёт таблицу из кэша до выполнения тяжёлого запроса.

2.3. Что из этого следует

После доработки NDFL_RDU_ОбщиеОбороты с массивом портфелей у нас уже есть всё необходимое для одного «массового» прохода. Не хватает оркестратора в обработке и точки приёма заранее посчитанного результата в РассчитатьНДФЛ.

3. Контракты нового API

В финальной архитектуре расширение NDFL_RDU предоставляет два независимых публичных контракта:

  • Контракт A — подготовка кэша: новый экспортный метод документа NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям(МассивПортфелей). Используется обработкой один раз перед основным циклом, возвращает кэш оборотов в разрезе портфелей.
  • Контракт B — приём готового кэша: в РассчитатьНДФЛ добавляется опциональный параметр ПараметрыРасчета, через который обработка передаёт уже посчитанные таблицы оборотов по текущему портфелю.

Такое разделение даёт чистую семантику: имя «расчёт НДФЛ» больше не перегружено техническим режимом «подготовь кэш и выйди», а перехват &Вместо("РассчитатьНДФЛ") делает ровно одну вещь — пробрасывает внешний кэш в ПараметрыРасчета() и зовёт ПродолжитьВызов().

4.7. Документ НачислениеНДФЛПоПортфелю (NDFL_RDU) — перехват РассчитатьНДФЛ (приём внешнего кэша)

После этого типовая ПараметрыРасчета() штатно кладёт результат в свою структуру — никакой подмены не нужно.

Изначально рассматривался второй перехват &Вместо("ПараметрыРасчета") с пост-подменой ключей; от него отказались по причине выше. Если в будущем понадобится «обогатить» ПараметрыРасчета чем-то ещё (не оборотами), такой перехват можно добавить отдельно — текущий план его не требует.

5. Сценарии и обратная совместимость

Сценарий A. Один портфель, одна дата (форма документа)

Пользователь открыл НачислениеНДФЛПоПортфелю и нажал «Рассчитать НДФЛ» на форме.
поведение РассчитатьНДФЛ() вызывается без параметров → NDFL_RDU_ВнешнийКэшОборотов остаётся Неопределено → ветка короткого замыкания не срабатывает → выполняется обычный запрос ОбщиеОбороты по одному портфелю. Поведение не меняется.

Сценарий B. Обработка с одним клиентом и одним портфелем

поведение Кэш всё равно собирается, но содержит одну строку на портфель. Запрос NDFL_RDU_ОбщиеОбороты отрабатывает на одном портфеле — это даже немного дороже чем «одиночный» вызов из-за двух обходов (текущий + прошлый год) до основного цикла. Чтобы не штрафовать малую выборку, добавляем порог: Если МассивПортфелей.Количество() < ПорогМассовогоПредрасчёта Тогда СтруктураКэшОборотов = Неопределено КонецЕсли; (по умолчанию, скажем, 5).

Сценарий C. Большая выборка (продакшн)

главный сценарий Сотни/тысячи портфелей. Один раз NDFL_RDU_ОбщиеОбороты на массив, дальше в цикле O(1) на портфель — из кэша. Главный выигрыш по времени.

Сценарий D. Внешний обмен / другие места вызова РассчитатьНДФЛ()

поведение Все они вызывают без параметров → старый путь. Гарантия обратной совместимости: новая логика срабатывает только при явной передаче внешнего кэша обработкой.

7. Риски, ограничения, открытые вопросы

  • Память. Большой кэш на тысячи портфелей и обороты за два периода может занять десятки/сотни МБ. Снизить риск: выгружать таблицы в кэш по мере обхода (генератор-стиль) либо ставить верхний порог МаксПортфелейДляМассовогоПредрасчёта (например, 2000) и выше него работать по-старому.
  • Согласованность периодов. Типовая ОбщиеОбороты в одиночном режиме берёт КонецПериода = МоментВремени() — это «момент текущего объекта документа». При массовом предрасчёте в техническом документе МоментВремени() относится к этому техническому несохранённому объекту. Нужно передавать дату явно: добавить в NDFL_RDU_ОбщиеОбороты приём опционального ключа ПараметрыРасчета.КонецПериодаЯвно, иначе при перетекании дат документов на разные даты получим расхождения.
  • Поле МинимальнаяДатаДокументов в типовой ОбщиеОбороты используется как НачалоПериода в текущем периоде. Оно вычисляется внутри СписокДокументовДляРасчетаДоходовРасходов и привязано к конкретному документу (его НачалоГода(Дата), дате документа). При массовом предрасчёте нужно выбрать «самую раннюю» МинимальнаяДатаДокументов по всем портфелям — иначе мы можем обрезать выборку в кэше. требует уточнения
  • Параметры по портфелю. РасчетСуммыНДФЛВыполнятьПоСуммамНалоговогоУчета, СписокДокументовДляРасчетаДоходовРасходов, ТаблицаПродажДляРасчетаЛьготПоКлиентамПодСанкциями в текущем NDFL_RDU_ОбщиеОбороты уже принимают значения по массиву портфелей (с колонкой Портфель). Это нужно проверить «end-to-end» именно в массовом режиме.
  • Совместимость с расширением VTB_NDFL_Exchange. В нём перехвачена другая функция (РасходыПоНКДПоВидуОбращаемости). Текущий план её не затрагивает; конфликта по &Вместо нет.

8. Выводы и порядок реализации

  1. Шаг 1 (документ, NDFL_RDU). Добавить NDFL_RDU_РазложитьТаблицуОборотовПоПортфелю и NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям. Юнит-тестировать на 3 портфелях.
  2. Шаг 2 (документ, NDFL_RDU). Добавить модульную переменную NDFL_RDU_ВнешнийКэшОборотов, перехват РассчитатьНДФЛ и короткое замыкание внутри NDFL_RDU_ОбщиеОбороты. Проверить сценарий A (один портфель, форма).
  3. Шаг 3 (обработка). Сбор МассивПарКлиентУК и МассивПортфелей перед основным циклом; вызов NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям; проброс СтруктураКэшОборотов в СоздатьНачислениеНДФЛПоПортфелю.
  4. Шаг 4. Включить порог ПорогМассовогоПредрасчёта (по умолчанию 5). Проверить сценарии B, C, D из раздела 5.
  5. Шаг 5. Прогон сравнительного теста (раздел 6, № 1) на тестовой базе WIM_FIn. Снять метрики времени и числа обращений к Хозрасчетному (раздел 6, № 5).
  6. Шаг 6. Документировать результат в Тестирование/reports/imdev7330_mass_precalc_report.html и обновить Документация/index.md.
Главное преимущество: архитектура остаётся «расширенческой» — NDFL_RDU добавляет два независимых публичных контракта:
  • Контракт A — новый экспортный метод документа NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям (вызывает обработка для подготовки кэша);
  • Контракт B — единственный новый опциональный параметр у РассчитатьНДФЛ (обработка передаёт готовые таблицы по текущему портфелю).
Плюс одна модульная переменная NDFL_RDU_ВнешнийКэшОборотов для проброса значения из перехвата РассчитатьНДФЛ в перехват ОбщиеОбороты. Любой текущий вызов РассчитатьНДФЛ() в системе по-прежнему работает один-в-один как до доработки.
