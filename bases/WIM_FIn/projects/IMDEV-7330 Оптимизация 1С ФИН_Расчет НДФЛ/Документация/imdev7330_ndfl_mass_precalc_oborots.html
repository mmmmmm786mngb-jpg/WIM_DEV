1. Цель и идея

Сейчас обработка ФормированиеНачисленийНДФЛ.СоздатьДокументы для каждой строки ДатыДокументов (то есть для каждого клиента/УК/даты) вызывает СоздатьНачислениеНДФЛПоПортфелю, внутри которой в цикле по портфелям клиента запускается полный РассчитатьНДФЛ(). На каждом портфеле выполняется тяжёлая функция ПараметрыРасчета(), в которую входят, в частности, ОбщиеОбороты(ПараметрыРасчета) и ОбщиеОбороты(ПараметрыРасчета, Истина).

В расширении NDFL_RDU функция NDFL_RDU_ОбщиеОбороты уже доработана: она поддерживает ПараметрыРасчета.Портфели (массив ссылок) и возвращает таблицу с колонкой Портфель. Это значит, что один пакетный запрос может за раз обработать обороты по любому числу портфелей.

Идея оптимизации: один раз перед основным циклом обработки собрать массив всех портфелей по всем клиентам выборки, выполнить NDFL_RDU_ОбщиеОбороты два раза (текущий и прошлый период) на этом массиве, разложить результат в кэш Портфель → ТаблицаОборотов, а в реальном цикле по клиенту/портфелю передать в РассчитатьНДФЛ(ПараметрыРасчетаВнешн) готовые таблицы по текущему портфелю. В момент, когда типовая ПараметрыРасчета() попытается вызвать ОбщиеОбороты(...), перехват NDFL_RDU_ОбщиеОбороты вернёт таблицу из кэша до выполнения тяжёлого запроса.

3. Контракты нового API

В финальной архитектуре расширение NDFL_RDU предоставляет два независимых публичных контракта:

  • Контракт A — подготовка кэша: новый экспортный метод документа NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям(МассивПортфелей). Используется обработкой один раз перед основным циклом, возвращает кэш оборотов в разрезе портфелей.
  • Контракт B — приём готового кэша: перехват РассчитатьНДФЛ с опциональным параметром ПараметрыРасчетаВнешн (NDFL_RDU_РассчитатьНДФЛ), через который обработка передаёт структуру с таблицами оборотов по текущему портфелю.

Перехват NDFL_RDU_РассчитатьНДФЛ не подменяет типовую ПараметрыРасчета(): он только выставляет модульную переменную NDFL_RDU_ВнешнийКэшОборотов и вызывает ПродолжитьВызов(). Короткое замыкание выполняется в NDFL_RDU_ОбщиеОбороты до тяжёлого запроса (см. п. 4.8).

4. Точки вставки кода

4.1. Обработка — уникальные пары Клиент / УК для предрасчёта

Факт в NDFL_RDU: функция NDFL_RDU_СобратьПарыКлиентУКСУчетомОтборовДокументов (модуль объекта обработки). Вызывается из NDFL_RDU_СоздатьДокументы до ПродолжитьВызов.

Отборы: те же, что у типового обхода ТЧ «ДатыДокументов»: диапазон НомерСтрокиС / НомерСтрокиПо, флаг «не создавать по клиентам без ЦБ» и список клиентов с ЦБ. Уникальность — по паре Клиент + УправляющаяКомпания (в ключе соответствия нет даты строки: набор портфелей для кэша — суперсет по клиенту и УК для всей выборки, даты документов в цикле остаются типовыми).

Результат: массив структур с полями Клиент, УправляющаяКомпания.

// Упрощённо: фрагмент логики из NDFL_RDU_СобратьПарыКлиентУКСУчетомОтборовДокументов
Ключ = Строка(СтрокаДокументов.Клиент.УникальныйИдентификатор())
    + "|" + Строка(СтрокаДокументов.УправляющаяКомпания.УникальныйИдентификатор());
Пара = Новый Структура("Клиент, УправляющаяКомпания");
Пара.Клиент = СтрокаДокументов.Клиент;
Пара.УправляющаяКомпания = СтрокаДокументов.УправляющаяКомпания;

4.2. Обработка — NDFL_RDU_СписокПортфелейПоКлиентам

Факт: функция объявлена с префиксом расширения и вызывается только из NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар. Типовая СписокПортфелей(СтрокаДокументов) в основном цикле не заменяется.

В табличный параметр запроса &Пары попадают только две колонки: Клиент, УправляющаяКомпания — без даты строки документов.

Суперсет: часть отборов из типовой СписокПортфелей здесь может не участвовать; это сознательно: шире кэш, уже сужает фактический цикл по-прежнему СписокПортфелей(СтрокаДокументов).

4.3. Обработка — NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар

Порог: локальная константа ПорогМассовогоПредрасчета = 2 сравнивается с числом пар МассивПарКлиентУК, а не с количеством портфелей. При меньшем значении кэш не строится.

Шаги: получить МассивПортфелей = NDFL_RDU_СписокПортфелейПоКлиентам(...); если пусто — выход; создать в памяти объект Документы.НачислениеНДФЛПоПортфелю.СоздатьДокумент(), установить Портфель = МассивПортфелей[0] (не пустая ссылка — чтобы типовая ПараметрыРасчета() не падала на чтении реквизитов), Дата = КонецДня(Период.ДатаОкончания), прочие обязательные реквизиты по правилам обработки (НалоговыйПериод, Заполнить, автор и т.д.); затем NDFL_RDU_СтруктураКэшОборотов = ТехДокОбъект.NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям(МассивПортфелей). Объект в ИБ не записывается.

4.4. Обработка — перехват NDFL_RDU_СоздатьНачислениеНДФЛПоПортфелю

Факт: сигнатура типовая (два параметра); кэш читается из модуля объекта обработки NDFL_RDU_СтруктураКэшОборотов, заполненного в NDFL_RDU_СоздатьДокументы. Третьего параметра нет.

Передача в расчёт: ключи структуры для РассчитатьНДФЛ — ОбщиеОборотыТек, ОбщиеОборотыПрошлыйГод. Если для портфеля в соответствии нет таблицы (Получить дал Неопределено), подставляется пустая ТаблицаЗначений с нужными колонками через NDFL_RDU_ПустаяТаблицаОборотов и шаблоны ШаблонОборотыТек / ШаблонОборотыПрошлыйГод, чтобы не уходить повторно в тяжёлый запрос ОбщиеОбороты.

4.5. Документ НачислениеНДФЛПоПортфелю (расширение NDFL_RDU) — NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям

Файл: NDFL_RDU\Documents\НачислениеНДФЛПоПортфелю\Ext\ObjectModule.bsl, экспорт без &Вместо.

Важно: первый вызов ПараметрыРасчета() внутри метода уже выполняет два тяжёлых прохода ОбщиеОбороты для одного реквизита Портфель объекта-донора (его заполняет обработка — см. п. 4.3). Затем в структуру добавляется Портфели = МассивПортфелей и ещё дважды вызывается перехваченная ОбщиеОбороты уже по полному массиву портфелей. Итоговый выигрыш — в типовом цикле по строкам и портфелям, а не в «абсолютном» числе запросов за один вызов предрасчёта.

// Факт (упрощённо, без комментариев платформы)
Функция NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям(МассивПортфелей) Экспорт

4.6. Документ НачислениеНДФЛПоПортфелю (NDFL_RDU) — служебная функция NDFL_RDU_РазложитьТаблицуОборотовПоПортфелю

Что: универсальный алгоритм группировки строк ТаблицаЗначений по полю Портфель. Возвращает Соответствие: ключ — ссылка на портфель, значение — отдельная ТаблицаЗначений с теми же колонками, кроме Портфель (опционально можно оставить — для проверок).

&НаСервере
Функция NDFL_RDU_РазложитьТаблицуОборотовПоПортфелю(ТаблицаОборотов)

    Результат = Новый Соответствие;
    Если ТаблицаОборотов = Неопределено
        Или ТаблицаОборотов.Колонки.Найти("Портфель") = Неопределено Тогда
        Возврат Результат;

        КонецЕсли;

Альтернатива через Скопировать(Отбор) — короче, но обходит таблицу N-й раз для каждого портфеля. Реализация выше делает один проход и, как правило, быстрее на больших таблицах.

4.7. Документ НачислениеНДФЛПоПортфелю (NDFL_RDU) — перехват РассчитатьНДФЛ (приём внешнего кэша)

Что: добавляем единственный перехват &Вместо("РассчитатьНДФЛ") с новой сигнатурой. Перехват делает ровно одну вещь — кладёт переданную структуру во внутреннюю модульную переменную расширения и зовёт ПродолжитьВызов(). Никакой бизнес-логики, никаких ветвлений, никакой подмены результатов.

// Документ.НачислениеНДФЛПоПортфелю, расширение NDFL_RDU (факт)
Перем NDFL_RDU_ВнешнийКэшОборотов;

&Вместо("РассчитатьНДФЛ")
Процедура NDFL_RDU_РассчитатьНДФЛ(ПараметрыРасчетаВнешн = Неопределено) Экспорт
    NDFL_RDU_ВнешнийКэшОборотов = ПараметрыРасчетаВнешн;
    Попытка
        ПродолжитьВызов();
    Исключение
        NDFL_RDU_ВнешнийКэшОборотов = Неопределено;
        ВызватьИсключение;
    КонецПопытки;
    NDFL_RDU_ВнешнийКэшОборотов = Неопределено;
КонецПроцедуры
Почему НЕ перехватываем ПараметрыРасчета. Сначала естественно подумать, что нужен ещё один перехват — &Вместо("ПараметрыРасчета"), который после ПродолжитьВызов() подменяет ключи ОбщиеОбороты и ОбщиеОборотыПрошлыйГод в полученной структуре. Это не работает по сути задачи: к моменту, когда мы получили бы управление в таком перехвате, типовая ПараметрыРасчета() уже выполнила оба тяжёлых вызова ОбщиеОбороты(ПараметрыРасчета) и ОбщиеОбороты(ПараметрыРасчета, Истина). Мы получили бы корректный результат, но без выигрыша по производительности. Поэтому вместо двух перехватов делаем один и переносим логику кэша вниз — в саму NDFL_RDU_ОбщиеОбороты (см. п. 4.8): когда тяжёлый запрос вот-вот выполнится, мы возвращаем готовую таблицу из кэша до его выполнения. После этого типовая ПараметрыРасчета() штатно кладёт результат в свою структуру — никакой подмены не нужно.

Изначально рассматривался второй перехват &Вместо("ПараметрыРасчета") с пост-подменой ключей; от него отказались по причине выше. Если в будущем понадобится «обогатить» ПараметрыРасчета чем-то ещё (не оборотами), такой перехват можно добавить отдельно — текущий план его не требует.

4.9. Технический объект для NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям (факт)

Перехват НайтиСоздатьДокументПоПортфелю для пустого портфеля не используется. В NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар создаётся несохранённый Документы.НачислениеНДФЛПоПортфелю.СоздатьДокумент(), реквизит Портфель = первый элемент МассивПортфелей, дата и прочие поля — из периода/настроек обработки; затем вызывается NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям. В базу объект не записывается.

Ранний вариант плана с НайтиСоздатьДокументПоПортфелю(ПустаяСсылка(), ...) оставлен только как историческая идея; в текущем коде выбран путь без изменения типовой функции поиска.

5. Сценарии и обратная совместимость

Сценарий A. Один портфель, одна дата (форма документа)

Пользователь открыл НачислениеНДФЛПоПортфелю и нажал «Рассчитать НДФЛ» на форме.
поведение РассчитатьНДФЛ() вызывается без параметров → NDFL_RDU_ВнешнийКэшОборотов остаётся Неопределено → ветка короткого замыкания не срабатывает → выполняется обычный запрос ОбщиеОбороты по одному портфелю. Поведение не меняется.

Сценарий B. Обработка с одним клиентом и одним портфелем

поведение При одной уникальной паре Клиент/УК в выборке кэш не строится: в коде порог ПорогМассовогоПредрасчета = 2 сравнивается с МассивПарКлиентУК.Количество(), а не с числом портфелей. Расчёт идёт типовым путём без внешнего кэша оборотов.

Сценарий C. Большая выборка (продакшн)

главный сценарий Сотни/тысячи портфелей. Один раз NDFL_RDU_ОбщиеОбороты на массив, дальше в цикле O(1) на портфель — из кэша. Главный выигрыш по времени.

Сценарий D. Внешний обмен / другие места вызова РассчитатьНДФЛ()

поведение Все они вызывают без параметров → старый путь. Гарантия обратной совместимости: новая логика срабатывает только при явной передаче внешнего кэша обработкой.

6. План тестирования

№ Что проверяем Как Ожидаемый результат
1 Идентичность сумм в Начисления и Удержания при включённом массовом кэше оборотов. На тестовой базе зафиксировать эталон (выгрузка ключевых полей документов / табличных частей) до включения массового предрасчёта в целевой среде или сравнить с контрольным пересчётом на эталонной копии без расширения для той же выборки. Для режима «кэш включён» (не менее двух пар Клиент/УК после отборов) — запрос-разностник по Документ.НачислениеНДФЛПоПортфелю.Начисления. Отдельно прогнать выборку с одной парой (кэш не строится, см. порог в NDFL_RDU_ИнициализироватьКэшОборотовПоМассивуПар) — контроль, что результат совпадает с ожиданием для «узкой» выборки. Нет расхождений между эталоном и режимом с кэшем на совпадающем наборе исходных данных.
2 Сценарий «один портфель» (форма). Открыть произвольный документ, нажать «Рассчитать НДФЛ». Поведение и результат не отличаются от типового.
3 Контракт NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям. Юнит-тест на тестовой базе: создать массив из 3 портфелей, вызвать функцию, проверить, что в каждом Соответствии — таблица только по этому портфелю и сумма строк сходится с одиночным запросом. Совпадение строк по числу и суммам.
4 Изоляция модульной переменной. Запустить параллельно два расчёта (например, фоновое задание + интерактивный пересчёт). Каждый сеанс работает в своём NDFL_RDU_ВнешнийКэшОборотов; гонок нет.
5 Производительность. Замерить общее время СоздатьДокументы на большой выборке (две и более пары Клиент/УК) по сравнению с эксплуатацией без расширения или с искусственным отключением массового кэша. Логи ОбщегоНазначенияДУ.ДобавитьВЛогОтладки для вызовов «ОбщиеОбороты». Ожидается снижение времени и числа тяжёлых проходов с Хозрасчётным относительно поочерёдного расчёта по каждому портфелю (точные цифры зависят от выборки; один вызов NDFL_RDU_ПолучитьОбщиеОборотыПоПортфелям сам делает несколько обращений к перехваченной ОбщиеОбороты, см. п. 4.5).
6 Граничные условия. Пустой МассивПортфелей; портфели у клиентов в СписокКлиентовСЦБ = пусто; неактуальные клиенты (помечены на удаление); закрытые портфели. Обработка не падает; идёт по старому пути; кэш не используется.

7. Риски, ограничения, открытые вопросы

  • Память. Большой кэш на тысячи портфелей и обороты за два периода может занять десятки/сотни МБ. Снизить риск: выгружать таблицы в кэш по мере обхода (генератор-стиль) либо ставить верхний порог МаксПортфелейДляМассовогоПредрасчёта (например, 2000) и выше него работать по-старому.
  • Период и МинимальнаяДатаДокументов в текущей сборке. В NDFL_RDU_ОбщиеОбороты до установки границ запроса нормализуются мультипортфельные параметры: NDFL_RDU_СписокДокументовДляРасчетаДоходовРасходов(..., Истина) даёт таблицу документов и МинимальнаяДатаДокументов на том же наборе портфелей, что и тяжёлый запрос (см. комментарий в коде про согласованность). Для текущего периода в запрос уходит НачалоПериода = МинимальнаяДатаДокументов, КонецПериода = МоментВремени() от объекта документа; технический документ в обработке получает Дата = КонецДня(Период.ДатаОкончания). Оставшийся предмет для постановки: если бизнес потребует увязать массовый кэш не с концом периода обработки, а с датой каждой строки ТЧ «Даты документов», это отдельное изменение контракта.
  • Параметры по портфелю. РасчетСуммыНДФЛВыполнятьПоСуммамНалоговогоУчета, СписокДокументовДляРасчетаДоходовРасходов, ТаблицаПродажДляРасчетаЛьготПоКлиентамПодСанкциями в текущем NDFL_RDU_ОбщиеОбороты уже принимают значения по массиву портфелей (с колонкой Портфель). Это нужно проверить «end-to-end» именно в массовом режиме.
  • Совместимость с расширением VTB_NDFL_Exchange. В нём перехвачена другая функция (РасходыПоНКДПоВидуОбращаемости). Текущий план её не затрагивает; конфликта по &Вместо нет.
