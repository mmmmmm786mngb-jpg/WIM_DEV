Что происходит сейчас

После запроса к регистру ЗначенияПараметровПортфеля и соединения с планом видов характеристик ПараметрыПортфеля для строк без значения в срезе выполняется цикл: в колонку Значение подставляется пустое значение по метаданным типа параметра:

СтрокаТЗ.Значение = СтрокаТЗ.Параметр.ТипЗначения.ПривестиЗначение();

У элемента ПВХ ПараметрыПортфеля реквизит ТипЗначения имеет тип ОписаниеТипов. Вызов ПривестиЗначение() без аргумента возвращает значение по умолчанию для этого описания (пустая ссылка, ноль, пустая строка и т.д.). При массовом проведении один и тот же параметр встречается много раз, поэтому накопительное число вызовов ПривестиЗначение велико, хотя доля времени по отчёту меньше, чем у основного запроса в документе «Сделка».

Рекомендуемое решение (идиоматика 1С)

Вынести получение пустого значения в отдельную экспортную функцию того же общего модуля УправлениеПараметрамиПортфеляПовтИспНаВремяСеанса, у которого уже включено повторное использование возвращаемых значений на время сеанса. Платформа сама кэширует результат вызова при одинаковом значении параметра Параметр (ссылка на элемент ПВХ).

В цикле вместо прямого обращения к ТипЗначения.ПривестиЗначение() вызывать эту функцию. Так устраняются повторные вычисления для одной и той же ссылки параметра в пределах сеанса без ручного Соответствие и без глобальных переменных модуля.

Ключ кэша: ссылка Параметр (элемент ПараметрыПортфеля), а не «абстрактный тип»: у разных элементов тип может совпадать, но кэш по ссылке однозначен и совпадает с тем, откуда берётся ТипЗначения.
