Оптимизация1769 — перенос вызова ПолучитьСуммуОНВ (без изменения текста запроса)

IMDEV-8662, документ Сделка, модуль объекта. Узкое место профиля проведения — обращение к виртуальной таблице остатков регистра РегистрБухгалтерии.Хозрасчетный внутри функции ПолучитьСуммуОНВ (в снимке кода WIM_FIn вызов Запрос.Выполнить() приходился примерно на строку ~1769; точный номер строки меняется при правках конфигурации).

Исходники базы: C:\1c\Cursor_1c\WORK\WIM_FIn\src\cf\Documents\Сделка\Ext\ObjectModule.bsl. Реализация в расширении: Расширения/FonProv/Documents/Сделка/Ext/ObjectModule.bsl.

Что именно делает ПолучитьСуммуОНВ в типовой базе

Запрос выполняется одним пакетом из трех частей:

  1. Временная таблица по остаткам на счете ПланСчетов.Хозрасчетный.ОблигацииТело (портфель, облигация).
  2. Временная таблица по остаткам на счете ПланСчетов.Хозрасчетный.ОНВ с теми же отборами.
  3. Итоговый ВЫБРАТЬ: из остатков ОНВ левое соединение с «телом», расчет суммы ОНВ с учетом количества сделки и количества остатка по телу.

Параметры запроса стандартные для проведения: Портфель, Количество, Облигация, Период, ВидыСубконто. При типовом сценарии по облигациям строк по ОНВ часто нет, но первая часть пакета все равно обращается к остаткам по телу облигации.

Замеры и постановка

При массовом перепроведении сделок в профиле заметная доля времени приходилась на выполнение запроса в ПолучитьСуммуОНВ в момент подготовки параметров проведения. При этом результат ТаблицаОНВ в типовом коде заполнялся в УстановкаДополнительныхПараметровПроведения, а фактически использовался только в ветке НУ при формировании движений реализации для облигаций с нужной комбинацией флагов.

Два направления оптимизации

Внедрено в расширении FonProv: ленивый вызов — текст запроса в ПолучитьСуммуОНВ не меняется, вызов переносится ближе к месту реального использования суммы ОНВ, чтобы не дергать остатки по «Хозрасчетный», когда ветка ОНВ к проводке не нужна.

Альтернатива, не используемая в этом расширении: переписать сам текст запроса — один итоговый ВЫБРАТЬ с подзапросами вместо двух ПОМЕСТИТЬ по ВТ, чтобы остатки по телу не материализовались отдельной первой частью пакета, когда по ОНВ пусто. Такой вариант требует отдельной проверки плана выполнения СУБД и регрессионных тестов в основной конфигурации; в рамках IMDEV-8662 для FonProv выбран только перенос места вызова.

Идея внедрения (ленивый вызов)

Ускорение за счет того, что ПолучитьСуммуОНВ() вызывается только если далее по проведению действительно нужна сумма ОНВ для НУ-проводки реализации: облигация, параметр портфеля «учет частичного погашения» в режиме ВСоставеДоходов, плюс уже известные флаги НУ и свойства счета выручки.

В базовой конфигурации результат ПолучитьСуммуОНВ попадал в ТаблицаОНВ в УстановкаДополнительныхПараметровПроведения, а использовался только в СформироватьДвиженияРеализация через ТаблицаОНВ.Итог("СуммаОНВ"). Перенос вызова убирает лишние обращения к регистру для портфелей и сценариев, где ветка ОНВ не выполняется.

Дополнительная защита перед Итог

Перед вычислением Итог("СуммаОНВ") добавлена проверка ЗначениеЗаполнено(ТаблицаОНВ): при отсутствии таблицы (не вызывали ПолучитьСуммуОНВ или вернулось Неопределено) сумма считается нулем, без обращения к методу таблицы значений.

Заполнение ТаблицаОНВ выполняется только при БУ (как и в базовой ПолучитьСуммуОНВ).

Запрос выполняется только при входе в условие, где в базе вызывался Итог. Семантика проводок не меняется: те же входные данные и та же формула после получения таблицы.

Почему ничего не «ломается» по данным: единственный потребитель ТаблицаОНВ в модуле объекта — блок НУ в СформироватьДвиженияРеализация. Перенос вызова не меняет порядок заполнения ОбъектПоАктиву и ЗначенияПараметров относительно этого блока (они по-прежнему задаются в УстановкаДополнительныхПараметровПроведения раньше). Риск «вызвать позже другой момент времени» отсутствует: ПолучитьСуммуОНВ по-прежнему использует МоментВремени() внутри себя, как в базе.

Где смотреть в расширении

  • &ИзменениеИКонтроль("УстановкаДополнительныхПараметровПроведения") — блок #Удаление вокруг ТаблицаОНВ = ПолучитьСуммуОНВ();, вместо вызова — комментарий о ленивом расчете.
  • &ИзменениеИКонтроль("СформироватьДвиженияРеализация") — вставка вызова ПолучитьСуммуОНВ и ветвление перед Итог("СуммаОНВ").
