Почему эта точка тяжелая

Строка 1160 относится к подготовке таблиц продажи по БУ и попадает в тяжелый пакет запросов, который выполняется через ВыполнитьПакет(). Внутри пакета есть выражения вида Ссылка.Дата, где одна и та же колонка может содержать ссылки разных типов: документы и бизнес-процессы.

Для платформы это означает, что дата извлекается не из заранее известного типа, а из полиморфного значения. В таких местах SQL получается менее прозрачным: движку нужно учитывать несколько вариантов ссылок, а план выполнения становится менее предсказуемым.

Ключевая идея: мы не меняем бизнес-логику списания и не перестраиваем пакет запросов целиком. Мы точечно делаем явным только одно место - как именно из ссылочного поля получается Дата.

Основная идея оптимизации

Заменить прямой доступ .Дата на явный шаблон ВЫБОР + ТИПЗНАЧЕНИЯ + ВЫРАЗИТЬ(...).Дата. Такой подход заранее раскладывает ссылочное поле по допустимым типам и для каждого типа обращается к реквизиту Дата уже после точного приведения.

Что это дает технически:

  • убирает неявную работу с составным ссылочным типом;
  • делает выражение чтения даты детерминированным и читаемым;
  • повторяет уже проверенный паттерн из аналогичной доработки в другом проекте;
  • снижает риск нестабильного SQL-плана в местах, где поле содержит разные виды ссылок.

Где именно меняем

1. ТекстЗапросаТаблицыПоПродажамБУ_БезНКД

  • заменяется получение даты по Субконто2;
  • заменяется получение даты по Партия через ЕСТЬNULL(...);
  • подстановка выполняется через текстовые блоки ТекстДатаПоСубконто2 и ТекстДатаПоПартии.

То есть меняется не смысл запроса, а только форма выражения, которое возвращает дату документа.

2. ТекстЗапросаНКД

  • в ветке учета НКД в разрезе партий заменяется ВТ_ОстаткиТело.Партия.Дата;
  • для этого используется отдельный шаблон ТекстДатаПоПартииНКД;
  • замена также делается до возврата итогового текста запроса.

В результате обе функции используют одинаковый принцип явного приведения типа перед чтением реквизита Дата.

Почему идея корректна по смыслу

В исходном коде система уже ожидала, что в этих полях лежат ссылки на документы и бизнес-процессы, у которых есть дата. Новая версия не меняет эту семантику, а только описывает ее явно: сначала проверяем тип, затем приводим значение, затем читаем Дата.

Для неизвестных или неподдержанных типов используется безопасный fallback ДАТАВРЕМЯ(1, 1, 1, 0, 0, 0). Это сохраняет защитное поведение и не ломает сценарии, где значение не попало в целевой перечень.

Как это оформляется в расширении

Обе функции заимствуются методом ИзменениеИКонтроль. Это важно для демонстрационного расширения: логика методов сохраняется, а измененные места хорошо видны через вставки и удаляемые блоки.

  • ТекстЗапросаТаблицыПоПродажамБУ_БезНКД - &ИзменениеИКонтроль
  • ТекстЗапросаНКД - &ИзменениеИКонтроль

Практически это означает точечные #Удаление / #Вставка или добавление новых блоков СтрЗаменить без полной переписи метода.

Что важно подчеркнуть разработчикам

  • Оптимизация направлена не на сокращение количества таблиц и не на отказ от ВыполнитьПакет(), а именно на упрощение вычисления даты внутри тяжелого пакета.
  • Изменение локальное: меняются только выражения, где дата читалась через точку у составной ссылки.
  • Результат запроса по смыслу должен сохраниться: на тех же поддержанных типах возвращается та же самая дата, что и раньше.
  • Черновик BSL нужен как наглядная карта переноса в расширение и место для ревью конкретных вставок.
