Оптимизация2551 - ПолучитьАвансы (строка ~2551)

Ниже описаны идеи оптимизации и реализация для запроса в функции ПолучитьАвансы документа Сделка (IMDEV-8662). Цель - ускорить выполнение Запрос.Выполнить() за счет уменьшения объема лишних данных и сохранения поведения зачета авансов.

Замеры: measurements_table_IMDEV-8662.html, строка 2551 (ПолучитьАвансы: ТекстЗапроса_ПолучитьАвансы).

Контекст и узкое место

В типовом коде ПолучитьАвансы() выполняет запрос, выгружает таблицу остатков авансов, сортирует ее и использует в последующих расчетах зачета. По замерам точка строки 2551 имеет заметный вклад по времени при массовом перепроведении.

Основные идеи оптимизации и как они реализованы

1. Удаление неиспользуемого поля НУ из запроса

Идея

В исходном запросе формировалось поле СуммаНУ, но в дальнейшем расчете зачета авансов это значение не использовалось в результате проводок (использовалось только для промежуточного коэффициента, который не влияет на итог).

Реализация

  • Удалены поля НУ в части ПОМЕСТИТЬ ОстаткиАвансов: СуммаНУОстатокДт и СуммаНУОстатокКт.
  • Удалено вычисляемое поле СуммаНУ из итогового ОБЪЕДИНИТЬ.
  • Удален вывод СуммаНУОстатокДт из ветки доп. расходов.
// Было в запросе:
... КОНЕЦ КАК СуммаНУ,
...
ОстаткиАвансов.СуммаНУОстатокДт,

// Стало:
// поля НУ в этой цепочке не выбираются

2. Согласование структуры данных с новым запросом

Идея

После удаления поля из запроса нужно синхронизировать структуру пустой таблицы и потребляющий код, чтобы избежать расхождений по колонкам.

Реализация

  • В ПустаяТаблицаОстаткиАвансов() удалена колонка СуммаНУ.
  • В ДобавитьСтрокиЗачтенныхАвансов() удален расчет КоэффициентКурсаАвансаНУ.
  • Логика расчета по БУ и регламентному учету сохранена без изменений.
// Было:
КоэффициентКурсаАвансаНУ = ...

// Стало:
// расчет удален как неиспользуемый

3. Демонстрационный формат для разработчиков

Идея

Расширение используется как демонстрация мест правок в базе, поэтому изменения должны быть явно видимы и легко переносимы.

Реализация

  • ТекстЗапроса_ПолучитьАвансы перехвачен через &Вместо (полная замена текста запроса).
  • ПустаяТаблицаОстаткиАвансов и ДобавитьСтрокиЗачтенныхАвансов оформлены через &ИзменениеИКонтроль с блоками #Удаление.
  • Такой формат наглядно показывает точку изменения и не требует ручного поиска в длинном методе.

Список затронутых методов

  • ТекстЗапроса_ПолучитьАвансы(ИспользуетсяСубконтоДокументы) - оптимизация текста запроса.
  • ПустаяТаблицаОстаткиАвансов() - синхронизация структуры таблицы.
  • ДобавитьСтрокиЗачтенныхАвансов(...) - удаление неиспользуемого расчета НУ.

Для бизнеса (одним абзацем)

Оптимизация строки 2551 уменьшает объем данных, обрабатываемых при подготовке зачета авансов, без изменения бизнес-результата проведения. Пользовательский сценарий и проводки сохраняются, но нагрузка на запрос и последующую обработку снижается.

Важно: данная оптимизация касается только цепочки расчета остатков авансов в Документ.Сделка. Удаление СуммаНУ в других модулях (например, общие модули взаиморасчетов) без отдельного анализа не рекомендуется.
