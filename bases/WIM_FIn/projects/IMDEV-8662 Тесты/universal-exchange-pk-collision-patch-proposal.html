Предложение патча: дубль PRIMARY KEY при параллельной загрузке (УниверсальныйОбменДаннымиXML)

Контекст: два потока не находят объект по GUID, оба создают новый с одним УИД; первый коммит проходит, второй получает ошибку СУБД о нарушении PRIMARY KEY / уникальности. Загрузка в ФИН: исходники по bases/WIM_FIn/README.md и source-path.txt. После ошибки PK и только если Объект.Ссылка имеет тип БизнесПроцессСсылка.СделкаTn (проверка через ТипЗнч / Тип): если в ИБ уже полный объект — выход без ошибки; если каркас — удалить строку в ИБ и снова Объект.Записать() без ошибки. Для остальных типов ссылок ветка обхода не выполняется.

2. Идея патча

  • В Исключение после Записать() распознать ошибку дубля ключа (функция п. 3).
  • Убедиться, что ТипЗнч(Объект.Ссылка) совпадает с Тип("БизнесПроцессСсылка.СделкаTn") (п. 4); иначе патч не применяется — обычный протокол и исключение.
  • По Объект.Ссылка получить ОбъектВБ. Если записи нет или объект «новый» в смысле ИБ — обычный протокол и исключение.
  • Если запись есть и она не каркас — считаем загрузку выполненной другим сеансом, Возврат без исключения.
  • Если запись есть и она каркас — в режиме обмена ОбъектВБ.Удалить(), затем снова УстановитьОбменДаннымиЗагрузка(Объект) и Объект.Записать(), Возврат.
Патч не сериализует конкурентные обновления одного УИД разным содержимым: при ошибочной эвристике «каркас» можно удалить полный объект. Надёжнее по архитектуре — один писатель на ключ или отключение параллельной загрузки конфликтующих типов.

3. Функция распознавания ошибки СУБД

Разместить выше ЗаписатьОбъектВИБ. На вход — строка (в ФИН удобно передать уже вычисленный ТекстОшибки из подробного представления).

//
// Параметры:
// ТекстОшибки - Строка
//
// Возвращаемое значение:
// Булево
//
Функция ЭтоОшибкаНарушенияУникальностиИлиПервичногоКлюча(ТекстОшибки)
	
	Верх = ВРег(ТекстОшибки);
	
	Если СтрНайти(Верх, "PRIMARY KEY") > 0 Тогда
		Возврат Истина;
	КонецЕсли;
	Если СтрНайти(Верх, "UNIQUE KEY") > 0 Тогда
		Возврат Истина;
	КонецЕсли;
	Если СтрНайти(Верх, "UNIQUE CONSTRAINT") > 0 Тогда
		Возврат Истина;
	КонецЕсли;
	Если СтрНайти(Верх, "НАРУШЕНИЕ ОГРАНИЧЕНИЯ UNIQUE") > 0 Тогда
		Возврат Истина;
	КонецЕсли;
	Если СтрНайти(Верх, "НАРУШЕНИЕ ОГРАНИЧЕНИЯ PRIMARY KEY") > 0 Тогда
		Возврат Истина;
	КонецЕсли;
	Если СтрНайти(Верх, "UNIQUE VIOLATION") > 0 Тогда
		Возврат Истина;
	КонецЕсли;
	
	Возврат Ложь;

4. Проверка типа ссылки: бизнес-процесс СделкаTn

В дереве метаданных объект обозначается как БизнесПроцесс.СделкаTn; для ссылки в языке 1С используется имя типа БизнесПроцессСсылка.СделкаTn (стандартное сравнение через ТипЗнч и Тип).

Критерий нужно зафиксировать под ваши метаданные. Неверный критерий приведёт к Удалить() полной записи или к ошибке «есть ссылки».

6. Удаление каркаса и повторная запись

Только если на объект в ИБ нет ссылок, нет движений и удаление допустимо политикой конфигурации. Иначе Удалить() вызовет исключение — тогда не перехватывать как успех (или расширить эвристику и не заходить в эту ветку).

УстановитьОбменДаннымиЗагрузка(ОбъектВБ);
ОбъектВБ.Удалить();

УстановитьОбменДаннымиЗагрузка(Объект);
Объект.Записать();
Между Удалить() и повторной вставкой другой сеанс может снова создать строку с тем же ключом — возможен повтор PK (при необходимости один контролируемый повтор в Попытка). Повторная Записать() объекта в памяти после первой неудачи проверьте на ваших типах в отладчике.

9. Ограничения

ТемаКомментарий
Текст ошибки Зависит от СУБД и платформы; при смене СУБД расширьте функцию распознавания.
Тип ссылки Ветка обхода PK выполняется только для БизнесПроцессСсылка.СделкаTn; для справочников, документов и других БП — стандартная ошибка.
