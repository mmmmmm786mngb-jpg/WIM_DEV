2. Цели разработки (бизнес и ИТ)

  • Ускорить массовое закрытие периода в сценарии «розница ДУ / РДУ» за счёт автоматического снятия признака выполнения с «лишних» строк плана регламентных операций до фактического запуска расчётов.
  • Сохранить полноту плана: строки плана не удаляются, изменяется только признак Выполнять (в таблице плана — число 0 или 1).
  • Перечень видов операций, для которых допускается такая оптимизация, вести в данных: регистр сведений ВидыОптимизируемыхРегламентныхОперацийДУ, а не «белый список» в коде.

3. Условия включения оптимизации

Оптимизация применяется только если одновременно выполняются оба условия (см. файл ГлобальнаяЛогика в корне проекта и раздел 1 файла imdev8641_development_brief.md в папке Документация):

  1. Константа ПулРозницаДУ заполнена (непустая ссылка на пул «розница ДУ»).
  2. В таблице плана на этот день все портфели относятся только к этому пулу: у каждого портфеля реквизит пула строго равен значению константы. Если в плане есть портфель с другим или пустым пулом — таблицу плана не менять, поведение как до доработки.

4. Границы объёма

В объём

  • Расширение конфигурации (CFE), без прямого изменения типовой поставки.
  • Заимствование обработки ГрупповоеВыполнениеЗакрытияПериодов; перехват процедуры ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей вариантом ИзменениеИКонтроль.
  • Вставка вызова фильтра плана после получения таблицы плана вызовом РегистрыСведений.НастройкиЗакрытияПериода.ПланРеглОпераций для дня и до ПланРеглОперацийПоДням.Вставить(День, ...).
  • Новые объекты расширения: константа ПулРозницаДУ; регистр сведений ВидыОптимизируемыхРегламентныхОперацийДУ; модуль менеджера этого регистра с процедурой фильтрации плана и функциями ПолучитьДанныеОптимизацииПланаПоВидуОперации и ПолучитьПортфелиДляСохраненияВыполненияВПлане.
  • Первичное наполнение регистра пятью видами операций из раздела 4 постановки (imdev8641_development_brief.md) и файла ПеречеьВидовОпераций в корне проекта.

Вне объёма (первый этап)

  • Однопоточный режим закрытия без кэша ПланРеглОперацийПоДням — ветка не дорабатывается (см. filter_plan_regl_operations_table_integration.md).

5. Принципы реализации

  1. Не менять типовую конфигурацию напрямую; доработки только в расширении.
  2. Точка встраивания — строго между расчётом таблицы плана на день и помещением её в соответствие по дням, чтобы все фоновые потоки получали уже скорректированный план.
  3. Решение «участвует ли вид в оптимизации» — по наличию записи в РС ВидыОптимизируемыхРегламентныхОперацийДУ по ссылке ВидОперации, а не по сравнению строки ИсполняемаяПроцедура с зашитым списком.
  4. Алгоритм фильтра: шаг 1 — применимость (константа и однородность пула); шаг 2 — свод уникальных ВидОперации при Выполнять <> 0; шаг 3 — цикл по видам из свода, пакетные запросы и вызовы с параметром-массивом портфелей.
  5. Момент среза для запросов (День и при необходимости время группы): приоритет — колонка ВремяРеглОпераций строки плана; если в контексте доступен только календарный день — собрать момент по правилам раздела 5.1 постановки (imdev8641_development_brief.md).
  6. Производительность: ранний выход при пустой константе пула; не обходить десятки тысяч портфелей по одному; шаги 1 и 2 — пакетно; шаг 3 — цикл по видам (их мало).

6. Связь с цепочкой исполнения

После фильтрации таблица плана передаётся дальше по типовой цепочке: ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ переносит Выполнять в табличную часть Операции документа ПланРегламентныхОперацийДУ; в исполнение попадают операции, отобранные в том числе с учётом признака Выполнять (см. plan_reg_oper_du_group_closure_chain.md в папке Документация).

7. Реализованные запросы (черновик для модуля менеджера РС)

Источник: файл get_portfolios_for_plan_execution.bsl в папке Скрипты/bsl. Это черновик для переноса в модуль менеджера регистра ВидыОптимизируемыхРегламентныхОперацийДУ. Экспортная функция ПолучитьПортфелиДляСохраненияВыполненияВПлане(МассивПортфелей, День, ВидОперации) ветвится по предопределённым элементам справочника ВидыОперацийЗакрытияПериода; для остальных видов возвращается входной массив без изменений.

Общий принцип: запросы намеренно шире типовой регламентной операции — фиксируется минимальное основание «расчёт может понадобиться», а не полная эквивалентность всем проверкам типовой процедуры.

8. Критерии приёмки (минимум)

  1. При незаполненной константе ПулРозницаДУ или при смешанных пулах в таблице плана за день значения Выполнять у всех строк совпадают с исходом ПланРеглОпераций.
  2. При заполненной константе и однородном пуле для видов операций, которых нет в регистре ВидыОптимизируемыхРегламентныхОперацийДУ, строки плана по этим видам не меняются.
  3. Для вида из регистра: строки с портфелями, не попавшими в массив «оставить выполнение», получают Выполнять = 0; остальные строки этого вида остаются с 1.
  4. Документ ПланРегламентныхОперацийДУ после переноса из плана содержит в ТЧ «Операции» согласованные значения Выполнять; операции с «ложь» не исполняются через типовой отбор списка к выполнению.
  5. Регистр ВидыОптимизируемыхРегламентныхОперацийДУ первично заполнен согласованно с пятью видами из раздела 4 постановки.

Дословная формулировка и контекст — в разделе 10 файла imdev8641_development_brief.md.
