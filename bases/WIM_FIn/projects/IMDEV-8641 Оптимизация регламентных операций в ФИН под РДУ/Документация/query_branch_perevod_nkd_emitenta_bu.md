# Запросы ветки `ПолучитьПортфелиДляСохраненияВыполненияВПлане`: ПереводНКДЭмитента_БУ

**Назначение файла:** описание источников данных и логики, по которым можно определить **портфели**, для которых в операционный день должны выполняться расчёты, сопоставимые с типовой цепочкой **погашения НКД в задолженность эмитента (БУ)**. Ориентир по виду операции: **`ВидыОперацийЗакрытияПериода`** с именем вроде **`ПереводНКДЭмитента_БУ`** (см. перечень в проекте; исполняемая процедура **`ИсполняемыеПроцедурыЗакрытияПериода.Операция_0050_ПереводНКДВЗадолженностьЭмитента`**).

**Учёт:** в прикладной «теории купонов» для этой операции в типовом сценарии используется **только бухгалтерский учёт (БУ)** — регистр **`РегистрБухгалтерии.Хозрасчетный`**, без ЕПС/УУ в приведённых запросах. Параметры **`&БУ`** / **`&НУ`** в исходных текстах задают, какие ветки условий считаются истинными; для фильтра плана под **перевод НКД эмитента (БУ)** имеет смысл ориентироваться на **`&БУ = Истина`** (и при необходимости отдельно согласовать, нужен ли **`&НУ`** в вашей политике закрытия).

**Контракт фильтра плана** (как в постановке IMDEV-8641): на вход — **`МассивПортфелей`**, **`День`**, **`ВидОперации`**. На выход ветки — **`Массив`** ссылок **`Справочник.Портфели`**, для которых **есть основания** оставить **`Выполнять = 1`**. Во всех фрагментах ниже условие **`Портфель = &Портфель`** из модуля документа следует заменить на **`Портфель В (&МассивПортфелей)`**, а итоги запросов — сводить к **различным портфелям** (через **`ВЫБРАТЬ РАЗЛИЧНЫЕ Портфель`** или **`СГРУППИРОВАТЬ ПО Портфель`** по смыслу).

**Источник логики:** объект **`Документ.ПереводНКД`** (или одноимённый модуль документа в конфигурации): последовательность **`ЗаполнитьКупоннымиПериодами`** и связанных процедур, внутри которых вызываются четыре блока РСБУ:

| № | Процедура (ориентир) | Смысл |
|---|----------------------|--------|
| 1 | **`ЗаполнитьИстекшимиКупоннымиПериодамиРСБУ`** | Истёкшие / релевантные купонные периоды по остаткам облигаций на счёте тела, плюс связка с датами оферт. |
| 2 | **`ЗаполнитьНеПогашеннымиКупоннымиПериодамиРСБУ`** | Непогашенные купоны по остаткам на счетах НКД (начисленный / уплаченный и т.д.). |
| 3 | **`ЗаполнитьСтруктурныеНотыРСБУ`** | Структурные ноты: остаток на счёте стоимости + купонное расписание на дату. |
| 4 | **`ЗаполнитьСтарыеКупоныРСБУ`** | «Старые» купоны по остаткам уплаченного НКД (УКД) с отбором по облигациям и купонным периодам. |

Ниже — структура запросов и параметры в том виде, в каком они задают **какие ценные бумаги / активы** попадают в расчёт при **одном портфеле**; для плана **тот же критерий** переносится на **`МассивПортфелей`**.

---

## Общие параметры (как в типовом вызове по дню)

| Параметр | Смысл |
|----------|--------|
| `&Дата` / `&КонецДня` | Обычно **`НачалоДня(День)`** и **`КонецДня(День)`** для границ среза. |
| `&Портфель` | В документе — один портфель; в фильтре плана — заменить на **`&МассивПортфелей`**. |
| `&БУ`, `&НУ` | Флаги учёта в условиях **`ВЫБОР`** по остаткам; для ветки «только БУ» типично **`&БУ = Истина`**. |
| `&ОфертыИсключения` | Список документов-оферт, исключаемых из анализа дат оферт (в **`ЗаполнитьИстекшимиКупоннымиПериодамиРСБУ`**). |

---

## 1. `ЗаполнитьИстекшимиКупоннымиПериодамиРСБУ`

**Идея:** отобрать пары **облигация / актив** с остатком на **`ПланСчетов.Хозрасчетный.ОблигацииТело`**, связать с **`Справочник.Активы`**, затем сузить по **купонным периодам** (дата окончания = дню операции или «вечная» облигация с началом до даты) и по ветке с **датами оферт** из **`РегистрСведений.ДатыОфертОблигаций`**.

**Параметры (фрагмент):**

- `&СчетОблигаций` = **`ПланыСчетов.Хозрасчетный.ОблигацииТело`**
- `&Дата`, `&КонецДня`, `&Портфель` (в плане — массив портфелей)
- `&БУ`, `&НУ`
- `&ОфертыИсключения`

**Схема пакета (сокращённо):**

1. **`ВТ_ОстаткиРСБУ`** — **`Хозрасчетный.Остатки(&Дата, Счет = &СчетОблигаций, , Портфель = &Портфель)`** + соединение с **`Активы`** по **`Субконто1 = Активы.Объект`**, расчёт признаков **`БУ`** / **`НУ`** по сумме и количеству остатка.
2. **`ВТ_ДатыОфертОблигаций`** — срез **`ДатыОфертОблигаций`** с **`ВидДаты = ДатаОферты`**, виды оферт (**`ДосрочноеПогашениеПоПравуЭмитента`**, **`MCAL_BN`**), исключение регистраторов из **`&ОфертыИсключения`**.
3. **`ВТ_ПромежуточныйРезультат`** — объединение двух логик:
   - купонные периоды по владельцу-облигации: окончание периода на **`&Дата`** или «пустая» дата окончания при начале до даты;
   - вторая часть **`ОБЪЕДИНИТЬ ВСЕ`**: связка оферт с активом и купонными периодами с условиями по датам оферты = **`&Дата`**.

**Для портфелей:** в каждом подзапросе, где есть отбор по портфелю, использовать **`Портфель В (&МассивПортфелей)`**; в **`ВЫБРАТЬ`** добавить (или сохранить через цепочку **`Активы`**) поле **`Портфель`**, чтобы на выходе получить множество портфелей, по которым есть хотя бы одна строка, удовлетворяющая условиям (после согласования с бизнес-правилом по **`БУ`/`НУ`**).

## 2. `ЗаполнитьНеПогашеннымиКупоннымиПериодамиРСБУ`

**Идея:** остатки по счетам НКД на **`&Дата`**, разрез **`Субконто1`** (облигация), **`Субконто2`** (купонный период); отбор «купон ещё не погашён по календарю» относительно **`&Дата`**.

**Параметры:**

- **`СчетаНКД`** — массив счетов, в типовом коде: **`НачисленныйНКД`**, **`НачисленныйНКД_58`**, **`УплаченныйНКД_58`**, **`УплаченныйНКД`**.
- **`&Дата`**, **`&Портфель`**, **`&БУ`**, **`&НУ`**.

**Схема:**

- **`ВТ_НепогашенныеКупоныОблигации`**: **`Хозрасчетный.Остатки(&Дата, Счет В (&СчетаНКД), , Портфель = &Портфель)`** + **`Активы`**.
- **`ГДЕ`**: дата окончания купонного периода **до** начала дня **`&Дата`** или «пустая» дата окончания при начале периода **до** **`&Дата`** (формулировки через **`НАЧАЛОПЕРИОДА(&Дата, ДЕНЬ)`** — как в исходном тексте).

**Для портфелей:** **`Портфель В (&МассивПортфелей)`**; итог — портфели, где есть непогашенный купон в смысле этого запроса.

---

## 3. `ЗаполнитьСтруктурныеНотыРСБУ`

**Идея:** остатки структурных нот на счёте **`ПланыСчетов.Хозрасчетный.СтоимостьСтруктурнойНоты`** с **`КоличествоОстаток > 0`**, плюс сопоставление с **купонным расписанием** документа **`КупонноеРасписание`** через **`РегистрСведений.КупонныеРасписания.СрезПоследних`** и отбор строк купонов по дате окончания периода относительно **`&Дата`** (в т.ч. «вечный» купон).

**Параметры:**

- **`&ДатаПолученияОстатков`** (как правило, дата дня закрытия),
- **`&СчетУчета`**, **`&Портфель`**.

**Схема:**

1. **`ВТ_ОстаткиРСБУ`** — остатки по ноте и портфелю, связь с **`Активы`**.
2. **`ВТ_КупоныеПериоды`** (имя в коде может отличаться орфографически) — строки **`Документ.КупонноеРасписание.Купоны`** + срез последних расписаний по активу.
3. **`ВТ_ПромежуточныйРезультат`** — соединение остатков с купонными периодами по **`Актив`**.

**Для портфелей:** заменить фильтр портфеля на массив; в итоге — портфели со структурными нотами, попавшими под условие купона на дату.

---

## 4. `ЗаполнитьСтарыеКупоныРСБУ`

**Идея:** остатки на счетах **уплаченного** НКД (**`УплаченныйНКД_58`**, **`УплаченныйНКД`** и т.д. — в коде задаётся массив **`СчетаУКД`**), с отбором по **`&Облигации`** во вложенном условии портфеля и субконто; затем соединение с **`КупонныеПериоды`**, где **`ДатаОкончанияКупонногоПериода < &Дата`**.

**Параметры:**

- **`&СчетаУКД`** / набор счетов УКД,
- **`&Дата`**, **`&Портфель`**, **`&Облигации`** (в сценарии документа — список облигаций; для плана может понадобиться обобщение без жёсткого предварительного списка — уточняется по модулю вызова).

**Схема:**

1. **`ВТ_ОстаткиРСБУ`** — остатки УКД с индексацией по купонному периоду.
2. **`ВТ_ПромежуточныйРезультат`** — отбор не помеченных на удаление **`КупонныеПериоды`** с **`ДатаОкончанияКупонногоПериода < &Дата`**.

**Для портфелей:** **`Портфель В (&МассивПортфелей)`**; множество портфелей, где есть «старые» купоны в смысле запроса.

## 5. Сшивка четырёх проверок в одну ветку `Если`

Типовой документ последовательно наполняет табличные части разными процедурами; для **`ПолучитьПортфелиДляСохраненияВыполненияВПлане`** нужно зафиксировать правило:

- **Вариант A:** портфель попадает в результат, если **хотя бы один** из четырёх запросов (после адаптации под массив портфелей) вернул для него строки — **объединение** множеств (**логическое ИЛИ**), по аналогии с вариантом B для начисления процентов по счетам.
- **Вариант B:** портфель нужен только если выполняются **все** четыре условия — **пересечение** (на практике для разных сущностей — облигации / ноты — редко; требует отдельного обоснования).

По умолчанию для «есть работа по переводу НКД в день» разумнее **объединение** портфелей из четырёх независимых критериев, если бизнес не требует иного.

Реализация: четыре запроса (или один пакет с четырьмя **`ПОМЕСТИТЬ`** и финальным **`ОБЪЕДИНИТЬ ВСЕ`** по полю **`Портфель`**) + **`ВЫБРАТЬ РАЗЛИЧНЫЕ Портфель`**, либо четыре вызова в коде и слияние массивов без дублей.

---

## 6. Пустой результат и согласование с планом

Если после адаптации ни один портфель из **`МассивПортфелей`** не прошёл условия, ветка возвращает **пустой** **`Массив`** — тогда по правилам фильтра плана для данного **`ВидОперации`** у всех строк снимается **`Выполнять`** (см. [filter_plan_regl_operations_table_integration.md](filter_plan_regl_operations_table_integration.md)).
