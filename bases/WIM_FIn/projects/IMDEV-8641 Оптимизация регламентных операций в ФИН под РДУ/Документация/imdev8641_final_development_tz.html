1. Задача и контекст

Назначение. Ускорить массовое закрытие периода в сценарии «розница ДУ / РДУ»: до запуска операций по строкам плана автоматически снимать признак Выполнять, где по данным это уже оправдано. Строки плана не удаляются. Перечень видов операций, для которых допускается такая оптимизация, задаётся в регистре ВидыОптимизируемыхРегламентныхОперацийДУ, а не только «зашит» в коде.

С точки зрения пользователя. Регламентное закрытие дня по большому числу однотипных портфелей пула «розница ДУ» занимает меньше времени: система не запускает те регламентные операции, которые по смыслу данных на этот день для конкретного портфеля не нужны (например, нет объектов для начисления или погашения). Пользователь по-прежнему видит полный перечень строк плана на день; отключённые позиции остаются в списке, но помечены как невыполняемые, без ручного снятия галочек ради ускорения. Дополнительно, если для группы операций после такого пересчёта не осталось ни одной строки к выполнению и документа плана за этот день ещё не было, система не создаёт «пустой» документ ПланРегламентныхОперацийДУ и не гоняет по нему лишние шаги закрытия (раздел 9): в журналах и списках документов меньше шума, фоновая нагрузка ниже.

Документ. Описывает цели, состав RduPF, место вызова фильтра в типовой цепочке, модуль менеджера РС, пошаговый алгоритм (сверка с кодом), отбор портфелей и приёмку. Тексты запросов на встроенном языке — в модуле менеджера регистра ВидыОптимизируемыхРегламентныхОперацийДУ.

Условия включения. Заполнена константа ПулРозницаДУ и в плане на день только портфели с Портфель.Пул, равным этой константе; иначе таблица плана не меняется (раздел 6, шаги 6.1–6.2).

Цепочка смысла. После ПланРеглОпераций и до ПланРеглОперацийПоДням.Вставить вызывается ОтфильтроватьПланРеглОперацийНаДень (раздел 4); по своду строк с Выполнять = 1 и видам из РС пересчитывается признак выполнения с учётом отбора портфелей по виду операции. Далее при исполнении плана срабатывает перехват СформироватьРеглОперацииПоГруппе (раздел 9): при отсутствии существующего плана и нуле выполняемых строк по группе — без создания документа плана и без вызова СоздатьПланРегламентныхОперацийДУ в этом случае.

Эффекты для эксплуатации

  • Меньше нагрузка при однородных пакетах портфелей пула «розница ДУ» при включённой настройке.
  • Без ручного снятия операций в плане ради этой оптимизации.
  • Полная картина плана сохраняется; отключённые строки не идут в исполнение.
  • Набор оптимизируемых видов ведётся в данных (РС).
  • Меньше лишних документов ПланРегламентныхОперацийДУ и связанных с ними проходов закрытия, когда выполнять по группе нечего и плана ещё не существовало.
  • Более предсказуемое время ночного и массового закрытия при типовых портфелях розницы.

3. Цели и границы

Согласовано с разделом 1; здесь — формальные цели и явные границы объёма.

3.1. Цели

  • Ускорить массовое закрытие в сценарии «розница ДУ / РДУ» за счёт снятия признака выполнения (Выполнять в таблице плана как число 0/1) без удаления строк.
  • Перечень видов операций, для которых допускается оптимизация, вести в РС ВидыОптимизируемыхРегламентныхОперацийДУ.
  • Условие «только пул розницы ДУ»: константа ПулРозницаДУ и однородность портфелей в таблице плана за день.

3.2. Границы

  • Уже в расширении: константа ПулРозницаДУ; РС ВидыОптимизируемыхРегламентныхОперацийДУ с измерением, формами списка и записи (комментарии в модулях форм); заимствование справочников ВидыОперацийЗакрытияПериода, Пул и обработки ГрупповоеВыполнениеЗакрытияПериодов с перехватом; вызов из маркера #Вставка процедуры ОтфильтроватьПланРеглОперацийНаДень менеджера РС; в модуле менеджера РС области ОтборПортфелейДляСохраненияВыполненияВПлане и ФильтрацияПланаРегламентныхОпераций (см. разделы 5 и 6).
  • Осталось по данным и эксплуатации: первичное наполнение РС перечнем видов по таблице 8.1 (сопровождение ИБ; согласовать с владельцем метаданных и эксплуатацией); регрессионные сценарии приёмки (раздел 10) на рабочих данных.
  • Вне объёма: прямое изменение типовой конфигурации; однопоточная ветка без кэша ПланРеглОперацийПоДням (см. раздел 4.3).

4. Встраивание в типовую цепочку

Структура таблицы плана на день, место вызова фильтра до ПланРеглОперацийПоДням.Вставить и граница по однопоточной ветке.

4.1. Колонки таблицы плана

После ПланРеглОпераций для дня используется ТаблицаЗначений для фильтра и вставки в соответствие ПланРеглОперацийПоДням:

  • Выполнять (0/1) — единственная колонка, которую меняет ОтфильтроватьПланРеглОперацийНаДень;
  • Портфель — проверка однородности пула (6.2);
  • ВидОперации, ВремяРеглОпераций, Родитель — ключ строки и вход в отбор портфелей (6.3–6.4, 8).

Дальнейшее использование плана типовой конфигурацией должно оставаться согласованным с изменённым Выполнять; проверка — в разделе 10.

4.2. Перехват и вызов процедуры

В заимствованной обработке ГрупповоеВыполнениеЗакрытияПериодов после получения таблицы плана на день и до ПланРеглОперацийПоДням.Вставить выполняется фильтр — так план корректируется до запуска операций по строкам (раздел 1).

Внутри #Вставка / #КонецВставки модуля объекта вызывается ОтфильтроватьПланРеглОперацийНаДень(День, тПланРеглОперацийПоДням) менеджера РС ВидыОптимизируемыхРегламентныхОперацийДУ. После выхода из процедуры типовой код вызывает ПланРеглОперацийПоДням.Вставить(День, тПланРеглОперацийПоДням) без изменений.

Перехват: &ИзменениеИКонтроль("ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей"); процедура в расширении — RduPF_ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей (тело типовое плюс вставка). При переименовании — синхронно модуль объекта и этот подпункт.

4.3. Ограничение реализации

Перехват и фильтрация относятся к ветке с кэшем плана по дням в ПланРеглОперацийПоДням. Однопоточное закрытие без такого кэша в объём расширения не входит (согласовано с 3.2).

5. Модуль менеджера РС

Модуль менеджера ВидыОптимизируемыхРегламентныхОперацийДУ: свод, РС, отбор портфелей, смена Выполнять. ОтфильтроватьПланРеглОперацийНаДень — область ФильтрацияПланаРегламентныхОпераций, вызов из раздела 4; шаги — раздел 6. Отбор портфелей — ОтборПортфелейДляСохраненияВыполненияВПлане (п. 5.1).

5.1. Область отбора портфелей

В модуле менеджера регистра ВидыОптимизируемыхРегламентныхОперацийДУ в области #Область ОтборПортфелейДляСохраненияВыполненияВПлане размещены вспомогательные функции с текстами запросов, экспортная ПолучитьПортфелиДляСохраненияВыполненияВПлане(МассивПортфелей, День, ВидОперации) и ветвление по предопределённым видам операций. Сверка предопределённых ссылок с фактической базой выполняется при приёмке и регрессии. Для объединения двух массивов портфелей без дублей (ветка частичного погашения) используется ОбщегоНазначенияКлиентСервер.ДополнитьМассив с третьим параметром Истина, а не отдельная функция в расширении.

5.2. Экспортная процедура фильтра плана

Экспортная процедура ОтфильтроватьПланРеглОперацийНаДень размещается в модуле после области отбора портфелей, вызывается из перехвата (между #Вставка и #КонецВставки) в ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей. Тело соответствует разделу 6 и вызывает ПолучитьПортфелиДляСохраненияВыполненияВПлане на шаге корректировки плана. Ранний выход без изменений таблицы — при незаполненной константе пула или неоднородном пуле портфелей в плане (проверки 6.1–6.2).

6. Алгоритм фильтра плана

Нормативное описание ОтфильтроватьПланРеглОперацийНаДень и ВТ: свод по Выполнять = 1 с соединением к РС в запросе; корректировка Выполнять — пакетом с левым соединением к ВТ портфелей из ПолучитьПортфелиДляСохраненияВыполненияВПлане. Роль «вид в РС» выполняет соединение на шаге свода, отдельная функция не выделяется. Детализирует раздел 1; при смене алгоритма обновляют этот раздел и код модуля менеджера согласованно.

Статус: шаги 6.1–6.5 реализованы в модуле менеджера РС в области ФильтрацияПланаРегламентныхОпераций. Функция ПолучитьПортфелиДляСохраненияВыполненияВПлане для шага 6.4 находится в области ОтборПортфелейДляСохраненияВыполненияВПлане (раздел 5.1).

6.1. ПРОВЕРКА 1

Сразу в начале процедуры: записать в локальную переменную (имя на усмотрение разработчика, ниже — ЗначениеКонстантыПулРозницаДУ) результат вызова ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ"); первый параметр метода — строковое имя константы (ИмяКонстанты). Проверить заполненность, например ЗначениеЗаполнено(ЗначениеКонстантыПулРозницаДУ). Далее в проверке 2 и в запросах использовать это же значение переменной. Если константа не заполнена — выход без изменений тПланРеглОперацийПоДням.

ЗначениеКонстантыПулРозницаДУ = ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ");

6.2. ПРОВЕРКА 2

У всех строк таблицы тПланРеглОперацийПоДням значение Портфель.Пул должно быть строго равно значению константы ПулРозницаДУ (тому же значению, что получено на шаге 6.1 через ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ")). Если условие не выполняется — выход без изменений. Рекомендация по реализации: выполнить проверку запросом к временной таблице, полученной помещением плана (минимизировать обращения к реквизитам ссылок в цикле на стороне встроенного языка); в параметрах запроса передавать эталон пула из локальной переменной шага 6.1.

6.3. Подготовка свода (после успешных проверок)

Эквивалент нормативных шагов «план во ВТ — отбор Выполнять = 1 — соединение с РС — уникальные ключи в ТЗ свода» в рабочем коде: один запрос с МенеджерВременныхТаблиц, затем дополнительные выборки из тех же ВТ.

  1. ВТ_План — помещение тПланРеглОперацийПоДням (пять полей плана; табличный параметр только здесь).
  2. ВТ_СводДопустимыеКлючи — ВЫБРАТЬ РАЗЛИЧНЫЕ из ВТ_План при Выполнять = 1 (в нормативном тексте встречается «Выполнить = 1»; в конфигурации колонка — Выполнять, число 0/1) и внутреннем соединении с РегистрСведений.ВидыОптимизируемыхРегламентныхОперацийДУ по ВидОперации.
  3. ВТ_СводКлючиСНомеромСтроки — те же ключи с колонкой НомерСтрокиСвода через АВТОНОМЕРЗАПИСИ() при ПОМЕСТИТЬ (в запросе помещения без явного УПОРЯДОЧИТЬ ПО по полям ключа; порядок строк и присвоение номеров определяет СУБД); по выборке из этой ВТ формируется ТЗСвод для кода на встроенном языке; для стабильного порядка обхода свода при выгрузке используется отдельная выборка с УПОРЯДОЧИТЬ ПО НомерСтрокиСвода.
  4. Отдельный запрос к ВТ_План и ВТ_СводКлючиСНомеромСтроки: портфели по строкам свода с группировкой по номеру строки свода и портфелю (ТЗПортфелиПоСтрокамСвода).
  5. На встроенном языке: колонки МассивПортфелей и День в ТЗСвод; сопоставление строк свода и портфелей через Соответствие по НомерСтрокиСвода. Колонку НомерСтрокиСвода в выгрузке свода удалять не обязательно.

6.4. Цикл по ТЗ свода

Для каждой строки свода:

  • По отбору ВидОперации, ВремяРеглОпераций, Родитель получить массив портфелей из плана (в реализации — запросом к ВТ_План и своду с последующим заполнением массивов на встроенном языке; допустим эквивалент через НайтиСтроки по тПланРеглОперацийПоДням).
  • Добавить в строку свода колонку МассивПортфелей и записать туда полученный массив.

Если ЗначениеЗаполнено(СтрокаТЗ.Родитель) Тогда

Далее для строки свода вызвать ПолучитьПортфелиДляСохраненияВыполненияВПлане(МассивПортфелей, День, ВидОперации) Экспорт. На выходе функции возможны три случая (для понимания последующего запроса): тот же состав портфелей; пустой массив; подмножество входного массива.

6.5. Пакетный запрос корректировки Выполнять (на одну итерацию цикла по строке свода)

Один текст запроса создаётся до цикла; в цикле меняются параметры ВидОперацииСвода и МассивПортфелейОставить. Табличный параметр плана — только в первом подзапросе пакета (требование к пакетам с табличными параметрами).

  1. ВТ_ИсходныйПлан — из &ТаблицаПлана (в цикле в параметр передаётся буфер НоваяТаблицаПлана, см. ниже; не обязательно та же ссылка, что у тПланРеглОперацийПоДням вызывающего кода).
  2. ВТ_Портфели — из Справочник.Портфели, отбор Ссылка В (&МассивПортфелейОставить) (ответ ПолучитьПортфелиДляСохраненияВыполненияВПлане: портфели, для которых выполнение в плане сохраняется).
  3. Итоговый ВЫБРАТЬ без промежуточных ВТ_ТаблицаПлана1 / ВТ_ТаблицаПлана2: из ВТ_ИсходныйПлан как П1 — левое соединение с ВТ_Портфели по Портфель. Поле Выполнять — одним ВЫБОР (эквивалент нормативной формулы с признаком «потенциально изменяемая строка»):
    ВЫБОР КОГДА П1.Выполнять = 1 И П1.ВидОперации = &ВидОперацииСвода И ПортфелиОставить.Ссылка ЕСТЬ NULL ТОГДА 0 ИНАЧЕ П1.Выполнять КОНЕЦ
  4. Буфер и запись в план вызывающего кода: перед циклом по своду — НоваяТаблицаПлана = тПланРеглОперацийПоДням.Скопировать(). В каждой итерации: НоваяТаблицаПлана = Запрос.Выполнить().Выгрузить(). После цикла: тПланРеглОперацийПоДням.Очистить() и для каждой строки буфера Добавить() + ЗаполнитьЗначенияСвойств в приёмник (в синтакс-помощнике у ТаблицаЗначений нет метода загрузки целой таблицы из другой; присваивание параметру процедуры новой ссылки не обновляет переменную вызывающего кода).

Цикл по строкам ТЗ свода повторяется; на каждой итерации обновляется буфер НоваяТаблицаПлана (кумулятивное ужесточение Выполнять). Порядок обхода строк свода согласовать с отсутствием взаимного пересечения изменений по одной строке плана в разных итерациях (при группировке по виду, времени и родителю строки свода не дублируют один и тот же ключ, если типовая таблица это гарантирует).

Уточнение: в пакете шага 6.5 условие смены Выполнять на 0 использует совпадение только ВидОперации с текущей строкой свода (параметр ВидОперацииСвода), без дополнительного отбора по ВремяРеглОпераций и Родитель в этом ВЫБОР. Свод по-прежнему строится по полному ключу (раздел 6.3–6.4). При необходимости сужения зоны корректировки — отдельная доработка и регрессия.

7. Описание цепочки фильтрации

7.1. Словесное описание

При массовом закрытии периода типовая обработка для каждого дня строит таблицу: какие регламентные операции по каким портфелям предполагается выполнить. Это обычный «план на день»: строки не удаляются, у каждой есть признак «выполнять или нет».

Идея доработки: перед тем как этот план уйдёт в общую память на день и дальше в исполнение, расширение даёт системе шанс «перечитать» план с точки зрения уже известных данных. Если по константе и пулу портфелей понятно, что мы в целевом сценарии (розница ДУ), и вид операции разрешён к оптимизации в отдельном регистре, то для части строк можно заранее снять признак выполнения. Так не запускается заведомо лишняя работа, при этом картина плана для пользователя и отчётности сохраняется.

Для каждого сочетания «вид операции — время — родительская строка» в плане система собирает список портфелей и спрашивает у специальной функции: для каких из этих портфелей операцию в плане всё же нужно оставить включённой. Ответ может быть «все», «никого», «только часть». Тогда в запросе к плану сравнивают каждую строку с этим списком: если операция была помечена к выполнению, но портфеля нет в списке «оставить», признак выполнения для этой строки снимается. Остальные строки и другие виды операций не трогаются в рамках этой итерации.

Такой порядок повторяется по всем строкам свода (по одному ключу за раз), буфер плана обновляется накопительно; в конце таблица возвращается в типовой код, и закрытие идёт дальше как раньше. Подробные правила запросов и полей — в разделе 6, ветвление по видам — в разделе 8.

Отдельно от фильтра таблицы плана, после того как план уже попал в исполнение закрытия по портфелю и дню, расширение может сократить работу на этапе создания документа ПланРегламентныхОперацийДУ по группе операций: если выполнять по срезу плана нечего и нового плана ещё не существовало, лишний документ и вызов проведения не выполняются (раздел 9).

9. Пропуск создания документа плана при нуле выполняемых операций

Реализация в рабочем каталоге расширения RduPF: перехват процедуры СформироватьРеглОперацииПоГруппе модуля объекта заимствованной обработки ГрупповоеВыполнениеЗакрытияПериодов.

9.1. Назначение

После того как фильтр плана (раздел 4, раздел 6) обнулил признак Выполнять по части строк, для очередной группы родителя (Родитель) типовой код мог бы создать заготовку документа ПланРегламентныхОперацийДУ и вызывать ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ даже при том, что ни одна строка среза плана для этой группы не помечена к выполнению. Доработка исключает лишние шаги в этом случае: если существующий план за дату и группу не найден, а выполнять нечего — дальнейшая обработка группы не выполняется.

9.2. Перехват и место вставки

  • Подписка: &ИзменениеИКонтроль("СформироватьРеглОперацииПоГруппе").
  • Процедура в расширении: RduPF_СформироватьРеглОперацииПоГруппе(Портфель, ДатаЗакрытия, ТекГруппа, Отказ, ДопПараметры) — тело совпадает с типовым по построению РеглОперацииПлан, ветвлению по ПоВыбраннымАктивам, определению ВыполняемыйПлан, с добавлением блока между определением ВыполняемыйПлан и вызовом ВыполняемыйПлан(ДатаЗакрытия) / распроведением существующего плана.
  • Сдвиг строки: присвоение РеглОперации = РеглОперацииПлан.Скопировать(Новый Структура("Родитель", ГруппаРегламентныхОпераций.Родитель)) выполняется до проверки «есть ли выполняемые операции»; дублирующее присвоение после вставки удалено (в отчёте сравнения с типовым модулем — маркеры #Вставка / #Удаление).

9.3. Условие раннего выхода

Одновременно:

  • ВыполняемыйПлан = Неопределено (документ плана за дату и группу ещё не существует в смысле типового НайтиПланРегламентныхОперацийДУ);
  • в таблице РеглОперации для текущей группы нет ни одной строки с Выполнять, эквивалентной истине — в реализации используется отбор НайтиСтроки(Новый Структура("Выполнять", 1)) (колонка плана — число 0/1, согласовано с 4.1 и 6.3).

При выполнении условия выполняется Возврат из процедуры RduPF_СформироватьРеглОперацииПоГруппе без вызова ВыполняемыйПлан(ДатаЗакрытия), без распроведения и без СоздатьПланРегламентныхОперацийДУ для этой ситуации.

Внимание (семантика Возврат): оператор завершает всю процедуру СформироватьРеглОперацииПоГруппе, а не только текущую итерацию цикла Для каждого ГруппаРегламентныхОпераций. Если по замыслу нужно пропускать только «пустую» группу и продолжать остальные группы того же вызова, вместо Возврат следует использовать Продолжить цикла. Текущая зафиксированная реализация — с Возврат; при смене поведения обновить этот подпункт и регрессию.

9.4. Что не затрагивается

  • Ветка ПоВыбраннымАктивам и требование уже проведённого «полного» плана — без изменений логики до вставки.
  • Ситуация ВыполняемыйПлан <> Неопределено (план уже есть): распроведение и вызов СоздатьПланРегламентныхОперацийДУ выполняются по-прежнему; отключение всех строк в срезе при существующем плане в этой вставке отдельно не обрабатывается.
  • Модуль ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ в базовой конфигурации не изменяется; оптимизация — на уровне вызова из обработки закрытия.

9.5. Связь с остальным ТЗ

Эффект проявляется после того, как таблица плана за день прошла фильтр ОтфильтроватьПланРеглОперацийНаДень в многопоточной ветке (раздел 7): при полном обнулении Выполнять по строкам группы для нового плана документ плана не создаётся. Для однопоточного закрытия без кэша ПланРеглОперацийПоДням фильтр по 4.3 в расширении не применяется; поведение перехвата СформироватьРеглОперацииПоГруппе зависит от того, вызывается ли эта процедура — см. типовой код обработки.

10. Критерии приёмки

  1. Незаполненная ПулРозницаДУ или неоднородный пул портфелей в тПланРеглОперацийПоДням: колонка Выполнять после вызова фильтра совпадает с входом.
  2. При выполненных проверках 1-2 строки по видам, отсутствующим в РС ВидыОптимизируемыхРегламентныхОперацийДУ, не меняют Выполнять на итерациях, относящихся к другим видам (согласованность кумулятивных проходов).
  3. Для вида из РС: после полного прохода цикла по своду строки с портфелем, не попавшим в «сохранить» по результату функции, имеют Выполнять = 0; остальные строки этого вида в шаге остаются с 1.
  4. Пустой ответ функции отбора портфелей для вида из РС приводит к обнулению Выполнять у всех строк плана с этим видом в рамках соответствующей итерации (логика ЕСТЬ NULL в левом соединении).
  5. Документ ПланРегламентныхОперацийДУ и типовой отбор к исполнению согласованы с итоговой таблицей плана после фильтра (раздел 1, колонки в 4.1).
  6. При сочетании условий из раздела 9 (нет существующего плана за дату и группу, в срезе РеглОперации нет строк с Выполнять, эквивалентным истине) процедура RduPF_СформироватьРеглОперацииПоГруппе не создаёт документ ПланРегламентныхОперацийДУ и не вызывает СоздатьПланРегламентныхОперацийДУ; регрессия фиксирует семантику Возврат (см. примечание в 9.3).
  7. После изменений в конфигураторе: успешная загрузка XML расширения в ИБ (Srvr="localhost", Ref="WIM_FIN") и актуальный собранный файл RduPF.cfe в каталоге Расширения.
  8. Код отбора портфелей для плана присутствует в модуле менеджера РС и компилируется вместе с расширением.
  9. Регистр ВидыОптимизируемыхРегламентныхОперацийДУ на целевой ИБ первично заполнен: в нём есть записи по всем пяти видам из таблицы 8.1 (измерение ВидОперации — согласованные ссылки на элементы ВидыОперацийЗакрытияПериода в этой базе; действие сопровождения / поддержки ИБ зафиксировано).
  10. Тело ОтфильтроватьПланРеглОперацийНаДень в модуле менеджера РС соответствует разделу 6 настоящего ТЗ и проходит сценарии приёмки; при изменении алгоритма обновляют раздел 6 и код согласованно.
