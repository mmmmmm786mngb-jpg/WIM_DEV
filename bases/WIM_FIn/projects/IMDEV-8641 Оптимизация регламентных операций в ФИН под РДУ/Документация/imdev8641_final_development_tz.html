2. Нормативный алгоритм (источник)

Описание разработки модуля менеджера нового регистра сведений и процедуры фильтра плана в настоящем документе приведено в соответствии с файлом ТЗ_на_модульМенеджера_новогоРС_ВидыОптимизируемыхРегламентныхОперацийДУ .txt (в корне проекта IMDEV-8641; в имени файла перед расширением допускается пробел). Отличия от раннего краткого ТЗ: в окончательном варианте свод строк по видам строится через временные таблицы запроса и соединение с РС в запросе; итоговая корректировка Выполнять выполняется одним пакетным запросом с левым соединением к ВТ портфелей, возвращённых функцией отбора портфелей; отдельная функция вида «есть ли вид в РС» в тексте нормативного файла не выделяется (роль РС выполняет соединение на шаге подготовки свода).

Соответствие коду расширения: функция отбора портфелей и вспомогательные запросы (вход для шагов нормативного алгоритма с вызовом ПолучитьПортфелиДляСохраненияВыполненияВПлане) реализованы в модуле менеджера РС; пошаговый алгоритм разд. 6 для процедуры ОтфильтроватьПланРеглОперацийНаДень в коде пока не внедрён (см. разд. 6, статус).

5. Модуль менеджера РС: состав и перенос кода

Процедура ОтфильтроватьПланРеглОперацийНаДень объявлена и вызывается из перехвата, но тело фильтра пока заглушка (см. разд. 1 и 4.2). Раздел 6 задаёт целевую реализацию этой процедуры. Блок отбора портфелей (разд. 5.1) в модуле менеджера уже перенесён из черновика.

5.1. Блок из черновика (выполнено)

В модуль менеджера регистра ВидыОптимизируемыхРегламентныхОперацийДУ перенесён код из файла get_portfolios_for_plan_execution.bsl в область #Область ОтборПортфелейДляСохраненияВыполненияВПлане (без вложенной области «СлужебныеПроцедурыИФункции» черновика): вспомогательные функции с текстами запросов, экспортная ПолучитьПортфелиДляСохраненияВыполненияВПлане(МассивПортфелей, День, ВидОперации) и ветвление по предопределённым видам операций. Сверка предопределённых ссылок с фактической базой — при приёмке и регрессии. Для объединения двух массивов портфелей без дублей (ветка частичного погашения) используется ОбщегоНазначенияКлиентСервер.ДополнитьМассив с третьим параметром Истина, а не отдельная функция в расширении.

5.2. Новая экспортная процедура фильтра

В коде расширения используется экспортная процедура ОтфильтроватьПланРеглОперацийНаДень модуля менеджера РС (размещается в модуле после области отбора портфелей), вызываемая из перехвата (между #Вставка и #КонецВставки) в ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей. На этапе заглушки тело процедуры не меняет таблицу плана; далее — реализация по разделу 6 с использованием уже готовой ПолучитьПортфелиДляСохраненияВыполненияВПлане.

6. Процедура фильтра плана (пошагово по нормативному алгоритму)

Статус реализации в коде расширения: шаги 6.1–6.5 ниже относятся к процедуре ОтфильтроватьПланРеглОперацийНаДень; по состоянию на актуализацию ТЗ они не внедрены (в модуле менеджера РС — заглушка). Функция ПолучитьПортфелиДляСохраненияВыполненияВПлане и вспомогательный код для шага 6.4 уже есть в том же модуле (разд. 5.1).

6.1. ПРОВЕРКА 1

Сразу в начале процедуры: записать в локальную переменную (имя на усмотрение разработчика, ниже — ЗначениеКонстантыПулРозницаДУ) результат вызова ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ"); первый параметр метода — строковое имя константы (ИмяКонстанты). Проверить заполненность, например ЗначениеЗаполнено(ЗначениеКонстантыПулРозницаДУ). Далее в проверке 2 и в запросах использовать это же значение переменной. Если константа не заполнена — выход без изменений тПланРеглОперацийПоДням.

ЗначениеКонстантыПулРозницаДУ = ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ");

6.2. ПРОВЕРКА 2

У всех строк таблицы тПланРеглОперацийПоДням значение Портфель.Пул должно быть строго равно значению константы ПулРозницаДУ (тому же значению, что получено на шаге 6.1 через ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ")). Если условие не выполняется — выход без изменений. Рекомендация по реализации: выполнить проверку запросом к временной таблице, полученной помещением плана (минимизировать обращения к реквизитам ссылок в цикле на стороне встроенного языка); в параметрах запроса передавать эталон пула из локальной переменной шага 6.1.

6.3. Подготовка данных в запросе (после успешных проверок)

  1. Поместить тПланРеглОперацийПоДням во временную таблицу запроса (пять полей плана).
  2. Выбрать во вторую временную таблицу строки с Выполнять = 1 (в нормативном тексте указано «Выполнить = 1»; в конфигурации колонка плана — Выполнять, тип число 0/1; при реализации использовать фактическое имя и согласованное сравнение с ненулём).
  3. Соединить с регистром ВидыОптимизируемыхРегламентныхОперацийДУ по ВидОперации (остаются только строки плана по видам, участвующим в оптимизации).
  4. В отдельной временной таблице сгруппировать по ВидОперации, ВремяРеглОпераций, Родитель и выгрузить результат во вспомогательную ТаблицаЗначений (далее «ТЗ свода»).

6.4. Цикл по ТЗ свода

Для каждой строки свода:

  • По отбору ВидОперации, ВремяРеглОпераций, Родитель получить массив портфелей из плана (запросом или НайтиСтроки по тПланРеглОперацийПоДням — на усмотрение разработчика при сохранении эквивалентности результата).
  • Добавить в строку свода колонку МассивПортфелей и записать туда полученный массив.
  • Добавить колонку День в строку свода и вычислить по правилу из нормативного файла (дата-время момента для вызова функции отбора портфелей):
Если ЗначениеЗаполнено(СтрокаТЗ.Родитель) Тогда
    СтрокаТЗ.День = Дата(Формат(День, "ДФ=""ггггММдд""") + Формат(СтрокаТЗ.Родитель.ВремяРеглОпераций,"ДФ=""ЧЧммсс"""));
Иначе
    СтрокаТЗ.День = Дата(Формат(День, "ДФ=""ггггММдд""") + Формат(ПолныеПрава.ОкончаниеРабочегоДня(),"ДФ=""ЧЧммсс"""));
КонецЕсли;

Далее для строки свода вызвать ПолучитьПортфелиДляСохраненияВыполненияВПлане(МассивПортфелей, День, ВидОперации) Экспорт. На выходе функции возможны три случая (для понимания последующего запроса): тот же состав портфелей; пустой массив; подмножество входного массива.

6.5. Пакетный запрос корректировки Выполнять (на одну итерацию цикла по строке свода)

Выполнить запрос, в котором:

  1. Временной таблицей в начале помещается актуальная тПланРеглОперацийПоДням (пять полей).
  2. В следующей ВТ (ВТ_ТаблицаПлана1) выбрать все поля плана и добавить поле-признак «потенциально изменяемая строка» для текущего шага цикла: в нормативном тексте указано как сравнение с параметром &ВидОперации с именем колонки ПотенциальноИзменяемаяСтрока (реализовать как булево условие «строка относится к обрабатываемому в этой итерации виду операции»).
  3. Построить ВТ_Портфели из справочника Портфели с отбором по входящему массиву портфелей, возвращённому функцией ПолучитьПортфелиДляСохраненияВыполненияВПлане (портфели, для которых выполнение в плане сохраняется).
  4. Построить ВТ_ТаблицаПлана2: соединение строк ВТ_ТаблицаПлана1 с ВТ_Портфели по Портфель типа ЛЕВОЕ. Поле Выполнять заменить выражением:
    ВЫБОР КОГДА ВТ_ТаблицаПлана1.Выполнять = 1 И ВТ_ТаблицаПлана1.ПотенциальноИзменяемаяСтрока И ВТ_Портфели.Ссылка ЕСТЬ NULL ТОГДА 0 ИНАЧЕ ВТ_ТаблицаПлана1.Выполнять КОНЕЦ
  5. Результат запроса выгрузить в тПланРеглОперацийПоДням, заменив таблицу новой версией (отличаться по смыслу могут только значения колонки Выполнять).

Цикл по строкам ТЗ свода повторяется; на каждой итерации таблица плана пересобирается из результата запроса (кумулятивное ужесточение Выполнять по видам из свода). Порядок обхода строк свода должен быть согласован с отсутствием взаимного пересечения изменений по одной и той же строке плана в разных итерациях (при группировке по виду, времени и родителю строки свода не дублируют один и тот же ВидОперации с разными ключами, если типовая таблица это гарантирует).

8. Связь с перехватом в RduPF

Внутри маркеров #Вставка / #КонецВставки модуля объекта ГрупповоеВыполнениеЗакрытияПериодов вызывается экспортная процедура модуля менеджера РС ОтфильтроватьПланРеглОперацийНаДень(День, тПланРеглОперацийПоДням). После выхода из процедуры типовой код выполняет ПланРеглОперацийПоДням.Вставить(День, тПланРеглОперацийПоДням) без изменений.

В расширении перехват оформлен как &ИзменениеИКонтроль("ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей"); имя процедуры в модуле объекта — RduPF_ВыполнитьМногопоточноеЗакрытиеПериодовПортфелей (тело совпадает с типовым, плюс маркер вставки).

Имя процедуры зафиксировано в коде расширения; при необходимости переименования — синхронно обновить вызов в модуле объекта обработки и этот раздел.

9. Черновик запросов и ветвление по видам

Исходный текст запросов и ветвления: get_portfolios_for_plan_execution.bsl (каталог Скрипты/bsl); рабочая копия — модуль менеджера РС ВидыОптимизируемыхРегламентныхОперацийДУ, область ОтборПортфелейДляСохраненияВыполненияВПлане. Экспортная функция ПолучитьПортфелиДляСохраненияВыполненияВПлане ветвится по предопределённым элементам ВидыОперацийЗакрытияПериода; для прочих видов возвращается входной массив (строки плана по таким видам в итоговом запросе разд. 6 не получают Выполнять = 0 из-за ветки ВТ_Портфели, так как соединение даёт строку для каждого портфеля). Детализация по веткам: таблица в imdev8641_brief_development_tz.html (раздел про запросы) и файлы query_branch_*.md.

10. Критерии приёмки (минимум)

  1. Незаполненная ПулРозницаДУ или неоднородный пул портфелей в тПланРеглОперацийПоДням: колонка Выполнять после вызова фильтра совпадает с входом.
  2. При выполненных проверках 1-2 строки по видам, отсутствующим в РС ВидыОптимизируемыхРегламентныхОперацийДУ, не меняют Выполнять на итерациях, относящихся к другим видам (согласованность кумулятивных проходов).
  3. Для вида из РС: после полного прохода цикла по своду строки с портфелем, не попавшим в «сохранить» по результату функции, имеют Выполнять = 0; остальные строки этого вида в шаге остаются с 1.
  4. Пустой ответ функции отбора портфелей для вида из РС приводит к обнулению Выполнять у всех строк плана с этим видом в рамках соответствующей итерации (логика ЕСТЬ NULL в левом соединении).
  5. Документ ПланРегламентныхОперацийДУ и типовой отбор к исполнению согласованы с итоговой таблицей плана (как в filter_plan_regl_operations_table_integration.md).
  6. После изменений в конфигураторе: успешная загрузка XML расширения в ИБ (Srvr="localhost", Ref="WIM_FIN") и актуальный файл RduPF.cfe в каталоге Расширения (навыки db-load-xml, db-dump-cf).
  7. Код отбора портфелей для плана присутствует в модуле менеджера РС и компилируется вместе с расширением; расхождения с черновиком get_portfolios_for_plan_execution.bsl устранять в пользу модуля менеджера или синхронно обновлять черновик.
