2. Нормативный алгоритм (источник)

Описание разработки модуля менеджера нового регистра сведений и процедуры фильтра плана в настоящем документе приведено в соответствии с файлом ТЗ_на_модульМенеджера_новогоРС_ВидыОптимизируемыхРегламентныхОперацийДУ .txt (в корне проекта IMDEV-8641; в имени файла перед расширением допускается пробел). Отличия от раннего краткого ТЗ: в окончательном варианте свод строк по видам строится через временные таблицы запроса и соединение с РС в запросе; итоговая корректировка Выполнять выполняется одним пакетным запросом с левым соединением к ВТ портфелей, возвращённых функцией отбора портфелей; отдельная функция вида «есть ли вид в РС» в тексте нормативного файла не выделяется (роль РС выполняет соединение на шаге подготовки свода).

Соответствие коду: отбор портфелей (ПолучитьПортфелиДляСохраненияВыполненияВПлане и вспомогательные запросы) — в модуле менеджера РС расширения. Алгоритм разд. 6 для ОтфильтроватьПланРеглОперацийНаДень реализован в draft_otfiltrovat_plan_regl_operatsiy_na_den.bsl; в выгрузке расширения процедура до переноса тела остаётся заглушкой (разд. 1, 4.2, 6).

6. Процедура фильтра плана (пошагово по нормативному алгоритму)

Статус: шаги 6.1–6.5 ниже реализованы в draft_otfiltrovat_plan_regl_operatsiy_na_den.bsl (перенос в модуль менеджера РС — разд. 4.2). В выгрузке расширения процедура ОтфильтроватьПланРеглОперацийНаДень до переноса — заглушка. Функция ПолучитьПортфелиДляСохраненияВыполненияВПлане для шага 6.4 — в модуле менеджера РС (разд. 5.1).

6.1. ПРОВЕРКА 1

Сразу в начале процедуры: записать в локальную переменную (имя на усмотрение разработчика, ниже — ЗначениеКонстантыПулРозницаДУ) результат вызова ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ"); первый параметр метода — строковое имя константы (ИмяКонстанты). Проверить заполненность, например ЗначениеЗаполнено(ЗначениеКонстантыПулРозницаДУ). Далее в проверке 2 и в запросах использовать это же значение переменной. Если константа не заполнена — выход без изменений тПланРеглОперацийПоДням.

ЗначениеКонстантыПулРозницаДУ = ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ");

6.2. ПРОВЕРКА 2

У всех строк таблицы тПланРеглОперацийПоДням значение Портфель.Пул должно быть строго равно значению константы ПулРозницаДУ (тому же значению, что получено на шаге 6.1 через ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ")). Если условие не выполняется — выход без изменений. Рекомендация по реализации: выполнить проверку запросом к временной таблице, полученной помещением плана (минимизировать обращения к реквизитам ссылок в цикле на стороне встроенного языка); в параметрах запроса передавать эталон пула из локальной переменной шага 6.1.

6.3. Подготовка свода (после успешных проверок)

Эквивалент нормативных шагов «план во ВТ — отбор Выполнять = 1 — соединение с РС — уникальные ключи в ТЗ свода» в черновике: один запрос с МенеджерВременныхТаблиц, затем дополнительные выборки из тех же ВТ.

  1. ВТ_План — помещение тПланРеглОперацийПоДням (пять полей плана; табличный параметр только здесь).
  2. ВТ_СводДопустимыеКлючи — ВЫБРАТЬ РАЗЛИЧНЫЕ из ВТ_План при Выполнять = 1 (в нормативном тексте встречается «Выполнить = 1»; в конфигурации колонка — Выполнять, число 0/1) и внутреннем соединении с РегистрСведений.ВидыОптимизируемыхРегламентныхОперацийДУ по ВидОперации.
  3. ВТ_СводКлючиСНомеромСтроки — те же ключи с колонкой НомерСтрокиСвода через АВТОНОМЕРЗАПИСИ() при ПОМЕСТИТЬ (упорядочивание по полям ключа); по выборке из этой ВТ формируется ТЗСвод для кода на встроенном языке.
  4. Отдельный запрос к ВТ_План и ВТ_СводКлючиСНомеромСтроки: портфели по строкам свода с группировкой по номеру строки свода и портфелю (ТЗПортфелиПоСтрокамСвода).
  5. На встроенном языке: колонки МассивПортфелей и День в ТЗСвод; сопоставление строк свода и портфелей через Соответствие по НомерСтрокиСвода. Колонку НомерСтрокиСвода в выгрузке свода удалять не обязательно.

6.4. Цикл по ТЗ свода

Для каждой строки свода:

  • По отбору ВидОперации, ВремяРеглОпераций, Родитель получить массив портфелей из плана (в черновике — запросом к ВТ_План и своду с последующим заполнением массивов на встроенном языке; допустим эквивалент через НайтиСтроки по тПланРеглОперацийПоДням).
  • Добавить в строку свода колонку МассивПортфелей и записать туда полученный массив.
  • Добавить колонку День в строку свода и вычислить по правилу из нормативного файла (дата-время момента для вызова функции отбора портфелей):
Если ЗначениеЗаполнено(СтрокаТЗ.Родитель) Тогда
    СтрокаТЗ.День = Дата(Формат(День, "ДФ=""ггггММдд""") + Формат(СтрокаТЗ.Родитель.ВремяРеглОпераций,"ДФ=""ЧЧммсс"""));
Иначе
    СтрокаТЗ.День = Дата(Формат(День, "ДФ=""ггггММдд""") + Формат(ПолныеПрава.ОкончаниеРабочегоДня(),"ДФ=""ЧЧммсс"""));
КонецЕсли;

Далее для строки свода вызвать ПолучитьПортфелиДляСохраненияВыполненияВПлане(МассивПортфелей, День, ВидОперации) Экспорт. На выходе функции возможны три случая (для понимания последующего запроса): тот же состав портфелей; пустой массив; подмножество входного массива.

6.5. Пакетный запрос корректировки Выполнять (на одну итерацию цикла по строке свода)

Один текст запроса создаётся до цикла; в цикле меняются параметры ВидОперацииСвода и МассивПортфелейОставить. Табличный параметр плана — только в первом подзапросе пакета (требование к пакетам с табличными параметрами).

  1. ВТ_ИсходныйПлан — из &ТаблицаПлана (в цикле в параметр передаётся буфер НоваяТаблицаПлана, см. ниже; не обязательно та же ссылка, что у тПланРеглОперацийПоДням вызывающего кода).
  2. ВТ_Портфели — из Справочник.Портфели, отбор Ссылка В (&МассивПортфелейОставить) (ответ ПолучитьПортфелиДляСохраненияВыполненияВПлане: портфели, для которых выполнение в плане сохраняется).
  3. Итоговый ВЫБРАТЬ без промежуточных ВТ_ТаблицаПлана1 / ВТ_ТаблицаПлана2: из ВТ_ИсходныйПлан как П1 — левое соединение с ВТ_Портфели по Портфель. Поле Выполнять — одним ВЫБОР (эквивалент нормативной формулы с признаком «потенциально изменяемая строка»):
    ВЫБОР КОГДА П1.Выполнять = 1 И П1.ВидОперации = &ВидОперацииСвода И ПортфелиОставить.Ссылка ЕСТЬ NULL ТОГДА 0 ИНАЧЕ П1.Выполнять КОНЕЦ
  4. Буфер и запись в план вызывающего кода: перед циклом по своду — НоваяТаблицаПлана = тПланРеглОперацийПоДням.Скопировать(). В каждой итерации: НоваяТаблицаПлана = Запрос.Выполнить().Выгрузить(). После цикла: тПланРеглОперацийПоДням.Очистить() и для каждой строки буфера Добавить() + ЗаполнитьЗначенияСвойств в приёмник (в синтакс-помощнике у ТаблицаЗначений нет метода загрузки целой таблицы из другой; присваивание параметру процедуры новой ссылки не обновляет переменную вызывающего кода).

Цикл по строкам ТЗ свода повторяется; на каждой итерации обновляется буфер НоваяТаблицаПлана (кумулятивное ужесточение Выполнять). Порядок обхода строк свода согласовать с отсутствием взаимного пересечения изменений по одной строке плана в разных итерациях (при группировке по виду, времени и родителю строки свода не дублируют один и тот же ключ, если типовая таблица это гарантирует).

Уточнение по черновику: в пакете шага 6.5 условие смены Выполнять на 0 использует совпадение только ВидОперации с текущей строкой свода (параметр ВидОперацииСвода), без дополнительного отбора по ВремяРеглОпераций и Родитель в этом ВЫБОР. Свод по-прежнему строится по полному ключу (разд. 6.3–6.4). При необходимости сужения зоны корректировки — отдельная доработка и регрессия.

Внутри маркеров #Вставка / #КонецВставки модуля объекта ГрупповоеВыполнениеЗакрытияПериодов вызывается экспортная процедура модуля менеджера РС ОтфильтроватьПланРеглОперацийНаДень(День, тПланРеглОперацийПоДням). 10. Критерии приёмки (минимум)

  1. Незаполненная ПулРозницаДУ или неоднородный пул портфелей в тПланРеглОперацийПоДням: колонка Выполнять после вызова фильтра совпадает с входом.
  2. При выполненных проверках 1-2 строки по видам, отсутствующим в РС ВидыОптимизируемыхРегламентныхОперацийДУ, не меняют Выполнять на итерациях, относящихся к другим видам (согласованность кумулятивных проходов).
  3. Для вида из РС: после полного прохода цикла по своду строки с портфелем, не попавшим в «сохранить» по результату функции, имеют Выполнять = 0; остальные строки этого вида в шаге остаются с 1.
  4. Пустой ответ функции отбора портфелей для вида из РС приводит к обнулению Выполнять у всех строк плана с этим видом в рамках соответствующей итерации (логика ЕСТЬ NULL в левом соединении).
  5. Документ ПланРегламентныхОперацийДУ и типовой отбор к исполнению согласованы с итоговой таблицей плана (как в filter_plan_regl_operations_table_integration.md).
  6. После изменений в конфигураторе: успешная загрузка XML расширения в ИБ (Srvr="localhost", Ref="WIM_FIN") и актуальный файл RduPF.cfe в каталоге Расширения (навыки db-load-xml, db-dump-cf).
  7. Код отбора портфелей для плана присутствует в модуле менеджера РС и компилируется вместе с расширением; расхождения с черновиком get_portfolios_for_plan_execution.bsl устранять в пользу модуля менеджера или синхронно обновлять черновик.
  8. После переноса из draft_otfiltrovat_plan_regl_operatsiy_na_den.bsl: тело ОтфильтроватьПланРеглОперацийНаДень в модуле менеджера РС соответствует разд. 6 настоящего ТЗ и проходит те же сценарии приёмки.
