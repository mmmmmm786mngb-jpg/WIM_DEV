# Техническое задание: внешняя обработка — наличие документа по операции закрытия в разрезе пула

## 1. Введение

### 1.1. Назначение документа

Задать требования к **внешней обработке** (EPF), которая по **операционному дню**, **виду операции закрытия периода** из **ограниченного перечня** и отбору портфелей (**пул** и/или **явный список портфелей** для отладки на малой выборке) проверяет для **каждого портфеля попавшего в отбор**, создан ли **хотя бы один** подчинённый документ **ожидаемого типа**, связанный с документом **`ПланРегламентныхОперацийДУ`**, в соответствии с таблицей соответствий «операция — тип документа».

### 1.2. Объём работ (явное ограничение)

- Реализуется **только внешняя обработка**. Команды на форме плана, отчёт СКД, изменения в расширении конфигурации **в объём ТЗ не входят**.
- Перечень операций **не расширяется** произвольным выбором из всего справочника: пользователь может выбрать только те **виды операций**, для которых задано соответствие типу документа в материале п. 1.3.

### 1.3. Связанные материалы

- Таблица соответствий «операция — процедура — документ» (эталон для белого списка и типов документов): [operation_closure_procedure_document_map.html](operation_closure_procedure_document_map.html).
- Цепочка вызовов плана и критерия подчинённых в конфигурации: [plan_reg_oper_du_group_closure_chain.md](plan_reg_oper_du_group_closure_chain.md).

### 1.4. Термины

| Термин | Описание |
|--------|----------|
| Пул | Ссылка на элемент справочника пулов (как в конфигурации WIM_FIn, реквизит связи с портфелем — по фактическим метаданным). |
| Портфель в пуле | Портфель, у которого реквизит **Пул** (или эквивалент в метаданных) равен выбранному пулу. |
| Список портфелей (отладка) | Явно заданное подмножество портфелей (табличная часть шапки или список значений); при заполнении сужает отбор для проверки на небольшой выборке. |
| План | Документ `ПланРегламентныхОперацийДУ`. |
| Вид операции | Элемент справочника `ВидыОперацийЗакрытияПериода`, выбранный в шапке обработки; должен входить в белый список п. 3.1. |
| Ожидаемый тип документа | Имя объекта метаданных документа из таблицы соответствий для выбранного вида операции. |
| Подчинённые документы плана | Ссылки, возвращаемые **`КритерииОтбора.СвязанныеДокументы.Найти(СсылкаНаПлан)`** — единый источник с поведением конфигурации. |

---

## 2. Цель

Дать пользователю по одному запуску обработки сводку: **для каждого портфеля итогового отбора** (все портфели пула или только из списка — см. п. 4.1.1) на заданную дату — **есть / нет** хотя бы один документ ожидаемого типа среди подчинённых **всем** планам этого портфеля за этот календарный день (см. п. 4.3), с опциональной детализацией (план, ссылка на найденный документ).

---

## 3. Белый список видов операций

### 3.1. Состав

В шапке обработки поле **Вид операции** заполняется выбором **только** из видов, для которых в [operation_closure_procedure_document_map.html](operation_closure_procedure_document_map.html) указан тип документа. Логически это следующие пары «смысл операции — тип документа» (точные ссылки на элементы справочника `ВидыОперацийЗакрытияПериода` фиксируются при внедрении по метаданным и полю **ИсполняемаяПроцедура**):

| Смысл (для спецификации) | Тип документа (имя в конфигурации) |
|--------------------------|-------------------------------------|
| Начисление %% по банковским счетам по графику выплат (0025) | `НачислениеПроцентовПоБанковскимСчетам` |
| Погашение НКД (БУ), перевод НКД (0050) | `ПереводНКДВЗадолженностьЭмитента` |
| Определение сделок с отклонением цен (БУ) (0140) | `ОтклонениеЦенСделок` |
| Погашение облигаций до переоценки (БУ) (0058, ветка до переоценки) | `ПогашениеОблигаций` |
| Частичное погашение облигаций (БУ) (0058) | `ПогашениеОблигаций` |
| %% по займам по графику выплат (0032) | `РасчетПроцентовПоЗаймам` |
| Погашение / начисление %% по займам без графика (0033) | `РасчетПроцентовПоЗаймам` |
| Операция по дефолтным облигациям (БУ) (0080) | `ДефолтнаяОперация` |

Префикс в логе **«Предварительные данные (N договоров):»** относится к **замерам** (диагностике охвата при закрытии), а не к отдельному виду операции; в обработке **не выбирается** как самостоятельная операция.

Вид операции **погашение облигаций после переоценки** (процедура `Операция_0058_ПогашениеОблигаций_ПослеПереоценки`) в HTML-таблице не перечислён: при необходимости контроля этой ветки строка добавляется в HTML и в белый список обработки **синхронно** (тип документа тот же — `ПогашениеОблигаций`).

### 3.2. Реализация выбора в обработке

- Либо жёстко заданный список ссылок на элементы справочника (константа/параметр обработки, заполняемый при поставке).
- Либо динамический отбор из `ВидыОперацийЗакрытияПериода` по совпадению **ИсполняемаяПроцедура** с перечнем имён процедур из HTML-таблицы (предпочтительно для сопровождения).

## 4. Функциональные требования

### 4.1. Реквизиты шапки формы

| Реквизит | Обязательность | Описание |
|----------|----------------|----------|
| **Пул** | Условно | Обязателен, если **Список портфелей** пуст (см. п. 4.1.1). Иначе необязателен; при заполнении вместе со списком задаёт дополнительный фильтр по реквизиту портфеля **Пул**. |
| **Список портфелей** | Нет | Один или несколько портфелей (табличная часть, **СписокЗначений** с типом «Портфель» или множественный выбор — по удобству UI). Назначение: **отладка** на малой выборке без прогона всего пула. Пустой список — режим «все портфели выбранного пула». |
| **Дата** | Да | Операционный день закрытия: отбор планов по полю **Дата** документа в границах **НачалоДня** … **КонецДня** (как в типовой логике поиска плана, см. цепочку в plan_reg_oper_du_group_closure_chain.md). |
| **Вид операции** | Да | Только из белого списка п. 3.1. |
| **Группа операций** | Нет | Если заполнено — учитывать только планы с совпадающим реквизитом шапки **`ГруппаОперацийПользователя`** (сужение до одного плана на портфель при типовой уникальности). Если пусто — учитывать **все** планы портфеля за день. |

### 4.1.1. Правила отбора портфелей (пул и список)

1. Если **Список портфелей** **не пуст**: взять множество портфелей из списка (**без дубликатов**), исключить помеченные на удаление (если применимо).
   - Если **Пул** **не заполнен** — в обработку идут **все** портфели из списка (удобно для отладки «любых» трёх портфелей).
   - Если **Пул** **заполнен** — оставить только те портфели из списка, у которых реквизит **Пул** равен выбранному пулу (**пересечение**; защита от ошибочной подстановки чужого портфеля).
2. Если **Список портфелей** **пуст**: **Пул** **обязателен**; множество портфелей — все портфели этого пула (как в исходной постановке).
3. Если **и** список пуст, **и** пул не заполнен — при нажатии **«Выполнить проверку»** вывести понятное сообщение: **«Укажите пул или добавьте портфели в список»**, расчёт не выполнять.

### 4.2. Основной алгоритм

1. Сформировать множество **портфелей** по правилам п. 4.1.1.
2. Для выбранного **Вида операции** определить **ожидаемый тип документа** по таблице п. 3.1 / HTML.
3. Для каждого портфеля из множества, сформированного на шаге 1:
   - Найти все **Планы** `ПланРегламентныхОперацийДУ` с отбором: портфель, дата в пределах суток **Дата** из шапки, при заполненной **Группе операций** — совпадение группы, без пометки удаления (и при необходимости **Проведен** — согласовать с заказчиком; по умолчанию не отсекать непроведённые, но выводить признак проведения плана в детализации).
   - Для **каждого** найденного плана вызвать **`КритерииОтбора.СвязанныеДокументы.Найти(СсылкаПлана)`**.
   - Объединить массивы ссылок; если среди них есть **хотя бы один** документ, у которого тип (имя метаданных) равен **ожидаемому типу** — для данного портфеля результат **«Документ найден (>=1)»**, иначе **«Не найден»**.
4. **Не требуется** сопоставлять документ с конкретной строкой ТЧ **Операции** плана; достаточно факта наличия типа среди подчинённых по критерию отбора.

### 4.3. Несколько планов на один день и портфель

Если для портфеля за день существует несколько планов (разные **ГруппаОперацийПользователя**), при **пустой** группе в шапке обработки подчинённые документы **объединяются** со всех этих планов: условие «хотя бы один документ нужного типа» проверяется по объединённому множеству.

### 4.4. Строка плана и признак «Выполнять»

В минимальной версии обработки **не обязательно** проверять, что выбранный вид операции присутствует в ТЧ **Операции** плана с **Выполнять = Истина**. Заказчик может заказать **расширение**: учитывать только планы, где есть такая строка (отдельная итерация ТЗ).

### 4.5. Выходные данные

**Минимум:**

- Таблица результатов: **Портфель**, **Пул** (дублирование для контроля), **Документ найден** (Да/Нет), **Количество** документов ожидаемого типа среди объединённых подчинённых (число), **Количество планов** за день, по которым выполнялся обход.

**Желательно:**

- Колонки: ссылки на **первый найденный** документ, на **план(ы)**, из подчинённых которых он получен (или список через разделитель).
- При **Документ найден = Нет** — пустые ссылки, без ошибки.

### 4.6. Экспорт

Выгрузка таблицы результата в **xlsx** или **mxl** (минимум одно из) — по возможности стандартными средствами БСП, если обработка подключается в типовую среду.

## 5. Интерфейс внешней обработки

- Одна основная форма: шапка с полями п. 4.1 (включая область **«Список портфелей»** с возможностью добавить/удалить строки или подбором из справочника), кнопка **«Выполнить проверку»** (или **«Сформировать»**), табличная часть или таблица значений с результатом п. 4.5.
- Краткая подсказка у списка портфелей: **«Если заполнено — проверяются только перечисленные портфели (режим отладки). Пул можно не указывать или указать для фильтрации списка по пулу»**.
- Команда **«Экспорт»** (если реализован п. 4.6).
- Краткая справка на форме: текст о том, что проверяется наличие типа документа среди **`СвязанныеДокументы`**, а не факт выполнения строки **Выполнять** (если п. 4.4 не расширен).

## 6. Техническая реализация (ориентиры)

### 6.1. Запрос портфелей (пул и/или список)

- Режим «только пул»: запрос к `Справочник.Портфели` с условием по реквизиту **Пул**.
- Режим «список»: использовать переданный массив ссылок на портфели; при заполненном **Пуле** дополнительно отфильтровать в запросе или в коде по `Портфель.Пул = Пул`.
- Имена полей уточнить по выгрузке WIM_FIn.

### 6.2. Запрос планов

Запрос к `Документ.ПланРегламентныхОперацийДУ` с параметрами `&ДатаНач`, `&ДатаКон`, `&Портфель`, опционально `&ГруппаОпераций`.

### 6.3. Подчинённые документы

Для каждой уникальной ссылки плана из выборки:

```bsl
МассивПодчиненных = КритерииОтбора.СвязанныеДокументы.Найти(СсылкаПлана);
```

Тип документа: `Метаданные.НайтиПоТипу(ТипЗнч(Элемент))`; сравнение имени с ожидаемым типом из соответствия.

### 6.4. Производительность

- Кэшировать `Найти(План)` в соответствии при повторном обращении к тому же плану в одном сеансе.
- При большом числе портфелей в пуле — индикатор длительной операции или пакетная обработка с сообщением пользователю.
- Опционально: верхняя граница числа портфелей за один запуск с запросом подтверждения.

### 6.5. Права и безопасность

Чтение планов и документов — в рамках прав пользователя. При отсутствии права на конкретный подчинённый документ: не показывать ссылку или показывать только факт «найден» и тип (политика согласовать с заказчиком).

## 7. Нефункциональные требования

- Платформа: не ниже версии сборки WIM_FIn (регламент проекта, не ниже 8.3.21).
- Код BSL: стандарты репозитория, документирующие комментарии к экспортным процедурам.
- Обработка **не изменяет** данные ИБ (только чтение и вывод), кроме опционального сохранения пользовательских настроек отбора, если предусмотрено.

## 8. Критерии приёмки

1. Для тестового пула с известным портфелем, планом на дату и одним созданным подчинённым документом ожидаемого типа — в строке результата **Документ найден = Да**, количество >= 1.
2. Для портфеля без планов за дату — **Документ найден = Нет**, **Количество планов = 0** (или отдельное пояснение в колонке «Комментарий»).
3. Множество ссылок, по которым считается «найден», согласовано с результатом **`СвязанныеДокументы.Найти`** для каждого плана (выборочная сверка на 2–3 примерах).
4. При выборе вида операции, не входящего в белый список, выбор в форме **недоступен** (или показывается ошибка при попытке подмены).
5. Запуск без отбора портфелей запрещён: если **Пул** и **Список портфелей** вместе не задают ни одного портфеля — сообщение п. 4.1.1, расчёт не стартует.
6. При непустом **Списке портфелей** из двух элементов и пустом **Пуле** в результате ровно **две** строки (по указанным портфелям), без прочих портфелей.
7. **Дата** и **Вид операции** по-прежнему обязательны при каждом запуске.

---

## 9. Риски и ограничения

- Один тип документа (`ПогашениеОблигаций`, `РасчетПроцентовПоЗаймам`) соответствует **нескольким** видам операций в белом списке: пользователь обязан выбирать **нужный** вид; обработка не различает сценарии внутри одного типа документа без дополнительных правил (отдельное ТЗ).
- Изменение состава критерия **СвязанныеДокументы** в новой версии конфигурации меняет состав проверки без изменения кода обработки.
- Условия, при которых документ не создаётся типовой процедурой (пустые ТЧ, ветка «до/после переоценки»), описаны в HTML-таблице; обработка фиксирует только **факт наличия** документа данного типа среди подчинённых, не качество проведения.

---

## 10. Итог

ТЗ описывает **одну внешнюю обработку**: отбор портфелей по **пулу** и/или по **явному списку портфелей** (для отладки на малой выборке), выбор **вида операции** из фиксированного перечня, сопоставление с **типом документа** по [operation_closure_procedure_document_map.html](operation_closure_procedure_document_map.html), проверка для **каждого портфеля** итогового отбора — есть ли **хотя бы один** такой документ среди подчинённых **всем** релевантным планам за выбранный день (с опциональным сужением по **группе операций**).
