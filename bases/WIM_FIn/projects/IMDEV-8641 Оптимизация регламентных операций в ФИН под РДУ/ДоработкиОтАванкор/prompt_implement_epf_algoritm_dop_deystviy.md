# Промпт: перенос IMDEV-8641 в EPF АлгоритмДопДействийПриЗакрытииДня

Скопируй этот блок в чат Agent mode, когда нужно выполнить работу.

---

## Задача

Перенести логику оптимизации плана регламентных операций из модуля менеджера РС **ВидыОптимизируемыхРегламентныхОперацийДУ** (расширение RduPF) во **внешнюю обработку** **АлгоритмДопДействийПриЗакрытииДня** по инструкции вендора.

**Расширение RduPF не изменять** (ни перехваты, ни РС, ни константу).

## Нормативные материалы

- `ДоработкиОтАванкор/Релиз___2_8_5_0.txt` — инструкция Аванкор (релиз 2.8.5.0)
- `ДоработкиОтАванкор/how_it_looks_in_code_from_docx.md` — точка входа в типовой конфигурации
- `ДоработкиОтАванкор/АлгоритмДопДействийПриЗакрытииДня.xml` — метаданные EPF
- `ДоработкиОтАванкор/АлгоритмДопДействийПриЗакрытииДня/Ext/ObjectModule.bsl` — текущий шаблон вендора (каркас)
- `ДоработкиОтАванкор/ПримерВнешнейОбработкиПоЗакрытиюПериода.epf` — эталон шаблона (при необходимости разобрать через epf-dump)
- **Источник кода для переноса:**  
  `Расширения/RduPF/InformationRegisters/ВидыОптимизируемыхРегламентныхОперацийДУ/Ext/ManagerModule.bsl`
- Пять видов операций: `ПеречеьВидовОпераций` в корне проекта IMDEV-8641

## Ограничения

1. Не трогать `Расширения/RduPF/**`.
2. Не использовать в EPF `РегистрСведений.ВидыОптимизируемыхРегламентныхОперацийДУ` (в проде РС не будет).
3. Константу **ПулРозницаДУ** читать как в менеджере:  
   `ОбщегоНазначенияДУПовтИсп.ПолучитьЗначениеКонстанты("ПулРозницаДУ")` (константа остаётся в расширении RduPF в ИБ).
4. Менять только колонку **Выполнять** в таблице плана; строки не удалять.
5. Код 1С: ключевые слова с правильным регистром, комментарии на русском для экспортных/сложных процедур, без HTML-сущностей в BSL.

## Архитектура после внедрения

Типовая **ГрупповоеВыполнениеЗакрытияПериодов** (поставка 2.8.5.0) после `ПланРеглОпераций` вызывает:

```
ОбработкаДопДействий.ВыполнитьДополнительныеДействия(ПараметрыОбработки, Отказ)
```

где:

- `ВидДопДействия` = `"ПриФормированииПланаРегламентныхОперацийЗаДень"`
- `Дата` = день плана
- `ПланРегламентныхОпераций` = таблица плана на день (в txt вендора опечатка `ПланРегламентныхОпераци` — в коде типовой использовать фактическое имя из docx: **ПланРегламентныхОпераций**)

## План работ (пошагово)

### 1. Подготовить EPF

- База: шаблон `АлгоритмДопДействийПриЗакрытииДня/Ext/ObjectModule.bsl` + `АлгоритмДопДействийПриЗакрытииДня.xml`.
- Сохранять исходники EPF в `ДоработкиОтАванкор/АлгоритмДопДействийПриЗакрытииДня/` (расширить структуру при необходимости: Forms, Templates — по шаблону epf-init/epf-build).

### 2. Каркас модуля объекта (по Релиз___2_8_5_0.txt)

- **УстановитьНастройки** — пустое тело (как в шаблоне).
- **ВыполнитьДополнительныеДействия** — оставить маршрутизацию; **удалить** пустые ветки:
  - `ПередВыполнениемВсехРегламентныхОпераций`
  - `ПослеВыполненияВсехРегламентныхОпераций`
  - при необходимости пустые ветки по портфелю, если не используются  
  Оставить вызов при  
  `ВидДопДействия = "ПриФормированииПланаРегламентныхОперацийЗаДень"` → `ПриФормированииПланаРегламентныхОперацийЗаДень(...)`.
- Сохранить **СведенияОВнешнейОбработке**, **ПроверитьСовместимость**, **Версия** из шаблона вендора.

### 3. Перенести код из ManagerModule.bsl

**Область `#Область ОтборПортфелейДляСохраненияВыполненияВПлане`** — перенести целиком (без экспорта, служебные функции модуля объекта EPF):

- `ПолучитьПортфелиДляСохраненияВыполненияВПлане`
- все функции `ПортфелиДля...` и вспомогательные запросы

**Процедура `ОтфильтроватьПланРеглОперацийНаДень`** — перенести в:

```bsl
Процедура ПриФормированииПланаРегламентныхОперацийЗаДень(ПараметрыОбработки, Отказ = Ложь)

    День = ПараметрыОбработки.Дата;
    тПланРеглОперацийПоДням = ПараметрыОбработки.ПланРегламентныхОпераций;

    // тело бывшей ОтфильтроватьПланРеглОперацийНаДень(День, тПланРеглОперацийПоДням)

КонецПроцедуры
```

Логика шагов 1–4 без изменения смысла:

1. Ранний выход: пустая `ПулРозницаДУ` или пустой план.
2. Проверка однородности пула портфелей в плане.
3. Свод ключей (вид + время + родитель) только для оптимизируемых видов с `Выполнять = 1`.
4. Цикл по своду + `ПолучитьПортфелиДляСохраненияВыполненияВПлане` + пакетная корректировка `Выполнять` + запись обратно в `тПланРеглОперацийПоДням`.

### 4. Замена join к РС на ВТ (обязательная доработка)

В запросе формирования `ВТ_СводДопустимыеКлючи` **убрать**:

```bsl
ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.ВидыОптимизируемыхРегламентныхОперацийДУ КАК ОптВиды
```

**Добавить** служебную функцию, например `ПолучитьОптимизируемыеВидыОпераций()`, возвращающую массив из **5** предопределённых ссылок (те же, что в `ПолучитьПортфелиДляСохраненияВыполненияВПлане`):

1. `Справочники.ВидыОперацийЗакрытияПериода.НачислениеПроцентовПоБанковскимСчетамПоГрафику`
2. `...ПереводНКДЭмитента_БУ`
3. `...ОпределениеСделокСОтклонениемЦен_БУ`
4. `...ПогашениеОблигаций_БУ_ДоПереоценки`
5. `...ЧастичноеПогашениеОблигаций_БУ`

В начале пакета запроса (менеджер ВТ):

```bsl
ВЫБРАТЬ ... ПОМЕСТИТЬ ВТ_ОптВиды
```

и join:

```bsl
ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_ОптВиды КАК ОптВиды
    ПО План.ВидОперации = ОптВиды.ВидОперации
```

### 5. Сборка и проверка

- Собрать EPF: skill `epf-build` → `АлгоритмДопДействийПриЗакрытииДня.epf` в `ДоработкиОтАванкор/`.
- Валидация: `epf-validate`.
- Логическое ревью: сравнить поведение с `ManagerModule.bsl` (кроме источника списка видов).

### 6. Эксплуатация (напомнить пользователю, не код)

- Зарегистрировать EPF в **Дополнительные отчеты и обработки**.
- В **НастройкиЗакрытияПортфелейПоРасписанию** (РДУ) указать **АлгоритмДопДействийПриЗакрытииДня**.
- База должна быть с поставкой **2.8.5.0** (вызов события в типовой обработке).

## Риски (не исправлять в RduPF, но предупредить)

Если расширение RduPF подключено и в перехвате остаётся вызов  
`РегистрыСведений.ВидыОптимизируемыхРегламентныхОперацийДУ.ОтфильтроватьПланРеглОперацийНаДень`,  
план может фильтроваться **дважды** (расширение + EPF). На тесте проверить один активный путь.

## Критерии готовности

- [ ] EPF собирается без ошибок
- [ ] `ПриФормированииПланаРегламентныхОперацийЗаДень` меняет только `Выполнять` при заполненной `ПулРозницаДУ` и однородном пуле
- [ ] Пять видов обрабатываются; остальные виды в плане не меняются
- [ ] В коде EPF нет обращений к РС `ВидыОптимизируемыхРегламентныхОперацийДУ`
- [ ] RduPF не изменён
- [ ] Краткая заметка в `ДоработкиОтАванкор/` или `Документация/` о сборке и подключении EPF (по желанию пользователя)

## Что не делать

- Не переносить перехват `СформироватьРеглОперацииПоГруппе` / `Продолжить` — остаётся в RduPF
- Не удалять метаданные РС из расширения
- Не коммитить без явной просьбы пользователя
