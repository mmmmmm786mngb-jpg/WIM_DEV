# Аналитика: цепочка ПланРегламентныхОперацийДУ и ГрупповоеВыполнениеЗакрытияПериодов (база WIM_FIn)

Источник кода: выгрузка конфигурации WIM_FIn, типичный путь `C:\1c\Cursor_1c\WORK\WIM_FIn\src\cf\...`.

---

## 1. Точка входа: регламент и обработка

Регламентное задание вызывает `ФоновыеЗаданияСервер.ГрупповоеВыполнениеЗакрытияПериодаПортфелей`: создаётся объект `Обработка.ГрупповоеВыполнениеЗакрытияПериодов`, затем `ЗаполнитьПериодыПортфелей(НастройкаРегулярногоЗакрытия)` и `ВыполнитьРегулярноеРасписаниеЗакрытияПериода(НастройкаРегулярногоЗакрытия)`.

Файл: `CommonModules/ФоновыеЗаданияСервер/Ext/Module.bsl`, процедура `ГрупповоеВыполнениеЗакрытияПериодаПортфелей`.

Интерактивный сценарий использует ту же обработку; отличие — источник заполнения `ПериодыПортфелей` и параметры.

---

## 2. Откуда берутся портфели и где реквизит Пул

В обработке список портфелей на дату закрытия строится через `Справочники.Портфели.ДействующиеПортфели(ДатаЗакрытия, СписокТипов, ...)` после отбора по типам клиентов ДУ и (опционально) стратегиям — см. `ЗаполнитьСписокПортфелей`.

В метаданных справочника **Портфели** есть реквизит **Пул** (тип `СправочникСсылка.Пул`). В рассмотренном фрагменте цепочки группового закрытия **отдельного отбора по Пул в базовом коде нет**: будущий фильтр в запросе — это аналитика над данными, а не отражение штатного алгоритма обработки.

---

## 3. День + портфель: выполнение регламентных операций

Для каждой строки `ПериодыПортфелей` (день + портфель) вызывается `ВыполнитьРегламентныеОперации`. Внутри:

- при определённых условиях — распроведение связанных документов и планов за этот день по портфелю;
- создаётся/проверяется регламентный период;
- по `ПолучитьСписокГрупп()` перебираются **группы** видов операций;
- на каждую группу вызывается `СформироватьРеглОперацииПоГруппе`.

Файл: `DataProcessors/ГрупповоеВыполнениеЗакрытияПериодов/Ext/ObjectModule.bsl`.

**Важно:** на один календарный день и портфель может быть **несколько проходов** — **по одному на каждую группу** операций. У документа `ПланРегламентныхОперацийДУ` в шапке хранится `ГруппаОперацийПользователя` — привязка к группе.

---

## 4. Откуда берётся таблица операций и флаг Выполнять

`РегистрыСведений.НастройкиЗакрытияПериода.ПланРеглОпераций(ДатаЗакрытия, СписокПортфелей, Группа)` возвращает таблицу с колонками, среди прочего: `ВидОперации`, `Выполнять`, `Родитель` (группа в иерархии видов операций). Комментарий к функции фиксирует состав; внутри запроса `Выполнять` выводится из логики настроек/регламента/внешних обработок и объединения с дополнительными операциями.

Далее в `СформироватьРеглОперацииПоГруппе` таблица режется по `Родитель` и для каждой группы вызывается `ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ(..., РеглОперации, ВыполняемыйПлан, ГруппаРегламентныхОпераций.Родитель, ...)`.

---

## 5. Поиск существующего плана и перезапись

Перед созданием плана вызывается `РегламентноеЗакрытиеПериода.НайтиПланРегламентныхОперацийДУ`: отбор по **портфелю**, **дате документа в пределах суток** (`НачалоДня` … `КонецДня`), **`ПоВыбраннымАктивам`**, **`ГруппаОперацийПользователя`**, без пометки удаления; приоритет плану, зафиксированному в `РегистрыСведений.ТекущиеЗакрываемыеПериоды`, если он есть.

Если найден проведённый план, его могут **распровести** и при константе вне транзакции вызвать `ПометитьНаУдалениеПодчиненныеДокументы` перед перезаписью.

---

## 6. Создание документа ПланРегламентныхОперацийДУ и запуск процедур

`ФоновыеЗаданияСервер.СоздатьПланРегламентныхОперацийДУ`:

- при необходимости создаёт новый документ или берёт существующий и **очищает ТЧ Операции**;
- заполняет строки: `ВидОперации` и `Выполнять` из переданной таблицы (особый случай `ПоВыбраннымАктивам` — фильтр по списку видов);
- выставляет `Портфель`, `ГруппаОперацийПользователя`, `Дата`: **дата периода + время** из группы (`ВремяРеглОпераций`) либо **окончание рабочего дня**, если группа пустая;
- **проводит** документ, фиксирует `ТекущиеЗакрываемыеПериоды`, вызывает `ВыполнитьРегламентныеПроцедуры`; при отказе — откат проведения и пометка подчинённых (в зависимости от режима константы).

Файл: `CommonModules/ФоновыеЗаданияСервер/Ext/Module.bsl`, функция `СоздатьПланРегламентныхОперацийДУ`.

---

## 7. ТЧ Операции: с признаком Выполнять и без

Фактическое **выполнение** алгоритмов идёт только по строкам, где `ПланРегламентныхОперацийДУ.Операции.Выполнять = Истина`: это условие в `ПолучитьСписокОперацийДляВыполнения`.

Строки с `Выполнять = Ложь` остаются в документе (полный перечень плана), но **через этот механизм не исполняются**.

Дополнительно: для операций с признаком `БезДокумента` в `ВыполнитьРегламентныеПроцедуры` может выполняться только отметка в `РегистрыСведений.ИсполнениеОпераций` без создания документа по операции. Есть ветка, когда выполнение блокируется, если **документы по операции уже есть** (`РеглОперацииОтсутствуют` и не режим по выбранным активам).

Файл: `Documents/ПланРегламентныхОперацийДУ/Ext/ObjectModule.bsl`, функция `ПолучитьСписокОперацийДляВыполнения`.

---

## 8. Подчинённые документы

`Документы.ПланРегламентныхОперацийДУ.ПометитьНаУдалениеПодчиненныеДокументы` не перечисляет типы документов вручную: вызывается `КритерииОтбора.СвязанныеДокументы.ПометитьПодчиненныеНаУдаление(ПланРеглОперации)` — состав подчинённых задаётся **критерием отбора СвязанныеДокументы** в конфигурации.

Файл: `Documents/ПланРегламентныхОперацийДУ/Ext/ManagerModule.bsl`, процедура `ПометитьНаУдалениеПодчиненныеДокументы`.

Во многих результирующих документах встречается реквизит `ДокументОснование` и проверки вида `ОбщегоНазначенияДУ.ДокументВходитвПланРеглОпераций` (по сути: основание — ссылка на `ПланРегламентныхОперацийДУ`). Для будущих запросов разумно сочетать критерий отбора (как на платформе) и/или явные связи (`ДокументОснование`, движения с основанием, если так заведено в метаданных).

## 9. Что учесть для постановки (портфель, пул, день)

| Аспект | Смысл для анализа |
|--------|-------------------|
| Период «день» | В `НайтиПланРегламентныхОперацийДУ` используется интервал начало–конец дня по полю `Дата` документа; само поле `Дата` может содержать время (не полночь). |
| Несколько планов | На один день и портфель возможны **несколько** `ПланРегламентныхОперацийДУ`, различающихся `ГруппаОперацийПользователя` и/или `ПоВыбраннымАктивам`. |
| Пул | Фильтр `Портфели.Пул = &Пул` в запросах — ваш отбор; **не** часть ядра цепочки в показанном коде. |
| Все ли операции создали документы | Нужно различать: строка ТЧ с `Выполнять = Ложь` (не запускалась), операции `БезДокумента`, отказ из-за уже существующих документов, несколько групп — несколько планов. |

## Связанные объекты (кратко)

- `Обработка.ГрупповоеВыполнениеЗакрытияПериодов` — модуль объекта: заполнение периодов, списки портфелей, `ВыполнитьРегулярноеРасписаниеЗакрытияПериода`, `ВыполнитьРегламентныеОперации`, `СформироватьРеглОперацииПоГруппе`.
- `ОбщийМодуль.ФоновыеЗаданияСервер` — `СоздатьПланРегламентныхОперацийДУ`, `ГрупповоеВыполнениеЗакрытияПериодаПортфелей`.
- `ОбщийМодуль.РегламентноеЗакрытиеПериода` — `НайтиПланРегламентныхОперацийДУ`.
- `РегистрСведений.НастройкиЗакрытияПериода` — `ПланРеглОпераций`.
- `Документ.ПланРегламентныхОперацийДУ` — `ВыполнитьРегламентныеПроцедуры`, `ПолучитьСписокОперацийДляВыполнения`.

Документ подготовлен по выгрузке конфигурации WIM_FIn; пути к модулям — относительно каталога `src/cf`.
