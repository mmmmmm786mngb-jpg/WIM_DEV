Замена логики ТолькоПолучитьУзелСсылки для ПКО СделкиTn

IMDEV-8661. Подсказка разработчику. Конфигурация: Wim_Du (ДУ). Связанные ТЗ: exchange-two-wave-development-plan.html, ТЗ - одноволновой обмен ДУ-ФИН.html.

1. Предыстория проблемы

При обмене ДУ-ФИН документ Документ.Сделка содержит реквизит БизнесПроцесс со ссылкой на БизнесПроцесс.СделкиTn. При выгрузке Документ.Сделка платформа вызывает ПКО СделкиTn повторно - по ссылке из реквизита. Без ограничения в XML уходит второй полный объект СделкиTn (дубль данных, лишний объем, риск коллизий при загрузке).

Задача IMDEV-8661: вынести Документ.Сделка из общего потока в пакетные потоки 1-6 (вместе с СделкиTn по портфелям). После этого старая схема с флагом ЭтоОбщийПакет перестает покрывать новые сценарии.

2. Как работает сейчас (IMAPPS-32010)

2.1. Оркестрация потоков

  • Обработка внОбменДУ-Финансы3.0(потоки) формирует фоновые задания.
  • Общий поток: ЭтоПакетСделокTn = Ложь - все объекты, кроме корневой выгрузки СделкиTn.
  • Пакеты 1-6: ЭтоПакетСделокTn = Истина + ПулСделок по портфелю.
  • Запуск: ОбщийМодуль.VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы.

2.2. Прокидывание флага в правила

Wim_Du / ОбщийМодуль.VTB_ОбщийМодуль / Ext / Module.bsl, процедура ВыполнитьОбменДУ_Финансы, ~стр. 616: 

ОбработкаXML.Параметры.Вставить("ЭтоОбщийПакет", Не ЭтоПакетСделокTn);

2.3. ПКО СделкиTn - обработчик ПередВыгрузкой

EPF внОбменДУ-Финансы3.0(потоки) / Templates / МакетПравил / Ext / Template.txt, правило <Код>СделкиTn</Код>, ~стр. 23692: 

ТолькоПолучитьУзелСсылки = Параметры.Свойство("ЭтоОбщийПакет") И Параметры.ЭтоОбщийПакет; // IMAPPS-32010

2.4. Смысл старой логики

ПотокЭтоОбщийПакетСделкиTn из ПВДСделкиTn из Сделка.БизнесПроцесс
Общий (сейчас) Истина не выгружается (ПВД выкл.) только узел ссылки (GUID)
Пакет 1-6 Ложь полный объект полный объект (дубль!)

ТолькоПолучитьУзелСсылки - штатный параметр функции ВыгрузитьПоПравилу обработки УниверсальныйОбменДаннымиXML: при Истина полный XML объекта не строится, возвращается только узел ссылки (~стр. 9643 ObjectModule.bsl).

2.5. Почему ЭтоОбщийПакет не подходит после IMDEV-8661

Вариант ТЗПроблема
Одноволновой В одном пакете 1-6: СделкиTn (корень, full) и Документ.Сделка (ссылка на тот же Tn). ЭтоОбщийПакет = Ложь - оба вызова дадут full.
Двухволновой, волна 2 Только Документ.Сделка; Tn уже загружен в волне 1, но по БизнесПроцесс снова может уйти full при ЭтоОбщийПакет = Ложь.

3. Приоритетное решение: мСтекВызововВыгрузкиДанных

Основной вариант

Одна правка в макете правил. Подходит для одноволнового и двухволнового обмена. Не зависит от флагов потока. VTB_ОбщийМодуль и EPF менять не обязательно.

3.1. Что изменить

ОбъектФайл / модульДействие
EPF внОбменДУ-Финансы3.0(потоки) .../IMDEV-8661.../EPF/внОбменДУ-Финансы3.0(потоки)/Templates/МакетПравил/Ext/Template.txt Заменить строку в <ПередВыгрузкой> ПКО СделкиTn
EPF (тесты) .../IMDEV-8662 Тесты/EPF/внОбменДУ-Финансы3.0(потоки)/Templates/МакетПравил/Ext/Template.txt Та же замена (синхронизация с боевым макетом)

Было:

ТолькоПолучитьУзелСсылки = Параметры.Свойство("ЭтоОбщийПакет") И Параметры.ЭтоОбщийПакет; // IMAPPS-32010

Стало:

// IMDEV-8661: корень ПВД - full; вызов по ссылке из другого объекта - только GUID
ТолькоПолучитьУзелСсылки = (мСтекВызововВыгрузкиДанных.Количество() > 0);

Строку ЭтоОбщийПакет в VTB можно оставить (не используется) или удалить при уборке.

3.2. Откуда берется мСтекВызововВыгрузкиДанных

Конфигурация Wim_Du / Обработка.УниверсальныйОбменДаннымиXML / Ext / ObjectModule.bsl

  • Объявление: Перем мСтекВызововВыгрузкиДанных; (~стр. 133)
  • Создание стека: процедура ВыполнитьВыгрузку()
  • Добавление в стек: ВыгрузитьПоПравилу() после ПередВыгрузкой, если ЗапоминатьВыгруженные = Истина и полная выгрузка (~стр. 9491)
  • Снятие со стека: при завершении ВыгрузитьПоПравилу (~стр. 9635, 9647)
  • Early return по ссылке: Если ТолькоПолучитьУзелСсылки ... Возврат УзелСсылки (~стр. 9643)

3.3. Диаграмма: корневой вызов СделкиTn (пакет 1-6)

ПВД включает правило "СделкиTn" (корень) | v ВыгрузитьПоПравилу(СделкиTn) | +-- ПередВыгрузкой СделкиTn | мСтекВызововВыгрузкиДанных.Количество() = 0 | ТолькоПолучитьУзелСсылки = Ложь | +-- стек: ДОБАВИТЬ СделкиTn | +-- полный XML объекта СделкиTn | +-- стек: УДАЛИТЬ СделкиTn

3.4. Диаграмма: СделкиTn по ссылке из Документ.Сделка

ПВД включает правило "Сделка" (корень) | v ВыгрузитьПоПравилу(Документ.Сделка) | +-- ПередВыгрузкой Сделка | мСтек = 0 | +-- стек: ДОБАВИТЬ Сделка <-- родитель в стеке | +-- ВыгрузитьСвойства | реквизит БизнесПроцесс -> ПКО СделкиTn | | | v | ВыгрузитьПоПравилу(СделкиTn) | | | +-- ПередВыгрузкой СделкиTn | | мСтек.Количество() = 1 (> 0) | | ТолькоПолучитьУзелСсылки = Истина | | | +-- RETURN только узел ссылки (GUID), без full XML | +-- стек: УДАЛИТЬ Сделка

3.5. Диаграмма: одноволновой пакет 1-6 (Tn + Сделка в одном XML, без склейки)

Пакет 1-6: один Выгрузить() -> один файл XML ПВД включает СделкиTn (ПулСделок) И Сделка (ПулПортфелей) [1] ВыгрузитьПоПравилу(СделкиTn) мСтек=0 -> FULL Tn [2] ВыгрузитьПоПравилу(Сделка) мСтек=0 в ПередВыгрузкой Сделки стек += Сделка БизнесПроцесс -> СделкиTn: мСтек=1 -> ТОЛЬКО ССЫЛКА Итог одного XML: 1 x full СделкиTn + 1 x full Сделка + ref СделкиTn внутри Сделки (без дубля full Tn) Поток 0 (общий): СделкиTn и Сделка в ПВД выключены - эта диаграмма к нему не относится

3.6. Условия корректной работы стека

  • У ПКО Сделка и СделкиTn нет <НеЗапоминатьВыгруженные>true</НеЗапоминатьВыгруженные> (по умолчанию ЗапоминатьВыгруженные = Истина).
  • Родитель (Документ.Сделка) выгружается полностью, не как ссылка.
  • Обработчик выполняется через Выполнить(ПКО.ПередВыгрузкой) в модуле УниверсальныйОбменДаннымиXML (боевой путь VTB, без режима отладки обработчиков).

3.7. Минимальный тест перед внедрением

  1. Временно в ПередВыгрузкой СделкиTn записать в ЖР: мСтекВызововВыгрузкиДанных.Количество().
  2. Пакет с одним портфелем: корневой Tn - ожидать 0; Tn из Сделка.БизнесПроцесс - ожидать >= 1.
  3. Проверить XML: один full СделкиTn, внутри Сделка - только ref.
Риски стека: недокументированная переменная модуля обработки; в режиме отладки обработчиков Конвертации данных (ФлагРежимОтладкиОбработчиков) переменная недоступна. Для фонового обмена VTB это не актуально.

4. Запасной вариант, если стек не сработал

Если тест показал ошибку «переменная не определена» или неверное поведение - см. блоки ниже. Схемы различаются для двухволнового и одноволнового ТЗ.

Запасной вариант

4.1. Двухволновой обмен (проще, стек не обязателен)

Волна 1: только СделкиTn (пакеты 1-6).
Волна 2: только Документ.Сделка (пакеты 1-6). Tn в волне 2 не корень ПВД.

ОбъектМодульИзменение
ОбщийМодуль VTB_ОбщийМодуль Wim_Du/SRC/CF/CommonModules/VTB_ОбщийМодуль/Ext/Module.bsl
процедура ВыполнитьОбменДУ_Финансы		 Добавить в ОбработкаXML.Параметры: 
ОбработкаXML.Параметры.Вставить("ЭтоПакетСделокTn", ЭтоПакетСделокTn);
(рядом с существующим ЭтоОбщийПакет или вместо него)
EPF внОбменДУ-Финансы3.0(потоки) Templates/МакетПравил/Ext/Template.txt, ПКО СделкиTn 
// IMDEV-8661, двухволновой запасной вариант
ТолькоПолучитьУзелСсылки = НЕ (Параметры.Свойство("ЭтоПакетСделокTn")
    И Параметры.ЭтоПакетСделокTn);
Двухволновой - логика флага Волна 1, пакет N: ЭтоПакетСделокTn = Истина, ПВД = только СделкиTn ПередВыгрузкой: ТолькоПолучитьУзелСсылки = Ложь -> FULL Волна 2, пакет N: ЭтоПакетСделокTn = Ложь (или отдельный флаг ЭтоПакетСделка), ПВД = только Документ.Сделка СделкиTn вызывается только из Сделка.БизнесПроцесс ПередВыгрузкой: ТолькоПолучитьУзелСсылки = Истина -> только GUID

Для волны 2 нужна доработка ObjectModule.bsl EPF и VTB_ОбщийМодуль.ПолучениеДанныеXMLПоПравиламКонвертации: отдельный режим ПВД для Документ.Сделка (см. двухволновое ТЗ). Флаг ЭтоПакетСделокTn в волне 2 должен быть Ложь.

4.2. Одноволновой обмен - рабочий вариант

Схема: поток 0 - все объекты кроме СделкиTn и Документ.Сделка; потоки 1-6 - оба типа в одном XML (один Выгрузить(), без склейки файлов). См. ТЗ - одноволновой обмен ДУ-ФИН.html.

Пакет 1-6: один XML [корень ПВД] СделкиTn -> FULL (один раз) [корень ПВД] Документ.Сделка -> FULL реквизит БизнесПроцесс -> REF на тот же Tn (GUID, не второй FULL) Цель: убрать второй FULL Tn. Ссылка REF внутри Сделки - норма, ее убирать нельзя.
Основной вариант

Шаг 1. Стек (то же, что п. 3)

EPF внОбменДУ-Финансы3.0(потоки) / Templates/МакетПравил/Ext/Template.txt, ПКО СделкиTn, <ПередВыгрузкой> 

// IMDEV-8661: вложенный вызов (из Сделка.БизнесПроцесс) - только ссылка
ТолькоПолучитьУзелСсылки = (мСтекВызововВыгрузкиДанных.Количество() > 0);

Корень из ПВД: стек пуст -> FULL. Вызов из Документ.Сделка: в стеке родитель -> REF. Порядок выгрузки Tn/Сделка в ПВД не важен.

Запасной вариант

Шаг 2. ПКО.Выгруженные (если стек недоступен)

Тот же файл Template.txt, ПКО СделкиTn

// IMDEV-8661, запасной: Tn уже выгружен full в этой сессии - только ссылка
КлючОбъекта = ЗначениеВСтрокуВнутр(Источник);
ТолькоПолучитьУзелСсылки = (ПКО.Выгруженные[КлючОбъекта] <> Неопределено);

ПКО - штатный параметр обработчика. Работает только если сначала выгрузился корневой СделкиTn, потом Документ.Сделка.

В макете группа ПВД Документы (порядок 100) идет раньше Бизнес-процессов (150). Для запасного варианта нужен порядок Tn -> Сделка: поменять <Порядок> групп в Template.txt или порядок включения в VTB_ОбщийМодуль.ПолучениеДанныеXMLПоПравиламКонвертации.

Что не использовать в одноволновом

  • ЭтоОбщийПакет / ЭтоПакетСделокTn в ПередВыгрузкой - в одном пакете флаг один, корень и ссылку не разделить.
  • Склейка двух XML или два файла на пакет - не по ТЗ.

Проверка (пакет с Tn и Сделкой на одном портфеле)

  1. В XML ровно один full-блок СделкиTn.
  2. Внутри Документ.Сделка у БизнесПроцесс - узел ссылки (GUID), не full.
  3. Загрузка в ФИН без ошибок дублей и без потери связи Сделка -> Tn.

Вынос Документ.Сделка в пакеты 1-6 (параметр ПулПортфелей, матрица ПВД в VTB) - отдельная доработка IMDEV-8661; без нее в пакете останется только СделкиTn.
