# IMDEV-8661 - Текущий алгоритм обмена ДУ-ФИН

## 1. Границы решения

- Точка оркестрации: `EPF/внОбменДУ-Финансы3.0(потоки)/Ext/ObjectModule.bsl`.
- Запуск из формы: `EPF/внОбменДУ-Финансы3.0(потоки)/Forms/Форма/Ext/Form/Module.bsl`.
- Фактическая выгрузка и загрузка в ФИН: `VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы`.
- Контур запуска: конфигурация `Wim_Du` (см. `bases/Wim_Du/README.md`).

## 2. Точка входа и первичная проверка

1. Команда фонового запуска попадает в `ВыполнитьКоманду`.
2. Выполняется защита от параллельного дубля: поиск активных фоновых заданий по имени метода
   `VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы`.
3. В структуру параметров добавляются:
   - узел обмена;
   - настройки веб-сервиса;
   - флаги рассылки и пост-обработки;
   - `ИдентификаторОбмена`.

## 3. Оркестрация потоков в EPF (как сейчас)

### 3.1 Подготовка данных по `СделкиTn`

- `СделкиTnПоПортфелям` строит пакетный запрос:
  - считает количество `СделкиTn` по узлу;
  - группирует ссылки по портфелю;
  - для РГС может исключать сделки не из списка договоров.
- `ЕстьСтатикаДокументыДляОбмена` определяет наличие изменений по всем объектам, кроме `БизнесПроцесс.СделкиTn`.

### 3.2 Формирование набора потоков

- Если есть "статика", создается один общий поток (без флага `ЭтоПакетСделокTn`).
- Для `СделкиTn` формируются пулы:
  - портфели сортируются по убыванию нагрузки;
  - каждый следующий портфель кладется в самый легкий пул;
  - итоговая цель - выравнивание числа сделок между пулами.
- На каждый пул запускается отдельное фоновое задание с флагом `ЭтоПакетСделокTn = Истина`.

### 3.3 Управление жизненным циклом фоновых заданий

- Запуск через `ВыполнитьФоновоеЗадание` с методом `VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы`.
- Контроль выполнения через `ОжидатьЗавершенияФоновыхЗаданий`:
  - период опроса 5 секунд;
  - жесткий таймаут 12 часов;
  - сбор ошибок в `ТекстОписаниеОшибки`.

## 4. Логика в `VTB_ОбщийМодуль`

### 4.1 Обработка параметров волны

- Процедура `ВыполнитьОбменДУ_Финансы` принимает XML со структурой параметров.
- Ключевые флаги:
  - `ЭтоПакетСделокTn`;
  - `ПулСделок`;
  - `Рассылка`;
  - `ИдентификаторОбмена`.

### 4.2 Матрица выгрузки

- В `ПолучениеДанныеXMLПоПравиламКонвертации` используется правило `СделкиTn`.
- Если пакетный режим `СделкиTn`:
  - отключаются все правила;
  - включается только правило `СделкиTn`;
  - ставится отбор по `ПулСделок`.
- Если это общий пакет:
  - правило `СделкиTn` выключается;
  - остальные объекты остаются в общем обмене.

### 4.3 Передача в ФИН

1. Формируется XML по правилам `УниверсальныйОбменДаннымиXML`.
2. Вызывается web-service `upload_data`.
3. По результату:
   - снимается регистрация изменений загруженных объектов;
   - обрабатываются ошибки протокола;
   - удаляются временные файлы.

## 5. Что это значит для идеи IMDEV-8661

- Сейчас уже есть разделение только для `СделкиTn`.
- `Документ.Сделка` в текущем алгоритме попадает в общий поток.
- Поэтому "общий" поток может быть длинным и создавать узкое место по времени.
- При параллельной обработке большой массы сделок риск коллизий по данным выше, так как
  отдельной волны по `Документ.Сделка` пока нет.
