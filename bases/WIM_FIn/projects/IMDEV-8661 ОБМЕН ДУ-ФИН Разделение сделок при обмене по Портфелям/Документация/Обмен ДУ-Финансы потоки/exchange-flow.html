Обмен ДУ-Финансы 3.0, многопоточная выгрузка

Внешняя обработка базы ДУ внОбменДУ-Финансы3.0(потоки), версия 3.37. Забирает зарегистрированные изменения узла обмена и параллельными потоками передает их в базу ФИН.

Источник: база ДУ Приемник: база ФИН, веб-сервис NDFL Метод: upload_data

Схема запуска

Общие шаги Общий поток Пулы СделкиTn
1. Старт в базе ДУ Форма обработки или регламентная команда
2. Защита запуска Повторный запуск не стартует, пока есть задание с тем же именем. Затем ожидание блокирующих регламентов
3а. Общий поток Справочники, документы и прочие бизнес-процессы. Правило СделкиTn выключено. Документ Сделка идет здесь
3б. Пулы СделкиTn Сделки узла группируются по портфелю и раскладываются в пулы так, чтобы число сделок было близким
4. Фоновые задания Метод VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы. Одновременно не больше 10, опрос 5 секунд, ожидание до 12 часов
5. Закрытие запуска Снятие регистрации загруженных объектов, письмо и задача интеграции

Как попадает в работу

Обработка зарегистрирована как дополнительная, наименование «Обмен ДУ-Финансы 3.0 многопоточно».

ВходЧто делает
Форма, команда обмена Проверяет активные задания «Выгрузка в базу Финансы» и вызывает оркестратор. Раз в минуту смотрит, завершились ли задания.
Регламент, обычный обмен Команда «ФоновоеВыполнение». Создает задачу интеграции и после всех потоков отправляет письмо по списку рассылки обработки.
Регламент, обмен РГС Команда «ФоновоеВыполнениеРГС». Тот же маршрут, но узел УзелОбменаРГС, отдельный веб-сервис и список договоров.
Если задание с тем же именем метода уже активно, новый запуск сразу завершается и письмо об ошибке не формируется.

Как режутся изменения

  1. Оркестратор выбирает узел: УзелОбмена для обычного обмена и УзелОбменаРГС для РГС.
  2. Если в настройке заданы блокирующие регламенты, обработка ждет их окончания. Опрос каждые 5 секунд, не дольше заданного лимита.
  3. Запрос собирает зарегистрированные на узле СделкиTn и группирует их по портфелю, реквизит ДоговорДУ. Для РГС в выгрузку входят только договоры из списка, остальные сделки снимаются с регистрации узла.
  4. Отдельно проверяется, есть ли изменения по справочникам, документам и бизнес-процессам, кроме СделкиTn. Если есть, под общий поток резервируется один слот из настройки числа потоков.
  5. Портфели сортируются по убыванию числа сделок. Каждый следующий портфель кладется в самый легкий пул. Число пулов равно оставшимся потокам и не меньше одного, поэтому пустой пул тоже может получить свое задание.
  6. На общий пакет и на каждый пул стартует фоновое задание. У всех потоков одного запуска общий идентификатор обмена. Последнему пулу, а если сделок нет, то единственному общему пакету, ставятся флаги рассылки и операций после обмена.
Документ Сделка в отдельные пулы не выделяется. Он выгружается общим потоком вместе со справочниками и остальными документами.

Один фоновый поток

1. Макет правил Текст макета МакетПравил загружается в УниверсальныйОбменДаннымиXML, режим «Выгрузка»
2а. Пакет сделок Все правила выключены. Включено только СделкиTn, отбор по ссылкам пула
2б. Общий пакет Правило СделкиTn выключено. Остальные объекты узла остаются в выгрузке
3. Файл XML Выгрузка по правилам конвертации. Ошибка протокола пишется в журнал и прерывает поток
4. Веб-сервис базы ФИН NDFL.upload_data. Для РГС адрес и учетная запись берутся из настроек РГС
5. Ответ в базу ДУ По списку загруженных объектов снимается регистрация изменений на узле

Взаимодействие базы ДУ и базы ФИН

База ДУ База ФИН, расширение обмена
1. ДУ. Файл XML Поток выгружает объекты по макету правил во временный файл
2. ДУ вызывает ФИН NDFL.upload_data. В JSON путь к файлу, идентификатор обмена, флаги транзакций и рассылки
3. ФИН. Старт потока Привилегированный режим, пропуск даты запрета. В регистр потоков пишется состояние «Новый»
4. ФИН. Загрузка XML Универсальный обмен пишет объекты. Правила раскладывают их по спискам в памяти
5. ФИН. Регистры расширения После загрузки данных списки переносятся в регистры ExchDU_Список*
6. ФИН. Поток «Загружен» Параметры кладутся в хранилище значения. Ответ JSON содержит путь к файлу параметров
7. ФИН. Письмо лога Если у этого идентификатора обмена все строки потоков в состоянии «Загружен»
8. ДУ. Снятие регистрации По файлу параметров снимаются загруженные объекты узла обмена
Оба контура читают временные файлы по путям из JSON: ДУ отдает путь к XML, ФИН возвращает путь к файлу параметров. Проведение документов и старт бизнес-процессов на этом шаге не выполняются. Объекты записываются, а действие над ними ставится в регистр-очередь.

Что происходит в базе ФИН

Метод upload_data в расширении обмена подменяет типовой метод веб-сервиса. Для одного потока порядок такой.

1. Подготовка сеанса Включается привилегированный режим и пропускается проверка даты запрета изменения
2. Регистр ExchDU_ПотокиОбмена, состояние «Новый» Ключ: идентификатор обмена и временный идентификатор потока. Дата обмена заполняется сейчас
3. Загрузка объектов Режим загрузки, флаг отладки включен: ошибка записи одного объекта не обрывает весь файл
4а. После загрузки объекта Правило кладет ссылку в один список параметров: провести, отменить, удалить, записать, новый или измененный БП
4б. После загрузки всех данных Каждый список параметров переписывается в свой регистр ExchDU_Список* с идентификатором потока из правил
5. Вторая строка потока, состояние «Загружен» Пишется с идентификатором потока из правил. В ресурс кладется хранилище параметров XML. Строка с временным идентификатором остается в состоянии «Новый»
6. Сообщения и ответ Тексты сообщений пользователя пишутся в ExchDU_СостояниеОбъектовЗагрузки. ДУ получает JSON без флага ошибки и путь к файлу параметров
Если загрузка XML завершилась с флагом ошибки, в журнал пишется протокол и метод сразу возвращает ошибку. Вторая строка потока в состоянии «Загружен» не пишется. Письмо лога смотрит состояния всех строк идентификатора обмена и уходит только когда среди них нет других состояний, кроме «Загружен». Строка «Новый» с временным идентификатором при этом остается, поэтому условие письма по одному запуску может не выполниться. Флаг запуска операций после обмена читается, процедура ExchDU_ЗапускОперацийПослеОбмена из этого метода не вызывается. Состояния «Обработка» и «Обработан» этим методом не ставятся.

Как пишутся регистры расширения

Регистры ExchDU_* принадлежат расширению обмена. Во время загрузки потока пишутся три группы.

РегистрКогдаЧто попадает в запись
ExchDU_ПотокиОбмена До загрузки XML и после успешной загрузки Измерения: идентификатор обмена и идентификатор потока. Сначала состояние «Новый» и временный идентификатор. После загрузки состояние «Загружен», идентификатор потока из правил, признак успешной загрузки и хранилище параметров.
ExchDU_Список* Обработчик «После загрузки данных» правил, уже в базе ФИН По одной записи на объект. Измерения: ссылка объекта и идентификатор потока. Очередь для последующих операций, не движения учета.
ExchDU_СостояниеОбъектовЗагрузки После успешной загрузки, если есть сообщения пользователю Одна строка на поток. Тип и представление «Сообщения пользователю», тексты в комментарии. Пообъектные строки этого регистра при загрузке не пишутся.

Справочник после загрузки своей карточки попадает в ExchDU_СписокСправочниковКЗагрузке.

Документ в обработчике «После загрузки» объекта раскладывается так:

УсловиеРегистр
В данных ДУ документ проведенExchDU_СписокДокументовДляПроведения
Не проведен и стоит пометка удаленияExchDU_СписокДокументовДляУдаления
В ФИН документ уже есть и проведен, а из ДУ пришел непроведеннымExchDU_СписокДокументовДляОтменыПроведения
Остальные непроведенныеExchDU_СписокНепроведенныхДокументов

Бизнес-процесс, на примере внебиржевой сделки, делится по новизне и состоянию в данных ДУ:

Объект в ФИНСостояние в данных ДУРегистр
НовыйПометка удаленияExchDU_СписокНовыхБПНаУдаление
НовыйЗавершенExchDU_СписокНовыхЗавершенныхБП
НовыйСтартованExchDU_СписокНовыхБПдляСтарта
НовыйЕще не стартованExchDU_СписокНовыхБП
Уже естьПометка удаленияExchDU_СписокБПНаУдаление
Уже естьЗавершенExchDU_СписокЗавершенныхБП
Уже естьСтартованExchDU_СписокИзмененныхБПдляСтарта
Уже естьНе стартованExchDU_СписокИзмененныхБП
Для внебиржевой сделки в ExchDU_СписокИзмененныхБПдляСтарта дополнительно пишется реквизит «Пройденные шаги». Сделки срочного рынка короче: новый объект идет либо в список новых на удаление, либо в список новых завершенных, уже существующий идет в список на удаление или в список завершенных. Если ссылки в ФИН нет, запись списка пропускается и в регистр не попадает. Сам метод загрузки эти списки не очищает и не обрабатывает: их читает обработка операций после обмена.

Что происходит после успешной загрузки

База ДУ снимает регистрацию и у загруженных объектов, и у объектов, которые правила пометили как не подлежащие загрузке. Типы из ответа ФИН сопоставляются с объектами ДУ:

Тип в ответе ФИНОбъект в базе ДУ
ПортфелиСправочник ДоговорДУ
СчетаБрокераСправочник ТорговыеКоды
ДепозитарныеРасписки, КлиринговыеСертификатыУчастияСправочник Акции
СделкиНаСрочномРынкеДокумент СделкаНаСрочномРынке

Затем в базе-приемнике помечаются удаленные объекты этой базы, временные файлы удаляются. Ошибки потоков попадают в описание задачи интеграции. Письмо регламентного запуска формируется в базе ДУ по итогу всех потоков и отдельно от письма лога, которое собирает база ФИН.
