IMDEV-8661: техническое задание

Тема: одноволновой многопоточный обмен ДУ-ФИН с выносом Документ.Сделка из общего потока в пакетные потоки 1-6 вместе с БизнесПроцесс.СделкиTn.
Версия ТЗ: 1.0 | Задача: IMDEV-8661

1. Зачем меняем

Сейчас документ «Сделка» (перерегистрация ц/б) выгружается в общем потоке 0 вместе со всеми справочниками и прочими документами. При большом объеме (десятки тысяч документов) общий поток становится очень длинным и задает время всего обмена.

Бизнес-процесс «Сделки T+n» (СделкиTn) уже вынесен в 6 параллельных потоков по портфелям. Нужно сделать то же для Документ.Сделка, не вводя вторую волну - один запуск обмена, одна волна, 7 потоков как сейчас.

2. Смысл решения простыми словами

Поток 0 - только «легкие» объекты: справочники, платежи, прочие документы и БП. Без СделкиTn и без Документ.Сделка.

Потоки 1-6 - по каждому пулу портфелей выгружаются: СделкиTn (как сейчас) и Документ.Сделка по тем же портфелям.

T+n и документы Сделка - независимые события на узле обмена: на портфеле может быть только T+n, только Сделка, или оба типа - все три случая должны обрабатываться.

3. Как будет работать по шагам

  1. Пользователь или регламент запускает обмен (как сейчас) - внешняя обработка внОбменДУ-Финансы3.0(потоки).
  2. EPF одним запросом получает очередь по портфелям: где есть T+n, где есть Сделка, или оба.
  3. EPF раскладывает портфели по 6 пулам (балансировка по суммарной нагрузке: Tn + Сделка).
  4. Запускается поток 0, если есть «легкие» изменения (без Tn и без Сделка).
  5. Запускаются потоки 1-6. В каждом:
    • выгрузка СделкиTn по списку ссылок пула;
    • выгрузка Документ.Сделка по списку портфелей (ДоговорДУ) пула.
  6. Каждый поток - фоновое задание VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы, загрузка XML в ФИН через web-service.
  7. Рассылка и пост-операции - в последнем пакетном потоке (как сейчас).
Один запуск обмена (целевая схема) | +-- Поток 0 (общий) | Справочники, документы, БП - БЕЗ СделкиTn и БЕЗ Документ.Сделка | \-- Потоки 1..6 (пакеты по портфелям) СделкиTn - по ссылкам БП из пула Документ.Сделка - по ДоговорДУ портфелей пула (В Списке)

3.1. Три ситуации на портфеле (все обязательны)

На узле по портфелюЧто уйдет в пакетном потоке
Только СделкиTn T+n по ссылкам; Сделка - если на узле есть (иначе пусто)
Только Документ.Сделка Все Сделка портфеля; T+n - пусто
И T+n, и Сделка Оба типа в одном потоке пула

7. Критерии приемки

  • Документ.Сделка не выгружается в потоке 0.
  • Портфель только с Сделка (без T+n) попадает в один из пулов 1-6 и выгружается.
  • Портфель только с T+n выгружается как сейчас.
  • Портфель с обоими типами - оба в одном пакетном потоке.
  • Обмен РГС: фильтр СписокДоговоров сохраняется для обоих типов в запросе.
  • Состав загруженных в ФИН объектов совпадает с текущим обменом (без потерь и дублей).
  • Рассылка - один раз, в последнем пакетном потоке.
