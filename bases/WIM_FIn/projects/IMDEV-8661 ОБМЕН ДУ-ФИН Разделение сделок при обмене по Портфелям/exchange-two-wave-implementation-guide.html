IMDEV-8661: двухволновой обмен ДУ-ФИН

Задача: за один запуск обмена выполнить две последовательные волны. В каждой волне - 1 общий поток + 6 пакетных потоков (итого до 7 параллельных фоновых заданий). Оркестратор: внешняя обработка внОбменДУ-Финансы3.0(потоки). Исполнитель выгрузки/загрузки: VTB_ОбщийМодуль.ВыполнитьОбменДУ_Финансы.

Итоговая схема в одном предложении Волна 1: выгружаем все объекты, кроме Документ.Сделка, параллелизуя только БизнесПроцесс.СделкиTn (6 пулов). Волна 2 (после полного завершения волны 1): выгружаем Документ.Сделка в 6 пулов; общий поток второй волны снова без СделкиTn и без Сделка.

1. Проблема: как работает обмен сейчас

Сейчас один запуск обмена (EPF ВыполнитьОбменДУ_Финансы) делает следующее:

ОДИН ЗАПУСК ОБМЕНА (сейчас) | +-- [Поток 0] Общий пакет (ЭтоПакетСделокTn = Ложь) | | | +-- Выгружается ВСЕ, кроме БизнесПроцесс.СделкиTn | | | \-- Документ.Сделка - ВСЕ сделки в одной куче <-- узкое место | \-- [Поток 1..6] Пакеты СделкиTn (ЭтоПакетСделокTn = Истина) | +-- Только БизнесПроцесс.СделкиTn | +-- Отбор по пулу портфелей | \-- Распределение: СделкиTnПоПортфелям + балансировка по портфелям

Почему нужны две волны:
1) Документ.Сделка в общем потоке создает очень длинный неделимый пакет - обмен тормозит.
2) При параллельной загрузке СделкиTn в ФИН возможны коллизии по GUID и ошибка PRIMARY KEY. Разделение тяжелых типов по волнам и пулам устраняет обе проблемы.

ОДИН ЗАПУСК ОБМЕНА (целевой) | +-- ВОЛНА 1 (ВолнаОбмена = "СделкиTn") | | [дождаться завершения ВСЕХ фоновых заданий волны 1] | | | +-- [Поток 0] Общий | | | | | \-- Все объекты, КРОМЕ: СделкиTn И Документ.Сделка | | | \-- [Поток 1..6] Пакеты СделкиTn | | | +-- Только БизнесПроцесс.СделкиTn | | | \-- Пул по портфелям (СделкиTnПоПортфелям) | \-- ВОЛНА 2 (ВолнаОбмена = "СделкаДокумент") [старт ТОЛЬКО после волны 1] | +-- [Поток 0] Общий | | | \-- Все объекты, КРОМЕ: СделкиTn И Документ.Сделка | (обычно пустой, если волна 1 прошла успешно) | \-- [Поток 1..6] Пакеты Документ.Сделка | +-- Только Документ.Сделка, пул по портфелям (ДоговорДУ) | \-- Рассылка и ЗапускОперацийПослеОбмена - ТОЛЬКО в последнем потоке
