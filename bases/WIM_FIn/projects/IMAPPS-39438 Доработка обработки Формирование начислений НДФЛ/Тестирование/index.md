# Тестирование IMAPPS-39438

Внешняя обработка сравнения двух отсевов пар клиент+УК после заполнения как в обработке «Формирование начислений НДФЛ», вариант 2.

## Файл

`IMAPPS39438_CompareTurnoverFilter.epf` — открыть как внешнюю обработку в ФИН20.

## Что делает

1. Набирает исходный список тем же методом, что кнопка Заполнить обычного варианта: `ЗаполнитьДокументамиНаДату` (вариант 2). На форме те же отборы, что в типовой обработке: период, **налоговый период** (год, по умолчанию 2026), **управляющая компания** (обязательна), клиент, «по закрытым портфелям», «по закрытым с поступлением НКД», схема выплаты. Оба флажка закрытых портфелей по умолчанию включены.
2. Для каждой пары клиент+УК смотрит обороты Хозрасчетного за год даты окончания периода.
3. Отсев по постановке: нет оборота по счетам `90.01, 91.01.02, 91.01.03, 91.01.04, 91.01.09, 91.01.99`.
4. Отсев по широкому списку: нет оборота по счетам доходов `90.01, 91.01, 91.03` (префикс `91.01` раскрывает все листья 91.01.xx, включая постановку). Расходы 91.02 / 90.02 / 91.04 и налог 68.01 в список не входят: сами по себе они не основание начислять НДФЛ.
5. В таблицу попадают только отличия двух отсевов. Пары без оборотов по обоим спискам в таблицу не входят (они в счетчике «Оба отсекают»).

## Виды строк в таблице

- «Отсекает только постановка (Jira)» — доход есть на счете, которого нет в постановке (например 91.03, 91.01.05, 91.01.01), по счетам постановки оборота нет.
- «Отсекает только широкий список» — при неизменных умолчаниях быть не должно: широкий список содержит постановку целиком.

Списки счетов на форме можно править перед сравнением.
