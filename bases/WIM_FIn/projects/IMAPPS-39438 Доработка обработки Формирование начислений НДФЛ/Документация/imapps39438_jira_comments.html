Комментарий 1. Отсев без дохода

Как отсеем клиентов без дохода

После «Заполнить» обработка больше не обязана оставлять в списке всех клиентов УК. Можно оставить только тех, у кого в выбранном периоде уже был доход, и создавать начисления только по ним.

На форме появляется флажок Не создавать начисление НДФЛ, если нет оборотов по счетам 90 и 91. По умолчанию он выключен: список собирается как сейчас. Справа от флажка открывается поле счетов. Уже заполнено: 90.01, 91.01, 91.03 (продажи, прочие доходы, ещё один счёт выручки). Список на прогоне можно поправить.

Программа смотрит обороты с 1 января по дату в поле «Период». Достаточно дохода хотя бы по одному портфелю клиента в этой УК. Субсчета подхватываются сами. Расходный 91.02 доходом не считается. Если доход был, а налог после расчёта вышел ноль, клиент в списке остаётся: доход-то был.

Пример 2026. Абайдулина, Абайдулова, Абакарова. До 2 сентября доходов нет, 2 сентября приходит купон. Заполнение на 1 сентября - этих троих в таблице нет. На 2 сентября - появляются, по ним можно начислить НДФЛ.

Расчёт налога и сами документы начисления не меняются. Меняется только состав списка после заполнения.

Комментарий 2. Отсев по РДУ / пулу

Как оставим только клиентов РДУ

Дополнительно можно заполнять начисления не по всем физлицам, а только по клиентам выбранного пула. Для розничного ДУ это пул Розничное ДУ в карточке портфеля - тот же признак, которым пул уже отличают в учёте.

На форме второй флажок Создавать начисления только по клиентам выбранного пула. По умолчанию выключен. Когда включаете, справа открывается поле Пул. Для РДУ выбирают «Розничное ДУ». Пустое поле - это клиенты не-РДУ (портфели, у которых пул не заполнен). Программа ничего не подставляет сама.

После «Заполнить» в таблице остаются пары клиент и УК, у которых есть хотя бы один портфель с выбранным пулом. Смотрим реквизит портфеля «Пул», а не номер договора.

Оба отбора можно включить вместе: сначала остаются клиенты выбранного пула, затем среди них - только с доходом за период.
