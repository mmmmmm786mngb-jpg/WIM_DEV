IMAPPS-39438 - краткое ТЗ

Не создавать начисление НДФЛ, если не было доходов

На обработку «Формирование начислений НДФЛ» добавляется флажок. При заполнении в список попадают только пары клиент и управляющая компания, у которых за период есть обороты по счетам доходов. Без флажка всё работает как сейчас. Старые пустые документы не трогаем.

Для заказчика Для разработчика

1. Для заказчика

1 Открыть обработку

Как обычно: период прогона, налоговый год, УК, при необходимости клиент.

2 Включить флажок

Рядом с уже знакомым отбором «без ЦБ». Появится поле со счетами доходов.

3 Нажать Заполнить

В таблице остаются только те, у кого был доход. Остальных не видно и документы по ним не создаются.

4 Создать как обычно

Дальше расчёт и пачки без изменений. Флажок сам ничего не пересчитывает: чтобы отсечь список, нужно снова Заполнить.

Кого оставляем

Пару «клиент + эта УК», если хотя бы по одному её портфелю за год до даты окончания периода есть оборот по доходам:

  • выручка 90.01
  • прочие доходы 91.01 и все субсчета (купон, дивиденды, курсовые, РЕПО, проценты и т.д.)
  • выручка на 91.03

На форме это три кода. Система сама подхватывает субсчета.

Кого не берём

  • клиент только с комиссией УК, брокера, депозитария - это расход 91.02, не доход
  • себестоимость продаж и налог 68.01 сами по себе НДФЛ не порождают
  • тот же клиент в другой УК без доходов в этой УК - строка этой УК не появится

Нулевой налог после расчёта и «не было доходов» - разные вещи. Если доход был, а налог вышел в ноль, строка останется.

Как это выглядит на примере

Ситуация Флажок выключен Флажок включен
До 1 сентября доходов нет, 2 сентября пришёл купон (91.01.02) клиент в списке в оба дня 1 сентября нет, со 2 сентября есть
Только вознаграждение УК, продаж и купона нет пустой документ создаётся в список не попадает
Продажи были, налог после расчёта ноль документ есть документ есть: доход был

Что не меняется

  • формулы расчёта НДФЛ
  • уже созданные пустые документы - не ищем и не удаляем
  • массовый прогон без флажка - как сейчас
  • налоговый период на форме по-прежнему ставится на документ; обороты смотрим по полю «Период» (с начала года даты окончания по эту дату)

Приёмка для бизнеса

  • флажок по умолчанию выключен
  • счета на форме: 90.01, 91.01, 91.03, список можно поправить на прогоне
  • три клиента из постановки (Абайдулина, Абайдулова, Абакарова) на 01.09.2026 не заполняются, на 02.09.2026 появляются
  • клиент только с 91.02 без доходов не заполняется

2. Для разработчика

Конфигурация ФИН, обработка ФормированиеНачисленийНДФЛ. Типовую CF не менять. Расширение IMAPPS39438_EmptyTurnover, назначение Customization.

Метаданные

Заимствовать обработку и форму Форма (в т.ч. реквизиты формы). Модуль менеджера не заимствовать. Документ начисления и ОбщиеОбороты не трогать.

Реквизиты объекта обработки:

  • НеСоздаватьНДФЛПоКлиентамБезОборотов - Булево, умолчание Ложь
  • СчетаОборотовДляОтбораНДФЛ - Строка, не сохраняется в ИБ

Поля в группе ГруппаОтборПраво после флажка БезЦБ. Поле счетов видно только при включенном флаге. ПриИзменении флага вызывает УправлениеФормой.

Перехваты

ГдеМетодТип

Не делать правку пяти ЗаполнитьПо..., перехват СоздатьДокументы, нарезку пачек, ОбщиеОбороты.

Снимок пачек IMDEV-7330 копирует реквизиты объекта сам. После Заполнить пустых пар в ТЧ уже нет.

Зерно и счета

Режем пару клиент + УК, как строка ТЧ ДатыДокументов. Не «клиент по всем УК сразу».

Умолчание строки: 90.01, 91.01, 91.03. Разбор ПланыСчетов.Хозрасчетный.СчетаПоСтроке (префикс по коду, не В ИЕРАРХИИ). 91.01 раскроет все 91.01.xx, 91.02 не попадёт. Если поле пустое - подставить умолчание. Если после разбора 0 счетов - не фильтровать, сообщить об ошибке списка.

Флаг и строка живут только в сеансе формы. После закрытия снова Ложь и умолчание счетов.

Запрос

Один запрос на нажатие Заполнить. Сначала временная таблица пар из ТЧ, затем Хозрасчетный.Обороты с Счет В (&СчетаОборотов) и внутренним соединением по паре.
