IMAPPS-39438. Просим включить доработку в базовую конфигурацию обработки «Формирование начислений НДФЛ».

Суть. На форме два дополнительных отбора (оба по умолчанию выключены).

1. Флажок «Не создавать начисление НДФЛ, если нет оборотов по счетам 90 и 91» и поле счетов справа. Умолчание счетов: 90.01, 91.01, 91.03. Если флажок включён, после штатного заполнения в таблице остаются только пары клиент + УК с оборотами по этим счетам.

2. Флажок «Создавать начисления только по клиентам выбранного пула» и поле пула справа (видно только при включённом флажке). При включении, если пул не выбран, подставляется константа «Пул розницы ДУ» (элемент «Розничное ДУ»). После заполнения остаются пары клиент + УК, у которых есть хотя бы один портфель с этим пулом. Признак розничного ДУ - реквизит портфеля «Пул», не номер договора.

Расчёт НДФЛ и документ «Начисление НДФЛ по портфелю» не меняются.

Референс. Расширение IMAPPS39438_EmptyTurnover (Customization). Просим перенести точечно в типовую и расширение снять. Аннотации &После в типовую не копировать. Комментарии IMAPPS-39438 оставить.

Что трогать. Только обработка ФормированиеНачисленийНДФЛ: четыре реквизита объекта, форма «Форма», модуль объекта, модуль формы. Модуль менеджера и документ начисления не менять.

Как встраивать.
1. В конец штатной ЗаполнитьДатыДокументов: вызов ОставитьТолькоПарыСПулом(), затем ОставитьТолькоПарыСОборотами().
2. В модуль объекта скопировать две процедуры (в расширении с префиксом IMAPPS39438_ - в типовой префикс снять). Область IMAPPS39438.
3. В конец штатной УправлениеФормой: умолчание счетов и видимость поля счетов; умолчание пула и видимость поля пула. Отдельный перехват ПриСозданииНаСервере не нужен.
4. На форме в ГруппаОтборПраво две горизонтальные группы: флажок со счетами и флажок с пулом. У обоих флажков ПриИзменении - вызов УправлениеФормой.

Код и приёмка - во вложении imapps39438_avancor.html.
