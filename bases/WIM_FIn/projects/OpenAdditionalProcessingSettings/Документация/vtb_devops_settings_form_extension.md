# Доработка расширения VTB_Devops: открытие ФормаНастроек без внешней обработки

Техническая спецификация для базы **WIM_FIn** (ДУ ред. 2).  
Цель: с карточки справочника `ДополнительныеОтчетыИОбработки` открывать, просматривать, редактировать и сохранять настройки внешней обработки **без отдельной EPF-утилиты**, по аналогии с гиперссылкой «Настройки» в конфигурации ДУ (Wim_Du / AVANCORE, SROS-14).

---

## 1. Контекст и целевое поведение

### 1.1. Что уже есть в ФИН

| Компонент | Состояние |
|-----------|-----------|
| Реквизит `Справочник.ДополнительныеОтчетыИОбработки.ХранилищеНастроек` | Есть |
| `Справочники.ДополнительныеОтчетыИОбработки.НастройкиОбработки()` | Читает `ХранилищеНастроек` |
| Передача в команды: `ПараметрыКоманды.ПараметрыДополнительнойОбработки` | Есть (SROS-14 / SROS-24 в `ДополнительныеОтчетыИОбработки`) |
| UI открытия `ФормаНастроек` с карточки справочника | **Отсутствует** (в ДУ — гиперссылка AVANCORE) |

Итог: данные и потребление настроек при выполнении команд уже работают. Не хватает только UX редактирования на форме элемента.

### 1.2. Эталон в ДУ (AVANCORE)

На `Справочник.ДополнительныеОтчетыИОбработки.Форма.ФормаЭлемента`:

1. Реквизит формы `Настройки` (произвольный тип) — кэш структуры из `ХранилищеНастроек`.
2. Кнопка-гиперссылка `ОткрытьФормуНастроек` (`Type = Hyperlink`), заголовок = представление настроек.
3. При чтении объекта: `Настройки = ТекущийОбъект.ХранилищеНастроек.Получить()`.
4. По клику: подключение внешней обработки, `ОткрытьФорму("ВнешняяОбработка.<Имя>.Форма.ФормаНастроек", Параметры)` с `НастройкиАлгоритма`.
5. В `ОбработкаВыбора`: если вернулась `Структура` — записать в реквизит формы `Настройки`, обновить заголовок гиперссылки.
6. При записи объекта: `ТекущийОбъект.ХранилищеНастроек = Новый ХранилищеЗначения(Настройки)`.

Источник эталона: `Wim_Du` / `Catalogs/ДополнительныеОтчетыИОбработки/Forms/ФормаЭлемента` (блоки `//AVANCORE`).

### 1.3. Целевое поведение в ФИН

Пользователь на карточке элемента:

1. Видит элемент управления «Настройки» (гиперссылка или кнопка).
2. Открывает `ФормаНастроек` подключенной внешней обработки/отчета.
3. Редактирует параметры.
4. Закрывает форму со структурой настроек.
5. После записи элемента справочника структура оказывается в `ХранилищеНастроек` и далее уходит в команды как `ПараметрыДополнительнойОбработки`.

Отдельная обработка в справочнике доп. отчетов **не требуется**.

---

## 2. Почему доработка именно через VTB_Devops

Расширение `VTB_Devops` уже:

- заимствует `Справочник.ДополнительныеОтчетыИОбработки` и формы `ФормаЭлемента` / `ФормаСписка`;
- в `&НаСервере ВТБ_ПриСозданииНаСервереПеред` вызывает `ВТБ_DevOps.ДобавитьКомандыНаФормуДопОбработок`;
- программно добавляет команды «Сохранить настройки» / «Загрузить настройки».

Это естественная точка расширения: тот же паттерн программных команд на форме, без снятия основной конфигурации с поддержки и без EPF.

### 2.1. Что не использовать

| Подход | Почему не подходит |
|--------|--------------------|
| Расширение определяемого типа `ОбъектСДополнительнымиКомандами` + команда БСП «Заполнение...» | При `ConfigurationExtensionCompatibilityMode = Version8_3_12` состав определяемого типа через расширение фактически не расширяется (ограничение платформы). `UpdateDBCfg` либо падает на контроле свойства `Тип`, либо «проходит» без эффекта на runtime. |
| Отдельная EPF «открывашка» | Решает задачу, но противоречит требованию «без всякой обработки». Оставить только как временный обходной путь. |
| Правка основной конфигурации ФИН | Возможна, но дороже по сопровождению (поддержка поставщика). Предпочтительнее расширение. |

## 3. Архитектура доработки

```
ФормаЭлемента (расширение VTB_Devops)
    |
    | ПриСозданииНаСервере
    v
ВТБ_DevOps.ДобавитьКомандыНаФормуДопОбработок  -->  кнопка/гиперссылка «Настройки»
    |
    | клик (клиент формы)
    v
ПодключитьВнешнююОбработку(Ссылка)  -->  Имя + проверка наличия ФормаНастроек
    |
    v
ОткрытьФорму(ВнешняяОбработка|ВнешнийОтчет.<Имя>.Форма.ФормаНастроек,
             Параметры = { НастройкиАлгоритма })
    |
    | ОповеститьОВыборе / Закрыть(Структура)  -->  ОбработкаВыбора формы
    v
Реквизит формы Настройки = Структура
    |
    | ПередЗаписьюНаСервере
    v
Объект.ХранилищеНастроек = Новый ХранилищеЗначения(Настройки)
```

Рекомендуемое разделение ответственности:

| Место | Ответственность |
|-------|-----------------|
| `ОбщийМодуль.ВТБ_DevOps` (сервер, вызов сервера) | Создание элемента UI; серверные функции: подключение, проверка формы, чтение/запись хранилища (по желанию) |
| Модуль формы `ФормаЭлемента` (расширение) | Клиентские обработчики команды, `ОбработкаВыбора`, вызовы сервера; реквизиты формы |
| Целевая внешняя обработка | `ФормаНастроек`, контракт параметра и результата (см. п. 6) |

## 4. Пошаговая реализация в VTB_Devops

### 4.1. Предварительные условия

1. Форма `ФормаЭлемента` уже заимствована (`ObjectBelonging = Adopted`).
2. В модуле формы есть перехват `ВТБ_ПриСозданииНаСервереПеред` с вызовом `ДобавитьКомандыНаФормуДопОбработок`.
3. У модуля `ВТБ_DevOps`: флаги **Сервер** + **Вызов сервера**.

### 4.2. Реквизиты формы элемента (расширение)

Добавить в расширении формы (через конструктор / `form-edit` / правку `Form.xml`):

| Имя | Тип | Назначение |
|-----|-----|------------|
| `ВТБ_Настройки` (или `Настройки`) | Произвольный / без типа | Кэш структуры настроек на форме |
| `ВТБ_ПредставлениеНастроек` (опционально) | Строка | Текст для заголовка гиперссылки |

Префикс `ВТБ_` предпочтителен, чтобы не конфликтовать с возможными будущими реквизитами основной конфигурации.

### 4.3. Элемент UI: два допустимых варианта

#### Вариант A (ближе к ДУ) — гиперссылка на форме

1. В расширении формы добавить команду `ВТБ_ОткрытьФормуНастроек`.
2. Добавить кнопку `Type = Hyperlink`, `CommandName = Form.Command.ВТБ_ОткрытьФормуНастроек`.
3. Разместить рядом с блоком команд / шапкой (как в ДУ — над таблицей «Поставляемые команды»).
4. Заголовок кнопки обновлять из `ЗаголовокНастроек` структуры (см. п. 4.5).

Плюс: визуально как в ДУ.  
Минус: нужна правка `Form.xml` расширения (элемент + команда + при необходимости `BaseForm`).

#### Вариант B (минимальный дифф) — программная кнопка

В `ВТБ_DevOps.ДобавитьКомандыНаФормуДопОбработок` рядом с существующими кнопками:

```bsl
Команда = Форма.Команды.Добавить("ВТБ_ОткрытьФормуНастроек");
Команда.Заголовок = "Настройки";
Команда.Действие = "ВТБ_ОткрытьФормуНастроек";
Команда.Подсказка = "Открыть ФормаНастроек и сохранить результат в ХранилищеНастроек";

КнопкаФормы = Форма.Элементы.Добавить(
    "ВТБ_ОткрытьФормуНастроек",
    Тип("КнопкаФормы"),
    Форма.Элементы.ФормаКоманднаяПанель);
КнопкаФормы.ИмяКоманды = "ВТБ_ОткрытьФормуНастроек";
КнопкаФормы.Вид = ВидКнопкиФормы.ОбычнаяКнопка;
```

Плюс: только BSL, без компоновки формы.  
Минус: выглядит как кнопка командной панели, не как гиперссылка в теле карточки.

Для паритета с ДУ предпочтителен **вариант A**.

### 4.4. Загрузка настроек при открытии карточки

В модуле формы расширения — перехват `&После` / `&Перед` на `ПриЧтенииНаСервере` (или дополнение существующего серверного обработчика):

```bsl
&НаСервере
Процедура ВТБ_ПриЧтенииНаСервереПосле(ТекущийОбъект)
    ВТБ_Настройки = ТекущийОбъект.ХранилищеНастроек.Получить();
    ВТБ_УстановитьЗаголовокНастроек();
КонецПроцедуры
```

Если перехват `ПриЧтенииНаСервере` неудобен — читать `ХранилищеНастроек` при первом открытии настроек с сервера по `Объект.Ссылка` (хуже UX: заголовок гиперссылки не покажет текущее представление до клика).

### 4.5. Обновление представления

```bsl
&НаСервере
Процедура ВТБ_УстановитьЗаголовокНастроек()
    Представление = НСтр("ru = '<настройки не установлены>'");
    Если ТипЗнч(ВТБ_Настройки) = Тип("Структура") Тогда
        ЗначениеЗаголовка = Неопределено;
        Если ВТБ_Настройки.Свойство("ЗаголовокНастроек", ЗначениеЗаголовка)
            И ЗначениеЗаполнено(ЗначениеЗаголовка) Тогда
            Представление = Строка(ЗначениеЗаголовка);
        Иначе
            Представление = НСтр("ru = 'Настройки установлены'");
        КонецЕсли;
    КонецЕсли;
    // Для гиперссылки:
    Элементы.ВТБ_ОткрытьФормуНастроек.Заголовок = Представление;
КонецПроцедуры
```

### 4.6. Открытие ФормаНастроек (клиент)

Алгоритм (по мотивам ДУ, с доработкой для отчетов):

1. Если `Модифицированность` и объект ещё не записан — потребовать запись (в ДУ: предупреждение и отказ).
2. На сервере:
   - определить вид (обработка / отчет);
   - `Имя = ДополнительныеОтчетыИОбработки.ПодключитьВнешнююОбработку(Ссылка)`;
   - проверить `Метаданные().Формы.Найти("ФормаНастроек")`;
   - вернуть полное имя формы:  
     `ВнешняяОбработка.<Имя>.Форма.ФормаНастроек` или  
     `ВнешнийОтчет.<Имя>.Форма.ФормаНастроек`.
3. На клиенте:
   ```bsl
   ПараметрыФормы = Новый Структура("НастройкиАлгоритма", ВТБ_Настройки);
   ОткрытьФорму(ИмяФормы, ПараметрыФормы, ЭтотОбъект, УникальныйИдентификатор);
   ```
   Владелец формы — карточка справочника, чтобы сработал `ОбработкаВыбора`.

Рекомендуется вынести серверную подготовку в `ВТБ_DevOps.ПодготовитьОткрытиеФормыНастроек(Ссылка)` (как в черновике варианта 2 проекта), а клиент оставить в модуле формы.

### 4.7. Приём результата и запись в объект

```bsl
&НаКлиенте
Процедура ОбработкаВыбора(ВыбранноеЗначение, ИсточникВыбора)
    // Если в основной форме уже есть обработчик — использовать &После
    Если ТипЗнч(ВыбранноеЗначение) = Тип("Структура") Тогда
        ВТБ_Настройки = ВыбранноеЗначение;
        ВТБ_УстановитьЗаголовокНастроек();
        Модифицированность = Истина;
    КонецЕсли;
КонецПроцедуры
```

Сохранение в БД — в `ПередЗаписьюНаСервере` (&После):

```bsl
&НаСервере
Процедура ВТБ_ПередЗаписьюНаСервереПосле(Отказ, ТекущийОбъект, ПараметрыЗаписи)
    ТекущийОбъект.ХранилищеНастроек = Новый ХранилищеЗначения(ВТБ_Настройки);
КонецПроцедуры
```

Альтернатива (сразу писать в БД при закрытии формы настроек, без ожидания записи карточки):

```bsl
СправочникОбъект = Ссылка.ПолучитьОбъект();
СправочникОбъект.ХранилищеНастроек = Новый ХранилищеЗначения(Настройки);
СправочникОбъект.Записать();
```

Ближе к ДУ — **кэш на форме + запись вместе с объектом**. Для DevOps-сценариев допустима немедленная запись (как в EPF-утилите).

### 4.8. Форма списка (опционально)

Для списка достаточно кнопки «Настройки» по текущей строке:

1. Взять `Элементы.Список.ТекущаяСтрока`.
2. Открыть `ФормаНастроек` так же.
3. По результату сразу записать `ХранилищеНастроек` объекта (на форме списка нет реквизита `Настройки`).

Точка входа та же: `ДобавитьКомандыНаФормуДопОбработок` (уже различает список и элемент по `Форма.ИмяФормы`).

## 6. Контракт целевой внешней обработки

Без выполнения контракта UI на справочнике бесполезен.

1. В метаданных есть форма с именем **`ФормаНастроек`**.
2. При открытии форма читает `Параметры.НастройкиАлгоритма` (ожидается `Структура`, часто с ключами `Значения`, `ЗаголовокНастроек`).
3. Обычно вызывается `Объект.УстановитьПользовательскиеНастройки(...)`.
4. При подтверждении форма возвращает **`Структура`** владельцу через `ОповеститьОВыборе(Структура)` или `Закрыть(Структура)`.

### 6.1. Несовместимость сигнатуры

Часть обработок объявляет:

```bsl
Процедура УстановитьПользовательскиеНастройки(Настройки, ПредставлениеНастроек = "") Экспорт
```

а форма передаёт один аргумент. Тогда при открытии с `НастройкиАлгоритма` возможна ошибка числа параметров.

Митигации в расширении:

- перед открытием на сервере пробовать `УстановитьПользовательскиеНастройки(Настройки)` на объекте; при ошибке совместимости открывать форму **без** `НастройкиАлгоритма`;
- либо править сигнатуру в целевых обработках.

## 7. Связь с выполнением команд

После записи `ХранилищеНастроек` штатный путь ФИН уже передаёт настройки в обработку:

```bsl
ПараметрыКоманды.Вставить(
    "ПараметрыДополнительнойОбработки",
    Справочники.ДополнительныеОтчетыИОбработки.НастройкиОбработки(...));
```

Дополнительных изменений в общих модулях БСП для этой задачи не требуется.

---

## 8. Критерии приёмки

1. На карточке элемента справочника есть «Настройки» (гиперссылка или кнопка) без регистрации отдельной EPF.
2. Для обработки с `ФормаНастроек` форма открывается, поля заполняются из `ХранилищеНастроек` (если совместимо).
3. После редактирования и записи элемента `ХранилищеНастроек` содержит новую структуру.
4. Выполнение команды этой обработки получает актуальные `ПараметрыДополнительнойОбработки`.
5. Для обработки без `ФормаНастроек` — понятное сообщение, без исключения платформы.
6. Для отчёта с `ФормаНастроек` открытие идёт через `ВнешнийОтчет.`, не `ВнешняяОбработка.`.
7. Существующие команды VTB_Devops «Сохранить/Загрузить настройки» (файл) не ломаются.
