По активным портфелям ИИС

Спасибо за уточнение и скрин карточки. Правило поняли.

Если в портфеле «Тип клиента» = «Индивидуальные инвестиционные счета» и «Дата окончания» пустая, это действующий ИИС. По такому портфелю начисление НДФЛ из обработки «Формирование начислений НДФЛ» создаваться не должно.

Это не ещё один отбор на кнопке «Заполнить». «Заполнить» собирает людей: клиент и УК. У одного человека в той же УК могут быть и обычное ДУ, и ИИС. Человека из списка из-за ИИС вычёркивать нельзя, иначе не посчитаем обычное ДУ. Действующий ИИС нужно отсечь позже, когда для выбранного человека собирают портфели в документ начисления.

Отдельный флажок на форме не делаем. Это постоянное правило при создании документов.

Как это уже устроено у нас

Внутренняя доработка, о которой вы пишете, как раз на этом шаге.

  • Начисление по портфелю берёт только портфели с типом «Физические лица». Действующий ИИС в документ не попадает.
  • Начисление по УК обработка создаёт как начисление физлица. В расчёт этого документа действующий ИИС (пустая дата окончания) тоже не входит.

По открытому ИИС начисление из этой обработки сейчас не создаётся. Нужно, чтобы в типовой Аванкора было так же: при сборке портфелей в документ действующий ИИС не брать.

Как это выглядит для человека.
Есть обычное ДУ и открытый ИИС - в списке после «Заполнить» клиент остаётся. Считаем только обычное ДУ. Открытый ИИС в документы не идёт.
Есть только открытый ИИС - начисление по ИИС не создаём.
ИИС уже закрыт (дата окончания заполнена) - это не «активный ИИС» из вашего правила. Такое закрытие в выбранном году по-прежнему может попасть в начисление по УК, если налог за год закрытия ещё нужно посчитать.

Что проверим у Аванкора

Просьбу «удостовериться, что у Аванкора это тоже будет работать» понимаем так: в типовой обработке при создании начисления действующий ИИС не должен попадать в список портфелей документа. Кнопку «Заполнить» под это не переделываем.

Просим подтвердить. Закрытый ИИС (дата окончания заполнена) в начислении по УК за год закрытия оставляем, как сейчас в расчёте? Или ИИС из этой обработки нужно убрать совсем, а закрытие считать только отдельной операцией по ИИС?
