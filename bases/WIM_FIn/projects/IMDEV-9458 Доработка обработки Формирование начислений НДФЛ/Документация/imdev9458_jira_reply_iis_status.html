По замечанию об активных портфелях ИИС

Спасибо за постановку. Ниже — принцип работы обработки «Формирование начислений НДФЛ» с ИИС и что видно по проверочному прогону.

Что требуется

Активный портфель ИИС (тип клиента «Индивидуальные инвестиционные счета», дата окончания пустая) не должен давать начисление НДФЛ из этой обработки.

Принцип: два разных шага

  • «Заполнить» — список пар клиент + УК. Здесь тип портфеля ИИС / обычное ДУ строку не отсекает: у одного клиента в одной УК могут быть и обычное ДУ, и ИИС. Отбор «без оборотов по счетам доходов» убирает только пары без оборотов; сам по себе факт «это ИИС» на заполнение не влияет.
  • «Создать» — уже набор портфелей и запись документов. Именно здесь решается, будет ли начисление по ИИС.
«Создать» и портфель ИИС
│
├─ Начисление по портфелю
│  └─ не создаётся
│     (в список портфелей обработки идут только «Физические лица»)
│
├─ Начисление по УК: налог по активному ИИС
│  └─ строк «Начисления» / «Удержания» по активному ИИС нет
│
└─ Начисление по УК: запись документа
   ├─ есть данные для расчёта (обычно по другим договорам клиента)
   │  └─ документ записывается;
   │     активный ИИС либо не входит, либо только в служебных ТЧ
   └─ данных для расчёта нет
      └─ документ по УК не записывается
         (клиент при этом мог остаться в таблице после «Заполнить»)

Что видно в логе прогона

В логе формирования есть сообщение:

Документ "Начисление НДФЛ по УК" не записан: отсутствуют данные для расчета

Рядом — блок Не созданы начисления по клиентам с нулевым НДФЛ.

Это как раз шаг «Создать», а не отсев на «Заполнить». Клиент с ИИС может остаться в списке после заполнения, а документ по нему не создаётся, потому что после расчёта нечего записывать.

Проверка по выгрузкам документов Результат
Отдельные документы начисления по портфелю ИИС 0
ИИС со строками налога («Начисления» / «Удержания») в документе по УК 0
ИИС только в служебных ТЧ без налога единичные случаи, и только внутри документа по УК, где уже есть расчёт по другим портфелям того же клиента
Важно. Отсутствие массовых «пустых» документов по ИИС — не эффект отбора по оборотам на «Заполнить». Этот отбор убирает клиентов без доходов из списка; ИИС-клиенты с оборотами (или с другими договорами) в заполнение всё равно могут попасть. То, что по ним не появляются документы начисления, даёт уже логика создания / записи документа (в том числе отказ записи при отсутствии данных для расчёта — это видно в логе).
Смысл для требования. «По активному ИИС не создавать начисление НДФЛ» на практике выполняется: документа по портфелю ИИС нет, строк налога по активному ИИС нет. Отдельный флажок на форме под это не нужен.
Вывод. Постановку по активным ИИС можно считать уже закрытой текущим поведением «Создать» (отбор портфелей + отказ записи документа без данных для расчёта). Это не новая настройка отбора на «Заполнить». Доработка имела бы смысл только если нужно жёстче: убирать таких клиентов ещё из списка после «Заполнить» или запретить даже служебные строки ИИС внутри документа по УК на 31.12. Если такого требования нет — по ИИС дополнительных изменений не планируем. Просим подтвердить.
