# Тестирование IMDEV-9458

Внешняя обработка сравнения двух отсевов пар клиент+УК после заполнения как в обработке «Формирование начислений НДФЛ», вариант 2.

## Файл

`IMDEV9458_CompareTurnoverFilter.epf` — открыть как внешнюю обработку в ФИН20.

## Что делает

1. Набирает исходный список тем же методом, что кнопка Заполнить обычного варианта: `ЗаполнитьДокументамиНаДату` (вариант 2). На форме те же отборы, что в типовой обработке: период, **налоговый период** (год, по умолчанию 2026), **управляющая компания** (обязательна), клиент, «по закрытым портфелям», «по закрытым с поступлением НКД», схема выплаты. Оба флажка закрытых портфелей по умолчанию включены.
2. Для каждой пары клиент+УК смотрит обороты Хозрасчетного за год даты окончания периода.
3. Отсев по листьям из текста Jira: нет оборота по счетам `90.01, 91.01.02, 91.01.03, 91.01.04, 91.01.09, 91.01.99`.
4. Отсев по умолчанию формы: нет оборота по `90.01, 91.01, 91.03` (префиксы раскрывают субсчета). Расходы 91.02 / 90.02 / 91.04 и налог 68.01 не входят.
5. В таблицу попадают только отличия двух отсевов. Пары без оборотов по обоим спискам в таблицу не входят (они в счетчике «Оба отсекают»).

## Прогон 17.09.2026

Вариант 2, УК АО НВМ Инвестиции, налоговый период 2026.

- Кандидатов Заполнить: 27 797
- Отсев по листьям Jira: 2 903
- Отсев по `90.01, 91.01, 91.03`: 2 903
- Оба отсекают: 2 903
- Отличий в таблице: 0

Умолчание на форме обработки НДФЛ: `90.01, 91.01, 91.03`.

## Виды строк в таблице

- «Отсекает только постановка (Jira)» — доход есть на счете вне листьев текста Jira (например только 91.03 или 91.01.05).
- «Отсекает только широкий список» — при неизменных умолчаниях быть не должно: `90.01, 91.01, 91.03` содержит листья постановки.

Списки счетов на форме можно править перед сравнением.
