IMDEV-9458 · тест обработки Формирование начислений НДФЛ

Сравнение прогонов Аванкор 9 и Аванкор 8

База 24889. Прогон 9 — без флага отбора клиентов с доходами. Прогон 8 — с отбором по доходам (эталон сумм).

1. Введение

Цель сравнения — проверить гипотезу: при выключенном флаге «В заполнение включать только клиентов с доходами» суммы по «живым» документам совпадают с прогоном 8, а лишними оказываются только пустые документы.

Итог. По документам начисления НДФЛ по портфелю гипотеза подтверждена полностью. По документам по управляющей компании — почти полностью: добавлены ожидаемые пустые, но выделены два дополнительных документа УК с доходом и нулевым удержанием (см. раздел 5). Известный кейс Платонова Д.В. в отчёт не включён (старый баг, не связан с флагом доходов).

2. Технология сравнения

Сравнивались выгрузки двух прогонов одной тестовой базы:

  • лог формирования начислений НДФЛ (xlsx);
  • сообщения пользователю (txt);
  • выгрузка документов «Начисление НДФЛ по УК» (xlsx, строки табличных частей);
  • выгрузка документов «Начисление НДФЛ по портфелю» (xlsx, строки табличных частей).

Документы группировались по номеру. «Пустой» документ: сумма дохода = 0 и сумма к удержанию = 0 (для портфеля дополнительно исчисленный налог = 0).

Параметры прогонов
  • Аванкор 8: 20.09.2026 09:02–13:34, ошибок в логе: 0
  • Аванкор 9: 20.09.2026 19:47 – 21.09.2026 02:29, ошибок в логе: 0
  • Прогон 9: флаг отбора по доходам выключен
  • Прогон 8: отбор по доходам включён (эталон для сумм)

6. Возможности дальнейшего анализа

  • Открыть документы УК 000000000045592 и 000000000046843 в базе 24889 и проверить, почему налог к удержанию не сформировался.
  • Сверить, попадали ли эти клиенты в заполнение прогона 8 (при включённом отборе по доходам) и почему документ УК тогда не создался.
  • При необходимости — точечный повтор «Заполнить + Создать» только по этим двум клиентам на той же дате/периоде.

7. Выводы

  1. Отбор по доходам на шаге заполнения работает: без флага появляются тысячи пустых документов портфеля и УК, а «живые» портфельные суммы совпадают с эталоном (Аванкор 8).
  2. Критических ошибок прогона 9 нет: 0 ошибок в логе, нет коллизий номера и блокировок СУБД.
  3. Для ручной проверки остаются только два клиента УК: Львов Павел Глебович и Баландин Дмитрий Викторович (документы с доходом и нулевым удержанием, отсутствующие в прогоне 8).
